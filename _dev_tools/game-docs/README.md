# game-docs/ ——《宋祚》文档树

> 本目录是项目**唯一的文档根**。四类内容定位不同，查证时**先分清权威 vs 历史**。

| 子目录 | 定位 | 用法 |
|---|---|---|
| **`docs/`** | **权威机制文档**（规范/口径，改代码前必读，且改完要同步） | 见下表 |
| **`analysis/`** | **分析与设计报告**（按主题/日期；结论会被后续修复推翻，属"过程记录"） | 找某个机制"当时怎么定的/为什么这么改" |
| **`kb/`** | 开发知识库（`build_kb.py` 生成 `dev_kb.sqlite`，供检索；**产物不入库**） | `kb_search` 检索代码/文档 |
| **`reviews/`** | **归档**：历次全审/复审/规范/交接（2026-09-27 从工作区根移入） | 追溯历史问题清单与外部复核意见 |

## 约定

1. **改机制 → 同步 `docs/`**（文档滞后于代码属缺陷，历史上多次因此产生口径漂移）；
2. `analysis/` 的报告**按日期命名**（`主题_YYYY-MM-DD.md`），便于判断时效；
3. 归档类文档进 `reviews/`，新写分析进 `analysis/`，不要散落到仓库根或工作区根。
