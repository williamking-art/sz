## 文档分层

| 目录 | 用途 | 判定规则 |
|---|---|---|
| [`docs/`](docs/README.md) | 当前机制 + 设计依据 | 只有标 **现行** 的可当当前事实；设计/依据不等于已实现 |
| [`specs/`](specs/README.md) | 专题需求、设计、任务、验收 | 状态看各域 `tasks.md` + 代码路径；本索引不复制易过期数字 |
| [`analysis/`](analysis/README.md) | 设计探索、平衡分析、项目审查 | 过程材料；结论采纳后回写 `docs/`，未采纳不作为机制事实 |
| [`reviews/`](reviews/README.md) | 审查、交接、未落地裁定 | 报告绑定编写时点；当前是否仍问题需复核代码 |
| [`archive/`](archive/README.md) | 旧计划、历史审查、过期材料 | 仅作历史查阅；不追改旧结论 |
| `kb/` | 文档/源码检索工具与生成知识库 | 生成数据库不是机制文档或唯一事实源 |

## 维护约定

1. **当前机制**只写进 `docs/` 的现行文档；主文档目标 ≤300 行；
2. 设计细节/批次/证据 → `specs/`；过程/旧结论 → `analysis/`、`reviews/`、`archive/`；
3. 新增文档必须进对应 README 或专题索引；
4. 旧版不追改，统一进 `archive/` 并在主文档标注；
5. 文档中的旧数字、旧行号、旧“已实现”状态不自动代表当前。
