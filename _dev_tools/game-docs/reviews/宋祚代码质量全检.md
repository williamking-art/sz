### 1.2 ✅ 已落地：数值 helper 收敛（11 处重复 → 1 处）

**核实**（AST 规范化比对，收敛**前**）：`_num`×4、`_finite`×2 与 `_clamp`×2 是**逐字相同**的实现
（仅函数名/参数名不同）→ 收敛**零行为风险**。

**做法**：新建 [`core/numeric.py`](../sz/game/core/numeric.py)，提供**语义分明的 API**（不是把不同业务语义强绑一起）：

| API | 语义 | 缺失（None/非法串） | NaN / ±inf |
|---|---|---|---|
| `parse_number(v, default)` | 容错取数（原 `_num`/`_finite`） | 返回 `default` | 返回 `default` |
| `finite_or_undefined(v)` | **对外**语义（面板/AI：未定义） | `None` | `None` |
| `clamp(v, lo, hi)` | 通用钳位（与 `content.data.clamp` 同源，仅 re-export） | — | — |
| `clamp_effect_multiplier(v, lo=0, hi=2)` | 效果系数钳位 | 钳到下界 | 钳到边界 |

各模块改为**本地别名 import**（`from core.numeric import parse_number as _num, clamp as _clamp`），
**调用点一行未改**；`literacy.py` 同时清掉不再使用的 `import math`。
总变化：**+6 / −187 行**，全量 `633 passed`（零行为变更）。

| 位置 | 现状 | 简化方向 |

| `core/game_state.py::GameState.__init__` | 587 行一次性构造全部子系统 | 抽 `_init_pops()/_init_army()/_init_prefecture()…`，纯搬家、零行为变更 |

| 11 处数值 helper | — | ✅ **已落地**（见 §1.2） |

**`ai/client.py` 的量化结论（修正我先前的估计）**：

| 指标 | 数量 |
|---|---|
| `raw = self._call(...)` | 31 |
| `self._postprocess(raw, validate, …)` | 30 |
| 内嵌 `def validate(o)` | **30**（每契约字段/语义各不相同 → **不可合并**） |
| 可用骨架替换的行 | 每个契约**仅 2 行**（`_call` + `_postprocess`） |

部分带 `history=`、5 处走 `_cached_call`、1 处走 `_tool_roundtrip`）——**收益 1%、风险高，判定为"不值得做"**。

**若确要精简 `ai/client.py`，正确方向是**（收益高、风险中）：
1. **按契约族拆文件**（`ai/contracts_settle.py` / `contracts_narrative.py` / `contracts_situation.py`），

### 7.1 ✅ 抵当所存款**存量**无上限（真缺陷，已修）

**来源**：外部流程提交的 `test_didang_permission.py`（未跟踪）有一处语法错误（第 61 行
`from content.data import X if False else None`）——已删该行让收集通过，随即暴露**真失败**：

```
AssertionError: 存款 15,541,569 超过上限 5,897,845（民间被抽干）
```

**诊断链**（逐层验证）：
1. 该流程已提交 commit `（旧提交·2026-09-27 历史重写后失效）`「吸储饱和（240 月压力测试修复）」，但只约束**当月吸储流量**
   （`_settle_bank` 的 `_room = cap - deposits`）；
2. 存款是**历史累积且从不回落**：民间 wealth 被抽走后当期 `cap` 随之下降，存量却留在银行
   → 240 月后仍超限（15.5M vs 5.9M）；
3. 第一版修法（银行步内按准备金**回吐**）受限于准备金不足（钱已贷出在 `loans`）→ 9.99M，仍超；
4. 第二版（回吐 + 超额**重分类**为 `disbursed` memo）→ 6.26M vs 上限 6.26M，仅差 1,489 贯
   —— 因为**银行步之后还有赋税/俸禄/物价等步骤继续改 POP wealth**。

**最终修法**：新增 **Step 10.6 `_settle_bank_stock`**，放在**全部结算步之后**（`settlement.py` 第 10.5 步之后），
基于**期末最终财富**重算上限并两段收敛：
- ① 准备金足够 → **回吐**给目标阶层（`reserve` → POP `wealth`，成对守恒）；
- ② 不足（钱已贷出）→ 超额由「存款负债」**重分类**为「已投放资金」memo `disbursed`
  （不动 `reserve`/`wealth`，**货币总量不变**，只是账面科目重分类，不假装仍是可提取存款）。

**同步面**（按项目纪律办齐）：`test_pop_identity.py::_STEPS` 镜像加入

### 7.2 ✅ 已修：集团「声量」把**兼任**重复计权（真 bug）

**先更正我的口径失误**：上一版报告按**旧印象**把"东南士人"当成"东南地域/路域子集"，据此把它声量最大

**真 bug（在改过的实现里）**：`core/faction_voice.py::voice_seats` 原本按"**每个 holder 都取机构权限累加**"

|---|---|---|

| `曾布` | 中书侍郎(12.0) + 尚书右仆射(6.5) | 18.5 |

**我第一次修法方向错了**：改成"同机构去重"，但那会**同时**砍掉旧党（御史台/谏院/尚书省各有两人），
把"人多势众"这一真实政治优势抹掉（旧党降到 33.0，东南士人 48.0，结论仍未变）。
**正确口径是「一位官员一份声量」**（依用户定稿"官员的声量来自官职，派系的声量来自其官员"——
**官员才是载体**）：每人只按其**最高权限职位**计一次，兼任不叠加。

**修正结果**：旧党 **53.5** > 东南士人 **41.5** > 新党 17.0 > 西军集团 10.5 > 宦官集团 5.5
→ 与"旧党在朝（韩忠彦等）"设定、`_examiner_faction` 默认取值、测试期望**三者自洽**。

**验收**：
