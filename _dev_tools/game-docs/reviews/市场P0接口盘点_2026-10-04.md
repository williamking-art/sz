## 二、逐项盘点

### 2.1 地点

| 层 | 现状 |
|---|---|
| ✅ 已有 | `material_holding.circuit_seats(circuit)` 列治所；`is_seat_bucket_key` 判治所桶 |
| ✅ 已有 | `transport._seat_index()` 治所索引、`route_days(frm, to)` **治所间**天数 |
| ❌ 缺口 | `market.trade_goods(state, dim, qty, price, buyer, seller, …)` —— **只认 POP 对象，无地点参数** |

**含义**：物流侧已经能表达「从 A 治所到 B 治所」，但成交侧表达不了「这笔货在哪个治所」。
所以跨路成交才必须靠 `trade_material` 抛错逼人改走 `transport.dispatch`。

### 2.2 报价

| 层 | 现状 |
|---|---|
| ✅ 已有 | `market_price.pref_good_key(pref, dim)` → `"路\|商品"`；B2-R2 路级价格发现 |
| ✅ 已有 | `discover_price` 纯函数（供需压力 → 封顶缓动） |
| ✅ 基座 | `seat_good_key(pref, seat, dim)` / `discover_seat_price` / `record_seat_trade_price`（本会话 `c0fca23f90`）|
| ❌ 缺口 | **州府级三函数零调用方** —— 无真实治所成交，故无处产生州府价 |

**已验证的兼容行为**：治所无成交 ⇒ 回落本路价，**不是填 0**（缺失≠0）。

### 2.3 成交

```python
trade_goods(state, *, dim, qty, price, buyer, seller, purpose, trade_id)
    -> {ok, traded, paid, unmet_qty, tail_delta, reason, material_delta?}
```

- ✅ **原子**：钱货**同一次调用**内转移，不拆成两腿（这是它最大的优点）；
- ✅ **全或无**：不足即 `unmet_qty` 原样返回，调用方须归因，**不静默丢弃**；
- ❌ **无地点**：`buyer`/`seller` 是 POP dict，没有「这笔交易发生在哪个治所」；
- ❌ **无物流**：跨地点成交会**瞬移**（故 `trade_material` 用抛错强制拦截）。

### 2.4 持有人

| 层 | 现状 |
|---|---|
| ✅ 已有 | POP 侧 `pops[阶层].goods[治所][维]`（G-2 已把料铺进州府桶）|
| ✅ 已有 | `_pop_stock` 读「扁平项 + Σ治所桶」，兼容旧档 |
| ❌ 缺口 | POP **无派系**（§6.24），故 `resolve_holder(维,阶层,派系)` **无法解析** |

### 2.5 运输

```python
dispatch(state, *, frm, to, dim, qty, ...)   # frm/to 是**治所**
arrive_due(state)     # 到期到货
in_transit(state)     # 在途清单
is_adjacent(frm, to) / haversine_km / route_days(frm, to)
```

✅ **本环节已完整实现治所级**，无需补。`material_trade.py:222` 是唯一真实调用方（玩家跨路交易）。

### 2.6 缺失原因

`trade_goods` 的 `reason` 枚举（实测）：

| reason | 含义 |
|---|---|
| `ok` | 成交 |
| `invalid` | 参数非法（价 ≤ 0 / qty ≤ 0 / buyer is seller）|
| `no_stock_local` | 本地无货 |
| `insufficient_purchasing_power` | 购买力不足 |

✅ 语义完备，且**「没买到」与「买不起」已分开** —— 与 §6.25「缺料如实记、不回落 0」一致。

## 三、缺口清单（按依赖顺序）

| # | 缺口 | 阻塞什么 | 依赖 |
|---|---|---|---|
| **1** | POP 增**派系**子池 | `resolve_holder` 无法解析 ⇒ 付款对象未定 | 无（T1）|
| **2** | **治所级成交**：`trade_goods` 增加地点参数（或新增 `trade_goods_at`） | G-4 / G-5 端到端 | 缺口1 |
| **3** | 持仓的**治所归属**校验：跨治所成交必须先经 `transport.dispatch` | 「运没运到」可观测 | 缺口2 |
| **4** | 州府价三函数**接入成交记账** | G-5 完成 | 缺口2 |

⚠️ 缺口 2 有两条路，取舍须裁：

- **甲** 给 `trade_goods` 加 `frm`/`to` 治所参数（**改现有签名**，调用点全需核）；
- **乙** 新增 `trade_goods_at(...)`，`trade_goods` 保持为路级薄封装（**不改签名**，更安全）。

🔴 **建议乙** —— `trade_goods` 已被多模块调用，改签名的回归面大；
新函数 + 薄封装可以把影响面限制在新路径。

## 四、目标形态（接线后）

```
① 定位   route -> seat（resolve_holder 给持有者，同时定地点）
② 报价   discover_seat_price(维, 路, 治所, 本地需求, 本地可售)
③ 清算   trade_goods_at(buyer@seat, seller@seat, …)  原子钱货转移
④ 在途   dispatch(frm=seatA, to=seatB, …) -> in_transit -> on_hand
⑤ 加工   工坊仅可消费 on_hand（**在途不可消费**）
⑥ 工资   冻结义务 -> 按合同结算
⑦ 售货   真实成交 -> record_seat_trade_price -> 下月 discover_seat_price
```

> 这一路径正是 [G-4工坊经营状态机_设计](G-4工坊经营状态机_设计.md) 的七段，
> 差别只在**接口层已具备什么** —— 本盘点表明：**③ 与 ④ 之间目前是断的**。
