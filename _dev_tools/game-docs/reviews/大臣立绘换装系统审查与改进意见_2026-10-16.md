## 〇、一句话结论

**设计稿、裁定、代码骨架都很完整；差的是两根电线——资产没生成、DNA 算出来没喂进去。**
修好这两处，「静态千人千面 + 换装」可达；「Live2D 微动态 + Shinsekai 情绪联动」**当前 PIL 静态合成栈永远达不到**，需另换渲染栈（见 §三）。

## 一、实测判定：能否达到预定效果

| 预定效果 | 当前可达性 | 证据 / 前提 |
|---|---|---|
| 静态千人千面（名臣专属 + 百官派生） | **❌ 当前不可达；修好可达** | 8 类图层资产**一张未生成**（见 §二.1）；`data.py` 不传 age/traits（见 §二.3） |
| 换装即时反映品级/恩赏 | **❌ 当前不可达；修好可达** | 同上 + 恩赏 head 覆盖未被读（见 §二.4） |
| 召对动态微动（呼吸/眨眼） | **❌ 需换渲染栈** | PIL `Image.alpha_composite` 叠静态 PNG，无骨骼/参数/运行时（见 §三.1） |
| 对话语义 → 立绘情绪联动 | **❌ 需换渲染栈** | DNA 无 expression 字段，渲染无表情槽位（见 §三.2） |

**实测多样性计数**（脚本随机造 80 名非名臣跑 `derive_official_visual_dna`）：

| 口径 | distinct 组合数 |
|---|---|
| 当前接线（age 恒 42、traits 空） | **15**（face×beard），且 **80/80 全为 middle** |
| 若喂入 age/traits | **29**（doll×face×beard） |
| 实现的真实上限（face×beard×doll 绑定） | ≈ 5×7×9 ≈ **315**（脸与底模绑定后更少） |
| 设计稿 §一.2 宣称 | 40,320,000 |

> 结论：对「全游数百官员不重脸」，**315 的上限够用**（碰撞概率仍低）；但**不要按「四千万」验收**——那是把未实现的「五官 7 维解耦」当成了已实现（实现塌缩成单一 `face_model`）。

## 二、逐项发现（按严重度）

### 1. 🔴 资产为零：paperdoll 图层一张没生成，实际渲染走旧路（且名臣断头）

- **证据**：`game/content/ministers/layers/` **无任何子目录**（无 `dolls/faces/beards/robes/belts/pouches/held/futou/`）。实测渲染非名臣「张知县」→ 头脸被横向空白条切成数段（断头 + 羽化带），正是 `JEV-台账-布娃娃素体…` 的 `premises_verified_by_me` 写明要废黜的缺陷形态。
- **机理**：`_composite_layer`（`portrait_assembler.py:348-360`）对缺图**静默返回 False**；`robes` 缺则回退旧 `body_*.png`——而旧 body 的头已被净身抹掉，新 `faces/*.png` 又不存在 → 断头。
- **隐患**：`body_*.png` 已焙入腰带/鱼袋/笏/幞头；**一旦先补 belts/held/futou 而 robes 未补，会重影**（焙入件 + 透明层各画一遍）。
- **动作**：跑 `_dev_tools/build_paperdoll_layers.py` 生成资产；**构建期加资产完整性清单校验**（别让「代码全、资产零」无声存活）；验收按 §四 锚点（视平线 y=285、肩线 y=460、革带 y=715、鱼袋垂至 y=810）。

### 2. 🔴 测试盲区：12 例全绿但没人验证装配产物

- **证据**：`test_paperdoll_audience_system.py` 12 passed，但**全是 DNA/提示词逻辑**断言；没有一例验证「装配输出真把 8 层叠上」。故「资产缺失 → 实际走旧路」完全捕不到。
- **动作**：加一例——mock 全图层资产后装配，断言输出非纯绢底/非旧 body 回退（或断言 `_composite_layer` 被调 N 次且全 True）。

### 3. 🔴 DNA 接线缺口（`data.py:606-611`）

| 缺口 | 现状 | 后果 |
|---|---|---|
| 不传 `age` | 恒 42 | `age_group` 全 `middle` → 千人千面塌一半 |
| 不传 `traits` | 恒 `[]` | `FACE_MODELS.trait_affinity` 权重失效 → 脸型纯随机 |
| 不传 `seed` | `md5(name+rank)` 兜底 | 确定性在，可暂不修 |

- **动作**：`age = state.year - MINISTERS[name]['born']`、`traits = fig.get("trait_ids", [])`。

### 4. 🟠 装配不用 DNA 的 `doll_id`；恩赏 head 覆盖未被读；缓存 hash 漏键

- **证据**：
  - `portrait_assembler.py:363` 用 `doll_{pose}.png`，非 DNA 算出的 `doll_id` → **`DOLL_CATALOG`（9 款底模）是死数据**，年龄/脸型进不了底模层。
  - `derive_official_visual_dna` 只读 `favor_equipment` 的 `waist/accessory/held`，**不读 `head`** → **赐金花幞头在立绘上不可见**。
  - `dna_hash` 不含 `age_group` 与 head 覆盖 → 岁月变老、赐帽**都不触发重算**，`_composed/{name}_{hash}.png` 陈旧。
- **动作**：装配改用 `dna["doll_id"]`；读 `head` 恩赏；hash 并入 `age_group` 与全部 favor 覆盖键。

### 5. 🟠 架构冲突：名臣仍叠旧位图头，与 §二 / Jev 裁定相悖

- **证据**：`portrait_assembler.py:367-374` 对 43 名臣叠 `head_{name}.png` 位图层。设计稿 §二：「不给名臣搞任何特殊双轨切片」；§一.3：「名臣同样运行在统一骨架之下」；裁定 `d1397c74fc`：「**废黜位图硬切伪图层**」——名臣专属位图头正是被废的那类。
- **处置**：**属架构含义的取舍，应先过 Jev**：要么按 §一.3 把名臣参数化进统一骨架（与裁定一致），要么补一份台账明确这是过渡期混合。**不建议直接改代码。**

### 6. 🟡 设计稿 §五 层表未实现齐：缺「内衬中单」；无 Live2D/情绪

- 设计稿是 10 层（Layer 0~9），实现叠到第 9 步且**缺 Layer 4「内衬中单（Collar）」**——该层的作用就是「彻底杜绝颈项断痕」，缺了它断痕风险回来。
- §三/§八 的 Live2D 微动态、Shinsekai 情绪联动均为空（见 §三）。

### 7. 🟡 一致性小问题

- `verify_costume_historical_integrity`：`TABOO_KEYWORDS` 含 `"dragon"`，而 `neg_en` 负面提示词**必含** "dragon robe" → 若接到完整 prompt 上恒 False。校验应只作用于正向描述。
- `portraits/_composed/` 无淘汰（每 (name,hash) 落一文件，无限增长）。
- `parse_costume_tier`（costumes.py）与 `data.py::rank_tier/minister_tier` **双实现**：宗室（rank 空）在前者会算成 `shi`；主路径 `data.py:603` 显式传 `costume_tier` 绕开了它（**当前不发作**），但 `rules/registry/controller/commands_decree/prefect_officials` 5 处仍在用。建议删前者、统一走 `minister_tier`。

## 三、Live2D / Shinsekai 为何换栈也做不到（给验收的硬依据）

1. **Live2D 微动态**：`assemble_official_portrait` 全程 PIL `Image.alpha_composite` 叠静态 PNG。呼吸/眨眼需要 Cubism 运行时 + motion 参数 + 分层源文件做参数化变形——静态 PNG 里没有这些。
2. **情绪联动**：`derive_official_visual_dna` 的 DNA 里**没有 expression 字段**，装配也无表情槽位。语义 → 情绪的映射、表情部件/参数驱动，都要另建。

> 建议把「预定效果」拆两期验收：**一期只验静态千人千面 + 换装**（当前架构能扛）；**Live2D/Shinsekai 单独立项**（前端 Canvas/游戏引擎做参数化动画，另一套工程量）。
