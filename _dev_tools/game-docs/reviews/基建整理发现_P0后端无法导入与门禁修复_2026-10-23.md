**为什么做这三件**：都是「本机噪声淹没真信号 / 命令缺位」类基建缺口，而非功能。

1. **MCP 体检脚本**：本机 `HTTP_PROXY`/`git http.proxy` 指向 `127.0.0.1:7890`，代理程序未运行时直连失败会被伪装成「服务端 502 / TLS 失败」。该误判**已发生三次**（本机一次 `git fetch` 失败；AGENTS.md §7 与开发服务器说明 §8.1 各记一次）。脚本先自省代理、再以 `curl --noproxy '*'` 探测，并把排查顺序写在末尾。纯 ASCII 写成——首版用中文，PowerShell 5.1 把无 BOM 的 UTF-8 按 ANSI 解码，乱码乃至字符串断裂致脚本无法解析。
2. **断链门禁恒失败**：`os.walk` 从仓库根扫文件系统，不区分 git 是否跟踪；本机解包的两份 vendored 仓库（`deepseek-harness-master/`、`dsh-market/`，`git ls-files` 均为 **0**）被一并扫描，37 处断链全在其中。我们自己的文档实测 **0 断链**。干净克隆/CI 无这两个目录、门禁本来通过 ⇒ 纯本机噪声。修法与该文件既有处理一致（`.cloudbase` 即同理）。
3. **17 个未跟踪文件**：逐条核查后 13 个是正式分析文档（其中 7 个被**已入库**的 `archive/` 审计档行内引用作证据，但干净克隆里被引文件不存在）、4 个是审查中间产物（`_replay_*.txt`、`_tmp_analyze.py`）。

## 二、🔴 P0：后端模块无法导入，服务起不来（需另一条线处置）

### 实测

```
cd game && python -c "import backend.server"
ImportError: cannot import name 'StaleAdvanceError' from 'core.commands'
  File "game\backend\server.py", line 42, in <module>
```

⇒ FastAPI 后端**无法导入** ⇒ 服务起不来 ⇒ 前端连不上 ⇒ 打包版 `backend_server_entry.py` 同样起不来。
连带 **21 个测试文件**收集期报错（含全部后端 API 测试）。

### 缺口全在 `core/commands.py`（server 侧与 backend 侧都已写好）

已就绪的消费方（说明这不是「要不要做」，而是「做了一半」）：

| 位置 | 已具备 |
|---|---|
| `backend/server.py:42` | `from core.commands import StaleAdvanceError` |
| `backend/server.py:554-576` | `AdvanceReq.expect_turn`；`_backend.advance(..., expect_turn=…)`；`except StaleAdvanceError` → 409 + `STALE_TURN` |
| `backend/client.py:189-199` | `LocalBackend.advance(state, ai_client, expect_turn=None)` 已接参 |
| `backend/client.py:205-221` | `settle_local(..., expect_turn=…)` 透传 + 重放时跳过 `finish_turn` |
| `_dev_tools/game-dev/tests/test_settle_idempotency_wiring.py` | 完整行为契约（见下） |

缺失的三处：

1. **`StaleAdvanceError` 类未定义**（全库 0 处定义，仅 6 处引用）；
2. **`advance_two_phase` 无 `expect_turn` 参数、无判重守卫**（现签名 `advance_two_phase(state, ai_client=None)`）；
3. **`settle_local` 无 `expect_turn` 参数**（现签名 `settle_local(state)`）——`client.py:217` 已在传，会 `TypeError`。

### 测试写明的行为契约（`test_settle_idempotency_wiring.py`）

- 守卫位于 **AI 预检之前**（`ai_client=None` 也能重放，重试不该因 AI 掉线而失败）；
- **落后**（`expect_turn < state.turn`）⇒ 幂等重放：返回该回合历史日志 `settlement_log[expect_turn]`、`events=[]`、不推进回合、不进结算窗口（不 spawn daemon）、不动富化链字段；缺历史则返回空；
- **超前**（`expect_turn > state.turn`）⇒ 抛 `StaleAdvanceError`，消息含「超前」，且不改状态；
- `LocalBackend.settle_local` 重放（回合未推进）时**跳过 `finish_turn`**（否则同回合重复终局判定/自动存档）。

### 🔴 未决的设计分歧（这才是必须由该线拍板的原因）

**返回元组arity 两个消费方互相冲突**：

| 消费方 | 解包 |
|---|---|
| `backend/client.py:196` | `events, log, report = cmd.advance_two_phase(...)` → **3 元组** |
| `test_…:31/43/57` | `events, log, report, out = advance_two_phase(...)`，且 `assert out is st` → **4 元组** |

两者不可能同时对。要么改 `client.py` 按 4 元组解包，要么改测试按 3 元组——**这属于该线的契约决策，本机不擅自选定**（本机已按「不做开发」停在此处）。

### 建议处置顺序

1. 先定 arity（建议以 `client.py` 的 4 元组统一：`(events, log, report, state)`，测试已按此写，且与 `HttpBackend` 注释「统一四元组签名」一致）；
2. 补 `StaleAdvanceError`（建议放 `core/commands.py`，与 `AIRuntimeError` 同处同风格）；
3. `advance_two_phase` 加 `expect_turn` 守卫（置于 AI 预检之前）；
4. `settle_local` 加 `expect_turn` 透传；
5. 复跑 `cd game; python -c "import backend.server"` 与 `python -m pytest --collect-only -q`（应收敛到 14 个错误，见下）。
