## 二、七段状态机

```
①资金所有 ──> ②资金拨付 ──> ③交易清算 ──> ④到货(in-transit)
                                                      │
                                                      v
                                       ⑦售货回款 <── ⑤加工 ──> ⑥工资结算
```

| 段 | 状态 | 进入条件 | 产出 | 🔴 本段最容易犯的错 |
|---|---|---|---|---|
| **① 资金所有** | `owner` 确定 | 工坊登记时 | `owner_id`（POP键 或 国库 或 内帑）| 虚构一个不存在的 owner（如凭空「坊主」阶层）|
| **② 资金拨付** | `capital` 就位 | ① 完成 | `capital += X`，**X 必须从既有账户划出** | 🔴 凭空注入（不在 `M_ALL` 内 ⇒ 印钞机）|
| **③ 交易清算** | 订单成立 | 意向冻结 | 钱货**同时**转移；失败不产生半成交 | 判定与采购口径分叉；字典顺序影响结果 |
| **④ 到货** | `in_transit` → `on_hand` | 运输完成 | 货权 + 地点迁移 | **在途货被供目的地消费**（物流失去意义）|
| **⑤ 加工** | 产出 | 料齐 | `yield` 入账 | 少拿料却满产；产出无买方仍记收入 |
| **⑥ 工资结算** | 工资义务结清 | 月末 | `capital → owner` 分成 | 🔴 料款与工资**共用同一笔钱**（历史回退真因）|
| **⑦ 售货回款** | 收入 | 真实成交 | 买方 wealth → owner | **无买方却记收入**（凭空造币）|

## 三、支付时序（关键修正）

Codex 建议**一份资本余额内设用途预留额**。我原实现是「投料时才算钱」，是错的 ——
钱必须**先冻结义务**，才谈采购：

```
月初：capital 余额 -> 冻结工资义务额（不可动用）
      剩余可用额     -> 冻结订单预算（当月采购上限）
采购：只从「订单预算」扣；成交才扣款，未成交**解冻**
到货：解冻未用预算，归还可用额
月末：解冻工资义务 -> 实际按合同结算（不足则如实记欠付，不回落 0）
```

⚠️ 这条顺序直接消灭「两腿抢钱」：工资在**冻结段**就被隔离，采购只能动订单预算。

## 四、持有者解析（承 §6.25）

```python
resolve_holder(维, 阶层, 派系) -> POP键 | 'treasury' | 'imperial_treasury'
```

- **盐铁（榷/官冶）** → 国库；
- **木石药材（山泽/内诸司）** → 内帑；
- **丝麻** → 农·民营＝POP／农·官营佃种＝国库；
- **`yields<0`（外输入）** → 商人（**流通者，非物主**）。

🔴 国库与内帑是**两个钱袋，不可混**。

## 五、守恒断言（每段必测）

| 段 | 断言 |
|---|---|
| ② | `ΣM_ALL` 不变（拨付是转移）；`capital ≥ 0` |
| ③ | 钱与货**同时**转移；`Σ商人物品` 不变 |
| ④ | 在途货**不可**被消费；到货后 `Σ` 才增加 |
| ⑤ | `产出 ≤ 投入 × yield率`；无买方时收入 = 0 |
| ⑥ | 工资 ≤ 冻结义务额；不足记欠付，**不回落 0** |
| ⑦ | 收入 = `Σ买方支出`；无买方 ⇒ 不记收入 |

## 六、停工线（Codex §6 的本地化）

- 无真实地点 / 持有人 / 单位依据 ⇒ 保持未定义，**不按人口比例伪拆**；
- 新钱袋无**账内出资** ⇒ 不实现；
- 销售收入**没有买方** ⇒ 不记收入；
- 在途货不能供目的地消费；派生市场视图**不拥有实物**；
- 旧 `grain` **不与** `goods` **双写**。
