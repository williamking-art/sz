### M1 田赋本色：州仓按**名义额**入仓 → POP 粮不足时凭空造粮
- **位置**：`game/core/settlement_econ.py:262-265`（`_settle_land_local`）
  ```python

  264:  _shen["grain"] = max(0, _shen["grain"] - _gt)
  265:  p["storage"] = p.get("storage", 0) + _st + _gt      # ← 用名义额
  ```
- **现象 / 实证**（构造探针 E2：非运期、农/士绅 `grain=0`、名义税粮 1,000,000 石）：
  `Δ州仓 = +899,480 石`，`ΔPOP grain = 0` ⇒ **净造粮 899,480 石**。钳位发生在扣减之后、入仓之前。
- **成因**：先扣后钳＋收款腿按请求额记账；与同函数 `:226-233`「官田入仓先算 `_room` 再截断」的正确写法自相矛盾。
- **改法**：先算实扣再入仓，缺口记可诊断科目。
  ```python
  _st_act = min(_st, max(0, _nong["grain"])); _gt_act = min(_gt, max(0, _shen["grain"]))
  _nong["grain"] -= _st_act; _shen["grain"] -= _gt_act
  p["storage"] = p.get("storage", 0) + _st_act + _gt_act
  state.granary_stats["land_tax_arrears"] = state.granary_stats.get("land_tax_arrears", 0) + (_st - _st_act) + (_gt - _gt_act)
  ```
- **验收断言**：
  ```python
  def test_land_tax_in_kind_never_creates_grain():
      s = GameState("史实"); s.month = 1
      by = {k: 50_000.0 for k in s.prefectures}
      s.calc_monthly_grain = lambda: (float(sum(by.values())), dict(by))
      for p in s.prefectures.values():

      st0 = sum(p["storage"] for p in s.prefectures.values())
      g0 = sum(pop["grain"] for p in s.prefectures.values() for pop in p["pops"].values())
      _settle_land_local(s, [])
      st1 = sum(p["storage"] for p in s.prefectures.values())
      g1 = sum(pop["grain"] for p in s.prefectures.values() for pop in p["pops"].values())
      assert (st1 - st0) + (g1 - g0) <= 0, f"州仓凭空得粮 {(st1-st0)+(g1-g0)} 石"
  ```
  现有 `test_harvest_month_land_tax_into_storage` 只断言 `0 < Δstorage ≤ tax_total`，**不断言 POP 侧同步扣减** → 该缺陷不被覆盖。

### M6 `resources`（盐/茶/丝/麻/蔗…实物存量）**完全不落档** → 读档回退到新开局值
- **位置**：写 `game/core/save_load.py:226`；读侧**无**（`:758-761` 只做形状兜底）
  ```python
  226:  "resources": getattr(state, "resources", {}),      # ← 写了
  758:  if not isinstance(state.resources, dict):
  759:      state.resources = {d: {"stock": 0, "cap": 5000} for d in RESOURCE_DIMS}
  761:      state.resources.setdefault(d, {"stock": 0, "cap": 5000})   # ← 只补缺维度，不灌存档值
  ```
- **实证**（往返探针）：`resources['salt'] = {'stock': 424242, 'cap': 50000}` → 存档 → 读档 → **`stock = 0`**。
- **影响**：`settlement_tech.py:58`（研发材料）、`settlement_finance.py:288`、`production_chain.py:54`、`settlement_econ.py`（产业链/工役）读的都是这份存量 → 玩家积累的**实物存量与产业进度在存档往返中清零**（且是静默的）。注意 `Test-Path`/静态审计都不易发现（键在 save 里存在）。

### M7 立场占比（`faction_split`）**不落档** ＋ 读档时被**错误层级的清洗器清空**
- **位置**：① save 侧**无** `"faction_split"` 键（138 键中缺失）；② 读 `game/core/save_load.py:613`；③ 清洗器 `game/core/save_load_util.py:34` + 调用点 `save_load.py:624`：
  ```python
  # save_load_util.py
  16:  def _strip_unknown_faction_keys(state) -> list:
  24:      known = FACTION_NAME_SET                 # 集团名白名单
  34:      _clean(getattr(state, "faction_split", None))   # ← 清洗的是**顶层**键
  ```
  而 `faction_split` 的**顶层键是 POP 阶级名**（`{"官僚": {集团名: 占比}, "士绅": …, "商人": …, "兵": …}`，见 `content/data.FACTION_SPLIT_INIT`）→ 清洗器把 4 个阶级键**全部当"废弃集团名"删掉**。
- **实证**（往返探针，日志与数值双证）：
  ```
  set_split(官僚) = {新党0.10, 旧党0.70, 皇党0.05, 军功0.05, 中立0.10}
  save_game -> True
  [WARNING] 旧存档含已废弃的集团名键，已清理（不迁移）：['兵', '商人', '士绅', '官僚']   ← 被删的是阶级名
  读档后 官僚 split = {新党0.45, 旧党0.25, …}   ← 回到开局锚点
  ```
  次级机制：`faction_split.split_of` 在表为空时**静默回落到 `FACTION_SPLIT_INIT`**（`core/faction_split.py:88`），故读档不会崩、只是**悄悄回退**——属"缺失值被默认值顶替"的典型形态。
- **影响**：`faction_split` 是集团人数的**权威切片**（`faction_metrics.faction_slice`）→ 转投（`defect_toward_satisfaction`）、科举入派（`blend_entrants`）、致仕/离任（`shift_split`/`exit_faction_members`）的**全部累积在读档后丢失**，各集团人口/影响力整体回退到开局立场分布。**即使修好 M7-a（落档），M7-b 仍会把它清掉**，两条必须同修。
- **改法**：① save 增 `"faction_split": {cls: dict(sp) for cls, sp in state.faction_split.items()}`；② `_strip_unknown_faction_keys` 对 `faction_split` 改为**逐阶级清洗内层键**（`for cls, sp in faction_split.items(): _clean(sp)`），诏令 `faction_stances` 那部分（顶层就是集团名）保持不变；③ 顺带把"表被清空后静默回落锚点"改为记 warning 可诊断。
- **验收断言**：
  ```python

      assert set(s2.faction_split) == {"官僚", "士绅", "商人", "兵"}   # 顶层键不得被删
  ```

## 1 · 「无法吃粮人数」做成**单点**

`core/settlement_common.py::food_insecure_headcount(pops, price)`：
- 月需求 = `size × GRAIN_CONSUME_PER_CAPITA[类]`（石）；
- 可支配粮 = **自有粮 ＋ 购粮能力**（`wealth / 粮价`，即"钱能买多少粮"）——**买得到就不算饿**；
- 缺粮人数 = `size − 可支配粮 / 人均需求`（向下取整、不为负）；

## 3 · 自查发现的一个自身设计缺陷（已修，留痕）

`action_fingerprint` 初版把**数组序号**掺进哈希，造成两个后果：

1. **计划内去重是死码**——同计划里两个内容相同的动作拿到不同 id，`seen_ids` 永不命中；
2. **重试幂等有漏洞**——AI 重试时只要重排动作顺序，同一逻辑动作就换 id → **重复立项漏过**。

由测试 `test_multi_action_plan_validated_per_action` 报 `proposed != duplicate` 暴露。
值得注意的是：**我第一次归因错了**——以为是自己测试数据写错，改完数据仍红，才回头定位到
是真缺陷。现改为指纹**不含序号**，并加 `test_action_id_survives_action_reordering` 锁住该性质。

字段把这层写出来，避免把政治轨道误当数值开关。
