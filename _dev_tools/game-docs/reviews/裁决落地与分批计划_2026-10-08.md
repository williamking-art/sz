## 一、逐条落地边界

### 1+2. G-4 营运资金与支付顺序

**必须先出影子预算与守恒方案**（用户定的顺序），再谈接线。

- 出资：**实际货主**，从其**已有账户**划入营运资金；**纳入 `M_ALL` 并记录转账**。
  🔴 禁止：影子记账、凭空注资。
- 开办额度 = `一个月预计工资义务` + `一个生产周期原料预算`；**受货主可用余额限制**；
  不足则**不启动或缩产**（不是借钱、不是透支）。
- 支付顺序：①先预留工资预算 → ②余款采购；采购**只按实际成交扣款**，未成交**解冻**；
  工资不足 → **记欠付**，🔴 **不得挪用预留工资去采购**。

**本批不做**：不接线、不改正式结算、不设初始额度常量（先影子）。

### 3. D 诏令复述门

⚠️ **先纠正一处旧表述**：此前文档称「复述机制不存在」是**错的**。
实测 `core/decree_confirm.py` 提供完整 API ——
`compose_recitation` / `render_recitation` / `record_recitation` / `recitations_of` /
`latest_recitation` / `compare_recitation` / **`confirm_decree`（门）** / `exec_ledger_of` /
`execution_of` / `backfill_candidates` / **`backfill_decree`（补录）**。

**真实缺口 = 生产链无调用者**：两个调用方只 import 了 `ensure_decree_id`（幂等锚，见
`commands_decree.py:399`、`settlement_decree.py:39-48`）；**`confirm_decree` 零生产调用者**。

**裁决**：**暂不接入主链**。接入设计采用「**受命承办者在承办前复述**」。

| 状态 | 语义 |
|---|---|
| 缺失 | **待复述** → 不执行、**可补录重试** |
| 不匹配 | **拒绝本次承办** → 可更正重试 |

🔴 **AI 可以生成候选，但不能自动照抄原旨并当作承办者已复述。**

**本批只做**：补**生产调用链设计**（在哪一步、由谁、状态机）+ **正/负样例**。**不接线。**

### 4. 家计等第与三税税基

口径沿用 [`POP家计与赋税体系设计_2026-10-04.md`](POP家计与赋税体系设计_2026-10-04.md)：

| 税种 | 税基 |
|---|---|
| 田赋 | **占田亩数** |
| 商税 | **真实交易额 × 货物税率** |
| 赋役 | **等第**（等第**只**影响赋役，不进其他税基）|

- 五等划分：按**等价家庭可支配家计**相对**基本生活篮子**的比例。
- 数据缺项 ⇒ **等第未定义**，🔴 **不当作零**。
- **档线先影子校准**；🔴 **校准前不接正式税收结算**。

**本批不做**：不接正式税收结算、不套假设比例。

### 5. `material_tech.py` 归属迁移

- 目标：`domains/construction/` → **`domains/economy/`**。理由：它参与**商品可交易性与价格规则**，
  不属于域中立的 `common/`。
- **先做归属迁移，不顺带改规则。**

### 6. `economic_affiliation` 切片

- 粒度：**州府 × POP 类别 × 生产关系**。
- 🔴 **关系份额总和必须等于对应 POP**（守恒）。
- 无证据部分保留 **`unclassified`**；**历史局不套假设比例**。
- 玩法假设**另行标注**且**可被数据覆盖**。
- ⏸ **待州府真账及写入桥接稳定后再落数据**（即：排在 #7 之后）。

### 7. POP 守卫

⚠️ **先纠正一处旧表述**：此前 TODO 写「启用可能崩」不准确。实测：

| 事实 | 证据 |

| **存在未桥接写点** | 本会话已修账本可见的 5 处；**未覆盖的仍可能静默丢失** |

**裁决顺序**（用户定）：

3. 验证**镜像一致**；
4. 在**结算入口安装**并按回合汇总；
5. 影子/测试结算**连续零违规**后，把「零违规」**纳入放行门**。
