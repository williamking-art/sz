## 1. 本次是怎么取证的

### 1.1 玩家式实跑（不是空跑回合）

每回合的完整闭环（**实测可跑通**）：

```

  → 召见大臣并下令（/api/ministers/{name}/chat，自然语言 + 固定话术）

      ↳ 未决呈请需先 /api/ministers/{name}/chat/confirm（否则颁诏 409）

      ↳ 结算四步：固定月度财政 tick → 推演 agent 写八章邸报 → 四路抽取 + reconcile → 落库
```

## 2. 机制层：值得搬进宋祚的 8 项

### 2.1 局势系统（issues）——单一最大借鉴

明末每个局势是一条**结构化长期任务**，字段 38 个，实测样例：

| 局势 | 进度 | 达成条件（玩家可见） | 失败条件 | 持续代价 |
|---|---|---|---|---|
| 户部亏空 | bar 26 | 看【国库上月实绩结论】：盈余则 +10，亏空则不推进或倒退 | 国库见底致刚性支出违约（欠饷哗变/官俸断发/宗禄拖欠） | 国库 −10 万、民心 −1/月 |
| 陕西流寇起 | bar 25 | 陕西民心 ≥60、动乱 ≤30、驻陕军士气 ≥50，连续 2 月 | 动乱 ≥85 且民心 ≤30，或万人流寇破州县即**立即失败** | 国库 −5 万、陕西民心 −2 |
| 宁锦防线整饬 | bar 38 | 关宁军欠饷 ≤34 万两 且 士气/补给/忠诚 ≥55，连续 2 月 | 欠饷激成兵变，或锦州/宁远失守 | 国库 −8 万 |

**宋祚可直接照搬的四个设计点**：
1. **成败条件全公开**（玩家永远知道"怎么算赢"）——这是长期目标可玩的前提；
2. **持续代价**（ongoing_text）让"不作为"有成本；
3. **progress_mode 分流**：bar（进度条型）与 goal（目标型，只判进行/达成/失败）；
4. **phase（起/中/终前）+ severity** 给玩家优先级排序依据。

### 2.2 大臣工具化：把"召对"变成"能办事"

14 个 SKILL 覆盖：拟旨（`propose_governance`）、调税（`adjust_tax`）、裁常支（`propose_fiscal_reform`）、拨钱粮（`transfer_funds`）、军务（`manage_army`）、营建（`propose_building`）、设衙（`propose_department`）、人事（`manage_person`）、科技（`propose_tech_research`）、密令（`secret_order`）、记忆（`remember_permanent`）。

**关键设计**：工具产物一律先落**草案**，玩家"准/驳"后才立项 → 既保留玩家裁决权，又让 AI 的产出**结构化可审计**。实测草案文本样例：
> `财政·调整宗室禄米——现660000两/月 → 定为500000两/月（国库·支出）（待核定，准则立项，进度满方落新额）`

**宋祚对应物**：已有 `STATE_TOOL_SCHEMAS`（3 工具）为"预留契约、尚无生产调用方"——正好是接线起点。

### 2.3 未决呈请强制确认（409）

实测触发（第 7 回合）：
> `409 unresolved_confirmation`：洪承畴有一件呈请圣裁未决（政令）；郭允厚有一件…请先回他的召对窗准或驳，再颁诏——**此刻颁诏，这件事会随本月一并作废，且从未办过**。

**价值**：把"玩家漏看大臣呈请"从静默丢数据变成显式拦截。宋祚的 `PENDING_CONTRACTS` / 待办面板可加同款守卫。

### 2.4 财政可解释层（账面 / 到账率 / 公式）

明末每条预算行都带解释，实测：
```
田赋: amount=69.52 base=79.0
  formula="官民田63090万亩×田赋亩率均约394毫（按省）/10000/12 → 到账率约38%"
```
到账率公式：`1 − Σmax(0, 因子−阈值)/100 × 权重`，钳 `[0.05, 1.0]`（三因子权重 0.55/0.45/0.30）。

**宋祚可借用**：把 `core/money.py` 的对账视图 + 税基/到账率做成会计面板的一栏"为何只收到这些"，与宋祚既有的守恒记账天然契合。

### 2.5 双账与内部转库

实测：国库跌到 20.14 万两时，内帑仍有 523.51 万两；"内帑拨银入太仓"是有效救命手段（第 6 回合转 50 万后，户部亏空局势 +5）。宋祚已有国库/内帑，建议把"内帑→国库"做成显式的代价决策（如消耗皇威/引发清议）。

### 2.6 抽取-对账质量层（四路互不通信 + 六类双向核账）

- 四路抽取器（internal / issues / military_external / personnel_secret）**互不通信**，同一份邸报各自抽账，再由 `reconcile` 双向核账（"既剔误抽也补漏抽"）
- 纪律：**点名单册法**（照 `regions`/`armies`/`court_roster` 逐行走）、**核销＝落地铁线**、**反重复双闸**（程序自动落账的项 AI 重抽＝双扣）、**留白优先**
- 宋祚已有 `state_applier` 守恒硬拒绝，可借鉴"多路独立抽取 + 对账"作为**AI 产出→落库**的第二道闸

### 2.7 记忆三层

| 层 | 压缩 | 可见性 |
|---|---|---|
| 月度章节奏报 | 3–5 件大事详写，其余列表 | 全局历史 |
| **大臣私人纪要** | **120 字内**第三人称，只记"干成的差事/已定方针/立场" | **仅该大臣本人** |
| 国策方针 | 30 字一句白话 | 注入为"现行国策" |

实测召对后自动写纪要：`[memory/保存] #16 character:郭允厚 minister_recap《崇祯1628年2月·郭允厚奏对》`。

**宋祚启示**：现有 `memory_graph` 存"史"、`dialogue_memory` 存召对；可加"**仅本人可见的私人纪要**"这一层，制造"大臣各怀心思/信息差"的玩法。

### 2.8 数值口径透明

军队战力分解（实测字段）：`base_weighted_manpower 10,697 → equipment_mult 0.61 → readiness_mult 0.321 → commander_mult 1.32 → person_power 445.69 + weapon_power 608.82 = total_power 1,055`。

**宋祚启示**：把 `ref_power` 一类综合值**展开成可见的乘数链**，玩家才能理解"为什么这支军不能打"。

## 3. UI / 交互层：值得搬进宋祚的 10 项（本次重点）

### 3.1 信息架构：三区 + 九书签 + 五命令

| 区域 | 明末实测内容 | 宋祚现状 | 建议 |
|---|---|---|---|
| 顶部书签 ×9 | 朝政 / 人物 / 科技 / 省份 / 军事 / 工程 / 外交 / 史册 / 总览 | Dock 有 12 个命令钮 + 若干面板 | 把"省份/史册/总览"提升为一等入口，降低"找功能"成本 |
| 底部命令 ×5 | **奏疏 / 邸报 / 密令 / 史册 / 拟诏**（动词式命名） | 朝堂/群臣/朝报/行止/邦交/拟旨… | 命令按"玩家要办的事"命名，而非按系统模块 |
| 拟旨工作区 ×4 页签 | **待答国书 / 明细 / 奏报 / 下一回合**（副标题"阅奏·核草·颁诏"） | 拟旨面板为单页 | 把"看奏报→改草稿→颁诏"拆成页签，符合真实公文流程 |

**最有价值的一点**：明末把**回合推进**设计成一个"审视—决断"的工作区（待答国书 → 明细 → 奏报 → 颁诏），而不是一键"结束回合"。宋祚可在 `AdvancePanel` 前后插入"待办核销页"。

### 3.2 交互范式：自然语言 + 固定话术 chip + 草案核定

- 玩家可以直接说话（召对），也可点前端提供的**固定话术**降低歧义：
  `「朕欲裁动一项常例开支：」` `「朕欲调税：」` `「密令如下：」` `「朕欲拨一笔钱粮：」` `「准奏」`
- 固定话术与 SKILL 的 `description` 一一对应，是**把 LLM 不确定性压到可控区**的成熟手法
- 实测："准奏"被称为"最强的落工具信号"——听到即必须本轮调工具

**宋祚建议**：在召对输入框上方加一排"话术 chip"（如"问户部钱粮""命兵部调兵""下密令"），点击即填入模板，玩家只需补关键要素。

### 3.3 邸报（八章奏章）作为回合结算报告

实测每回合 2,200–4,000 字，固定八章：
`诏书核销 / 指令核销 / 长期局势 / 密令动向 / 讣闻与登场 / 人物历练 / 军事 / 邦交`，
外加章末七言联（如"《辽左罢兵清议伏，秦关拜将黑云翻》"）与**人物属性涨跌账**：
> 毕自严：管理涨1（92→93），设局核九边积欠…；祖大寿：忠诚涨1（80→81）…

**宋祚建议**：`settlement_log` 升级为固定章节的"月度奏章"，尤其补 **① 局势进展逐条 ② 人物历练/属性涨跌 ③ 密令动向** 三章——它们把"看不见的数值变化"翻译成可读叙事。

### 3.4 进度与成败条件全公开（可玩性关键）

局势面板同时给出：进度条数值、`bar_good_meaning`（"财用渐丰"）/ `bar_bad_meaning`（"太仓见底"）、达成条件、失败条件、持续代价。
宋祚的国策/事件面板可照此加"**双向语义标签**"（推进=什么好、恶化=什么坏），比单纯数字更易理解。

### 3.5 数值可解释（hover 看公式）

明末的财政行、战力分解、到账率都是"**数字 + 公式 + 备注**"三件套。宋祚面板建议统一为：主数值大字 + 次要小字基线 + 悬停显示公式（宋祚已有 `format.ts` 工具函数可复用）。

### 3.6 失败路径 UX（宋祚可直接抄）

- **启动四阶段状态机**（spawning → waiting → steam → ready/error）+ splash 展示进度
- **失败不秒退**：把后端 stderr 尾部经正则脱敏（`api_key|session_token|ticket|password`）上屏，并提供"一键复制诊断"
- **日志治理**：`electron.log` 统一收口，渲染层错误 2s 去重、200 条/分限流、16KB 截断
- **多级降级链**：WebGL2 → 软件渲染 → 自绘 SVG；GPU 安全模式；Steam 不可用全静默降级
- 平台坑补丁**全部带 why 注释**（禁外域样式表、Windows 保留 Edit 菜单、强制 UTF-8）

### 3.7 地图与地区识别

明末用真实地图 + **区域头图 banner**（`region-headers/`: capital/city/farmland/great-wall/mongol-steppe/…）+ 势力徽记 + 5,000+ 立绘，省份条目一望可知"这是哪儿、什么地貌"。
宋祚已有 MapLibre 底图，建议给州/路详情加**地貌头图 + 势力色带**，把"文字列表"变成"可辨识的地图对象"。

### 3.8 无障碍与语义

实测 `aria-label` 312 处、`role` 202 处、Escape 22 处、`tablist/tab/tabpanel` 完整。宋祚前端可低成本补齐（lint 规则 + 组件模板）。

### 3.9 反面教材（宋祚不要学）

| 问题 | 实测证据 |
|---|---|
| **HUD 坐标契约与实现脱钩** | `hud-slots.json` 声明底图 `.png`，磁盘只有 `.webp`，且 bundle 内 **0 引用** → 坐标硬编码 |
| **字体 53MB 未子集化** | 两个 Source Han Serif OTF 共 50MB；font stack 里 Noto Serif SC / ZCOOL XiaoWei 未打包 |
| **大图无条件先拉** | `east-asia-handshade-8k.webp` 8.9MB 被 `Promise.all` 先拉，降级判定在下载之后 |
| **无代码分割** | 单 JS 2.75MB + 单 CSS 966KB |
| **纯中文单语却留 i18n 壳** | 仅 8 个 `io(key,fallback)` 键，数万条中文为 JSX 字面量 |
| **渲染层 `sandbox:false` + 后端零鉴权** | 140+ 端点在本机无 token（实测 `/api/menu/debug/token_usage`、`/api/llm/providers` 均 200） |

### 3.10 资源冗余清理

`ui-cutouts\home-menu\` 与 `ui\home\` **逐字节相同**（~1MB）；`dist\` 根还发布 8 个开发编辑器 HTML + 12.5MB MapChart SVG；地图模板两份 31MB 且 `bricks.geojson` **SHA256 相同**。宋祚仓库同样存在"Tk 遗留 / 开发脚本入库"问题（`content/ministers/layers/_src/` ~30MB），可一并清理并加 CI 体积门禁。

## 4. 省级/地方数据面板：现状、问题与改善方案

### 4.1 明末的省面板字段（实测 `state.regions` 26 个数值字段）

| 组 | 字段 |
|---|---|
| 民生 | `public_support`（民心）、`unrest`（动乱）、`gentry_resistance`（士绅阻力） |
| 土地 | `registered_land`（官民田）、`hidden_land`（隐田） |
| 财政 | `tax_per_turn`（账面应征）、`tax_actual`（实收）、`tax_efficiency`（到账率） |
| 粮食 | `grain_output`（年产）、`grain_stock`（存粮） |
| 军防 | `city_defense`（城防） |
| 建筑 | `building_capacity` / `_used` / `_queued` / `_available` / `_over` / `_planned_over` / `_load_pct` / `_planned_load_pct`（8 项） |
| 产出 | `building_output_efficiency_pct` / `building_output_projected_efficiency_pct` |
| 文本 | `id` / `name` / `kind` / `status` / `controlled_by` |
| 人口 | `population` |

另有按月落库的地区状态：实测 `[地区状态] 月度效果落库 97 笔：[('北直隶','public_support',0.39), ('北直隶','population',-2.0), ('北直隶','grain_stock',-15.0)…]`，且地区可挂"状态标签"（如"浙江·生齿日繁"，条件不再成立时自动解除）。

### 4.2 明末省面板的优缺点

**优点**：① 字段覆盖"民生—土地—财政—粮食—军防—建筑"完整闭环；② 账面/实收/到账率三值并列，玩家能看出"征收效率"；③ 建筑容量 8 项能解释"为什么这条政策落不下去"；④ 地区状态标签提供"叙事化特征"。

**缺点**：① 字段太多且无默认排序/筛选；② `building_capacity_*` 8 项对玩家是噪声；③ 缺少"趋势"（只有当前值，无上月对比）；④ 省份与全局指标的关系需要玩家自己脑补（民心是各省人口加权镜像，但界面未提示）。

### 4.3 宋祚州/路面板的改善方案（可直接落地）

**现状**（`PrefecturePanel.tsx`）：三视图（列表 / 单路详情 / 田亩户籍总览），字段以 户/田/粮 为主，进度用 ASCII `█▓▒░`，只读展示。

**建议改造（三阶段）**：

**阶段一（3–5 天）：字段补齐 + 可视化**
1. 每路补 `民心 / 动乱 / 士绅阻力 / 到账率 / 存粮安全垫`（宋祚已有对应 POP/土地数据，多为派生值）
2. 列表页改为**可排序表格**（默认按"动乱"降序，即"哪里先出事"）
3. ASCII 进度条 → 真实条形（复用现有 CSS 变量，参考明末的 7 档色阶）

**阶段二（1–2 周）：可解释 + 趋势**
4. 每个数值格显示"**当前值 + 上月增量 + 悬停公式**"（如 `民心 42.95 ▼0.87`，悬停显示"受田赋/赈济/动乱三项影响"）
5. 加"**本路局势**"区：把与本地相关的局势（陕西流寇起、北直隶地大震）并列显示，并给"直达拟旨"按钮
6. 地形/势力头图（宋祚已有 MapLibre 与 assets，成本低）

**阶段三（2–3 周）：行动闭环**
7. 区域条目支持**就地施政**（赈济/减税/调兵）→ 生成拟旨草案，与 3.2 的"话术 chip"共用一套入口
8. 与地图联动：点地图区域 → 打开该路面板（宋祚 `MapView` 已有 click 事件）

**验收标准**：打开面板 3 秒内能回答三个问题——"哪路最危险？为什么？我能做什么？"
