> **范围**：只审查现存的产业链扩充规划 §8、全商品州府级架构方案及当前配方/结算实现；未改设计正文或代码，未运行测试。

> **材料边界**：`产业链扩充规划_2026-10-03.md` 在工作区和当前 `HEAD` 中均只有 §8 联动部分（96 行）；README 所述的“16 类工坊、原料与成品分级”等 §1–7 不在该文件中。因此本审查不能确认全部链条清单、贡物映射和配方依据。代码中的未来日期注释也只视为注释，不当作当前已验证的时间线。

## 结论

**方向成立，尚不适合按 §8 直接扩链。** 先处理产品分类/所有权和生产地点，再做配给与交易；把多级生产引擎与新增历史链拆开。最大的设计问题不是“工坊种类不够”，而是现有状态账本与拟议的商品市场、州府地点、工序投入还没有统一的承载契约。

推荐保留“丝→绸、麻→布”等已有加工的玩法主干；只在中间工序会改变玩家决策、区域分工或物流时增加半成品。不要把每项贡物都变成新商品或一条新工坊。

## 发现与处理建议

### 1. 规划文档缺少链条目录与数据映射

**位置**：[产业链扩充规划 §8](产业链扩充规划_2026-10-03.md)；[reviews/README.md](README.md)。文件从 §8 开始，缺少其余部分，无法审查 README 宣称的 16 类工坊及其原料、成品、史料出处。

**建议**：恢复/重建一个规范化的链条清单：链 ID、原料和成品维、单位/转换系数、地点、可交易性、来源证据、证据等级、状态。不能从贡物名目或出现次数直接推导年产量、坊数或配方。

**验收断言**：README 描述的工坊数和阶段可逐项定位到清单；每种新维度有唯一 ID/单位与可追溯来源；未映射项明确留空，不被误当作已支持商品。

### 2. L1′ 配给规则有内在矛盾，权重也没有依据

**位置**：[产业链扩充规划 §8.3](产业链扩充规划_2026-10-03.md)；[`_settle_workshops`](../../../game/core/settlement_econ.py#L1525)。当前函数按 `state.workshops` 遍历顺序直接扣共享 `state.resources`；所以解决顺序依赖是必要的。但设计同时要求“分配总量等于池存量”和“未领用差额保留”，且举例的 0.5/0.3/0.2 没有对应产能或政策依据。

**建议**：先按活跃工坊的配方需求与本期可用产能求出每种原料的总需求；实际分配量取 `min(库存, 总需求)`，只在各工坊之间确定性分配该量，剩余库存留在原持有人账户。权重从显式产能/优先级规则产生，不硬编码示例比例。整数余数按稳定的工坊 ID 排序分配，避免字典顺序影响结果。

**验收断言**：`分配量 ≤ 库存`、`实际消耗 ≤ 分配量`；库存不足时按规则同比欠产；未领用库存不减少；重排工坊字典后每个工坊的分配和产量不变。

### 3. “工坊所在州府”尚无权威字段，人口分摊不能代表产地

**位置**：[`game_state.py` 开局工坊实例](../../../game/core/game_state.py#L548)；[`_settle_workshops` 的成品分派](../../../game/core/settlement_econ.py#L1608)。工坊实例持有 `name/recipe/output_dim/yield/active`，地点只出现在实例键名中；结算把成品汇总后按各路工匠人口比例分派。这不能证明实际生产地点，也会让产地和库存位置不一致。

**建议**：在启用州府级生产前，为工坊实例增加持久化、可验证的 `prefecture_key` 和所有者/持有人标识；由建造/开局数据写入，不从字符串键名猜地点。明确原料库存由谁持有、生产扣谁的库存、产出归谁、卖方收入归谁。没有地点来源的旧存档应保留为“未定位”或按有依据的迁移规则处理，不按人口伪拆。

**验收断言**：一笔工坊产出只记入其唯一地点与持有人；变更工匠人口不会改写既有货物产地；旧存档迁移前后全国商品总量一致，未知地点不变成伪精确州府数据。

### 4. 成品目录不能单独决定商品交易路径

**位置**：[`WORKSHOP_RECIPES` / `FINISHED_DIMS` / `RESOURCE_DIMS`](../../../game/content/data_constants.py#L150)；[`_settle_workshops` 酒、肉、布绸分支](../../../game/core/settlement_econ.py#L1561)。目前 `wine` 列在成品目录但不进物资仓，酒坊走酒课；`meat` 走民间收钱进内帑，没有经过商品库存；布/绸又先增加 `resources`，后进入工匠 `goods` 池。简单把 `meat` 加进 `FINISHED_DIMS` 不会自动把它变成可交易商品，酒、肉、布绸的现有收支含义也不同。

**建议**：把“生产产物”“可存货”“可交易”“财政税收输出”分成明确属性/路径，避免一个 `FINISHED_DIMS` 同时承担目录、存储、市场资格和财政结算。每种输出指定一个权威库存；若保留仓储读数和待售视图，后者应是可追溯的子账/派生视图，明确禁止总供给、价格与守恒审计重复计数。

**验收断言**：每种商品在目录、生产、库存、市场供给、价格、财政收入中的路径都有映射；同一批产出在各读数中不会被重复加总；`wine`/`meat` 的旧税收/财政规则在改变前后有明确对照。

### 5. 物料“投入总量 = 产出总量”不适用于异维加工

**位置**：[产业链扩充规划 §8.4–8.5、守恒验收](产业链扩充规划_2026-10-03.md)。输入可能是丝、粮、染料，输出可能是布、酒、肉；不同维度的数量单位不可直接相加。加工还可能有损耗、废料和副产物。

**建议**：守恒按“持有人 × 地点 × 商品维”核库存变动；配方用有单位的转换系数记录输入、主产物、副产物和明确损耗。资金另按买方扣款、卖方收款、税费流转核账，不要求钱值等于物料数量。若暂时没有可靠转换单位，就先不把该链纳入数值生产。

**验收断言**：每种输入库存变化等于明确消耗；每种输出库存变化等于主/副产出；损耗有单独去向；市场交易钱货两边分别守恒；不存在无买方收入或无来源原料。

### 6. 串联时序、加工能力和半成品库存还未定义

**位置**：[产业链扩充规划 §8.2、§8.5、§8.7](产业链扩充规划_2026-10-03.md)。流程图写“茧→缫丝→生丝→织造”，正文另列“生丝→纱”工序，但图中没有纺纱；按拓扑序同月串联也可能让上游本月生产的产物立即被下游消费。当前工坊有 `yield`，还没有显式的批量单位、月加工能力、在制品/半成品时序。

**建议**：先决定游戏要模拟即时加工还是跨月在制品；若同月串联，明确上游产出先记账、下游后取料且不可超额；若跨月，显式保存半成品库存/在制品。配方图需拒绝循环、缺失维度和不存在的工序。将流程图、配方表、实际结算顺序保持同一份权威定义。

**验收断言**：环路在载入配方时被拒绝；无上游产出时下游不产出；同月可用量不超过上游实际落账量；结算顺序和存档恢复不会令半成品重复使用。

### 7. 实施顺序与市场架构互相冲突

**位置**：[产业链扩充规划 §8.7](产业链扩充规划_2026-10-03.md)；[全商品市场架构 §3、§5](../docs/全商品州府级与统一市场流转_架构方案_2026-10-03.md)。产业链稿把 L2′–L4′ 排在 L5′（州府产出）之前，并只给 L5′ 加 G-4 前置；架构稿又明确 G-4 才引入真付款、市场和运输。若先激活新链，新增工坊仍从全局资源池暗取原料，后补市场接线会改变已运行产量与账本。

**建议**：可提前开发并验证通用配方校验器，但不要激活新链。运行顺序改为：G-6-L1 口径收敛 → L1′ 确定性分配 → G-2 明确原料地点/供给 → H/G-3 确定粮食承载（只影响用粮配方）→ G-4 市场采购/付款/运输 → 工坊地点与唯一库存 → 再启用多级链/副产物/新增工序 → G-5 价格发现与长局校准。G-2 骨架本身仍可先行，不必等 A 旧粮价裁定。

**验收断言**：每条已激活 recipe 都经统一投入入口；无免费领料、无未到货即消费；价格和销售读取同一权威库存；新增链未通过市场与守恒门前保持关闭。

## 推荐先做的最小模型

不先做“16 种工坊 + 全部贡物”。先冻结以下模型，再扩链：

1. **商品定义**：稳定维度 ID、名称、单位、原料/中间品/终品分类、是否可存/可交易、规范价格键。
2. **配方模板**：输入清单、输出清单、单位换算、损耗、副产物、单期能力、允许的上游/下游。
3. **工坊实例**：模板 ID、唯一地点、持有人、容量、启停状态；实例字段序列化并有旧档默认规则。
4. **库存归属**：每个持有人和地点只有一个实物权威账；仓储展示、待售量及市场读数不得成为额外库存。
5. **结算分步**：先统计需求与产能，再仲裁原料；再执行购买/运输；最后结算加工、成品、副产物与收入。所有分配和排序确定性。

## 最终建议

- **继续当前近期路线**：G-6-L1 先厘清 `meat/wine` 是市场商品还是财政/官营产物；L1′ 先做确定性配给；G-2 建立有来源的供给落州府接口。
- **先暂停新增链的实际接线**：直到工坊地点、货权、库存单点和 G-4 市场采购语义明确。
- **史料只支撑“有此物/某地有此贡物”时，只录存在性证据**；不由贡物频数推产量或工坊比例。把缺乏单位与工艺证据的链放在待研究表。
- **链条复杂度以玩法价值为门槛**：只有当中间品带来区域比较优势、运输瓶颈、生产选择或政策反馈时，才增加该中间品和工序；否则用单步配方表示，避免模拟细节增加但玩家没有可观察影响。
