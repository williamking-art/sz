## 〇、AI 驱动架构总览

- **AI 通过结构化契约返回变更**（2026-09 审计对齐实现现状）：各角色 `*_decide` 契约（JSON 输出 + validate 校验 + 失败回喂）为**主通道**；大臣办差走 **function calling**（`enable_tools` 三档：auto/on/off）；`STATE_TOOL_SCHEMAS`（`update_state`/`query_state`/`trigger_event` 3 工具 + `tool_choice=required`）为**预留契约**（尚无生产调用方，见 `ai/client_utils.py` 注释）；AI 无自由文本改状态权。
- **应用层唯一改状态通道**（`engine/state_applier.py`）：验证（path 白名单/op 类型/clamp/非负）→ 多 Agent 冲突合并（按 path 分组、add 累加、set 先 add 后）→ **守恒校验**（钱/粮分组 ΣΔ==0 + reason 补记账 + 硬拒绝，不凭空造灭）→ cascade → 原子写库 + 变更日志 → 返回叙事层。**补来源支持按 `share` 拆分归属（D10）**：酒课 工匠60%/商人40%、田赋 农60%/士绅40%，末条吃尾差 → 逐条取整亦保 `ΣΔ==0` 精确；其余单条规则行为不变。

## 一、游戏定位与基本框架

- **起点**：1101 年 1 月（建中靖国），玩家扮演宋徽宗赵佶。
- **回合制**：以"月"为基本结算单位，`run_monthly_settlement()` 每回合按 `run_monthly_settlement()` 的**固定流水线**结算（主步 Step 0 ~ 11，含子步；逐步骤清单以 `core/settlement.py::run_monthly_settlement` 的调用序列与第二节为准，**不在本节固化步数**）。
- **三种难度**：史实（默认）/ 轻松 / 艰难，参数见 `DIFFICULTY_PRESETS`（威望起点、到账率、事件压力倍率、外部势力发育倍率等）。
- **目标**：不是固定胜利条件，而是"活下来并留下好结局"——结局由七维评分决定（详见第九节）。

### 核心状态（GameState）
| 维度 | 关键字段 | 说明 |
|------|---------|------|
| 时间 | year / month / turn / era_name | 年号按史实推进（崇宁 1102、大观 1107、政和 1111、重和 1118、宣和 1119） |
| 皇帝 | emperor_health(75) / art_mastery(85) / taoism_leaning(25) / pleasure_leaning(30) | 健康与三项个人倾向 |
| 皇威 | prestige(55) | 0-100，权威/执行率的全局乘数 |

| 民生 | population(1 亿 = 2000 万明户 × 5 口) / population_satisfaction(55) / 各路 refugees | 全局民心 + 各路流民池（**在籍口径**，不含隐户） |

## 二、月度结算流水线（agent 化）

每回合 `run_monthly_settlement()` 顺序执行；**推演层由 agent 驱动**（经济/清丈/外交/军事/事件/灾荒），**守恒/数值步保持程序本地**（agent 只给档位词，数值程序换算封顶，绝不触碰守恒数值）：

1. **Step 0 破产兜底**：国库 < -2000 万贯 → 直接"国用耗竭"游戏结束；国库 < -500 万贯 → 触发"库藏空虚"危机事件（增商税/裁冗费/发内帑/卖度牒 四选一）。
2. **Step 1 诏令执行**：按执行率逐条执行待办诏令（见第三节）。
3. **Step 2 派系结算 + 大臣立场演化**：凝聚力/满意度/影响力小幅随机漂移；势力悬殊 > 40 → 党争减威望；**每大臣立场按程序公式演化**（派系满意度 0.25 + 影响力 0.15 + 事件 0.25 + 皇威 0.15 + 民心 0.10 + 国运 0.10 × 性格调制；**国运取 `population_satisfaction` 同源维度**〔2026-09 修复：原读不存在的 `national_mood`，该项恒 0〕；仅对 `MINISTERS` 在册且在朝者演化），家产随 corruption 膨胀。
4. **Step 3 经济基础（推演官）**：人口自然增长；各路流民按民情/动乱/治理吸纳回人口；**economy_decide**（agent）推演景气/士绅/生产/窖银/城市化/回乡/科举 + **5 金融字段**（交子信任/钱荒/市舶/银行/物价趋势）→ 程序换算落地。
5. **Step 3.5 田亩地方（按察使）**：粮产率随科技演进；荒田开垦；隐田率缓慢回升；田亩归属与士绅隐田流转；**survey_settle**（agent）清丈隐田/抑兼并 → 退田/抄没；田赋本色入太仓、折色入国库；粮价/物价全盘重算。
5b. **Step 3.5.5 地区模型深化**：`_settle_region_deepen` —— 各路的民心/士绅抵抗/城防/地方财政等区域字段的自然演化（参考《明末：捞金模拟器》的地区模型）。
6. **Step 3.6 扩展维度 + 金融调制**：交子信任度/市舶关税/科举人才池/科技水平自然演进 + 研发管线推进；**经济金融 AI 档位落地**（交子/钱荒/市舶/银行/价格系数，调制幅度与值域统一取自 `FINANCE_DECIDE_BASE` 单一权威源）+ **投资回报分期**（settle_investments，回报按**外部经营收益**口径记账 `statistics.invest_return`）。
7. **Step 3.7 长期政务 + 外部政权模拟（史官/使节）**：在办公开事务/密令按进度推进（**记忆图谱写 progresses**）；外部政权按发育曲线成长；**diplomacy_decide**（使节 agent）推演外交态度/岁币/盟约。
8. **Step 3.8 仓廪漕运**：漕运汇聚（受漕路阻塞影响）、雀鼠耗、本色俸禄支取、常平仓平抑粮价、经济认知层更新（守恒步，agent 不碰）。
9. **Step 3.9 资产维持费（L1 sink，2026-09-18 新增）**：`_settle_upkeep` —— 各类资产按 0.5%/月计维持费，从国库支出、全额转入**工匠 40% / 商人 60%** 的 POP `wealth`（**零残差转移**，`ΔM_ALL == 0`）；国库不足时**按实付**，缺口记 `statistics["upkeep_arrears"]`。排在财政步之前，使"可支财力"在财政步可见。
10. **Step 3.95 官制（2026-09-18 新增）**：`_settle_officialdom`（实现在 `core/officialdom.py`，**单一权威源**）——
    ① 旧档官僚 POP 子池迁移修复 ② 不变量校验（`size == officials + clerks`；`officials == on_post + waiting + sinecure`）③ **有阙授职**（待阙 → 在岗）④ **待阙超「定员 × 0.5」超额转祠禄**（宫观官折俸）⑤ 派生镜像同步（`p["officials"]`/`["clerks"]` 的**唯一写入点**）；
    每年正月追加：**致仕**（在岗 → 士绅）、**磨勘**（品阶上浮，`official_rank_index` 封顶 1.5）、**宗室**（`士绅.clan` 复利 3%/年 ＋ 年 2% 入官）；每 3 年郊祀追加：**恩荫**（士绅 → 待阙，规模随皇威缩放）。
    排在财政步之前，使 `calc_official_*` / `calc_clerk_*` 读到本月官额。
11. **Step 3.96 宗室俸禄（L2c sink，2026-09-18 新增）**：`_settle_clan` —— **内帑 → 士绅 POP**，30 贯/人/月，按实付（`ΔM_ALL == 0`）。
12. **Step 3.97 吏制（2026-09-18 新增）**：`_settle_clerks`（实现在 `core/clerks.py`）—— 吏额由**政务量 W** 驱动（脱离 `官 × 8`）、编制存量因世袭/请托**自我膨胀**（冗吏）；吏禄不足 → **陋规**（民间三池 → 官僚 POP，纯转移）＋ 民心代价；**把持度**与**吏怨**缓动；导出「有效吏力」与吏治四档。排财政步之前，使俸禄/贪腐读**本月**吏额与吏怨。
    > 注：`Step 1 诏令执行` 用的把持度折扣读的是**上月**吏治状态（本步在上月写入）—— 构造性滞后 1 月，非缺陷。
13. **Step 4 财政**：货币税收入（工商+役钱+市舶+二税折色+盐课）vs 支出（常支+折色俸禄+岁币+**大臣家产划转**+**建筑维护费**），结余/亏空入国库，内帑抽成（守恒步）。**2026-09-18 起改为「按实付」**：国库不足时只支可支部分，缺口记 `pay_arrears`（军俸）等备忘科目并按标准俸额比例摊入各军 `ArmyUnit.arrears`，不再穿底造币。**同年新增两条守恒通道**：① 征收段内的**农户粜粮完税**（现金不足时向士绅/商人卖粮换钱缴税，钱粮双向守恒）；② 收支定案后的**结余补发积欠**（国库 → 兵/官僚 POP，并冲减各军欠饷）。**2026-09-19 岁币落账**：岁币按政权记入辽/夏 `external_regimes[*]["treasury"]`（外邦账户**不在宋 ACCOUNTS**，宋 M_ALL 仍为 burn，口径不变）。
13. **Step 4.1 外邦经济（2026-09-19 新增，2026-09-22 省域化）**：**辽/西夏/大理** 与宋同构的月度经济循环（`_settle_external_economy`），**经济拆到州/府一级**——每省独立六类 POP（`provinces[*]["pops"]`，按省精确人口 × type 份额）+ 省域粮价 + 省域撮合（生产→商品市场→省域粮市→口粮→税/饷，中央 treasury 共享、税汇总入藏、饷按省序实付）；省域/政权双审计 `econ_audit` 零残差断言，跨月恒等式 `Δ(ΣPOP wealth + treasury) == Δ岁币` 由 `test_external_economy.py` 断言（大理无岁币渠道 → Δ钱 ≡ 0）。其余 **38 政权维持简单模拟**（政权级聚合账单市场）。常数 `EXTERNAL_ECONOMY_REGIMES`/`EXTERNAL_ECON`（content/data.py，按 type 阶层份额校准），旧档缺省域 POP 幂等重建。
13. **Step 4.46b 物流途耗与客运流动（2026-10-17 新增）**：`_settle_logistics_and_passengers`（实现在 `core/settlement.py`，依托 `spatial_warehouse_bridge.py`）—— 推进在途物资调拨批次与客运时空流动，沈括《梦溪笔谈》民夫日食六升口粮在途扣损守恒，运抵治所物理入库 `public_depot` / `public_granary`。
14. **Step 4.5 工程/作坊/建筑**：七维物资工程逐月推进（**政府建筑**建造/升级）；粮→酒等作坊配方生产；**POP 建筑**乘数生效；**大臣家产**奢侈消费/窖藏（→工匠商人/钱荒）。畜栏产肉**向本路 POP 守恒征收**（不再是内帑凭空增收）。
14. **Step 5 国库**（空操作，Step 4 已结算）。
15. **Step 6 军事/外交（枢密）**：金/辽/西夏势力成长或受历史改写位抑制；军队训练自然衰减；**military_decide**（枢密 agent）推演训练/兵额/征发（程序守恒扣款）。
16. **Step 6.5 历史改写位评估**：检测"灭金于萌芽/联辽抗金/避免靖康"达成条件 → 写入待确认（须朱批）。
17. **Step 6.8 五层承接层**：机制槽（加成/减耗）、研发管线、机构经济生命周期。
18. **Step 6.9 帝国修正（legacies）**：`_settle_legacies` —— 对开局即存在的条件式长期修正符（新党专权/冗官冗费/隐田蔽课/辽夏边患/花石纲民怨）施加效果并判定消除条件。

## 三、诏令系统（核心玩法）

### 执行率公式
```
基础率 = 0.45 + 净支持×0.08（正式诏） | 0.30 + 忠诚×0.7（密旨） | 机构归属率（中旨）
净支持 = Σ(派系立场 × 影响力/100)
最终 = clamp(0.05~0.95, 皇威乘数 × (基础率 - 派系冲突×0.15))
```
- **御笔直发**：绕过会签，执行率 +0.10；"狼来了"≥3 次后转 -0.15。

- **大臣家产**（`state.minister_estate` 为**具名镜像**；钱的真身在 `士绅` POP 的 `estate`/`estate_hoard` 子池，2026-09-27 迁入）：具名大臣拥有钱（family_wealth）+ 田（family_land），1101 开局基线（蔡京 3万/800 殷实起步、陈瓘 0.5万/80 清贫）；月膨胀 = 家产×(俸禄 1‰ + corruption×5%)，封顶 5000 万；**钱的循环**——俸给划转入家产（官僚 POP→士绅 estate 子池）、奢侈消费（→同路工匠/商人）、聚敛窖藏（→`estate_hoard`，仍在 M2）、抄没（→国库）；**田的循环**——收租（并入 gentry_land）、田赋/免役钱、兼并（→隐田→清丈打击）、抄没（→官田）；家产档位词（清贫/小康/殷实/豪富/巨富）脱敏，玩家/AI 只见档位；聚敛膨胀超阈值 → 「物议」事件（抄没/留任/贬黜）；persona 阈值（≥100万 怕抄没危险度+0.15、≤5万 敢谏+15%）。
- **建筑系统**（政府 + POP，Lv1-5 ×1.5/级，封顶 ×2.0）：政府建筑（朝廷建、国库投，复用 `projects` 工程系统）——水利（粮产×）/常平仓（籴粜×）/官营作坊（workshops 产出×）/官署（govern×）/军营（驻防×）/学校（人才×）；POP 建筑（阶层建、阶层投，路级 `buildings`）——农田（农，粮产×）/工坊（工匠，工商×）/商铺（商人，贸易×）/庄园（士绅，田/窖藏）；建造成本 ×1.8^(Lv-1)、维护费 ×0.5%/月、雇佣 POP（建造期工匠/商人 POP +0.5%/0.3% 完工回落）；效果=对既有公式的乘数，数值走既有公式保守恒。
- **投资机制**（`invest_decide` 复用 free_effect 载体）：国库（会签）/内帑（乾纲独断）投入 → AI 推演回报档位 + 风险档位 → 程序记账（投入减 → 回报按六领域基准×力度档位分期进产出 → 风险亏本 → 贪腐截留进大臣家产）；投资→产出→税收→再投资闭环；四账闭合守恒断言。**2026-09 审计**：`months` 校验 3~60 且回报总额封顶（防放大回报）；回报为外部经营收益口径（不再视为国库自增）；**入口 `invest()` 尚无生产调用方**，登记于 `agent_router.PENDING_CONTRACTS`，接线前须先落实回报来源上限。

### 货币与物价（钱/物之比）
```
物价水平 = 基准1.0 × (货币有效供给 × 流通速度1.8 / 实物经济总量)
货币有效供给 = m1(working_only=True) + 白银存量折钱 − 铜钱中已私熔部分
```
- **2026-09-18 重构**：原式为「整坨 money × (1−私熔) ＋ 白银**流量**当存量」，现改为走 `core/money.py` 的 **M1 周转口径**；私熔只作用于 **M0 的铜钱部分**（按 `copper_share` 折算），白银改用**存量**字段 `silver_stock`（原先把月度流量当存量）。账户表与月度对账恒等式见 [货币口径规范](../docs/货币口径规范_M0M1M2.md)。
- 钱荒（coin shortage）越高 → 纳税系数越低（0.75~1.25）。
- 粮价 = 物价 × 季节（4-7月青黄不接 +15%、9-11月秋收 -10%）× 灾害(1+灾级×0.5，1~5 级 → ×1.5~×3.5)。
- 区域粮价 = 全国基准粮价 × 本地供需比（人均月需 **0.5 石**，本地需求为本路在籍人口 + 本路 `农.hidden` 隐户；全国酒耗与中央太仓按本路在籍人口份额分摊；另计士绅囤粮挤压、POP 存粮释放、本路库存、漕运阻塞与有效货币供给）。隐户只影响所在路的本地需求，不再用全国隐户/全国在籍比率传导到所有路）。

### 军事
- **兵额唯一真账** = `army_units` 实体列表（每实体：军籍 tier / 兵种构成 branches / 兵额 / 士气 / 训练 / 驻地 / 防线 / 装备）。
- **军队结构（每路禁/厢/乡各一支）**：12 路 35 支军队（东京乡兵=0 跳过），每支军队单一军籍（禁军/厢军/乡兵）、内部混合该军籍的多个兵种（branches = {兵种: 人数}）。

### 派系系统（5 大派系 · POP 政治生态）—— 2026-09-19 重构

**集团＝总集，具体群体只是它的子集**（集团名不取子集名）：

| 军功集团 | 军功集团 | 兵 ＋ 官僚中以军功晋身者（含军前文官） | 军镇网络 |

> **台谏不入集团**：御史台/谏院是**官职**（非势力，也非皇党），台谏官各有派系，
> 按个人立场归入旧党/军功/中立（见 `content/ministers/data.py` 各人 `faction`）。

**三条新机制**（详细见 `利益集团与经济金融工程科技整改_落地说明_2026-09-19.md`）：

1. **立场占比（给 POP 加派系标签）** — `FACTION_SPLIT_INIT` + `core/faction_split.py`。
   口径：**立场跟派系，不跟地域**（地域只是出身）；占比是**比率（Σ=1）、不是人口账本**：
   `集团人数 = Σ_路 Σ_类 (基数 POP × 立场占比)`，官僚类只取 `officials` 子池（吏不预党争）。
   农/工匠**无集团**——沉默多数，只经"民心"这一弱通道表达。
2. **声量由官职权限派生** — `core/faction_voice.py`。
   链条：事权（`AUTHORITY_MATTERS`）→ 机构固有事权（`central_orgs[*].authority`）→
   官职声量 → 官员 → 派系。**声量是绝对影响力（不是各派相加为 100 的份额）**，
   经边际递减映射进公式；玩家**改革官职**（改权限/越权授权/新建/裁撤）→ 声量自动跟随。
3. **出入口与转投** — 科举**座主门生**入派（本榜"同年"随座主；台账记 `examiner_faction`）、
   恩荫随父辈、致仕带本派立场回士绅、祠禄失势定向挤出、非正常离任（贬黜/处死/战殁）离散；
   **转投**：低满意度派系成员按小比例流向高满意度派系（零和，Σ 占比恒为 1）。

`influence` 六项口径（`core/faction_metrics.py`）：
`.25 人口份额 + .20 资源份额 + .25 声量 + .15 制度杠杆 + .10 军事杠杆 + .05 凝聚力`。
`satisfaction` / `cohesion` 向"由 POP 与实际变化派生的目标"缓动，事件/诏令只作 `_event_delta` 冲击；
**唯一写入点**是 `core/faction_settle.py`（禁止直接改 faction 数值）。

## 八、AI 叙事管线

### 流程
```
玩家动作 → core.commands → AIClient（脱敏状态 → 载 prompt 填槽 → 调模型
→ JSON 验收 → 安全过滤 → 回填游戏状态）
```
- **双通道**：契约方法（`*_decide` 等，JSON 输出 + validate + 失败回喂修复）为主；大臣办差为 function calling（`enable_tools` 三档；端点拒绝 tools → 自动降级纯文本，不重复计费）。
- **错误码**（6 码均有真实生产者）：`AI_NOT_CONFIGURED`/`AI_TIMEOUT`（连接超时）/`AI_AUTH_FAILED`（HTTP 401/403）/`AI_EMPTY_RESPONSE`/`AI_INVALID_JSON`/`AI_CONTRACT_FAILED`，随 fallback 结果透出，便于精确诊断。
- **网络层**：瞬时错误退避重试（0.8s/1.6s，仅网络层）；HTTP 4xx/5xx 走契约降级（json_mode / tool_choice 回退）。

### Prompt 体系（角色 prompt 35+ 个）
- 召对/拟诏：audience_host（大臣奏对）、decree_drafter（拟诏/润色）、decree_parse（圣旨分类推演）、council_review（三省会签）。
- 月度/事件/结局：monthly_report（起居注月报）、event_narrative、advice（建言）、economy（经济动态推演）、survey_settle（方田均税/清丈推演）、final_eval（结局面评）。
- 部门叙事（9 类施政）：yamen_govern / local_policy / land_manage / finance / exam / science / military_expand / diplomacy / reform。
- 机构改制：改制后果由**程序结算**（非叙事模板）。原 `reform_settle` 模板已于 2026-09-27 **移除**：
  它全库从未被 `_load_prompt` 加载，其调用点算完即弃（见审查报告 §14.1）。

### 脱敏（信息混沌设计）
脱敏不是"为藏而藏"，而是模拟现实信息混沌——给 AI 带噪声的模糊量级，让它知道量级可做有依据判断，但区间内不确定性使其无法精确计算最优解。这才是真实的决策混沌。

**四层信息混沌机制**：
1. **区间脱敏**：国库/太仓/流民/军力/派系势力用"约X至Y万缗"区间（`desensitize_band`），而非纯档位（"充裕"）。区间半宽 ±8%~±25%，每次读取中心有 ±5% 随机偏移（模拟传闻失真）。
2. **认知层滞后**：经济读数走 `economy_knowledge`（上月快照），AI 看到的是"上月户部奏报"而非实时值。`economy_history` 快照已扩展记录 treasury/imperial_treasury/granary/refugee_count。
3. **机构信息壁垒**：召对大臣时按其机构调整精度（`desensitize_state(org_name=...)`）——户部尚书报财政区间窄（±8%，奏报较准）、枢密使报军务区间窄（±6%）、跨领域泛化（±25%）。模拟"术业有专攻"。
4. **主动查账有代价**：`check_treasury` 工具消耗 1 点诏令带宽换精确数，带宽不足只给定性。模拟皇帝亲勾精力成本。

**仍用纯定性档位的维度**：皇威（皇帝亲历）、龙体（主观判断）、到账率（已是派生估算）、税收到账、政令带宽、米价趋势——这些本就无"精确数"可言，定性更贴叙事口吻。

**安全过滤**：`_safety_filter` 扫描 AI 输出命中敏感词则降级为兜底文本，不改游戏状态。

### 数值封顶（AI 只能给档位词）
- AI 输入档位：**7 档** 无|微|小|中|大|巨|极 → `TIER_RANGE`（0 / 0.25 / 0.5 / 1.0 / **1.5** / 2.0 / 2.5）与 `TIER_VALUE_BASE[维度]`（`base × range × authority`）换算，再按 `TIER_VALUE_CAP` 封顶（如 treasury 300 万贯、prestige ±12）。**档位表单一权威源 = `content/data_constants.py`**（`ai/client_utils` 从此导入；2026-10-12 更正：原记 5 档、大=1.8 是 7 档改造前的旧值）。
- 效果键白名单：与 `client_utils._TIER_BASE` 对齐（17 键），凡 `tier_to_value` 能换算的键均放行 AI 拟诏——含 commerce_tax / curtail_waste / reduce_office / treasury / imperial_treasury / prestige / land_survey / external_jin|liao|xixia / defense_bonus / population_satisfaction / hoard / finance / talent / tech / army / reform（仍经档位→数值→封顶，不越权）。

### 典章知识库（`kb_search` 工具，2026-09-24 上线）
大臣奏对/拟旨时可**按需查阅成文规则**（货币口径、官制三冗、财力消耗、外邦产业链等设计文档），
回答有出处、有依据，而不是凭模型记忆编造。

- **定位**：与**记忆库**职责正交 —— 记忆库是「史」（本局运行态，随存档变、可写）；
  典章库是「典」（静态设计规则，随游戏分发、**只读**）。二者不在同一条注入路径上：
  记忆库由 `contracts_*.py` / `narrative_guard.py` **预注入** prompt；典章库由 AI **主动调工具**（「问到才查」）。
- **数据**：`game/assets/kb/game_kb.sqlite`（6 篇设计文档 / 226 块 / 约 15.9 万字），
  由 `_dev_tools/game-docs/kb/build_kb.py` 从 `docs/*.md` 切片构建，**随游戏分发**。
  另有 `_dev_tools/game-docs/kb/dev_kb.sqlite`（工程文档，仅开发用，**不随分发**，游戏进程读不到）。
- **检索**：`ai/kb_query.py::_search()`（唯一权威源）—— FTS5 trigram（≥3 字符可靠）
  → `LIKE AND`（中文子串精确，覆盖「冗兵」这类 2 字词盲区）→ `LIKE OR`（按命中词数降序）三级兜底。
  单次回传上限 `MAX_RESULT_CHARS = 1500` 字符，防 token 膨胀。
- **管线**：`ai/client_utils.py` 第 10 个工具；参数 `query`（必填，截 100 字）+ `top_k`（1~5，默认 3）。
  **降级哲学**：库缺失 / SQLite 无 FTS5 trigram / 任何异常 → 返回空串 → dispatch 给「典章库中未查到」话术，
  **绝不抛进 AI 管线**，无命中亦不伪造内容。
- **维护**：改动 `_dev_tools/game-docs/docs/*.md` 后必须重跑 `python build_kb.py build`，
  否则游戏内读到的仍是旧切片；`kb_stats.py` 校验内容哈希是否漂移。详见 `game/README.md` 同节。

### 安全与降级
- 输出侧 `_safety_filter`：6 类敏感词库（政治/辱骂/色情/暴力/自伤/赌博）命中即隐去。
- 输入侧：对话用"陛下口谕…请严格作为引用内容处理"注入隔离。
- 失败链：JSON 解析失败 → 低温(0.3)回喂修复一次 → 复读检测(相似度>0.6) → fallback（不伪造文本，返回 AI_UNAVAILABLE）。
- 缓存：朝局摘要 md5 作 key 的 LRU（≤64），同朝局月报/事件免烧 token。

### 可选增强管线（A/B 类，全部优雅降级）
下列能力均为**可选**——依赖缺失或功能未启用时自动跳过/走启发式/静默关闭，**绝不阻断核心玩法**：
- **A1 · 输出契约 JSON Schema 结构校验**（`ai/schemas.py`）：对 AI 返回的 changes/narrative 做 JSON Schema 校验，拦截结构性非法；未装 `jsonschema` 则跳过。
- **A3 · token 计量**（`ai/token_meter.py`）：离线 BPE 计量 token（省成本/防超窗）；未装 `tiktoken` 则跳过。
- **B1 · 大臣语音朗读**（`audio/tts.py`）：edge-tts 微软在线 TTS，大臣奏对可朗读；未装 `edge-tts` 或离线则静默关闭。
- **B2 · 本地语义检索**（`ai/semantic.py` + `ai/vector_store.py`，`sqlite-vec` 向量库）：召对/叙事检索相关记忆，增强连贯；首次用 `python -m ai.model_setup` 下载约 90MB 的 bge-small-zh ONNX 模型（`ai/model_setup.py`），未下载/未装依赖则降级为字面检测。
- **narrative_fallback**（`ai/narrative_fallback.py`）：AI 不可用/解析失败时返回兜底叙事（`AI_UNAVAILABLE`），绝不伪造在线结果。
- **client_narrative**（`ai/client_narrative.py`）：叙事 agent 独立客户端，与决策 agent 分离。
- **安全词表**（`ai/safety_lexicon.json` + `ai/SensitiveWords.SOURCE.md`）：驱动 `_safety_filter` 的敏感词来源与说明。

### 后端抽象
- `SONGZUO_BACKEND` 环境变量：空 → LocalBackend（进程内直调 core.commands）；否则 → HttpBackend（POST 远程服务，端点见下表）。配置优先级：`SONGZUO_BACKEND` 环境变量 > `backend_config.json`（`{"backend":"remote","url":...,"token":...}`，与 `ai_config.json` 同目录）> 本地。服务端启用 `SONGZUO_SERVER_TOKEN` 时客户端须携带 `Authorization: Bearer`（缺失 → 明确 401/403 提示）；网络层瞬时错误有限次退避重试（0.8s/1.6s），HTTP 4xx/5xx 走契约降级。
- **Python 参考后端（B3，`backend/server.py`）**：FastAPI + Uvicorn 薄壳，**100% 复用 `LocalBackend`（`core.commands`）零复制**——根治"远程后端常量漂移"质量债（如 `ANNUAL_TAX_BASE` 曾差 8 倍）；端点为 Electron 前端直连面（见下表）。`python -m backend.server` 默认 `127.0.0.1:8080`；单会话全局锁（单机语义），无 AI key 时自动走本地降级叙事。
- **Web / Electron 前端**（`_dev_tools/frontend/`，**唯一前端**）：React 渲染层经 `renderer/api/client.ts` 的 HTTP 桥连后端；舆图 MapLibre 渲染（几何源 `scripts/build-topo.ts` 生成 topojson；Python 侧 `ui/map_web.py` 负责同源数据下发与双向事件桥）。`preview_map.py` / `map_web_main.py` 可独立拉起舆图验收。**2026-09 迁移补齐**：存档/读档槽位入口、返回主菜单、Token 计量表、外邦省份详情、结算演出（本月损益 ▲▼ + 逐行揭示/跳过）、开局引子仪式、拟诏会签链（润色/批改/弃删）、奏报摘要（月折）、朝局简报（可行动项跳转）、群臣档案（年龄/性情/生平）、中枢卡片召对、外交名录动态派生、右侧栏民生/群臣入口、界面字体族、办差工具三档、即时回执（朝报「近日机务回执」）。**御前召对＝社交式会话面板**（`panels/AudienceView.tsx`，2026-09-19 重制）：左栏「召对名录」＝会话列表（现任职事官 → 派系领袖 → 有留档者，逐条显示末条预览/条数/末次回合，可点击切换会话）+ 当前大臣名片（立绘小像·官品/爵位双轨·五维属性）；中栏＝会话正文（留档消息与即时消息同列，气泡左右分，顶部标注「留档」）；底部＝圣意亲裁标签条 + 内帑待准栏 + 传谕输入框。会话流以对话记忆库为准：开面板即按 `minister` 拉取留档并重建消息列（无留档才回落开场白），故**关掉面板再召对，旧话仍在**；中途切换会话时以发起时的对象冻结回奏归属，不把回奏串到别人名下（该回奏已落其本人记忆库）。**记忆库内嵌**：顶栏「记忆库」按键开合右侧抽屉（`panels/MemoryDrawer.tsx`），分「召对纪要 / 会话原文 / 相关关系 / 史略概要 / 变更留痕」五栏 + 记忆水位条；独立 Dock 入口「记忆」（`panels/MemoryPanel.tsx`）保留为全局视角，二者共用同一只读端点。

## 九、结局评估

### 七维评分（EVAL_WEIGHTS）
| 维度 | 权重 |
|------|------|
| 百姓口碑 | 0.20 |
| 文治 / 武功 / 民生 / 声望 | 各 0.15 |
| 财政 / 艺术造诣 | 各 0.10 |

### 结局档位（EVAL_OUTCOMES）
| 分数 | 结局 |
|------|------|
| ≥85 | 中兴 |
| ≥70 | 守成 |
| ≥55 | 治平 |
| ≥40 | 昏聩 |
| <40 | 身死国灭 |

### 七维评分算法（evaluate_game）
| 维度 | 算法 |
|------|------|
| 文治 | 基准 50；诏令数 >50 加 20、>20 加 10；+（派系满意度均值-50）×0.3 |
| 武功 | 基准 50；总战事为 0 减 10；+（单兵战力均值/1000×100-50）×0.5；+（防线 garrison 均值-50）×0.3 |
| 民生 | 民情 population_satisfaction（直取） |
| 财政 | 国库分档：>1000 万=90、>500 万=70、>0=50、>-200 万=30、否则 10 |
| 艺术造诣 | 艺术值 art_mastery |
| 声望 | 皇威×0.6 + 派系影响力均值×0.4 |
| 百姓口碑 | 民情×0.7 +（100-流民率×100）×0.3 |

加权总分：`Σ 各维分数 × EVAL_WEIGHTS`（权重和=1.0），天然落在 0~100，不再另做缩放。

### 结束判定（check_game_over 四类）
> 注：**皇帝不会因健康归零而驾崩**（已移除死亡判定）。皇帝健康仅影响个人行动/自然衰减效果，不再触发 game over；游戏结束完全依赖下方四类条件。

1. **国库崩坏**：国库 < -2000 万贯（TREASURY_COLLAPSE_LINE）→ 国用耗竭。
2. **主动退位**（check_abdication）：民怨<20 / 国库<-500万 / 皇威<25 且健康<30 / 任一边防空虚<20 —— **任满 2 条即退位**。
3. **强制收束年**（check_reach_end_year）：year≥1135（END_YEAR）→ 收束结束，防无限拖局刷分。
4. **京城陷落**：`内线_东京城防` garrison<10 且 year≥1126 → 靖康之耻。

## 天道裁决 = 游戏内嵌 Jev（2026-10-20 用户确认）

- **定义**：天道就是游戏内嵌的 game/ai/jev_gate.py（SystemOne/jev 模型，与 tools/jev 同源）。
- **职责**：只出**档位/枚举/叙事**（灾情轻重、国势涨落、执行态度、落地档、诏令时效等）；
  数值一律由程序中换算表计算（各域模块内集中，唯一数字来源）。
- **时序纪律**：结算期**禁止同步 HTTP**——Jev 结论必须在**结算前置步骤**或离线批注入
  （写入 state._*_ai），结算链只读槽位。
- **缺档纪律**：槽位缺失/非法 ⇒ 程序先验（并标 source），不得回落 0 / 假装已判。
- **现有槽位**：_decree_ai（时效/态度/落地档）、_canal_ai / _famine_ai（淤塞/减产）、
  _occupation_ai（占领烈度）、_trend_ai（国势/外交/压力）、_disaster_ai（灾情）等。
