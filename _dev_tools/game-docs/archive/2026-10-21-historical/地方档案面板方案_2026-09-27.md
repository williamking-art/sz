# 《宋祚》地方档案（州府级 → 省级 → 全国）方案 v2 —— 2026-09-27

> **用户已定口径**：① **从州府级做**（各州府面板汇总即省级）；② **隐田/隐户按原设定**（朝廷只知约值，
> 清丈才知真数）；③ **军政按钮对应省级（路）**，故**另开新面板**，与州府面板整合后即全国视图。
>
> **本文只出方案，不改代码。** v1 的板块映射仍有效，v2 按上述三点重构层级、数据来源与分期。

---

## 0. 层级与聚合链（先定骨架）

```
州/府（面板一级单位）  ──汇总──▶  路（= 省，游戏单位 game_unit）  ──汇总──▶  全国
   ↑ 静态底盘：content/demography.py           ↑ core/region_brief.py 逐路行      ↑ region_brief 全国汇总（已有）
   ↑ 动态量：按份额从「路」分配（只读派生）      （已有 population/mood/unrest/
                                              city_defense/tax/grain/risk…）
```

**已核实的可用件**（不用新写）：

| 环节 | 现成实现 | 证据 |
|---|---|---|
| 路 → 府/州的**静态拆分** | `content/demography.py::split_circuit_demog()`（按 `population/households/land/grain/monthly_tax` 五维 + 面积/治所权重） | `demography.py:93,108`；`_weighted:70`、`_split_dim:80` |
| 全府/州表 | `demography.py::prefecture_demog()` | `:164` |
| 外邦省域 | `demography.py::regime_prefecture_demog()` | `:123,185` |
| 路级注册表（type/治所/成员/经纬） | `content/geo_admin.py::CIRCUIT_INFO`、`members_of()`、`all_city_points()` | `:39,1013,1020` |
| 游戏单位 ↔ 行政路 | `geo_admin.CIRCUIT_INFO[*]["game_unit"]` | `:41`（`"京畿"` ↔ `"京畿路"`） |
| 路级动态读数 | `core/region_brief.py::build_region_brief()` | `:181-203`（`mood/unrest/city_defense/public_support/literacy/grain_*/tax_month/army_*/risk_*`） |

**核心设计判断**：州府级的**静态底盘**（人口/户/田/粮/月税基数）已由 `demography` 派生；
而**动态量**（民心/动乱/城防/POP 子池/建筑/驻军）**只存在于路级** `state.prefectures[game_unit]`。
→ 州府面板的做法是**按 demography 的同一份额把路级动态量分配到府**（只读派生、可复现），
**不给每个府新建账本**（POP 挂载律条④），并断言 **Σ(各府) == 路级值**（守恒）。

## 2. 隐田/隐户：按原设定（**约值 + 清丈解锁**）

- **面板显示**：不给真数，给**估计区间/档位词**（复用 `ai/desensitize.py` 的档位映射），
  文案如「隐田 约七百万亩（**未清丈，据税籍推估**）」，与 `农.hidden` 真值**分离**。
- **解锁手段**：`survey_settle` 契约（清丈）执行后，把该路/府记为**已清丈**，面板才展示真数
  —— 即 POP 改良 §4.3「中央只知约值、清丈才知真数」的中央-地方博弈落点。
- **实现要点**：约值必须是**确定性派生**（同一 state 同一结果），不得每次刷新抖动；
  建议 `hidden_land × 系数` 或按 `mood/govern` 修正的带宽生成。
- ⚠️ **需确认**：既存是否有"某路已清丈"标记（若无，建议复用既有 decree/situation 标记，**不新增字段**）。

## 3. 军政：**省级新面板**（用户口径③）

州府面板**不含**军令按钮（避免"在府里下路的令"的错位）；军令集中在省级「地方军政」新面板：

| 参考图按钮 | 本游落点 | 说明 |
|---|---|---|
| 地图调度 / 调动驻军 | `commands.py::_apply_military_dispatch` | 已有 |
| 扩编 / 裁撤 | 兵额经 `army_models` + `approve_ai_action` | ⚠️ 兵 POP `size` 是 `army_units` 的**重聚合派生量** → **不可在此直接 move 人口**（POP 改良 §6.1 已查明） |
| 拆分 / 合并 / 整编 | 需确认 `army_units` 是否支持下级编制 | ⚠️ §5-② |
| 换帅 / 改名 | `officialdom`/`minister_profile` 指派 + `registries` 番号 | 需确认既有指派入口 |
| （信息）兵力/饷/士气/欠饷 | `army_units`（`army_models.py`） | 已有 |

**"整合起来就是全国的"**：省级军政面板即**该路**；再加「**全国军政总览**」页签
（各路军额/总饷/欠饷，数据 = `region_brief` 的 `army_cash_month`/`army_grain_month` 求和 + `army_units` 聚合）
→ **州府（民政）＋ 路（军政）＋ 全国（总览）** 三层合起来即完整视图。

## 6. 第四节待确认项的**落地口径**（用户已定：建筑/治安叫法差异 + 走地方修正）

### 6.1 城防 / 动乱 → 本游就叫 **城防 / 治安**，杠杆是**既有建筑与治理**

| 参考图 | 本游字段 | 证据 | 面板建议叫法 |
|---|---|---|---|
| 城防 130 | **`city_defense`**（0–100） | `game_state.py:866` 初始化（按路类型：边镇高/腹里低/京畿最高）；`settlement_econ.py:421-429` 随军备/边患演化；**`region_brief.py:192` 已输出** | 「城防」 |
| 动乱 0 | **`unrest`**（0–100，**越高越差**） | `game_state.py:816` 默认 15；**`region_brief.py:193` 已输出**；本游已有玩家语汇与门槛：`content/data.py:724 PROJECT_SECURITY_UNREST = 60`（"**治安口径**：本地动乱 > 此值 → 工程降效"），`settlement_tech.py:295` 在用 | **「治安」= 100 − `unrest`（越高越好）** —— ⚠️ 不可把 `unrest` 直接标成「治安」（极性相反） |
| 民心 100 | `mood` / `public_support` | `region_brief.py:188,190` 已输出 | 「民心」 |

- **杠杆 = 本游既有建筑与治理**（不新增机制）：政府建筑（军营/官署/水利…，`projects` 系统）、POP 建筑（`p["buildings"]`）、
  `p["govern"]`（治理）与 `p["mood"]`（民心）；工程遇高动乱按 `PROJECT_SECURITY_UNREST` **降效不静默完工**（`settlement_tech.py:163,295`）。
- **极性口径（用户 2026-09-27 纠正）**：**凡叫「治安」的数值必须越高越好**。故面板显示
  **`security = 100 − unrest`**，并**由 `core/region_brief.py` 单点派生**（前端不自算 `100−x`），
  与既有门槛对齐：`PROJECT_SECURITY_UNREST = 60` ⇔ **治安 < 40 → 工程降效**（同一含义，换了极性）。
  档位建议：**治安 ≥ 80 太平 / 60–79 尚可 / 40–59 多事 / < 40 不靖**。
  同时把原始 `unrest` 保留在读数里（内部与 AI 契约口径不变），仅**展示层**用治安正极性。
- **其余指标极性复核**（一次查清，避免同类错误）：

  | 指标 | 字段 | 极性 | 命名是否自洽 |
  |---|---|---|---|
  | 民心 | `mood` / `public_support` | 高=好 | ✅ |
  | 城防 | `city_defense` | 高=好 | ✅ |
  | **治安** | 派生 `100 − unrest` | **高=好** | ✅（本轮修正） |
  | 动乱（原字段） | `unrest` | 高=差 | ✅（名字表意） |
  | 士绅抵抗 | `gentry_resistance` | 高=差 | ✅（"抵抗"表意） |
  | 腐败 | （派生） | 高=差 | ✅ |
  | 流民 | `refugees` | 多=差 | ✅ |

- **面板呈现**：读数（治安/城防/民心）+ 一行「**杠杆提示**」（本路现存建筑、治理等级、在办工程），
  把"叫什么"与"怎么改"分开讲，避免玩家把派生读数当成可直接点的旋钮。

### 6.2 清丈与否 / 隐户数量 → 走**既有地方修正通道**，无需新账本

| 需求 | 既有落点 | 证据 |
|---|---|---|
| **隐田真值（路级）** | `state.prefectures[路]["hidden_land"]` —— **开局即有**，逐路给定（如 8,897,500 亩），注释"开局 = land×25%，随清丈/隐漏回升演化" | `data_geo_tables.py:61-156`；`game_state.py:818` |
| **清丈落地（隐田转正）** | `settlement_decree.py:277-280`：`hidden_land -= reduce` **同时** `land += reduce`（守恒转正）；隐漏回升 `settlement_econ.py:186 _conceal` | 同上 |
| **隐户归籍** | `settlement_imperial.py:126-143`：清丈/招抚 → 该路 `农.hidden` 减、`农.size` 增（**同额**），逐路局部守恒 | 同上 |
| **"是否已清丈"的既有判据** | **`legacy_mechanic.py:165-171`** 的 `hidden_land` 修正项：`clear_cond = _clear_hidden_land`（`land.hidden_rate < 0.2`）、`clear_desc = "清丈田亩，检括隐田（施行 land_survey）"` → **这就是"地方修正"式的既有机制** | `legacy_mechanic.py:63-64,165-171` |
| **士绅抵抗（参考图"士绅阻力 35"）** | **`p["gentry_resistance"]` 逐路演化**（清丈/抑兼并上升、治理高下降） | `settlement_econ.py:392,408-415`；`situations.py:1097` |

**结论**：面板**不需要新增任何字段**——「已清丈程度」可由 **`hidden_land` 相对开局值的下降比例** +
`legacy_mechanic` 的 `clear_cond`（`hidden_rate < 0.2`）共同判定；隐户同理看 `农.hidden` 与归籍记录。

### 6.3 ⚠️ 由此发现一个**既存脱敏缺口**（P0 级，与本面板直接相关）

`core/region_brief.py:187` 现在是 **`"hidden_land": int(_num(p.get("hidden_land")))`** —— 即
`/api/readouts::regions` **把隐田真值原样下发**给了前端。这与用户口径「隐田/隐户按原设定：朝廷只知约值、
清丈才知真数」**冲突**（前端/AI 可直接读到真数）。
**建议（P0，独立于面板）**：该字段改为**档位/区间**（复用 `ai/desensitize.py` 的档位映射），
真值仅在"已清丈"（`clear_cond` 满足）时下发；并补一条断言（仿
`test_http_snapshot_hides_estate_slices_without_mutating_state`），锁死"未清丈不得下真数"。

### 3.1 军令对象口径修正（用户 2026-09-27："军队应该是**按编制成军**的，又不是看兵种"）
