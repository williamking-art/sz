## 2. 落地内容

### 2.1 后端：只读派生视图（POP 挂载律合规）

`build_region_brief(state)` 返回 `{routes, top_risk, nation, readout_status, readout_errors}`。

**纪律遵守**（项目硬约束）：
1. **零写入**：全部数据来自 `state.calc_monthly_tax_income()` / `calc_army_cash()` / `calc_army_grain()` 与州县既有字段；测试用**深度快照**（`json.dumps(prefectures)` + `pops` + 国库/内帑/太仓/声望/货币存量）证明前后逐字一致。
2. **不新建平行账本**：所有聚合为即时计算，响应 DTO 不回写 state。
3. **口径单点**：风险算法、安全垫、口径归一化只在 core；前端只展示。

**每路新增的可解释指标**：
- `tax_month`：**到账后**月税（二税折色实收）＋ `tax_share` 占全国比；
- `army_cash_month` / `army_grain_month`：驻军月饷/月粮；
- `grain_months`：**粮储安全垫** ＝（州仓＋常平仓）÷（民口月耗 ＋ **驻军月粮**）；
- `risk_score` / `risk_label` / `risk_hints`：0–100 风险分与成因（动乱、民心、士绅阻力、城防、粮储）。

### 2.2 前端：从"文字列表"到"可决策面板"

- **风险降序**为默认：最可能出事的路排最前（对应改善建议 §4.3 的验收标准"3 秒答出哪路最危险"）；
- **真实进度条**替代旧 ASCII `█▓▒░`（民心/动乱/城防/财政，红黄绿语义）；
- **四维排序**：风险 / 民心↑ / 动乱 / 税入；
- **详情页派生解释**：到账月税＋占比、驻军月饷/月粮、存粮可支月数、风险成因、归属；
- **读数不完整提示**：`readout_status=partial` 时显式提示"数字已回落为 0，勿据此判定无税入"。

### 2.3 顺带修复：AI 报文契约（换供应商即可用）

实跑中发现：`/api/advance` 在 Agnes 上恒 400 ——
> `No user query found in messages.`

根因：`ai/client.py::_call` 在 `user_prompt` 为空且无 history 时只发 system。修复为补一条中性 user 占位（任务语义仍在 system，占位不改变要求）。修复后同一配置下错误从"400 报文不合法"变为"契约字段不符"（进入正常校验路径）。

| 14 | gpt-6-astra | 返回 `(inf, {})` 不记 partial（`readout_status` 可能误判 ok） | ✅ `_derive` 校验总额有限性＋映射类型 |

## 5. 遗留与建议

| 优先级 | 事项 |
|---|---|
| P1 | **`gemini-3.8-flash` 网关可用性复核**：本次多次 503（"订阅池没有活跃候选"），建议与其客服确认该模型路由状态；代码侧无需改动 |
| P1 | **契约遵循度**：`agnes-2.5-flash` / `gemini-2.5-flash` / `claude-sonnet-5` 均 `AI_CONTRACT_FAILED`。建议在 AI 设置页显式标注"推荐模型"，或对失败给出更具体的字段级提示（当前只有"字段缺失/越界"） |
| P2 | **请求级缓存**：`/api/readouts` 每次遍历 20 路 POP 并调 3 个派生函数；若前端高频轮询，建议按回合号缓存（gpt-6-astra B4 提及；本模块坚持不建独立账本，故缓存应放在端点/会话层） |
| P2 | **快照一致性**：派生计算与州县读取之间无版本号（gpt-6-astra A7）。当前 Web 架构下 `/api/readouts` 与结算都在同一把锁内，风险低；若改为并发读模型需补快照 |
| P3 | **面板字段继续补齐**：可加"上月增量"（需引入按回合的历史读数组，属新数据面，需单独设计） |
| P3 | 前端列表 20 行未 memo（当前规模无性能问题；若扩到百路需 `memo`） |
