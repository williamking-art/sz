### 2.1 为何都用 `drivers=["decay"]`

现有动因只有 `population`/`crowding`/`decay`/`expansion`。
官有工程**不随人口膨胀**，而是**年久失修需重建** ⇒ **`decay` 是唯一贴切动因**。

⚠️ `_validate_spec` 规定：`drivers` 含 `population`/`crowding` 时 `capacity_per_lv` 须 > 0；
本草案不含这两项 ⇒ `capacity_per_lv=0` **合法**（无容量口径，不回落 0 假装）。

## 四、🔴 阻塞项：**付款渠道错了**

### 4.1 现状机制

`build_civil_building` 的工钱来自：

```python
paid, legs = _pay_wage(state, pref, tuple(spec["payers"]), pay_to, wage)
```

⇒ `payers` 是 **POP 阶层名**（`士绅`/`商人`/`农`/`工匠`…），钱从它们的 `wealth` 扣。

### 4.2 🔴 问题

**官有营造的钱不应由民间 POP 出**。它应来自：

| 归属 | 应付款方 |
|---|---|
| 地方公产 | `prefectures[路]["local_treasury"]` |
| 国家公产 | `state.treasury` / 内帑 |

⇒ 若照草案用 `payers: ["商人",...]` 注册 ⇒ **民间 POP 被官府工程抽血**
⇒ 既**不合史实**，也**违背你在意的「民间自造 vs 官府营建」分野**。

### 4.3 建议改法

`build_civil_building` 增一条付款分支（承「口径单点」，**不新建账本**）：

```python
if spec.get("dept") == DEPT_OFFICIAL:
    paid, legs = _pay_official(state, pref, ownership, pay_to, wage)
else:
    paid, legs = _pay_wage(state, pref, tuple(spec["payers"]), pay_to, wage)
```

`ownership` 由 `dept_entity.owner_kind` 决定（`local_gov` → 地方库，`state` → 国库）。

⚠️ 这会新增一条**付款腿**，属**核心模拟**改动 ⇒ 须**口径说明 + 定向回归 + 钱账本恒等式断言**。
