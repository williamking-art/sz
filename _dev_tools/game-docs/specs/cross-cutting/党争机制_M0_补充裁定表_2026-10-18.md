# 党争机制 · M0 补充裁定表 v4.2

> 日期：2026-10-18　状态：**待审（只读核验，不改生产代码）**
> 依据：用户 2026-10-18 对 v4.1 的复核意见；v4.1 设计稿；M0 接口核验。
> 本表冻结 M1a 的开工口径；审过之前不授权任何生产代码变更。

---

## 0. 结论摘要

1. **四项「新事权」不存在**：现有 `AUTHORITY_MATTERS` 已有对应键，党争只做映射（§1）。
2. **兼任折损不再并入 `vacant_share`**：新增 `concurrent_discount_share` / `acting_discount_share`，
   守恒式扩为五项（§3）。
3. **多事权诏令拆 `primary_matter + co_matters`**：关口一 AND、关口二共享程序态、
   关口三只聚合「已进入执行」的事权，且逐事权幂等（§4）。
4. **`resisted` 三期定死**：`resist_period=1..3`、到期重评一次、第三期失败、等待期不重复扣、读档可恢复（§5）。
5. **拒收事实与弹劾证据分离**：拒收只生成案件线索，不自动定罪（§6）。
6. **张力唯一公式**：`base` 持久 + `impulse` 按月 `0.9×` 衰减（§7）。
7. **M3 弹劾暂缓**：裁定映射未批准前不实现（§8）。
8. **M0/M1a/M1b/M2 授权边界**：M1a 只读，M1b 只接权限校验，M2 才接诏令三关（§9）。

## 2. 三个关口的独立状态

| 状态 | 字段 | 取值 | 职责 |
|---|---|---|---|
| 确认态 | `confirmation_state` | `unconfirmed/confirmed/mismatch/unauthorized/undefined` | 受命人复述原旨（沿用 `decree_confirm`） |
| 程序态 | `procedure_state` | `not_required/pending_review/passed/returned/bypassed` | 会签/副署/封驳 |
| 执行态 | `exec_state` | `not_entered/ready/resisted/partially_executed/blocked` | 是否进入执行、执行是否受阻 |

| 事态 | 合法性 | procedure_state | exec_state |
|---|---|---|---|
| 事权不合法 | 不合法 | 不进入正常审议 | `not_entered` |
| 合法诏令被封驳 | 合法 | `returned` | `not_entered`（**不是 blocked**） |
| 合法诏令待会签 | 合法 | `pending_review` | `not_entered` |
| 程序通过、执行方拖延 | 合法 | `passed` | `resisted` |
| 程序通过、执行真实阻断 | 合法 | `passed` | `blocked` |
| 中旨绕过程序 | 合法性仍须通过 | `bypassed` | 按执行条件另行评估 |

> **硬规则**：`not_entered`（未进入执行）≠ `blocked`（进入执行后被阻断）。

## 3. 职位槽位与份额口径（重写）

### 3.1 数据源

```
state.central_orgs[org] = {
  "posts": [{"title": "吏部尚书"}, {"title": "吏部侍郎"}],
  "holders": {"吏部尚书": "邓洵武", "吏部侍郎": ""},
  "abolished": False,
  ...
}
```

- `posts` 只有 `title`；无权重、无品级、无代理字段。
- `holders[title] == ""` 表示**实际空缺**。
- `abolished=True` 表示机构废置。

### 3.2 五类份额（守恒式）

```
Σfaction_share
+ vacant_share                 # 真实空缺（有人已满但无人任职的槽位）
+ unaffiliated_share           # 有人任职但无已登记派系
+ concurrent_discount_share    # 兼任次职的 50% 未分配权重
+ acting_discount_share        # 代理职位的 50% 未分配权重
= 1.0
```

- 分母 `W_org = Σ_{i∈established} w_i`，**固定不随人事变动**。
- M1a 阶段 `acting_supported=False`，`acting_discount_share=0.0`（五项退化为四项）。
- `vacant_share` **只表示真实空缺**，不得再吸收兼任/代理折损。

### 3.3 兼任与代理

| 情形 | 份额归属 |
|---|---|
| 主职（`posts` 顺序首个；或最高权重） | 全额 `w_i` 计入其派系；未登记派系则计入 `unaffiliated_share` |
| 次职（同人同机构其他岗位） | `0.5 w_i` 计入其派系/未归属；`0.5 w_i` 计入 `concurrent_discount_share` |
| ≥3 个兼职 | 除主职外每个都按 `0.5/0.5` 拆 |
| 代理（`acting=True`，当前未建模） | `0.5 w_i` 计入其派系/未归属；`0.5 w_i` 计入 `acting_discount_share` |
| 实际空缺 | 全额计入 `vacant_share` |
| 未登记派系任职人 | 主职全额、次职 0.5 计入 `unaffiliated_share`；次职剩余 0.5 仍进 `concurrent_discount_share` |
| 全部岗位空缺 | `defined=True`、`vacant_share=1.0`、其余 0 |
| 无岗位定义/空列表 | `defined=False`（`undefined`），不得输出 0/1 |
| 岗位标题重复 | `defined=False` + `error="duplicate_post_title"`（数据错误，不静默） |
| 机构废置 | 不进入 `orgs`，列入 `excluded_orgs` |

### 3.4 明细字段（可追溯）

每个岗位条目必须同时给出：
- `post_weight`：原始岗位权重（headcount 模式恒 1.0）；
- `faction_counted_weight`：实际计入派系的权重；
- `unaffiliated_weight`：实际计入未归属的权重；
- `concurrent_discount_weight`：实际计入兼任折损的权重；
- `acting_discount_weight`：实际计入代理折损的权重；
- `is_primary` / `concurrent` / `acting`。

> 汇总值必须能由明细逐项加总得到；测试同时断言两者一致。

## 4. 多事权诏令聚合（重写）

### 4.1 数据结构

```python
{
  "primary_matter": "官吏铨选",          # 1 个
  "co_matters": ["赋税", "度支调度"],     # 0..n
  "executors": {"官吏铨选": {...}, "赋税": {...}},
  "matter_exec": {matter: {"status": "pending|executed|failed|skipped",
                            "executor": "...", "reason": "..."}}
}
```

- 不再使用 `matter: [...]` 旧字段；实现者只支持这一种结构。

### 4.2 三个关口

| 关口 | 规则 |
|---|---|
| 一 合法性 | `primary_matter` 与所有 `co_matters` 逐一 `check_authority`，**逻辑与**；任一不合法即拒绝 |
| 二 程序 | **整道诏令共享一个 `procedure_state`**；各事权可记 `matter_procedure` 子状态；整体优先级 `bypassed > returned > pending_review > passed > not_required` |
| 三 执行 | 只聚合**已进入执行**的事权；`not_entered` 不参与排序；若部分完成、部分未进入 ⇒ `partially_executed`；任一已执行事权 `blocked` ⇒ 整诏 `blocked`；否则 `resisted > partially_executed > ready` |

**逐事权幂等**：
- 每个 `(decree_id, matter)` 只能执行一次；`matter_exec[matter].status=executed` 后不得重跑。
- 户部已完成、吏部仍在等待 ⇒ 整诏 `partially_executed`；户部**不得重复执行**。
- 只有全部必要事权 `executed`，整诏才可标 `ready/completed`。

## 5. `resisted` 生命周期（重写）

| 期 | 规则 |
|---|---|
| 第 1 期 | 首次评估失败 ⇒ `status="resisted"`、`resist_period=1`、`due_turn=当前+1` |
| 第 2 期 | 到期重评一次；仍受阻 ⇒ `resist_period=2`、`due_turn=+1` |
| 第 3 期 | 到期重评一次；仍受阻 ⇒ 终态 `failed`，`detail="resisted_expired"`，生成**一次**事件种子 |
| 通过 | 任一期重评通过 ⇒ 执行并落账（`outcome=executed`） |
| 代价 | 等待期**不重复扣**；初始 `_event_delta` 只在颁诏时施加一次 |
| 台账 | **只在终态写**；`resisted` 不是终态，`execution_of` 不得据此跳过 |
| 队列 | 诏令留在 `pending_decrees`；`decree_id` 在队列中唯一 |
| 读档 | 恢复 `status/resist_period/due_turn`；重复月结算按 `decree_id + resist_period` 幂等 |

## 6. 拒收：事实、执行判断、案件分离

| 步骤 | 输出 | 规则 |
|---|---|---|
| 拒收事实 | `refusal_fact = {who, when, decree_id, reason_code, reason_text}` | 只记录事实，不判性质 |
| 执行判断 | `exec_state` | 命令有效且无正当理由 ⇒ `blocked`；主体错误/无法执行 ⇒ `not_entered`/`failed` |
| 案件处理 | `case_seed` | 只生成**弹劾调查线索**，不自动认定抗旨、不定罪 |

- 拒收原因必须分类：`wrong_recipient` / `impossible` / `authority_conflict` / `willful_refusal` / `unknown`。
- 只有 `willful_refusal` 才进入抗旨调查线索；其余先走纠错/改派。
- 任何情况下都不得由拒收直接写 `fact_finding=supported`。

## 7. 张力唯一公式

```
sat_gap_norm        = (max_sat - min_sat) / 100
policy_conflict_norm= Σ_{立场相反的派系对} w_i*w_j / Σ_{所有派系对} w_i*w_j
base_target         = 100 * (0.6*sat_gap_norm + 0.4*policy_conflict_norm)
base_t              = clamp(base_{t-1} + clamp(base_target - base_{t-1}, -5, +5), 0, 100)

redline_delta_t     = min(20, 5 * 本月红线命中数)
impulse_t           = clamp(0.9*impulse_{t-1} - 2 + redline_delta_t, 0, 40)
tension_t           = clamp(base_t + impulse_t, 0, 100)
```

- **唯一衰减规则**：`impulse` 每月 `×0.9 − 2`，不保留「或 −10」的第二种写法。
- 新事件只增加 `impulse`，不改变 `base` 公式。
- 缺失数据：有效派系 <2 ⇒ `base_t=base_{t-1}`、`impulse_t=impulse_{t-1}`、`tension` 不变，
  并记 `tension_undefined=True`；**不得把无法计算当成冲突缓和**。
- 阈值只给调查/事件资格，不生成证据、不定罪。

## 8. 弹劾裁定：M3 暂缓

- 在裁定映射获批前，**M3 不实现**；只保留输入/输出契约草案。
- 三层分离：
  1. `fact_finding ∈ {supported, unsupported, unknown}`：只看证据，不受派系/皇帝影响；
  2. `institutional_ruling ∈ {dismiss, demote, acquit, retry}`：由事实+程序+制度规则决定；
  3. `imperial_disposal ∈ {pardon, force_dismiss, remand, none}`：玩家圣旨，承担政治/制度代价，**不得改写 fact_finding**。
- 派系影响力只影响调查阻力（拖延/证人/案卷），不进入证据分数。
- 若 M3 要开工，必须先交一张「事实→制度裁定」的完整映射表并单测。

## 9. 授权边界（M0 / M1a / M1b / M2 / M3）

| 阶段 | 允许做什么 | 禁止做什么 |
|---|---|---|
| M0 | 文档、规则、现有映射核对 | 改生产代码 |
| **M1a** | **只读**计算机构派系分布、输出诊断 | 改人事权限、诏令结果、派系数值、存档、UI |
| M1b | 仅对**列明的新操作**接 `check_authority`；修人事权限缺口 | 顺手扩党争效果；把校验做成永远放行 |
| M2 | 诏令三关、执行阻力、逐事权状态机 | 提前做党禁、自动弹劾 |
| M3 | 一条可追溯案件闭环 | 在映射未定前写裁定公式 |
| M4 | 党禁/动态集团 | 未授权前不动 |

- `executor=None` 的旧调用：M1b 保持旧行为；新操作必须显式传 `executor`。
- 兼容行为必须有独立测试与迁移裁定，不得用「逐位一致」掩盖新权限未生效。

## 10. 两阶段执行与补偿

| 阶段 | 做什么 | 失败处理 |
|---|---|---|
| A 预检 | 事权、程序态、执行主体、目标对象、必要数据、所有写入口可用性 | 不写任何状态；返回明确原因 |
| B 提交 | 按固定顺序应用；每个子事项记 `applied_steps` / `failed_step` / `idempotency_key` | 可回滚的回滚；不可回滚的记录并补偿 |

| 后果类型 | 是否可回滚 | 失败处理 |
|---|---|---|
| 人事任免 | 可补偿（反向任免需留记录） | 记 `compensation=reappoint`，不静默 |
| 财政划转 | 可补偿（反向过账走同一桥） | 记 `compensation=reverse_transfer` |
| 派系 `_event_delta` | **不可回滚**（追加式） | 记 `partial`，必要时追加反向 delta 并标注 |
| 事件种子 | 不可回滚 | 记 `partial`，不重复生成 |

> `degraded=True` 是诊断结果，**不是事务保证**；没有可靠回滚时不得宣称原子性。

## 13. 四条硬约束

> 1. 任何派系优势都不能自动变成法定事权。
> 2. 任何政治阻力都不能伪造程序封驳。
> 3. 任何执行失败都不能伪装成已经完成。
> 4. 任何政治后果都必须能追溯到一份圣旨、一个案件或一个明确事件。
