# 党争机制 · M0 补充裁定表

> 日期：2026-10-18　状态：**待审（只读核验，不改生产行为）**
> 依据：用户 2026-10-18 对 v3 的裁定；v3 设计稿；M0 接口核验。
> 本表用于**冻结 M1 的开工边界**；审过之前不授权生产代码变更。

## 0. 结论摘要

1. **四项「新事权」不需要新增**：现有 `AUTHORITY_MATTERS` 已有对应事权，只是名称不同（见 §1）。
2. **真正的缺口**是：人事流程不调用 `check_authority`；`issue_decree` 不携带 `matter/executor/intent`；诏令确认/程序/执行三态未分离。
3. **职位槽位数据源已存在但口径不足**：`central_orgs[*]["posts"]` 只有 `title`，无权重/代理字段；M1a 只能先做 `headcount`（见 §3）。
4. **效率指标已有两套**：`statistics["administrative_efficiency"]`（1.0 尺度）与 `central_orgs[*]["efficiency"]`（1.0 倍率；衙门另有 0–100）。**不得新增第三套**（见 §5）。
5. **M1 拆为 M1a（只读分布）/ M1b（权限接线）**，避免「逐位一致」与「新权限生效」互相掩盖（见 §8）。

### 1.1 四项映射

| v3 名称 | 现有事权键（真实） | owner 机构 | 运行时机构 | 现有执行入口 | 校验入口 | 状态 |
|---|---|---|---|---|---|---|
| 文官铨选 | `官吏铨选` + `官员考课` | 吏部 | `central_orgs["吏部"]`（posts: 吏部尚书/吏部侍郎） | `appoint_circuit_official` / `dismiss_circuit_official` / `appoint_prefect_official` / `dismiss_prefect_official` | `check_authority` | **事权已存在；人事流程未校验** |
| 财政 | `赋税` / `国库` / `度支调度` / `财政勾稽` / `盐铁专营` / `官营放贷` | 户部 | `central_orgs["户部"]`（posts: 户部尚书/户部侍郎/抵当所提举） | 财政/结算函数 | `check_authority` | **事权已存在；需按操作拆分** |

> **裁定**：不新增 `文官铨选/财政/封驳/中书政令` 四个键；改为**映射表**，按诏令内容选真实事权键。
> 若未来确需新键，必须先证明现有键不能表达，再走「待建制度」流程。

### 1.2 财政操作拆分（防一个「财政」通吃）

| 操作 | 应校验的事权键 | 说明 |
|---|---|---|
| 赋税/免赋/税率 | `赋税` | 税基与税率 |
| 国库拨付/内帑 | `国库` | 中央库 |
| 预算/调拨/度支 | `度支调度` | 跨部门调拨 |
| 审计/对账 | `财政勾稽` | 事后勾稽 |
| 盐铁茶专卖 | `盐铁专营` | 专卖 |
| 官营放贷/抵当 | `官营放贷` | 抵当所 |
| 常平/仓储 | `钱粮户籍`（暂定）或走仓储事权 | **待核**：现有事权表无常平专键 |

> **裁定**：首版不允许「一个财政权通吃」；每类操作显式声明事权键，未声明即拒绝。

### 1.3 皇帝 / 执行机构 / 受命官员的权限边界

| 主体 | 拥有什么 | 不拥有什么 |
|---|---|---|
| 皇帝 | 颁诏权、御笔中旨（可绕程序）、对合法事权的最终裁决 | 不能凭皇威获得不存在的事权；不能绕过硬权限/安全校验 |
| 执行机构 | 机构 `matter_keys` 定义的事权 | 不能执行未授权事权；不能自行扩大事权 |
| 受命官员 | 其任职岗位对应的事权（`posts_of`/`holds_matter`） | 不在其岗位的事权；离任即失权 |

**越权处理**：`check_authority` 返回不合法 ⇒ 拒绝并留痕；不得以「满意度/皇威/钱粮」补足。

## 2. 三个关口的状态语义（修正 v3 §3.2–§3.3）

### 2.1 三态分离

| 状态 | 字段 | 取值 | 职责 |
|---|---|---|---|
| 确认态 | `confirmation_state` | `unconfirmed/confirmed/mismatch/unauthorized/undefined` | 受命人是否正确复述原旨（沿用 `decree_confirm`） |
| 程序态 | `procedure_state` | `not_required/pending_review/passed/returned/bypassed` | 会签/副署/封驳 |
| 执行态 | `exec_state` | `not_entered/ready/resisted/partially_executed/blocked` | 是否进入执行、执行是否受阻 |

### 2.2 状态矩阵（修正「returned 被当成 blocked」）

| 事态 | 合法性 | procedure_state | exec_state |
|---|---|---|---|
| 事权不合法 | 不合法 | 不进入正常审议 | `not_entered` |
| 合法诏令被封驳 | 合法 | `returned` | `not_entered`（**未进入执行，不是 blocked**） |
| 合法诏令待会签 | 合法 | `pending_review` | `not_entered`（尚未评估） |
| 程序通过、执行方拖延 | 合法 | `passed` | `resisted` |
| 程序通过、执行真实阻断 | 合法 | `passed` | `blocked` |
| 中旨绕过程序 | 合法性仍须通过 | `bypassed` | 按执行条件另行评估 |

> **硬规则**：`not_entered`（未进入执行）≠ `blocked`（进入执行后被阻断）。
> `blocked` 只能由**执行阶段的真实阻断**产生；程序封驳不得写成 `blocked`。

### 2.3 存放位置

- 不把三态塞进 `decree_confirm` 的单一枚举；`decree_confirm` 继续负责 `confirmation_state` 与执行台账。
- `statistics["decree_exec_ledger"][decree_id]` 增加子键：`confirmation_state/procedure_state/exec_state/applied_steps/failed_step`。
- 该台账已在存档白名单内，逐字往返，无需改 `save_load.py`。

## 3. 职位槽位口径（修正 v3 §4）

### 3.1 真实数据源

```
state.central_orgs[org] = {
  "posts": [{"title": "吏部尚书"}, {"title": "吏部侍郎"}],
  "holders": {"吏部尚书": "邓洵武", "吏部侍郎": ""},
  "abolished": False,
  "efficiency": 1.0,
  ...
}
```

- `posts` 只有 `title`；**无权重、无品级、无代理字段**。
- `holders[title] == ""` 表示**空缺**。
- `abolished=True` 表示机构废置。

### 3.2 裁定

| 情形 | 计数规则 |
|---|---|
| 应设且有人 | 计入该人派系；权重 = 1（headcount 模式） |
| 应设但空缺 | 计入 `vacant_share` |
| 机构废置 | 整个机构排除 |
| 兼任（同一人在同机构多岗） | **人只计一次**，权重 = 该人在该机构持有的岗位数；标 `concurrent=True`；**法定事权仍按岗位逐个计**（两套口径分开） |
| 代理 | 当前无字段 ⇒ `acting=False`；**不得默认 0.5**；标「待建制度」 |
| 未登记派系 | 计入 `unaffiliated_share` |
| 全部岗位空缺 | `defined=True, vacant_share=1.0, faction_share={}` |
| 无岗位定义 | `defined=False`（`undefined`），不得输出 0/1 |
| 同一人在两个机构任职 | 在每个机构分别计（机构级口径） |

### 3.3 权重模式

- M1a 只支持 `weight_mode="headcount"`。
- `weight_mode="position"` 为**待建制度**：需先补岗位权重/品级/代理字段，不得用拍脑袋权重。

## 6. 张力：结构性与事件性分开（修正 v3 §15.1）

| 概念 | 来源 | 衰减 |
|---|---|---|
| `structural_tension` | 满意度差距、政策分歧、红线命中（持续存在） | **不向 0 衰减**；随结构变化缓慢变化 |
| `event_shock` | 具体诏令/弹劾/党禁事件 | 每月 ×0.9 或 −10，取较小变化 |
| `tension` | `clamp(structural_tension + event_shock, 0, 100)` | 由前两者合成 |

- 「无事件」只让 `event_shock` 衰减，**不让结构性矛盾消失**。
- 阈值只提供「调查/事件资格」，**不生成证据、不定罪**。
- 速率上限：`event_shock` 每月 ±10；`structural_tension` 每月 ±5。

## 7. 弹劾：事实 / 制度 / 政治三分（修正 v3 §9）

| 阶段 | 输出 | 影响来源 | 禁止 |
|---|---|---|---|
| 事实认定 | `fact_finding ∈ {supported, unsupported, unknown}` | 证据是否存在、关联、充分 | 派系影响力/皇帝偏向不得改变事实 |
| 制度裁定 | `institutional_ruling ∈ {dismiss, demote, acquit, retry}` | 事实 + 程序 + 制度规则 | 不得直接由 `imperial_bias` 决定 |
| 政治处置 | `imperial_disposal ∈ {pardon, force_dismiss, remand, none}` | 玩家圣旨 + 皇威/民望代价 | 不得改写 `fact_finding` |

- 派系影响力只影响**调查阻力**（拖延、证人不敢出面、案卷被压），不进入证据分数。
- `罢黜` 是政治/人事结果，**不等于指控成立**；皇帝强行干预要留制度代价与史册记录。
- M3 只做一条可追溯案件闭环，不同时接党禁/批量罢官。

## 9. 两阶段执行与恢复（修正 v3 §14/§17）

| 阶段 | 做什么 | 失败处理 |
|---|---|---|
| 预检 | 校验事权、程序态、执行主体、目标对象、必要数据、所有写入口可用 | 不写任何状态；返回明确原因 |

## 12. 四条硬约束（写入设计稿与测试）

## 15. 边界问题裁定（v4.1，5 项）

### 15.1 兼任分母守恒（修正 §4.1–§4.2）

**问题**：若「只计最高权重职位、分母计一次」，机构总权重会随人事变动漂移，破坏
`Σfaction_share + vacant_share + unaffiliated_share = 1.0`。

**裁定**：
- 分母固定为**机构全编制岗位权重之和** `W_org = Σ_{i∈established} w_i`，不因在任人数变化。
- **主职**（权重最高；并列取 `posts` 顺序第一个）：全额 `w_i` 计入其派系。
- **次职**（同人同机构的其他岗位）：`0.5 w_i` 计入其派系，剩余 `0.5 w_i` 计入 `vacant_share`。
- ≥3 个兼职：除主职外每个都按 `0.5/0.5` 拆。
- 法定事权仍按岗位逐个计（与派系份额两套口径）。
- 恒等式：`Σfaction_share + vacant_share + unaffiliated_share = 1.0`。

**验收**：户部 3 岗（王古兼尚书+抵当所，侍郎空缺）⇒ `faction_share={"中立派":0.5}`、
`vacant_share=0.5`；增减任职者后 `W_org` 不变。

### 15.2 多事权诏令聚合（修正 §6.1）

**问题**：`matter` 支持列表，但 `resolve_executor` / `exec_state` 是单主体语义；
户部 ready、吏部 resisted 时整道诏令取什么状态未定义。

**裁定**：
- 诏令拆 `primary_matter`（1 个）+ `co_matters`（0..n）。
- **关口一（合法性）**：所有 matter 逐一 `check_authority`，**逻辑与**；任一不合法即拒绝。
- **关口二（程序）**：单状态，优先级 `bypassed > returned > pending_review > passed > not_required`。
- **关口三（执行）**：取**最严瓶颈** `blocked > resisted > partially_executed > ready > not_entered`。
- 台账记录 `matter_exec: {matter: {executor, exec_state, reason}}`。

**验收**：户部 ready + 吏部 resisted ⇒ 整诏 `resisted`；户部 blocked + 吏部 ready ⇒ `blocked`；
任一 matter 不合法 ⇒ 整诏拒绝。

### 15.3 `resisted` 生命周期（修正 §3.3 / §6.2）

**问题**：只写「记到期月」，未定义到期转移与队列驻留；留在 `pending_decrees` 可能每月重复扣代价，
进 `decree_exec_ledger` 又可能被幂等逻辑当已终结而跳过。

**裁定**：
- `resisted` 诏令**留在 `pending_decrees`**，标 `status="resisted"`、`due_turn=T`（默认 +1~3 月）。
- 等待期**不重复施加政治代价**；初始 `_event_delta` 只在颁诏时施加一次。
- 到期月**重评一次**：
  - 通过 ⇒ 执行并落 `decree_exec_ledger`（`outcome=executed`）；
  - 仍不通过 ⇒ 转 `failed`，落账（`outcome=failed`, `detail="resisted_expired"`），并生成
    「御前催办/弹劾」事件种子；
- 最多 3 期；超过转 `failed`。
- `execution_of` 不得把 `resisted` 当终态；**台账只在终态写**。

**验收**：resisted 不重复扣；到期成功只执行一次；到期失败落账并移出队列。

### 15.4 御笔绕过范围（修正 §3.2 / §6.1）

**问题**：`bypass=True` 只写「绕过程序」，未写明对关口三的影响；玩家体感与「中旨直付有司」未对齐。

**裁定**：
- 御笔只置 `procedure_state=bypassed`（免中书/门下封驳）。
- **不豁免关口一（事权合法性）**；**不豁免关口三（执行阻力）**。
- 受命机构可 `mismatch/vetoed` 拒绝确认 ⇒ `exec_state=blocked`（`blocked_reason="recipient_refused"`），
  并生成「抗旨」弹劾证据。
- 地方/部院的 `resisted` 仍照常生效。

**验收**：御笔 + 不合法事权 ⇒ 拒绝；御笔 + 地方拖延 ⇒ `resisted`；御笔 + 拒收 ⇒ `blocked` + 证据。

### 15.5 张力：结构性基线 + 事件脉冲（修正 §15.1）

**问题**：`prev + clamp(raw - prev, ±10)` 是向 `raw` 收敛，而「无事件向 0 缓动 5%/月」是向 0 衰减；
只要满意度差/立场分歧存在，二者数学上互斥。

**裁定**：
- `tension_base = 100 × clamp(0.7×sat_gap_norm + 0.3×policy_conflict_norm, 0, 1)`（结构性，持久）。
- `tension_impulse`：由红线命中/具体事件产生，每月 `×0.9` 或 `−10`（取变化较小者）向 0 衰减。
- `tension = clamp(tension_base + tension_impulse, 0, 100)`。
- `tension_base` 每月最多 ±5 缓动；无事件时总张力**回落到 base**，不归零。
- 阈值只给「调查/事件资格」，不生成证据、不定罪。

**验收**：无事件但存在满意度差 ⇒ 张力稳定在 base 附近，不归零；脉冲可在 3–6 月内衰减到 0；
总张力随 base 缓慢变化。
