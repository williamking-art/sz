# 党争机制 · M0 补充裁定表 v4.8.1

> 日期：2026-10-18　状态：**待审（只读核验，不改生产代码）**
> 依据：用户 2026-10-18 对 v4.1/v4.4 的复核意见；v4.8.1 设计稿；M0 接口核验。
> 本表冻结 M1a 的开工口径；审过之前不授权任何生产代码变更。
>
> **v4.8 裁定**：**皇权 vs 臣权**——皇帝可以亲裁/亲行/破例（御驾亲征、超迁、特旨、御笔）；
> 限制不是「无权」，而是个人成本、政治代价、臣权抵制、行政执行需要。中旨/御笔只绕程序，不创造事权。

## 0. 结论摘要

1. **四项「新事权」不存在**：现有 `AUTHORITY_MATTERS` 已有对应键，党争只做映射（§1）。
2. **兼任折损不再并入 `vacant_share`**：新增 `concurrent_discount_share` / `acting_discount_share`，
   守恒式扩为五项（§3）。
3. **多事权诏令拆 `primary_matter + co_matters`**：关口一 AND、关口二共享程序态、
   关口三只聚合「已进入执行」的事权，且逐事权幂等（§4）。
4. **`resisted` 三期定死**：`resist_period=1..3`、到期重评一次、第三期失败、等待期不重复扣、读档可恢复（§5）。
5. **拒收事实与弹劾证据分离**：拒收只生成案件线索，不自动定罪（§6）。
6. **张力唯一公式**：`base` 持久 + `impulse` 按月 `0.9×` 衰减（§7）。
7. **M3 弹劾暂缓**：裁定映射未批准前不实现（§8）。
8. **M0/M1a/M1b/M2 授权边界**：M1a 只读，M1b 只接权限校验，M2 才接诏令三关（§9）。

## 1. 事权与真实机构映射（替代「新增 4 事权」）

> **v4.7 关键裁定（先看这条）：皇帝主权 vs 承办适法性**——皇帝法理上几乎不会「无权」。
> `check_authority` 约束的是**承办人（在任职位）**，不是皇帝本人；部门只是默认归属。
> - `sovereign_right`：皇帝有颁诏权（退位/被废/摄政/非法即位等极端状态除外）；
> - `executor_authority`：承办者是否依法掌该事权；
> - **皇帝可以亲裁/亲行/破例**（御驾亲征/超迁/特旨/御笔）；受限的是**个人成本、政治代价、臣权抵制与行政执行需要**，不是「无权」；
> - 中旨/御笔只绕**程序**，不创造事权、不豁免执行阻力；
> - 承办者不掌事权 ⇒ 诏令可发但 `exec_state=not_entered`，需改派/加授差遣/中旨（中旨仍需合法承办者）。
>
> UI 不写「皇帝无权」，只写「承办者不掌事权 / 有司拖延」。

| 旧名 | 现有事权键（真实） | 默认归属部门 | 运行时机构 | 现有执行入口 | 状态 |
|---|---|---|---|---|---|
| 文官铨选 | `官吏铨选` + `官员考课` | 吏部 | `central_orgs["吏部"]` | `appoint_*` / `dismiss_*` | **事权已存在；人事流程未校验** |
| 财政 | `赋税` / `国库` / `度支调度` / `财政勾稽` / `盐铁专营` / `官营放贷` | 户部 | `central_orgs["户部"]` | 按操作分别校验 | **事权已存在；不许一个「财政」通吃** |
| 封驳 | `诏令封驳`（+`政令审议`） | 门下省 | `central_orgs["门下省"]` | `issue_decree` / 程序 | **事权已存在；未接入** |
| 中书政令 | `朝政决策` / `人事除授` / `官制` | 中书省 | `central_orgs["中书省"]` | `issue_decree` | **事权已存在；未接入** |

> **裁定**：不新增事权键；按诏令内容映射到既有键。财政必须逐动作映射，禁止宽口径授权。

## 2. 三个关口的独立状态

| 状态 | 字段 | 取值 | 职责 |
|---|---|---|---|
| 确认态 | `confirmation_state` | `unconfirmed/confirmed/mismatch/unauthorized/undefined` | 受命人复述原旨（沿用 `decree_confirm`） |
| 程序态 | `procedure_state` | `not_required/pending_review/passed/returned/bypassed` | 会签/副署/封驳 |
| 执行态 | `exec_state` | `not_entered/ready/resisted/partially_executed/blocked` | 是否进入执行、执行是否受阻 |

| 事态 | 合法性 | procedure_state | exec_state |
|---|---|---|---|
| 事权不合法 | 不合法 | 不进入正常审议 | `not_entered` |
| 合法诏令被封驳 | 合法 | `returned` | `not_entered`（**不是 blocked**） |
| 合法诏令待会签 | 合法 | `pending_review` | `not_entered` |
| 程序通过、执行方拖延 | 合法 | `passed` | `resisted` |
| 程序通过、执行真实阻断 | 合法 | `passed` | `blocked` |
| 中旨绕过程序 | 合法性仍须通过 | `bypassed` | 按执行条件另行评估 |

> **硬规则**：`not_entered`（未进入执行）≠ `blocked`（进入执行后被阻断）。

## 3. 职位槽位与份额口径（重写）

### 3.1 数据源

```
state.central_orgs[org] = {
  "posts": [{"title": "吏部尚书"}, {"title": "吏部侍郎"}],
  "holders": {"吏部尚书": "邓洵武", "吏部侍郎": ""},
  "abolished": False,
  ...
}
```

- `posts` 只有 `title`；无权重、无品级、无代理字段。
- `holders[title] == ""` 表示**实际空缺**。
- `abolished=True` 表示机构废置。

### 3.2 五类份额（守恒式）

> **旧口径废止（v4.5 明示）**：v4.2 早期草稿中的「兼任：人只计一次，权重 = 持岗数」
> **已废止**，不得再作为实现依据；唯一有效口径见 §3.3（主职全额、次职 0.5/0.5）。
> 三项守恒式（faction + vacant + unaffiliated）同样**已废止**，统一为五类守恒式。

```
Σfaction_share
+ vacant_share                 # 真实空缺（有人已满但无人任职的槽位）
+ unaffiliated_share           # 有人任职但无已登记派系
+ concurrent_discount_share    # 兼任次职的 50% 未分配权重
+ acting_discount_share        # 代理职位的 50% 未分配权重
= 1.0
```

- 分母 `W_org = Σ_{i∈established} w_i`，**固定不随人事变动**。
- M1a 阶段 `acting_supported=False`，`acting_discount_share=0.0`（五项退化为四项）。
- `vacant_share` **只表示真实空缺**，不得再吸收兼任/代理折损。

### 3.3 兼任与代理

| 情形 | 份额归属 |
|---|---|
| 主职（`posts` 顺序首个；或最高权重） | 全额 `w_i` 计入其派系；未登记派系则计入 `unaffiliated_share` |
| 次职（同人同机构其他岗位） | `0.5 w_i` 计入其派系/未归属；`0.5 w_i` 计入 `concurrent_discount_share` |
| ≥3 个兼职 | 除主职外每个都按 `0.5/0.5` 拆 |
| 代理（`acting=True`，当前未建模） | `0.5 w_i` 计入其派系/未归属；`0.5 w_i` 计入 `acting_discount_share` |
| 实际空缺 | 全额计入 `vacant_share` |
| 未登记派系任职人 | 主职全额、次职 0.5 计入 `unaffiliated_share`；次职剩余 0.5 仍进 `concurrent_discount_share` |
| 全部岗位空缺 | `defined=True`、`vacant_share=1.0`、其余 0 |
| 无岗位定义/空列表 | `defined=False`（`undefined`），不得输出 0/1 |
| 岗位标题重复 | `defined=False` + `error="duplicate_post_title"`（数据错误，不静默） |
| 机构废置 | 不进入 `orgs`，列入 `excluded_orgs` |

### 3.4 明细字段（可追溯）

每个岗位条目必须同时给出：
- `post_weight`：原始岗位权重（headcount 模式恒 1.0）；
- `faction_counted_weight`：实际计入派系的权重；
- `unaffiliated_weight`：实际计入未归属的权重；
- `concurrent_discount_weight`：实际计入兼任折损的权重；
- `acting_discount_weight`：实际计入代理折损的权重；
- `is_primary` / `concurrent` / `acting`。

> 汇总值必须能由明细逐项加总得到；测试同时断言两者一致。

## 4. 多事权诏令聚合（重写）

### 4.1 数据结构

```python
{
  "primary_matter": "官吏铨选",          # 1 个
  "co_matters": ["赋税", "度支调度"],     # 0..n
  "executors": {"官吏铨选": {...}, "赋税": {...}},
  "matter_exec": {matter: {"status": "pending|executed|failed|skipped",
                            "executor": "...", "reason": "..."}}
}
```

- 不再使用 `matter: [...]` 旧字段；实现者只支持这一种结构。

### 4.2 三个关口

| 关口 | 规则 |
|---|---|
| 一 合法性 | `primary_matter` 与所有 `co_matters` 逐一 `check_authority`，**逻辑与**；任一不合法即拒绝 |
| 二 程序 | **整道诏令共享一个 `procedure_state`**；各事权可记 `matter_procedure` 子状态；整体优先级 `bypassed > returned > pending_review > passed > not_required` |
| 三 执行 | 只聚合**已进入执行**的事权；`not_entered` 不参与排序；若部分完成、部分未进入 ⇒ `partially_executed`；任一已执行事权 `blocked` ⇒ 整诏 `blocked`；否则 `resisted > partially_executed > ready` |

**逐事权幂等**：
- 每个 `(decree_id, matter)` 只能执行一次；`matter_exec[matter].status=executed` 后不得重跑。
- 户部已完成、吏部仍在等待 ⇒ 整诏 `partially_executed`；户部**不得重复执行**。
- 只有全部必要事权 `executed`，整诏才可标 `ready/completed`。

## 5. `resisted` 生命周期（重写）

| 期 | 规则 |
|---|---|
| 第 1 期 | 首次评估失败 ⇒ `status="resisted"`、`resist_period=1`、`due_turn=当前+1` |
| 第 2 期 | 到期重评一次；仍受阻 ⇒ `resist_period=2`、`due_turn=+1` |
| 第 3 期 | 到期重评一次；仍受阻 ⇒ 终态 `failed`，`detail="resisted_expired"`，生成**一次**事件种子 |
| 通过 | 任一期重评通过 ⇒ 执行并落账（`outcome=executed`） |
| 代价 | 等待期**不重复扣**；初始 `_event_delta` 只在颁诏时施加一次 |
| 台账 | **只在终态写**；`resisted` 不是终态，`execution_of` 不得据此跳过 |
| 队列 | 诏令留在 `pending_decrees`；`decree_id` 在队列中唯一 |
| 读档 | 恢复 `status/resist_period/due_turn`；重复月结算按 `decree_id + resist_period` 幂等 |

## 6. 拒收：事实、执行判断、案件分离

| 步骤 | 输出 | 规则 |
|---|---|---|
| 拒收事实 | `refusal_fact = {who, when, decree_id, reason_code, reason_text}` | 只记录事实，不判性质 |
| 执行判断 | `exec_state` | 命令有效且无正当理由 ⇒ `blocked`；主体错误/无法执行 ⇒ `not_entered`/`failed` |
| 案件处理 | `case_seed` | 只生成**弹劾调查线索**，不自动认定抗旨、不定罪 |

- 拒收原因必须分类：`wrong_recipient` / `impossible` / `authority_conflict` / `willful_refusal` / `unknown`。
- 只有 `willful_refusal` 才进入抗旨调查线索；其余先走纠错/改派。
- 任何情况下都不得由拒收直接写 `fact_finding=supported`。

## 7. 张力唯一公式

```
sat_gap_norm        = (max_sat - min_sat) / 100
policy_conflict_norm= Σ_{立场相反的派系对} w_i*w_j / Σ_{所有派系对} w_i*w_j
base_target         = 100 * (0.6*sat_gap_norm + 0.4*policy_conflict_norm)
base_t              = clamp(base_{t-1} + clamp(base_target - base_{t-1}, -5, +5), 0, 100)

redline_delta_t     = min(20, 5 * 本月红线命中数)
impulse_t           = clamp(0.9*impulse_{t-1} - 2 + redline_delta_t, 0, 40)
tension_t           = clamp(base_t + impulse_t, 0, 100)
```

- **唯一衰减规则**：`impulse` 每月 `×0.9 − 2`，不保留「或 −10」的第二种写法。
- 新事件只增加 `impulse`，不改变 `base` 公式。
- 缺失数据：有效派系 <2 ⇒ `base_t=base_{t-1}`、`impulse_t=impulse_{t-1}`、`tension` 不变，
  并记 `tension_undefined=True`；**不得把无法计算当成冲突缓和**。
- 阈值只给调查/事件资格，不生成证据、不定罪。

## 8. 弹劾裁定：M3 暂缓

- 在裁定映射获批前，**M3 不实现**；只保留输入/输出契约草案。
- 三层分离：
  1. `fact_finding ∈ {supported, unsupported, unknown}`：只看证据，不受派系/皇帝影响；
  2. `institutional_ruling ∈ {dismiss, demote, acquit, retry}`：由事实+程序+制度规则决定；
  3. `imperial_disposal ∈ {pardon, force_dismiss, remand, none}`：玩家圣旨，承担政治/制度代价，**不得改写 fact_finding**。
- 派系影响力只影响调查阻力（拖延/证人/案卷），不进入证据分数。
- 若 M3 要开工，必须先交一张「事实→制度裁定」的完整映射表并单测。

## 9. 授权边界（M0 / M1a / M1b / M2 / M3）

| 阶段 | 允许做什么 | 禁止做什么 |
|---|---|---|
| M0 | 文档、规则、现有映射核对 | 改生产代码 |
| **M1a** | **只读**计算机构派系分布、输出诊断 | 改人事权限、诏令结果、派系数值、存档、UI |
| M1b | 仅对**列明的新操作**接 `check_authority`；修人事权限缺口 | 顺手扩党争效果；把校验做成永远放行 |
| M2 | 诏令三关、执行阻力、逐事权状态机 | 提前做党禁、自动弹劾 |
| M3 | 一条可追溯案件闭环 | 在映射未定前写裁定公式 |
| M4 | 党禁/动态集团 | 未授权前不动 |

- `executor=None` 的旧调用：M1b 保持旧行为；新操作必须显式传 `executor`。
- 兼容行为必须有独立测试与迁移裁定，不得用「逐位一致」掩盖新权限未生效。

## 10. 两阶段执行与补偿

| 阶段 | 做什么 | 失败处理 |
|---|---|---|
| A 预检 | 事权、程序态、执行主体、目标对象、必要数据、所有写入口可用性 | 不写任何状态；返回明确原因 |
| B 提交 | 按固定顺序应用；每个子事项记 `applied_steps` / `failed_step` / `idempotency_key` | 可回滚的回滚；不可回滚的记录并补偿 |

| 后果类型 | 是否可回滚 | 失败处理 |
|---|---|---|
| 人事任免 | 可补偿（反向任免需留记录） | 记 `compensation=reappoint`，不静默 |
| 财政划转 | 可补偿（反向过账走同一桥） | 记 `compensation=reverse_transfer` |
| 派系 `_event_delta` | **不可回滚**（追加式） | 记 `partial`，必要时追加反向 delta 并标注 |
| 事件种子 | 不可回滚 | 记 `partial`，不重复生成 |

> `degraded=True` 是诊断结果，**不是事务保证**；没有可靠回滚时不得宣称原子性。

## 15. 天道裁决层（v4.3 新增）

### 15.1 定位：第四维度，不是第四道关口

| 层 | 回答的问题 | 能否否决诏令 |
|---|---|---|
| 承办适法性 | 谁依法承办？承办者是否掌该事权？ | ✅ 不合法即不可执行（皇帝主权另计，见 §1） |
| 程序审议 | 是否经过会签/封驳？ | ✅ `returned` 即不执行 |
| 执行落实 | 实际有没有办成？ | ✅ `blocked` 即未完成 |
| **天道裁决** | **顺不顺天、该不该有此后果？** | ❌ **不否决**；只定天命/天象/史评与后果强度 |

**硬规则**：天道不改变 `legal/procedure_state/exec_state`；不决定 `fact_finding`；不能创造事权；
只输出档位，数值由程序按表换算。

### 15.2 输入（只读）

| 维度 | 输入 |
|---|---|
| 法理 | `legal`、`procedure_state`、弹劾是否有实据 |
| 民心 | `population_satisfaction`、`unrest`、民变 |
| 民生 | `treasury`、`granary`、流民、灾荒 |
| 党争 | `faction_tension`、`faction_ban`、是否株连 |
| 皇威 | `prestige`、近期御笔频率、程序 bypass 次数 |
| 天时 | `TianDaoFacade.summarize_monthly_omen(state)` |

### 15.3 输出与后果

| 天命档位 | 典型条件 | 天象/后果 |
|---|---|---|
| **顺** | 合法+程序通过+有实据+民望≥50+民生稳 | 祥瑞、皇威 +1、民心 +1、史评「褒」 |
| **平** | 合法+程序通过+民生一般 | 无额外后果 |
| **疑** | 合法但御笔/bypass、民望<40、弹劾无实据、党禁牵连过广 | 言官议论、小灾、皇威 −1、史评「中」 |
| **逆** | 党禁株连、打压无据、民怨沸腾、连续御笔、财政崩溃仍加税 | **天谴**：灾异档位 +1、民变事件、皇威 −3、史评「贬」 |

- 天象 `无/轻/中/重` → 程序按表换算灾异/损耗强度（同类 `STORAGE_LOSS_TIER_MULT`）。
- 史评 `褒/中/贬` → 写史册/legacy，不直接改钱粮。

### 15.4 确定性接口（已由 §15.7 取代）

本游 `gate` 为二元、`choose` 为多档、`score` 为分档评价，三者不能各自对外出裁决；
唯一正式入口见 §15.7 `TianDaoFacade.faction_action_verdict`。本节旧伪代码**作废**。

### 15.5 与党争的反馈环

```
党争 tension/党禁/打压 → 天道裁决 → 天象/灾异 → 粮价/民望/流民
  → POP 人均资源/动乱 → 派系 satisfaction → 下一次党争
```

- 天道是**放大器/刹车**：顺天减少灾异，逆天制造灾异与民变，再由既有政治系统产生后果。
- 党争代码**不得直接写天道数值**；只提交输入、读取档位。

### 15.6 验收（M2/M3）

1. 合法但逆天的党禁 ⇒ `legal/procedure/exec` 不变，`verdict=逆`、天象档位上升、生成天谴事件种子；
2. 顺天的调停 ⇒ `verdict=顺`、皇威/民心小幅正向、无灾异；
3. 弹劾：`fact_finding` 只由证据决定，`verdict` 不得改写；
4. 同 seed 重放一致；读档不重复天谴；
5. 天道裁决无任何 `state.*` 直接写入。

### 15.7 唯一裁决契约（v4.5 修正）

`gate/choose/score` 的语义不同，不能各自代表「天道裁决」。只保留**一个正式入口**：

```python
TianDaoFacade.faction_action_verdict(state, action, context) -> {
  "verdict_id": "tdv_<hash>",          # 幂等键
  "verdict": "顺|平|疑|逆",
  "omen_tier": "无|轻|中|重",
  "historical_assessment": "褒|中|贬",
  "reason_codes": [...],
  "source_id": "<decree_id|event_id>",
  "seed": int,
  "inputs_digest": "<sha1>",
  "defined": bool,
  "basis_undefined": bool,
}
```

- 内部组合：`gate`（二元是非）→ `choose`（四档）→ `score`（史评）→ `summarize_monthly_omen`（天象）；
  三个旧接口只作**内部辅助**，不得分别产出对外裁决。
- `basis_undefined=True` ⇒ `verdict=None`/`"未定"`，`defined=False`；不得伪造「平」。
- `verdict_id = hash(source_id, turn, inputs_digest, policy_version)`；同一 `source_id` 只生成一次。

### 15.8 后果幂等与因果方向

- 裁决结果、事件种子、实际后果三者分开：
  - `verdict` 只是判定；
  - `event_seed` 用 `event_id = verdict_id + ":omen"` / `":historical"`；
  - 实际后果由既有系统执行，并在 `political_event_ledger[event_id]` 检查幂等。
- **仅靠确定性 seed 不能防重复**：重放会得到同一裁决，但不得再次生成事件/扣皇威民心。
- 因果方向固定：
  `政治行为及背景 → 天道裁决 → 官员行为选择 → 制度裁定 → 既有系统结算`。
  官员后续行为只能产生**新事件/新裁决**，不得回头改写已确定的裁决。

## 16. 官员行为裁决层（v4.4 新增）

### 16.1 定位

**官员行为裁决 = 天道裁决在「人」层面的投影。**

- 决定官员在具体情境下选哪种行为；
- 不绕过、不直接改写 `legal/procedure_state/exec_state` 三态字段；只作为关口二/三的**上游证据输入**；
- 不直接写 `state.*`；
- 结果经 `decree_confirm`、`refusal_fact`、`impeachment`、`appoint/dismiss`、`faction_settle` 落地。

### 16.2 行为空间（11 种）

`comply`（奉诏）/ `delay`（拖延）/ `partial`（部分执行）/ `refuse`（封还拒收）/
`report`（告发泄密）/ `impeach`（弹劾）/ `resign`（辞官）/ `coalition`（结党）/
`defect`（转投）/ `conceal`（隐瞒包庇）/ `recommend`（举荐附议）。

### 16.3 输入（只读，复用现有）

| 维度 | 现有入口 |
|---|---|
| 个人立场 | `decree_confidential.standing_of`（loyalty/corruption/traits/faction/in_office） |
| 能力/经历 | `state.official_stats` / `official_profile` |
| 派系状态 | `state.factions`、`faction_voice` |
| 命令性质 | **关口二**：`legal` + 天道（**不含 `exec_state`**）；**关口三**：`legal` + `procedure_state` + 天道（`exec_state` 由 L2/L3 合成，**不作为行为输入**） |
| 风险 | `exposure_profile` / `assess_leak`、皇威、惩罚先例 |
| 利益 | 升迁/贬黜/财货/恩赏；是否触及其基本盘 POP |
| 关系 | 同乡/座师/姻亲/政敌（`relations` 待建） |
| 环境 | 民望/财政/灾异/边患 |

### 16.4 裁决方式

```
seed = hash(official_id, decree_id or event_id, turn)
action = TianDaoEngine.choose(options={11 种行为}, context=..., seed=seed)
# 输出：{action, confidence, reason, tier}
```

权重示例（非最终数值）：
- `comply ∝ loyalty × 顺天权重 × (1−风险)`
- `delay/partial ∝ corruption × 逆天权重 × (1−被察觉概率)`
- `report ∝ loyalty × integrity × 逆天权重 × 被察觉概率`
- `impeach ∝ 派系影响力 × 逆天权重 × 是否有实据`
- `defect ∝ (1−派系满意度) × 目标派吸引力`
- `resign ∝ 忠诚/气节 × 皇威压力`
- `coalition ∝ 同派/关系强度 × 共同利益`

### 16.5 天道档位倾向

| 天道 | 行为倾向 |
|---|---|
| 顺 | `comply`↑；`report/impeach/refuse`↓ |
| 平 | 按个人/派系利益正常分布 |
| 疑 | `delay/partial/conceal`↑；忠直者 `report`↑ |
| 逆 | `refuse/report/impeach/resign`↑；贪腐者 `conceal/delay`↑ |

- 天道不是唯一变量：忠臣可能死谏，贪官可能压案；个体差异与派系利益仍起作用。

### 16.6 接线单点

| 行为 | 写入点 |
|---|---|
| `comply/refuse` | `decree_confirm.confirmation_state` + `refusal_fact` |
| `delay/partial` | `exec_state=resisted/partially_executed`（M2） |
| `report` | `assess_leak` / 泄密事件种子 |
| `impeach` | `state.impeachments`（M3） |
| `resign` | `dismiss_*` 人事流程 |
| `coalition/defect` | `set_split` + `_event_delta` |
| `conceal` | 案件阻力/调查延迟（不伪造证据） |

### 16.7 硬规则

1. 不绕过、不直接改写 `legal/procedure_state/exec_state` 三态字段；只作为关口二/三的上游证据输入；
2. 不决定证据真假；
3. 不创造事权/官职/人口；
4. 不直接写 `state.*`；
5. 同 seed 可复盘；读档不重复行为；
6. 行为概率 ≠ 事实认定。

### 16.8 验收（M2/M3）

1. 同一官员、同一命令，天道 `顺` vs `逆` ⇒ 行为分布显著不同；
2. 忠臣 vs 贪官，同一逆天命令 ⇒ `report` vs `conceal`；
3. 派系满意度低 ⇒ `defect/coalition` 权重上升；
4. 同 seed 重放一致；读档不重复；
5. 无直接 `state.*` 写入；
6. `report/impeach` 产生可追溯的 `_event_delta` 或案件种子。

### 16.9 阶段

| 阶段 | 接什么 |
|---|---|
| M1a | **不接** |
| M2 | `comply/delay/partial/refuse`（与 `exec_state` 对接） |
| M3 | `report/impeach/resign`（与案件/人事对接） |
| M4 | `coalition/defect`（与关系网络/份额对接） |

### 16.10 三层分离（v4.5 修正）

行为层**不是**「直接产生执行状态」，而是三层：

| 层 | 名称 | 输出 | 是否写状态 |
|---|---|---|---|
| L1 | 行为意向 | `{intent, confidence, reason_codes, context_type, candidate_set, behavior_id}` | ❌ 不写 |
| L2 | 制度裁定 | 合法性/职权归类：`procedure_return` / `execution_refuse` / `report_only` / `delay` / `comply` / `impeach_seed` / `resign_request` / `faction_move` / `conceal` | ❌ 不写；只给裁定 |
| L3 | 状态落地 | 经正式诏令链/确认流程/人事流程/案件入口/派系结算入口写入 | ✅ 只走单点 |

**修正**：
- L1 的 `refuse` 不再是一个混合行为；L2 必须区分：
  - `procedure_return`（门下依法封驳）⇒ `procedure_state=returned`、`exec_state=not_entered`；
  - `execution_refuse`（受命机构拒收）⇒ 视原因 `blocked` 或 `not_entered`；
  - `report_only`（官员报告不法命令）⇒ 只生成案件/泄密种子，**不改** `procedure/exec`。
- `delay` 也不能由 L1 直接写 `resisted`；必须由 L2 裁定为「可拖延」且 M2 执行评估确认后，才写 `resisted`。
- 因此表述改为：**行为层不直接写状态；它通过 L2 裁定影响状态。**

### 16.11 角色权限过滤（先过滤，再选择）

候选行为必须先按**法定职权**过滤，再交给 `TianDaoEngine.choose`：

| 行为 | 需要的职权/条件 |
|---|---|
| `procedure_return` | `诏令封驳`（门下省/给事中） |
| `impeach` | `监察百官` 或 `言路` |
| `resign` | 在任（`in_office`） |
| `coalition/defect` | 有派系归属；派系层允许 |
| `conceal` | 对案件/诏令有知情权（`knowledge_of`） |
| `report` | 知情 + 有言路/泄密渠道 |
| `delay/execution_refuse` | 受命执行该诏（受命人/机构） |

- 行为概率/倾向**不得创造职权**；无职权选项直接移出候选集。
- 结果中记录 `candidate_set` 与 `filtered_reasons`，便于复盘。

### 16.12 情境候选集（context_type）

| 情境 | 允许的行为 |
|---|---|
| `decree_receive`（接诏） | `comply / delay / execution_refuse / report / resign` |
| `censor_case`（监察案件） | `investigate / report / impeach / conceal` |
| `personnel`（人事） | `accept / resign / recommend / coalition` |
| `faction_conflict`（派系冲突） | `coalition / defect / watch / report` |
| `secret_decree`（密令） | `comply / leak / conceal / report` |
| `fiscal_order`（财政） | `comply / delay / execution_refuse / report` |
| `military_order`（军事） | `comply / delay / execution_refuse / report` |

- 候选集来自**既有流程**，不为覆盖 11 个枚举而新造平行流程。
- 未列情境 ⇒ 默认只用 `comply/delay/report`，不得默认开放弹劾/辞官/转投。

### 16.13 缺失关系数据

- `relations` 未建：`relations_undefined=True`，关系项**不参与权重**，并在 `reason_codes` 记录 `relations_undefined`。
- 不得把缺失关系默认为 0（= 无关系）或 1（= 至亲），两者都会扭曲行为。

### 16.14 行为幂等

- `behavior_id = hash(official_id, source_id, context_type, turn)`；
- L1 可重算（同 seed 同结果），但 L3 必须按 `behavior_id` 幂等：
  已完成的 `resign/impeach/coalition/defect/set_split` 不得因读档重跑再次生效；
- `behavior_ledger[behavior_id] = {status, applied_steps, event_id}`。

## 17. 党争奏折 / 弹章层（v4.6 新增）

### 17.1 现有管道（必须复用）

| 环节 | 现有入口 |
|---|---|
| 待审奏折 | `state.memorials` |
| 准奏 | `commands_decree.accept_memorial(state, index)` → 诏草、三省会签 |
| 留中 | `commands_decree.dismiss_memorial(state, index)` → 留中、怠政反噬 |
| 朱批待阅 | `state.ai_pending_actions` |
| 事实签 | `TianDaoFacade.scan_memorial_seeds(state, limit)` |
| 记忆/关系 | `memory.memory_graph` |

> 弹章不另造系统；只给 `memorials` 增加 `kind` 与路由。

### 17.2 类型与生成来源

`kind ∈ {impeachment, remonstrance, resignation, recommendation, joint, secret, omen}`。

来源：党争张力、天道 `疑/逆`、官员 `report/impeach` 行为、天象灾异、政策冲突、辞官/举荐。

### 17.3 事实签

```python
{
  "memorial_id": "mem_<hash>",          # 幂等键
  "kind": "impeachment|...",
  "accuser": "<官员名>",
  "target": "<对象>",
  "target_faction": "<派系|None>",
  "matter_domain": "faction_strife|impeachment|...",
  "trigger_fact": "...",
  "evidence_refs": ["..."],
  "suggested_title": "...",
  "severity": 0.0,
  "tian_dao_verdict": "顺|平|疑|逆|未定",
  "created_turn": int,
}
```

### 17.4 朱批路由

| 朱批 | 路由 | 禁止 |
|---|---|---|
| 准奏 | 弹章 → `impeachment_case(investigating)`；谏章 → 政策复核；辞呈 → 人事；举荐 → 任命提案；灾异 → 赈济/修省 | 准奏即定罪 |
| 留中 | 记录留中 + 怠政/民望代价；不开案 | 留中当无罪 |
| 彻查 | 开调查、补证据 | 跳过证据审查 |
| 罢黜 | 仅案件裁定后可用；走 `dismiss_*` | 奏折直接删官 |
| 申饬/驳斥 | 政治回应；`_event_delta` | 伪造事实 |

### 17.5 天道与派系

- 天道 `疑/逆` ⇒ 谏章/灾异奏频率与 severity ↑；**不生成弹章证据**。
- 张力/党禁 ⇒ 弹章频率、联名概率 ↑；目标派影响力高时可压案/留中（`suppressed_by_faction`），但不得销毁奏折。
- 派系影响力只影响调查阻力，不影响证据真假。

### 17.6 幂等与硬规则

- `memorial_id = hash(seed_id, turn, kind, target, accuser)`；
- `memorial_ledger[memorial_id] = {status, disposed_turn, outcome}`；
- 读档重跑不重复生成/准奏/开案；`accept_memorial`/`dismiss_memorial` 按 `memorial_id` 幂等；
- **弹章 ≠ 定罪；准奏 ≠ 罢黜；留中 ≠ 无罪**；
- 弹章缺 `accuser/target/trigger_fact` ⇒ 不生成；
- 天道/派系不得改写 `evidence_refs` 或 `fact_finding`。

### 17.7 验收（M2/M3）

1. 高 tension ⇒ 弹章数量/severity ↑；
2. 弹章准奏 ⇒ `investigating` 案件，不直接罢官；
3. 留中 ⇒ 不开案，但记怠政/民望代价；
4. 天道 `逆` ⇒ 谏章/灾异奏 ↑，弹章证据不变；
5. 同 `memorial_id` 读档不重复；
6. 缺 `accuser/target/trigger_fact` 不生成。

## 18. 附录 A：M1b 迁移方案（v4.8）

硬约束「人事/财政必须有权限」不能靠永久兼容绕过，分三步：

| 步骤 | 内容 | 兼容策略 |
|---|---|---|
| M1b-1 | **新操作**（新诏令字段/新事权映射）强制 `check_authority` | 旧调用不变，但标 `legacy_unchecked=True` |
| M1b-2 | 人事/财政旧入口补 `executor` 解析（post/holder/org）；能解析则校验 | 解析失败：新模式下拒绝，旧模式告警并留痕 |
| M1b-3 | 移除旧模式豁免；所有人事/财政操作必须有事权 | 旧档迁移：读档时补默认 executor 或显式标记待迁移 |

- 每一步都需独立测试：旧行为兼容、新操作越权拒绝、合法操作可执行、迁移后无豁免。
- 不得把「兼容」写成永久后门。
