# 商品类目词条 · 「粮」= 米 / 麦 / 面（2026-10-18）

> 用户裁定原话：「不是应该新建词条来定义吗？米面麦不都是粮」
> 状态：**定义层已落地**（数据 + 单点访问 + 门）；**未改模拟行为**。

## 1. 旧口径的问题

`GRAIN_DIMS = ["米", "麦"]` 只是**两个并列商品维**，没有「粮」这个概念 ⇒ 后果：

1. G-3 迁移被写成「旧档 `pops[].grain` 全额记入**米**」——把「粮」与「米」混为一谈；
2. 任何要按「粮」汇总的地方，都得自己硬编码 `米 + 麦`（口径易分叉）；
3. 米/麦/面作为「粮的成员」这层语义**无处安放**。

## 2. 词条定义（数据单点）

位置：`content/data_constants.py::GOODS_CLASSES`（`GRAIN_CLASS = "粮"`）

```text
粮:
  kind: 类目
  members: [米, 麦, 面]
  active:  {米: 是, 麦: 是, 面: 否}     # 面尚未立商品维（不交易、无价）
  member_kind: {米: 原粮, 麦: 原粮, 面: 成品粮}
  default_member: 米                    # 旧档无分项时的记账落点
  base_unit: 石
  conversion: {}                        # 例 {麦: {面: 0.80}}；待史料核校，暂空
  pending_members: [粟, 菽]              # 只登记，不立维
```

**访问层（唯一入口）**：`core/foundation/ledger/goods_class.py`

| 函数 | 语义 |
|---|---|
| `class_of(dim)` | 某维属哪个类目（无则 None） |
| `members(cls, active_only)` | 类目成员 |
| `class_total(goods, cls)` | 类目合计（**缺失 → None**，桶/布尔跳过） |
| `class_add(goods, cls, qty, member)` | 类目写入（默认落 default_member，**不做隐式换算**） |
| `assert_exclusive()` | 不变式：一个维只能属一个类目 |

**粮的派生读口** `grain_ledger.grain_of()` 已改为 `class_total(goods, GRAIN_CLASS)`——
行为与旧实现等价（现状只有米/麦），但**不再硬编码成员集合**。

## 3. 不变式（门钉住）

1. 一个商品维至多属一个类目；
2. `default_member` ∈ `members` 且 `active=True`；
3. 类目合计 = Σ 成员值；缺失成员**跳过而不是按 0**；非数值成员（州府桶 dict / 布尔）跳过。

门：`_dev_tools/game-dev/tests/test_quality_gate_goods_class.py`（5 条，含注入跨类目即红）。

## 4. 与 G-3 迁移的关系（未实施）

G-3（`pops[].grain` → `goods`）原方案「全额记入米」改为：**落 `default_member`（当前=米）**，
读一律走类目合计。将来米/麦分项就绪时，**只需改数据定义或迁移映射**，不动调用点。
