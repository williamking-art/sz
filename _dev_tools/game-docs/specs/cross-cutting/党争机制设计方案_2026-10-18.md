# 宋祚 · 党争机制设计方案 v1

> 日期：2026-10-18　状态：**设计稿（待拍板）**　范围：朝堂党争 / 事权 / 圣旨
>
> 用户裁定（硬约束，不得绕过）：
> 1. **皇帝（玩家）只能通过圣旨行动**——调停、站队、打压都是「诏令意图」，不存在直接点按钮改数值。
> 2. **人事操作、财政操作必须有权限**；权限（事权）本身就是党争争夺的核心。

---

## 1. 设计目标

把现有「派系情绪模拟」升级为**「以事权为战场、以圣旨为唯一输入」的党争系统**：

- 玩家每一招都要**拟诏 → 廷议 → 封驳/执行 → 派系反应**；
- 派系不直接改钱粮/人口，而是**争夺事权**（吏部/户部/御史台/枢密院…）；
- 事权被谁掌握，决定圣旨能不能出中书、能不能过门下、能不能真执行；
- 党争失控会产生**行政效率下降、财政失控、边患、民变**，最终可能亡国。

成功标准：
1. 玩家不能说「我要新党满意度 +10」，只能下诏；数值变化是**执行结果**。
2. 任何人事/财政诏令，必须先过 `check_authority`（事权）与 `封驳`（门下）两道门。
3. 默认无党争时，现有结算行为**逐位不变**（默认中性）。

---

## 2. 现状与差距（简）

**已有**：
- 五派 `新党/旧党/皇党集团/军功集团/中立派` + `FACTION_POP_BASIS`（基本盘 POP、利益、红线、子渠道、重叠）；
- `state.factions`（satisfaction/influence/cohesion/leader）——唯一写入点 `core/faction_settle.py`；
- 月度两步：`_settle_factions`（AI/事件冲击 → `_event_delta`）→ `_settle_faction_metrics`（POP 派生 + 25%/20% 缓动 + 2%/月 转投）；
- 玩家入口：召见/赏赐/贬斥、诏令 `oppose_factions`/`faction_change`、事件 `factions_prestige`；
- 事权基座：`AUTHORITY_MATTERS` + `resolve_executor` + `check_authority` + `settle_reform(executor=...)`；
- 官员/大臣带 `faction` 字段；前线有派系条。

**差距**：
1. `AUTHORITY_MATTERS` 缺 **文官铨选（吏部）** 与 **财政（户部）** —— 党争两大主战场没有事权载体。
2. 没有「机构被某派控制」的读数，圣旨执行是二值（过/不过），没有「打折/拖延/封驳」。
3. 派系只影响情绪读数；**不影响任免、不影响诏令执行率**（`_official_support_proxy` 自标 `proxy=True`）。
4. 没有台谏弹劾、党禁/清算状态机；`emerging` 新集团登记通道未接。

## 3. 核心模型：三层

```
┌─────────────────────────────────────────────┐
│ 圣旨层（玩家唯一输入）                       │
│ intent = 调停 / 站队 / 打压 / 常规           │
│ 必填：matter（事权）、executor（执行主体）   │
└──────────────────┬──────────────────────────┘
                   ↓ check_authority（事权）
┌──────────────────┴──────────────────────────┐
│ 事权层（权限）                               │
│ matter → owner 机构 → holders（官员）        │
│ institution_capture[matter][faction]         │
│ 执行判定：放行 / 打折 / 拖延 / 封驳          │
└──────────────────┬──────────────────────────┘
                   ↓ 执行结果
┌──────────────────┴──────────────────────────┐
│ 派系层（利益/立场）                          │
│ satisfaction / influence / cohesion / stance │
│ 利益议题、红线、重叠、转投                   │
└─────────────────────────────────────────────┘
```

**纪律**：
- 圣旨层**只写 `state.pending_decrees` / `state.decree_intents`**，绝不直接写 factions/国库/官员；
- 事权层只读官员册与派系影响力，产出 `obedience ∈ [0,1]`；
- 派系层仍由 `faction_settle.py` 唯一写入 satisfaction/influence/cohesion；
- 所有写操作走现有单点（`set_split`、`pop_bridge`、`local_treasury_bridge`、`storage_bridge`）。

## 4. 事权体系（权限）

### 4.1 新增事权（AUTHORITY_MATTERS）

| 事权 | owner | 说明 |
|---|---|---|
| `文官铨选` | 吏部 | 除授/磨勘/差遣/贬黜——**人事党争主战场** |
| `财政` | 户部 | 赋税、上供、拨帑、免赋、常平——**财政党争主战场** |
| `封驳` | 门下省 | 诏令副署/封还；无此权者下诏视为「御笔直下」 |
| `中书政令` | 中书省 | 政令起草与颁行 |

> 现有 `官营放贷→户部`、`监察百官→御史台`、`言路→谏院`、`调兵/边防→枢密院` 保留。

### 4.2 机构控制度 `institution_capture`

每月由官员册派生（只读）：

```
capture[matter][faction] =
    Σ_{holder ∈ owner机构, holder.faction = faction} influence(faction)
    ────────────────────────────────────────────────────────
    Σ_{holder ∈ owner机构} influence(holder.faction)
```

- 分母为 0（机构无人/未设）⇒ `capture = {}`，`emperor_control = 0.5`（未定义按中性，不伪造）。
- `dominant[matter] = argmax capture`；`emperor_control[matter] = 1 - max(capture)`。
- 例：吏部 5 个堂官，3 人旧党（影响力 60/50/40），2 人新党（70/30）⇒ 旧党 capture ≈ 0.62。

### 4.3 圣旨执行判定

```
obedience = clamp(1 - Σ_{faction 反对该诏} capture[matter][faction], 0, 1)
```

`faction_opposes(decree, faction)` 为真，当且仅当：
1. faction ∈ `decree.oppose_factions`；或
2. `decree.direction` 与该派 `stance` 相反（进取↔守成），且该派不是受益方；或
3. 诏令触碰该派 `red_lines`（如「废新法」对 New Party）。

| obedience | 结果 | 表现 |
|---|---|---|
| ≥ 0.70 | **放行** | 效果全额；当月生效 |
| 0.40–0.70 | **打折/拖延** | 效果 × obedience；延迟 1 月；log「有司玩愒」 |
| < 0.40 | **封驳** | 不执行；皇威 −2；tension +5；log「门下封还」 |

> 御笔直下：若玩家选择 `bypass=True`，跳过 `封驳` 事权，但 `obedience` 仍按 capture 计算，
> 且额外 **皇威 −3、民望 −2**，并在史册留「御笔中旨」污点（可被台谏弹劾）。

## 5. 三种党争圣旨（调停 / 站队 / 打压）

> 全部走 `issue_decree(intent=..., target=..., matter=..., executor=..., body=...)`。
> 玩家不直接改数值；以下「效果」是**执行后**由结算写入 `_event_delta` 的冲击。

### 5.1 调停（conciliation）

- 圣旨例：「诏：新旧之臣，各释前嫌，共济国事。」
- 必填：`matter=中书政令`；`executor=中书省/宰相`。
- 通过（obedience ≥0.7）：
  - 所有派系 `satisfaction +2`、`tension −10`；
  - 皇威 −1（和稀泥的代价）；
  - 6 个月冷却。
- 打折：效果 ×obedience，tension 只 −5。
- 封驳：tension +5、皇威 −2；两派都认为皇帝偏袒对方。

### 5.2 站队（alignment）

- 圣旨例：「诏：绍述先帝之政，凡新法悉复。」/「诏：罢新法，复祖宗旧制。」
- 必填：`matter=中书政令` + `财政` 或 `文官铨选`（看诏令内容）；`executor` 对应机构。
- 通过：
  - 目标派 `satisfaction +8`、`influence +5%`（相对值）、`cohesion +5`；
  - 敌对派 `satisfaction −6`；若触碰 red line，额外 `_event_delta −4`；
  - `state.policy_direction` 切到目标派方向；相关诏令执行率 +10%（6 个月）；
  - 皇威 −2。
- 打折：效果 ×obedience，政策方向只切一半（`policy_direction` 记「摇摆」）。
- 封驳：目标派 −4（皇帝说了不算，威信受损），敌对派 +2，皇威 −2。

### 5.3 打压（suppression / 党禁）

- 圣旨例：「诏：元祐党人，永不叙用。」/「诏：禁新学，毁《三经新义》板。」
- 必填：`matter=文官铨选 + 监察百官`；`executor=吏部 + 御史台`。
- 通过（obedience ≥0.6）：
  - 目标派官员按影响力**抽样罢黜**（`n = ceil(该派在朝官数 × 0.5 × obedience)`）；
  - 目标派 `satisfaction −20`、`influence −30%`、`cohesion +10`（受害者抱团）；
  - 其他派 `satisfaction +3`（震慑）；
  - 进入 **党禁状态** `state.faction_ban = {faction, start, end=+6..12, severity}`；
  - 行政效率 −10%（党禁期间）；皇威 −3；民望 −2。
- 打折：罢黜人数 ×obedience，不进入党禁，只算「贬黜数人」。
- 封驳：目标派 +2（反成受害者叙事）、皇威 −3、tension +8；**可能触发目标派反击弹劾**。
- 冷却：12 个月；同一派不可连续党禁。

> 三种意图的数值都进 `_event_delta`，由 `faction_settle` 在读完 POP 后一次性消化——
> 保持「禁止先改 faction 再假设 POP 受益」的既有纪律。

## 6. 月度结算顺序（接入现有 pipeline）

```
① decrees           圣旨受理：check_authority → obedience → 放行/打折/封驳
② factions          事件/AI 冲击 → _event_delta（现有）
③ economy           生产/财政（现有）
④ faction_metrics   satisfaction/influence/cohesion 派生（现有，唯一写入点）
⑤ faction_authority ← 新增：由官员册重算 institution_capture / emperor_control
⑥ faction_strife    ← 新增：tension 判定 → 弹劾/攻讦/联姻/和解/清算事件
⑦ military / timeline / mechanisms（现有）
```

- ⑤ 必须排在 ④ 之后：控制度用**当月最新 influence**。
- ⑥ 的事件只写 `_event_delta` 与 `state.pending_*`，不直接改 satisfaction。
- 两个新步骤默认 `critical=True`，但内部异常必须**降级为中性**（不中断整月），并记 log。

## 7. 状态机

### 7.1 弹劾（impeachment）

```
触发：御史台/谏院 holder（有 监察百官/言路 事权）+ tension ≥ 50
     或玩家圣旨「命御史台察劾某官」
状态：state.impeachments = [{id, target, accuser, evidence, due_month, status}]
次月廷议：score = accuser_faction.influence + evidence×20
                 - target_faction.influence + emperor_bias
玩家可在廷议前下圣旨：留中 / 彻查 / 罢黜 / 贬谪
结果：罢（remove）/ 贬（降职外放）/ 留（反坐 accuser）
效果：target 派 satisfaction ±8；capture 可能翻转；皇威 ±2
```

### 7.2 党禁 / 清算（proscription）

```
state.faction_ban = {faction, start_month, end_month, severity: 轻|重}
期间：该派官员不得除授；在朝者按 severity 每月再罢 1–2 人；
      satisfaction −20 一次性，之后每月 −2；influence −30%；
      行政效率 −10%；该派 red_line 事件概率 ×2。
到期：satisfaction +5（解禁），tension −10；史册记「解禁」。
```

### 7.3 和解 / 联姻

- tension ≥70 时，两派可能自发「和解/联姻」事件（AI 契约已支持 `联姻/和解` 类型）；
- 效果：双方 satisfaction +3、tension −8；若玩家下诏「赐婚/赐宴」，效果 ×1.5，花费内帑。

### 7.4 新集团登记（M4）

- `emerging_from_reforms(state)` 已给出候选（人口占比/凝聚力/暴露月数门槛）；
- 新增 `register_faction(state, spec)`：写入 `state.faction_registry`，并把 split 中该派初始份额设为门槛值（从母派划出，Σ=1）；
- 全库 `FACTION_NAMES` 改为 `faction_names(state)`（默认仍是五派，默认中性）。

## 8. 权限争夺与反噬（党争的核心循环）

```
圣旨（人事/财政）
  → 若吏部/户部被敌对派 capture 高 ⇒ 打折/封驳
  → 玩家改用「调停」换缓冲，或「打压」换人
  → 打压成功 ⇒ 该派官员被罢 ⇒ capture 翻转
  → 但党禁触发行政效率 −10%、民望 −2、台谏反击
  → 下一轮：对立派 capture 上升 …
```

**关键读数**（前端「朝堂·事权」面板）：

| 读数 | 含义 | 来源 |
|---|---|---|
| `emperor_control[matter]` | 皇帝对该事权的实际控制 | `1 - max(capture)` |
| `dominant[matter]` | 该事权实际被哪派把持 | `argmax(capture)` |
| `obedience`（每诏） | 本诏预计执行度 | 事权 capture × 派系立场 |
| `faction_tension` | 党争张力 0–100 | Σ influence×|sat 差| + 政策冲突 |
| `bureaucracy_efficiency` | 行政效率 0–100 | 各派 satisfaction × capture 加权 − 党禁惩罚 |

---

## 9. 失败态（不是即时 Game Over）

| 读数 | 阈值 | 后果 |
|---|---|---|
| `bureaucracy_efficiency` | <30 持续 6 月 | 政令执行率 −50%、税收 −10%、民变 + |
| `faction_tension` | ≥90 持续 6 月 | 触发「党祸」事件链：台谏互相攻讦、官员批量去职、边将拥兵 |
| 财政 | 连续 3 月赤字 + 党禁 | 军饷拖欠 → 兵变风险 |
| 民望 | <20 + 党禁 | 民变/流民事件 |

亡国不是单一数值判定，而是上述事件链叠加（史实向：慢、可挽回；游戏向：可调阈值）。

## 14. 待拍板（5 项）

1. **御笔直下**是否允许？允许的话，皇威/民望代价是否够重（−3/−2）？

5. **失败态节奏**：史实慢（阈值高、事件链长）还是游戏快（6 月见分晓）？

## 15. 与现有代码的边界

- 不新增人口/钱粮账本；所有钱粮写仍走既有桥接单点。
- 不直接改 `state.factions` 的 satisfaction/influence/cohesion；只写 `_event_delta` 与 `pending_*`。
- `settle_factions_from_pop` 仍是唯一写入点；新步骤只做**派生读数**与**事件调度**。
- 默认中性：没有圣旨、没有党禁、没有弹劾时，月度结果与今日逐位一致。
