## 1. 设计目标与非目标

**目标**
1. 玩家只能下圣旨；圣旨经「合法性 → 程序 → 执行」三关后产生政治后果。
2. 党争的主战场是**事权**（谁依法有权办这件事），不是满意度数字。
3. 所有政治后果都能追溯到既有机制（POP、财政、人事、天道、民心/皇威）。

**非目标（本版不做）**
- 不做动态新集团（M4 后置，见 §13 裁定）。
- 不做重度清算/流放/籍没（先轻/中两级）。
- 不新增人口/钱粮账本；不新增第二套诏令执行入口。

## 3. 三个关口（核心修正）

### 3.1 关口一：承办适法性（不是「皇帝无权」）

> **先回答关键问题**：皇帝在法理上几乎不会「无权」。本关约束的是**承办者**，不是皇帝本人。
> 详见 §28。

```
issuable(emperor)  = sovereign_right(emperor) ∧ edict_form_valid
executable(decree) = executor_authority(executor, matter)
legal(decree)      = issuable ∧ executable          # 关口一：只判「能不能发、有没有人依法承办」
procedure_state    = 关口二（独立状态，不参与 legal 计算）
exec_state         = 关口三（仅 procedure ∈ {passed, bypassed} 才评估）
```

- **顺序固定**：关口一 → 关口二 → 关口三；`legal` **不依赖** `procedure_state`，避免因果环路。
- `sovereign_right`：皇帝有颁诏权（退位/被废/摄政/非法即位等极端状态除外）。
- `executor_authority`：**承办人**是否因**在任职位**而持有该权限（`permission_model.has_permission(actor, matter)`）；部门只是默认归属。
- 皇帝可以**亲裁/亲行/破例**（超迁、特旨、御驾亲征、御笔），但**日常行政执行**仍需有司/军队/地方去做；
  亲自行使有个人成本、政治代价与臣权抵制（§28）。
- 承办者不掌事权 ⇒ 诏令**可发但不可执行**（`exec_state=not_entered`），需改派/加授差遣/中旨；
  **中旨也不能让无权者承办**。
- **亲裁/亲行/破例不走本条**：它们走 §28「皇权 vs 臣权」的个人行动路径，不套用 `executor_authority` 二值判定；
  但其后续执行仍需既有单点（如亲征仍需枢密院调兵、超迁仍需吏部发告身）。
- 真正「法理无权」只出现在退位/被废/摄政/非法即位；「事实无力」表现为 `resisted/blocked`，不是合法性否定。
- **v4 修正**：以下四项**不是新增事权**；现有 `AUTHORITY_MATTERS` 已存在对应键，
  党争只做**映射**，不新建重复事权（详见补充裁定表 §1）：

| 旧名 | 现有事权键 | 默认归属部门 | 现有执行入口 |
|---|---|---|---|
| 文官铨选 | `官吏铨选` + `官员考课` | 吏部 | `appoint_*` / `dismiss_*`（**尚未校验事权**） |
| 财政 | `赋税` / `国库` / `度支调度` / `财政勾稽` / `盐铁专营` / `官营放贷` | 户部 | 按操作分别校验，**不许一个「财政」通吃** |
| 封驳 | `诏令封驳`（+`政令审议`） | 门下省 | `issue_decree` / 程序（**尚未接入**） |
| 中书政令 | `朝政决策` / `人事除授` / `官制` | 中书省 | `issue_decree`（**尚未接入**） |

### 3.2 关口二：程序审议（状态，不是分数）

```
procedure_state ∈ {not_required, pending_review, passed, returned, bypassed}
```

| 状态 | 含义 | 触发 |
|---|---|---|
| `not_required` | 常规事务，无需会签 | 既有诏令类别 |
| `pending_review` | 待廷议/会签/门下副署 | 新事权诏令、党争三意图 |
| `passed` | 程序通过 | 会签/副署完成 |
| `returned` | **合法封驳** | 门下/给事中行使封驳权；记录理由 |
| `bypassed` | 御笔中旨绕过程序 | 玩家显式选择；留政治代价与史册记录 |

- `returned` 是**程序结果**，不是执行阻力；不得由 `capture` 或满意度产生。
- `bypassed` 不等于合法：若事权本身不合法，仍被关口一拒绝。

### 3.3 关口三：执行落实（状态机，数值只作证据）

```
exec_state ∈ {not_entered, ready, resisted, partially_executed, blocked}
```

| 状态 | 含义 | 适用 |
|---|---|---|
| `not_entered` | 未进入执行阶段（程序 returned / 待会签 / 事权不合法） | **不等于 blocked** |
| `ready` | 正常执行 | 默认 |
| `resisted` | 有期限的拖延/复核（不改数值） | 地方阻力、机构消极 |
| `partially_executed` | **仅当机制明确支持分段**时执行部分 | 分批拨款、分批罢黜；人事/财政/军事不得做 `×obedience` |
| `blocked` | **进入执行阶段后**的真实阻断 | 只能由执行阶段产生；程序 returned 只到 `not_entered` |

- 输入证据（只读、可解释）：
  - `TianDaoFacade.circuit_decree_compliance(state_context)` → 逐路合规档位；
  - `institution_distribution`（§4）→ 机构内派系占比；
  - `faction stance on decree`（§10）→ 支持/反对；
  - 现有 `decree_confirm` 复述状态（受命人是否确认原旨）。
- 状态转移规则必须显式写在代码常量表里，不允许「0.69/0.70 跳变」式隐式阈值。

## 4. 机构派系分布（重写 `institution_capture`）

> **注意**：本节 `institution_distribution` 是**任职分布**；**事权分布**用
> `permission_model.permission_capture(state, matter)`。权限挂在职位上，部门只是默认归属。

### 4.1 公式

\[
C_{m,f}=\frac{\sum_{i\in(m,f)} w_i}{\sum_{i\in m,\ \text{established}} w_i}
\]

- `w_i`：**制度定义的职位权重**（品级/岗位权重），不是派系 `influence`。
- 无可靠权重时：`w_i=1`，并显式标注 `weight_mode="headcount"`（含义是人数占比，不是实际控制力）。
- 输出 `faction_share`（各派占比），不再叫 `capture`（避免「控制」的暗示）。

### 4.2 缺失与边界语义（必须逐项定义）

| 情形 | 分子 | 分母 | 备注 |
|---|---|---|---|
| 空缺职位 | 不计 | **计**（进入 `vacant_share`） | 空缺不能被算成任何派系 |
| 兼任（同一机构多个职位） | 主职全额计入派系/未归属；每个次职 `0.5` 计派系/未归属、`0.5` 计 `concurrent_discount_share` | **每个岗位都计**（全编制分母） | 标 `concurrent=True`；五项守恒 |
| 代理 | `0.5` 计派系/未归属、`0.5` 计 `acting_discount_share` | **每个岗位都计** | 标 `acting=True`；M1a 未启用时该份额为 0 |
| 非在朝者 | 不计 | 不计 | 无任职即无机构份额 |
| 未登记派系 | 不计 | **计**（进入 `unaffiliated_share`） | 未登记 ≠ 皇帝的人 |
| 机构废置 | 不计 | 不计 | `established=False` |
| 机构无人 | 空 | 0 | 输出 `undefined`，**不输出 0 或 1** |

### 4.3 输出

```
institution_distribution = {
  matter: {
    "faction_share": {faction: float},
    "vacant_share": float,                 # 真实空缺
    "unaffiliated_share": float,           # 有人任职但无已登记派系
    "concurrent_discount_share": float,    # 兼任次职 50% 未分配
    "acting_discount_share": float,        # 代理 50% 未分配（M1a 恒 0.0）
    "dominant": str|None,
    "dominance_margin": float,
    "weight_mode": "position"|"headcount",
    "as_of_turn": int,
  }
}
```

- 派生数据，**不存档**（每次从官员册重算）；旧档无需迁移。

| 指标 | 定义 | 用途 |
|---|---|---|
| `faction_share` | 机构内各派职位权重占比 | 展示、执行阻力证据 |
| `faction_dominance` | `max_share - second_share`；`dominant` 仅当 `max_share ≥ 0.5` 或领先 ≥0.2 | 判断「是否有明显主导派」 |
| `imperial_leverage` | **第一版只给状态**：`strong / contested / weak` + 理由列表（任命权、诏令权、程序权、制度约束） | 不给假精确百分数；后续有制度依据再公式化 |

**禁止**：`emperor_control = 1 - max(share)`。五派均分不等于皇帝 80% 控制。

## 6. 圣旨接入现有诏令链（不另造入口）

### 6.1 唯一入口

```
issue_decree(state, decree, direct=False)
  decree = {
    "title", "category", "desc",
    "intent": "调停|站队|打压|常规",
    "primary_matter": "官吏铨选",       # 主办（1 个，既有事权键）
    "co_matters": ["赋税"],             # 协办（0..n，既有事权键）
    "executor": {"org"|"post"|"holder": ...},  # 复用 resolve_executor
    "target_faction": str|None,
    "direction": "进取|守成|中立",
    "bypass": bool,                    # 御笔中旨
    "effects": {...},                  # 仍走既有 effects 通道
  }
```

- 草稿/审批/队列/执行仍走：`preview_draft → issue_decree → pending_decrees → settlement_decree → decree_confirm`。
- `direct=True`（御笔）只能**跳过程序关口**（`procedure_state=bypassed`），**不能跳过承办适法性**（仍须合法承办者）。
- `is_zhongzhi`（中旨）保留现有语义，但必须记录「绕过了哪道程序、保留了哪些硬校验」。

### 6.2 评估时机

| 时点 | 做什么 | 不做什么 |
|---|---|---|
| 拟诏预览 | 显示 `legal` / 预计 `procedure_state` / 预计 `exec_state` + 理由 | 不写任何状态 |
| 正式颁诏 | 重新计算 `legal` 与 `procedure_state`（防止预览后人事变动） | 不重复扣政治代价 |
| 月度执行 | 计算 `exec_state`；`resisted` 记到期月；`blocked` 记原因 | 不对人事/财政做 `×obedience` |
| 执行后 | 写 `decree_exec_ledger`（幂等）+ 结果分发（§7） | 不重复施加同一事件 |

### 6.3 幂等与失败

- 每道诏令必须有 `decree_id`；`decree_exec_ledger` 已有 `executed/registered_only` 幂等语义，党争结果沿用。
- 失败诏令记录 `outcome=failed/vetoed`，**允许重新拟诏**，但同一 `decree_id` 不重复施加政治冲击。
- 读档重跑：已 `executed/registered_only` 的诏令不再执行（现有逻辑）。

## 7. 结果分发契约（不再全塞 `_event_delta`）

| 结果类型 | 写入点 | 允许写 | 禁止 |
|---|---|---|---|
| 派系 satisfaction/influence/cohesion | `faction_settle`（唯一写入点） | 只提交 `_event_delta` 冲击 | 直接改三读数 |
| 派系份额（转投） | `core/domains/politics/split.set_split` | 零和迁移 | 改 POP size |
| 人事任免 | `appoint/dismiss_*` 现有人事流程 | 走流程、留记录 | 党禁状态机直接删官员 |
| 财政（钱粮） | `local_treasury_bridge` / `storage_bridge` / `treasury` 既有链 | 走既有 effects/桥接 | 另开财政账本 |
| 皇威/民望 | `state.prestige` / `state.population_satisfaction` 既有写入点 | 有来源的冲击 | 旁路直写 |
| 弹劾案件 | `state.impeachments` 状态机 | 创建/推进/结束 | 绕过审理直接定罪 |
| 党禁 | `state.faction_ban` 状态机 | 起止/强度/维护 | 每月重复一次性惩罚 |
| 天道档位 | 只读 `TianDaoFacade` 输出 | 作为执行/灾异证据 | 党争直接写天道数值 |

## 8. 三种党争圣旨（目标/成本/代价/风险）

> 不再写「固定 +8/−6」作为设计核心；数值是平衡参数，必须能解释来源。

### 8.1 调停

| 要素 | 内容 |
|---|---|
| 目标 | 降低公开冲突、换取处理其他政务的窗口 |
| 制度成本 | `朝政决策`（中书省）+ `诏令封驳`（门下省）；需廷议/会签；6 个月冷却 |
| 政治代价 | 皇威 −1；双方都不认为皇帝真正站自己这边 |
| 后续风险 | **只降低公开对抗，不消除利益矛盾**；政策分歧仍在，下次触发更尖锐 |
| 效果 | 只压 `tension`（有上限），不自动给所有派系加满意度；若诏文含具体政策让步，才按让步内容改 `_event_delta` |

### 8.2 站队

| 要素 | 内容 |
|---|---|
| 目标 | 让某一派的方向成为朝廷主导，换取其配合 |
| 制度成本 | `朝政决策` + 户部对应财政键（`赋税/国库/度支调度`）/ `官吏铨选`（按诏文）；需程序通过 |
| 政治代价 | 敌对派 satisfaction/影响力下降；触碰红线触发额外冲击 |
| 后续风险 | 增益**限期 6 个月**且**不叠加**；敌对派会反制（弹劾/封驳/地方消极），不能形成「越站队越强」正反馈 |
| 效果 | 目标派 `_event_delta +`（有上限）；政策方向切换；执行阻力下降有上限 |

### 8.3 打压

| 要素 | 内容 |
|---|---|
| 目标 | 清除某一派在关键事权上的任职者，改变机构分布 |
| 制度成本 | `官吏铨选` + `监察百官`；需程序通过；12 个月冷却 |
| 政治代价 | 皇威 −3、民望 −2；目标派抱团/反制；史册留痕 |
| 后续风险 | 官员空缺 → `vacant_share` 上升、关口三执行阻力增加；可能触发台谏反击、地方消极、边将不安 |
| 效果 | 每次罢黜走人事流程（留目标/依据/结果/来源）；只对**在朝任职者**生效；不批量抽样式删除 |

## 9. 弹劾（四段式）

1. **提出指控**：需 `监察百官`/`言路` 事权；必须有 `evidence` 条目（来源、对象、事由）。
2. **证据审查**：检查证据是否存在、是否关联指控、是否足以进入审理；派系影响力只影响**调查阻力**（拖延/证人不敢出面/案卷被压），**不影响证据真假**。
3. **审理裁定**：输入统一量纲：`evidence_score ∈ [0,1]`、`procedure_bonus ∈ [0,1]`、`imperial_bias ∈ [-1,1]`；输出 `罢/贬/留`；派系影响力不直接加到分数里。
4. **政治后果**：派系冲击 → `_event_delta`；人事 → 人事流程；皇威 → 既有写入点；全部留 `case_id` 台账。

> 「罢黜」是人事结果，不等于「指控成立」；皇帝强行干预必须留政治代价与制度记录。

## 10. 党禁（先轻/中两级）

| 级别 | 内容 | 后果 |
|---|---|---|
| 轻 | 限制该派除授、限制部分官职任用 | 该派 satisfaction 一次性 −8；机构分布缓慢变化；6 个月 |
| 中 | 撤换特定职位、限制政治活动 | satisfaction 一次性 −15；指定职位罢黜（走人事流程）；官员空缺推高 `vacant_share`，直接增加关口三执行阻力；12 个月 |

- **不做**重度清算（流放/籍没/永不叙用）——后置。
- 一次性冲击只在开始时施加；维护态每月只做**状态检查**（不再扣 satisfaction）。
- 罢黜必须走 `dismiss_*` 现有人事流程，保留目标/依据/结果/来源；党禁状态机不得直接删官员。
- 到期/恢复：到期自动解除；若期间无新弹劾且财政/民望达标，可提前 1–2 月解除；解除后 satisfaction +5。

## 11. 全系统耦合矩阵（v3 新增，重点）

> 党争是**横切政治层**，不是独立玩法。它必须**读遍**既有系统、**只经单点写**少数政治状态；
> 任何「另开账本/另造入口/直接改数值」都视为设计缺陷。

### 11.0 五条总则

1. **只读优先**：能派生就不要存；能读既有读数就不要新建字段。
2. **写只走单点**：派系三读数→`faction_settle`；份额→`set_split`；人事→`appoint/dismiss_*`；钱粮→既有桥接；皇威/民望→既有 effects 通道。
3. **不建第二账本**：不新增人口、钱粮、兵力、库存、天命数值；党争只产生「政治冲击/程序状态/案件」。
4. **缺失 ≠ 0 ≠ 1**：机构无人、派系未登记、读数缺失，一律输出 `undefined` 或显式 `unknown`，不得当成「皇帝全控/全员服从」。
5. **可复盘**：所有随机掷点用 `TianDaoEngine.dice(seed)`；所有冲击带 `source/decree_id/event_id`，可追溯到具体诏令或事件。

### 11.4 耦合验收（每个系统一条）

对每个「强/中」系统，至少一条**反旁路测试**：

- 把该系统的权威写入口替换成会抛错的桩；
- 跑一条党争诏令/事件；
- 断言：党争代码**没有**绕过单点（要么走桩成功，要么显式失败并留 `faction_strife_error`）；
- 断言：不产生第二份账本（对比该系统总量前后守恒）。

`pop_bridge.pop_obj_*` / `local_treasury_bridge.*` / `storage_bridge.*` / `appoint_*`/`dismiss_*` / `issue_decree` / `faction_settle._event_delta`。

## 14. 持久化与迁移

| 数据 | 性质 | 处理 |
|---|---|---|
| `institution_distribution` / `imperial_leverage` | 派生 | **不存档**，每次由官员册重算 |

## 15. 张力与失败态（可验证定义）

### 15.1 `faction_tension`

```
sat_gap_norm         = (max_sat - min_sat) / 100
policy_conflict_norm = Σ_{立场相反派系对} w_i*w_j / Σ_{所有派系对} w_i*w_j
base_target          = 100 * (0.6*sat_gap_norm + 0.4*policy_conflict_norm)
base_t               = clamp(base_{t-1} + clamp(base_target - base_{t-1}, -5, +5), 0, 100)

redline_delta_t      = min(20, 5 * 本月红线命中数)
impulse_t            = clamp(0.9*impulse_{t-1} - 2 + redline_delta_t, 0, 40)
tension_t            = clamp(base_t + impulse_t, 0, 100)
```

- **权重**：base 固定 `0.6/0.4`；impulse 只由红线/事件增加，不参与 base。
- **唯一衰减**：只有 `impulse` 每月 `×0.9 − 2`；`base` 不向 0 衰减。
- **输入**：`state.factions[name].satisfaction`、`policy_vector`/`stance_on`、本月诏令 `red_lines` 命中。
- **去重**：同一 `decree_id` 只计一次；同一事件按 `event_id` 去重。
- **缺失**：有效派系 <2 ⇒ `base/impulse/tension` **全部保持上一月**，记 `tension_undefined=True`；
  **不得把无法计算当成冲突缓和**。
- **触发**：
  - ≥50：御史台可发起弹劾（概率/资格，不是必然）；
  - ≥70：可触发和解/联姻事件；
  - ≥90 连续 3 月：进入「党祸」事件链（不是即时亡国）。
- **恢复**：<40 连续 3 月 → 解除党祸标记；解除后 tension 上限降至 60（防立刻反弹）。

### 15.2 失败态（事件链，不是单阈值）

| 条件 | 后果 | 解除 |
|---|---|---|
| ~~`bureaucracy_efficiency <30` + 税收 −10%~~ | **v4 作废**：不新增效率字段、不新增税收惩罚；首版效率只作执行评估证据（见补充裁定表 §5） | — |
| `tension ≥90` 连续 3 月 | 「党祸」事件链（台谏攻讦/官员去职/边将拥兵） | tension <40 连续 3 月 |
| 财政连续 3 月赤字 + 党禁 | 军饷拖欠 → 兵变风险事件 | 财政转正 3 月 |
| 民望 <20 + 党禁 | 民变/流民事件 | 民望 ≥40 |

- 亡国是事件链叠加结果，不是单一数值即死；阈值全部可配置、可复盘（`TianDaoEngine.dice` 固定种子）。

## 24. 天道裁决层（v4.3 新增）

### 24.1 定位：第四维度，不是第四道关口

| 层 | 回答的问题 | 能否否决诏令 |
|---|---|---|
| 承办适法性 | 谁依法承办？承办者是否掌该事权？ | ✅ 不合法即不可执行（皇帝主权另计，见 §28） |
| 程序审议 | 是否经过会签/封驳？ | ✅ `returned` 即不执行 |
| 执行落实 | 实际有没有办成？ | ✅ `blocked` 即未完成 |
| **天道裁决** | **这件事顺不顺天、该不该有此后果？** | ❌ **不否决**；只决定天命/天象/史评与后果强度 |

**硬规则**：
- 天道裁决**不改变** `legal / procedure_state / exec_state`；
- 天道裁决**不决定证据真假**（`fact_finding` 仍只看证据）；
- 天道裁决**不能给皇帝不存在的事权**；
- 天道只输出**档位**，数值由程序按表换算（沿用 `storage_loss` 的「AI 只出档位」口径）。

### 24.2 裁决对象

只对**重大政治行为**裁决，避免每诏都天象：
- 圣旨三意图：调停 / 站队 / 打压；
- 党禁、弹劾、御笔中旨；
- 大规模人事清洗、大规模财政动作（加税/免赋/拨帑）。

日常细务不进入天道裁决。

### 24.3 输入（只读）

| 维度 | 输入 |
|---|---|
| 法理 | `legal`、`procedure_state`、弹劾是否有实据 |
| 民心 | `population_satisfaction`、`unrest`、民变 |
| 民生 | `treasury`、`granary`、流民、灾荒 |
| 党争 | `faction_tension`、`faction_ban`、是否株连 |
| 皇威 | `prestige`、近期御笔频率、程序 bypass 次数 |
| 天时 | `TianDaoFacade.summarize_monthly_omen(state)` 的当月天象 |

### 24.4 输出与后果

| 天命档位 | 典型条件 | 天象/后果 |
|---|---|---|
| **顺** | 合法 + 程序通过 + 有实据 + 民望 ≥50 + 民生稳 | 祥瑞、皇威 +1、民心 +1、史评「褒」 |
| **平** | 合法 + 程序通过 + 民生一般 | 无额外后果 |
| **疑** | 合法但御笔/bypass、民望 <40、弹劾无实据、党禁牵连过广 | 言官议论、小灾、皇威 −1、史评「中」 |
| **逆** | 党禁株连、打压无据、民怨沸腾、连续御笔、财政崩溃仍加税 | **天谴**：灾异档位 +1、民变事件、皇威 −3、史评「贬」 |

- 天象档位 `无/轻/中/重` → 程序按表换算损耗/灾异强度（同类 `STORAGE_LOSS_TIER_MULT`）。
- 史评 `褒/中/贬` → 写入史册/legacy 评价，不直接改钱粮。

### 24.5 唯一裁决契约（v4.5，按本游实际接口修正）

本游 `TianDaoEngine` 的真实语义：

| 接口 | 真实返回 | 不能做什么 |
|---|---|---|
| `gate(...)` | `{verdict: bool, probability, basis_undefined, defined}` | **二元**，不能直接代表四档 |
| `choose(...)` | `{verdict: str, probabilities, ...}` | 需显式选项集，不是固定四档 |
| `score(...)` | `{level, score, ...}` | 分档评价，不是政治裁决 |
| `dice(seed, entropy)` | 确定性微扰 | 只保证可复盘，不保证幂等 |

因此三者**不能各自对外出裁决**。只保留一个正式入口（M2 待建，不假设今日已存在）：

```python
TianDaoFacade.faction_action_verdict(state, action, context) -> {
  "verdict_id": "tdv_<hash>",          # 幂等键
  "verdict": "顺|平|疑|逆",
  "omen_tier": "无|轻|中|重",
  "historical_assessment": "褒|中|贬",
  "reason_codes": [...],
  "source_id": "<decree_id|event_id>",
  "seed": int,
  "inputs_digest": "<sha1>",
  "defined": bool,
  "basis_undefined": bool,
}
```

- 内部组合：`gate`（是非）→ `choose`（四档）→ `score`（史评）→ `summarize_monthly_omen`（天象）；
  旧接口只作内部辅助。
- `basis_undefined=True` ⇒ `verdict=None`/`"未定"`、`defined=False`；**不得伪造「平」**。
- `verdict_id = hash(source_id, turn, inputs_digest, policy_version)`；
  `event_id = verdict_id + ":omen"|":historical"`；`political_event_ledger[event_id]` 幂等。
- **仅靠确定性 seed 不能防重复**：重放得到同一裁决，但不得再次生成事件/扣皇威民心。
- 因果方向固定：`政治行为及背景 → 天道裁决 → 官员行为选择 → 制度裁定 → 既有系统结算`；
  后续行为只能产生新事件/新裁决，不得回头改写已定裁决。

### 24.6 与党争的反馈环

```
党争 tension / 党禁 / 打压
  → 天道裁决（顺/平/疑/逆）
  → 天象档位（无/轻/中/重）+ 天谴事件
  → 灾异/粮价/流民/民望
  → POP 人均资源/动乱
  → 派系 satisfaction / influence
  → 下一次党争 tension
```

- 天道是**放大器/刹车**：顺天不奖励数值，但减少灾异；逆天不直接罢官，但制造灾异与民变，
  再由既有政治系统（弹劾/民变/边患）产生后果。
- 党争代码**不得直接写天道数值**；只提交裁决输入，读取裁决档位。

### 24.7 验收（M2/M3）

1. 合法但逆天的党禁 ⇒ `legal=true / procedure=passed / exec_state` 不变，但 `verdict=逆`、
   天象档位上升、生成天谴事件种子；
2. 顺天的调停 ⇒ `verdict=顺`、皇威/民心小幅正向、无灾异；
3. 弹劾：`fact_finding` 只由证据决定，`verdict` 不得改写 `fact_finding`；
4. 同 seed 重放裁决一致；读档重跑不重复施加天谴；
5. 天道裁决不产生任何 `state.*` 直接写入（只读 + 事件种子）。

## 25. 官员行为裁决层（v4.4 新增）

### 25.1 问题

现有官员行为多是**固定阈值/脚本**：
- `decree_confirm` 只判 `confirmed/mismatch/unauthorized/undefined`；
- 泄漏模拟用 `_pressure`（loyalty/corruption/traits）算一个概率；
- 弹劾/拒收/辞官/结党没有统一的行为选择层。

结果：明明有天道裁决机制，大臣却「不灵活」——同一情境下行为可预测、缺少个体差异与政治博弈。

### 25.2 定位

**官员行为裁决 = 天道裁决在「人」层面的投影。**

- 它决定官员在具体情境下**选择哪种行为**；
- **不绕过、不直接改写**事权/程序/执行三态字段；
- 只作为**关口二（封还）与关口三（确认/阻力）的上游证据输入**；
- **不直接写 state**；
- 结果经既有单点落地（`decree_confirm`、`refusal_fact`、`impeachment`、`appoint/dismiss`、`faction_settle`）。

### 25.3 行为空间

| 行为 | 代码 | 说明 |
|---|---|---|
| 奉诏 | `comply` | 正常执行 |
| 拖延 | `delay` | 阳奉阴违/消极 |
| 部分执行 | `partial` | 只办一部分 |
| 封还/拒收 | `refuse` | 合法封驳或抗命 |
| 告发/泄密 | `report` | 向台谏/外廷/敌派泄露 |
| 弹劾 | `impeach` | 主动发起弹劾 |
| 辞官 | `resign` | 以退为进 |
| 结党/串联 | `coalition` | 联合同派/跨派 |
| 转投 | `defect` | 改换门庭 |
| 隐瞒/包庇 | `conceal` | 压案/保人 |
| 举荐/附议 | `recommend` | 推荐同派/人才 |

### 25.4 输入（只读，复用现有）

| 维度 | 现有入口 |
|---|---|
| 个人立场 | `decree_confidential.standing_of`（loyalty/corruption/traits/faction/in_office） |
| 能力/经历 | `state.official_stats` / `official_profile` |
| 派系状态 | `state.factions`（satisfaction/influence/cohesion）、`faction_voice` |
| 命令性质 | **关口二**：`legal` + 天道 `顺/平/疑/逆`（**不含 `exec_state`**）；**关口三**：`legal` + `procedure_state` + 天道（`exec_state` 由 L2/L3 合成，**不作为行为输入**） |
| 风险 | `exposure_profile` / `assess_leak`、皇威、惩罚先例 |
| 利益 | 升迁/贬黜/财货/恩赏；是否触及其基本盘 POP |
| 关系 | 同乡/座师/姻亲/政敌（`relations` 待建） |
| 环境 | 民望/财政/灾异/边患 |

### 25.5 裁决方式（确定性 + 灵活性）

```
seed = hash(official_id, decree_id or event_id, turn)
action = TianDaoEngine.choose(options={comply, delay, partial, refuse, report, impeach,
                                       resign, coalition, defect, conceal, recommend},
                              context=..., seed=seed)
# 输出：{action, confidence, reason, tier}
```

权重来自显式表（示例，非最终数值）：
- `comply ∝ loyalty × 顺天权重 × (1 − 风险)`
- `delay/partial ∝ corruption × 逆天权重 × (1 − 被察觉概率)`
- `report ∝ loyalty × integrity × 逆天权重 × 被察觉概率`
- `impeach ∝ 派系影响力 × 逆天权重 × 是否有实据`
- `defect ∝ (1 − 派系满意度) × 目标派吸引力`
- `resign ∝ 忠诚/气节 × 皇威压力`
- `coalition ∝ 同派/关系强度 × 共同利益`

**灵活性**来自：同一官员在不同天道档位/风险/派系状态下权重不同；不同官员同一情境因 loyalty/corruption/traits 不同而选择不同；
但**同 seed 可复盘**，不是真随机。

### 25.6 天道在这里的作用

| 天道档位 | 官员行为倾向 |
|---|---|
| **顺** | `comply` 权重↑；`report/impeach/refuse` 权重↓ |
| **平** | 按个人/派系利益正常分布 |
| **疑** | `delay/partial/conceal` 权重↑；忠直者 `report` 权重↑ |
| **逆** | `refuse/report/impeach/resign` 权重↑；贪腐者 `conceal/delay` 权重↑ |

- 天道不是唯一变量：忠臣可能死谏（逆天也 `report`），贪官可能压案（顺天也 `conceal`）。
- 官员行为结果**不改变**天道裁决本身；只把「人怎么反应」写进既有单点。

### 25.7 三层分离（v4.5 修正）

行为层**不是**「直接产生执行状态」，而是三层：

| 层 | 名称 | 输出 | 是否写状态 |
|---|---|---|---|
| **L1** | 行为意向 | `{intent, confidence, reason_codes, context_type, candidate_set, behavior_id}` | ❌ 不写 |
| **L2** | 制度裁定 | 合法性/职权归类：`procedure_return` / `execution_refuse` / `report_only` / `delay` / `comply` / `impeach_seed` / `resign_request` / `faction_move` / `conceal` | ❌ 不写；只给裁定 |
| **L3** | 状态落地 | 经正式诏令链/确认流程/人事流程/案件入口/派系结算入口写入 | ✅ 只走单点 |

**关键修正**：
- `refuse` 不再是一个混合行为；L2 必须区分：
  - `procedure_return`（门下依法封驳）⇒ `procedure_state=returned`、`exec_state=not_entered`；
  - `execution_refuse`（受命机构拒收）⇒ 视原因 `blocked` 或 `not_entered`；
  - `report_only`（官员报告不法命令）⇒ 只生成案件/泄密种子，**不改** `procedure/exec`。
- `delay` 也不能由 L1 直接写 `resisted`；必须由 L2 裁定为「可拖延」且 M2 执行评估确认后才写。
- 表述改为：**行为层不直接写状态；它通过 L2 裁定影响状态。**

### 25.8 L2 裁定后的 L3 落地映射

| 行为结果 | 写入点 |
|---|---|
| `comply/refuse` | `decree_confirm.confirmation_state` + `refusal_fact` |
| `delay/partial` | `exec_state=resisted/partially_executed`（M2） |
| `report` | `assess_leak` / 泄密事件种子 |
| `impeach` | `state.impeachments` 案件（M3） |
| `resign` | `dismiss_*` 人事流程 |
| `coalition/defect` | `set_split`（份额）+ `_event_delta` |
| `conceal` | 案件阻力/调查延迟（不伪造证据） |

### 25.9 硬规则（v4.5 收紧）

1. L1 只出意向，不写任何状态；L2 只做制度裁定；L3 只走既有单点。行为层**不绕过三关口状态机、不直接改写三态字段**，只作为关口二/三的上游证据输入。
2. 不决定证据真假（`fact_finding` 只看证据）。
3. **行为概率/倾向不得创造职权**：先按法定职权过滤候选集，再交 `TianDaoEngine.choose`。
4. `context_type` 限定候选集；未列情境默认只用 `comply/delay/report`，不得默认开放弹劾/辞官/转投。
5. 关系数据缺失 ⇒ `relations_undefined=True`，关系项不参与权重，记 `reason_codes`；不得默认为 0 或 1。
6. 同 seed 只保证**可复盘**；L3 必须按 `behavior_id` 幂等，读档重跑不重复 `resign/impeach/coalition/defect/set_split`。
7. 行为概率 ≠ 事实认定；不能把「某人可能告发」当成「已告发」。

### 25.10 角色权限过滤（先过滤，再选择）

| 行为 | 需要的职权/条件 |
|---|---|
| `procedure_return` | `诏令封驳`（门下省/给事中） |
| `impeach` | `监察百官` 或 `言路` |
| `resign` | 在任（`in_office`） |
| `coalition/defect` | 有派系归属；派系层允许 |
| `conceal` | 对案件/诏令有知情权（`knowledge_of`） |
| `report` | 知情 + 有言路/泄密渠道 |
| `delay/execution_refuse` | 受命执行该诏（受命人/机构） |

结果记录 `candidate_set` 与 `filtered_reasons`，便于复盘。

### 25.11 情境候选集（context_type）

| 情境 | 允许的行为 |
|---|---|
| `decree_receive`（接诏） | `comply / delay / execution_refuse / report / resign` |
| `censor_case`（监察案件） | `investigate / report / impeach / conceal` |
| `personnel`（人事） | `accept / resign / recommend / coalition` |
| `faction_conflict`（派系冲突） | `coalition / defect / watch / report` |
| `secret_decree`（密令） | `comply / leak / conceal / report` |
| `fiscal_order`（财政） | `comply / delay / execution_refuse / report` |
| `military_order`（军事） | `comply / delay / execution_refuse / report` |

候选集来自既有流程，不为覆盖 11 个枚举而新造平行流程。

### 25.12 行为幂等

- `behavior_id = hash(official_id, source_id, context_type, turn)`；
- L1 可重算（同 seed 同结果），L3 按 `behavior_id` 幂等；
- `behavior_ledger[behavior_id] = {status, applied_steps, event_id}`；
- 已完成行为不得因读档重跑再次生效。

### 25.13 生命周期单向时序（P0 因果环路修正）

**禁止**把 `exec_state` 作为官员行为的输入，再由官员行为产出 `exec_state`。固定单向时序：

| 步 | 输入 | 产出 |
|---|---|---|
| 1. 关口一 + 天道 | 承办适法性 + 皇帝主权 + 政治行为背景 | `legal` + 天道 `顺/平/疑/逆`（§24、§28） |
| 2. 关口二（审议官行为） | `legal` + 天道档位（**不含 `exec_state`**） | `procedure_state`（如门下封还 ⇒ `returned`） |
| 3. 关口三（受命官行为） | `legal` + `procedure_state` + 天道档位 | `comply/delay/partial/refuse` **证据**；与机构分布、天道各路合规度共同合成 `confirmation_state` 与 `exec_state` |

- 官员行为只提供**证据**，最终 `exec_state` 由关口三的**裁定器**合成；不是 L1 直接写。
- 天道裁决在前，官员行为在后；官员后续行为只能产生**新事件/新裁决**，不得回头改写已定天道裁决。

### 25.14 验收（M2/M3）

1. 同一官员、同一命令，天道 `顺` vs `逆` ⇒ 行为分布显著不同；
2. 忠臣 vs 贪官，同一逆天命令 ⇒ 行为不同（`report` vs `conceal`）；
3. 派系满意度低 ⇒ `defect/coalition` 权重上升；
4. 同 seed 重放一致；读档不重复；
5. 无直接 `state.*` 写入；结果经 `decree_confirm/refusal_fact/impeachment` 等单点；
6. 党争反馈：`report/impeach` 产生 `_event_delta` 或案件种子，可追溯。

### 25.15 实施阶段

| 阶段 | 接什么 |
|---|---|
| M1a | **不接**（只读机构分布） |
| M2 | `comply/delay/partial/refuse`（与 `exec_state` 对接） |
| M3 | `report/impeach/resign`（与案件/人事对接） |
| M4 | `coalition/defect`（与关系网络/份额对接） |

### 26.1 按本游实际接口做的取舍

## 27. 党争奏折 / 弹章层（v4.6 新增）

### 27.1 现有管道（必须复用）

| 环节 | 现有入口 |
|---|---|
| 待审奏折 | `state.memorials` |
| 准奏 | `commands_decree.accept_memorial(state, index)` → 生成诏草、入三省会签 |
| 留中 | `commands_decree.dismiss_memorial(state, index)` → 留中、记怠政反噬 |
| 朱批待阅 | `state.ai_pending_actions`（AI 提议/处置记录） |
| 事实签 | `TianDaoFacade.scan_memorial_seeds(state, limit)`（从真实账本提炼） |
| 记忆/关系 | `memory.memory_graph` 记录准奏/留中 |

> 弹章**不另造奏折系统**；只给 `memorials` 增加 `kind="impeachment"` 等类型与路由。

### 27.2 奏折类型

| 类型 | `kind` | 说明 |
|---|---|---|
| 弹章 | `impeachment` | 台谏/官员弹劾某官 |
| 谏章 | `remonstrance` | 对政策/诏令进谏 |
| 辞呈 | `resignation` | 官员请辞 |
| 举荐 | `recommendation` | 举荐/附议某人 |
| 联名 | `joint` | 多人联署（高张力时） |
| 密奏 | `secret` | 密报（走密令/知情范围） |
| 灾异奏 | `omen` | 天象/灾异后的修省/赈济之请 |

### 27.3 生成来源

| 来源 | 触发 |
|---|---|
| 党争张力 | `faction_tension` 越高，弹章/谏章频率与 severity 越高 |
| 天道裁决 | `疑/逆` 档位 → 谏章/灾异奏；不直接生成弹章证据 |
| 官员行为 | `report/impeach` 行为 → 生成弹章事实签 |
| 天象 | `summarize_monthly_omen` → 灾异奏 |
| 政策冲突 | 站队/打压/党禁 → 敌对派谏章/弹章 |
| 人事 | 辞官/举荐行为 → 辞呈/举荐折 |

### 27.4 事实签字段

```python
{
  "memorial_id": "mem_<hash>",          # 幂等键
  "kind": "impeachment|remonstrance|resignation|recommendation|joint|secret|omen",
  "accuser": "<官员名>",                 # 弹章必填
  "target": "<被弹劾/被谏对象>",
  "target_faction": "<派系|None>",
  "matter_domain": "faction_strife|impeachment|finance|...",
  "trigger_fact": "...",                # 来自真实读数
  "evidence_refs": ["..."],             # 证据引用（可为空=待查）
  "suggested_title": "...",
  "severity": 0.0,
  "tian_dao_verdict": "顺|平|疑|逆|未定",
  "created_turn": int,
}
```

### 27.5 朱批选项与路由

| 朱批 | 路由 | 禁止 |
|---|---|---|
| **准奏** | 弹章 → 开 `impeachment_case`（`investigating`），**不是直接罢黜**；谏章 → 政策复核；辞呈 → 人事流程；举荐 → 任命提案；灾异 → 赈济/修省 | 不得准奏即定罪 |
| **留中** | 记录留中；怠政/民望代价；案件不成立 | 不得把留中当无罪 |
| **彻查** | 开调查、补证据；进入 M3 案件 | 不得跳过证据审查 |
| **罢黜** | 仅在案件已裁定后可用；走 `dismiss_*` | 不得由奏折直接删官 |
| **申饬/驳斥** | 对弹章/谏章的政治回应；`_event_delta` | 不得伪造事实 |

### 27.6 接线方式

- `scan_memorial_seeds` 增加 `matter_domain="faction_strife"/"impeachment"` 的事实签；
- `accept_memorial` 按 `kind` 分流：`impeachment` → `open_impeachment_case()`；其余走原诏草/人事；
- `dismiss_memorial` 保留留中语义，补 `memorial_id` 幂等与 `reason_code`；
- `ai_pending_actions` 记录朱批处置，供史册/邸报回溯。

### 27.7 天道与派系的作用

- 天道 `疑/逆` → 提高谏章/灾异奏频率与 severity；**不生成弹章证据**。
- 党争张力/党禁 → 提高弹章频率、联名概率；目标派影响力高时可能被**压案/留中**（记 `suppressed_by_faction`），但不得销毁奏折。
- 被弹劾者派系影响力可影响**调查阻力**，不影响证据真假。

### 27.8 幂等

- `memorial_id = hash(seed_id, turn, kind, target, accuser)`；
- `memorial_ledger[memorial_id] = {status, disposed_turn, outcome}`；
- 读档重跑不得重复生成同一弹章、重复准奏或重复开案；
- `accept_memorial`/`dismiss_memorial` 必须按 `memorial_id` 幂等，而不是只按 index。

### 27.9 硬规则

1. **弹章 ≠ 定罪**；准奏 ≠ 罢黜；留中 ≠ 无罪。
2. 弹章必须有 `accuser`、`target`、`trigger_fact`；缺一不生成。
3. 天道/派系不得改写 `evidence_refs` 或 `fact_finding`。
4. 所有处置经既有 `accept_memorial`/`dismiss_memorial`/人事/案件入口，不直接写 state。
5. 同一 `memorial_id` 只处置一次。

### 27.10 验收（M2/M3）

1. 高 tension ⇒ 弹章数量/severity 上升；低 tension ⇒ 下降；
2. 弹章准奏 ⇒ 开 `investigating` 案件，**不**直接罢官；
3. 留中 ⇒ 不开案，但记怠政/民望代价；
4. 天道 `逆` ⇒ 谏章/灾异奏增加，弹章证据不变；
5. 同 `memorial_id` 读档重跑不重复生成/处置；
6. 缺 `accuser/target/trigger_fact` 的弹章不生成。

### 27.11 阶段

| 阶段 | 接什么 |
|---|---|
| M1a | **不接** |
| M2 | 奏折生成、朱批路由、准奏/留中幂等 |
| M3 | 弹章 → 案件 → 证据审查 → 裁定闭环 |
| M4 | 联名弹章、党禁奏折、派系压案 |

## 28. 皇权 vs 臣权：亲裁、超迁、御驾亲征与有司承办（v4.8 裁定）

### 28.1 一句话

**皇帝可以亲裁、亲行、破例；限制不是「无权」，而是四件事：**

1. **个人精力/健康/时间**（capacity）；
2. **政治代价**（皇威/民望/史评/台谏积怨）；
3. **臣权抵制**（封驳/谏争/拖延/不奉诏/辞职/弹劾）；
4. **行政执行仍需有人去做**（军队/有司/地方）。

> 所以不再写「皇帝不能亲自带兵/提拔」；正确表述是：
> **皇帝可以亲征、可以超迁，但亲自行使有成本、有风险、会被臣权抵制，且最终仍要有人执行。**

### 28.2 皇权光谱

| 层级 | 皇帝做什么 | 例子 | 是否绕程序 |
|---|---|---|---|
| **委托** | 决定，交有司办 | 常诏 | 否 |
| **亲裁** | 亲自拍板，仍走部分程序 | 超迁、特旨除授、亲录囚 | 部分 |
| **亲行** | 亲自到场/亲自指挥 | 御驾亲征、亲祭、亲审 | 是（部分） |
| **破例** | 绕中书/门下，直付 | 中旨、御笔 | 是 |
| **压制** | 罢黜/党禁/清洗 | 贬台谏、党禁 | 是（高代价） |

### 28.3 皇帝可以亲自行使的权力

| 权力 | 做什么 | 个人成本 | 政治代价 | 臣权抵制 | 结果 |
|---|---|---|---|---|---|
| **御驾亲征** | 亲统大军 | 健康/京城空虚/继承风险 | 皇威大起大落 | 宰相/枢密/台谏谏阻 | 胜/败/僵持 |
| **超迁** | 越级提拔 | 精力/察人不明 | 铨选制度受损、其他官员不满、派系反弹 | 吏部封驳/台谏弹劾 | 任命成功+政治反噬 |
| **特旨除授** | 特旨授官/宫观祠禄 | 精力 | 制度弹性/被授者感恩 | 吏部/台谏 | 任命+制度争议 |
| **亲录囚/亲审** | 亲自审案 | 时间/专业不足 | 皇威/民心 | 刑部/大理寺 | 平反/冤案风险 |
| **御笔/中旨** | 亲笔诏令 | `DIRECT_DECREE_MAX` | 皇威/民望/台谏积怨 | 门下封还/台谏谏争 | 执行/封驳 |
| **亲祭/封禅** | 亲自主祭 | 时间/财政 | 皇威/合法性 | 礼部 | 合法性+财政压力 |
| **内帑** | 私财动用 | 内帑余额 | 民望/户部抗议 | 户部 | 可绕财政审核但有政治代价 |

### 28.4 臣权的六个支点

| 臣权 | 载体 | 能做什么 |
|---|---|---|
| **封驳** | 门下省/给事中 | 封还词头、要求复议 |
| **副署** | 宰相/中书 | 拒绝副署、拖延 |
| **铨选** | 吏部 | 按资序铨选、抵制超迁 |
| **财政审核** | 户部/三司 | 拒拨、缓拨、要求度支 |
| **台谏** | 御史台/谏院 | 谏争、弹劾、风闻 |
| **执行** | 有司/地方/军队 | 拖延、阳奉阴违、不奉诏 |

### 28.5 博弈判定

```
imperial_action      = {delegate, personal, bypass, suppress}
ministerial_response = {comply, return, remonstrate, delay, refuse, resign, impeach}
outcome = f(imperial_action, personal_capacity, political_cost,
            ministerial_resistance, executor_authority)
```

- 皇帝亲裁/亲行 **不等于自动成功**；臣权可以封驳、谏争、拖延、不奉诏。
- 皇帝可以压服（罢黜/超迁/亲征），但会改变政治格局与制度成本。
- 皇帝不能凭一句话让不存在的事权/资源/军队/机构凭空出现；仍需要有人执行。

### 28.6 与现有代码的接线

| 现有机制 | 用途 |
|---|---|
| `DIRECT_DECREE_MAX = 2` | 御笔/中旨的月度个人精力上限 |
| `S_DIRECT_BONUS = 0.10` / `S_ZHONGZHI_SUPPORT_WEIGHT = 0.04` | 御笔/中旨对执行率的既有影响 |
| `issue_edict_from_review(decision="force")` | 御笔直发 → 中旨的现有入口 |
| `official_appraisal`「特旨除授宫观祠禄」 | 已有的特旨任命路径 |
| `emperor_health` / `emperor_alive` / `is_abdicated` | 亲征/亲行的个人成本与资格 |
| 台谏积怨（`commands_decree.py`） | 御笔中旨次数与台谏积怨跟踪 |
| `issue_military_order(executor=...)` | 御驾亲征后的调兵/粮草仍需枢密院执行 |

- **御驾亲征/超迁**当前无独立入口；M2/M3 新增 `imperial_personal_action`，
  但必须走既有军事/人事/案件单点，不另造账本。

### 28.7 验收

1. **御驾亲征**：`emperor_health`/`prestige`/`army` 变化；败则皇威大跌，胜则大涨；不能自动获胜。
2. **超迁**：目标官上任，但吏部/台谏反弹、其他官员 satisfaction 下降、铨选制度受损。
3. **特旨除授**：走现有 `official_appraisal` 特旨路径；不绕过人事记录。
4. **御笔**：受 `DIRECT_DECREE_MAX` 限制；中旨仍可被门下封还。
5. **亲录囚**：可平反/制造冤案；刑部/大理寺抵制。
6. **臣权抵制**：封驳/谏争/拖延/不奉诏都有明确状态与代价。
7. **UI 文案**：不写「皇帝无权」，只写「亲裁成本 / 臣权抵制 / 执行受阻」。

### 28.8 与三关口的关系

- 委托执行（常诏）仍走 §3 三关口；
- 亲裁/亲行/破例走本节博弈路径，**不套用** `executor_authority` 二值判定；
- 但亲裁之后仍需有人执行（如御驾亲征仍需枢密院调兵、超迁仍需吏部发告身），
  执行阶段仍受臣权与实际能力约束。

## 30. 回合制时序（v4.9 修正）

### 30.1 总则

- **1 回合 = 1 月**；`state.turn` 是唯一时钟。
- 所有延迟用 `due_turn` / `end_turn` / `created_turn`；所有时点显式标注
  `same_turn | next_turn | turn_start | turn_end`。
- 同一 `turn` 重入必须幂等（`turn` 进入所有 id）；`advance_turn` 是唯一时钟推进。
- 禁止 `time.time()` / `datetime.now()` / `random` 做政治计时或掷点；只用 `turn` + `TianDaoEngine.dice(seed)`。

### 30.2 回合内固定顺序

| 阶段 | 做什么 | 与现有管线的关系 |
|---|---|---|
| `turn_start` | 到期事项：`resisted` 重评、弹劾审理、党禁到期、事件触发 | `settle_local` 之前 |
| `memorials` | 生成当回合奏折/弹章（天道 scan + 官员 `report/impeach` + 张力） | `commands.py` 上折段 |
| `player_commands` | 玩家下诏/朱批/召见/任免（受 `decree_bandwidth` / `DIRECT_DECREE_MAX` 限制） | 玩家阶段 |
| `court` | 廷议/会签/封驳；官员 L1/L2（接诏/审议） | `settlement_decree` 前段 |
| `execution` | 逐事权执行评估（ready/resisted/partially_executed/blocked） | `settlement_decree` 执行段 |
| `tian_dao` | 对当回合重大行为裁决（顺/平/疑/逆 + 天象/史评） | 新 `faction_strife` 前后 |
| `settlement` | 经济/财政/军事/派系 metrics/官员 L3 | 现有 49 步管线 |
| `events` | 事件/灾异/党争张力更新 | `events`/`situations` 步 |
| `turn_end` | 史册/邸报、清理、进入下一回合 | `turn += 1` |

### 30.3 各机制时点

| 机制 | 产生 | 裁决 | 落地 | 跨回合 |
|---|---|---|---|---|
| 圣旨 | 玩家阶段 | 关口一/二立即；关口三结算 | 结算 `decrees` 步 | `resisted` 按 `due_turn` |
| 天道 | 玩家阶段（随诏/事件） | 同回合 | 结算 `faction_strife` | 不重掷；`verdict_id` 含 turn |
| 官员行为 | 接诏/审议时 L1 | 结算 L2 | 结算 L3 | 每官每诏每回合最多一次 |
| 弹章 | `memorials` 阶段 | 玩家朱批同回合 | 次回合 `faction_strife` 审理 | `due_turn = T+1` |
| 党禁 | 玩家阶段 | 同回合 | 结算 `faction_strife` | `end_turn = T+6/12` |
| 奏折 | `memorials` 阶段 | 玩家朱批 | 同回合或次回合 | 未批结转，`turn_end` 计怠政 |
| 张力 | — | `faction_strife` 每回合一次 | 同回合 | 连续 `N` 回合判失败态 |

### 30.4 三处必须改写的旧表述

1. 「延迟 1 月」→「`due_turn = T+1`（下一回合重评）」。
2. 「冷却 6/12 个月」→「`end_turn = T+6/12`（6/12 回合）」。
3. 「3 期」→「`resist_period=1..3`，每期 1 回合」。

### 30.5 禁止

- 不在回合中途插入实时事件；所有事件在固定阶段。
- 不把「3 期」写成「3 天/3 小时」；统一「3 回合」。
- 不用「毫秒/秒/分钟」做延迟；统一 `due_turn` 整数。

## 34. M1b-3c 修正：权限挂在职位上（2026-10-18）

### 34.1 裁定

- **权限是职位的属性**：任职某职位 = 拥有该职位的事权；免职/空缺 = 失去该事权；
- 同一人兼多个职位 ⇒ 权限取**并集**；
- **部门只是职位的集合与默认归属**，不是权限主体；`AUTHORITY_MATTERS.owner` 只是默认分组；
- **不引入**「特旨授予/委任/收回」独立层；**任命/免职就是权限变更的唯一途径**；
- 皇帝要换权限持有人 ⇒ 走人事任免（含超迁/特旨除授），不是直接改权限表。

### 34.2 实现

| 项 | 内容 |
|---|---|
| 新模块 | `game/core/permission_model.py`：`resolve_actor` / `post_permissions` / `has_permission` / `permission_holders` / `permission_capture` / `personnel_authority` |
| 判权 | `has_permission(actor, matter)` = 该人在任职位的事权并集是否含 matter |
| 人事入口 | 四个入口改用 `permission_model.personnel_authority` |
| 自动解析 | 取 `permission_holders(matter)` 的**当前在任持有人**，不再返回「吏部」部门 |
| 兼容 | `institution.require_matter` 保留为**部门级旧口径**；新代码一律走 `permission_model` |
| 读数 | `institution_distribution` 是**任职分布**；`permission_capture` 才是**事权分布**（M1a-2） |

### 34.3 验证

- 权限模型 9 条 + 人事迁移/接线 20 条 + 人事回归/叶子 29 条 = **58 passed**；
- 全量 pytest：见下方基线（本批提交时以 junit 为准）。

## 35. 皇威权柄（2026-10-18 设定）

### 35.1 规则

- **皇威 > 阈值**：皇帝获得该**权柄**，特定程序化命令**言出即行**；
  跳过执行侧权限与程序，但仍校验**目标合法/物理约束**，并支付**皇威代价**。
- **皇威 ≤ 阈值**：走正常流程；承办人须因**在任职位**持有该事权；入队 `due_turn=T+1`。
- 皇威**不改变职位权限表**；直行是**皇权对程序的覆盖**，不是把事权授给某部门。
- 阈值与代价都是**平衡数值**，可调。

### 35.2 权柄表

| 权柄 | 阈值 | 直行代价 | 状态 |
|---|---|---|---|
| 任免 | 80 | 2 | **已接** `personnel_order` |
| 调兵 | 85 | 5 | 已登记，待接军队入口 |
| 财政直令 | 85 | 3 | 已登记，待接财政入口 |
| 刑狱 | 80 | 2 | 已登记，待接刑狱入口 |
| 党禁 | 90 | 8 | M4 |

### 35.3 实现

| 项 | 内容 |
|---|---|
| 权柄表 | `core/imperial_mandate.py`：`DirectActionSpec` / `ACTION_SPECS` / `can_direct` / `charge_direct_cost` |
| 任免 | `core/personnel_order.py`：直行 `imperial_direct=True`，跳过执行侧权限；走流程仍走 `permission_model` |
| 低层写入口 | `appoint_*`/`dismiss_*` 新增 `imperial_direct` 参数；仅权柄通道可置 True |
| 未来权柄 | 先在表中 `implemented=False` 登记，避免假接线 |

### 35.4 验收

1. 皇威 81 + 任免 ⇒ 立即落地，扣 2 皇威；
2. 皇威 80 + 任免 ⇒ 入队，`due_turn=1`，本回合不改官职；
3. 下一回合结算 ⇒ 落地；
4. 皇威 81 + 户部 executor ⇒ **直行成功**（皇权覆盖执行侧权限），但非法目标仍拒绝；
5. 皇威 80 + 户部 executor ⇒ 走流程拒绝；
6. 重复结算 ⇒ 只生效一次；
7. 结算前承办职位被废 ⇒ 失败，不改官职；
8. `military_dispatch` 等已登记但 `implemented=False`，`can_direct` 为 False。
