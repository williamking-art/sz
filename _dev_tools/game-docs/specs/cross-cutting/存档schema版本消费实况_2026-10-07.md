## 一、两件事被混叫成"schema 版本"，实际是两套

| 层 | 写在哪 | 读/校验在哪 | 状态 |
|---|---|---|---|
| **顶层存档版本**（整个存档文件） | `core/save_load.py:86` `"schema_version": 3` | `core/save_load.py:434-449` | **真机制** |
| **子系统级版本戳**（各数据块内） | 13 个 `*SCHEMA_VERSION` 常量、共 **37 处**写入 | 仅 **1 处**真消费（见下） | **写而不读为主** |

### 顶层版本门（真实存在）

```
:434  _ver_raw = data.get("schema_version", 1)
:435  _ver = _safe_int(_ver_raw, default=None)      # 非法类型不抛异常（P2-10）
:437  若 None → error + 改名为 .corrupt 备份 + 返回 None（调用方按"档损坏"处理）
:446  若 _ver > 3 → error + 拒绝加载
```

⚠️ 但上限 **`3` 是硬编码字面量**，共 3 处（写值 1 处 + 门 1 处 + 文案 1 处），且**没有**
`SAVE_SCHEMA_VERSION` 之类的常量。⇒ 出下一版存档格式时，最容易漏改的就是这三处字面量。

### 子系统版本戳：13 个常量，只被消费 1 次

全项目 `*SCHEMA_VERSION` 常量共 **13 个**，取值**全部 = 1**（从未有任何子系统升过版）：

`ACTOR` `DECREE_CONFIRM` `DECREE_PLAN` `DYNAMIC_BLUEPRINT` `EXPORT_POLICY` `FINANCE`
`INCOME_READOUT` `MARKET_READOUT` `MATERIAL` `PLAN_ACTION` `POPAGE` `PRICE` `TRADE`

消费面逐类（AST 判定：常量出现在比较表达式里才算"被消费"）：

| 类别 | 个数 | 说明 |
|---|---:|---|
| 进存档头聚合（`_plan_schema_versions()`） | 3 | `DECREE_PLAN` / `DYNAMIC_BLUEPRINT` / `PLAN_ACTION` |
| ↑ 其中**真的参与判定** | **1** | 仅 `PLAN_ACTION`：`save_load.py:914` 逐条 `_ver > _supported["plan_action"]` ⇒ 跳过该条行动 |
| 进存档头但无人比对 | 2 | `DECREE_PLAN`、`DYNAMIC_BLUEPRINT`（打进头里，读侧不看） |
| 只打戳、全项目无任何读取判定 | 8 | `FINANCE` `MATERIAL` `PRICE` `TRADE` `MARKET_READOUT` `INCOME_READOUT` `EXPORT_POLICY` `POPAGE` |
| 只打戳（`ACTOR` / `DECREE_CONFIRM` 两类） | 2 | 同上，写在返回契约/结构里 |
| 透传保留（非校验） | 1 | `save_load.py:969` `minister_agents` 读回后**原样存回**，不判定 |

⇒ **判定口径**：存档头只聚合 3 个常量，而项目里有 13 个；且其中 10 个连聚合都不进。
所以"子系统级版本"目前是**给人看的标记 + 一处真门（plan_action）**，不是迁移分派机制。

## 二、据此修正的两条结论

1. **撤回**"先建 schema 版本注册表，再搬 `save_game`"这一提案。
   理由：注册表服务的是"按版本分派迁移"，而该机制**当前没有消费方**（除 `plan_action` 一处），
   13 个常量也从未变过。为不存在的机制建接口＝给假想需求做设计。
   该做的时机是**第一次出现"某子系统 v1→v2 且需按版本分派"**时——那时才知道注册方是谁、
   缺项该硬失败还是降级。
2. **架构方案 §4.1 里"persistence = 存档读写、版本迁移"这句中的"版本迁移"**，
   按现状应读作"**按字段存在性做幂等迁移**"（如 `_migrate_pops_to_seats`、`_merge_regions`、
   `_strip_unknown_faction_keys` 都是"缺则补、有则不动"，不看版本号），
   而**不是**"按 schema 版本号分派迁移函数"。显式标注以免后人误当现状已具备。

### 三之补：搬走 `_slot_path` 的**实测副作用**（2026-10-07，第七包开工后才暴露）

本节的"纯叶子"判定按**导入边**做的，`_slot_path` 确实没有导入边——但它有另一条隐藏依赖：
它读的是**所在模块的模块级 `SAVE_DIR`**。搬到 `persistence/slots.py` 后，这条读源跟着搬家，
而 `save_load.save_game` 里"建目录"那行仍读 `core.save_load.SAVE_DIR` ⇒ 两处不同源。

第七包首跑全量 `EXIT=1`、3 例 `FileNotFoundError` 就是它。**教训**：叶子资格不能只看 import，
**模块级可被 monkeypatch 的全局名也是依赖**（本项目里 `SAVE_DIR` 正是测试重定向的开关）。
处置与断言见 [`foundation/README.md` §五](../../../../game/core/foundation/README.md)。

### 三之补 2：三处**同名不同实现**的 `_safe_int`（复核"第八包前置"时新登记的风险）

| 位置 | 签名 | 关系 |
|---|---|---|
| `core/save_load_util.py:63` | `_safe_int(value, default=None)` | 权威那份。**第八包起实现已搬到 `core/foundation/common/numeric.py:80`**，`save_load_util` 只留转发；`core/save_load.py` 是其唯一业务调用方（10 个调用行：`_safe_int` 8 + `_safe_float` 2） |
| `ai/client_utils.py:708` | `_safe_int(v, default, lo, hi)` | **另写**，带区间夹取 |
| `core/free_effect.py:30` | `_safe_int(v, default: int = 0)` | **另写**，无区间 |

**实测语义差异表**（第八包复核时跑的，`default` 用各自缺省）：

| 输入 | `parse_number` | `_safe_int` | `_safe_float` |
|---|---:|---:|---:|
| `None` / `""` / `[1]` / `nan` / `inf` | `0.0` | `None` | `None` |
| `True` | `1.0` | `1` | `1.0` |
| `'2.7'` | `2.7` | **`None`** | `2.7` |
| `2.7` | `2.7` | `2`（截断） | `2.7` |

⇒ 单独记一条此前无人写过的口径：**存档整数字段被写成小数串时，`_safe_int` 判为"缺失"而不是截断**
（`int('2.7')` 抛 `ValueError` → 回 `default`）。读档的"缺失值不作 0"就建立在这点上。

⇒ 三者语义不同（是否夹取、缺失默认值口径），**不是**同一函数的重复拷贝，合并/收敛属**口径变更**，
须另立批次先证语义等价，不混入结构迁移。
⇒ 方法教训：按**名字** grep 会得到跨实现的假命中（本文件原写"`_safe_int` 有 4 个跨域调用方"就是这么错的，
实际那 3 个命中里 2 个是同名自定义、1 个是注释）。**调用方计数必须按导入来源判**。
