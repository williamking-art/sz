## 2. 真正的守恒式（已验证）

**配货前后 Σ(商人持有 + 国库库存) 不变** —— 实测 丝/麻/铁 有搬运，总量差恒 **0**。
这条才是「搬运守恒」；holding_report 的「持有 == 库存」是另一个更强的断言。

## 3. 候选缺陷（本轮只报不改）

**位置**：game/core/foundation/ledger/material_holding.py::supply_goods_to_seats
（need = stock - held 于 :681；_cell[stock] = max(0, _cur - int(put)) 于 :725-728）

**现象**：配货后 **held_after == stock_before 且 stock_after == held_before**（两者互换）。
门用例实测：配货后「铁」为 merchant_total=961812 / stock_total=961811 / gap=-1。

**成因**：把 stock **同时当成「配货目标总量」与「来源库存」**：
先按 need = stock - held 补足商人，又把同样的 need 从 stock 扣掉
⇒ 相当于「用 A 补 B，再从 A 扣 B 的量」。

**影响**：不影响总量（守恒成立），但
① holding_report 在 stock > 0 时**必然报 gap≠0**，这个自检实际不可用；
② 商人与国库的相对读数被系统性偏移。

**改法（二选一，均属口径变更 ⇒ 需裁定）**：

| 方案 | 语义 | 验收断言 |
|---|---|---|
| **A 目标语义** | stock 是「应达总量」，配货只补差额、**不扣 stock** | 配货后 held == stock；Σ 守恒 |
| **B 真搬运** | stock 是「待发库存」，一次搬空 | 配货后 stock == 0 且 held == 原 stock；Σ 守恒 |

现门里用 **xfail(strict=True)** 钉住 A 的断言：**修好那天它会变红**，强制同步更新文档与用例；
另有一条正例钉住「当前是互换行为」，任何口径改动都会被看见。
