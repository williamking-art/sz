# 党禁机制设计（2026-10-19）

> 状态：**设计稿，未授权实现**；关键取舍待真实 JEV 裁决。
> 历史出发点：**行政命令压不住党派**。党禁能改变“谁还能做官”，不能消灭“谁还在网络里”。

## 0. 核心命题

**党禁不是删除派系，而是把派系从“正式职位网络”赶进“非正式网络”。**

三条铁律：
1. 党禁只能降低**正式职位准入/在任比例**（`permission_capture`），不能直接删 `state.factions` 或清零 POP 基础。
2. 压得越狠，`grievance`（怨望）与 `cohesion`（抱团）越高；正式渠道越窄，非正式网络越强。
3. 执行党禁本身要消耗皇威、台谏支持与行政能力；执行越弱，党禁越可能只是“名义禁令”。

## 1. 历史含义 → 机制映射

| 历史现象 | 机制映射 |
|---|---|
| 元祐党籍、崇宁党禁、党人碑 | 正式除授限制 + 在朝者落职；不删派系 |
| 禁子弟、限差遣、编管 | 任命禁令 + 人事令逐人处置，不直接改 holder |
| 被禁者转向讲学、地方、姻亲、门生 | `grievance`↑、`cohesion`↑、非正式影响↑ |
| 禁令由政敌执行、借机扩权 | 执行强度受派系渗透/台谏/宰相配合影响 |
| 禁而不绝、日后昭雪 | 到期解除 +5 一次；保留“党禁记忆”修正 |

## 2. 三层模型

1. **正式层**：职位准入、在任 holder、`permission_capture`。
2. **非正式层**：`grievance`、`cohesion`、门生/姻亲/地方网络；不新建“第二个 influence”。
3. **皇权代价层**：皇威、台谏怨望、士林清议、行政效率。

## 2.1 天道层：只裁“天意/史评”，不改合法性

党禁是重大政治行为，必须进天道，但**天道不能改写 legal/procedure/fact_finding**。它只回答：
“这件事在天意与史评上是什么档位，会招来什么天象/反噬。”

**现有真实接口**（`game/core/ai/tiandao_engine.py` / `tiandao_facade.py`）：
- `TianDaoEngine.gate`：二元放行；
- `TianDaoEngine.choose`：多档选择（顺/平/疑/逆）；
- `TianDaoEngine.score`：分档（天象 无/轻/中/重、史评 褒/中/贬）；
- `TianDaoEngine.dice(seed, entropy)`：确定性微扰；
- `TianDaoFacade` 已有 `reform_compliance_gate` / `circuit_decree_compliance` / `summarize_monthly_omen` / `scan_memorial_seeds` 等业务门面。

**设计新增（待建，M4）**：`TianDaoFacade.faction_ban_verdict(state, ban) -> dict`，作为党禁唯一裁决出口，内部组合 `choose/score/dice`，不另造模型。

输入：皇威、台谏反对强度、士林/科举反应、`grievance`/`cohesion`、株连范围、财政/民望、执行事实。
输出：`{verdict_id, verdict(顺/平/疑/逆), omen_tier(无/轻/中/重), historical_assessment(褒/中/贬), reason_codes, defined, basis_undefined, seed}`。

| 裁决 | 对党禁的影响 |
|---|---|
| 顺 | 执行阻力小幅下降、史评偏褒；**不消灭派系** |
| 平 | 无额外修正 |
| 疑 | 反噬阈值下降，台谏/士林事件概率上升，皇威小幅受损 |
| 逆 | 天谴/灾异/民变事件种子；皇威/民望明显受损；**仍不改 fact/legal** |

纪律：
- `verdict_id`/`event_id` 进 `political_event_ledger`，同 seed/同回合不重复施加；
- `basis_undefined=True` ⇒ 不判、不伪造“平”；
- 不用 `random.random()`；只用 `TianDaoEngine.dice(seed)`；
- 天道不能替玩家决定是否党禁，也不能把“疑/逆”写成“党禁非法”。

## 2.2 科举层：党禁的“下一代官僚再生产”

现有科举（`core/domains/administration/imperial_exam.py` + `officialdom.py`）：
- 每 **36 个月**开科，`run_triennial_exam_full` 走解试→省试→殿试；
- `state.exam["cohorts"]` 保留最近 12 科；
- `_examiner_faction` 解析座主（知贡举）派系：显式指派 → 人名 → 礼部在任者；
- 新进士经 `blend_entrants` **随座主入派**，只改 `faction_split` 比率、Σ=1；
- `run_three_halls_assessment` 提供三舍法/学校路径（崇宁三年罢科举行三舍的历史入口）。

党禁对科举的影响按级别：

| 级别 | 考官/知贡举 | 子弟应试 | 三舍/学校 | 新科 cohort |
|---|---|---|---|---|
| 轻 | 被禁派系不得任当科考官 | 不禁 | 不禁 | `ban_context` 记录，lean 不变 |
| 中 | 考官须非被禁派系 | 被禁派系子弟**不得参加当科** | 限制入学名额 | `ban_context` + lean 轻微偏离 |
| 重 | 清除被禁派系考官 | 子弟禁当科 + 限制差遣 | 三舍/学校限制 | `ban_context` + lean 明显偏离 + 士林反噬 |

关键设计：
- **禁而不绝**：若考官仍是被禁派系（执行失败/渗透），`blend_entrants` 仍会让新进士随座主入派；党禁只能降低概率/名额，不能清零。
- `exam["cohorts"][-1]["ban_context"] = {faction, level, examiner_banned, restricted_children}`；不新增顶层 state。
- `blend_entrants` 只改比率，不改 POP size；禁止直接改 `state.faction_split`。
- 重级“禁子弟/限三舍”必须走**科举入口**的资格判断，不直接删考生/POP。
- 科举年与党禁 `end_turn` 的交叉：6/12/18 回合的党禁可能覆盖 0–1 个科次；重级更容易跨科次，故反噬更重。
- 历史依据：元祐党籍/崇宁党禁的“禁锢子弟、限制差遣”；崇宁三年罢科举行三舍（`宋代官制与三冗设计.md` §15）。

## 2.3 天道 → 行为：派系 / 人物 / 机构

天道裁决不是终点，它给行为层提供**倾向证据**。三层行为都要走既有单点，不得由天道直接写状态。

### 2.3.1 三层行为

| 层 | 天道给什么 | 行为表现 | 写入点 |
|---|---|---|---|
| 派系 | verdict + grievance/cohesion | 抱团/离心、转投阻力、告发/弹章/隐匿倾向 | `faction_settle` / `set_split` |
| 人物 | verdict + `derive_dialogue_stance` 的 stance/intensity/compromise_threshold | L1 `comply/delay/report/impeach/resign/conceal/faction_move` → L2 制度裁定 → L3 | 诏令/确认/人事/案件/派系单点 |
| 机构 | verdict + `circuit_decree_compliance` 的 mult、`reform_compliance_gate`、`appraisal_score`、`granary_corruption_check` | 执行快慢、阳奉阴违、积压、贪墨、考课 | `decree_effect` 合成层 / 机构结算 |

### 2.3.2 现有真实接口

| 接口 | 输出 | 用途 |
|---|---|---|
| `TianDaoFacade.derive_dialogue_stance` | `stance/intensity/compromise_threshold/defined/in_office` | 人物 L1 意向权重；不写 state |
| `TianDaoFacade.circuit_decree_compliance` | `verdict` + `mult`（1.05/0.90/0.65/0.40） | 机构执行证据，供 `decree_effect.effect_channels` 合成层消费 |
| `TianDaoFacade.reform_compliance_gate` | bool | 改革/党禁执行是否阳奉阴违 |
| `TianDaoFacade.appraisal_score` | 分档分数 | 官员考课/执行能力证据 |
| `TianDaoFacade.granary_corruption_check` | bool | 贪墨风险；无依据不判贪 |
| `TianDaoFacade.summarize_monthly_omen` | 月报天机 | 叙事/月报，不直接改行为 |
| `TianDaoFacade.scan_memorial_seeds` | 奏折事实签 | 奏折/弹章生成，不直接定罪 |

### 2.3.3 裁决档位对行为的影响

| 天道 verdict | 派系行为 | 人物行为 | 机构行为 |
|---|---|---|---|
| **顺** | 抱团略升但告发/转投下降 | `comply` 权重升、`delay/report` 降 | `mult` 取高段；积压/贪墨风险降 |
| **平** | 基线 | 基线 | 基线 |
| **疑** | grievance 升、告发/弹章升、转投阻力升 | `delay/report/conceal` 权重升，`comply` 降 | `mult` 取中低段；考课/执行阻力升 |
| **逆** | 抱团/怨望显著升，离心与告发并存 | `impeach/resign/conceal/defiance` 权重升 | `mult` 取最低段；积压/贪墨/地方阻滞升；生成天谴事件 |

### 2.3.4 硬规则

1. 天道只出**概率/档位/证据**，不直接写 `exec_state`、`grievance`、`cohesion`、holder。
2. 先按**法定职权**过滤候选行为集，再交 `TianDaoEngine.choose`；行为概率不得创造职权。
3. L1 只出意向；L2 只做制度裁定；L3 只走既有单点（诏令/确认/人事/案件/派系）。
4. `exec_state` 不作为行为输入；关口三由 `legal + procedure + 天道 + 行为证据 + 机构分布` 合成。
5. `behavior_id = hash(official_id, source_id, context_type, turn)`；`verdict_id`/`behavior_id` 幂等，读档重跑不重复 `resign/impeach/conceal/defect`。
6. 同 seed 只保证可复盘，不用 `random.random()`；`basis_undefined=True` 不伪造“平”。
7. 天道不能把“可能告发”写成“已告发”，也不能把“疑/逆”写成“党禁非法”。

## 2.4 情报层：皇帝通过大臣/机构获取信息，不通过 UI 全知

**硬约束：不新增 UI、不改现有面板。** 皇帝不是全知视角；党禁的执行、派系反应、民情变化，只能通过**大臣与机构**这条链路进入玩家视野。

| 渠道 | 能看到什么 | 偏差/延迟来源 | 现有落点 |
|---|---|---|---|
| 宰相/中书 | 党禁执行概览、人事空缺、政策阻力 | 宰相自身派系/自保；可能压案 | 召对、奏折、`monthly_gazette` |
| 台谏 | 弹章/谏章、风闻、联名 | 派系攻击、风闻失实；可能被留中 | `state.memorials` |
| 吏部/户部 | 任免执行、财政/度支影响 | 数据滞后、瞒报、机构 capture | 机构奏报/`circuit_decree_compliance` |
| 监司/知州 | 地方执行、民情、士林反应 | 地方自保、截留、阳奉阴违 | 路级合规/奏报 |
| 内侍/皇党 | 私下情报、宫禁消息 | 不可靠、迎合、派系操纵 | 召对/密奏 |
| 天道/天象 | 灾异、吉凶、史评 | 只给档位，不给精确数值 | `summarize_monthly_omen` |

情报规则：
- 皇帝看到的不是 `grievance/cohesion/permission_capture` 精确值，而是**奏报档位 + 叙事 + 可追问项**；
- 奏报可以**滞后、偏差、被派系过滤**；`scan_memorial_seeds` / `derive_dialogue_stance` 是证据来源，不是全知读数；
- 玩家只能基于奏报决策；想查得更准，走召对/勾校/台谏，不靠新 UI；
- 情报质量受**渠道忠诚/能力、机构 capture、贪腐、党禁 grievance、交通通信**影响，但**不把公式和精确值展示给玩家**。

UI 边界：
- 不新增“党禁仪表盘”“派系仇恨条”“精确 capture 面板”；
- 复用现有奏折/召对/邸报/月报；只给档位词与叙事；
- 前端不得重算党禁数值、不得直写 state、不得显示 hidden 字段；
- 若未来确需 UI，先单独裁定，不在本设计内动。

验收：
1. 不新增 UI 文件/面板；现有面板不改布局；
2. 玩家可见文案不出现 `grievance/cohesion/permission_capture` 精确数值；
3. 同一事实可因渠道不同出现不同奏报（滞后/偏差）；
4. 奏报不能替代证据：弹章仍需 `evidence_refs`，党禁执行仍需人事令；
5. 玩家不能通过 UI 直接看到“派系已消灭/未消灭”的全知结论。

## 2.5 奏折前的执行层（党禁先作用于这里）

- 党禁不是先作用奏折，而是先作用于**地方官/监司/机构的日常事故处理与执行**；
- 被禁派系地方官/监司被罢黜或限制任用 → 处理能力下降、代办 +1 回合、事故升级更频繁；
- 执行党禁的部门可压案/拖延/给偏向建议（`suppressed_by_faction`/`delayed`），但原始报告仍留档；
- **禁而不绝**：正式 `permission_capture` 下降，门生/吏员/地方网络仍在，执行受非正式影响；
- 只有事故升级/需钱粮/人事/政策/军令/问责时，才整理成御前摘要；已解决只进邸报/背景档；
- 天道 verdict 影响执行/反噬，不改 `legal/procedure/fact_finding`；不新增 UI。

## 3. 级别

| 级别 | 时长 | 正式 capture | satisfaction target | cohesion target | grievance | 反噬 |
|---|---|---|---|---|---|---|
| 轻 | 6 回合 | **-15%** | **-8** | **+3** | **+5** | 低 |
| 中 | 12 回合 | **-35%** | **-15** | **+8** | **+12** | 中 |
| 重 | 18 回合 | **-55%** | **-25** | **+15** | **+25** | 高 |

**一次性冲击与持续偏移分开**：`_event_delta` 单次最多 ±12；轻/中可直接用事件冲击，重级用 `-12 事件 + 剩余 -13 target 偏移`，**不重复每月扣**。target 偏移是“党禁期间的目标值修正”，不是每月再扣一次 satisfaction。

**边际递减**：越往上，正式 `permission_capture` 降幅越小；`grievance`/`cohesion` 增幅越大。

## 4. 回合生命周期

- `start`：皇帝以 `party_ban` 权柄下诏（阈值 90、代价 8）；一次性冲击走 `faction_settle._event_delta`。
- `turn_start`：结算到期/复核；不重复扣一次性 satisfaction。
- `maintenance`：任命限制；逐人罢黜走 `issue_personnel_order`/`dismiss_*`，不直接删 holder。
- `review`：`enforcement` 低于阈值 → `nominal`（名义党禁）；高于阈值 → `enforced`；连续高压 → `overreach`。
- `end`：`end_turn` 到期自动解除；+5 satisfaction 一次；保留 `ban_memory` 修正。

## 5. 执行强度（JEV 裁 B：固定档位）

> JEV Q4 裁 **B：按级别固定效果**，不用公式。皇威/台谏/吏治/渗透只用于叙事与反噬阈值，不改变固定档位。

| 级别 | formal `permission_capture` | grievance | cohesion | 反噬 |
|---|---|---|---|---|
| 轻 | **-15%** | +5 | +3 | 低 |
| 中 | **-35%** | +12 | +8 | 中 |
| 重 | **-55%** | +25 | +15 | 高 |

- formal capture 只降不清零；派系仍存在、POP 基础不变。
- 固定档位是“行政命令能达到的上限”，不是“派系真实力量”。
- 反噬阈值仍按 Q7 用显式事件：grievance/cohesion/台谏反对/皇威过线才触发。

## 6. 失败态

| 状态 | 触发 | 表现 |
|---|---|---|
| `nominal` | enforcement 低 | 禁令在，职位变动少；派系转入地下 |
| `enforced` | enforcement 中高 | 正式 capture 明显下降；grievance/cohesion 上升 |
| `backlash` | backlash_risk 过阈 | 台谏伏阁/士林清议/地方消极；皇威、民望代价 |
| `overreach` | 重级 + 高 enforcement | 官员隐匿、行政效率下降、非正式网络更强 |
| `lifted` | end_turn/特旨解除 | +5 satisfaction 一次；保留 ban_memory |

## 7. 数据契约（设计）

- **不新增顶层 `state.*`**：状态写在 `state.factions[faction]` 内：
  ```
  "ban": {level, status, start_turn, end_turn, enforcement,
          decree_id, event_ids, ban_memory}
  "grievance": float
  ```
- `faction_settle` 仍是 faction 字段唯一写入点；党禁只提供 `_event_delta` 与 target 修正。
- 任命限制：`issue_personnel_order`/四个 `appoint_*` 在目标派系 `ban.status` 活跃时拒绝；`imperial_direct` 不豁免（皇帝要先解禁）。
- 罢黜：逐人走 `issue_personnel_order`/`dismiss_*`；不得直接清 `central_orgs.holders`。
- 事件：`political_event_ledger`，`event_id` 幂等；一次性冲击只一次。

### 7.1 写入纪律（与 `faction_settle` 对齐）

- `ban` 是**政策控制块**：由党禁状态机在 start/end 写；`faction_settle` 只读，不写。
- `grievance`、satisfaction/cohesion 由 `faction_settle` 写；党禁只提交 `_event_delta` 与 target 修正。
- `influence` 不写；`permission_capture` 不写，只通过任免/准入改变。
- `defect_toward_satisfaction` 需增加**按派系的 resistance/rate 乘子**；否则“党禁越狠、越抱团”在代码层不成立（当前它只看 satisfaction）。
- `save_load` 的 `state.factions[fn].update(fdata)` 会保留 `ban/grievance`；但 `FACTION_NAME_SET` 之外的新派系名仍被丢弃 → 不新建动态派系。
- `party_ban` 仍 `implemented=False`；未接线前不得让 UI 显示“已生效”。

## 8. 跨系统耦合矩阵

| 系统 | 党禁 → 它 | 它 → 党禁 | 写入点/边界 |
|---|---|---|---|
| 天道 | 重大政治行为 → verdict/omen/史评；疑/逆 → 天谴/灾异种子 | 天道只给档位，不改 legal/fact；`basis_undefined` 不判 | `TianDaoFacade.faction_ban_verdict`（待建），不写 faction 数值 |
| 科举 | 考官资格、子弟应试、三舍名额、cohort lean/ban_context | 座主派系/新进士入派决定党禁能否“禁绝”；科举年与 end_turn 交叉 | `imperial_exam` 资格判断 + `blend_entrants` 零和；不删 POP |
| 台谏 | 党禁提高弹章/谏章频率、联名概率；疑/逆放大 | 台谏反对降低执行、提高反噬；台谏官个人派系不入“台谏派” | `state.memorials` / 弹章事实签；不直接定罪 |
| 财政 | 官员空缺/差遣中断 → 执行阻力、财政效率；不新增“效率字段” | 财政恶化 + 党禁 → 军饷/民变事件（既有失败态） | `permission_capture`/执行态；不另开财政账本 |
| 军事 | 军功集团被禁 → 边将空缺/士气；重级可能边防风险 | 边防压力 → 党禁“主战/主和”争议 | `issue_military_order`/军队链；不直接调兵 |
| 外交 | 主战/主和派被禁 → 对外态度波动 | 外患 → 党禁正当性/皇威 | 外交 API；不直接改外邦态度 |
| 民心/士林 | 子弟禁锢/学禁 → 士绅/士林 grievance、民望 | 民望低 + 党禁 → 民变事件 | `population_satisfaction`/grievance；不旁路直写 |
| 官员行为 | 被禁官员 `report/impeach/resign/conceal`；执行者阳奉阴违 | 行为证据 → 执行态/弹章；不改事实 | L1/L2/L3 单点；不写 faction 数值 |
| 奏折/弹章 | 党禁 → 弹章/联名/留中；`suppressed_by_faction` | 弹章 → 案件 → 人事 → 派系反应 | `state.memorials` / `state.impeachments`；准奏只开案 |
| 存档 | `factions[faction].ban/grievance`、`exam.cohorts.ban_context` | 读档恢复；同 event_id 不重复 | `save_load` 白名单；不新增顶层 state |
| 情报/UI | 不新增 UI/面板；皇帝通过奏折/召对/机构奏报获取党禁执行与民情 | 奏报可滞后、偏差、被派系过滤 | `state.memorials`/`monthly_gazette`/召对；只读派生；前端不直写、不重算 |

## 9. 设计级验收

1. 党禁后正式 `permission_capture` 下降，但 `state.factions` 仍存在、POP 基础不变。
2. 一次性 satisfaction 只扣一次；维护月不重复扣。
3. enforcement 低 → `nominal`，职位变动少；高 → `enforced`，但 grievance/cohesion 上升。
4. 重级高执行 → `backlash/overreach` 事件，皇威/民望/行政效率有代价。
5. 任命限制生效；罢黜逐人走人事令，不直接删 holder。
6. `end_turn` 解除 +5 一次；`ban_memory` 保留。
7. 存档往返 faction.ban/grievance 逐字保留。
8. 不新建动态派系、不改 `FACTION_NAME_SET`（除非 JEV 另裁）。
9. `influence` 仍由 POP 派生，党禁前后 `factions[*].influence` 不得被党禁直接改写。
10. `_event_delta` 不超过 ±12；重级必须走 target 偏移补足，不能伪造一次性 -30。
11. `faction_split` Σ=1 不变；党禁不得改 POP size。
12. `save_load` 往返后 `factions[faction].ban/grievance` 逐字保留。
13. 天道裁决只改 `omen_tier/historical_assessment/backlash`，不得改 `legal/procedure/fact_finding`。
14. 同 `verdict_id`/seed 重放一致；`basis_undefined=True` 不伪造“平”。
15. 被禁派系任考官时，党禁执行减弱、新科 cohort 仍随座主入派（禁而不绝）。
16. 中/重党禁下子弟应试/三舍名额受限；`exam.cohorts[-1].ban_context` 可读；`faction_split` Σ=1。
17. 三舍法路径受党禁资格判断影响；不新建动态派系。
18. `save_load` 往返后 `exam.cohorts[*].ban_context` 逐字保留。
19. 党禁 + 科举士林反噬可触发显式 `grievance/backlash` 事件，不靠随机。
20. 党禁前后 `factions[*].influence` 仍由 POP 派生；不直接改 POP size。

## 10. 综合取舍与实现前置

### 10.1 为什么选“正式排斥 + 非正式反噬”

| 方案 | 结果 | 结论 |
|---|---|---|
| 删除派系 | 一键消灭，历史失真，POP/份额/POP 基础全崩 | 否 |
| 只扣 satisfaction | 只是数值惩罚，职位/网络/执行都不变 | 否 |
| **正式 capture 降 + grievance/cohesion 升** | 能表达“禁得住官、禁不住人”，并产生反噬 | **JEV Q1=A，采用** |

### 10.2 实现前置（未授权，不得开工）

2. `faction_settle` 写 `grievance`（唯一写点）；
3. `defect_toward_satisfaction` 增加按派系的 resistance/rate 乘子；

9. `blend_entrants` 保持零和；党禁只改“哪批人可入”，不改 POP size。

### 10.3 历史依据（本项目现有文档）

- `游戏机制说明.md` §六：旧党 = 元祐旧臣与保守士绅；台谏不入集团；科举同年/座主门生是跨派系网络。
- `宋代官制与三冗设计.md` §15：崇宁三年罢科举行三舍法；取士/学校本身是党争工具。
- 设计含义：党禁能改“谁被除授”，改不了“谁有门生、同年、姻亲、地方声望”；所以必须保留非正式层与反噬。

## 11. 不做什么

- 不做“一键删除派系”。
- 不把党禁做成每月重复扣 satisfaction 的惩罚机器。
- 不让党禁直接清 holder / 绕过人事流程。
- 不用派系影响力决定禁令是否合法。
- 不在未授权前写生产代码。
- 不新增/改动 UI；党禁情报只通过大臣、机构、奏折、召对、邸报。
- 不把 `grievance/cohesion/permission_capture` 精确值暴露给玩家。
