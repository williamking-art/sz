# B-1 字段单点注册 · 需求与验收

> 权威设计见 [`design.md`](design.md)；实施状态见 [`tasks.md`](tasks.md)。
> 授权：用户 2026-10-12「B-1 有条件通过，按两阶段实施」。

## 1. 需求（R）

| ID | 需求 | 可验证判据 |
|---|---|---|
| R1 | `engine/state_applier` 的六套路径/规则集合由**单点声明**生成 | 六集合均来自 `engine/field_registry`，`state_applier` 内不再有 ≥3 条路径的列表字面量 |
| R2 | 每条声明必须明确 `kind` 与 `cons`，不允许默认值掩盖遗漏 | 缺 `cons` 的声明被 `validate_registry` 报错 |
| R3 | `cons` 必须显式 ∈ {MONEY, GRAIN, EXEMPT} | 同上；`EXEMPT` 也必须写 |
| R4 | `cons=EXEMPT` 且路径名命中钱粮语义词时必须给 `exempt_reason` | 缺理由 ⇒ 自检红 |
| R5 | 关键词**只触发解释要求**，不决定分类 | 自检代码中无语义词 → 守恒组的赋值路径；分类结果与迁移前逐条一致 |
| R6 | `validate_registry()` 校验**实际传入值** | 传非 `str` 路径 / 非枚举值 / 非 `bool` 位 ⇒ 红（用构造的坏规则验证） |
| R7 | MONEY/GRAIN/NON_NEG/RANGE_100/可写白名单之间关系经自检与回归验证 | `MONEY/GRAIN/RANGE_100 ⊆ VALID`、`RANGE_100 ⊆ NON_NEG` 成立；红线用例覆盖不成立时的报错 |
| R8 | 迁移前后**行为**一致（不是仅集合相等） | L1 多重集 + L1.5 顺序不变性 + L2 谓词 golden + L3 管道 golden 全绿（见 design §6） |
| R9 | 保留原有五个 matcher 的实现与语义 | B-1a/B-1b 后五个函数体与迁移前逐字一致（AST/文本证据），`granary` 宽松前缀与通配范围未变 |
| R10 | 新增字段缺少必要元数据时在**测试期**失败，不静默放行 | 负向用例 N1–N9 全红/全拒 |
| R11 | 现有消费方无需改动 | `from engine.state_applier import VALID_PATHS / MONEY_PATHS / NON_NEG_PREFIXES` 全部照常；5 个既有测试模块一行不改 |
| R12 | 期望值来自旧实现**实跑**记录 | L2/L3 golden 由迁移前探针实跑产出并留档，不得使用未验证预期 |

## 2. 边界

**B-1a（影子期）**：新增 `field_registry.py` + 自检 + golden + 差分测试；
**生产判定代码零改动**（`state_applier.py` 的 diff 必须为空）。
**B-1b（数据源切换）**：`state_applier.py` 六套字面量改为导入派生集合；
**保留原有五个 matcher，不收敛匹配实现**。

## 3. 非目标（冻结，本轮一律不做）

| ID | 冻结项 |
|---|---|
| N1 | 不新增游戏引擎 / 规则 DSL / 新架构层 |
| N2 | 不统一或收敛五个 matcher（未来单独设计、逐集合匹配契约与行为差分证据） |
| N3 | 不收紧 `granary` 的宽松前缀 |
| N4 | 不删除 `land.hidden_households` 孤儿规则 |
| N5 | 不改变 `era_state.` 的写入能力或月结覆盖关系 |
| N6 | 不调整 `art_mastery` 可写性 |
| N7 | 不修正 `defense_lines.*.fortification` 与 `garrison` 的规则不对称 |
| N8 | 不改变 `waste_reform.savings` 的守恒分类（只要求例外有理由） |
| N9 | 不删除 `NO_CONSERVATION_PATHS = None` |
| N10 | 不开展宽松前缀的全面显式化 |
| N11 | 不实施 B-2（守卫进放行门）、B-3（结算步序契约）、B-4（机制台账机器可读） |

## 4. 验收条件（A）

| ID | 条件 |
|---|---|
| A1 | 六集合 vs 冻结 golden 多重集相等；顺序分歧有报告与环路证据，**未伪称顺序恒等** |
| A2 | 顺序不变性证据通过（洗牌后谓词与代表性管道结果不变）；不通过则停止改走"按集合顺序元数据"分支 |
| A3 | L2：样本集 P 上五个谓词输出与旧实现实跑 golden 逐条一致 |
| A4 | L3：14 场景 `applied/rejected/errors/conservation_failed/CHANGE_LOG`/状态摘要逐字段一致 |
| A5 | 回滚场景**先有旧实现实跑记录**；记录含异常类型与消息、状态前后、逐字段 diff、`CHANGE_LOG` 前后 |
| A6 | 负向 N1–N9 按期望红/拒 |
| A7 | 全量回归：无新增失败/错误；跳过项变化有解释；记录**基准提交标识**与完整结果 |
| A8 | 关键生产调用方（4 处）定向回归通过 |
| A9 | 每阶段交付：文件级变更 + git diff、六集合旧值/新值对照、自检与负向结果、差分报告、回归终态、未解决问题与回退证据 |
| A10 | 任务板与文档状态与实际一致：B-1a/B-1b **分别**标注，不以"设计完成/影子通过/兼容导入成功"代替生产接线 |

## 5. 停止条件

任一成立即**停止并保留证据、重新裁定**：
1. B-1a 发现六集合无法由声明结构无损生成；
2. 顺序不变性证据不成立且不采用顺序元数据分支；
3. B-1b 出现任何行为差异；
4. 回滚场景旧实现不符预期（登记独立缺陷，不修）。
