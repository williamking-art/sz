## 0. 结论摘要

1. **守卫已在生产入口接线，但"零违规"从未被任何门要求**：`settle_local` 装了守卫却只把违规写进日志；
   唯一"一条命令全量验证"入口 `_dev_tools/verify-all.ps1` **既不设 `SONGZUO_POPS_GUARD`、也不读违规**。
2. **零违规断言确实存在，但走的是"直接装守卫"路径**（`test_route_pops_readonly_guard.py`），
   覆盖机制与场景，**不覆盖生产 env 开关**；生产接线用例 `test_prod_pops_guard.py` 的 docstring 写了
   "正常局零违规"，**但用例本身没有该断言**（只断言容器类型还原）。
3. **违规通道可用但很窄**：`_VIOLATIONS` 在 `uninstall_all_guards` 后**不清空**（`reset` 只发生在下次装配），
   故门用例可以在 `settle_local` 返回后读取本轮违规；归因能力（file/line/function）已存在
   （`set_pops_guard_trace` / `pops_guard_violation_details`），**但全库无调用方**。
4. **四类账本的拓扑各不相同**，不存在可套用的统一守卫外形：
   POP = 真账+镜像（写入检测）；粮 = **载体二选一**（双源检测）；商品 = 双形态+单点访问层（越层检测）；
   资源桶 = 单一总账（搬运守恒/双记检测）。
5. **B-2a（POP 进放行门）几乎不需要改生产逻辑**：门用例 + 1 处静默 `except` 补留痕 + 门脚本加开关。
   粮/商品/资源桶必须先各自取证，**不得**为了外形统一强制同一规则。

## 1. 现有守卫与放行门的真实关系（取证）

### 1.1 生产调用链（已接线）

`core/commands.py::settle_local`（`:755-803`）：

```
snap = _snapshot_state(state)                      # 装守卫**之前**取（异常回滚用）
_guard_on = env SONGZUO_POPS_GUARD 非 ("",0,false,no)   # :773 缺省关闭
if _guard_on:
    try:  reset_pops_guard(); install_all_guards(state)          # :780-781
    except Exception: _guard_on = False                          # :782-783  ⚠️ 无日志
try:      return run_monthly_settlement(state)                   # :785
except:   _restore_state(state, snap); log.error(...); raise     # :787-790
finally:  # :791-803
    if _guard_on:
        _viol = pops_guard_violations()
        if _viol: log.warning("路级 pops 只读守卫：结算期检出 %d 处直写…", ...)   # 仅日志
        uninstall_all_guards(state)                              # 还原 plain dict
```

- **装配点唯一**：`settle_local` 覆盖 `settle_turn` / `advance_and_settle` / async / backend client 全部生产面
  （§路线文档「主线A」与 `handover/worklog/20261010T160525Z-DSH.md` 一致）。
- **卸装成对**，且异常路径由 `_restore_state(snap)` 整体替换 `prefectures`（守卫子类随之失效）。
- **违规不出函数**：既不返回、也不落 `state`、也不落 `statistics`；只有一条 `WARNING` 日志。
  ⇒ 调用方（前端/后端/AI 管线）**无法知道**本轮是否有违规。

## 2. 运行时策略 vs 质量门策略（必须分离）

| 层 | 启用条件 | 违规后果 | 允许改什么 | 禁止 |
|---|---|---|---|---|
| **生产运行时** | `SONGZUO_POPS_GUARD=1`（缺省关闭） | **记录日志，不中断、不改数值** | 补留痕（装配失败必须 `warning(exc_info=True)`） | 不得改为抛异常/拒绝结算（用户已裁「POP 守卫暂不硬失败」） |
| **质量放行门** | 门用例内显式置该 env；门脚本显式声明 | **断言失败 ⇒ 套件红 ⇒ 非零退出** | 只改测试/门脚本 | 不得把门的失败**实现成**生产硬失败；不得改账本口径 |

要点：两层的**唯一区别是失败后果**，不是判定逻辑。同一个 `pops_guard_violations()` 既是生产日志来源，
也是门断言来源——避免"两套判定"再次分叉。

## 3. 账本写入链盘点（粮 / 商品 / 资源桶）

| 账本 | 真账 | 派生/镜像 | 桥 | 现有自检设施 | 多写者风险 | 建议的守卫语义 |
|---|---|---|---|---|---|---|
| **POP** | `seats[治所]["pops"][类]` | 路级 `pops`（`sync_route_pops` 刷） | `pop_bridge`（`pop_get/set/add`、`pop_obj_*`） | **只读守卫**＋`assert_pops_consistent`＋`survey_pops` | 33 处直访历史、桥接漏传 `state` | **写入检测**（已有）→ 入门 |
| **粮** | `goods[米/麦]`（迁移后）／legacy `.grain` | **无镜像**；`.grain` 是并存的旧载体 | `grain_bridge`（`grain_get/set/add`，`state` **可选**） | `survey_grain`（对账读数） | **载体二选一可能被破**（同 POP 两边都写）；未下沉路回落 legacy | **载体单一性检测**（双源/双写） |
| **商品** | 扁平 `goods[dim]` ＋ `goods[治所][dim]` 桶（双**形态**，非镜像） | — | `material_holding` 单点访问层（`goods_amount/set/add`、`commodity_dims`） | `holding_report` / `seat_holding_report`（搬运守恒 `Σ商人 == stock`） | 裸遍历 `goods` 会把州府桶当商品维参与算术；裸写绕过访问层 | **越层检测**（访问层绕过） |
| **资源桶** | `resources[dim] = {"stock","cap"}`（全国总账） | 无（`by_pref` 明细**已整体退役**，避免平行账本） | **无桥**（设计上不需要） | `holding_report.ok`（单向：`Σ商人 ≤ stock`） | 与商人 POP 持货**双记**；`cap` 超限写入 | **守恒/双记检测**（现有 `gap` 只有单向 `held > stock`） |

### 3.1 粮：桥与回落（实测）

- 桥函数 `state` 参数**可选**，回落写法是惯例化的：
  `if _grain_add(pop, x, state) is None: <legacy 直写>`。
- `grain_add/grain_set` 的调用点（`_grain_*` 共 **57 处**匹配）在结算侧**全部传了 `state`**
  （`settlement_granary` / `settlement_finance` / `settlement_econ` / `settlement_common` / `settlement_decree`
  / `domains/production/settlement_agri` / `building_jobs:297` / `free_effect:153`）。
  ⇒ 与 `AGENTS.md` §3-1「三处漏网」的历史描述**已不一致**（可能已修，或指其它形态）；**建议实施前重跑该盘点**。
- 遗留直写 `["grain"] [-+]?=` 共 **22 处**（granary 9 / finance 2 / econ 4 / decree 2 / common 4 / agri 1），
  抽样核实**均为回落分支**（如 `settlement_granary.py:178→179`），即在已下沉路上是**死代码**、在未下沉路是**活跃路径**。
- 🔴 **精度提醒（避免误报）**：`settlement_econ.py:351` 与 `settlement_granary.py:745` 写的是
  **路级 `p["grain"]`**（`prefectures.*.grain`，田亩产出基数），**不是** POP 粮，**不属** POP 守卫目标。
- 粮**没有**守卫；其不变式是"同一 POP 载体二选一"（`has_grain_bucket` 判定），
  `survey_grain` 只报 Σ，**Σ 相等仍可能是双写等量** ⇒ 门必须断言**逐 POP 载体单一**，不能只比 Σ。

### 3.2 商品与资源桶（实测）

- 访问层：`material_holding.goods_amount/goods_set/goods_add/commodity_dims`；
  禁止裸遍历（`commodity_dims` 是唯一安全判据）。
- `holding_report(state)`（`:884-907`）：逐维 `merchant_total` vs `stock`，`gap = stock - held`；
  **注意它只在 `held > stock` 时置 `ok=False`**（单向）——"总账被多扣/少记"方向**不会**被它发现。
- 该自检目前**只在 `test_material_holding.py` 中被断言**，生产与门脚本均未使用。
- `building_jobs.produce_job_track(..., resources=None, goods_pool=None)`（`:301-333`）的 `resources`
  是**传入的本地累加字典**（`resources[dim] = int(...) + q`，形如 `{dim: qty}`），
  **不是** `state.resources`（后者是 `{dim: {"stock","cap"}}`）。⚠️ 实施前须核实调用方传参，勿据形状臆断。
