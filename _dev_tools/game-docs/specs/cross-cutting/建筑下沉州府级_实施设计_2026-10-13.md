## 3.5 M38b-1 交付：**form-aware 桥**（2026-10-13，已落地）

M38a 的桥把条目归一成 int ⇒ **会丢 `built_month`**（读者见 §2 更正）。本步把它做成**保形态**：

| 函数 | 形态语义 |
|---|---|
| `norm_level(entry)` | 标量 `2`⇒2；`{"lv":2}`⇒2；`{"closed":true}`⇒**0**（`building_jobs` 既有语义）；无 `lv`/`None`/`bool`⇒**`None`**（缺失≠0） |
| `sink_route_buildings` | 路级条目**原样搬运**到首府治所（含 `built_month`），其余治所空 `{}`；然后刷新镜像 |
| `aggregate_seat_buildings` | Σ 等级；**保形态**：标量进⇒标量出；字典进⇒`{"lv":Σ, "built_month":各贡献者最老者}`（**推演**口径，逐治所真账各留原值） |
| `building_add(..., built_month=None)` | 增量；既有字典 ⇒ 只更新 `lv`（保留 `built_month`）；传了 `built_month` ⇒ 写字典形态；否则标量 |
| `building_set(..., entry)` | 按**原始条目**精确写（营造落点用），无 `lv` 的字典**拒绝** |

**定向回归**：`test_building_sink.py` **22 passed**（含形态四例：原样搬运、聚合保形态+最老月、
增量保留 `built_month`、`closed`⇒0）。

## 4. 🔴 为什么本批**刻意不开闸**（M37 实测教训）

M37（地方府库）实测过两个失败模式：

| 做法 | 结果 |
|---|---|
| 只下沉、不桥任何写点 | 结算第 1 轮起 **20/20 路失配**（镜像漂移、真账冻结） |
| 只桥账户层、留 5 处直写 | **2× 冲账** |
| 七处全桥 | 0 失配 ✅ |

建筑同理：**开闸（new_game/读档调用 sink）必须与「全部写点桥接 + 阈值类消费者处理」同批**。
本批刻意只交付**可验证的桥接层**（未下沉时所有函数返回 `None` ⇒ **零行为变化**），
接线留给 M38b 一并完成——避免出现"等级被 Σ 放大"的静默数值污染。

## 5. 验收断言（M38b 开工时逐条验）

1. **Σ 恒等**：迁移后路级 == 原值（逐建筑名，已在用例锁定）；
2. 新局/读档：`is_sunk` 20/20 路；`survey_buildings` 字段失配 **0**；
3. **消费者数值不劣化**：财政/科技/岗位读数与迁移前**同种子对照**（阈值类读者须改逐治所后复测）；
4. 结算回放 ≥3 轮：`survey_buildings` 0 失配（对齐 M37 的验证方式）；
5. 全量串行回归 `EXIT=0`。
