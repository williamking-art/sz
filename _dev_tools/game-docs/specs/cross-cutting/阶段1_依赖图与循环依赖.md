## 🔴 更正：阶段 0 报告「循环依赖 = 0」**是错的**


**根因**：阶段 0 的扫描脚本把「模块级 import」当成**有向无环图**处理，
但**函数内延迟导入**（`from core.X import Y` 写在函数体内）同样形成真实依赖边，
而阶段 0 用了**不同的匹配逻辑**（只认 `ast.ImportFrom.module` 以 `core.` 开头，
漏了 `import core.X` 形式与部分条件分支），导致边集不完整 ⇒ 假 0。

### 附带发现：反向边现场的异常吞噬（已修 1 处）

这些边既已延迟到函数内，就近常配 `try/except`，于是冒出一类与依赖方向无关的问题：
**失败不留痕**。按 AST 精确统计（`_scratch/silent_except_audit.py`，判据=处理体语句仅 `Pass`）：

| 文件 | except 处理体 | 纯静默 `pass` | 已记日志 |
|---|---:|---:|---:|
| `game_state.py` | 10 | **6** | 0 |
| `save_load.py` | 31 | 11 | 15 |

- 本轮修掉登记边上的那处：`game_state.py:1068` 隐户入 POP（POP 挂载律条 1/4）
  原为 `except Exception: pass` ⇒ 改为 `logging.warning(..., exc_info=True)`，
  **不改控制流**（仍不阻断开局），口径对齐 `save_load` 同一迁移点的既有写法。
  实测证据：把 `ensure_hidden_in_pops` 换成抛错桩后，开局照常成功而隐户口归零
  （`_scratch/hidden_swallow_proof.py`，VERDICT=SILENT_BUT_TEST_COVERED）；
  测试侧 `test_new_game_materializes_hidden_into_pops` 的「在籍+隐户=1.25 亿」守恒断言
  会红，**缺的只是运行时信号**。新增用例
  `test_hidden_init_failure_is_logged_not_silent` 锁住留痕本身（去掉修复它会红，已验证）。
- ⚠️ 一处自我更正：先前把 `save_load.py:1049` 也报成"静默吞掉"是**误判**——
  grep 窗口把注释里的 "原静默 `pass`" 当成了语句；AST 复核该处早已 `warning(..., exc_info=True)`。
