## 0. 一句话总纲

皇帝**可以**亲裁/亲行/破例；`check_authority` 约束的是**承办者**，不是皇帝。
所有政治后果必须能追溯到一份圣旨、一个案件或一个明确事件。

## 1. 三层模型

| 层 | 字段 | 判定 | 失败表现 |
|---|---|---|---|
| 皇帝主权 | `sovereign_right: bool` | 正常在位恒真；退位/被废/摄政代行/非法即位才假 | `issuable=False`，直接拒绝 |
| 承办适法性 | `executor_authority: bool` | `check_authority(executor, matter)` | `executable=False`，`exec_state=not_entered` |
| 实际执行 | `exec_state` | 关口三评估 | `resisted/partially_executed/blocked`，**不是「皇帝无权」** |

```
issuable  = sovereign_right ∧ edict_form_valid
legal     = issuable ∧ executor_authority      # 关口一，不包含 procedure_state
procedure = 关口二（独立状态）
exec      = 关口三（仅 procedure ∈ {passed, bypassed} 才评估）
```

**顺序固定**：关口一 → 关口二 → 关口三。`legal` 不依赖 `procedure_state`。

## 2. 皇权 vs 臣权

| 层级 | 皇帝做什么 | 例子 |
|---|---|---|
| 委托 | 决定，交有司办 | 常诏 |
| 亲裁 | 亲自拍板，仍走部分程序 | 超迁、特旨除授、亲录囚 |
| 亲行 | 亲自到场/亲自指挥 | 御驾亲征、亲祭、亲审 |
| 破例 | 绕中书/门下，直付 | 中旨、御笔 |
| 压制 | 罢黜/党禁/清洗 | 贬台谏、党禁 |

**皇帝可亲自行使**：御驾亲征、超迁、特旨除授、亲录囚/亲审、御笔/中旨、亲祭/封禅、内帑。

**限制**（不是「无权」）：
1. 个人成本（健康/精力/`DIRECT_DECREE_MAX`）；
2. 政治代价（皇威/民望/史评/台谏积怨）；
3. 臣权抵制（封驳/副署/铨选/财政审核/台谏/执行）；
4. 行政执行仍需有人做（亲征需枢密院调兵、超迁需吏部发告身）。

**臣权六支点**：封驳（门下/给事中）、副署（宰相/中书）、铨选（吏部）、财政审核（户部/三司）、台谏（御史台/谏院）、执行（有司/地方/军队）。

**UI 文案**：不写「皇帝无权」，只写「亲裁成本 / 臣权抵制 / 执行受阻」。

## 4. 机构派系分布（M1a 唯一实现）

> **注意**：本节是**任职分布**（谁在哪个机构任职），不是**事权分布**。
> 事权分布用 `permission_model.permission_capture(state, matter)`：
> **权限挂在职位上**，在任某职位 = 拥有该职位事权；免职/空缺 = 失去。

### 4.1 数据源（只读）

`state.central_orgs[org]["posts"]`（`[{"title": ...}]`）+ `["holders"]`（`title -> name`，`""`=空缺）+ `["abolished"]` + `MINISTERS[name]["faction"]`。

`decree_confidential.posts_of` **只作交叉核验**，不参与正式计算。

### 4.2 五类份额守恒

```
Σfaction_share
+ vacant_share                 # 真实空缺
+ unaffiliated_share           # 有人任职但无已登记派系
+ concurrent_discount_share    # 兼任次职 50% 未分配
+ acting_discount_share        # 代理 50% 未分配（M1a 恒 0.0）
= 1.0
```

分母 `W_org = Σ established w_i`，**固定不随人事变动**。

### 4.3 规则

| 情形 | 份额归属 |
|---|---|
| 主职（`posts` 顺序首个） | 全额计入其派系；未登记派系则计入 `unaffiliated_share` |
| 次职（同人同机构其他岗位） | `0.5` 计入其派系/未归属；`0.5` 计入 `concurrent_discount_share` |
| ≥3 兼职 | 除主职外每个都按 `0.5/0.5` 拆 |
| 代理（`acting=True`，当前未建模） | `0.5` 派系/未归属；`0.5` 计入 `acting_discount_share` |
| 实际空缺 | 全额计入 `vacant_share` |
| 全部岗位空缺 | `defined=True`、`vacant_share=1.0`、其余 0 |
| 无岗位/空列表 | `defined=False`、`vacant_share=None` |
| 岗位标题重复 | `defined=False` + `error="duplicate_post_title"` |
| 机构废置 | 不进入 `orgs`，列入 `excluded_orgs` |

### 4.4 输出字段

```python
{
  "as_of_turn": int, "weight_mode": "headcount",
  "acting_supported": False, "excluded_orgs": [...],
  "orgs": {
    org: {
      "defined": bool, "posts_total": int, "filled_posts": int,
      "vacant_share": float, "unaffiliated_share": float,
      "concurrent_discount_share": float, "acting_discount_share": float,
      "faction_share": {faction: float},
      "holders_detail": [{
        "post": str, "holder": str, "faction": str|None,
        "post_weight": float, "faction_counted_weight": float,
        "unaffiliated_weight": float, "concurrent_discount_weight": float,
        "acting_discount_weight": float,
        "is_primary": bool, "concurrent": bool, "acting": bool
      }],
      "concurrent_holders": [str], "notes": [...]
    }
  }
}
```

- 权重字段全为 **float**（主职 1.0、次职 0.5、空缺 0.0）。
- `concurrent=True`：同一人在该机构多岗时，其**全部岗位条目**都标 True；`is_primary` 区分主职。
- 汇总必须等于明细逐项加总。

## 5. 多事权诏令

- 字段：`primary_matter`（1 个）+ `co_matters`（0..n）；**禁止**旧 `matter: [...]`。
- 关口一：所有 matter 逐一 `check_authority`，**逻辑与**；任一不合法即拒绝。
- 关口二：**整道诏令共享一个 `procedure_state`**；优先级 `bypassed > returned > pending_review > passed > not_required`。
- 关口三：只聚合**已进入执行**的事权；部分完成 ⇒ `partially_executed`；任一已执行事权 `blocked` ⇒ 整诏 `blocked`。
- 幂等：逐 `(decree_id, matter)`；已完成事权不得重复执行；全部完成才算整诏完成。

## 6. `resisted` 三期

| 期 | 规则 |
|---|---|
| 1 | 首次失败 ⇒ `status="resisted"`, `resist_period=1`, `due_turn=+1` |
| 2 | 到期重评一次；仍失败 ⇒ `resist_period=2`, `due_turn=+1` |
| 3 | 到期重评一次；仍失败 ⇒ 终态 `failed`，`detail="resisted_expired"`，生成**一次**事件种子 |
| 通过 | 任一期重评通过 ⇒ 执行并落账 `executed` |
| 代价 | 等待期不重复扣；初始 `_event_delta` 只在颁诏时施加一次 |
| 台账 | 只在终态写；`resisted` 不是终态 |
| 读档 | 恢复 `status/resist_period/due_turn`；`decree_id` 在队列中唯一 |

## 7. 拒收三分

```
refusal_fact = {who, when, decree_id, reason_code, reason_text}
reason_code ∈ {wrong_recipient, impossible, authority_conflict, willful_refusal, unknown}
```

| 原因 | exec_state |
|---|---|
| `willful_refusal` | `blocked` |
| `wrong_recipient` / `impossible` | `not_entered` / `failed` |
| `authority_conflict` | `not_entered` |
| `unknown` | 保持未定，补查 |

- 拒收只生成 `case_seed`（调查线索），**不自动认定抗旨、不定罪**。
- 只有 `willful_refusal` 才进入抗旨调查线索；其余先走纠错/改派。

## 8. 天道唯一裁决契约

本游真实接口：`gate` 二元、`choose` 多档、`score` 分档；**三者不各自对外出裁决**。

唯一入口（M2 待建，不假设今日已存在）：

```python
TianDaoFacade.faction_action_verdict(state, action, context) -> {
  "verdict_id": "tdv_<hash>", "verdict": "顺|平|疑|逆",
  "omen_tier": "无|轻|中|重", "historical_assessment": "褒|中|贬",
  "reason_codes": [...], "source_id": "<decree_id|event_id>",
  "seed": int, "inputs_digest": "<sha1>",
  "defined": bool, "basis_undefined": bool,
}
```

- `basis_undefined=True` ⇒ `verdict=None`/`"未定"`，`defined=False`；**不得伪造「平」**。
- `verdict_id = hash(source_id, turn, inputs_digest, policy_version)`。
- `event_id = verdict_id + ":omen"|":historical"`；`political_event_ledger[event_id]` 幂等。
- 因果方向：`政治行为及背景 → 天道裁决 → 官员行为选择 → 制度裁定 → 既有系统结算`。

## 9. 官员行为 L1/L2/L3

| 层 | 输出 | 是否写状态 |
|---|---|---|
| L1 行为意向 | `{intent, confidence, reason_codes, context_type, candidate_set, behavior_id}` | ❌ |
| L2 制度裁定 | `procedure_return` / `execution_refuse` / `report_only` / `delay` / `comply` / `impeach_seed` / `resign_request` / `faction_move` / `conceal` | ❌ |
| L3 状态落地 | 经诏令链/确认流程/人事/案件/派系结算单点 | ✅ |

- L1 不写状态；L2 只裁定；L3 只走单点。
- `refuse` 必须由 L2 区分：`procedure_return`（门下封还 ⇒ `returned`, `not_entered`）/ `execution_refuse`（拒收 ⇒ `blocked`/`not_entered`）/ `report_only`（只生成案件/泄密种子）。
- 先按**法定职权**过滤候选集，再交 `TianDaoEngine.choose`；行为概率不得创造职权。
- `context_type` 限定候选集（接诏/监察/人事/派系/密令/财政/军事）；未列情境默认只用 `comply/delay/report`。
- 关系缺失 ⇒ `relations_undefined=True`，关系项不参与权重，记 `reason_codes`。
- `behavior_id = hash(official_id, source_id, context_type, turn)`；L3 按此幂等。

## 10. 奏折 / 弹章

- 接现有：`state.memorials`、`accept_memorial`、`dismiss_memorial`、`ai_pending_actions`、`TianDaoFacade.scan_memorial_seeds`。
- 类型：`impeachment/remonstrance/resignation/recommendation/joint/secret/omen`。
- 事实签：`memorial_id/kind/accuser/target/target_faction/matter_domain/trigger_fact/evidence_refs/severity/tian_dao_verdict/created_turn`。
- 朱批：准奏→弹章开 `investigating` 案件（**不直接罢官**）；留中→不开案但记怠政/民望代价；彻查→补证据；罢黜仅案件裁定后可用；申饬/驳斥→`_event_delta`。
- **弹章≠定罪；准奏≠罢黜；留中≠无罪**。
- `memorial_id` 幂等；`accept_memorial`/`dismiss_memorial` 按 id 而非 index。

## 11. 张力与失败态

```
sat_gap_norm         = (max_sat - min_sat) / 100
policy_conflict_norm = Σ_{立场相反派系对} w_i*w_j / Σ_{所有派系对} w_i*w_j
base_target          = 100 * (0.6*sat_gap_norm + 0.4*policy_conflict_norm)
base_t               = clamp(base_{t-1} + clamp(base_target - base_{t-1}, -5, +5), 0, 100)

redline_delta_t      = min(20, 5 * 本月红线命中数)
impulse_t            = clamp(0.9*impulse_{t-1} - 2 + redline_delta_t, 0, 40)
tension_t            = clamp(base_t + impulse_t, 0, 100)
```

- 只有 `impulse` 衰减；`base` 不向 0 衰减。
- 有效派系 <2 ⇒ `base/impulse/tension` 全部保持上一月，记 `tension_undefined=True`。
- 阈值只给调查/事件资格，不生成证据、不定罪。

## 17. 回合制时序（唯一时钟 = `state.turn`）

> **1 回合 = 1 月**。代码/存档只用 `turn` 整数；不用墙钟、实时计时、帧计时。
> 所有延迟用 `due_turn` / `end_turn` / `created_turn`；所有时点显式标注
> `same_turn | next_turn | turn_start | turn_end`。同一 `turn` 重入必须幂等（`turn` 进入所有 id）。

### 17.1 回合内固定顺序

| 阶段 | 做什么 | 归属 |
|---|---|---|
| `turn_start` | 到期事项：`resisted` 重评、弹劾审理、党禁到期、事件触发 | 结算前 |
| `memorials` | 生成当回合奏折/弹章（天道 scan + 官员 `report/impeach` + 张力） | 结算前 |
| `player_commands` | 玩家下诏/朱批/召见/任免（受 `decree_bandwidth` / `DIRECT_DECREE_MAX` 限制） | 玩家 |
| `court` | 廷议/会签/封驳；官员 L1/L2（接诏/审议） | 程序 |
| `execution` | 逐事权执行评估（ready/resisted/partially_executed/blocked） | 执行 |
| `tian_dao` | 对当回合重大行为裁决（顺/平/疑/逆 + 天象/史评） | 天道 |
| `settlement` | 经济/财政/军事/派系 metrics/官员 L3 | 月度管线 |
| `events` | 事件/灾异/党争张力更新 | 事件 |
| `turn_end` | 史册/邸报、清理、进入下一回合 | 结算后 |

### 17.2 各机制时点

| 机制 | 产生 | 裁决 | 落地 | 跨回合 |
|---|---|---|---|---|
| 圣旨 | 玩家阶段 | 关口一/二立即；关口三结算 | 结算 `decrees` 步 | `resisted` 按 `due_turn` |
| 天道 | 玩家阶段（随诏/事件） | 同回合 | 结算 `faction_strife` | 不重掷；`verdict_id` 含 turn |
| 官员行为 | 接诏/审议时 L1 | 结算 L2 | 结算 L3 | 每官每诏每回合最多一次 |
| 弹章 | `memorials` 阶段 | 玩家朱批同回合 | 次回合 `faction_strife` 审理 | `due_turn = T+1` |
| 党禁 | 玩家阶段 | 同回合 | 结算 `faction_strife` | `end_turn = T+6/12` |
| 奏折 | `memorials` 阶段 | 玩家朱批 | 同回合或次回合 | 未批结转，`turn_end` 计怠政 |
| 张力 | — | `faction_strife` 每回合一次 | 同回合 | 连续 `N` 回合判失败态 |

### 17.3 禁止

- 不用 `time.time()` / `datetime.now()` / `random` 做政治计时或掷点；只用 `turn` + `TianDaoEngine.dice(seed)`。
- 不在回合中途插入「实时」事件；所有事件在固定阶段。
- 不把「3 期」写成「3 天/3 小时」；统一「3 回合」。
- 不用「毫秒/秒/分钟」做延迟；统一 `due_turn` 整数。

## 18. 皇威与人事令（2026-10-18 设定）

- **皇威 > 80**：可**当场任免**官职（即时落地）。
- **皇威 ≤ 80**：必须**走流程**；人事令入队，`due_turn = T+1`，下一回合 `_settle_officialdom` 中重校验并落地。
- 皇威只决定**时点**，**不创造权限**：承办人仍须因在任职位持有「官吏铨选」；高皇威也不能让户部去办吏部的事。
- 入口：`core/personnel_order.py`
  - `can_appoint_immediately(state)`：`prestige > 80`
  - `issue_personnel_order(state, action=..., executor=..., ...)`
  - `settle_personnel_orders(state)`（由 `_settle_officialdom` 调用）
- 幂等：`order_id` + `statistics["personnel_order_ledger"]`；已落地/失败的令不重复执行。
- 存档：待办与台账都在 `state.statistics`（白名单内，逐字往返）。
