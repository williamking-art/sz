# 军令机制现状与皇威差异（2026-10-19）

> 对应参考图 8 个军令按钮；本文记录**现状/接线**，不改 UI。

## 1. 现有链路

```
issue_military_order(unit_id, button, ...)
  → enqueue_ai_action(kind="military_dispatch")   # 留审计
  → approve_ai_action
  → _apply_military_dispatch                      # 唯一落地通道
```

- 对象是**编制单位**（`ArmyUnit`），不是兵种/军籍整批；
- `_apply_military_dispatch` 负责校验、钱粮、POP/兵力守恒；
- `issue_military_order` 本身不直接写军队状态。

## 2. 八键映射

| 按钮 | 内部动作 `act` | 说明 |
|---|---|---|
| 调度军令 / 地图调度 | `调赴` | 改变驻地；需 `调兵` 事权 |
| 扩编 | `增募` | 增募兵额，扣钱粮/POP |
| 整编 | `整编` | 训练/编制整理 |
| 拆分 | `拆分` | 拆出编制单位 |
| 合并 | `合并` | 合并两支编制单位 |
| 换帅 | `换帅` | 改 `commander`（展示层） |
| 改名 | `改名` | 番号改名 |
| 裁撤 | `裁撤` | 裁撤编制，人员回流 |

`调度军令` 与 `地图调度` 是同一动作的两种文案，二者都映射 `调赴`。

## 3. 皇威差异（2026-10-19 接线）

| 皇威 | 行为 |
|---|---|
| **>85** | 除**调赴/调度军令**（天然耗时）外，其余军令**即时直行**：跳过执行侧 `调兵` 事权，扣 5 皇威；调赴仍入枢密院，按 `transport.route_path` 交通耗时到期落地 |
| **≤85** | **全部军令进月结算队列**：必须由掌 `调兵` 事权主体执行（默认枢密院）；传户部等越权主体会被拒绝；`due_turn=T+1`（调赴按交通耗时） |

- 直行仍校验目标合法性/物理约束（编制单位存在、目的地合法、钱粮够）；
- 直行不是“免费”：`charge_direct_cost("military_dispatch")`，扣 5 皇威；
- 高皇威的**非调赴**军令即时；**调赴**入 `ai_pending_actions`，`due_turn` 由 `military_order_delay_info` 消费 `transport.route_path` 决定；
- 低皇威**所有军令**入 `ai_pending_actions`，`due_turn` 默认 T+1（调赴按交通耗时），由 `core/military_order.settle_military_orders` 到期批红；
- payload 记 `imperial_direct`/`executor`，可审计。

## 4. 边界

- **不改 UI**；按钮文案属于现有界面；
- 军令不直接改 `army_units`，只走 `_apply_military_dispatch`；
- 军报/急递走 `military_report.py`，与军令分离；
- 不新增顶层 `state.*`。

## 5. 验收

1. 高皇威 + 越权 executor（户部）→ 军令成功、皇威 -5；
2. 低皇威 + 越权 executor → 明确拒绝，不落地；
3. 低皇威 + 枢密院 → 成功；
4. 八键都有映射；`调度军令/地图调度` 同义；
5. 直行失败（目标非法/钱粮不足）不扣皇威；
6. 军令不改 UI、不直写军队。

## 6. 未接
