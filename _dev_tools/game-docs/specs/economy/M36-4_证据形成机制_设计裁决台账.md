# M36-4《证据形成机制》设计裁决台账

> 2026-10-11 建立。**纯设计、零代码**（用户裁定：M36-4 先裁 D9／D10／D11，不得直接编码）。
> 目标一句话：**确定"监察发现如何成为证据"，而不是"如何自动成为案件"。**
>
> ⚠️ **称谓与术语（2026-10-11 用户裁定）**：本游背景为**宋**，宋制**无**「巡按」（明制巡按御史）。
> 内容层一律用**察访**（出使）／**差遣**（出使形式）／**奏报**（回报）——监察机构＝御史台·监司。
> 技术层保持 `inspection_*` 不改名（朝代映射 `INSPECTION_IDENTITY`：宋／明／清）。
> ⚠️ **本游引擎内不存在中央政务 AI**：决策方＝**玩家／外部 AI**；引擎只提供事实、合法性校验与单点执行。


---

## 1 · 定位与冻结

M36-4 处在**监察**与**司法**的接缝上。此前 M36-1～3 已把监察做成**只提供信息**的行动者：

```
监察（M36-1 编制/在途）→ 生命周期（M36-2 任务/奏报容器）→ 政治后果观察量（M36-3 反馈）
```

M36-4 要回答的是：**奏报之后，信息能不能、以及怎样才能进入"证据"这一层**。

**冻结边界（不得因 M36-4 松动）**

| 编号 | 冻结内容 |
|---|---|
| F1 | 监察**不产案**：`state.audit_cases` 的**唯一生产者**是 `audit_case.resolve_audit`（至今唯一） |
| F2 | 监察**不产证据项**：`evidence` 字段仍**只**由 `resolve_audit` 在"查得实情"档写入，内含 `financial_evidence(include_real=True)` |
| F3 | 监察**不写财政**：money／tax／grain／POP／occupation／欠给三层／三分财政一律不写（M36-1～3 已由源码测试钉住） |
| F4 | 监察**不改司法**：不自动处罚、不定罪、不抄没、不降官（`confiscate_by_case` 仍只由既有执行路径调用） |
| F5 | **口径单点**：真账与差额一律经 `financial_evidence`，任何新代码**不得**自算第二套 |

## 2 · 现状事实（接口与调用图，皆为已存在设施）

### 2.1 发现链四级（`audit_case.discovery_readout`，只读）

```
一级 异常   ← 账面耗损读数（tax_loss_readout）＋ 民心
二级 怀疑   ← state.discovery_suspicions（**唯一写入点** record_suspicion；6 回合窗口、容量 12）
三级 证据   ← 案卷 status == "证据在握"
四级 真相   ← 案卷 judgement 非空
```

### 2.2 关键函数（签名照录）

| 函数 | 角色 | 写状态？ |
|---|---|---|
| `audit_case.audit_fidelity(state, route, executor=None, secret=False)` | 保真度三档判定；输入＝`corruption × clerks_detail[路].grip × spy_network × secret` | **否**（纯读） |
| `audit_case.resolve_audit(state, route, executor=None, secret=False, log=None)` | **成案单点**：写 `state.audit_cases[cid]`（`outcome`／`evidence`／`status`）；"查得实情"档写入 `financial_evidence(include_real=True)`；"反噬"档动皇威；另写 P3-4 反向观察量 | **是**（案卷＋吏治量＋统计） |
| `audit_case.financial_evidence(state, route, include_real=False)` | **证据读数单点**（只读快照）：`include_real=False` 只给 `rumor_source`；`True` 才给真账三项 | **否** |
| `audit_case.record_suspicion(state, text, *, source, minister=None, route=None, turn=None)` | **怀疑唯一写入点**（发现链二级）：关键词过滤＋去重＋容量上限 | **是**（`discovery_suspicions`） |
| `audit_case.case_is_evidenced(state, case_id)` | Q11 抄没前置判据 | 否 |
| `audit_case.confiscate_by_case(state, case_id=None, route=None, …)` | 抄没**执行**（既有下游） | 是 |
| `game_state_econ.fiscal_gap_report(viewer, oversight=None, secret=False)` | **权限范本**：`player/official/court` 只账面侧；`inspector` 需 `secret` 或 `oversight ≥ FIN_ANOMALY_OVERSIGHT_LINE`；`ai/system` 全知 | 否 |

### 2.3 现有**唯一**生产触发路径

```
AI 产出诏令（effects["audit_route"] = {route, executor, secret}）
        ↓  settlement_decree._apply_decree_effect
   audit_case.resolve_audit   ← 单点执行
        ↓
   financial_evidence(include_real=True)   ← 口径单点
```

> 结论：**"AI 决定 → 系统单点执行"在本仓已是既成事实**，M36-4 只需说清"奏报不新增触发通道"。

### 2.4 M36 侧现状（已落地，M36-4 不改）

- `inspection_tasks`（`created → active → completed ／ expired`）；`file_inspection_report(task_id, summary, case_id)`：
  `case_id` **必须已存在**于 `state.audit_cases`（**引用校验**，绝不建案）。
- `inspection_feedback_readout()`：政治后果观察量（`interpretation="record-only"`）。

## 4 · D9：察访发现是什么？

| 方案 | 内容 | 与既有设施的关系 | 风险 |
|---|---|---|---|
| **A** | 察访只提交自由文本 `observation`（＋可选 `attached_case_id`，须已存在） | 相当于现状 M36-2 的 `summary`＋`case_id` | 信息不进发现链，AI 只能用正文；下游无法计数、无法复核 |
| **B（推荐）** | 察访可提**涉嫌事项**（结构化），**不形成案件**；进入**待审查**＝既有发现链**二级「怀疑」** | **直接复用** `record_suspicion`（唯一写入点，已有呈请/召对两处接线），新增 `source="察访"` | 与"怀疑≠证据"分层一致；不改单点 |
| C | 察访直接形成"调查案卷" | 违反 F1／F2（案卷与证据项各有单点） | **不建议**：司法链被监察旁路 |

**推荐 B**，理由：
1. 与既有四级阶梯同构——察访产出的是**二级怀疑**，不是三级证据；
2. 保持 F1/F2：`证据在握` 仍只能由 `resolve_audit` 的"查得实情"档产生；
3. 最小改动面：一个既有函数的新 `source` 值＋（可选）一处调用接线，无新写入点。

**若裁 B，落地形态（二选一，推荐 B-2）**

- **B-1（加参数）**：`file_inspection_report(..., allegation: Optional[dict] = None)` → 内部调用
  `record_suspicion(state, text, source="察访", route=task["route"])`，返回 `allegation_written: bool`。
- **B-2（零接口改动）**：不动 `file_inspection_report`；决策方在需要时**自己调用**既有
  `record_suspicion(..., source="察访")`。**优点**：M36-4 可**零代码**落地（仅设计＋测试＋文档），
  监察与发现链彻底解耦（监察连"提涉嫌"的专用入口都不新增）。

> B-2 的测试价值：可写"察访奏报本身**不**产生任何 suspect 条目；只有 AI 显式调用才产生"——
> 直接把"不自动成案"钉到怀疑层，比钉在案卷层更早、更严。

## 5 · D10：`financial_evidence` 的触发者（单点定义）

现状（§2.3）只有一条链：`AI 诏令 → resolve_audit → financial_evidence`。M36-4 需要裁的是
**奏报之后是否新增触发路径**。

| 候选 | 链路 | 评价 |
|---|---|---|
| **甲（推荐）** | **决策方（玩家／外部 AI）决定 → 调用 audit**：`奏报（信息）` ⇢ **AI 另行决定** ⇢ `resolve_audit`（单点）→ `financial_evidence` | 触发者＝AI，执行者＝单点；与现状同构；"信息≠行动" |
| 乙 | `inspection_report → resolve_audit → financial_evidence`（奏报自动接钩校） | ❌ 等于"奏报自动成案"，违反 F1／§3 |
| 丙 | 新增第二个证据生产者（如 `inspection_evidence()`） | ❌ 违反 F5 口径单点；三个月后必两张账 |

**推荐甲**，并明确三条附则：

1. **唯一执行点不变**：`audit_case.resolve_audit` 仍是唯一致案函数，`financial_evidence` 仍是唯一证据读数函数；
2. **`audit_fidelity` 输入口径冻结**：`corruption × grip × spy_network × secret` 四输入**不因察访存在而变**
   （若要"察访在场更易查实"，属监察能力模型 ⇒ M37/M38 另案，且必须同时裁定"证据形成机制"的扩展）；
3. **触发通道不新增**：仍走既有 `settlement_decree.effects["audit_route"]`（或等价的显式 AI 行动接口）；
   奏报提供的只是**上下文信息**（AI 可据此决定下诏勾校）。

> 补充（信息，不写死）：奏报的 `summary`／`late`／`inspection_feedback` 观察量**可以**作为 决策方输入，
> 但**不得**作为 `resolve_audit` 的隐藏参数——否则又变成"概率/成功率"的绕道实现。

## 6 · D11：证据权限（谁可见什么）

沿用既有 viewer 模型（`fiscal_gap_report` 为范本；门限 `FIN_ANOMALY_OVERSIGHT_LINE`），M36-4 **不放松**：

| viewer | rumor（风闻档位） | official 账 | real 账（真账三项） | financial evidence（入卷） |
|---|---|---|---|---|
| `player` 玩家 | ✓ 档位/标签 | ✓ | ✗ | ✗ |
| `official` 地方官 | ✓ | ✓ | ✗ | ✗ |
| `court` 中央（常规） | ✓ | ✓ | ✗ | ✗ |
| `inspector` 监察 | ✓ | ✓ | **仅密查，或 `oversight ≥ 门限`** | ✗（见附则 2） |
| `ai` / `system` | ✓ | ✓ | ✓ | ✓ |

**附则（须同时裁定的三条）**

1. **不因察访存在而全开放**：察访使 AI 有"派出去"的手段，**不等于**让所有 viewer 看见真账；
   真账仍按 viewer＋门限判定（现状即如此，M36-4 不得改宽）。
2. **奏报 ≠ 开卷**：`file_inspection_report(case_id=…)` 仍只做**引用校验**；`financial_evidence(include_real=True)`
   仍**只**由 `resolve_audit` 在"查得实情"档调用。M36-3 的反馈观察量是本层的唯一"额外可见物"。
3. **审理阶段入库**：进入三级证据（`status=="证据在握"`）后，证据随卷（`case_is_evidenced` 判据不变），
   执行层（`confiscate_by_case`）沿用既有入口。

## 7 · 明确不做（M36-4 及 M36 全程）

❌ 奏报/到期/反馈 → 自动 `resolve_audit`　❌ 新增第二证据生产者　❌ 察访改变 `audit_fidelity` 四输入
❌ 自动处罚/定罪/抄没/降官　❌ 监察写财政/POP/occupation/欠给　❌ 因察访而放宽任何 viewer 的真账权限
❌ 把 `exposure`/`official_pressure`/`rumor_change` 解释成"贪污概率/犯罪程度/定罪依据"
