# M36《巡按大批次》设计台账（**模型设计，暂不编码**）

> **性质**：设计台账。**本轮不改代码**；先定模型（行动者／资源／任务／选择／反馈），再分批实现。
> **既定冻结边界**：六 POP 不动；occupation 不升人口桶；**不改** `settlement_common`／POP 层；
> 财政只提供状态；**第一版不接**：自动处罚／自动定罪／自动抄没／自动财政恢复（等案件审理链成熟）。
> **上游**：`P3_监察巡按接口_设计台账.md`（P3-1/P3-3/P3-4 已落地）｜`宋代财政流向…V1.3.md` §7-§8。

---

## 0 · 一句话

监察要从"**玩家点一次诏令、系统算一次保真度**"升级为"**一个行动者**"：
**有限的人（巡按）＋ 有限的时间窗口 ＋ 可选的深度（明查/密查）**，
由 AI 决定**是否派、派谁、查哪里、查多深**，其产出仍是**信息**（案卷/证据/透明度）与
**社会反馈**（吏怨/官场反弹/民间期待）——**产出物里没有一分财政修改**。

| 反向观察量 | `inspection_backlash_readout()`（P3-4；grievance/unrest/计数） | 同上 |

| 风闻 | `record_suspicion(...)`（M34-③；唯一写入点、容量 12、窗口 6 回合） | `core/audit_case.py` |

| 官员池（**巡按人选来源**） | `waiting`（待阙）／`sinecure`（祠禄）／`on_post`（在岗）；镜像 `p["official_units"]` | `officialdom.py`（§13.3/§13.4 不变量） |

`audit_fidelity → resolve_audit → audit_cases` 链上。

## 3 · 任务模型（五类：查什么 ⇒ 读哪一层 ⇒ 产出什么证据）

| 任务类型 | 读什么（**权限内**） | 产出（写入 `audit_cases.evidence`） | 成功要素（既有口径） |
|---|---|---|---|
| **查粮** | 仓廪/常平/粮价（`rumor_tier.signals.grain_price`、`changping_stock`、`storage`） | `local_arrears` 之 **public_supply**／粮耗相关；账面 vs 真账（耗损掩护） | 保真度三档（grip 越低越易查实） |
| **查赋** | 田赋三分（`land_tax_*`）、征收缺口 | **`official_gap`**（掩护虚增／征收缺口恒等式）＋`unacknowledged_arrears` | 同上；密查加成 |
| **查吏治** | `clerks_detail.grip/grievance`、吏额 | `local_arrears.clerk_pay`／`officials_salary_arrears` ＋把持度档位 | grip 高 ⇒ 反被蒙蔽／反噬概率↑ |
| **查民情** | `unrest`、`population_satisfaction`、流民、`rumor_tier` | **`rumor_source`**（观察层）＋民心档位（**不含真账**） | 密查更适用（扰民小） |
| **查军务** | 军额/军饷/驻防（`army_units`、`calc_army_cash` 读数） | `soldiers_arrears`（现有接口留白）＋军情档位 | 边镇 grip 与"地方戒备"更高 |

**统一落地**：任务完成时调用**既有** `resolve_audit(state, route, executor=巡按, secret=…)`——
证据项由 P3-1 的 `financial_evidence` 供给（**口径单点**，任务层**不得**另算）。

## 4 · AI 选择接口（决策在 AI，模块只给状态）

```
AI 读：
  inspection_capacity()         # 可派人数 / 在途 / 剩余窗口
  inspection_candidates()       # 人选（待阙/祠禄，含 corruption 倾向）
  rumor_tier()/by_route[*]      # 哪里"听到异常"（何档、何信号）
  identity_pressures()          # 吏/役/官压力（查谁最痛）
  fiscal_gap_report("inspector")# 已有差额（若曾查实）
  inspection_backlash_readout() # 反噬/扰民代价（还查不查）
AI 决定：是否派 → 派谁 → 查哪里 → 查多深（明查/密查）→ 何时撤（窗口）
```
**接口纪律**：以上**全部只读**；决定经**既有入口**落地（诏令/长期任务/召对）；
`TASK_HANDLERS` 登记巡按 topic（`longterm_task.py:122`），**不由财政模块生成剧情**。

## 5 · 风险反馈（监察的代价，全部为**观察量/状态量**）

| 反馈 | 机制（只改状态） | 落点 |
|---|---|---|
| **地方戒备** | 明查 ⇒ 该路"文书修饰"↑：`clerks_detail.grip` 小幅上抬（做账更狠） | 既有字段 |
| **官场反弹** | 每次勾校 `grievance += 1.0×mult`／`unrest += 0.2×mult`（**P3-4 已落地**） | 既有字段 |
| **民间期待变化** | 巡按在途/查实 ⇒ 民心观察量微调（查实升、扰民降） | `population_satisfaction`（需裁 D6 强度） |
| **反噬** | 既有三档之一（`反噬` ⇒ 皇威 −1 已实现） | 既有 |

**均不触碰**：`money`／`finance`／欠给三层／POP／occupation／`identity_pressures`（后者由财政状态派生，**不得由监察写**）。

## 6 · 密查成本（三方案，**待裁 D4**）

| 方案 | 内容 | 代价/风险 |
|---|---|---|
| **甲（推荐·不动钱）** | 密查 ＝ **在途时长 +1 月** ＋ **失败代价更大**（`secret` 仍给"更易查实"加成，但反噬损失加重） | 零财政耦合，与冻结边界完全一致 |
| 乙 | 密查消耗**内帑/赏赐**额度（走既有台账、成对划转） | 触及国库科目 ⇒ 需守恒测试与校准门 |
| 丙 | 密查占用 **2 个**待阙名额（资源计价） | 不动钱；可作甲的参数化 |

| **在途占位** | 一人＝一任务；任务在途期间**不可再派** | `D2`：同时可查路数上限（如 ≤ 3 路） |
| **时间窗口** | 任务 `window`（月）：到期未归 ⇒ 终止并按"已巡月数"结算成果 | `D3`：单任务 **2–4 月**（随路远近/任务种类） |
| **密查成本** | **不动钱**：以"**更多在途时长**（+1 月）＋**更高反噬风险**"计价；或（若用户要求）走既有台账 | `D4`：三方案见 §6 |

> **纪律**：巡按人数来自**既有官员池**（占用 `waiting/sinecure` 名额），**不新增 POP、不改粮耗**；
> 任务本身**不产生任何财政收支**（唯一可能的"成本"是时间与风险）。

## 8 · 结算位置与顺序（设计，不编码）

```
月度结算（既有 Step 序）：
  … → （既有）勾校/发现链相关步骤 → 【M36 新增】inspection_tick(state, log)
       ├─ 任务推进：window −1；到期 ⇒ 结算成果（调 resolve_audit）或终止
       ├─ 地方戒备：明查在途 ⇒ clerks_detail.grip 微抬（上限）
       ├─ 民间期待：查实/扰民 ⇒ population_satisfaction 微调
       └─ 计数落 statistics（含超期数）
```
- **幂等**：同月重复调用不得重复结算（`started_turn`＋`settled_turn` 双标记）；
- **失败兜底**：任务/人数读数异常 ⇒ 记日志跳过，**不得阻断结算**；
- **不改财政**：`inspection_tick` **不出现** `change_treasury`／`transfer_money`／欠给写入。

## 9 · 信息流与权限（与 `fiscal_visibility_view` 对齐）

```
巡按任务完成
  ├─ 观察层（始终）：rumor_source（档位/信号）→ 玩家/中央可读（汇总或逐路）
  └─ 真账层（仅"查得实情"档）：financial_evidence(include_real=True) → 案卷 evidence
        ↑ 之后该路对**该观察者**开放 real（inspector 且 oversight≥门限或密查）
```
**中央仍只见汇总**（`court` 粒度 `national`）；**玩家永不直读 real**——巡按的价值在于"**替中央看见**"。

## 15 · M36-1 落地记录（2026-10-11）

### 15.1 架构定位（用户裁定，本次冻结）

M36 ＝ **监察世界接口层**，**不是**规则化巡按系统。流程固定为：

```
游戏系统提供事实 → AI 读取信息与约束 → AI 提出政治行动选择 → 系统校验合法性 → 执行并产生反馈
```

- **系统负责**：`inspection_capacity()`／`inspection_candidates()`／`rumor_tier()`／`identity_pressures()`／
  `fiscal_gap_report()`／`inspection_backlash_readout()`；任务**合法性检查**；**状态迁移**；**时间推进**；
  **存档**；**守恒校验**。
- **AI 负责**：是否派／派谁／查哪里／查什么／明查还是密查／是否暂缓（或改走赈济、召对、加拨等）。
  **这些一律不写死**——不得出现"自动派遣算法／固定触发条件／自动监察策略"。
- 冻结边界不变：AI 只能**提出行动**，不能改财政／POP／自动认定腐败／自动生成罪名／自动抄没／降官；
  流程仍为 **观察 → 监察任务 → 证据 → 审理 → 执行**（M36-1 只覆盖容器与迁移）。

### 15.2 D1–D8 裁决冻结

| 编号 | 裁决 | 落地 |

| D2 | **固定上限＋官职容量**，不绑财政：小朝廷 3／正常 5／强监察 8 | `INSPECTION_MAX_ACTIVE_TASKS`／`INSPECTION_MAX_ACTIVE_DEFAULT`；`inspection_capacity(tier=)` |

### 16.2 生命周期（本批实现）

```
enqueue（AI 提交，系统校验）→ created      受理待发，占名额
        ↓ 月度推进（inspection_tick）
      active（出发；出发当月不扣窗口）        占名额
        ↓ 每期 remaining −1
      expired（超期未回；非"查出问题"）       释放名额
        ↓ file_inspection_report（回奏；含超期回奏 late=True）
      completed（已回奏）                    释放名额
```

- **无任何自动化**：不自动派遣、不自动完成、不自动成案；`done` 只在**显式回奏**时自增。
- **回奏容器** `file_inspection_report(state, task_id, summary, case_id, log)`：
  只做 ① 任务存在 ② 已出发 ③ 未重复回奏 ④ `case_id` **必须是已存在案卷**（引擎绝不建案）；
  `late=True` 标注超期回奏（**不改写历史**）；`summary` 截断 500 字。
- **名额口径**：`created` 与 `active` **同占名额**（`occupied`），`completed`／`expired` 释放——
  防止"受理不出发"绕过上限。
- **幂等键**：`last_tick_period`（`年-月`）；同期重复推进不重复出发/扣减。
- **存档兼容**：`ensure_inspection_schema` 规范化旧任务（补 `report`／`created_period`／
  `dispatched_period`；**未知状态归一为 `active`**，不猜成 `completed`）。
- **AI 读数**：`inspection_readout()["status_counts"]`（created/active/completed/expired）。
