# M35-C《衙役身份载体设计台账》

> **性质**：**设计台账（本阶段不改代码）**——不修改财政结算、**不移动 `runner_pay`**、不新增 POP。
> 台账先定「人口口径 / 粮耗口径 / 财富口径 / 存档方案 / AI 读取接口」，**由用户裁决后再落代码**。
> **纪律（用户 2026-10-11）**：六 POP 不变；职业层扩展；先设计后实现。

## 0 · 一句话

`runner_pay`（衙役雇钱）现在挂在**兵桶**上——但衙役**不是军人**，且兵桶 `size` 每月由
`army_units.troops` **重算**，衙役塞进去会被抹掉。正确做法是给**职业层（occupation）**一个**并列计数**载体：
**计入人口、消耗粮食、钱落挂靠池**，而**不改任何桶的 `size`**（从而不破三条受测试钉住的不变量）。

**结论（技术约束）**：役人**不能**通过"塞进某个桶的 size"来载入人口/粮耗——
官僚桶会破坏等式不变量、兵桶会被月度聚合抹掉、农桶会破坏 farm slices。
⇒ 必须走 **occupation 并列计数**（本节 Q1 甲）并在**人口与粮耗两个口径点**显式并入。

## 2 · Q1 衙役是否计入人口？

### 候选

| 方案 | 内容 | 代价 |
|---|---|---|
| **甲（推荐）** | **计入人口**，但**不独立 POP**：逐路 `runner_count`（occupation 计数，挂靠 `官僚` 桶）+ 人口口径显式并入 | 需**人口统计接口**支持（1 处口径点） |
| 乙 | 不计入人口，仅作财政身份 | 改动最小，但**"钱给不存在的人"**（长期自相矛盾） |

### 推荐：**甲**，且载体与口径如下

```yaml
prefectures[路]:
  runners: N                    # 已存在的接口字段 → M35-C 升格为**役人计数真账**
  pops["官僚"]:
    runner_count: N             # 🟢 occupation 计数（**不进 size**；SPLIT_FIELDS 注册）
人口口径（单点，改 1 处）：
  路人口 = Σ六桶 size  ( 现状 )
        + Σ occupation 计数（runner_count）   ← M35-C 增补
```

**为什么不并入 size（三条硬理由，均有测试钉住）**
1. 并入 `官僚.size` ⇒ 破 `size == officials + clerks`（`test_officialdom`／`test_pop_flow_wealth`）；
2. 并入 `兵.size` ⇒ 每月被 `Σ army_units.troops` 重算**抹掉**（兵额真账单一）；
3. 并入 `农.size` ⇒ 破 farm slices 不变量（`check_farm_invariants`）。

⇒ 「**计入人口、但不独立 POP**」在工程上＝**occupation 并列计数 + 人口 Σ 显式并入**，
这正是裁决字面（"人口统计读取 occupation"）的实现。

## 3 · Q2 衙役是否消耗粮食？

| 方案 | 内容 | 代价 |
|---|---|---|
| **甲（推荐）** | **消耗粮食**（役人是实际居民，不突破人口守恒）；粮耗**归属人口主体**（挂靠桶），**不新增粮桶** | 需在**粮耗需求口径点**显式并入（现口径皆为 `size × 人均`，故须补一项） |
| 乙 | 不单独计粮，视为**官府行政成本**（只在钱侧体现） | 实现最小；但"账上有人、仓里不吃饭"，长局会出现役人不饿的反直觉 |

### 推荐：**甲**，口径与读写点（**不新增粮桶**）

```
役人粮耗 = runner_count × GRAIN_CONSUME_PER_CAPITA[挂靠桶]      # 与六桶同口径，单点
归口：挂靠桶 = 官僚（州县赡养，推荐；见 §4）
```

**需并入的粮耗口径点（落代码时逐处补，并各配一条守恒断言）**

| # | 口径点 | 现状 | M35-C 增补 |
|---|---|---|---|
| 1 | 口粮需求 / 饥饿人数（`settlement_common` 唯一口径） | `size × per` | `(size + runner_count) × per` |
| 2 | 保底豁免线（贯） | `size × per × price` | 同上（役人也要保底） |
| 3 | 太仓/常平发放与购粮能力（`settlement_granary`） | `size × per` | 同上 |
| 4 | 月报/面板粮需读数（`region_brief`、`income_readout`、`market_readout`） | `size × per` | 同上（**读数同源**，不得各自另算） |
| 5 | 太仓/常平仓**存量**与仓储口径 | 不改 | 不含役人（役人不另占仓容） |

**替代方案（不推荐，供对照）**：把 `runner_count` 并入**挂靠桶 size** ⇒ 粮耗/人口/财富全部自动成立、
**零口径点**，但破 §2 的三条不变量（含月度重算抹除）⇒ **不可取**。

## 4 · Q3 `runner_pay` 的财富归属

**原则**：**不新增 POP**；钱落**挂靠人口主体**的 `occupation_income`（记账层），
欠给落**同一挂靠桶**的身份字段；**本阶段不移动**（仅定方案）。

**挂靠桶选择（三选一）**

| 方案 | 挂靠桶 | 史实/模型理由 | 代价 |
|---|---|---|---|
| **甲（推荐）** | **官僚** | 衙前/弓手/手力等**职役由州县支给**（雇役法后为"雇钱"），属"官府赡养人口"；且与 `clerk_pay`（吏禄）同池，便于"吏役一体"推演 | 官僚桶新增 occupation 计数与记账额度；需迁移 `runners_pay_arrears` |
| 乙 | 农 | 役人本由**乡村主户**抽充（差役原形） | 与"官府支给"矛盾；且破 farm slices 的风险更高 |
| 丙 | 兵 | 与现状一致（弓手近似乡兵） | 与"衙役非军人"的裁决冲突；兵 size 月度重算会抹掉计数 |

**推荐甲的实现口径（落代码时）**

```
收款方：transfer_money("local:<路>", "pop:<路>:官僚", 额)        # 与 clerk_pay 同池
记账层：pops["官僚"]["occupation_income"] = {"runner": 累计额}   # 🟢 新增（SPLIT_FIELDS 注册）
        （与 M35-A 的 officials_wealth/clerks_wealth 同性质：**记账不改真账**）
身份欠给：runners_pay_arrears 由 **兵桶 → 官僚桶**（一次性幂等迁移，留痕）
压力/月数：identity_pressures().runner_pressure 与 arrears_months["runner_pay"] **不变**（口径不变）
```

**不动项（本阶段明确保留）**：`LOCAL_EXP_ACTIVE_KINDS`／`_payout` 映射／财政结算调用链
**一行不改** ⇒ 校准门必保持逐位不变。

## 5 · 存档方案

**新增字段（落代码时；全部幂等补默认，**不升 schema**——皆在既有容器内）**

| 字段 | 归属 | 类型/默认 | 注册 |
|---|---|---|---|
| `prefectures[路]["runners"]` | 路级（**升格**：接口 → 役人计数真账） | int / 0 | 无需（非 POP 池） |
| `pops["官僚"]["runner_count"]` | occupation 计数 | int / 0 | ✅ `SPLIT_FIELDS`（可加下游） |
| `pops["官僚"]["occupation_income"]` | 记账层（M35-A 同族） | int / 0（`runner` 分项） | ✅ `SPLIT_FIELDS` |
| `pops["官僚"]["runners_pay_arrears"]` | 身份欠给（**迁池**） | int / 0 | ✅ `SPLIT_FIELDS`（已注册） |
| `pops["兵"]["runners_pay_arrears"]` | **旧位（保留一版兼容）** | int / 0 | 保留注册 |

**迁移（一次性、幂等、可重入）**
1. 旧档缺 `runner_count`／`occupation_income` ⇒ 补 0（与 M35-A/B 同款 `setdefault`）；
2. `runners_pay_arrears`：若**兵桶有、官僚桶无** ⇒ 搬移（数值不复制，**搬运**），
   并写 `statistics["m35c_runner_arrears_migrated"]` 留痕；**幂等**：已搬过的档不再重复；
3. 迁移**不得改动**任何 `size`／`wealth`／`grain` 总量（只动记账/欠给字段）⇒ Σ 货币、人口、粮耗全不变；
4. `runners` 旧档缺失 ⇒ 0（"未建模役人"与"役人为 0"同义，**不伪造人口**）。
