## 2 · 数据结构变化

```
pops["官僚"] += {
    officials_wealth: 0            # M35-A 记账层（官）
    clerks_wealth: 0               # M35-A 记账层（吏）
    officials_salary_arrears: 0    # M35-B 官欠俸
    clerks_pay_arrears: 0          # M35-B 吏欠钱
}
pops["兵"] += {
    soldiers_arrears: 0            # M35-B 士卒欠饷（中央军饷欠，接口留白）
    runners_pay_arrears: 0         # M35-B 衙役欠钱（runner_pay 落点）
    militia_pay_arrears: 0         # M35-B 乡兵欠给（地方）
}
prefectures[路]["runners"] = n     # M35-C 接口留白（AI/事件可填；不改 POP、不改人口真账）
```

**不变的量**：`size`／`grain`／`wealth`／`欠税`／`欠给`／`officials`｜`clerks`｜`on_post`｜`waiting`｜`sinecure`
（身份经济层只是**记账**，不拆真账、不改粮耗、不改人口）。份额 `wealth_share` **读侧派生**
（`officials_wealth ÷ (officials_wealth+clerks_wealth)`；两池皆空 → `None`，缺失不伪造 0.5）。

**只读视图**（AI/面板接口）
- `identity_economics()`：逐路 官/吏 计数、记账额、`coverage`（记账 ÷ 整池）、share、身份欠给；
- `calc_local_identities()`：`official/clerk/soldier/militia/runner`（士卒／乡兵按 `army_units.tier`
  映射；**不改军费**）；
- `fiscal_visibility()`：`real`（真账）／`official`（官府账＝真账＋P2 损耗掩护）／`rumor`（风闻，
  来自 P3 发现链）**三层同一投影**，不新建账本。

## 3 · 状态公式

**① 时间（M35-2-A）**
```
当月该科目 未付 > 0      → months = min(CAP, months + 1)
当月该科目 未付 == 0     → months = max(0, months − 1)          # 恢复递减
该身份欠给存量 == 0      → months = 0                            # 清偿即清零（"补发即缓解"）
```

**② 压力（M35-2-B）**——各项先归一到 0–1，再加权 ×100（**只报状态，不自动成事件**）
```
金额占比 = clamp(身份欠给存量 ÷ 该科目当月现实应支 due_eff, 0, 1)      # 分母缺失 → 0（不伪造）
月数占比 = clamp(连续欠给月数 ÷ LOCAL_PRESSURE_MONTHS_REF(24), 0, 1)

clerk_pressure    = 100·clamp(0.35·金额占比 + 0.35·月数占比 + 0.20·吏胥把持度 + 0.10·侵渔率)
official_pressure = 100·clamp(0.35·金额占比 + 0.35·月数占比 + 0.15·(1−俸禄实付率) + 0.10·侵渔率)
runner_pressure   = 100·clamp(0.35·金额占比 + 0.35·月数占比 + 0.20·吏胥把持度 + 0.10·侵渔率)
```
输出含**构成**（`inputs`：金额/月数/grip/pay_ratio/div），AI 可据此判断"为什么有压力"。

**③ 可见度读取规则（M35-2-C）**——保持 real／official／rumor 三层，**只加读取规则**
```
viewer="player"（默认，含 finance_readout）→ official + rumor          # ❌ 不含 real
viewer="audit"                              → 同上；**仅当** oversight ≥ 0.45 或 secret=True → + real
viewer="system"/"ai"                        → real + official + rumor   # 内部/全知
真账入口 = fiscal_visibility()（内部只读；为审计/巡按/调查预留）
```

## M35-3《欠给补发与恢复机制》· 落地记录

> 裁决 2026-10-11：从"记录欠给"进入"**财政恢复闭环**"——财政改善 → 补发欠给 → 压力下降 → 治理恢复。
> 约束：六 POP 不变；职业层扩展；不新增人口桶；runner 仍为 occupation 接口。

### 1 · 修改文件列表

| 文件 | 改动 |
|---|---|
| `content/data_constants.py` / `content/data.py` | `LOCAL_REPAY_ENABLED`（接口开关，默认开但**无自动调用**）、`LOCAL_REPAY_KEEP_MONTHS`（府库留存线）、`LOCAL_REPAY_MONTHS_RELIEF`（补发缓解月数） |
| `core/settlement_finance.py` | 新增 `repay_local_arrears(...)`（**账户划转**补发引擎：来源／级序／同步冲减三层账与月数） |
| `core/game_state_econ.py` | 新增 `arrears_recovery_capacity()`（AI 补发能力读数）；`finance_readout` 增 `arrears_recovery_capacity` 与 `local_arrears_repaid` |
| 测试 | 新 `test_arrears_repayment_m35_3.py`（8 例） |

### 2 · 数据结构变化

**无新增持久字段**（复用 M35-1/2 的欠给三层与月数表）；仅新增**累计读数键**：
```
statistics["local_arrears_repaid"]   # 累计补发额（诊断/AI；statistics 整存整取，无需迁移）
```

### 3 · 状态公式（补发）

```
可动用额 avail：
  source="coffer"   → max(0, 府库余额 − LOCAL_REPAY_KEEP_MONTHS × 现实应支 due_eff)
  source="treasury" → min(amount, max(0, 国库 − ARREARS_KEEP_TREASURY))  # 先拨到本路府库再补发

顺序 ＝ D7′ LOCAL_EXP_PAY_TIERS（一级 clerk_pay → runner_pay → public_supply；二级 official_salary）
        若显式传 kinds 则以 kinds 为序（**制度选择**，不做自动公平分配）

单笔：payable ＝ min(池 `欠给` 份额, 身份欠给存量)；pay ＝ min(avail, payable)
      got ＝ transfer_money("local:<路>", "pop:<路>:<阶层>", pay)   # 唯一写口，Σ 守恒
同步冲减（**同一笔成功后**）：池 `欠给` − got；身份字段 − got；统计三层 − got；
      月数：身份存量归零 → 0；否则 max(0, 月数 − LOCAL_REPAY_MONTHS_RELIEF)
**不触碰**：corruption / grip / unrest / 治理派生（由时间与改革恢复）
```

### 4 · 测试结果（8 例全绿）

① 补发＝真实流转：**Σ 货币守恒**（`money.m_all` 前后相等）、POP wealth↑、欠给总额↓、月数↓、压力↓；
② **不直接降** `grip`／`unrest`（"欠钱解决 ≠ 立即清廉"）；
③ 六桶**人口/粮耗不变**；
④ **级序**：现金仅够一级时，`clerk_pay` 得款、`official_salary` 不得越级；显式 `kinds` 体现制度选择；
⑤ **中央拨款来源**：国库实付↓、府库中转、POP↑，Σ 守恒；
⑥ **未自动调用**：府库充裕时 `_settle_finance` 也不自行补发（累计补发额不变）；
⑦ 补发能力读数（AI 接口）齐备且只读；
⑧ 存档往返后欠给/月数/累计补发一致。
**相关回归 152 例全绿；校准门逐位不变**（国库 99,806／人口 101,108,605／民生 55／粮价 1.220904／州库 9,833,497）。

### 5 · 存档兼容说明

- 补发**不新增持久字段**：欠给/月数沿用 M35-1/2 的既有容器；累计额在 `statistics`（整存整取）。
- 旧档无需迁移；**已测**：存读往返后三层欠给账与月数一致。
- 未下沉档走桥接回落路径；已下沉档写 `seats` 真账并刷新镜像（补发用「每次取新鲜镜像」避免丢账）。

2. **M35-C 台账（裁决指定下一项）**：先解决"**衙役是否计入人口/粮耗**"的史实与模型裁决——
