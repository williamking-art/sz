# requirements · 民间经济与营造市场

> 依据：[`docs/AI推演与民间经济营造市场落地建议.md`](../../../docs/AI推演与民间经济营造市场落地建议.md)
> （下称《建议》）。计划见 [`tasks.md`](tasks.md)。**本文件是需求基线，不是实现状态声明**；实现/接线/放行进度以任务表的最新收口状态和代码证据为准。

## 目标（《建议》§1.1）

1. 民间 POP 成为持续的**市场买方、生产者、投资者、持货者**，而非仅税赋与政府支出的承接方；
2. "需求—财富—供给—成交—库存—价格—生活状况—政治反应"构成**可追踪的回合因果链**；
3. 口粮与商品粮、官仓与民仓、官营与民营、政府工程与民间营造**共处一套经济规则**；
4. AI 能因不同局势提不同方案，并可提出内容库没有的新科技/商品/蓝图/装备；
5. 保留混沌、分歧、失败与意外；**数值仍须可审核、可守恒、可回放**。

## 需求条目

### R1 · 成交必须真实（《建议》§4.2、P0-1）
- **R1.1** 一笔购买同时完成：买方 wealth 减、卖方 wealth 增、卖方库存减、买方库存增。
- **R1.2** `成交量 ≤ min(期望量, 支付量, 可售量)`；**无货不能买**。
- **R1.3** 供给不足→**未满足需求**；财富不足→**被价格排挤**；两者**必须可区分**。
- **R1.4** **禁止虚拟供给**——需求不得直接生成商品（《建议》§1.2）。
- **R1.5** ⚠️ **现状不是"完全没有成交"**：`core/settlement_granary.py:280-285`
  的 POP 购买路径确有"扣款→给货→无卖方扣减"，但 `settlement_granary.py:296-309`
  （存货外销）与 `production_chain.py` （工匠 goods 池产出）**是真扣货路径**。
  故 R1 的要求是**逐路径定性并消除虚拟供给**，不是"从无到有建市场"。

### R2 · 库存口径单一（《建议》§4.1）
- **R2.1** 库存必须表达**真实持有人 ＋ 所在路府 ＋ 用途/预留状态**。
- **R2.2** 市场汇总只是**读视图**，不得形成第二份商品账。
- **R2.3** 预留可标记不可售，**但不得复制库存**。
- **R2.4** ⚠️ **实测前提**：代码现存**三处库存载体**——
      ① `state.resources[dim]["stock"]`（仓储资源）；
      ② `pop["goods"]`（POP 手持，**其中工匠条目兼作生产库存/待售货**）；
      ③ 在途（**尚无实现**）。
      ②中"消费库存"与"生产库存"语义重叠，须按**持有人/地点/用途**分离，
      而非把容器合并成一个字典（见 tasks §1.1、B0-1）。

### R3 · 粮食用途分离（《建议》§4.3）
- **R3.1** 口粮／商品粮／军粮／赈济粮是**不同用途**，各自归属明确。
- **R3.2** 转成商品粮时**必须从原持有人库存移出/锁定**。
- **R3.3** 先保农户口粮与安全垫，**再**算可售粮（不得让农户买回自己的口粮）。
- **R3.4** 买粮/吃粮/缴粮/官府采购/平粜/赈济/军需 = **不同交易类型**，避免双扣款/双扣粮。

### R4 · 需求分层（《建议》§5.1、§9 阶段 2）
- **R4.1** 阶层偏好是**初始倾向**，非固定清单；商品与价格变化后 AI 可改选择。
- **R4.2** 需求接入**财富余量**：余量不足则不消费或降档。
- **R4.3** 耐用品有**目标库存**，非每月线性消耗。
- **R4.4** 地区权重进入需求。

### R5 · 价格发现（《建议》§5.1、§9 阶段 2）
- **R5.1** 价格按报价/成交需求/可售供给**缓动**，有**上下界**与**单月涨跌封顶**。
- **R5.2** 使用**统一权威算法**，不得多处各算。
- **R5.3** 缺数据的商品先为**提案**，不进入已生效市场。

### R6 · 营造材料与工期（《建议》§6.2、§9 阶段 4）
- **R6.1** 木/石/砖等有**实物来源、单位、库存、价格、可替代性**。
- **R6.2** 水泥/钢筋等新材经**科技解锁**；**科技 ≠ 免费材料**。
- **R6.3** 基准造价是**预算估值**，由材料价＋人工＋运输估算；**不是额外扣钱项**。
- **R6.4** 三种取材路径（市场购料／官仓领料／民间自建）**分别记账**，
      基准估价、采购款、工钱、运费**不得双计**。
- **R6.5** **赶工预算独立于基准预算**；边际提速递减；**未用余额退回出资方**。
- **R6.6** **缺料不会照常完工**（排队/追加采购/延期）。

### R7 · 官员个体 Agent（《建议》§7）
- **R7.1** 每名具名官员是**独立 Agent**，不因同派/同职/同领域而合并。
- **R7.2** 最小状态：身份与时间／个性与能力／立场与利害／私人关系／个人记忆／
      认知边界／当前意图（§3.3 七项）。
- **R7.3** 换职改权限与信息可见，**不换人格、不抹记忆**。
- **R7.4** 领域契约是**专业分析/幕僚输入**，**无官职、无派系利益、无最终决定权**；
      **不得由领域 Agent 代替主事官员拍板**。
- **R7.5** 沉默/异议/联署/拖延/观望都是**不同状态**；
      **不得用缺失输出冒充"忠诚支持"或"没有异议"**。
- **R7.6** 记忆与对话**不跨人物混用**；合议只传递已公开或合法获知的信息。
- **R7.7** 批量推理必须**逐人分隔上下文与输出 schema**，防串人格/串记忆。

### R8 · 命令对象四维度（《建议》§7.3）
- **R8.1** `authority / procedure / visibility / delivery` **四维分离**，
      替掉纠缠的布尔字段（`is_secret` / `is_direct` / `is_zhongzhi`）。
- **R8.2** 四类命令差异体现在**速度、知情面、协调成本、支持/抵触、信息可靠性、
      皇威代价、可追责性**，**而非各套一个静态成功倍率**。
- **R8.3** 口谕须**复述确认**；补录沿用**同一命令 ID**，**不重复执行**。
- **R8.4** 密令泄露按**真实知情范围与传递路径**推演。
- **R8.5** 玩家已颁命令**不得被 AI 投票取消**；但执行中可迟延/走样/寻租，
      且须有**符合人物与制度的具体原因**。

### R9 · 动态内容生命周期（《建议》§8）
- **R9.1** 科技/商品/蓝图/装备进入推演前**必填机械信息**（§8.1 表）。
- **R9.2** 未满足机械信息时保持**"提议中/待补蓝图/待技术支持"**，**不立即影响结算**。
- **R9.3** 突破史实时标记**"架空发展/玩家诱发创新"**，不误写成真实宋史。
- **R9.4** **模块级全局注册 ≠ 当前存档的稳定内容注册**（需存档级注册＋读档迁移）。

### R10 · 读数与可诊断（《建议》§9 阶段 0、§11）
- **R10.1** 逐月/逐路/逐POP/逐商品的需求、支付能力、供给、成交、未满足量、价格、库存、
      生产、外运、损耗**可读**。
- **R10.2** 未满足原因**四分解**：没需求／没钱／没货／没运到。
- **R10.3** 区分货币支出、商品转移、生产耗料、消费耗用、官府拨用、初始存量。
- **R10.4** 派生失败**显式留痕**（如 `readout_errors`），**不以空白冒充"无数据"**。

## 非目标（《建议》§1.2）

- ✗ 不让 LLM 直接改 POP 财富/人口/库存/价格/建筑等级/回合进度；
- ✗ 不把历史事件年表扩成唯一玩法路线；
- ✗ 不为"真实"把行为细节写成固定公式——参数只给**边界、惯性、反馈**；
- ✗ 不同时重做全部商品/官仓/AI 契约（按可验证闭环分期）；
- ✗ 不为追求动态提案而延迟基础货物流守恒。

## 硬约束（继承 `sz/AGENTS.md` §3）

1. **POP 挂载律**：人只落 6 类 POP 的 `size`；钱粮只落 POP `wealth`/`grain` 或国库/内帑；
   **禁与 POP 平行的账本**。
2. **口径单点**：算法在 `core/`；端点薄壳；前端不复制算法。
3. **缺失 ≠ 0 ≠ 1.0**：缺失一律 `None` → "未定义"。
4. **核心模拟改动先说明口径与影响 ＋ 加定向回归**。
