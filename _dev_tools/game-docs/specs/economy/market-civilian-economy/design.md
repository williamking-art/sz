## 1 · 库存归属建模（B1-3 技术方向）

> ⚠️ 依 2026-10-11 用户修订：**不采用"两仓合并/择一"的旧方案**。
> 要求是**每一份库存都能回答"持有人是谁、在哪里、是什么商品、可作何用途、是否预留"**，
> 市场可售量**从权威持有记录派生**，不在多处重复记货。

### 建模要求

```text
每一份库存须可回答：
  持有人（POP 阶层 / 作坊 / 官仓 / 工程预留 / 在途）
  所在路府
  商品维度 ＋ 计量单位
  用途（消费持有 / 生产投入 / 待售 / 官用 / 预留）
  是否可售（预留与自用须扣除）
```

- **不合并物理容器**——`resources`、POP、作坊各自的存储语义不同，强行合并会丢信息；
- **派生视图**：路级可售量、全国库存、品类汇总均为**读视图**，不重复持货；
- `pop.goods` 里工匠条目的**双重语义需拆开**（生产池 vs 消费持有），这是 B0-1 的重点产出。

**新增单点函数**（`core/market.py`，口径单点；签名以 B0-1 台账为准）：
```python
def trade_goods(state, *, dim, qty, buyer, seller, purpose="consume") -> int:
    """单笔成交：钱与货双向转移，返回实际成交量。
    成交量 ≤ min(qty, 买方可支付, 卖方可售且非预留)。
    任一侧不足即按实成交量成交，绝不虚拟供给。"""
```
- 钱走既有守恒通道（民间↔民间直接对划；涉官府走 `transfer_public_funds_to_pops`）；
- **禁止**在调用点直接 `+=` / `-=` 库存或 wealth。

## 2 · 成交撮合（B1-1/2/5 技术方案）

```python
def clear_goods_market(state) -> dict:
    """路内 goods 撮合（《建议》§9 阶段 1：先做路内，不做跨路）。
    顺序：① 卖方报价（按数量/价格/意愿）② 买方预算排序
          ③ 逐笔成交 trade_goods ④ 汇总未满足原因。
    """
```

- **整数尾差**：成交价与量用 `int` 时，尾差归**最后成交方**并记 `statistics`，
  不静默截断（现靠"尾差归商人"，推广到通用路径）；
- **未满足四因**（R10.2）：
  | 原因 | 判据 |
  |---|---|
  | 没需求 | `期望量 == 0` |
  | 没钱 | `支付量 == 0 且 期望量 > 0` |
  | 没货 | `可售量 == 0 且 期望量 > 0` |
  | 没运到 | `在途 > 0 但本地可售 == 0` |
- **防重复卖出**：同回合同商品总成交 `≤ Σ可售库存`，由 `trade_goods` 内部扣减保证。

## 3 · 需求分层与余量（B2 技术方案）

```python
def demand_basket(pop_cls: str, wealth: float, prices: dict,
                  basket: dict) -> dict:
    """《建议》§4.2 + 用户定论（2026-10-01：阶层需求 × 财富余量，相乘非相加）。
    余量释放 = clamp((wealth − 温饱线(cls)) / 余量尺度(cls), 0, 1)
    品类需求 = 篮子[cls][dim] × 余量释放 × 价格敏感(涨价降档/减量)
    """
```

- **相乘而非相加**：贫民不会因等级低就不消费，富人不会因余量大就买超等级的量；
- **量入为出**：上限 `min(余量, 等级需求上限)`；
- ⚠️ **温饱线/余量尺度待裁定**（tasks §9-2）。

## 5 · 营造材料与工期（B4 技术方案）

### 5.1 造价挂材料（用户定论：单一真源）

```text
基准造价 = Σ(材料量 × 单价)        ← 派生，不落第二份账
```
- **消除** `cost_coin` 与 `cost_material` 双声明（旧代码把同一个数塞给两者，是语义冲突根源）；
- 材料单价读 §4 的动态价。

### 5.2 工期随投入（用户定论：凹函数）

```text
投入倍数 k = 实际月投入 / 基准月投入     （缺省 k=1）
工期倍率 = k ** α                        （α ≈ 0.5，用户定：凹函数）
月度应付 = 基准月投入 × k，总额封顶 = 基准造价
赶工溢价 = 基准造价 × (工期倍率 − 1) × 溢价系数 ⚠️待裁定
未用赶工余额 → 退回出资方（用户定）
```

### 5.3 营建支出上限（**开工复核项**，非既定缺陷）

> 2026-10-11 用户修订：**"6 月付 6 倍"是 2026-10-01 的实测观察，
> 不是已确认的缺陷定论**——计划演进后不得沿用为验收断言。

B4 开工时先复核 `settlement_tech._settle_projects`：
当前是否存在**项目预算余额 / 已付累计 / 工期联动上限**？
- 若**仍**按每月对完整 `cost_coin` 计算当期支出 → 作为 B4-3/4 的**前置缺陷**一并修；
- 若已引入余额机制 → **以当前代码与流水测试为准**更新本节，废止旧断言。

**验收口径**（tasks B4 已对齐）：不同供给率与工期下，
**累计付款与材料消耗不超过批准预算/清单**；延期/中止时余款余料退回原所有者或继续专款预留，
**不静默消失**；月付累积可审计。

### 5.4 新材（水泥/钢筋）

- 全库**现无此物**；`asset_context.py:567` 关键词表预留过 `"水泥"`；
- 用户定论：**科技 ≠ 免费材料**，须经解锁配方/工艺/贸易。
