## 1 · 开工必须复核的结构前提（代码与存档可演进）

### 1.1 库存按持有人、地点和用途归属，不能只按两个字段归一

| 载体 | 维度 | 产出 | 消费 | 实测现状 |
|---|---|---|---|---|
| `state.resources[dim]["stock"]` | 仓储资源维度（开局量需逐档核实） | 作坊/生产链按配方写入 | 工程领料等路径读取 | 可能为 0，不等于市场供给全集 |
| `prefectures[路].pops[阶层].goods` | 路级 POP 持货商品 | 市场成交/迁移/旧档兼容 | 消费、持有与折旧 | 商品维度及消费者需按现代码核实 |
| `prefectures[路].pops["工匠"].goods` | 工匠生产库存/待售货 | `_settle_workshops` 或生产链写入 | POP 购买、外销 | 与工匠个人消费库存语义须厘清 |
| 建筑/岗位/作坊的 `goods` 或原料槽 | 行业生产中间品/在制品 | 岗位生产 | 后续配方/工资/成品形成 | 查明是否为独立库存或临时营收池 |

**设计要求不是把所有物理容器合并成一个字典**，而是每一份库存都能回答“持有人是谁、在哪里、是什么商品、可作何用途、是否预留”；市场可售量必须从这些权威持有记录派生，不能在 `resources`、POP、作坊和市场汇总中重复记货。`state.resources` 若代表中央/官仓，不得自动视为民间本地可售库存。

### 1.2 两条商品消费路径语义不同，不能合并为一个“全市场已/未接线”结论

`core/settlement_granary.py:280-285`：
```python
spend = int(pop["wealth"] * base_rate * _elastic * _boom)
pop["wealth"] -= spend
pop["goods"][gdim] += int(spend * share)   # ← 凭空入库，无卖方校验
```
该函数的商品购买路径确实按财富比例扣款、给消费者增加 goods，并将钱分配给工匠/商人，但没有对应扣除具体卖方库存，属于无卖方商品产生。与此同时，`settlement_econ.py` 已存在另一条从路级工匠库存扣货、POP 支付、卖方收款的成交路径。B0/B1 必须分别画出调用顺序与商品维度，明确哪些是有效闭环、哪些是旧路径/兜底，不能重复结算或误删有效的作坊交易。

### 1.3 财政 Agent 当前路由已停唤醒，不列作经济修复任务

`core/agent_router.py` 将 finance 的 `wired` 设为 `False`，路由有守卫会跳过该 Agent；不能再把“仍会真实唤醒/白烧 token”当作当前事实或 B1 工作项。若后续要恢复，须先定义负责官员、消费字段和程序落点（官员 Agent 见 B5）。

## 3 · B1 · 库存所有权与交易通道定型

**目标**（《建议》§10 P0-1、P0-2）：为试点商品定义唯一权威的持有人库存和成交入口，淘汰/迁移不完整旧路径，消除无卖方入货与重复售货。

### 任务

- [x] **B1-1** 按 B0 台账选一组试点商品和一条市场路径（先本地布/绸或粮，不全商品一次切换）；给定买方、真实卖方、路府和用途，成交须同时完成
      `买方 wealth −paid` ＋ `卖方 wealth +paid` ＋ `卖方 goods −q` ＋ `买方 goods +q`；
      `成交量 ≤ min(期望量, 支付量, 可售量)`（§4.2）
      → `core/market.py::trade_goods`（成交**唯一入口**；三重上限；写前复核防重入）
- [x] **B1-2** 市场可售视图只能汇总真实卖方可出售库存，扣除预留/自用/官用量；库存卖光后不再成交，短缺保留为未满足需求。
      → `sellable_stock`＝持仓 − `reserved`；无货 → `no_stock_local` ＋ 未满足量
- [x] **B1-3** 定义并迁移库存槽位：POP 持有量、作坊待售成品、在制品、中央/地方仓、在途、工程预留各有用途；路级与全国读数均为派生视图，不重复持货。旧档缺字段按显式迁移，不凭空生成库存。

- [x] **B1-4** 统一成交原子操作与防重：货币/货物任一腿失败时整笔回滚；稳定交易 ID 防回合重试重复成交。

- [x] **B1-5** 收口旧消费分配路径：把 granary 的无卖方 `wealth → goods` 代码改为真实成交，或按已核实的商品语义移除；不得与 `settlement_econ` 的路级作坊成交重复购买。

- [x] **B1-6** 统一取整和尾差的对手方规则，所有余数去向写入流水，禁止无来源销毁/生成。
      → `trade_goods` 返回 `paid` 精确整数（`qty × price`）；分派尾差归末路并回填

- [x] **无货不能买**（构造空库存用例：成交额 == 0）；→ `test_no_stock_means_no_trade`
- [x] `ΔM_ALL == 0`（内部转移不增残差）；→ 60 月 `residual` 全程 0

### 用户裁定与 B1 揭示的待决问题

**裁定（2026-10-11）**：①移除兜底直产，让消费**无货则不买**；②宋境**配置麻坊/丝坊**作为布绸供给。

3. **成品双记账** —— `resources`（storage）与工匠 goods（resale）是**同一批货的两个用途槽**，

      规格要求"明确主事官员/消费者/执行入口/失败语义"四条件齐备才启用，实测**四条件均不齐**：

      | 契约 | AIClient 方法 | 消费者 | 结论 |
      |---|---|---|---|
      | `finance_decide` | ✅ 存在（`contracts_settle.py:601`） | ❌ `settlement_steps._settle_finance` **未消费** | 唤醒会**白烧 token**：结果被丢弃（`agent_router.py:165` 已注"反向不一致"） |
      | `invest_decide` | ✅ 存在（`contracts_settle.py:210`） | ⚠️ `settle_investments` 有，但落地入口 `invest()` **无生产调用方** | ⛔ **回报凭空铸币**，见下 |
      | `reform_decide` | ❌ **方法不存在** | `settlement.py::settle_reform` 存在 | 契约缺失，无内容可唤醒 |

      ⛔ **`invest_decide` 的硬阻塞（守恒律，`estate_mechanic.py:432`）**：
      `ret_total = amount × INVEST_BASE[领域]["return"] × (months/12)`，
      而 `invest()` 走`state.change_treasury(-amount)` 出钱，**产出端不存在**——
      即"国库出钱→按系数凭空多出钱"，**违反 POP 挂载律第2 条（钱只落 POP wealth/grain 或国库/内帑）**，
      会使货币残差恒不为 0。
      `estate_mechanic.py:415-416` 原有注释已登记此问题并要求
      「接线前须一并落实**回报来源守恒**（回报应来自产出端）」。
      **故在"回报来自产出端"落地前，`invest` 保持无生产调用方是正确的**，
      强行接线 = 把已登记的缺陷变成实际铸币。

### 验收断言

- 相同局势**可出现不同官员主张**与合法路径；
- 跨回合保留**个人记忆**，不同官员**不共享私密信息**（逐人隔离断言）；
- 任免改变权限而**不重置人物身份**；
- 批量推理与逐人推理在**身份/记忆/归因上等价**；
- 四类命令差异在**时效、知情范围、意见流程、承办条件、后果**可被玩家感知，
  **而非仅显示为静态倍率**；
- 口谕补录**不重复执行**；密令未授权者**看不到正文**。

### 前置依赖与并行关系

官员 Agent/命令对象与市场库存是不同子系统：人物身份、权限、记忆和四维旨意模型可与 B1–B4 并行；凡提案涉及采购、消费、仓储、工资或工程的动作，须依赖相应交易/营造闭环。先盘点并复用 `decree-action-chain` 已完成能力，不得重复建设行动计划/动态蓝图链。
