# M36.6-A《AI 大臣人格化事实视图与提案契约》设计裁决台账

> 2026-10-11 建立（用户裁定：**先加深 M36.5 的 AI 侧接线，暂不开 M37**）。
> **首轮只定义**：数据结构、权限继承、提案格式、状态转换；**不改执行单点，不新增监察能力**。
>
> 三条必须坚持的原则（用户原话精神）：
> 1. **人格化 ≠ 权限提升**（兵部可从军事职责组织事实、户部可从财政职责组织事实，但**不得**因此获得额外隐密信息）；
> 2. **提案 ≠ 决策，决策 ≠ 执行**（驳回/退回/暂缓**均不得产生世界状态变更**；执行失败**不得**标记为成功批准）；
> 3. **监察发现／审计取证／司法判断继续分离**（M36.6 只改善决策表达与交互语义）。

## 2 · M36.6-A 人格化事实视图（Minister Lens）

**定义**：在**事实集合与权限完全不变**的前提下，按大臣的**职责／派系／关切**对同一份事实做**分组与排序**，
并给出"我该看什么"的**视线提示**。**不是**信息特权。

```python
minister_lens(state, name) -> {
  "minister": {"name", "role", "faction", "rank", "nobility",
               "traits": [...], "in_office": bool},          # 公开档案字段（不含 loyalty/corruption 数值）
  "focus": ["军务", "边防"],                                  # 由 role/traits 派生（只读，可解释）
  "sections": [                                              # 同源事实的**分区重排**（不可新增字段）
     {"key": "发现链",   "refs": ["discovery"], "note": "…"},
     {"key": "察访编制", "refs": ["inspection.capacity", "inspection.candidates_by_route"]},
     {"key": "在途与奏报", "refs": ["inspection.tasks", "inspection.suspicion_pending"]},
     {"key": "财政上下文", "refs": ["fiscal_context"], "filtered_by": "viewer 权限"}],
  "facts": <ai_decision_view 的同源输出>,                      # **同一份**事实（权限同样受 D11 约束）
  "viewer": "official",                                       # 权限身份＝大臣自身（**不因官职/人格升级**）
  "note": "人格化只重排与标注，不增权限、不增字段",
}
```

**纪律（契约测试钉住）**
1. `facts` 必须与 `ai_decision_view(state, viewer=<该大臣身份>)` **逐键等价**（人格化不改变事实与权限）；
2. `loyalty`／`corruption` **数值不得出现**在 `minister_lens` 输出里（沿用既有"只给档位词"的纪律）；
3. `focus`／`sections` 由**可解释规则**派生（职责关键词＋标签），**不含**推荐与优先级；
4. 越权读：`viewer` 身份决定 `fiscal_context`（D11 逐格），**官职更高不放宽**。

## 3 · 提案契约（Proposal Contract，**不执行**）

**目标**：统一"大臣为什么这么想"，让皇帝能据此裁决。**仅承载表达**，实际执行仍走上位通道。

```python
proposal = {
  "id": "pr…",                    # 由 enqueue_ai_action 生成（复用其 id）
  "proposer": "李纲",              # 大臣名（既有字段）
  "role": "兵部尚书",              # 呈报时职衔（快照，便于回溯）
  "kind": "inspect_dispatch",      # **动作种类**（与既有 kind 同名；执行仍走诏令载荷/批红）
  "action": {"route": "河北路", "kind": "查赋", "secret": False},   # **行动参数**（既有载荷结构）
  "rationale": "…",                # 理由（≤200 字）
  "evidence_refs": ["discovery.suspicions[0]", "fiscal_context.totals"],
                                   # **事实依据＝读数键引用**（可核对；不得写未公开数据）
  "risks": ["若粮价继续上涨，转输不继"],   # 自陈风险（定性）
  "authorization": "需诏令授权",     # 所需授权：`直接执行`／`需批红`／`需诏令`／`需召对确认`
  "expected": "…",                 # 预期（定性，不得写承诺数值）
  "status": "pending",             # 见 §4 状态机
  "feedback": None,                # 见 §5
}
```

**与既有通道的映射（零新增执行入口）**
- 落地载体＝`state.enqueue_ai_action(kind, title, summary, payload, proposer)`：
  `payload` 携带 `action`；**新增字段一律放 `payload.proposal`**（`rationale/evidence_refs/risks/authorization/expected`），
  **不改**函数签名与既有调用方（旧呈请 `payload` 缺 `proposal` 键时行为不变）；
- 执行：批红（`approve_ai_action`）→ `_apply_inspect_request` → **既有单点**
  （或诏令载荷 `inspect_*`／`audit_route`）；
- **禁止**：提案里出现"请务必准奏"式强制语、出现未公开真账、出现承诺数值。

## 4 · 批红状态机（**状态转换 ≠ 世界变更**）

```
                 ┌──────────── reject ──────────► rejected（终态）
                 │
 pending ────────┼──────────── approve ─────────► approved ──► 执行单点 ──► executed / failed
   （待批）        │                                   │
                 ├──────────── return（退回补充）─► returned ──(重提)──► pending(新 id, parent=旧 id)
                 │
                 └──────────── defer（暂缓）─────► deferred ──(可再批)──► pending / rejected
```

| 转移 | 触发者 | 世界状态变更 | 备注 |
|---|---|---|---|
| `pending → approved` | 皇帝批红 | **是**（仅经既有执行单点） | 只有此路进执行链 |
| `pending → rejected` | 皇帝 | **否** | 终态 |
| `pending → returned`（退回补充） | 皇帝 | **否** | 可**重提**（新 `id`，`parent_id` 指向旧件） |
| `pending → deferred`（暂缓） | 皇帝 | **否** | 保留在册；以后可再批/驳回 |
| `approved → executed` | 执行单点成功 | **是** | 记 `executed_at` |
| `approved → failed` | 执行单点拒绝/异常 | **否** | **不得**标记为成功批准并已完成；必须带 `reason` |

**四条硬约束（契约测试钉住）**
1. 只有 `approved` 能触发执行；`rejected/returned/deferred` **绝不**触碰任何世界状态；
2. **重复批准**幂等：`approved/executed` 条目再次批红 ⇒ 拒绝且**不**重复执行；
3. **执行失败 ≠ 批准完成**：`failed` 必须留 `reason`，且不得写 `executed_at`；
4. **退回补充**允许修改**参数**（`action`）与理由，但**不得**借重提绕过权限/名额校验（重提仍走完整校验）。

## 5 · 执行反馈契约（**反馈不得自动触发新行动**）

```python
feedback = {
  "proposal_id": "pr…",
  "outcome": "executed" | "failed",
  "task_id": "ins990-3-1",          # 若产生了差遣
  "reason": "无可用差遣名额：…",      # 失败原因（直接引执行单点的 reason）
  "world_refs": ["inspection.tasks[0]", "inspection.suspicion_pending"],
  "period": "990-3",
}
```

- 反馈**只写提案容器**（`ai_pending_actions[*].feedback`）与（如有）任务容器**既有字段**；
- 反馈是**事实**：可被下次 `minister_lens` 读到，供大臣复述"上次所请未果，原因何在"；
- **禁止**：因反馈自动再生成提案、自动重试、自动升级手段（避免"自动行动链"）。

## 6 · 权限继承（**人格化不升权**）

| 身份 | 可见 | 备注 |
|---|---|---|
| `player`（皇帝） | 账面＋可裁决一切提案 | 批红权唯一 |
| 大臣（按 `viewer` 身份） | `official` 级事实（账面）＋**其职责相关分区** | `minister_lens` 只重排；`loyalty/corruption` 数值不可见 |
| `inspector`（察访执行者） | 密查或 `oversight ≥ 门限` 时可见真账 | 既有 D11 |
| `ai`／`system` | 全知（引擎内部） | **不**等价于"每个大臣都全知" |

> **越权读取**（如兵部尚书读户部真账、无察访身份者读真账）必须在 `viewer` 过滤层被拒，并留可审计痕迹。

## 7 · 回归与守卫（实现阶段的验收清单）

| # | 测试 | 断言 |
|---|---|---|
| 1 | **视图权限** | `minister_lens(name).facts` ≡ `ai_decision_view(viewer=该大臣身份)`；越权读取不出现真账字段 |
| 2 | **无特权** | 换人格/换官职 ⇒ 事实集合与权限**不变**（只变分区顺序与 focus） |
| 3 | **数值不外泄** | `loyalty`／`corruption` 数值不出现在任何视图/提案/提示词文本中 |
| 4 | **唯一桥接／唯一成案** | 提案与反馈路径**不含** `record_report_suspicion` 以外的新桥接，`audit_route` 仍是唯一成案载荷 |
| 5 | **财政隔离** | 走完"提案→驳回/退回/暂缓/批准"全流程的对照局**逐位一致**（差异只在提案容器） |
| 6 | **状态机** | 驳回/退回/暂缓**零世界变更**；重复批准幂等；失败带 reason 且不写 `executed_at` |
| 7 | **UI 兼容** | `briefing.build_briefing_actions` 行为不变；既有 `enqueue_ai_action` 旧调用方行为不变 |
| 8 | 回归／校准门 | `--junitxml` ＋ 进程退出 ＋ 标记普查一致；校准门逐位一致 |

## 8 · 明确不做（M36.6-A）

❌ 新增执行入口（一律复用诏令载荷／批红）　❌ 因人格/官职放宽权限　❌ 自动生成提案或自动重试
❌ 改变 `ai_decision_view` 的事实权限　❌ 扩大监察能力（发现权/怀疑权/移送权留 M37）
❌ 让监察直接成案或绕过既有司法桥接　❌ 暴露 `loyalty/corruption` 数值／真账给无权限者

## 9 · 待裁 → **已裁**（2026-10-11 用户裁定；详见 M36.7-A 台账 §15）

| 编号 | 问题 | **裁决** |
|---|---|---|
| **P1** | 退回补充的**重提上限** | **不设固定上限**：每次重提＝新 `id` ＋ `parent_id` 关联，**重跑完整校验**；不得因曾被退回跳过校验 |
| **P2** | 暂缓（deferred）的**期限语义** | **不自动过期**：持续保留，**不因月度轮转**自动改状态；是否恢复/驳回由明确后续动作决定 |
| **P3** | 反馈是否注入**下次提示词** | **不自动注入**：反馈可在 UI 与授权事实视图查看，**不自动**拼入下一轮提示词、**不自动**触发重提/升级；历史保留、可检索、可审计（是否用于后续判断须另有显式、可审计机制） |
