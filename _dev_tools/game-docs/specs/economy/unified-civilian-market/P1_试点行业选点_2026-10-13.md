## 二、🔴 选点：**绸（丝 → 绸）**

理由（逐条对应规格的支撑度要求）：
1. **链条完整**：`丝坊`（20 座/开局 7 座在本轮 6 月内建）· 配方 `{丝:10000} → 绸:8000` · 原料与成品**都真有货**；
2. **需求侧有据**：`绸` 有 `durable` 通道（`DURABLE_TARGET_STOCK["绸"] = 1.0/人`）⇒ 需求**可算**（M74 已接）；
3. **可达性**：`transport` 原语齐（P0 5/5 门）；但**在途批次现为 0** ⇒ 纵向切片**先在路内**做，跨路留 P4；
4. **财政接口**：`绸` 属 `FINISHED_TAX_DIMS` 系列（成品税）；工钱/利润侧仍缺（见 §四）；
5. **可观察**：`readout_hub` + 治所级影子（M53/M74）已能给出"产地→成交→到货→加工"各段。

## 三、切片设计（**先路内、后跨路**）

**对象**：一条链 —— `丝（原料，本路治所真账）→ 丝坊（作坊实例，owner=本路商人 M66）→ 绸（成品）→ 本治所买家（`durable` 缺口）→ 钱（买家 wealth → 卖家）`。

**口径**
1. **原料**：取本路治所真账（`pop_goods`/`material_holding` 单点）；**不得**按人口比例分派（台账 §三-1 已由 M47 修正）；
2. **加工**：作坊 `recipe` × 在岗（M78 已可算**实到**——纯函数 `allocate_employment_detail`）× 等级；
3. **成品**：按作坊**所属路**归属（M47）；
4. **成交**：走既有唯一入口 `market.trade_goods`（**不另写撮合器**——台账 §四 明示）；
5. **需求**：`max(基本需求×余量释放, 耐用品缺口)`（M74 口径）；
6. **税**：成品税按**逐笔成交记录**（**无记录不计税**，P4 同口径）；
7. **缺字段 ⇒ `undefined`**（不用默认值补齐）。

**验收断言（写死）**
- [ ] 丝→绸 的**物料守恒**（投入丝 × 产出率 ± 尾差可解释，尾差归末位作坊）
- [ ] 绸只按**作坊所属路**归属（**不得按人口比例分派**）
- [ ] 成交必过 `trade_goods`（幂等/三重上限由既有实现保证）
- [ ] 需求侧走 `max(基本, 耐用品缺口)`；无通道维 ⇒ `undefined`
- [ ] 缺记录 ⇒ 税为 **0**（不是 `None`）；不可读 ⇒ `None`（**缺失≠0**）

**非目标**：跨路运输与运价（P4）· 工钱/利润（D 线，须先定营运资金来源）· 建筑实例 schema（P2）。

## 四·补：切片第一片**已落地**（M80，只读读数）＋ 实测经济发现

模块 `core/domains/economy/p1_pilot_chain.py`（Jev 甲 0.985）：逐路报「原料（治所真账 Σ丝）→ 作坊
（座数/active/owner/recipe/yield）→ 理论上限（Σyield/轮，**上限非承诺**）→ 成品（Σ绸）→ 需求（M74 口径）
→ 缺口（夹 0）」；**缺失 ⇒ `None`**；**只读、零数值变化**。

⚠️ **作坊"在岗"如实 `undefined`**：作坊**不在 `state.buildings`** 里 ⇒ M78 的建筑岗位实到**覆盖不到作坊**；
M67 亦实测**作坊岗位数无权威来源** ⇒ 不按人口均分、不默认满员（`jobs_reason` 里写明）。

**🔴 实测（6 个月，同种子 20261013）**：
```
7 路共 7 座丝坊（全 active）· 成品 11,230 · 需求 1,861,770 · 缺口 1,850,540
京畿路：原料（丝）426,260 · 1 座坊 · 上限 8,000/轮 · 成品 1,609 · 需求 341,141 · 缺口 339,532
```
⇒ **绸的成品供给仅为需求的 0.6%**：丝坊**数量太少**（20 路只有 7 座）且单轮产出（8,000）远低于需求。
这是 P1 试点给出的**第一条可操作经济结论**（"缺的不是钱、是产能与作坊数量"）。
