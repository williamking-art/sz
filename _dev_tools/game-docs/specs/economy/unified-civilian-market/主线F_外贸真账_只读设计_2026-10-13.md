# 主线 F 外贸**逐笔真账**：只读设计（2026-10-13 · M141）

> 前置：M139 取证（常量齐备 · **无对外入口** · **无逐笔容器**）· M140 第 18 项读数
> `trade_line_status=4`（已把"素材就绪度 + 真账缺口"变成可下钻读数）。
> 🔴 本件**只出设计**：不写 state、不改结算、不建容器。**三条口径待你裁定**（见 §4）。

## 1. 目标（要能回答的四个问句）

「**哪一路**、**哪一货**、**跟谁**、**多少**（数量/价格/运费/税费）」，且**钱与货双守恒**。
对应 P5 验收问句链的「谁本来应供」与「结果影响了谁」。

## 2. 硬约束（不得违反）

| 约束 | 含义 |
|---|---|
| §3-1 **禁与 POP 平行的账本** | **存量**（钱/货）只能落 POP `wealth`/`goods`、国库/内帑、`resources`；**不得**新建"外贸库存" |
| §3-2 口径单点 | 费率/税率/地形距离乘数**已在 `trade_shadow`**（`LOGISTICS_FEE`/`SEA_FREIGHT`/`OVER_TAX_SHARE`/`STAY_TAX_SHARE`/`DISTANCE_BAND`/`TERRAIN_MULT`）⇒ **不得复制** |
| §3-3 缺失≠0 | 无该路数据 ⇒ `None` + reason（例如未通水路的路不报 0，报"未通"） |
| 钱守恒 | 任何一笔：出口方钱↑ ⇒ 进口方钱↓（同额）；运费/税费**各有归属**，不得蒸发 |

## 3. 载体候选（**待裁**）

| 候选 | 做法 | 是否新增账本 | 优点 | 风险 |
|---|---|---|---|---|
| **甲（推荐）** | **只记流水**：新增 `state.trade_journal`（**append-only 逐笔事件**：路/政权/商品/量/价/运费/税费/去向）＋存量仍落既有载体 | 否（**流水不是账本**：不含余额、不可被当存量查询；与既有"转账日志"同级） | 四问全可答；**存量仍在 POP/国库** ⇒ 不碰 §3-1；便于审计与回放 | 需定义事件 schema 与容量上限（长局膨胀） |
| 乙 | 新增 `state.trade_legs`（**带余额/在途的容器**） | **是**（若含余额即在造平行账本） | 查询快 | **违反 §3-1（除非只放"在途"且明证非存量）** |
| 丙 | 不建容器：只把影子函数结果做成读数（现状 = M140） | 否 | 零风险 | **无法回答四问**（只能报素材就绪度） |

**我的建议：甲**——"**流水可留、余额不新造**"。若你更保守，可先走**丙 + 逐笔只读采样**（不落 state）。

## 4. **三条口径待你裁定**（本设计的核心问题）

1. **账本载体**：甲（只记流水）/ 乙（含在途容器）/ 丙（不建，仅读数）——见 §3。
2. **过税 vs 住税**：`OVER_TAX_SHARE`/`STAY_TAX_SHARE` 已有，但"**谁收、入哪个账户**"未定：
   - 候选：过税 ⇒ **沿途路级地方府库**；住税 ⇒ **交易发生地治所所在路**；两者皆入 `local_treasury_bridge`。
   - 影响：地方府库收入结构（是 D 线营运资金的潜在来源之一，与 M122 的"营运资金来源"**相互影响**）。
3. **与 `statistics` 的关系**：外贸税费是否计入既有 `statistics`（月报/财政口径）？
   - 候选：① 计入（与既有税目同表，需防**双重计数**——本会话已修过一次同类缺陷 M74）；
   - ② 单列（新表项，前端另栏显示）；③ 暂不计入（只做流水，待口径）。

## 5. 验收断言（实施时写死）

- [ ] **双守恒**：`Σ货`（出口减 + 进口增）与 `M_ALL`（钱只在账户间转移）逐笔可对账
- [ ] **运费/税费归属明确**：每笔的运费与两税都有**明确收款方**，不得"消失"
- [ ] **不新增平行账本**：`trade_journal` 内**无余额字段**（用断言锁定：不得出现 `balance`/`stock` 语义键）
- [ ] **口径单点**：费率/税率一律取自 `trade_shadow` 常量，**不得**在结算里重写数字
- [ ] **缺失≠0**：未通水路/无该政权 ⇒ `None` + reason
- [ ] **同种子 A/B**：接线 vs 不接线逐月对账（**接线必然改数值** ⇒ 须标定 + ≥60 月长局 + 全量回归）

## 6. 回滚

只需清空 `trade_journal` 与接线开关（存量从未被本设计改动 ⇒ 回滚不动钱货）。

## 7. 数值影响量化（M142，**只读**，用既有纯函数实算）

> 目的：把 §4 的三条口径**从"原则之争"变成"量级判断"**。以下全部经 `trade_shadow` 既有纯函数实算，
> **未改任何 state**。基准：**货值 10,000 贯 · 税率 5%**。

| 项 | 实算结果 | 含义 |
|---|---|---|
| **两税份额** | `tax_split(0.05)` ⇒ 过税 **0.02** / 住税 **0.03**（**40 : 60**） | §4-② 归属：一笔税里**六成是住税**（交易地），四成是过税（沿途） |
| **税额** | `tax_cost(10000, 0.05)` ＝ **500 贯** | 每万货值贡献 500 贯税；若入地方府库，是**百贯量级** |
| **陆运运费** | `land_freight(10000, band)`：`intra`→**0** · `d300`→**2** · `d1000`→**3** · `d3000`→**6** · `far`→**10** | 陆运**极小**（个位数贯/万）；⚠️ 且 `band` 必须用 `LOGISTICS_FEE` 的**键**（`intra`/`d300`/…），传中文档位会返回 **`None`**（正是"缺失≠0"的体现） |
| **海/水运运费** | `sea_freight(10000)` ＝ `{fee: 50.8, loss_qty: 500}`（`storm=True` ⇒ 76.2 / 750） | **固定 50 贯主导**（`SEA_FREIGHT.fixed`）＋ 5% 货损 ⇒ 海运成本量级**远高于陆运** |
| **净利自洽** | `trade_net(12000, 10000, 1000, 0.05)` ⇒ `net=500`，`total=11500` | 毛 2,000 − 运费 1,000 − 税 500 ＝ **500** ✅ 公式自洽（可直接用于核算） |
| **水路覆盖** | `ROUTE_WATERWAY`：强 **7** 路 · 有 **11** 路 · 弱 **3** 路（共 **21** 条） | ⚠️ 与"20 路"口径**存在 1 条差**（含 `黔中路`）⇒ **列为待核点**，不擅自改 |

### 由量级导出的**建议**（仍待你确认）

1. **载体（§4-①）**：**甲**（只记流水、余额不动）——与数值无关，且不触 §3-1。
2. **税费归属（§4-②）**：**过税 ⇒ 沿途路级地方府库（40%）· 住税 ⇒ 交易地所在路（60%）**；
   ⚠️ **但不要指望它解决营运资金**：单笔税仅**百贯量级**，而 D 线采购需求是 **28,400,000 贯**
   ⇒ **外贸税源相对于营运资金缺口是杯水车薪**。这从量级上**支持 M122「先甲（士绅）」**的判断。
3. **`statistics`（§4-③）**：建议 **②单列**——税目表若混入，极易与既有税目**双重计数**
   （本会话已修过同类缺陷 M74：`basic_need` 双重乘 `size`）。

### 待核点（M142 提出 → **M143 收敛到确证**，仍**不擅改**）

- `ROUTE_WATERWAY` **21** 条 vs 游戏 **20 路**：**M143 实测** —— `游戏路数 = 20` ·
  `ROUTE_WATERWAY 覆盖 = 21` · **表中多出＝`黔中路`（唯一）** · **游戏路中缺＝空**（20 路**全部**被覆盖）。
  ⇒ 该键是**多余的陈旧键**（历史路名）。**当前无害**：`trade_shadow` 只按**路名查找**该表（不遍历），
  多余键不会被产出。处置（按「不臆断」）：
  - **不删**（删除属"改数据"，须先有口径与定向回归）；
  - **列为待裁**：①保留并加注释说明来源 ②删除 ③改名对齐现存 20 路；
  - 🔴 **实施主线 F 真账时必须先处理**：若有代码**遍历**该表（如"按水路档位逐路结算"），
    多余键会**凭空多出一条路** ⇒ 届时须断言「**遍历集合 == `state.prefectures`**」。


## 8. 载体甲：字段级 schema + 两条守卫（M144，只读设计）

> 目的：把 §3「甲」从一句判断变成**可直接实施**的规格。**本件仍不改 state。**

### 8.1 `state.trade_journal`（**append-only 事件流，无余额**）

| 字段 | 类型 | 说明 | 缺省 |
|---|---|---|---|
| `month` | int | 绝对月序（与 `built_month` 同量纲：`year×12+month`） | 必填 |
| `route` | str | **我方路名**（必须在 `state.prefectures` 内） | 必填 |
| `seat` | str \| None | 治所（能定位则填；不能 ⇒ `None` + `reason`） | 可缺 |
| `partner` | str | 对方政权名（取自 `REGIME_IMPORTS` 的键） | 必填 |
| `dim` | str | 商品维（**必须**经 `commodity_dims` 判定合法） | 必填 |
| `qty` | int | 数量（>0） | 必填 |
| `unit_price` | float | 单价（贯/单位） | 必填 |
| `goods_value` | int | 货值＝`round(qty × unit_price)`（**冗余但可校验**） | 必填 |
| `freight` | int | 运费（陆运 `land_freight` / 海 `sea_freight.fee`，**口径单点**） | 必填 |
| `tax_over` | int | 过税（= `tax_split(rate)["over"] × goods_value`） | 必填 |
| `tax_stay` | int | 住税（= `tax_split(rate)["stay"] × goods_value`） | 必填 |
| `tax_to` | str | 两税接收方（甲口径：**路级地方府库**，走 `local_treasury_bridge`） | 必填 |
| `freight_to` | str | 运费接收方（船户/脚夫对应的既有载体） | 必填 |
| `direction` | str | `export` \| `import`（**枚举**） | 必填 |
| `reason` | str \| None | 任何字段不可读时的**原因**（缺失≠0） | 可缺 |

🔴 **禁止字段（守卫会断言）**：`balance` / `stock` / `inventory` / `on_hand` / `holdings`
——出现任一即视为**在造平行账本**，直接失败。

### 8.2 两条守卫（实施时写成用例）

```python
# 守卫 1：容器不是账本
BANNED = {"balance", "stock", "inventory", "on_hand", "holdings"}
for leg in state.trade_journal:
    assert not (BANNED & set(leg)), leg          # 无余额语义 ⇒ 不是平行账本

# 守卫 2：遍历集合必须等于游戏路集合（防 ROUTE_WATERWAY 的 `黔中路` 幽灵路）
assert set(r for r in iter_trade_routes(state)) == set(state.prefectures)
```

### 8.3 保存/读取与容量

- **随存档持久化**（`save_load` 既有字段白名单需登记 `trade_journal`）；
- **容量**：长局会膨胀 ⇒ 约定**只保留最近 N 个月**（N 待裁，建议 24），**更早的滚动汇总进
  `statistics`**（§4-③ 单列），这是"流水不删、但有界"的折中；
- 读档时**不校验历史**（老档无该字段 ⇒ 空列表，**不拒档**、不臆造历史）。

### 8.4 与 §4 三条口径的对应

| 口径 | 本 schema 的落点 |
|---|---|
| ①载体 | `state.trade_journal`（**无余额**，见 §8.1 禁止字段 + §8.2 守卫 1） |
| ②税费归属 | `tax_to`（过税⇒沿途路级地方府库 · 住税⇒交易地所在路；均走 `local_treasury_bridge`） |
| ③`statistics` | 只把**滚动汇总**写入（单列），**逐笔流水不进税目表** ⇒ 防双重计数（M74 前例） |
