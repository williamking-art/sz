- `state.resources` 有 **71 处引用、横跨 8+ 模块**，是**全国口径**——任何"本地市场"都不得复用它冒充；
- `POP_BUILDING_VALUE` 是**标量**（全库一个值），维护费对所有建筑一视同仁。

**已知必须面对的结构缺口**（设计文档原文，实施前逐条复核）：

| # | 缺口 | 出处 |
|---|---|---|
| 1 | 宋境 `prefectures` 仍是**路级**经济容器；目标是州府级。**没有可靠初始数据的 POP/建筑/库存不能按面积或人口比例伪拆成"真实州府值"** | 统一设计 §4.2、§14.1 |
| 2 | 宋侧建筑等级/岗位、政府项目、全局 `state.workshops` 配方产出**并非统一实体**；全局作坊产出与逐路工匠库存之间存在**分派路径**（疑似按人口比例） | 统一设计 §8.4、§14.1 |
| 3 | ~~**B4-1 建材市场"已实现未接线"**~~ ✅ **已解除**（2026-10-02 裁决 C/C-c/E-1 并接线，存量落商人 POP `goods`）。⚠️ 初衷继续适用：**不得另造"工程专用免费货源"**，缺料即 `material_short` | market-civilian-economy §9、§14.1 |

## 2 · P0 市场契约与空间可达性

**《落地建议》§14.2 要点**（原文口径，勿改）：
- 先定义**州府市场的数据契约**，**不先铺商品目录**。最少确定：稳定 `market_id`/`location_id`、商品、买卖主体、用途、库存持有人、成交价/估价、预算、月份、交通边、税费、在途状态、**缺失原因**和**来源 ID**。
- 市场库存是底层 POP/经营主体/仓储库存的**派生可售视图**；**视图不得再持有同一批商品**。
- 市场范围由**地域 ID、政权/关税制度、实际控制、交通连通和容量**共同决定。**邻接 ≠ 可达**，**全国总库存 ≠ 本地供给**。
- 交通边先只表达**承载力、成本、时滞、季节/风险、通行条件**。市场圈可从此派生；**市场圈改变只改变可交易集合，不搬迁或复制实体库存**。
- 价格至少区分**基准价 / 有效报价 / 实际成交价 / 官定或合同价**。**未定义价格不可静默回落到 0 或 1**；同月报价/成交窗口与价格更新时点须统一。
- 月度撮合读**冻结的意向快照**：先形成订单，再按已批准优先级**清算一次**；清算成交**不在本月变成新需求**、再采购并无限循环。

**本规格补充的落地要点**：
1. **以路级兼容实现空间契约**（§14.3 允许）：`location_id` 现阶段＝路键，但字段语义留出州府迁移空间；
   **不得**把路级数据贴上"州府级"标签（§14.2 验收门 + §14 验收断言"当前路级模拟不得以州府级输入标签呈现"）。
2. **交通边**先建**最小可验证集**（相邻可达 + 漕运线），能表达"断路⇒目的地不可消费"即可；
   不做全图任意互通（§14.6 明确"先不做所有路线任意互通"）。
3. **在途批次**是本阶段的核心新实体：`{来源, 目的地, 商品, 数量, 发出月, 预计到达月, 运价, 运力占用, 风险/损耗, 状态}`。
   在途货**既不在来源可售、也不在目的可售**。
4. **价格四态**与既有的 `core/market_price.py` 对齐（该模块已有基准价/动态价分离，勿另造）。

**验收门**（§14.2 原文，逐条须有定向回归）：
- [ ] 两个相邻州府有路可达时可以调货
- [ ] 断路 / 运力耗尽时，目的地**不能消费未到货库存**
- [ ] 同一货物**只有一个持有人**
- [ ] **移除市场聚合视图不改变底层账**
- [ ] **只冲击一地不会无因同步改全图价格**

## 3 · P1 地方经济纵向切片

**《落地建议》§14.3 要点**：选一个**有可信位置、需求、投入和现有机制支撑**的试点。
**首轮若无法获得可靠州府拆分依据，应明确以路级兼容切片验因果，另立州府迁移门**，
不能把路级数据贴州府标签。

**切片因果链**（原文）：
```text
POP 生计/持钱
→ 一种基础需求和有限替代
→ 当地真实库存成交与价格记录
→ 一个本地生产者/经营记录及投入约束
→ 工资或经营收益回到既有 POP/政府账户
→ 下一月需求、供给或 Agent 意图响应
```

**落地要点**：
- 优先选**现有配置和稳定数据能支撑**的农副 / 纺织 / 窑业；**不预先指定历史上未核实的产能**。
- 每件商品在「自用 / 待售 / 储藏 / 在制 / 项目预留 / 在途」间转移时**只做状态/所有者变更，不重复建货**。
- 允许先用**轻量经营记录**过渡，但字段须能迁移到 P2 的经营主体 schema。

**验收门**（§14.3 原文）：
- [ ] 能**逐月复原**货币和商品库存恒等式
- [ ] 缺钱 / 缺货 / 缺岗位 / 缺料 / 缺运力**分别可见**
- [ ] 贫困人口有需求但买不起时**不伪造成交**
- [ ] 有库存和购买力时可成交
- [ ] 生产者/卖方获得的收入**有来源**，后续消费可由收入变化驱动

## 4 · P2 建筑资产与经营主体并轨

**《落地建议》§14.4 要点**：沿用现有项目、蓝图、`prefectures[*].buildings` 和岗位计算，
**不另外创建平行建筑账本**。分清 **建筑资产 / 经营者 / 生产方法 / 雇佣岗位 / 库存与订单**：
- 建筑提供**空间/设备/耐久/容量**；
- 经营者决定**资金、原料、工艺、销售和盈亏**。
- 首期可将经营记录**嵌在建筑实例中**，但 schema 要能将经营主体**独立出来**。

**每个试点建筑/经营记录须能确定**：蓝图版本、稳定地点、等级和完工/可运营月份、所有者、
经营者/管理 Agent、维护责任、经营方式（家庭兼业/民营雇工/官营/官有承包）、可选生产方法、
岗位容量/**实到**、配方、投入/产出库存、收入去向。**缺字段标未定义，不能用默认全员就业或默认满产补齐**。

**月结因果**（原文）：
```text
可用建筑与技术
→ 经营 Agent/主体提出开工、停工、转产或采购意向
→ 程序检查资金、原料、岗位/技能、设备、维护、法规和订单
→ 扣投入并产出到本地经营库存
→ 销售/服务履约
→ 收入按产权/合同转给雇工 POP、经营者 POP、政府账户与税收
→ 经营者下月决定工资、留存、维修、扩建或退出
```

**落地要点**：
- 生产方法切换须有**培训/改造成本或延迟**，不免费瞬切。
- 官府拥有 / 官府经营 / 官有承包 / 民有民营 / 公共设施**分别建模**；
  公共道路/水利产生**网络或服务能力，不自动产出普通商品**。
- 新建筑完工**当月还是次月生效须统一规定**（现状见 §1 台账）。
- **经营资本如需留存，所有权必须继续归属 POP 或政府账户**；
  **不要增加脱离 `M_ALL` 的影子钱池**。
- 家庭/未就业人口仍可通过农业生计、家庭生产或季节性活动参与经济，
  **避免"没专门建筑就无收入/无供给"**。

**验收门**（§14.4 原文）：
- [ ] 建筑不因等级存在**自动满产**
- [ ] 缺任一必要投入/工资/许可时按规则**降产或停产**
- [ ] 产出**先入本地经营库存**
- [ ] 成品卖出后**收入正确归属**
- [ ] 将建筑设为**停业不会继续产出**
- [ ] 官营和民营使用**同一物理成交接口但钱货去向不同**

## 5 · P3 官府旨意、Agent 与经济动作接线

**《落地建议》§14.5 要点**：复用已有 `decree-action-chain` 与 B5 Agent 能力，**不重写命令 schema**。
新增市场/建筑行动时，**扩展既有注册行动/效果构件**：修路、港口扩容、官仓目标库存、
某货官买优先、许可调整、支持某行业、官府采购、保护商路。

- 玩家旨意明确**目标/授权范围/主办官员/可用预算与仓料/期限/公开或保密/传达方式**；
  **AI 不可替玩家加拨款、征用权或强制调兵**。
- 相关官员以各自身份接收**权限内**信息，出现**领旨/异议/请款/争办/拖延/改办/执行**等**可区分**响应；
  **财政/经济分析是奏报，不代替户部或主事官员作决定**。
- **没有生产 handler** 的新蓝图/制度/行业命令维持「待支持/待补蓝图/待裁决」，**不能只增加事务进度**。
- 程序月结落实**资金/货物/采购/运输/建造/效果**；Agent 产生**行为策略和叙事理由，不直接写结算数值**。
- 执行回执分别写入**主办、协办、反对者**的记忆；次月推演基于**已发生结果**调整策略，
  **不让 AI 读到尚未批准的闲聊就改状态**。

**验收门**（§14.5 原文）：
- [ ] 同一旨意在两名不同官员承办时可以产生**有依据的路径差异**
- [ ] **未授权人员看不到密旨**
- [ ] 拒绝/受阻原因能追到**权限、资源或关系**
- [ ] 玩家能从命令**回看**资金/商品/建筑/POP 后果
- [ ] **重试不重复执行**

## 6 · P4 府际、边境与远方市场

**《落地建议》§14.6 要点**：按**成本和历史不确定性逐步扩图**，不直接搭"全世界一个市场"。

| 序 | 层 | 要点 |
|---|---|---|
| 1 | **府际市场** | 先把可复原的州府邻接/漕运路线接入，有**在途批次、运价、到达月、运力、损耗、截断原因**；**先不做所有路线任意互通** |
| 2 | **边境与政权市场** | 接辽/西夏/大理等**当前直接接触**的市场与关卡/互市条件；库存**继续属于其地域账本**，易主**改制度归属、不搬空库存** |
| 3 | **中亚陆路需求** | 有限预算、有限需求篮子、多段陆路表示河西—绿洲—中亚转运；**政治控制和风险可让路线中断** |
| 4 | **印度洋—西亚转口与欧洲终端需求** | 首期只用**转口商圈 + 滞后终端需求信号**；宋境只在本地可接触节点卖给**具体买方**；**欧洲需求不能直接成为宋境买家，也不能即时改写宋境价格** |

**共同要求**：每段路线都需**有限预算/库存/运力、时滞、交易成本、税费、风险**；
**转售货物需先到货并进入中间商库存**；商人 Agent 可按预期利润扩张/收缩/改道，
但程序在**月初意向快照 + 当月约束**下确定成交；
价差**只在扣除运费、税费、资金占用与风险后**才可能形成套利；
**没有实际贸易记录不得计市舶税或外销收入**。

**验收门**（§14.6 原文）：
- [ ] 关路后贸易量、价格/采购意向和财政税基**按逻辑逐月变化**
- [ ] **无预算或运力时不成交**
- [ ] **在途货未到不能使用**
- [ ] 沿途转售**不重复计收入**
- [ ] 终端欧洲需求通过**转口滞后传递**而非瞬时买空宋境商品

## 7 · P5 玩家界面与月度推演报告

**《落地建议》§14.7 要点**：采用可追原因的信息层级，**新增读数从后端权威派生，

|---|---|

| **商品详情** | 期初/产出/输入/成交/消费/损耗/期末库存、**需求未满足原因**、本地可达供应、价格历史、主要交易双方 |

| **通知分层** | 重大缺粮/断路/工程受阻默认提示；一般价格变化汇入市场报告，**减少每月弹窗噪声** |

- [ ] 每个显著读数**能下钻到来源**
- [ ] **读数缺失不显示为 0**
- [ ] 一个用户能回答"哪里短缺、为何未运到、谁本来应供、旨意为何未办成、结果影响了谁"
