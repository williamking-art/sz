## 0 · 一句话

`local_treasury`（州郡府库）**只有"进"和"买粮"，没有"花"**——留州只完成了"分层"（P1 三分），
没有完成"支用"：行政/治安/水利/救灾/仓廪**五条消费性出口一条都没接**。V2 就是把出口接上，
且**不新造账本**（写口＝既有的 `transfer_money("local:<路>", "pop:<路>:<阶层>")`）。

- 即：**"只进不出"应精确表述为「只进 ＋ 只买资产（粮），无消费性支用」**。

## 2 · 可复用的唯一范式（守恒三律 · 禁止另造）

**范式 A · 结算期支出（`_settle_upkeep`，`core/domains/administration/settlement_officialdom.py:87`）**
```
due  = 资产折算 × 费率                # 派生（单点公式）
paid = min(due, 支付能力)             # 不穿底
缺口 → statistics["upkeep_arrears"]   # 欠费科目（与「欠饷」「欠税」同构）
change_treasury(-paid)                # 出账
distribute_cash(state, paid, 表)       # 全额给民间 POP（精确守恒，尾差兜底退回国库）
```
**范式 B · 逐路划转（`GameState.transfer_money`，`game_state.py:1139`）**
```
state.transfer_money(f"local:{路}", f"pop:{路}:{阶层}", amt)   # 按 src 可付截断，返回实转额
```
- 账户语法**已支持** `local:<路>`（`game_state.py:1165-1195` 读写＋`_writable` 校验）与 `pop:<路>:<阶层>`；
- `money.ACCOUNTS` 的 `local_treasury_total()` **已聚合**（不双计）；
- ⇒ **V2 的写口零新增**：`transfer_money` 即单点；**禁止**任何模块直写 `pref["local_treasury"]`。

**范式 C · 逐路成对（`_changping_trade`）**：钱腿＝本路府库，粮腿＝本路民间 POP，ΣΔ==0。

## 9 · 裁决记录（2026-10-11 用户裁定）＋ 批次 1 落地（**财政顺序改造**）

### 9.1 裁决原文要点

> **问题不是「留州太少」，而是「财政顺序反了」**：宋代更像「**地方先养活行政，再上供中央**」，
> 而不是「中央拿走以后地方自己想办法」。
>
> - ❌ 不建议把留州从 5% 直接提到 20% 以上（会破坏中央财政）；
> - ✅ 保留留州概念；✅ **增加地方必要支出扣除层**；✅ 把胥吏、公用、行政成本从"新增支出"
>   改为"**地方财政责任**"；✅ 留州初始提高到约 10% 左右**测试**；
> - ✅ **要留出接口**：玩家大概率走中央集权，但**开局先尽量符合历史**。

### 9.2 已按裁决实现的**顺序改造**（批次 1）

```
田赋折色实收 collected
  ├─（1）地方必要支出优先层：min(due_eff, 中央本应得) → 本路府库      ← 顺序改造
  └─ 剩余按四率三分：transfer → 中央（国库）／keep → 府库／div → 官僚
地方府库 → 地方经费支出腿（`_settle_local_expenditure`）→ 本路民间 POP
```

- **`local_expense_mult`（地方经费保障倍数）**：开局 **1.0 ＝ 史实口径**；接口＝
  `finance_rates` 诏令效果 / `apply_finance_reform`（不参与四率归一化，独立钳制 [0.0, 1.5]）；
  集权下调 → 责任收归中央、上供相应增；分权上调。旧档缺键幂等补 1.0。
- **官员有效使用**（裁决："地方政府、官员要能**有效使用**府库资金"）：
  `efficacy = clamp(1 − 0.5×吏胥把持度 − 0.3×(1−官俸实付率) − 侵渔率, 0.3, 1)`；
  现实应支 `due_eff = 责任应支 × 保障倍数 × efficacy` ⇒ **吏治/厚禄/监察改革让同一笔钱更有效**。
- **责任科目**（批 1 起，史实词表见 §11.3）：`official_salary` 官员俸禄／`clerk_pay` 胥吏雇钱／
  `runner_pay` 衙役雇钱／`public_supply` 公用钱；粮仓/救灾仍为**只读预报**
- **效果**：治安实付按 1,000 贯/点 压该路 `unrest`（"钱花出去，盗贼少了"）；水利维护实付即原
  国库 upkeep 口径（已从 `_settle_upkeep` 资产折算中**排除**）。
- **欠支科目** `statistics["local_arrears"]`（与 `upkeep_arrears`/欠饷/欠税同构）；实付累计
  `statistics["local_expense_paid"]`；读数字段 `finance_readout.local_expenditure /
  local_arrears / local_expense_paid / land_tax_required`（**均不并入 `total_out`**）。

### 9.3 「地方花钱，为什么扣国库？」——账目说明（回答用户质询）

**不是从国库额外抽钱**，而是"**责任转移**"的两条腿同时记账，净额为零：

| 腿 | 动作 | 国库 | 府库 | POP |
|---|---|---|---|---|
| ① 上供优先层 | 中央解送额 −X → 府库 +X | **−X（少收）** | +X | 0 |
| ② 支出腿 | 府库 −X → 本路 POP +X | 0 | −X | **+X** |
| ③ 中央抵减 | 国库不再重复支付该份额 | **+X（少付）** | 0 | 0 |
| 合计 | 责任从中央转到地方 | **≈0** | **≈0** | **+X−X＝0（同一批人，同一笔钱）** |

- ③ 的必要性：官俸/军饷原由国库**全国统一发放**，若地方再付一份而国库不减，即为**双重支付**
  （同一科目两次出钱）。
- **另设有口径旋钮** `LOCAL_EXP_REIMB_SHARE`：`1.0`＝责任转移（默认，中央财政中性）；
  `0.0`＝**正俸之外的地方贴补**（国库不动，官吏/兵卒多收一份，吏治受益、府库吃紧）。
  史实介于两者之间（州县官俸有中央拨给，公使钱/职田属地方自筹）。
- 守恒保证：`local_treasury` **计入 M1/`m_all`**（`money.py:180`），故"府库→民间"是货币容器内部
  转移，**不造币不销币**；实测 `ΣΔ(府库) + ΣΔ(POP) ≡ 0`（测试钉住）。

### 9.5 关于「留州提到 ~10% 测试」的实测结论（**待你复核**）

- 现口径 `transfer=0.94 / keep=0.04 / div=0.02`；归一化保护顺序为 transfer＞keep＞div，
  且 `FIN_KEEP_MAX=0.08` ⇒ **keep 想上 10% 必须同时下调 transfer（≈0.88）**；
- 该调整 = 中央每月再让 ≈68k 贯（12 月 ≈815k），而**当前中央本身 12 月末仅余 6.1 万贯**：
  顺序改造已把中央"少收—少付"对齐，故**不再有额外让利空间**；
- ⇒ 建议：**先跑本批（keep 维持 0.04＋顺序改造）**，观察 24–60 月；

### 9.8 裁决（2026-10-11 追加）：欠支分类 ＋ 地方科目池扩展（**批次 2 设计**）

> 用户要点：① 宋代的"欠"分三类——**正式官员俸禄拖欠**、**小吏/胥吏/衙役/弓手等基层人员拖欠**、

> 而应把「**胥吏雇钱**」「**衙役雇钱**」加入地方财政支出池（公用钱亦然）。

### 9.10 「与 POP 如何挂钩」——桶、写口、注册（**批次 2a 已落地**）

## 11 · POP 桶结构增强 V2（裁决 2026-10-11 · 路线图）

> 用户裁决：**POP 桶要改善，但不是现在推倒重做**；原则＝
> **不增加新的大类 POP，而是在现有六类 POP 内增加"身份层"和"收入来源层"**。
> 否则镜像/存档/粮耗/人口统计会全面爆炸（本游已有前车之鉴：`estate`/`clan`/`grain` 下沉时的三类事故）。

### 11.1 保留六桶（不动）

`农 / 士绅 / 工匠 / 商人 / 官僚 / 兵`——粮食消费、财富、人口、税收**全部绑定六类**；
新增"胥吏 POP""衙役 POP"会导致**人口重复计算、粮耗重复、财富归属混乱** ⇒ **不做**。

### 11.2 缺的是"职业经济层"（官僚桶现在承担太多）

```
官僚（现状）: officials / clerks / waiting / sinecure (只存人数) + wealth（整池）
  ⇒ 官员（俸禄/恩赏/职田；政绩/派系/廉洁）与胥吏（雇钱/公费/灰色收入；文书控制/操作税收/侵渔）
     经济行为完全不同；混在一池 ⇒ **无法回答"欠谁的钱导致谁腐败"**。
```

**V2 目标结构（子池补经济属性）**

```yaml
官僚:
  size: N
  wealth: 整池（保持现状，不新桶）
  officials: {count, wealth_share, salary_arrears}     # 官：欠俸
  clerks:    {count, wealth_share, pay_arrears}        # 吏：欠给（clerks 最敏感 → grip↑ → 侵渔）
  waiting:   {count}
  sinecure:  {count}
兵:
  standing_army  # 中央军费
  local_militia  # 地方承担
  runners        # 衙役系统（**runner_pay 不应挂普通兵**——衙役不是军人）
```

- **役人不新增桶**：役人＝**职业标签（occupation）**，即 `官僚.clerks`、`兵.runners`；
- **occupation 层留 M36+**（`POP.官僚.occupations = {official, clerk}` / `POP.兵.occupations = {soldier, runner}`）。
