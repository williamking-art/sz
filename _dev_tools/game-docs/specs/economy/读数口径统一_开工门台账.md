## 0 · 一句话

## 2 · 差异（为什么必须统一）

1. 面板"二税折色"（旧径 arrival 折扣值）与结算"应征/实收/三分"**对不上账**——玩家在会计面板看到的税入与月结流水不一致；
2. `nominal_annual_full` 的 `/arrival×12` 反推式在旧径下成立；新径下若直接替换 `tax_color` 会**放大 1/arrival（≈1.7×）**，必须同步改反推式；
3. `arrival_ratio_*` 家族的语义（"应征 ÷ 账面月额"）建立在 arrival 单率之上，而新模型已把"征收/解送"拆成两率。

---

## 3 · 方案（三选一，推荐甲＋乙新字段）

| 方案 | 内容 | 代价 |
|---|---|---|
| **甲（推荐·最小一致化）** | ① `tax_color` 改为**应征**（`calc_land_tax_channels().assessed_total`）；② `tax_color_annual = 应征×12`（**去掉 /arrival**）；③ `arrival_ratio_full` 分子改"实收合计"、分母"应征合计"（语义＝实收率）；④ `arrival_ratio_taxed/cross_scope` 保留但**改注"诊断口径·勿当到账率"** | 改 `finance_readout` 1 处＋测试 2 处（`test_zero_subject_contributes_zero` 反推式、`test_finance_readout_scope` 部分恒等式）；前端**零改动** |
| **乙（双率读数·可与甲并做）** | 新增只读字段：`assessed_total`／`collected_total`／`collection_rate_avg`／`transfer_rate_avg`／`three_way{central,local,diverted}`（取自 `statistics["land_tax_*"]`）；前端可择期展示 | 纯新增（additive），风险最低 |
| 丙（不动） | 维持两侧分叉 | 面板长期与结算不一致（不推荐） |

**`region_brief` 逐路税**：与甲同步——该路 `tax_raw` 改取 `calc_land_tax_channels()["by_route"][路]["assessed"]`（否则逐路和 ≠ 面板总额）。
