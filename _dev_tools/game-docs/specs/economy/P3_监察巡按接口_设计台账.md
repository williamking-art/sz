# P3 监察/巡按接口设计台账（M35-D 后）

> **性质**：**设计台账**（先设计，不急代码）。
> **原则（用户裁定）**：**监察改变信息，不直接改变财政**——巡按/御史的作用是"让中央看见真相"，
> 而不是"让钱变多"。本台账只定**信息层口径与接口**，不改任何钱粮结算。
> **上游**：`宋代财政流向…V1.3.md` §7（发现系统四级阶梯）／P3 已落地的 `audit_case`（保真度三档、
> 案卷、`audit_route` 勾校诏令）／`M35-C_衙役身份载体设计台账.md`／M35-D（rumor 档位化）。

---

## 0 · 一句话

M35-D 已让"**中央/民间听到了什么**"（rumor 0–4 档）与"**官府账面**"（official）分层；
P3 巡按要做的是给出**从 rumor 到 real 的合法通道**：通道开多大＝监察投入（oversight／密查／巡按在途），
而不是"自动揭露"或"直接改钱"。

---

## 1 · Q1 巡按能看到什么？

**看得到的层由三要素决定**（单点＝`fiscal_visibility_view(viewer, oversight, secret)`）：

| 观察者 | 可见层 | 粒度 | 依据 |
|---|---|---|---|
| 玩家（player） | `official` ＋ `rumor` | 逐路档位 | M35-D；**不含 real** |
| 地方官（official） | `official` ＋ `rumor` | 逐路 | 同上（**自己的账自己报**） |
| 中央（court） | `official` ＋ `rumor` | **汇总**（无逐路明细与信号构成） | `FIN_VIS_GRANULARITY["court"]="national"` |
| **巡按/御史（inspector/audit）** | `official` ＋ `rumor`；**监察足额（oversight ≥ 0.45）或密查 ⇒ ＋ `real`** | 逐路 | `FIN_VIS_LAYERS_AUDIT(_TRUTH)` |
| 系统/AI（internal） | `real` ＋ `official` ＋ `rumor` | 逐路 | `FIN_VIS_LAYERS_SYSTEM` |

**巡按另有"观察量"入口（无需查实即可读）**：
`rumor_tier()`（逐路 0–4 档＋构成信号）、`identity_pressures()`（吏/役/官压力）、
`arrears_months_summary()`（欠给**时长**）、`arrears_recovery_capacity()`（补发能力）。

⇒ **巡按能"看见异常"，但"认定真相"仍需一次勾校**（见 Q2）——这正是信息差的存在方式。

---

## 2 · Q2 巡按如何"发现真实欠支"？

**通道＝既有 P3 勾校链**（本台账不改机制，只把它与 money/欠给口径对齐）：

```
① 触发（玩家/中央下诏「勾校某路」 → 既有 `audit_route` 效果键，先于数值过滤）
② 保真度三档（既有 `core/audit_case.resolve_audit`）：
     fidelity = f(执行者 corruption ↓, 目标路 grip ↓（把持越高越蒙蔽）,
                  spy_network ↑（渗透）, 密查加成)
   → 三档：查得实情／查无实据／反噬
③ 成案（既有 `state.audit_cases`：case_id ＋ evidence ＋ judgement；Q11 抄没前置）
④ **仅"查得实情"档**：把该路的 **real 层**（真欠给三层、真侵渔、账面损耗掩护）
   写入案卷 `evidence`，供中央据此读真账 ⇒ 此后该路对**该观察者**开放 real
```

**与欠给口径的对接（本台账新增的"证据项"）**：查得实情时携带
`local_arrears`（真欠给）／`local_arrears_by_identity`（官欠俸/吏欠钱/衙役欠钱）／
`arrears_months`（连续拖欠月数）／`land_tax_diverted`（真侵渔累计）
——**这些即"真欠支"的可验证凭证**；未查得则案卷不落真账（只记"无据/反噬"）。

**守恒**：本通道**只写案卷与风闻**（信息层），**不动** `treasury`／`local_treasury`／POP wealth；
`money.m_all` 不变（测试钉住）。




## 3 · Q3 地方官上报与真实账差多少？

**三条既有口径直接给出"差"**（全部只读，单点派生）：

| # | 差项 | 官方账（上报） | 真账 | 差额公式 |
|---|---|---|---|---|
| 1 | **侵渔掩护** | `tax_loss_report`（火耗/运输损耗/地方耗费/杂费；P2 账面科目） | `statistics["land_tax_diverted"]`（真侵渔累计） | **上报损耗 − 真侵渔 ＝ 掩护虚增**（>0 ⇒ 多报损耗掩盖侵渔） |
| 2 | **欠支隐瞒** | （官方口径"无欠"） | `local_arrears` ＋ `local_arrears_by_identity`（真欠给三层） | **真欠给 − 官方承认欠支 ＝ 隐瞒规模**（当前官方未记欠支 ⇒ 差额＝全额真欠给） |
| 3 | **征收缺口解释** | 应征 → 实收 的"豁免/欠税" | `land_tax_*`（应征/实收/上供/留州/侵渔） | 缺口 ≡ 豁免 ＋ 欠税 ＋ 侵渔（**恒等式**，可逐项核） |

**读数落点**：`finance_readout.fiscal_visibility.real`（内部）与
`official.loss_report`（账面）**并置** ⇒ 差额可直接算出；
**巡按档位**另有 `rumor_tier.by_route[*].signals`（月数/压力/把持/粮价/动乱）作为"为什么起疑"的线索。

**纪律**：差额**只报不判**——是否"做账"须由 P3 勾校（Q2 通道）与案卷给出结论。

## 4 · Q4 中央如何通过监察降低信息差？

**三条杠杆，全部只改信息**：

| 杠杆 | 手段（既有接线点） | 效果 | 不改什么 |
|---|---|---|---|
| ① **视野升级** | 提升 `oversight`（机构/改革参数）或**派巡按**（长期任务/诏令）；`audit_route` ＋ 密查 | `fiscal_visibility_view("inspector")` 由 `official+rumor` → **＋ real** | 不改钱粮 |
| ② **保真度提升** | 吏治改革（降 `corruption`）、监察人事、`spy_network` 渗透、密查 | 勾校三档更易落"**查得实情**"（P3 既有公式） | 不改钱粮 |
| ③ **档位—真值收敛** | 巡按持续在途 ⇒ 该路 `rumor_tier` 与真账偏差收窄（可观测指标＝**查实率**） | 中央据此判断"还需不需要再查/再派人" | 不改钱粮 |

**可观测指标（建议随 P3-2 落地）**：`oversight`／密查次数／查得实情档数／案卷数／
**查实率 ＝ 查得实情 / 勾校总数**，以及 `rumor_tier` 与 real 层差额的收敛轨迹。
**反向效果**（史实）：巡按扰民／吏怨上升——可在 `unrest`／`clerks.grievance` 侧留观察量，
**仍不改财政**。

## 2 · 证据项口径（全部为**读取快照**，JSON 可序列化）

```yaml

  tier: 0..4
  label: 无异常/钱粮迟滞/吏胥鼓噪/州县积欠/地方失控风险
  signals: {months, pressure, grip, grain_price, unrest}

arrears_months:          # 连续欠给月数（逐科目 + max）
  official_salary / clerk_pay / runner_pay / public_supply / max
official_gap:            # 上报 vs 真账
  loss_report_total       # 账面损耗（P2 做账掩护）
  real_diverted           # 真侵渔 land_tax_diverted
  cover_overstatement     # ＝ 损耗 − 真侵渔（>0 ⇒ 多报损耗掩盖）
  unacknowledged_arrears  # 未承认欠支（当前官府不记欠支 ⇒ ＝真欠给合计）
  collection_gap: {assessed, collected, gap}   # 缺口恒等式（豁免 ＋ 欠税 ＋ 侵渔）
```

**未查得实情** ⇒ `financial_evidence(include_real=False)` **只返回 `rumor_source`**；
且 `resolve_audit` 对该档仍**不写 `evidence`**（既有行为不变 ⇒ `case_is_evidenced`/抄没前置语义不变）。

## 5 · 架构冻结（本批确认）

```
六 POP → occupation → 财政状态(欠给/压力) → real／official／rumor 信息差 → 监察发现链
```
监察**只产生**：信息／案卷／证据／透明度／吏治压力（含反向观察量）；
**不产生**：罚款／补税／降官／清廉变化／财政修改。**M35-D ＋ P3-1 监察证据基础层完成**。
后续：**M36 察访与监司行动**（官员移动／任务／监察资源／决策方选择／风险反馈）——M36 前不引入自动处罚、
自动反腐判定、监察直接改财政；P3-2 暂缓。
