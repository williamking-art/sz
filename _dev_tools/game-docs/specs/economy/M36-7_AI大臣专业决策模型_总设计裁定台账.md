# M36.7-A《AI 大臣专业决策模型》总设计裁定台账

> 2026-10-11 建立（用户裁定：M36.7 系列 **A 阶段＝零代码设计**；先出本台账，再进 B 原型）。
> 目标不是让大臣"说话像古人"，而是让**不同职责、专业、立场与证据**下产生**可审阅的不同判断**。
>
> **最终目标**：皇帝面对的是一群能依据专业/职责/立场/证据提出可审阅意见的大臣；他们可以判断、争论、犯错、修正立场，
> 但**始终处于既定制度与执行边界之内**。

---

## 1 · 冻结边界（整个 M36.7 系列不得放宽）

| 冻结项 | 在本架构中的含义 |
|---|---|
| **D11 权限** | 专业能力、官职、人格、派系、议政身份**均不能**扩大事实访问权限 |
| **唯一桥接** | 不新增绕过既有监察—司法桥接的通道 |
| **唯一成案入口** | 大臣判断、议政结论、政策推断**均不能**创建司法案卷；继续遵守既有 `audit_route` 契约 |
| **财政隔离** | 不因专业推演或跨部门讨论泄露受限财政事实；不改变财政隔离契约 |
| **M36.6-A 提案契约** | 保持提案通道、旧调用方兼容与已裁定批红语义（P1–P3 见 §15） |
| **人格/权限分离** | 人格与专业能力只影响判断与表达，**不赋予**额外操作权 |
| **反馈/行动分离** | 反馈记录本身不触发重试、升级、自动提案或其他世界状态变更 |

> ⚠️ **四处工程落点不是四个可互相绕过的权限域**：
> 内容层工具集只**描述**现有制度工具；执行资格仍由既有执行入口与校验决定；只读视图**不成为**执行入口。

## 2 · 八层分析模型 → 四处工程落点

| 落点 | 承载 | 负责 | 不负责 |
|---|---|---|---|
| **A 内容层静态数据** | 职责↔domain 映射、能力档案、领域枚举、可用政策工具集 | 定义"这大臣负责什么、有哪些**已核定**专业能力、制度内有哪些工具" | 动态推演；授予权限 |
| **B AI 契约层** | 专业判断契约（单轮原型）、既有 `council_review` 会签扩展 | 把**已授权事实**转化为可校验的判断/异议/质询/建议 | 执行；新增平行 `*_decide`（v1 不新增，Q4） |
| **C 状态容器** | 既有提案容器（`ai_pending_actions`）、既有 `state.council_reviews`、新增 `state.minister_growth` | 提案走既有审批与执行链；会签用既有缓存；成长独立存储 | 改人格常量；绕过执行校验 |
| **D 只读事实视图** | 既有 `minister_lens`、`ai_decision_view`，拟新增 `court_opinions_readout()` | 按**查看者权限**提供事实与意见 | 因能力/官阶/派系展示额外信息；成为执行入口 |

八层映射（分析用，不建模块）：①人物与履历／②人格与倾向 → A（数据）＋既有 `persona`；
③专业能力 → A；④事实与证据认知 → D；⑤专业判断 → B；⑥朝廷议政 → B＋C（复用 `council_review`）；
⑦奏议/批红/执行 → C＋既有链路；⑧政绩/立场演化 → C（`minister_growth`）。

## 3 · 职责／专业／权限**三分模型**（Q2）

| 概念 | 含义 | 载体 | 纪律 |
|---|---|---|---|
| **职责** | 我**应该**管什么 | 内容层**职责↔domain 映射表** | **映射不清 ⇒ 标 `unknown`**，不让 AI 自行补全职责 |
| **专业** | 我**擅长判断**什么 | 内容层能力档案（§4） | 影响分析深度与谨慎度；**不**参与权限判定、**不**转为成败概率 |
| **权限** | 我**有资格**看/做什么 | 既有 viewer（D11）＋既有执行契约 | **不得**由官职/能力/人格/派系推导 |

**domain 枚举（v1 锁定，新增须另裁）**：
`military`（军务）｜`finance`（财政）｜`personnel`（铨选吏治）｜`justice`（刑狱）｜
`works`（工役水利）｜`diplomacy`（邦交）｜`agri`（农桑仓储）｜`culture`（文教礼制）。
`minister_lens.focus` **复用同一枚举**（避免两套词汇）。
> 现况说明：`MINISTERS[name]["role"]` 目前是自由文本（如"宰相(门下侍郎兼…)"）⇒ 映射表是必要的**内容层**新增物。

## 4 · 能力档案（Q1）

```python
minister_competence = {
  "minister": "李纲",
  "source": "human_reviewed" | "ai_draft" | "derived",   # 数据来源标记（非权限）
  "confidence": 0.0-1.0,                                  # 可信度标记（非权限、非能力值）
  "domains": {
    "military": {"level": 1|2|3, "limitations": ["…"], "note": "…"},
    # 未覆盖的域 = 缺省 unknown（**不是 level 0**）
  },
  "experience_refs": [],                                  # 指向可追溯事件（提案/案卷 id、读数键）
}
```

**硬约束**
1. **内容层人工核定**；v1 仅覆盖 **6–8 位代表性大臣 × 2–3 域**，其余**显式 `unknown`**（不伪造）；
2. 3 级描述：**1** 熟悉制度与常规／**2** 能诊断问题与设计方案／**3** 能权衡多变量与代价；
3. `source`：`human_reviewed`＝人工核定；`ai_draft`＝草拟待核（**不得**当作已确认能力）；`derived`＝由明确规则派生且**可追溯来源**；
4. **不得自评**：能力档案**不能**由大臣（LLM）自述产出；运行时**引擎与 AI 均不得修改**内容层能力档案；
5. 能力影响**分析深度/领域知识调用/判断谨慎度**；**不影响**权限、**不直接转成**政策成败概率；
6. 不同领域能力**不可**横向折算成"综合智力分"。

## 5 · 专业判断流程与四类内容（硬校验规则 1）

**流程**（认知与表达流程，**非**新增执行链；**不要求**每步一次 AI 调用，也不要求逐步持久化）：
① 接收事实 → ② 识别问题 → ③ 形成判断 → ④ 构造方案 → ⑤ 检查代价 → ⑥ 形成奏议 → ⑦ 等待裁决。

**四类内容强制分离**

| 类型 | 定义 | 典型 |
|---|---|---|
| **事实 Fact** | 系统中可核对，且**该大臣有权查看** | 已记录的边军粮秣数量 |
| **推断 Inference** | 依据事实得出的解释，**可能错** | 粮秣不足可能由运输延误造成 |
| **主张 Position** | 希望朝廷采取的政策立场 | 建议优先修复转运环节 |
| **未知 Unknown** | 现有资料无法支持结论的部分 | 延误源于道路/征运/管理失当 |

**结构约束（引擎校验，非提示词自觉）**
- `inferences[].based_on` **必须是** `facts_refs` 的**子集**；无可核对依据 ⇒ 必须显式 `"speculative": true`；
- **引用校验只保证依据来源与可见性，不为推理结论背书**（合法引用 ≠ 推断成立）；
- `facts_refs` 每个引用必须：存在、属于**允许的读数键白名单**、且**对当前 viewer 可见**；
- **禁止任意属性路径**（防借引用探测受限信息）；
- **不要求每次多方案**：证据充分 ⇒ 可只给一项主张；路径分歧 ⇒ 才做方案比较；
  缺关键事实 ⇒ 可建议**补充信息**；无制度内可行解 ⇒ 应**明确指出约束**。

## 6 · 风险五类与**禁止无依据数值**（硬校验规则 2）

| 风险类别 | 典型问题 |
|---|---|
| `finance` 财政 | 财源是否可靠？是否挤占其他必要支出？ |
| `execution` 执行 | 现有人员/制度/资源能否落实？ |
| `military` 军事与安全 | 是否削弱防御、延误战机、暴露部署？ |
| `political` 政治 | 是否激化部院冲突、地方抵制、派系对立？ |
| `information` 信息 | 关键证据是否缺失？结论是否依赖未证实假设？ |

**数值纪律**：**禁止**凭空给出精确成功率、财政收益、伤亡人数、政策影响数字。
数值只有两种合法来源：
1. 可追溯到**该 viewer 有权读取**的真实数值事实（引用读数键）；
2. 由**既有模拟机制**计算，且记录必要输入、假设与校验结果。

否则改为**定性表述**；若结构化契约**要求数值**却无法满足 ⇒ **校验失败**（不得让模型"填一个看似合理的数"）。
**第一阶段一律定性**（分析类别 ≠ 新权限；涉及受限信息时只能依据获准事实判断）。

## 7 · 时代适用性＝**工具集约束**（硬校验规则 3）

历史合理性是**可行性约束**，不是文风约束：
- 方案须符合当时官制、财政制度、军事组织、法律程序；**不**把现代治理概念当作默认认知；
- 现代 AI 可在内部辅助分析，**输出**须落在模拟世界的制度语境内；
- 不得因"模型知道某现代方案"就默认历史人物拥有其实施所需的制度/技术/组织能力。

**`executable` 语义（关键）**

| 取值 | 含义 | 禁止 |
|---|---|---|
| `executable: true` | **仅当**既有 action kind、既有载荷结构、对应校验**全部成立** | 不得用于制度外方案 |
| `executable: false` | "当前**无执行器**" | ≠ 可绕过审批链；≠ 系统应自动创建待执行动作 |

制度外方案**允许**作为"主张/待办"，但必须标记 `executable: false` **并说明原因**（Q7）。

## 8 · 会签扩展（基于**既有** `council_review`，不另建平行系统）

**既有设施（复用）**：`ai/contracts_court.py::council_review(draft, state_summary, state)`
＋ `prompts/council_review.md` ＋ `token_meter` 组「会签」＋ 后端 `/api/council_review`
＋ **缓存**（`state.council_reviews` / `store_council_review`，随存档；批改后清缓存**重入待签**）。

**扩展内容**：结构化保存**意见／异议／质询／答复**；**保留**缓存与清缓存重入语义。
新字段如何入缓存、旧缓存如何失效、批改后如何重生成 ⇒ 纳入 **D 阶段验收**（见 §12 矩阵）。

**规模（Q5）**：默认**单轮**、**≤3 位**相关大臣；每人**最多 1 份结构化意见 + 1 条质询**；
配置**只能收紧或受控调整**，**不能**绕过权限与事实校验。

**五个治理要点**

| 议题 | 规则 |
|---|---|
| 议题与授权范围 | 由皇帝提出或经既有机制要求议论；明确讨论范围与**可见事实边界** |
| 意见形成 | 每位大臣分别提交事实依据／推断／主张／未知（§5 结构） |
| 交叉质询 | 只能针对**主张/推断/风险/论证过程**；**不得**索取对方无权公开的事实（规则 4） |
| 异议记录 | **保留未解决的专业分歧**；目标不是"制造一致意见" |
| 呈报 | 议政结果是**材料**，**不能**自行变成诏令或执行指令 |

**硬校验规则 4（质询不得探测受限事实）**：
越界质询**直接拒绝**，统一回复：

> **此项依据不在你可核对的范围内。**

**不**确认该信息是否存在，**不**泄露受限信息的存在性，**不**因拒绝而暴露任何额外权限信息。

**分歧四类（不都归结为派系斗争）**：专业分歧（判断不同）／职责分歧（部院目标不同）／
政治分歧（权力与用人立场）／价值与风险分歧（代价取舍）。
⇒ **不规定"某派系永远反对某政策"**：派系影响利益与政治立场，**不替代**具体议题中的判断。

## 9 · 成长与经历（Q6：`state.minister_growth`）

**三种变化必须分开**

| 变化类型 | 应如何处理 | 不应如何处理 |
|---|---|---|
| 知识更新 | 因新事实或可靠经验修正认知 | 直接获得未授权信息 |
| 立场变化 | 因政策后果/政治关系/新判断调整主张 | 因**一次驳回**就永久改变立场 |
| 人格变化 | 仅在**足够长期**经历支持时考虑 | 每回合随机改变性格 |

**容器契约（派生层，不动内容常量）**
```python
state.minister_growth = {"schema": 1, "records": []}
# record = {"id", "minister", "kind": "knowledge|stance|experience",
#           "evidence_refs": [...],   # 必须指向可追溯事件（提案/案卷 id、读数键、月序）
#           "delta_text": "…", "period": "990-3", "reverts": None}
```
- **只增不删**；回滚＝**追加**一条 `kind="revert"`（`reverts=<record id>`），派生视图按序应用；
- **不改 `PERSONA`**（内容层常量）｜**不写 `loyalty`／`corruption`**｜**不**改政治地位；
- **不自动**奖惩、升迁、罢免、提案、执行；
- "皇帝驳回"**不是反证**：不得设统一规则（如"被驳后忠诚下降"）；反应由特质、事件与处境决定（属表达层，非数值写入）。

**履职评价记录（设计，第一阶段不实现奖惩）**：须区分
① 当时可获得的信息 ② 大臣实际提出的判断 ③ 皇帝最终决定 ④ 执行系统实际完成的行动
⑤ 后续观测到的政策结果 ⑥ 结果与原判断之间**能被证据支持**的联系（**不**自动把结果归因于能力）。

**P3（已裁）**：反馈**不自动**注入下次提示词；历史可留存/检索/审计，**是否进入某次推理上下文须另有显式、可审计机制**。

## 10 · 数据契约与字段级映射（与 M36.6-A）

```python
decision_record = {                       # 内部中间产物（可随提案持久化）
  "issue_id": str, "proposer": str,
  "facts_refs": [str],                    # 白名单内、viewer 可见
  "inferences": [{"text": str, "based_on": [str], "speculative": bool}],
  "unknowns": [str],
  "position": str,
  "alternatives": [{"option": str, "why_not": str}],     # 可空（不强制多方案）
  "risks": [{"category": "finance|execution|military|political|information",
             "text": str, "based_on": [str]}],
  "authorization_required": "direct|needs_approval|needs_decree|needs_audience",
  "executable": bool, "executable_reason": str,          # executable=False 必填原因
  "expected": str,
}
```

| `decision_record` | M36.6-A 提案契约 `payload.proposal` | 说明 |
|---|---|---|
| 主要判断理由 | `rationale` | 由 `position`＋关键推断归纳 |
| `facts_refs` | `evidence_refs` | **同一白名单与 viewer 校验** |
| `risks` | `risks` | 保持五类标签（定性） |
| `authorization_required` | `authorization` | 语义对齐 |
| `expected` | `expected` | 定性，不得承诺数值 |
| `inferences`／`unknowns`／`alternatives`／专业限制 | **不映射** | 如要进提案须**另裁**（不得借映射扩张执行载荷） |

> **兼容**：`payload.proposal` 缺新键时旧调用方行为不变；`proposal` 建议带 `proposal_version`（便于演进）。

## 11 · 拒绝与降级矩阵

| 情形 | 处置 | 禁止 |
|---|---|---|
| `facts_refs` 含不存在键／未授权键／任意属性路径 | **整单拒绝** | ❌ **删除引用后继续执行**（把安全失败降级成成功） |
| `based_on ⊄ facts_refs` 且未标 `speculative` | **整单拒绝** | ❌ 自动补 `speculative: true` 后放行 |
| 出现**无依据**精确数值（成功率/金额/伤亡/影响） | 定性字段 ⇒ **强制改判为定性**并记 `downgraded: true`；**数值字段** ⇒ **整单拒绝** | ❌ 让模型自填"看似合理"的数 |
| `executable: true` 但无对应 action kind/载荷/校验 | **整单拒绝** | ❌ 自动降级为 `false` 后继续 |
| 质询越界（索取未公开事实） | **拒绝该条质询**（局部），统一话术（§8） | ❌ 透露"存在此类信息" |
| 结构化输出缺必需字段／类型错误 | **整单拒绝** | ❌ 部分接受 |
| LLM 不可用／契约重试后仍失败 | 走既有 **`narrative_fallback`**（分级降级模板） | ❌ 主流程崩溃 |

**原则**：**安全失败不得被降级为成功**；局部拒绝（单条质询）与整单拒绝（判断/提案）必须区分明确。

## 12 · 缓存与旧数据兼容矩阵

| 场景 | 处置 |
|---|---|
| `state.council_reviews[draft_id]` 为**旧结构**（缺新字段） | 读取时**补默认空数组**（只读补缺，**不重算**）；写入新结构时带上 `struct_version` |
| 新字段是否参与缓存键 | **不参与**（键仍为 `draft_id`）；`struct_version` 不符 ⇒ 视为**未命中**，重新生成 |
| 诏草**批改后**重新签审 | 沿用既有语义：清缓存（`store_council_review(draft_id, {})`）⇒ **重入待签**时重新生成 |
| 旧存档缺 `state.minister_growth` | 补默认 `{"schema":1,"records":[]}`；**不**回溯伪造记录 |
| `minister_growth` 回滚 | 追加 `revert` 记录（只增不删）；派生视图按序应用 |
| 旧存档缺能力档案 | 能力档案属**内容层**（随代码发布）；存档只存派生引用；缺省即 `unknown` |

## 13 · 工程纪律（每个涉及 LLM 契约的里程碑都要验收）

### 17.2 三个口径风险（必须先裁，否则实现必出双账）

- **R-a 取向 ≠ 能力**：`聚敛` 是**取向**且**已被机制消费**（gate＋利益向量）。若再加 `competence.finance`，**不得**把聚敛当理财能力（双重计账）。
- **R-b 文本/枚举混用**：`traits`（自由文本）与 `trait_ids`（枚举）并存；机器判断必须**只用枚举**，否则 AI 可自造标签。
- **R-c 三套量纲**：persona **0–100**｜loyalty/corruption **0–1**｜competence **3 级离散**——**禁止互相折算**，禁止"综合分"。
- 另：`rank`／`nobility` 存在空值 ⇒ 按 Q1 纪律**缺省即 `unknown`，不伪造**。

### 17.4 量纲与写入纪律（建议，待裁）

1. **取向只影响立场/利益/表达；能力只影响判断质量**；二者**不得互相折算**、不设综合分。
2. **机制已消费的 persona 维度（如 `聚敛 ≥ 70`）保持不变**；`competence` **不得复制**其判据。
3. 机器判断一律用**枚举**（`trait_ids`／`faction`／domain）；自由文本（`traits`／`role`）**仅叙事**。
4. **AI/LLM 不得写任何属性**（只产出判断与表达）；能力档案＝内容层人核定，运行时**引擎与 AI 均只读**。
5. **数值不外泄**：`loyalty/corruption`／派系内部字段／能力数值一律给**档位词或 `unknown`**（沿用 `desensitize` 纪律）。
6. 缺值一律 `unknown`，**不伪造**。
