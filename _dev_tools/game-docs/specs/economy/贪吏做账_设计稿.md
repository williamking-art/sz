## 0 · 一句话定义

路级田赋**真账**按全额征收并三分（上供 / 留州 / 吏囊），**账面**只记上供——民间被多刮走的 `(1−arrival)×G` 在账上**不存在**；玩家看不见这笔钱，只能靠改革把账一点点做平，AI 大臣用叙事把这场分裂"演"出来。

## 1 · 四层账模型（谁看得到什么）

| 层 | 载体（全部既有） | 内容 | 谁看得到 |
|---|---|---|---|
| **真账层** | `state` 权威字段：`treasury` / `prefectures[路].local_treasury` / POP `wealth` / `欠税` | 钱真实在哪 | 只有程序 |
| **账面层** | `state.tax_breakdown`、`statistics.total_income/total_expenditure`、econ summary（`game_state_econ.py:497-532`）、月报 | 官府账上写的数字（**做账后**） | 玩家面板、AI 大臣（脱敏） |
| **观测层** | `income_readout` 的 `per_capita_wealth/total_wealth`（按路按阶层）、`pref_local_treasury`（`income_readout.py:419`） | 账上没有的痕迹：民间更穷、官僚更富、地方库在涨 | 玩家（**推理**用，非直读真相） |
| **叙事层** | 召对/月报/事件的 AI 文本，受大臣 `corruption` 权重影响（`decree_confidential.py:142` W_CORRUPTION=0.70） | 真相的暗示或遮掩 | 玩家（代入感） |

**做账 = 账面层与真账层的受控分裂**；玩家的解法从来不是"打开对账工具"，而是改革（§7）让分裂自己缩小，从观测层**看出**钱的去向。

## 2 · 真账机制（承台账 §3，甲形态守恒闭合）

### 2.1 守恒公式（唯一口径）

```
令 G  = 本路田赋折色**全额**基数（calc_monthly_tax_income 去 arrival 的口径）
POP 实付   = G                    ← 钱真出 POP（_tax_agents 逐路扣缴、保底豁免/欠税沿用）
国库      += arrival × G          ← 上供
地方库    += (1−arrival) × G × keep    ← 留州
官僚/吏囊 += (1−arrival) × G × (1−keep) ← 侵渔
────────────────────────────────────
ΣΔM_ALL   = −G + arrival·G + (1−arrival)·G = 0   ✅ 纯转移
```

- `arrival = calc_arrival_rate()`（`game_state_econ.py:537`）：`ARRIVAL_BASE 0.45 + audit_effort×0.30 + authority×W − diversion×0.25`，钳 [0.05, 0.95]（`data_constants.py:68-73`）。
- 三个落点都是 `money.ACCOUNTS` 内既有字段 ⇒ **不开新账户**（台账 §1 约束）。
- 吏囊落点：POP 类无「吏」（`POP_CLASSES` 六类），按 `hoard_settle.py:77` 既有范式 **吏 → 官僚回退**；`transfer_money` 的 `local:<路>` / `pop:<路>:<类>` 通道现成（`game_state.py:1120`）。

### 2.2 keep 派生（纠正台账笔误）

台账 §2/§4 写的 `state.corruption[路]` **不成立**——实测 `state.corruption` 是**大臣级**字典（`corruption_init()` 按 MINISTERS 构造，key=大臣名；`settlement_finance.py:978-980` 只对户部 lead 漂移）。

路级现成读数只有 **`p["govern"]`（0-100，`data_geo_tables.py` 初始化 56-67，`settlement_econ.py:350` 月漂 ±1）**。派生改走：

```
keep = clamp( keep_base + (govern − 50) × govern_w , keep_min, keep_max )
```

治理好 → keep 高（多入府库）；治理差 → keep 低（多入吏囊）。**系数即疑问 Q4。**

## 3 · 账面机制（"做"在哪里）

**账面刻意不解释 `(1−arrival)×G`**：账面收入仍显示 arrival×G（与今天一致），但 POP 实际付了 G——差额**只存在于真账的民间财富缺口**里。账上没有任何科目记它，这就是"做账"。

- ✅ 账面单点：不新增第二本账，不碰 `money.ACCOUNTS`。
- ✅ 不写进 `欠税` 子池——现有追缴机制（`ARREARS_COLLECT_RATE`，`settlement_finance.py:625-633`）会对假欠税**二次征税**，真账双扣（疑问 Q2 丙案因此排除）。
- 历史掩护科目（可选）：现金**火耗**科目当前不存在（`SPARROW_RAT` 只管粮耗）——若要账面"有掩护"，需新增 `statistics` 键（疑问 Q2）。

## 5 · AI 大臣读账（check_treasury 保留语义）

现状（`client_utils.py:1069-1083`）：耗 1 点诏令带宽 → **精确实数**（府库、累计入出）；带宽不足 → 脱敏定性。

按体验裁定，此接口是**大臣阅读账目**的界面。设计基线：

- **大臣默认读到的就是账面**（做账后的数字）——贪官读自己经手做的账，清官读不出破绽但**在奏对里犯嘀咕**（`corruption` 已有权重通道，`decree_confidential.py:142` / `ministry_council.py:497`）；
- 玩家**没有**任何直读真账的工具；
- 亲勾（带宽消耗）语义是否升级为"看穿假账"→ **疑问 Q1**。

## 6 · 圣旨承接与落地（玩家动作层）

> 原则（用户 2026-10-11）：**玩家的唯一动作语言是圣旨**。机制不回答"圣旨怎么办、钱怎么动"，就是没做完。

### 6.1 承接链（全走现成管线，不新造通道）

```
玩家拟旨 / 召对口谕
  ├─ issue_decree（普通·御笔直发·密谕）        commands_decree.py:294
  ├─ issue_free_decree（AI 解析的自由诏令）     commands_decree.py:420
  ├─ issue_secret_decree（密旨＋泄密推演）      commands_decree.py:375
  ├─ issue_kouyu（口谕：即时但弱、可能走样）     commands_decree.py:657
  └─ issue_task_decree（对长期事务督行）        longterm_task.py:715
        ↓ 入队
  pending_decrees / pending_secret_decrees / longterm_public|secret / longterm_effects
        ↓ 月度结算
  _settle_decree：逐诏执行率判定 → 失败"执行受阻"或成功 _apply_decree_effect 落地
```

### 6.2 第一重承接：诏令办不办得动（现成，本稿不改）

| 环节 | 现成挂点 | 语义 |
|---|---|---|
| 会签执行率 | `game_state.py:1352` `calc_decree_execution_rate` | 派系净支持×皇威；中旨按归属：内廷 1.0 / 政府 0.85 / 地方 0.60（`data_decree.py:42`） |
| 吏治折扣 | `clerks.py:331` `decree_execution_mult` | ×(1 − 把持度×W)**（现状=全国聚合口径）**——贪吏越强，政令越办不动（面板可诊断；按路细化见 Q12） |
| 弱通道 | `decree_effect.py:260` `decree_effect_mult` | ×民心/识字率（≤15%） |
| 调兵强制 | `enforce_troops=True` | 民政诏可调兵，最多补 30% 缺口——**"派兵督办"现成玩法** |
| 概率执行 | `settlement_decree.py:196` | `random()<rate` 成功；否则"执行受阻，部分落实" |

**这就是"承接"的游戏性**：同一道查核旨，走政府 0.85／地方 0.60（机构归属），再被**吏治把持度**打折。⚠️ **实测校正**：`decree_effect_mult` 的吏治折扣取 `clerks.totals(state)`（**全国聚合**，`decree_effect.py:163`），`route` 参数只影响民心/识字与军队通道——"贪得越狠的路越查不动"需按路细化（**Q12**）。玩家对策全在既有件里：中旨、密旨、调兵、换派系（会签立场）。

### 6.3 第二重承接（**新增**）：查出来的账可不可信

第一重只解决"办没办"，不解决"账真假"。新增**查核保真度**：

```
保真度 = f(执行者清廉度, 目标路把持度 grip, 是否密查)
结果三档：
  · 查得实情（保真高）→ 奏报"该路钱粮约有 X 成未见账"（档位/区间，不给真数）
  · 查无实据（保真低）→ 假阴性："账目清白"——**这就是做账的胜利**
  · 反噬（极端）→ 查者被倒打一耙（贪吏先发制人反劾查官）
```

- 执行者＝御史台/户部在任大臣（`MINISTERS[*]["corruption"]` 现成可读）；
- 落地＝`_apply_decree_effect` 新增分支（如 `audit_route`），产出入"查核案卷"（供奏报与后续抄没引用）；
- **反制手段（玩家侧，全走既有件）**：换清廉御史（选执行者）／密查（绕会签）／调兵督办（+30% 缺口）／多路交叉查（互相印证）；假阴性不可怕，可怕的是**只有一条路可查**。

### 6.5 与 check_treasury 的分工（用户点名）

- `check_treasury`＝**大臣读账**（读的是账面；保留原样，不动）；

## 7 · 改革闭环（一点点改革 → 分裂缩小）

### 7.1 核心发现：改革旋钮目前是死参数

`calc_arrival_rate(audit_effort=0.5, diversion=0.35)` 的两个参数**全部调用点都吃默认值**，无任何 state 接线（`game_state.py:1520`、`game_state_econ.py:337/561/581`、`settlement_finance.py:553`）——即现状"审计力度/截流比例"是**常量**，改革无从作用。本机制必须先把它 state 化（挂点 = 疑问 Q8）。

### 7.2 闭环链条

```
玩家改革（焦点树 govern 分支 / 考课·方田均税类长期诏）
   → state.audit_effort ↑、state.diversion ↓（按路或全局，Q8 定）
   → arrival ↑（每 +0.1 ≈ 田赋上供 +10%·G）
   → 分裂额 (1−arrival)×G 缩小
   → 观测层：账面收入逐月上升、民间压力不增、官僚财富增速放缓
   → 玩家读到"改革见效"——这就是游戏体验
```

- 焦点树 govern 分支（`focus_mechanic.py:27+`，"整饬吏治"三节点 `govern_eff`）是现成改革载体；
- AI 大臣可经 `propose_governance`/长期诏**提议**改革，玩家批红——治理经由 AI 协作完成（补代入感）。

## 8 · 守恒与验收（台账 §6 + 新增）

1. 单月 `_settle_finance` 前后 `m_all(state)` 不变（纯转移守恒）。
2. Σ `local_treasury` 增量 == Σ `(1−arrival)·G·keep`。
3. 官僚 POP wealth 增量（本机制贡献） == Σ `(1−arrival)·G·(1−keep)`。
4. `treasury` 增量 == Σ `arrival·G`（与既有保底豁免/欠税口径对齐）。
5. 路级 `pops` 只读守卫零违规（落点全走 `transfer_money`/`_pop_obj_add` 桥接）。
6. **账面/真账分离断言**：`statistics.total_income` 不含截留额（账面外观与改造前逐月一致的回归）。
7. 长局（≥15 月）`m_all` 全程不变 + `SONGZUO_POPS_GUARD=1` 下零违规。

## 9 · 疑问清单（**全部裁完才开工**）

### Q1 · check_treasury 亲勾给真账还是账面？
- **甲**：带宽亲勾 = **真账**（皇帝花精力看穿假账——"亲勾"本义，玩家借 AI 大臣之手获得唯一真相窗口）；
- **乙**：亲勾仍给**账面**（做账无死角，真相只能靠改革缩小，更硬核但大臣永远无解）。
- **推荐甲**：带宽是稀缺资源，真相有价——与"皇帝治理"的体验最贴。

### Q2 · 账面要不要掩护科目？
- **甲**：不记（§3 现状，最简，缺口只在民间财富里）；
- **乙**：新增现金**火耗**科目 `statistics["tax_fire_loss"]`，账面把 `(1−arrival)·G` 包装成"火耗损耗"（史实最贴——火耗本就是贪墨掩护），玩家在账面上**看得见这个科目变大**，观测通道更明确；
- **丙**：虚列欠税——**已排除**（会触发真欠税追缴、二次征税）。
- **推荐乙**：给观测层一个直接读数，且"火耗奇重"天然是月报风闻与大臣奏对的叙事钩子。

### Q3 · 范围（承台账待裁 A）：只改田赋折色，还是工商/役钱/盐/市舶一并改？
- **推荐只改田赋折色**：史实上做账主体是田赋征解（胥吏经手），工商/盐/市舶是专卖渠道不经路级胥吏；且改动面小一档。其余税种的 arrival 维持税基折扣原语义。

### Q4 · keep 系数与派生源（承台账待裁 B + 笔误纠正）
- 派生源：`govern`（§2.2 纠正后，**没有路级 corruption 可用**）；
- 四系数 `keep_base / govern_w / keep_min / keep_max` 取值——需定标：开局 govern 56-67、月漂 ±1，期望 keep 落在什么区间？（建议初值 keep_base=0.6、govern_w=0.01、[0.3, 0.9]，长局校准门再调。）

### Q5 · 平衡冲击：POP 负担上移多少？
现状 POP 只付 arrival×G ≈ **0.45-0.59×G**；改后付全额 G，田赋折色负担当月 **≈×2**。国库到手不变，纯属把"没征上的"变成"征上了但瓜分"。
- **甲**：接受——民生压力上升正是徽宗朝实况，配合改革回落；
- **乙**：重标定 G 基数（`TAX_COLOR_RATE`/`LAND_TAX_RATE_BENEFIT` 下调），使 POP 实付 ≈ 现状，分裂改从"国库本该多收的"里出（**账面虚增**形态，国库账与实际入库会对不上，做账更狠）；
- **推荐甲**先做，长局校准（P6 质量门）数据说话。

### Q6 · 留州钱的支用通道本批接吗？
`local_treasury` 现状**只进不出**（台账盘点已证）。留州若无支用，钱就是死水，"留州支用"名不副实。
- **甲**：本批只做流入（分层先立起来），支用下批；
- **乙**：本批一并接最小支用（如路级官俸/河工按月扣 `local_treasury`）——范围明显变大。
- **推荐甲**（守住"主改点唯一"）。

### Q7 · 观测层直白度：官僚 wealth 直接可见会不会太直白？
- **甲**：保持现状（income_readout 就是这么设计的——给痕迹不给答案，分不清俸禄/贪墨）；
- **乙**：新增档位化读数（官僚财富"殷实/富足/拮据"band）代替精确实数。
- **推荐甲**：现读数已是既有口径，本批不动。

### Q8 · audit_effort / diversion 的 state 化挂哪？
- **甲**：全局 state 字段（`state.audit_effort` 等），由焦点树 govern 分支 + 长期诏效果直接改；
- **乙**：按路（`p["audit_effort"]`）——改革局部生效，更细但写入面大；

### Q9 · 查核保真度公式与结果形态？
- 输入三要素：执行者 `corruption`（低=保真高）、目标路 `clerks_detail[路]["grip"]`（高=蒙蔽强）、是否密查（加成）；
- **甲**：三档（查得实情／查无实据／反噬）——可读性强，落事件/奏报方便；
- **乙**：连续保真度（0-1），按阈值切档输出——更平滑，但呈现复杂。
- **推荐甲**：三档先说清玩法，公式参数化留校准（P6 门）。

### Q10 · 「巡按」承接形态？
- **甲**：新长期任务 topic（`longterm_task.TASK_HANDLERS` 登记落点：逐月压 `grip`）——推进靠督行诏，失败可诊断（连续 6 月无进展=废弛）；
- **乙**：一次性 free_effect（查一次给一次结果）——简单但无"巡按威慑"持续感。
- **推荐甲**：巡按的威慑感（grip 逐月下降+吏怨上升）正是玩法。

### Q11 · 抄没前置"须先成案"采纳？
- **甲**：须先有查核案卷（防盲抄）——证据链玩法，但也更繁琐；

- **推荐甲**：本系统立意的核心就是"钱必须有去处、真相靠治理发现"，无案而抄会绕开整个机制。

### Q12 · 吏治折扣按路细化？
- 现状：`decree_effect_mult` 的 clerks 通道 = `decree_execution_mult(state)` **全国聚合**（`decree_effect.py:163`），`route` 只进民心/识字/军队通道；

- **乙**：route 提供时改用该路口径（按该路 `clerks_detail[路]["grip"]` 聚合）——"贪得越狠的路越查不动"的精确表达；对无 route 调用方**无影响**（增量改）。
- **推荐乙**：本机制的核心体验是"查哪路"，全国平均会把体验稀释掉。
