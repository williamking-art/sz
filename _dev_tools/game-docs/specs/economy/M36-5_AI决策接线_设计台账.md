# M36.5《AI 决策接线》设计台账（决策接口层适配）

> 2026-10-11 建立（用户裁定：**先做 AI 侧接线，不开 M37**）。
> **目标**：让外部 AI 能**正确使用** M36 提供的信息与行动接口；**不是**让系统替 AI 做政治决策。
>
> **纪律（本轮冻结）**
> - AI 可以：**读取 / 判断 / 调用**。
> - AI 不得被系统**建议**：❌ 推荐派谁　❌ 推荐查哪　❌ 自动生成监察令　❌ 自动生成怀疑。
> - 任何新增通道**不得**引入自动路径（结算链不自动派遣/不自动桥接/不自动查账）。
> - 复用既有三层校验：`schemas.py`（结构）→ `validators.py`（语义）→ 执行点（守恒）。

## 2 · G1／G2 裁定（2026-10-11 用户）

> 前提确认：**玩家＝皇帝，AI＝大臣**；结算分**朝廷决策层**与**世界执行层**两层。

### 2.1 G1：AI 大臣通过什么通道行动

| 通道 | 职责 | 权力边界 |
|---|---|---|
| ① **诏令载荷** | 承载已获准或规则允许**直接执行**的结构化行动 | 必须通过结构、语义与执行点校验 |
| ② **`ai_pending_actions`** | 大臣呈请、皇帝批红、记录批准或驳回 | **呈请 ≠ 批准 ≠ 执行** |
| ③ **行动计划 `op`** | 只**描述**大臣打算做什么 | **不是独立执行入口**，最终转入①② |

**契约名（冻结）**：
`inspect_dispatch {route, kind, secret}`｜`inspect_report {task_id, summary}`｜
`inspect_allege {task_id, text}`（**只能**经 `record_report_suspicion()` 进怀疑层）。
`resolve_audit` **仍只经 `audit_route`**（唯一成案入口，不得新增绕过路径）。

**双层结算流程**：
```
① 朝廷决策层：大臣读有权看到的事实 → 判断 → 建议/奏请/行动载荷
② 皇帝裁决：玩家批准/驳回/修改/授权（需批红者**不得**默认批准）
③ 世界执行层：引擎重新校验权限、参数与状态 → 执行获准且合法的行动
④ 结果反馈：世界状态变化 → 生成新的可见事实 → 供下一轮推演
```

### 2.2 G2：事实清单与系统推荐如何解耦

- **保留** UI 推荐：`briefing.build_briefing_actions(state)` 服务 UI（`key/title/desc/goto/urgent` 兼容不变），
  **不得**直接充当 AI 大臣的决策依据（否则 AI 看到的不是世界，而是系统筛选/排序/暗示过的行动）。
- **新建** AI 中立事实视图 `ai_decision_view(state, viewer, oversight, secret, tier)`（朝廷决策层信息输入）：

| 应提供 | 不应提供 |
|---|---|
| 察访容量/占用/剩余名额 | 推荐先派谁、查哪一路 |
| 符合条件候选人的可见事实 | 预设最优人选/路线排序 |
| 可用行动种类与**参数约束** | `urgent` 一类系统优先级 |
| 在途任务及状态 | 替 AI 直接决定下一步 |
| 已奏报未桥接的 `suspicion_pending` | 自动生成怀疑/自动成案 |
| **动作不可用的具体原因** | 把不可执行动作伪装成可执行 |

- **权限在入口落实**：`player/official/court` 只账面；`inspector` 需密查或 `oversight ≥ 门限`；
  `ai/system` 全知——但**面向具体大臣的视图仍按其实际权限身份过滤**。

### 2.3 最终裁定表

| 项目 | 裁定 |
|---|---|
| G1 行动通道 | 诏令载荷为主，呈请—批红为辅，`op` 不独立执行 |
| G2 信息视图 | UI 推荐与 AI 中立事实视图**分离** |
| 朝廷决策层 | 大臣推演、进言与皇帝裁决 |
| 世界执行层 | 校验、执行与状态推进，**不**代替政治决策 |
| M36.4 桥接 | `record_report_suspicion()` 仍是唯一桥接 |
| 生产成案 | `audit_route` 仍是唯一入口 |
| 财政与权限 | 不得扩大权限或改变财政/欠给/POP/冻结层契约 |

> **暂停线**：任何涉及 **D11 权限／唯一桥接／唯一成案入口／财政隔离契约** 的变更，必须暂停并另行裁定。

## 3 · M36.5 明确不做

❌ 推荐派谁/查哪/查什么/是否追究　❌ 自动生成监察令或诏令文案　❌ 自动生成怀疑或案卷
❌ 系统自动调用任一 M36 动作（结算链、事件链均不得）　❌ 引入成功率/概率/阻力
❌ 因"AI 可用"而放宽任何权限（D11 维持）　❌ 改 `audit_fidelity` 四输入

## 4 · 验收口径（裁后开工门）

1. **可用动作清单是事实**：`inspection_capacity()["free"]>0` 才列"可授差遣"，候选池为 0 的路**不得**列为可选；
2. **禁止自动**（源码守卫）：`settlement.py` 不得出现 `enqueue_inspection`／`file_inspection_report`／
   `record_report_suspicion`／`resolve_audit`；
3. **三层校验齐备**：新载荷有 `schemas.py` 结构校验＋`validators.py` 语义校验＋执行点守恒；
4. **权限回归**：新增读数必须带 viewer 语义，`fiscal_gap_report` 逐格断言不回退；
5. **财政隔离契约（长期保留）**：同种子对照局逐位一致；
6. **回归终态**：`--junitxml` ＋ 进程退出 ＋ 标记普查一致；校准门逐位一致
   （99,806／101,108,584／55／1.220904／9,833,490）。

## 5 · 落地记录（2026-10-11 · 裁定后实现）

| 项 | 落地 |
|---|---|
| **AI 事实视图** | `core/inspection.ai_decision_view(state, viewer, oversight, secret, tier)`——**只读**；键：`viewer／identity／capacity／candidates_by_route／tasks／suspicion_pending／available_actions／pending_requests／feedback／fiscal_context／note`。<br>**无** `urgent`／推荐／排序；行动项仅 `{action, params, available, reasons, via}`；名额或候选池不足时给**具体原因**。 |
| **权限入口** | `fiscal_context` 一律经 `fiscal_gap_report(viewer=…)` 计算（D11 逐格生效：`official` 只账面／`inspector` 需密查或门限／`ai` 全知）；**AI 大臣身份不升权**。 |
| **诏令载荷（正式执行通道）** | `core/inspection_wiring.apply_inspect_decree_payload(state, effects, log)`（**独立接线模块**，由 `settlement_decree._apply_decree_effect` 在**数值过滤之前**调用，与 `audit_route` 同姿态）：<br>`inspect_dispatch{route,kind,secret}` → `enqueue_inspection()`｜`inspect_report{task_id,summary}` → `file_inspection_report()`｜`inspect_allege{task_id,text}` → `record_report_suspicion()`（唯一桥接）。<br>结构非法／路名不存在／未开放种类／超名额 ⇒ 记日志**不执行**，不打断结算。 |
| **为什么单独模块** | `core/inspection.py` 必须保持"监察不读司法"（M36-1～4 源码守卫禁止其 import `audit_case`／出现成案标识符）；而「涉嫌事项→怀疑层」必须调用司法侧唯一桥接 ⇒ 执行层接线独立成 `inspection_wiring.py`：**只做结构校验＋调用**，同时依赖察访单点与怀疑层桥接，**不含**任何判断/推荐，也**不含**成案入口。 |
| **呈请—批红（辅通道）** | `state.enqueue_ai_action(kind="inspect_*", payload=…)` 只入 `ai_pending_actions`（**不改世界**）；`commands.approve_ai_action` 新增三分支 → `_apply_inspect_request()` → 同一单点 → 成功才 `approved`，否则 `rejected`（**呈请≠批准≠执行**）。 |
| **UI 兼容** | `briefing.build_briefing_actions` **未改**（键与兜底行为不变）；与 AI 事实视图彻底分离。 |
| **`audit_route`** | 仍是唯一成案入口（源码测试断言 `settlement_decree` 中 `resolve_audit(` 仅 1 处）。 |

**验证**（`_dev_tools/game-dev/tests/test_m36_5_ai_wiring.py`，11 例）
① 视图只读＋中立（无 urgent/推荐/排序；行动项无优先级字段）；② 可得性随状态变化（名额/在途/已奏报未桥接）；
③ 权限逐格（player/official/court 无真账；inspector 需密查或达标；ai 全知）；
④ 三载荷走**真实执行点**（授差遣→奏报→涉嫌入怀疑层；全程不产案卷）；
⑤ 非法结构/语义/超名额被拒且不留痕；⑥ 呈请不改世界、批红才落地、驳回落空、非法呈请被驳；
⑦ UI 兼容；⑧ 守卫（`settlement.py` 无自动调用；`audit_route` 唯一成案；监察层代码不调用成案；证据读数调用点唯一）；
⑨ **财政隔离契约**：走完三动作后的对照局逐位一致。
