## 一、四项待定规则的裁定与落地细则

### 规则 1：农 POP 不足时 —— **按玩家优先级分配**

| 项 | 细则 |
|---|---|
| **优先级** | 玩家可给**每个作物建筑**设优先级（数值/排序）|
| **未设置时** | 按**比例分配**可用农 POP |
| **不得** | 自动**拆除**、自动**改种**、自动**扩建** |
| **须显示** | ① 分配结果（各建筑实得在岗）② **未满足的用工需求** |

**口径**：

```
可用农 POP = 农 size × 可上岗比例上限        # 见规则 3 的来源查明
供给 = 各建筑需求之和
若 供给 ≤ 可用  ⇒ 全部足额
若 供给 >  可用  ⇒ ① 有优先级者按优先级依次满足，直至用尽
                   ② 无优先级者按需求比例分配剩余
未满足量 = 需求 − 实得   ← **必须界面显示**
```

⚠️ **本文只定分配规则**，**不定优先级 UI**（属界面设计）。

### 规则 2：隐户率 —— **可调整的玩法设定**

| 项 | 细则 |
|---|---|
| **记录粒度** | **按路** |
| **标记** | **明确标注为「开局假设」** |
| **禁止** | ❌ 冒充史实 ❌ **从隐田率推算** |
| **可替换** | 后续有更合适数据时替换 |

⇒ **隐户率与隐田率是两条独立的设定**（承「分开记录」）。

## 二、两处澄清的答复

### 澄清 A：`household_self` 的依据 —— 🔴 **是玩法设定，不是史实**

**查明**：

```
HOLDER_MAP["丝"] = household_self
HOLDER_PROVENANCE["丝"] = "玩法设定"        ← 源码中的显式标记
```

⇒ 依裁定：**它只是玩法开局假设** ⇒

| 要求 | 落实 |
|---|---|
| **必须标出** | 展示/文档中一律写作「**归农户（玩法假设）**」|
| **不得** | ❌ 说成「农户**已确权**产出」|
| 无归属依据时 | 走**待定槽** |

🔴 **先前算例的问题（必须更正）**：

> 我写「归属：household_self ⇒ 本路聚合农 POP」，**未标明它是玩法假设**，
> 读起来像「已确权」。**更正为**：

> ```
> 归属 = household_self（**玩法假设**，非史实确权）
>        ⇒ 货记入本路聚合农 POP 的 goods
>        ⇒ **不代表农户对该货物拥有可主张的产权**
> 若无 household_self 依据 ⇒ 走**待定槽**
> ```

### 澄清 B：和买的**完整规则**（买方 / 支付 / 入库）

「官府需用走和买」**不足以**证明丝已进入**官府可用库存**。以下为**已实现**的完整规则
（`core/farm_procurement.procure_from_farmers`）：

| 项 | 规则 |
|---|---|
| **购买方** | **国库** `state.treasury` |
| **出售方** | 本路 **`农` POP** |
| **价格** | `MATERIAL_PRICE_BASE[丝] × FARM_PRICE_RATIO`（**0.9**，玩法设定）|
| **支付** | `transfer_money("treasury" → "pop:<路>:农")` |
| **入库（货腿）** | 从农 POP `goods` 取出 → 计入 `state.resources["丝"]["stock"]` |
| **三重约束** | ① 国库资金 ② 官仓**剩余容量** ③ 当月**需求**（目标 = 工坊月需求 × `PROCURE_TARGET_MONTHS`=1.0）|
| **国库保留** | `PROCURE_MAX_TREASURY_SHARE = 0.5` —— 和买**不得把国库压到 50% 以下** |
| **未买走的部分** | **仍归农户**（不丢失、不无偿入库）|
| **对账** | `实付 == 实收 == 取货量 × 单价`，且钱货同步 |

**⇒ 「丝进入官府可用库存」的成立条件**（三者同时）：

```
① 国库有钱（且未触 50% 保留线）
② 官仓有剩余容量
③ 当月有需求（工坊投料目标）
⇒ 满足则成交：钱从国库到农户、货从农户到官仓
⇒ **不满足则不成交**（**不是**「官府要用就有」）
```

⚠️ 故算例中**不能**直接断言「丝已入官库」——须按上述条件逐条校验。

## 三、更正后的完整算例（两浙路 · 桑田 14 级）

### 3.0 输入（实测）

```
路 = 两浙路        气候 = 温带
农 size = 9,003,150   ｜   农 ding = 3,151,102（= size×0.35，**可上岗上限，非史实丁口**）
实际田亩 = 42,550,000  ｜  隐田率 hidden_rate 开局 = 0.35（**既有设定**，非 0.25）
yields[丝] = 4,500,000/年 ⇒ 月 375,000   ← 校验基准
```

⚠️ **两处更正**：① 丁口**直读 `ding`**，不再自行 ×35%；
② 隐田率用**开局 0.35**（我先前误用 0.25）。

### 3.1 种植 → 产出

```
玩家动作：两浙路 桑田 14 级（优先级：未设）
可用农 POP 上限 = 9,003,150 × 0.35 = 3,151,102   （= ding）
需求在岗 = 14 × 100,000 = 1,400,000   ≤ 上限 ✓ 足额
产出(丝/月) = 1,400,000 × 0.1586 × 1.65 × 1.0 = 366,366   （vs 基准 375,000，−2.3%）
```

### 3.2 归属（**更正标注**）

```
归属 = household_self（**玩法假设**，非史实确权）
     ⇒ 记入本路聚合农 POP 的 goods
     ⇒ **不代表农户拥有可主张的产权**
若无依据 ⇒ 待定槽（缺失≠0）
气候 / 土地登记 / 人口登记 **均不参与判定**
```

### 3.3 税收（**更正隐田率**）

**田赋 —— 按明田**

```
实际田亩 42,550,000
隐田率 0.35 ⇒ 明田 27,657,500  隐田 14,892,500
田赋税基 = 明田 27,657,500  ⇒ 税额 ≈ 553,150（按 2%）
⚠️ 若按实际田亩征 ⇒ 851,000（**多征 297,850**）
```

**赋役 —— 按编户丁**

```
ding = 3,151,102（可上岗上限口径）
隐户率（玩法设定，按路；**开局假设**）取 0.15 ⇒ 编户丁 2,678,437
赋役征发基 = 编户丁 2,678,437
⚠️ 若按实际 ding 征 ⇒ 3,151,102（**多征 472,665**）
```

**丝**：不直接纳税；官府需用走**和买**（须满足 §二B 三条件）。

### 3.4 全链

```
1) 玩家定：两浙路 桑田 14 级
2) 可用农 POP 上限 = ding = 3,151,102；需求 1,400,000 ⇒ 足额
3) 产出 = 366,366 丝/月
4) 归属 = household_self（**玩法假设**）⇒ 农 POP goods；无依据 ⇒ 待定
5) 田赋：按明田 27,657,500（隐田率 0.35）
6) 赋役：按编户丁 2,678,437（隐户率 0.15 玩法设定）
7) 丝需入官库 ⇒ 走和买，**须满足国库/容量/需求三条件**
```
