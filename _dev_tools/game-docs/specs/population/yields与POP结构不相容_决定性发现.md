# 🔴 决定性发现：`yields` 与 POP 结构根本不相容（2026-10-05）

> 影子推演跑「20 路 × 9 维」合计需求时发现。**结论改变了整个接入方向。**

---

## 一、发现过程

### 1.1 第一层：逐维校准「通过」了，但那是**假象**

前几轮我按**逐维**校准基数，使「最紧的路」占可上岗上限 ≤ 80%。
**逐维看确实全通过**。

### 1.2 第二层：按**全 9 维合计**重算 ⇒ **19/20 路超上限**

| 路 | 合计需求 / 上限 |
|---|---:|
| 广南东路 | **360%** |
| 广南西路 | 350% |
| 河东路 | 331% |
| …（中位约 230%）|
| 京畿路 | 59%（唯一合格）|

⇒ **逐维都合格，合计却爆表** —— 因为**一路同时产多个维**，劳力需求**叠加**。

### 1.3 第三层：按**阶层**分流后，工匠侧更离谱

按 V3 口径（建筑决定职业）分流：

| 建筑 | 所属阶层 |
|---|---|
| 桑田 / 麻田 / 果园 / 蔗田 / 茶园 | **农** |
| 林场 / 石场 / 矿场 / 盐场 | **工（工匠）** |

结果：

| 阶层 | 超上限路数 | 最坏 |
|---|---:|---:|
| **农** | **17 / 20** | 284%（广南东路）|
| **工匠** | **20 / 20** | **4264%**（河东路）|

## 二、🔴 根因

```
工匠 POP 极小：京畿路 工匠 342,750  vs  农 6,217,964   （仅 5%）
而 木/石/铁/盐 的产量需求（来自 yields）极大
⇒ 工匠人口**根本供不起**这些产量
```

**⇒ `yields` 是**独立手写的输入**，撰写时**未考虑由谁生产、有多少人可生产**。**

## 三、这推翻了先前的方法论

| | 先前假设 | 实测结论 |
|---|---|---|
| `yields` | 「权威总量」，基数向它反推 | ❌ **它要求的劳力超出人口 2~40 倍** |
| 基数校准 | 调基数使产出匹配 `yields` | ❌ **调不出来**（调高基数则人均产出荒谬）|

🔴 **⇒ 不能以 `yields` 为准反推，只能**：**

| 选项 | 含义 |
|---|---|
| **甲** | **大幅调低 `yields`**（尤其木/石/铁/盐），使其落在人口可支撑的范围内 |
| **乙** | **重定 POP 结构**（工匠占比 5% 是否合理？矿/盐工或应更多）|
| **丙** | **允许跨阶层共岗**（农闲时也可从事矿林，或另设「工役」）|
| **丁** | **产出改为由 POP 派生**（POP × 合理人均产出 ⇒ 产出，`yields` 降为参考）|

## 四、与既有裁定的关系

用户先前裁定「**不设固定作物面积比例、不设硬性土地面积上限**，玩家决定种什么」——
**与此不冲突**：上表讲的是**存量 `yields` 的合理性**，不是玩家扩产的自由度。

但**若采用丁**（产出由 POP 派生），则「玩家扩产」的**上限**自然来自 POP，
与「无硬性面积上限」仍相容（**上限来自人口，不是来自面积规则**）。

## 五、建议

🔴 **甲 + 丁 组合**：

```
① 先按「人口可支撑」重定各维产出的**合理量级**（丁）
② 据此下调 `yields`（甲），使其成为**校验基准**而非权威输入
③ 再校准基数
```

⚠️ 若只做甲不做丁，`yields` 仍是手写输入，**同类矛盾会再次出现**。
