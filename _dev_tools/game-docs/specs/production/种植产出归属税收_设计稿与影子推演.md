## 〇、设计边界（用户明定，不得逾越）

| # | 边界 |
|---|---|
| 1 | **不设固定作物面积比例**，**不设硬性土地面积上限** —— 保留玩家扩产空间 |
| 2 | 玩家决定**种什么、投入多少**；**市场收益只给渐进反馈，不自动替玩家改种** |
| 3 | 气候**仅分寒带/温带/热带**，只管**适种性 + 产出系数**，**不限制可种面积** |
| 4 | `yields` / `CASH_CROP_LAND` **暂作校验/平衡基准**，**不作新的独立生产输入** |
| 5 | **明田/隐田**（土地登记）与**编户/隐户**（人口登记）**必须分开记录**；隐户≠隐田；隐田**推不出**谁耕种/谁拥有/谁取得产出 |
| 6 | 两组登记状态只影响**登记可见度、税负、征发、统计覆盖**，**须列明规则**，**不得笼统乘到产量或货主分配上** |
| 7 | 气候 / 土地登记 / 人口登记 **都不能单独证明货主**；归属沿用**已有货主规则**，缺依据走**待定** |
| 8 | 为可玩性增加开局假设，**须明确标注为玩法假设** |

## 一、气候 × 作物：适种性与产出系数

| 作物 | **寒带** | **温带** | **热带** |
|---|---:|---:|---:|
| 丝（桑）| 0.6 | **1.0** | 0.8 |
| 麻 | 0.7 | **1.0** | 0.9 |
| 果 | 0.5 | **1.0** | 1.1 |
| 蔗 | **不适种** | 0.7 | 1.2 |
| 茶 | **不适种** | 0.8 | 1.1 |
| 粮 | 0.8 | **1.0** | 1.0 |

**口径**：
- 数值 = **产出系数**（乘数），**不是面积限制**；
- **「不适种」是明确状态**（承「缺失≠0」）——不是 0 系数、不是缺失；
- 基准档（温带）为 1.0，便于对照。

### 1.1 各路气候分档（**依地理事实**，非随意设定）

| 气候 | 路 |
|---|---|
| **寒带** (2) | 河北路 · 河东路 |

⇒ 若需更贴史实，可将温带**再分「北温带/亚热带」** —— 但**须先裁定**是否要突破「仅三档」。

## 二、玩家如何选择作物、投入与扩产

### 2.1 三层玩家决策

| 层 | 玩家动作 | 载体 |
|---|---|---|
| **种什么** | 在某路**建哪种作物建筑** | 桑田 / 麻田 / 果园 / 蔗田 / 茶园 |
| **投多少** | 决定**建筑等级**（等级 ↑ ⇒ 在岗 ↑ ⇒ 产出 ↑）| 建筑 `lv` |
| **扩产** | 投入资源**新建/升级**建筑 | 建设动作 |

### 2.2 关键口径

```
在岗人 = 建筑等级 × 每级在岗基数          （路级：桑田/麻田 100,000/级）
约束：在岗 ≤ 该路农 POP                    （不得凭空造人）
```

- ❌ **无面积上限**（用户明定）；
- ❌ **无固定比例**（用户明定）；
- ✅ 但**受农 POP 约束** —— 想多种必须**人口先够**（或从别处迁入），
  这本身构成**自然上限**，且是**有依据的**（人口是实有的）。

⚠️ **待裁**：若某路「桑田+麻田+…」的在岗合计 > 农 POP 时，如何争抢？
（建议：按建筑等级比例分配 —— 但**属未定规则，本文不擅自补**。）

## 三、市场收益如何渐进影响后续决策

### 3.1 设计口径（**渐进反馈，不自动改种**）

```
收益信号 = f(价格, 单产, 投入成本)
价格 = 由**供需**决定（已有市场系统）
```

**「渐进」的三条含义**：

| # | 含义 |
|---|---|
| 1 | 收益**不直接改产出**，只改**玩家下一轮的决策依据**（显示/建议）|
| 2 | 价格**逐月平滑**（已有价格惯性），不因单月供需突变 |
| 3 | **不自动替玩家改种** —— AI/系统**不代玩家配置建筑** |

### 3.2 信号如何呈现（不自动执行）

| 信号 | 内容 |
|---|---|
| **比较优势** | 本路各作物**气候系数**差异（温带种蔗 0.7 vs 热带 1.2）|
| **市场价格** | 该作物现价 vs 基准价 |
| **边际收益** | 升级一级的**新增产出 × 价格 − 建设成本** |

⚠️ 本设计**只定义信号**，**不定义玩家决策算法** —— 那是玩家/UI 的事。

## 四、明田/隐田、编户/隐户 分别影响哪些环节

### 4.1 🔴 两组状态**分开记录**（用户明定）

| 组 | 对象 | 载体 | **不得混同** |
|---|---|---|---|
| **明田 / 隐田** | **土地**登记 | 田亩 | 隐田 ≠ 隐户 |
| **编户 / 隐户** | **人口**登记 | 户/丁 | 隐户 ≠ 隐田 |

**且**：隐田**推不出**「谁耕种 / 谁拥有 / 谁取得产出」（用户明定）。

### 4.2 影响环节（**逐项列明，不笼统相乘**）

| 登记状态 | 影响 | **不影响** |
|---|---|---|
| **隐田** | ① **田赋税基**（可征亩 < 实际亩）② 登记可见度 ③ 统计覆盖 | ❌ 产出 ❌ 货主 ❌ 谁耕种 |
| **隐户** | ① **赋役征发基数**（可征丁 < 实际丁）② 登记可见度 ③ 统计覆盖 | ❌ 产出 ❌ 货主 |

### 4.3 🔴 三条禁止（用户明定）

1. **不得**把隐匿比例乘到**产量**上；
2. **不得**把隐匿比例乘到**货主分配**上；
3. **不得**由隐田推出耕种者/所有者/产出归属。

### 4.4 与产出的关系

```
产出 = 实际耕种 × 气候系数 × …      （与登记状态**无关**）
税基 = 登记可见部分                   （隐田/隐户 各自削减）
```

⇒ **产量与税基是两条独立的线**，这是本设计的关键分野。

## 五、完整算例：两浙路 · 桑田

### 5.0 输入（实测，非假设）

```
路 = 两浙路            气候 = 温带
治所数 = 9             农 POP = 9,003,150
实际田亩 = 42,550,000   实际户数 = 2,005,000   实际人口 = 10,025,000
yields[丝] = 4,500,000/年  ⇒ 月 375,000   ← 校验基准
```

### 5.1 种植 → 产出

**玩家动作**：在两浙路建 **桑田 14 级**

```
在岗 = 14 × 100,000 = 1,400,000 人   （占农 POP 15.6% ✓ 未超）
基数(丝) = 0.1586/人/月             （由全国 yields 反推的校验基准）
等级系数 = 1 + 0.05×(14−1) = 1.65
气候系数 = 1.0                       （温带 × 桑）
生产率系数 = 1.0                     （未实现因素**不列入**）

产出(丝/月) = 1,400,000 × 0.1586 × 1.65 × 1.0 = 366,366
                      ↑ 与校验基准 375,000 差 −2.3% ✓ 量级吻合
```

等级敏感性：

| 等级 | 在岗 | 占农 POP | 丝/月 | vs 基准 |
|---|---:|---:|---:|---:|
| 12 | 1,200,000 | 13.3% | 294,996 | −21.3% |
| **14** | **1,400,000** | **15.6%** | **366,366** | **−2.3%** |
| 16 | 1,600,000 | 17.8% | 444,080 | +18.4% |

### 5.2 归属（**沿用已有货主规则**）

```
HOLDER_MAP["丝"] = household_self
resolve_holder("丝") 无证据 ⇒ None        ⇒ 走**待定槽**（缺失≠0）
有 household_self 依据 ⇒ 归**本路聚合农 POP**
```

⚠️ **气候 / 土地登记 / 人口登记 均不参与本轮归属判定**（用户明定）。

### 5.3 税收（**明田 / 编户 分别作用**）

**田赋 —— 按明田**

```
实际田亩 42,550,000
隐田率 25% ⇒ 明田 31,912,500  隐田 10,637,500
田赋税基 = 明田 31,912,500   ⇒  税额 ≈ 638,250（按 2%）
⚠️ 若**错误地**按实际田亩征 ⇒ 851,000（**多征 212,750**）
```

**赋役 —— 按编户**

```
实际人口 10,025,000 ⇒ 丁口（×35%）= 3,508,750
隐户率 15% ⇒ 编户丁 2,982,437  隐户丁 526,313
赋役征发基 = 编户丁 2,982,437
⚠️ 若**错误地**按实际丁口征 ⇒ 3,508,750（**多征 526,313**）
```

**丝本身**：**不直接纳税**；官府需用时走 **和买**（国库付钱 → 农户收钱 → 货入官仓）。

### 5.4 全链串起

```
1) 玩家定：两浙路 桑田 14 级
2) 在岗 = 1,400,000（≤ 农 POP 9,003,150）
3) 产出 = 366,366 丝/月
4) 归属：household_self ⇒ 本路聚合农 POP（无证据 ⇒ 待定槽）
5) 田赋：按**明田** 31,912,500 （≠ 实际 42,550,000）
6) 赋役：按**编户丁** 2,982,437 （≠ 实际丁 3,508,750）
7) 丝不纳税；官府需用 ⇒ 和买（钱货对账）
```

## 六、影子推演检查项与接入正式结算的条件

### 6.1 影子推演检查项（本文已跑通，列为回归清单）

| # | 检查项 | 断言 |
|---|---|---|
| 1 | **在岗 ≤ 农 POP** | 任何路任何作物，`在岗 ≤ 农 POP`，否则拒绝 |
| 2 | **气候不适种 ⇒ 不可建** | 寒带建蔗田/茶园 ⇒ 拒绝（**明确报错**，非静默 0）|
| 3 | **气候系数生效** | 同等级同基数下，热带蔗 > 温带蔗 |
| 4 | **产出与校验基准量级吻合** | 差值落在预设容差内（本例 −2.3%）|
| 5 | **归属不受登记状态影响** | 改隐田率/隐户率，**产出与货主不变** |
| 6 | **税基随登记状态变** | 改隐田率 ⇒ 田赋税基变；改隐户率 ⇒ 赋役基数变；**两条独立** |
| 7 | **隐田不推出货主** | 隐田率任意取值，货主判定结果不变 |
| 8 | **缺失 ≠ 0 ≠ 1.0** | 未实现的生产率因素**不列入**、**不填 1.0** |
| 9 | **无固定比例、无面积上限** | 无任何代码路径强制作物占比或面积上限 |
| 10 | **不自动改种** | 系统/AI 不得代玩家修改建筑配置 |
