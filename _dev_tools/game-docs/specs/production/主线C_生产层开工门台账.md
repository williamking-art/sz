## 0. 一句话结论

宋侧生产链**缺的不是公式，而是「接线」**。

- 完整生产链**已经存在**：`core/domains/production/crop_shadow.py`（341 行）已实现
  「气候 → 作物 → 在岗人口 → 产出 → 税基 → 劳役」的**纯函数影子模型**；
- 但它**零生产消费者** —— 全仓库除自身 docstring 外没有第二处引用；
- 今天的**正式产出**走的是 `core/domains/production/production_chain.py:160-190`：
  **`产出 = 路级 yields 年额 / 12 × 建筑乘数`** —— 与**在岗人口、气候、建筑等级、生产率因子全部无关**。

⇒ 主线 C 的性质是：**裁定粒度 → 把影子模型接成唯一生产链 → 影子对比 → 分关切换**，
而不是「从零设计生产公式」。

### 1.1 今天宋侧产出是怎么算出来的（端到端）

```
① 生成期   content/build_prefecture_demog.py
             → content/data_prefecture_demog.py（生成物，含路级 yields 年额）
                    │
② 开局     core/game_state.py:1003   prefectures[路]["yields"] = dict(info["yields"])
                    │
③ 月结算   core/settlement.py:527    「Step 4.4 产出链（批 4 S1）：原料 yields 年额/12 × 建筑乘数 → state.resources」
                    │
④ 产出公式 core/domains/production/production_chain.py:160-190  ★现状唯一产出入口
             for 路 in state.prefectures:
                 yields = p["yields"]                 # 路级年额
                 mult   = _building_mult(p)           # 路级建筑乘数
                 for dim in RAW_DIMS:
                     annual = yields.get(dim)
                     q = int(annual / 12.0 * mult)    # ★产出与人口无关
                     → state.resources[dim]["stock"]（或货主账户）
                    │
⑤ 货主解析 production_chain.py:149-158
             HOLDER_MAP[dim] == "household_self" ⇒ "pop:农:household_self"
             否则 ⇒ resolve_holder(dim)

⑥ 官方取用 core/domains/production/farm_procurement.py（和买）
             国库 → 本路 农 POP 采购；价 = MATERIAL_PRICE_BASE[dim] × 0.9
             三重约束：①国库资金 ②官仓余量 ③本月需求；国库保留 ≥50%（PROCURE_MAX_TREASURY_SHARE）
```

**要点**：`yields` 是**路级常数年额**，与「谁在种、种在哪、地力如何」无关；

### 1.4 影子模型实况（`crop_shadow.py`，本轮新增取证）

这是主线 C 的**既有资产**，不是空白设计稿：

| 符号 | 内容 |
|---|---|
| `CLIMATE_BANDS` | `("寒带","温带","热带")` —— 用户裁定**暂维三档**，不加亚热带 |
| `ROUTE_CLIMATE` | **逐路气候**（依地理事实）；两浙/江南按裁定并入温带。气候仅由 `productivity_factors()` 提供一个有依据的产出系数；资格判断与系数应用分离 |

### 1.6 🔴 决定性约束：`yields` 与 POP 结构根本不相容（既有结论，必须继承）

> 来源：[`../population/yields与POP结构不相容_决定性发现.md`](../population/yields与POP结构不相容_决定性发现.md)（2026-10-05，影子推演）。
> **这是主线 C 最重要的输入约束，任何方案不得与之冲突。**

| 层级 | 实测 |
|---|---|
| 逐维校准 | 「最紧的路占上限 ≤80%」**逐维全通过** |
| **按全 9 维合计** | **19/20 路超上限**（广南东路 360%、河东路 331%、中位约 230%；**只有京畿路 59% 合格**）|
| 按阶层分流 | **农 17/20 超限**（最坏 284%）／**工匠 20/20 超限**（最坏 **4264%**）|

**根因**：

```
工匠 POP 极小：京畿路 工匠 342,750  vs  农 6,217,964（仅 5%）
而 木/石/铁/盐 的产量需求（来自 yields）极大
⇒ 工匠人口根本供不起这些产量
```

⇒ **`yields` 是独立手写的输入，撰写时未考虑由谁生产、有多少人可生产。**
**所以「用 yields 反推基数」这条路已被证伪**（要调出匹配，人均产出会荒谬）。

**既有建议（甲＋丁）**：

```
① 先按「人口可支撑」重定各维产出的合理量级（丁：产出由 POP 派生）
② 据此下调 yields（甲），使其成为校验基准而非权威输入
③ 再校准基数
```

⚠️ **只做甲不做丁 ⇒ `yields` 仍是手写输入，同类矛盾会再次出现。**

🔴 **对本台账的直接影响（C0 必须处置）**：

1. `crop_shadow.CROP_BASE_RATE` 的注释写「由全国 yields 反推（目标占比 15%）」——
   **该方法论已被推翻**；`run_checks()` 第 4 项「两浙路桑田 14 级 vs 375000、偏差 ≤10%」不再是有效验收门。C0 将其登记为**旧量级弃用**；该函数的断言须待 C1 另行获批后随影子口径更新，C0 不改代码。
2. 工匠侧超限只证明**旧 yields 规模与现有 POP 不相容**，不证明工匠 POP 占比不合理。依用户裁定：**本轮冻结工匠 POP 占比**；木/石/铁后置，待新链形成可解释基准后独立评估。
3. 既有裁定允许玩家自行决定开垦与扩建，不设固定作物面积比例或硬面积上限。这与丁相容：产出受实际在岗人口及合法经营/建造状态约束，不以旧路级田亩封顶。

## 2. 五项统一方案：同一条链、同一份契约

### 2.1 唯一生产链（目标形态）

```
玩家指定治所 → 开垦田地 / 建造或扩建产业（玩家经营动作）
                         │ 形成治所级可经营建筑/等级
                         ▼
人口 POP ─→ 岗位需求 jobs_by_position ─→ allocate_farm_pop ─→ 实际在岗人口
  │                                                              │
  │ 路级气候/已定义条件 ─→ productivity_factors() ───────────────┤
  │（未定义因子显式 undefined；不设通用默认）                    ▼
  └────────────────── crop_output() = 在岗 × 作物基数 × 等级加成 × 已定义因子
                                      │
                                      ├─→ 治所级新链产出明细
                                      └─→ 汇总到路，与旧路级 legacy 总量诊断比较
                                          （旧值不拆给治所；无 seat 基准）
路级无归属旧建筑 ─→ blocked_unlocated，不进入新链
正式账务仍经 production_chain；C0/C1 不改正式来源，切源需 C3 另行授权
corvee_base() 只留接口：本轮不启用劳役，未来仍单独授权
```

🔴 **唯一性要求**：

1. **生产率只有一个入口** —— `productivity_factors(state, route, building, crop)`；
   任何模块**不得**自行再乘一个系数。
2. 新链作物结果由 `crop_output()` 计算，粮维沿既有 `produce_grain_track` 独立轨道；正式记账仍走 `production_chain` 唯一受控入口。legacy `yields/12 × mult` **当前仍是正式来源**；只有 route/dim 完成消费者迁移并经 C2/C3 单独授权后，才能关闭该维旧来源（§3.3–3.4）。
3. **气候产出系数只出现一次**：`crop_status()` 判适种/缺气候，不乘系数；唯一气候产出因子由 `productivity_factors()` 明细返回，并只在 `crop_output()` 中应用一次。不得既乘 `climate_coef` 又把气候列入 factors。
4. **AI 不进入本链的数值段** —— 只可提供**档位**（见 §5）。

### 2.2 数据契约（C0 必须冻结）

| `productivity factors` | 每个因子有名、来源、单位/类别与适用层级的明细 | 路级条件与适用的治所/建筑上下文 | 已定义因子列入；未实现/缺数据显式列 `undefined`，不得填 1.0 | `productivity_factors()`；仅按 `combined` 汇总，不允许消费者再手乘 |

⚠️ `productivity_factors()` 的返回**必须是「明细」而非单个标量**：

```json
{"factors": [{"name":"气候", "value":0.92}, {"name":"水利", "value":1.08}],
 "combined": 0.9936,
 "undefined": ["土壤", "区位"]}
```

这样面板与影子对比都能解释「为什么是这个数」。**只返回 0.9936 一律视为不合格。**

## 3. 粒度裁定（C0 必须先裁，裁完才许写公式）

### 3.1 粒度口径与本轮已裁事项

| 对象 | 目标归属单位 | C0 口径 |
|---|---|---|
| 地理条件（气候/地形/水利/土壤/区位/灾频）| **路级** | 地理事实按路登记，同路治所共享；不按治所伪拆（AGENTS §3-7）|
| 土地与扩建 | 玩家在指定治所开垦田地、扩建产业；扩建形成当地建筑/产业等级 | 旧路级田亩只作历史读数、不作新生产硬上限；产量由当地等级和实际在岗人口决定，不需要额外土地会计模型 |
| 建筑 | **治所级（目标）＋路级待分配残量** | 有来源证据才迁入对应治所；只有路级总数者保留原路级、显式未分配，不得归给主治所（§3.2）|
| 岗位 | **治所级**（从已归属治所的建筑派生）| 路级未分配建筑不得产生新链岗位 |
| 在岗 POP | **治所级** | 与 POP seats 真账同粒度；路级镜像只用于聚合/旧读数 |
| 新链产出 | **治所级**，再按路汇总 | 只从已归属治所的建筑、人口和已定义参数计算 |
| 旧 `yields` | **路级旧输入/读数** | 保持原粒度与旧消费者语义；不拆成 seat 基准，不作为新链土地上限；新链产量另由 seat 建筑/在岗决定 |

🔴 **简化生产口径**：玩家在指定治所开垦田、扩建产业，直接增加对应建筑/产业等级或经营量；新产量直接从当地产业规模、实际在岗人口、单位产出与已定义生产率参数计算。旧路级田亩只留作历史读数，不限制新产量；不另建土地账、亩/级公式或固定面积比例。建造成本等不在本轮生产公式内。

### 3.2 路级建筑迁移：有据下沉、无据留存、未归属阻断

现状 `buildings` 有标量、结构对象（含 `lv`）及 `closed` 标记等形态；`building_level()` 是统一读口。**迁移不能把一个路级总数伪装成治所级历史事实。**

| 现存数据 | C0 迁移规则 | 能否进入治所级新链 |
|---|---|---|
| 有明确治所归属的建筑记录 | 按来源/主键原样迁入相应 `seats[治所].buildings`；保留类型、等级、`closed` 等字段 | ✅ 可参与；还须满足建筑类型与生产配置契约 |
| 只有路级总量，治所归属未知 | 保留为**路级待分配存量**（C0 规定独立可识别的待分配槽/记录；本轮不实施 schema），不复制、不摊分、不指定主治所 | ❌ 不可进入新链，不产生治所岗位或治所产出 |
| 已证据映射一部分、路级尚有残量 | 已映射部分可在 C1 生成 seat 影子明细；余量留路级待分配。按类型检查 `路级总量 = 已映射治所量 + 路级待分配量` | C1 可展示覆盖范围与缺口；**该 route/type 不可正式切到新链**，因为旧 route 总量尚包含未映射部分 |
| `closed` / 裁撤记录 | 按其原始归属迁移；归属未知时仍留路级待分配，保持关闭状态 | 关闭建筑不得产生岗位/产出 |

**不得**把路级数值默认给主治所；若将来提出“主治所归集”作为**游戏规则**（而非史实），须另立决策并标注为规则性初始分布，不得偷渡进迁移。

**兼容阻断规则**：未归属的路级建筑留在旧载体；新链对此返回 `blocked_unlocated`，不创建 seat 岗位。旧路级 `yields` 路径继续作为唯一 legacy 来源，直到对应 `(route, dim)` 的旧消费者已迁移、该维度所需建筑/生产量已全部完成归属、并经 C2/C3 授权切换。只要仍有未定位建筑/残量，整个 route/dim 保留 legacy 唯一产出，不允许已映射 seats 先正式入账再与完整 route legacy 总量并存。

⚠️ 迁移**不得改变 `building_level()` 的语义**，尤其「保留 0」不能退化成 1。

**生命周期与禁止双重语义**：

> 玩家扩产闭环：**治所开垦/建造/扩建 → 当地产业等级或经营规模增加 → 实际在岗人口 × 对应单位产出 × 已定义生产率因子 → 产出**。不需要新增土地账或亩数输入；旧路级 `yields` 与田亩读数不封顶玩家新扩产。经济投入、建设成本不在本轮。



1. **C0/C1 期间**，原 `yields` 仍是 legacy 正式产出的输入；盐课继续把盐维按年产能读取；原始/派生字段不调整。C1 使用旧值只形成**诊断对照值**，不是新链校准目标。
2. **C2/C3（另行授权）**，先将活动消费者迁到语义独立字段/参数（至少 legacy producer、盐产能；物料权重 API 明确 dormant/兼容状态；生成器派生读数标成分配估计）；保存来源、量纲、旧值与 parity 证据。
3. **仅在活动消费者脱离后**，才可按维度调整 `yields`，作为新链校验基准；若仍有任何活动读取把它当产能/产出/权重，该维不得调整。校验读取只读，不驱动产出。

|---|---:|---:|---|
| `legacy_active` | ✅ 唯一 | ❌ | 当前默认；未完成旧消费者迁移/建筑归属时保留原路级行为 |

### 3.4 迁移期防重复计产的机制（不能靠自觉）

**双闸门 ＋ 单写入点**：

1. **单写入点**：正式产出仍由 `production_chain` 的受控入口写账；legacy 与新链都不能绕开它。`crop_output` 是纯函数，不写 state。
2. **切源维度**：模式所有权至少按 `(route, dim)` 记录；一个 route/dim 仅可处于 `legacy_active` / `crop_chain_active` / `blocked_unlocated` 之一。
3. **粒度标记分开**：旧产出来源只记 `(route, dim, month, legacy)`；新链记 `(route, seat, crop/dim, month, crop_chain)`。不构造旧 seat 来源标记。
4. **影子报告**仅写报告/独立临时结果，不写 state，不入 `resources`/`goods`，不改存档。
5. 同 route/dim 新旧正式来源并存 ⇒ 回归失败；未完成消费者迁移不得批量调低旧 `yields`。

### 5.2 AI 在经济体系中的自由度与边界（C0 设计契约）

AI 可用自然语言理解开放式经济局面，提出不同发展构想、发现新问题，并起草新科技维度、新产业方向或建筑蓝图；**玩法不应被封闭档位列表或现有静态目录限制**。科技可以扩展可用维度；获批的新蓝图可以新增建筑，或提出对既有蓝图的升级方案。该自由体现在「提出与设计」层，不等于 AI 可直接改游戏状态。

**提案到效果的路径（复用现有设施）**：

```

  → 查重与校验：科技前置和领域；蓝图的材料、岗位/劳动、工期、建设地点、效果构件、维护、产权/出资主体

  → 安全注册/版本化保存
  → 研究/建造/升级项目按既有 action/project、资金、材料、地点和进度规则执行
  → 已注册效果只通过既有科技/蓝图/settlement 算子进入结算
  → 反馈执行结果与因果链
```

现有设施可复用：`TECH_NODES`/`regime_tech`（科技树推进及静态部署蓝图解析）、`decree_plan` 的已注册 `EFFECT_OPERATORS`、`blueprint_dynamic.validate_dynamic_blueprint/register_dynamic_blueprint`、`plan_commit`、`construction`、存档 round-trip。注意：动态蓝图**目前只支持新建、声明式注册**；没有原子升级既有动态蓝图的 API。升级必须设计成新版本/升级提案，经玩家批准后与旧版有兼容迁移和在建工程策略，不能用同名覆盖（当前重复注册明确拒绝）。静态蓝图升级也须先确认已有等级/科技机制能表达，不得假设已存在任意改写接口。

## 7. 迁移与回退

### 7.1 影子对比怎么做（C1；获批后运行）

```
对每个 (route, dim)：
    old_route_total = route_yields[dim] / 12 × route_building_multiplier  # 唯一合法旧值粒度
    new_route_total = Σ 有据映射 seats 的 crop_chain 影子产出之和（先按 route 聚合）
    coverage = mapped_seats / candidate_seats；未映射部分标 blocked_unlocated
    记录 (route, dim, old_route_total, new_route_total, delta, coverage, reasons)

新链另列 seat 明细：
    (route, seat, crop, staffed, building_mapping_evidence, base_rate,
     defined_factors, new_output, old_seat_baseline_status)
old_seat_baseline_status = no_seat_baseline  # 旧 yields 无 seat 实测时
```

**比较纪律**：路级旧总量与 seat 新产出明细不做 seat 对 seat 差分。旧值仅在 route/dim 粒度；新值由有据映射 seats 聚合回 route。覆盖不全须报告 coverage；不得将同一旧 route 值复制给每个 seat，不得将未映射的旧值伪造成 seat 基准。旧 yields 的盐产能、物料权重等消费者需按 §3.3 独立迁移；影子比较不改数据，也不改变其输入。

### 7.2 如何发现双重计产（必须机械化）

1. legacy 来源记为 `(route, dim, month, legacy_yields)`；新链来源记为 `(route, seat, dim/crop, month, crop_chain)`，两种粒度不可伪对齐。
2. 正式产出 source 所有权按 `(route, dim, month)` 检查，最多一个正式来源；shadow 不计为 source 入账。
3. coverage/未定位状态与 source 所有权一起留痕；12 月回放验证同 route/dim 没有双正式来源。

### 7.3 出问题时如何回退

| 层级 | 手段 |
|---|---|
| C0/C1 设计与影子 | 只读、纯影子，不改 state/存档/资源；停止运行即可，无行为回滚 |
| C2/C3（仅获批后） | route/dim source 表保留旧来源版本；出现异常时按同一 route/dim 回切 legacy，禁止 legacy 与新链同时入账 |
| 建筑数据迁移（仅 C2 授权后） | 只迁有依据映射；迁移幂等；保留原路级待分配记录与来源证据，回退不得丢失/重复计建筑 |
| 校准数据（将来另行授权） | 不改全局 `yields`，直至盐产能/物料权重等消费者各自完成迁移和回归；按维度/提交可回退 |
