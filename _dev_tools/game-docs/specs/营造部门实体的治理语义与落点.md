# 建造部门实体的**治理语义与落点**（2026-10-05）

> **用户裁定**：
> 「**要落到州府，而州府一级是自造，因为玩家是中央一级，一般不会管州府一级的事务**」

---

## 一、🔴 这一句定了两件事：**治理语义** 与 **实体落点**

### 1.1 治理语义（三层权责）

| 层 | 角色 | 对营造的权限 |
|---|---|---|
| **玩家 / 中央** | 朝廷视角 | **直管**国家营建（漕渠/驿道/边堡）+ 政令（疏浚运河）；**不碰**州府与民间 |
| **州府（治所）** | 地方 | 🔑 **自造** —— 自行决定建什么、出资、产权；**只上报汇总** |
| **民间** | 士绅/商人/农户 | 🔑 **自造** —— 自筹自发 |

⇒ **玩家不是「所有营造的操作者」**，而是「国家营建的经营者 + 政策制定者」。

### 1.2 落点：州府（治所）级

```
prefectures[路]["seats"][治所]["departments"]["民间营造"]
prefectures[路]["seats"][治所]["departments"]["官有营造"]
```

⇒ **故州府级部门实体是「汇总/呈现层」，不是「玩家指令层」。**
（承《州府级真账总批计划》甲方案）

---

## 二、实体内容（玩家可见的最小完整单元）

| 要素 | 字段 | 说明 |
|---|---|---|
| **名字** | `dept_id` / `label` | 民间营造 / 官有营造 |
| **归属** | `owner_kind` | 民间＝`pop`；官有＝`local_gov`（州府自办）|
| **坐标** | `route` / `seat` / `level` | 🔴 **治所级坐标**（`level="seat"`）|
| **规模** | `craftsmen` | 民间＝工匠；**官有＝工匠 + 应役丁** |
| **月度产出** | `monthly` | 完工/雇工工时/征役人日/工钱/民情代价 |
| **官有标记** | `official` | 供 UI 区分 |

### 2.1 两个部门**各自独立、不合并**

承《建设主体与产权设计》§四：**路级只聚合「量」，不聚合「产权」** ⇒
**州府级同理**：民间与官有是两个独立实体，**不合并成「本州营造部」**。

## 三、🔴 与现状的差距（诚实记录）

```
departments_all({'prefectures': 新局.prefectures})
  → {ok: False, reason: 'no_seats', seats_covered: 0}
```

⇒ 🔴 **新局 `seats` 为空** ⇒ **州府级实体目前一个都取不到**。

**原因**：`seats` 目前**仅旧档迁移时建立**（`_migrate_pops_to_seats`），
新局不建 —— 即《州府级真账》**批次 3** 的未完成项。

⇒ **本设计的完整落地，依赖批次 3（新局即建 `seats`）**。
在此之前：`departments_of`（路级）可作**过渡读数**，但**不是甲方案口径**。

## 五、一个设计上的好处

「州府自造」这条裁定让 **玩家与州府的权责清晰**：

```
玩家能做的：国家营建 + 政令（疏浚运河等）
玩家**不能**（也不该）直接插手指令州府/民间修什么
玩家能做的是：**看**（各州府有哪些部门、建了什么）→ **推**（税、政令影响它）
```

⇒ **这避免了「中央玩家替地方做决定」的反直觉玩法**，
也解释了为何**中央营建与州府自造必须分两条通道**。
