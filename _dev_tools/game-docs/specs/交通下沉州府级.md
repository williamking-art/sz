# 🔴 交通下沉州府级（2026-10-05 用户裁定）

> **用户裁定**：「**交通是州府级**」。
> 本文记录裁定、**现状差距**与**影响面**。**未改代码。**

---

## 一、裁定

交通（水路/道路/漕运状况）的**真账层级 = 州府级（治所）**，
与既有裁定「**POP 实体下沉到州府级（方案乙）**」**同一口径**。

⇒ 与 `prefectures[路]["seats"][治所]` 一致：**治所为真账，路级为派生聚合**。

## 二、🔴 现状差距：**三个件都不在州府级**

| 件 | 现状层级 | 位置 |
|---|---|---|
| **`canal_block`**（漕运阻塞 0~100）| 🔴 **全国**（单一标量）| `game_state.py:718` `self.canal_block` |
| **`buildings`**（含「水利」）| 🔴 **路级** | `game_state.py:951`（在路级 dict 内）|
| **`ROUTE_WATERWAY`**（本会话新增）| 🔴 **路级** | `core/trade_shadow.py` |

⇒ **三者均需下沉到治所级。**

## 三、影响面（**比 POP 下沉更牵动多系统**）

### 3.1 `buildings` 被多个系统共用

`game_state.py:205` 记载：开局 `buildings` 只配 **`水利`**（增产 + 降损耗 + **疏浚运力**）
与 **`常平仓`**（降储粮损耗）。

⇒ `buildings` 的消费者至少有：

| 消费者 | 用途 |
|---|---|
| `settlement_agri` | 7 条农业效果**挂在建筑/科技上** |
| 岗位系统 | `POP_BUILDING_TYPES`（农田/商铺/工坊…）是**岗位类** |
| 科技 | 部分建筑与科技节点绑定 |
| **交通（本次）** | 水利 ⇒ 疏浚漕运 |

🔴 **下沉 `buildings` 会同时改动上述全部系统** ⇒ **不是小改**。

### 3.2 `canal_block` 是**全国标量**

```python
self.canal_block: int = CANAL_BLOCK_START
```

⇒ 现状**无法表达「某段运河淤塞、别处通畅」**。
⇒ 下沉后应为 **`prefectures[路]["seats"][治所]["canal_block"]`**，
全国值降为**加权聚合**（派生）。

⚠️ **但** `canal_block` 已被**粮价**消费（`game_state_econ.py:293`「漕运阻塞越高，外粮难入 → 加价」）
⇒ 下沉后**粮价逻辑需改为逐路/逐治所读**，否则行为分叉。

```

```

**建议合并为一批「州府级真账」工作**，而非各自零敲。
