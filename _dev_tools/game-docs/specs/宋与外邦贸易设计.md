## 九、裁定落地：**商人优先 + 物流成本**（2026-10-05）

> 用户裁定：「**商人优先，还有记得物流成本**」。

### 9.1 商人优先（进出口皆然）

| 环节 | 规则 |
|---|---|
| **出口货源** | ① **商人 goods 优先**；② 不足才取**官仓**；③ 仍不足 ⇒ **不成交**（不凭空给货）|
| **进口去向** | ① **商人 goods 优先**；② 官仓为补充（**待裁是否启用**）|
| **钱腿** | 走既有 `transfer_money(pop:<路>:商人 → …)` |

**理由**：商人本就是「经营外贸」的角色；现有 `test_maritime_trade_ledger_closed` 的
设计也是**商人获外贸毛利** ⇒ 商人优先与既有设计**一致**。

### 9.2 🔴 物流成本 —— **复用既有机制，不另造**

`content/data_external.py:271-276` **已有完整物流成本表**（承「口径单点」）：

### 9.4 🔴 `WAR_MULT` 与 `attitude` 已经联动（重要）

```python

```

⇒ **关系恶化 ⇒ 运费 ×1.5** ⇒ 这条**已经存在的规则**正好成为
「**attitude ↔ 贸易**」驱动环的**天然接口**，**无需新造**：

```
attitude \u2193 \u21d2 \u8fd0\u8d39 \u00d71.5 \u21d2 \u8d38\u6613\u53d8\u4e0d\u5212\u7b97 \u21d2 \u8d38\u6613\u91cf \u2193
attitude \u2191 \u21d2 \u8fd0\u8d39\u5e38\u6001   \u21d2 \u8d38\u6613\u5408\u7b97   \u21d2 \u8d38\u6613\u91cf \u2191
```

⇒ **运费经成本传导影响贸易量，不需额外写一个「贸易驱动公式」** ——
这是**更省、更不容易振荡**的做法。

### 9.5 事务模式：照搬 `material_trade.sell_material_across`

该函数（`core/material_trade.py:190-240`）已确立**可复用的安全模式**：

| 步 | 做法 |
|---|---|
| 1 | 受**真实存量**约束（`goods_amount`，含州府桶）|
| 2 | 买方钱不足 ⇒ **拒绝**（`insufficient_purchasing_power`）|
| 3 | **先发货，再收钱**；收钱不足 ⇒ **退回批次** |
| 4 | 钱走**既有守恒通道** `transfer_money`，**不新开账本** |

⇒ 🔴 **外贸货腿应照此实现**，把「另一路」换成「外邦」，
**避免出现「货发了钱没收到」或「钱收了货没发」的半笔账**。

### 9.6 更新后的货腿公式

```
\u8d38\u6613\u6210\u4ea4\u989d\uff08\u5355\u4f4d\uff09= min(\u53ef\u4f9b\u91cf, \u5bf9\u65b9\u9700\u6c42\u91cf, \u4e70\u65b9\u4ed8\u5f97\u8d77\u7684\u91cf)
\u4ed8\u5f97\u8d77\u7684\u91cf = (\u4e70\u65b9 wealth \u2212 \u8fd0\u8d39) / \u5355\u4ef7
\u8fd0\u8d39 = \u4ea4\u6613\u91cf / 10,000 \u00d7 LOGISTICS_FEE[\u6863] \u00d7 TERRAIN_MULT \u00d7 (1.5 if attitude<30 else 1.0)
```

⚠️ **运费须与货款分账**（既有口径「钱 + 距离 + **民间/政府分账**」）—— 分账比例**待查/待裁**。

### 10.2 🔴 海贸成本：与陆路**结构不同**（不是换个档位）

**史实依据**：海运**单位距离成本远低于陆运**（大船、顺风、载量大），

⇒ 故**近程海贸不划算、远程远优于陆路** —— 这正是「海上丝路」发达的原因。

### 14.2 设计：把税落进**单笔贸易成本**

#### 宋代口径（史实锚点）

| 税目 | 史实率 | 含义 |
|---|---|---|
| **过税** | **2%** | 商货每过一卡（流通税）|
| **住税** | **3%** | 在销地销售（交易税）|
| 合计 | **5%** | 与游戏默认 `0.06` **量级相符** |

⇒ **建议：把 `commerce_tax_rate` 按 `过税 : 住税 = 2 : 3` 分解**，
落实到**单笔成交额**：

```python
\u8fc7\u7a0e\u7387 = commerce_tax_rate * 0.4
\u4f4f\u7a0e\u7387 = commerce_tax_rate * 0.6
\u7a0e\u52a1\u6210\u672c = \u6210\u4ea4\u989d * (\u8fc7\u7a0e\u7387 + \u4f4f\u7a0e\u7387)   # \u5373\u6210\u4ea4\u989d * commerce_tax_rate
```

⚠️ **不新增税率旋钮** —— 复用 `commerce_tax_rate`，只把它的**作用面从「总量」扩到「单笔」**
（承「口径单点」）。
