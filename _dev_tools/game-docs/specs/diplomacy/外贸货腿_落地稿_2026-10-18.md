## 3. 计算层（F2/F3 共用）

### 3.1 新模块 `core/domains/economy/trade_legs.py`

| 函数 | 签名 | 作用 |
|---|---|---|
| `plan_legs` | `(state, channel, total_value) -> list[leg]` | 纯函数：按现金流拆货腿（路/治所/对家/方向/货种/量/价） |
| `execute_leg` | `(state, leg) -> dict` | 执行一侧：出口扣货（商人优先，其次官仓）、进口加货（受库容/购买力约束）；不足⇒缩量 |
| `apply_tariff` | `(state, leg, rate) -> int` | 税费按**实际成交额**计算并入既有账户 |
| `contraband_check` | `(state, leg) -> dict` | 禁榷判定 + 查获概率 |

口径：**所有费率/税率/运费取 `trade_shadow`**（单点），本模块不复制数字。

### 3.2 结算接入点

`core/settlement_econ.py` 市舶段（现 ~555 行）改造：

```text
if state.maritime["open"]:
    for leg in plan_legs(state, "sea", monthly_value):
        res = execute_leg(state, leg)          # 缩量在内部完成
        tax = apply_tariff(state, res["leg"], tariff)   # 按实际成交额
        state.trade_journal.append(record)     # append-only，无余额字段
    # 陆路（F3）：if frontier_market_open(state, partner): 同构
```

**顺序不可颠倒**：先执行货腿拿到实际量 → 再算税 → 再落流水；**不得先按目标额收税再缩货**。

### 3.3 榷场开关（F3）

`frontier_market_open(state, partner)`：读既有邦交值（`external_*` / `diplomacy`），
阈值与档位进 `content/data_constants.py`（如 `FRONTIER_MARKET_MIN_RELATION`），**不臆造新状态**。

## 6. 标定顺序（F2 前必做）

1. 先定 **7 维基准价**（与既有消费品比价，避免"香药比米便宜"）；

4. 长局（≥60 月）对账：物价指数、商人 wealth、国库税收、silver_stock 四条曲线不得爆炸。

## 12. 类目层级（2026-10-18 · Jev 裁定 B 0.993）

### 12.1 为什么不是平铺互斥

用户指出：**粮是食品的子集**。若按「一维一类目、食品排除粮」处理，等于宣布"粮不属于食品"——
与事实相反，且外贸/榷场按类目算货种时会立刻撞上。

Jev 裁定：**类目层级制**（A 平铺 0.007 / B 层级 0.993）。

### 12.2 结构

```text
食品（聚合专用，writable=False）
  ├─ 粮（可写，成员：米/麦/面，default_member=米）
  └─ 非粮食品（meat/wine/酱醋/食用油/糖/果）
```

规则：

| # | 规则 | 实现 |
|---|---|---|
| 1 | 类目可带 `parent`，子类目在 `children` 里 | `goods_class.parent/children` |
| 2 | **递归合计**：父类目 = Σ自身成员 + 递归子类目 | `class_total_deep` |
| 3 | **父子不得同时相加**（否则双计） | 门用例把该纪律写死 |
| 4 | **聚合类目不可写**（无 default_member） | `is_writable` + `class_add` 返回 None |
| 5 | 无环、parent/children 互指一致、成员不跨类目 | `assert_tree` |
| 6 | 类目名不得出现在库存键 | `assert_no_class_in_keys` |

### 12.3 对库存的影响（结论：零）

| 项 | 影响 |
|---|---|
| 库存载体 | **不变**：仍只落维（`POP.goods[维]`、`resources[维].stock`） |
| 字段数/总量/守恒 | 不变 |
| 类目合计 | 新增**派生视图**（不存、不搬、不可写） |
| 同源双计 | 由「层级 + 父子不同加」规则消除 |
| 加工链 | 与类目正交；粮内 原粮/成品粮 仍按 `member_kind` 分列 |

### 12.4 门

`test_quality_gate_goods_class_tree.py`（8 条）：层级自检 / 粮⊂食品 / 递归合计等于子类+自身 /
父子同加即双计（反证） / 聚合类目只读 / 类目名不得进库存键 / 成环检出 / 父子不一致检出。

### 12.5 后续（C1 扩展）

把其余境内类目（纺织/金属/木料/器物/军需/杂料/进口奢侈）按同一层级接入；
每加一类都要过 §12.4 的门，并保证 **Σ叶子类目 + 未归类 == Σ全维**。

### 13.2 关键分类修正

| 维 | 原归 | 现归 | 理由 |
|---|---|---|---|
| 机械构件、机械零件 | 军需 | **工具/机具** | 民生日用/工程/军工**两用**，不是军品 |

### 13.3 覆盖与自洽（门已钉）

- `assert_tree()`：无环、父子互指一致、成员不跨类目；
- `members_deep("商品", active_only=True)` **恰好等于** `GOODS_DIMS`（未归类 0、幻影 0）；
- `class_total_deep("商品", goods)` == Σ全部维；
- 聚合节点允许自身无成员，但必须有 `children` 或 `pending_members`（防空壳）。

全部新类目 `writable=False`（只有 `粮` 保留可写 + `default_member=米`），
库存写入路径与之前**完全一致**：只落维。

## 15. 海运距离口径（2026-10-18 用户提问「现在海运的距离怎么算」）

> ✅ **已按 A 方案落地**（2026-10-18）：海路图 `SEA_LANES`（16 节点 / 15 段，带 note 依据）
> + Dijkstra + 河口加价；`sea_route` 旧「大圆×1.2」口径已废弃。
> 新实算：登州→密州 **520km**（旧 282）、明州→泉州 **1,025km**（旧 749）、
> 杭州→明州 **280km**（旧 168，含 +60 河口）、明州→琼州 **2,500km**（旧 1,884）、
> 广州→琼州 **770km**（旧 549）；非海港（如越州）⇒ None。
> 门：`test_quality_gate_sea_lanes.py`（7 条）。

### 15.1 现状实算（`transport.sea_route`）

```text
km   = 大圆距离(起点,终点) × SEA_DETOUR_FACTOR(1.2)
days = ceil( km / (KM_PER_MONTH 1000 × sea speed 1.2) )
```

|---|---:|---:|---:|---:|
| 明州→泉州 | 624.1 | 748.9 | 1.20 | 1 |
| 明州→广州 | 1,113.8 | 1,336.6 | 1.20 | 2 |

| 明州→琼州 | 1,570.4 | 1,884.5 | 1.20 | 2 |

### 15.2 问题（按严重度）

| # | 问题 | 说明 |
|---|---|---|
| 1 | **不是航线距离** | 全部取大圆 × 1.2，等于假设"海上没有陆地" |
| 2 | **不绕半岛** | 登州(蓬莱)—密州(胶州) 直线 235km，实际须绕成山头，航程约 500km+ ⇒ **低估一倍**；同理 明州—泉州 须绕浙闽海岸，实际约 900–1,000km，现算 749 |
| 3 | **统一系数** | 短程（杭州→明州 140km）与长程（琼州 1,570km）都乘 1.2，长短途误差方向相反 |
| 4 | **不分区** | 渤海/黄海/东海/南海航法不同（近岸 vs 跨海），一个系数吞掉 |
| 5 | **无季风** | 宋商船依赖季风（冬北风南下、夏南风北上），现无顺逆风差异 |
| 6 | **取整粗糙** | `ceil(km/1200)`：898km 与 1,100km 同为 1 月，短程被高估 |
| 7 | **与陆路口径不一致** | 陆路是逐跳真实邻接累加；海路是两点宏观直线 |
| 8 | **跨陆直线** | 某些港对直线穿岛/穿陆（如经台湾海峡、群岛区），误差不可控 |

### 15.3 三种改法

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 海路图（推荐）** | 沿海治所按**岸线顺序**连成链（渤海：登州—密州；黄海/东海：密州—…—明州—台州—泉州—潮州—广州；南海：广州—雷州—琼州），每段给**沿岸里程**（设定表，可附史实航线依据）；两港走 Dijkstra | 能绕半岛/海峡；可逐段标定；与陆路同构（都是图） | 需维护 ~15 段岸线表 |
| B 分区系数 | 渤海 1.5 / 黄海 1.4 / 东海 1.3 / 南海 1.2，按两端海域取 | 改动小 | 仍不解决绕行，只是把误差摊平 |
| C 绕行点表 | 给每对重点航段列绕行点（成山头、舟山、台湾海峡、琼州海峡） | 精度高 | 组合爆炸，维护成本高 |

**建议 A**，与陆路"邻接图 + 最短路"同构；B 可作为过渡（一天内可落）。

### 15.4 口径细节（A 方案配套）

1. **天数按段累加**后再取整：`days = ceil(Σ段km / (1000 × 海速))`，不再对总 km 一次取整；
2. **季风修正**（设定值，可关）：南下（纬度减小）速度 ×1.15，北上 ×0.85；月序决定风向（冬/夏）；
3. **内河出海口**：杭州/明州等需先经河口段（可给固定 +30km），避免"港到港 0 距离"；
4. **不可达**：岸线不连通（如未来加海外据点）⇒ `reachable=False`，不臆造直线；
5. **门**：海路段必须两两成链且总程单调（A→B→C 不得短于 A→C）；段表必须有 `note` 依据。

### 15.5 与外贸的关系

外贸海路的运费/耗时直接吃这套距离；**F2 接线前必须先定海运距离**，
否则"明州→泉州 1 月、运费按 749km"会系统低估海上成本，导致外贸看起来过于有利。

## 17. 回合制下的运输/贸易时序（2026-10-18 用户指出「我们是回合制游戏」）

### 17.1 时间单位与既有实现

| 项 | 现状 |
|---|---|
| 回合 | **1 回合 = 1 月**；绝对月序 `abs_month_index = year×12 + month`（`civil_building`） |
| 批次到期 | `arrive_month = 当前月 + days`；`_now()` 读不到 ⇒ **拒绝建批次**（不回落 0） |
| 钱到账 | `settlement.py` 最前调 `arrive_money_due`（回合初，本月可用） |
| 建材到货 | 流水线 Phase 3：`supply_goods_to_seats` → **`arrive_due`** → `spatial_logistics` → **`procure_materials`（本月发运）** |

⇒ **回合内顺序是正确的**：先到货、后发运（本月发的货不会本月到）。这一点已被流水线顺序钉住。

### 17.2 回合制带来的四个真问题

| # | 问题 | 现状 | 应改成 |
|---|---|---|---|
| **1** | **运力是"每回合"的**，不是连续流 | `dispatch_along` 超运力直接 `over_capacity` **拒绝** | 本回合限额 + **自动排队**（未运完的进 `pending_shipments`，下回合继续）；回合制下"拒办"会让玩家没法把 50 万贯运完 |
| **2** | **外海有开航季** | `OVERSEAS_SAILING_MONTHS` 已登记但**没有任何地方校验** | 发运时校验月份：非窗口 ⇒ `off_season` 并给下个窗口月（回合制正好一月一判） |
| **3** | **跨回合占用不可见** | `in_transit` 有批次，但没有"还剩几个月" | 读数补 `remaining_months`；面板显示「N 回合后到」 |
| **4** | **两套在途时间轴** | (a) `core/transport` 按 `arrive_month`（月）<br>(b) `settlement_pipeline.spatial_logistics` 的 `advance_in_transit_batches(days=30)`（沈括途耗/客运） | 明确边界：**两套容器互不重叠**（建材批次 vs 空间物资/客运）；文档写清 + 门断言不重复推进同一批 |

### 17.3 回合制规则（建议写死）

1. **最小粒度 1 回合**：`days ≥ 1` ⇒ 任何发运**最快下回合到**；同州府/同港 0 天仅限"不走运输"的本地成交；
2. **回合内顺序固定**：①回合初到货入账（钱/货）→ ②本月生产/采购/发运 → ③本月支出；
3. **运力按回合**：`capacity` 是"本回合可发运上限"，超出部分排队，**不拒绝**；
4. **季风窗口**：外海航线只在开航季月可发船；非窗口排到下个窗口；
5. **可观测**：每个批次必须能回答"还剩几回合到、走的哪条路、谁付的运费"；
6. **不臆造波动**：到达偏差默认 0（回合制下若加"延误"必须来自天道档位，不由程序随机）；
7. **事务一致**：结算 critical 步失败 ⇒ 整月回滚（含本月新建批次），不得留下半笔在途。

### 17.4 对既有设计的修正

| 原设计 | 修正 |
|---|---|
| P5c `dispatch_along` 超运力 ⇒ `over_capacity` 拒绝 | ⇒ **接受并排队**（返回 `queued` 与 `deferred_qty`），仅当"该方式完全不可用"才拒 |
| 外海航线只算里程 | ⇒ 增开航季校验（`off_season` + `next_window_month`） |
| 批次只有 `arrive_month` | ⇒ 增 `remaining_months` 派生读数（不落库，按 `arrive_month - now` 算） |
| 单一批次直达终点 | ⇒ 大额货**按回合分批**（每回合发运上限自然形成"多次发运"），这与历史上"分纲起发"一致 |

### 17.5 门（待补）

- `test_quality_gate_turn_based_transport.py`：
  ① `dispatch` 一律 `arrive_month ≥ now+1`（跨回合）；② 运力超额排队且不丢货（Σ在途+已到守恒）；
  ③ 非开航季外海发运 ⇒ `off_season`；④ `remaining_months` 与 `arrive_month` 一致；

## 19. 运量口径：内陆 vs 海运，每月各能运多少（2026-10-18 用户指出「不是加速，是想运量」）

### 19.1 现状：单位是混的

| 方式 | 当前 capacity | 放大 | 实际含义 |
|---|---:|---|---|
| 陆运 | 500 | ×1 | 500 **（无单位）** |
| 水运 | 2,000 | ×50 漕船 | 100,000 / 月 |
| 海运 | 5,000 | ×50 漕船 | 250,000 / 月 |
| 驿传 | 50 | ×1 | 50 |

**问题**：capacity 没有单位——货物按「石」计、钱按「贯」计，却直接跟同一个数比大小。
于是「50 万贯」被当成「50 万石」去比运力，**钱和货的运量混为一谈**。

### 19.2 统一单位：载重「石」

| 换算 | 值 | 依据 |
|---|---|---|
| 1 石 | ≈60 kg | 宋制石（取中值，设定） |
| 1 贯铜钱 | ≈4 kg | 1 贯 = 1,000 文、每文约 4 g |
| **1 石 ≈ 15 贯** | — | 4 kg × 15 ≈ 60 kg |

⇒ 运力一律用**石**；运钱时按 `贯 ÷ 15` 折算成石。**钱很重**，这是交子存在的物理基础。

### 19.3 史实锚点（定上限用）

| 锚点 | 量级 | 用途 |
|---|---|---|
| 北宋漕运额 | **600 万石/年**（天禧后）＝ **50 万石/月** | 全国**水运**月运力上限 |
| 市舶年贸易额 | 约 **200 万贯/年** ≈ 16.7 万贯/月 ≈ **1.1 万石/月**货值 | 全国**海运**月运量量级 |
| 单漕船载重 | 500 石（汴河漕船典型） | 单船上限 |
| 单海船载重 | 2,000 石（宋海船大者） | 单船上限 |
| 单牛车/驴车 | 10 石 | 单车上限 |

### 19.4 建议的月运力表（设定值，锚定史实量级）

| 方式 | 单载具 | 数量 | **月运力** | 说明 |
|---|---:|---|---:|---|
| 陆运 | 车 10 石 | 50 车/路 | **500 石/路·月** | 现状 500 正好保留 |
| 水运 | 漕船 500 石 | 全国漕船池 50 艘 | **25,000 石/月**（全国） | 史实 50 万石/月是漕运上限，游戏取 5%（可调） |
| 海运 | 海船 2,000 石 | 20 艘 | **40,000 石/月**（全国） | ≈ 60 万石/年货量，与市舶贸易额同量级 |
| 驿传 | 轻载 10 石 | 5 队 | **50 石/月** | 只走文书/小额，现状保留 |

⚠️ 关键差异：**水运/海运是「全国池」，不是「每路池」**——现状 `capacity × barges` 对每条路都算一遍，
等于全国有 20 个独立船队，实际月运力被放大 20 倍。

### 19.5 运力池的正确用法（回合制）

```text
每回合开始：state.transport_used = {}          # 本月已用（石）
发运时：    used = transport_used.get(mode, 0)
            free = monthly_capacity(mode, route) - used
            ship = min(want, free)              # **不足则排队，下回合继续**
            transport_used[mode] = used + ship
回合末：    瞬态字段，不落档
```

钱运折算：`贯 ÷ 15` → 石，再按上表扣运力。

### 19.6 与史实/玩法的一致性检查

| 场景 | 换算 | 结论 |
|---|---|---|
| 50 万贯陆运 | 33,333 石 ÷ 500 石/路·月 = **67 个月（单路）** | 陆运大额钱**不可能** ⇒ 必须走水运/交子 |
| 50 万贯水运 | 33,333 石 ÷ 25,000 石/月 ≈ **1.3 个月** | 可行（正是漕运「分纲起发」的节奏） |
| 50 万贯交子 | 无实物流转 | **即刻**，手续费 0.2% | 交子的价值在这里 |
| 全国漕运年运力 | 25,000 × 12 = 30 万石/年 | 为史实 600 万石的 5%（设定，可调） |

### 19.7 落地步骤（F1 之后）

| 步 | 内容 |
|---|---|
| C-1 | 单位统一：capacity 全部改用「石」；钱按 ÷15 折算；常量表 + 门 |
| C-2 | 全国池：水运/海运改为**全国月运力**，按路/港权重分配（不按每路重复） |
| C-3 | 回合运力账：transport_used 瞬态 + 排队（超额不拒办，下回合继续） |
| C-4 | 读数：面板显示「本回合各方式已用/剩余」 |

### 19.8 待你拍的一点

**水运全国月运力取多少**：史实漕运上限 50 万石/月，我建议取 **5%（25,000 石/月）**——
理由：本作是「朝廷 + 民间」混合经济，漕运只是一部分；取满额会让水运过强、粮价被压平。

## 20. 载具级运力与时间差别（2026-10-18 用户：「不同交通方式的运力差别，时间差别；马运、步行这种」）

### 20.1 载具表（设定值，锚定史实量级）

| 载具 | 方式 | 载重 | 速度 km/日 | 月可行 | 载具数 | **月运力** | 成本系数 |
|---|---|---:|---:|---:|---:|---:|---:|
| 步行挑担 | 陆运 | 1 石 | 30 | 900 km | 500 人 | 500 石 | 3.0（最贵） |
| 驴骡驮运 | 陆运 | 2.5 石 | 40 | 1,200 km | 200 驮 | 500 石 | 2.0 |
| 牛车 | 陆运 | 15 石 | 20 | 600 km | 34 车 | 510 石 | 1.0（最便宜） |
| 马车 | 陆运 | 10 石 | 30 | 900 km | 50 车 | 500 石 | 1.2 |
| 驿马急递 | 驿传 | 0.5 石 | **250** | 7,500 km | 100 马 | 50 石 | 8.0（最快最贵） |
| 内河漕船 | 水运 | **500 石** | 35 | 1,050 km | 50 船 | **25,000 石** | 0.4 |
| 海船 | 海运 | **2,000 石** | **100** | 3,000 km | 20 艘 | **40,000 石** | 0.3（最便宜） |

四条取舍线一眼可见：

| 维度 | 极端 | 代表 |
|---|---|---|
| **最快** | 250 km/日 | 驿马急递（但只运 0.5 石/马） |
| **最慢** | 20 km/日 | 牛车（但单载 15 石） |
| **运力最大** | 40,000 石/月 | 海船（全国池） |
| **单位最贵** | 成本系数 8 | 驿马；最便宜是海船 0.3 |

### 20.2 时间差别（同一段路，不同载具）

| 距离 | 步行挑担 | 驴骡 | 牛车 | 马车 | 驿马 | 漕船 | 海船 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 短途 280 km | 1 | 1 | 1 | 1 | 1 | 1 | 1 |
| 中位 1,008 km | **2** | 1 | **2** | **2** | 1 | 1 | 1 |
| 最远 2,356 km | **3** | **2** | **4** | **3** | 1 | **3** | 1 |

⇒ 只要用「驿马/海船」，全境 1 回合可达；但**大宗货只能走慢载具**，于是 2–4 回合。
这正好解决了上一轮「境内一律 1 回合」把玩法压平的问题：**快的是小件，大件必然慢**。

### 20.3 与 §19 月运力的关系（重要）

§19 定的是**总量上限**（水运 25,000、海运 40,000、陆运 500 石/路·月）；
本条把上限**拆到载具**：

```text
月运力(mode, route) = Σ 载具载重 × 该载具本月可用数量 × 月往返趟数
趟数 = 1                    （单程 > 15 日，本月回不来）
      = 2                    （单程 ≤ 15 日，可往返一次）
```

上表 `载具数` 就是**反推**出来的（= 目标月运力 ÷ 单载重），所以两张表天然一致。

### 20.4 载具级 API 建议

| 函数 | 作用 |
|---|---|
| `carriers(mode)` | 某方式下的载具清单（载重/速度/成本） |
| `carrier_plan(mode, qty, km)` | 自动选载具组合：小件→驿马/挑担；大宗→车/船 |
| `carrier_capacity(mode, route, month)` | 本月该路/该池剩余运力（接 §19 的 transport_used） |
| `carrier_days(carrier, km)` | `ceil(km / (km_per_day × 30))` |

### 20.5 AI/玩家如何选

| 货源 | 推荐载具 | 理由 |
|---|---|---|
| 文书、诏令、小额军情 | 驿马急递 | 1 回合内到全境 |
| 钱（大额） | 漕船（走水）或**交子** | 陆运 33,333 石 ≈ 67 个月，不可行 |
| 粮（大宗） | 漕船 | 25,000 石/月，成本 0.4 |
| 香药/珠宝（高值小量） | 海船/驿马 | 价高体积小，速度优先 |
| 建材（重、量大） | 牛车/马车 + 水运 | 水运最便宜，陆运补最后一程 |

### 20.6 落地顺序

| 步 | 内容 |
|---|---|
| D-1 | `TRANSPORT_CARRIERS` 常量表（本 §20.1）+ 门（载重/速度/成本自洽、月运力与 §19 上限一致） |
| D-2 | `carrier_plan` 自动选载具（按货量/距离/成本） |
| D-3 | `carrier_capacity` 接入回合运力账（§19 C-3） |
| D-4 | 面板：每条在途批次显示载具、剩余回合 |

### 20.7 待你拍的一点

**是否采用载具级**（推荐）还是保持现在的 **4 方式单一速度**？
- 采用 ⇒ 玩法变深（快贵/慢廉/大载重慢），但需要动 `dispatch` 的选载具与运力账；
- 不采用 ⇒ 简单，但「马运 vs 步行」的差别就没了。

## 21. 官有运力 vs 私有运力（2026-10-18 用户：「跟官仓民仓一样，官有的运载工具，私有的运载工具」）

### 21.1 为什么要分

现在的 `barges_pool`（缺省 50）是**一个混合池**：官府漕船与商人私船混在一起，
于是「官物用商船」「商货用官船」都算得通，漕运/驿传/和雇这些概念就没法落地。

分所有权之后，才谈得上：官物走官运、商货走商运、官不足时**和雇/差雇**民船。

### 21.2 两类运力

| | 官有（官营/递铺/纲运） | 私有（商人/车行/脚行） |
|---|---|---|
| 载具 | 官造漕船、驿马、官车 | 商船、骡马、牛车、挑夫 |
| 来源 | **官营造船作坊产出**（`造船作坊`：木12,000+铁1,000+麻2,000 → 漕船海舶 50）、驿马由马政拨给 | 商人 `wealth` 出资购置 |
| 用途 | 漕粮、军需、官物、驿传 | 商货、民用 |
| 成本 | 维护费走国库（已有 upkeep） | 自负盈亏，运费内含 |
| 可征调 | — | 官府可**和雇**（付钱）或**差雇**（强制，降民心） |

### 21.3 规则（建议写死）

1. **官物只能走官运力**（漕粮/军需/贡物），官运力不足 ⇒ 和雇民船（付费）或差雇（民心代价）；
2. **商货只能走私运力**（不得占用官船/驿马）；违者视为**私用官物**（可作事件/贪腐）；
3. **驿传只能是官运力**（驿马、递铺）；民间急脚递是另一回事（不接运输层）；
4. **海运**：官有海船（市舶/纲运）与私有海船分开；禁海令影响民船（政治手段），官船不受；
5. **战时征调**：官运力可被征调（漕船改军运），表现为运力短暂下降 + 军需优先。

### 21.4 数据模型

```text
state.carriage = {
  "official": {"boat": 50, "cart": 34, "horse": 100},   # 官有载具数
  "private":  {"boat": 20, "cart": 50, "horse": 0},     # 私有载具数（商人资本）
}
```

- 官有数量：**造船产出**转入（每 50 艘一次产出，扣木/铁/麻），或开局按史实给初值；
- 私有数量：随商人 `wealth` 增长（比例设上限，避免无限膨胀）；
- 月运力 = Σ(载具载重 × 数量 × 趟数)，按 §19/§20 同口径；
- `transport_used` 也分 `official/private` 两本账。

### 21.5 API 建议

| 函数 | 作用 |
|---|---|
| `carriage(state, owner, carrier)` | 某所有权下某载具的数量 |
| `carrier_capacity(mode, route, owner, month)` | 本月剩余运力（分官/私） |
| `dispatch(..., owner="official"\|"private")` | 发运时指定所有权；缺省按货权推断 |
| `hire_private(state, mode, qty)` | **和雇**：付钱用民运力（费用 = 运费 × 系数） |
| `impress_private(state, mode, qty)` | **差雇**：强制征用（民心/吏治代价） |

### 21.6 玩法联动

| 场景 | 结果 |
|---|---|
| 官运力不足 + 有民船 | 玩家可选「和雇」（花钱）或「差雇」（省钱但民怨） |
| 造船作坊产能 | 直接决定官运力上限（→ 漕运能力） |
| 战时 | 官船被征调，商货运力不受影响（但航道管制可能降） |
| 禁海 | 民海船不得出海（市舶落）；官海船仍可行 |
| 贪腐/私用官船 | 事件触发：官运力下降 + 罚没 |

### 21.7 落地步骤

| 步 | 内容 |
|---|---|
| E-1 | `state.carriage` 字段 + 开局初值（官 50 漕船/34 车/100 马；私 20 船/50 车） |
| E-2 | 造船产出 → 官运力入账（替代当前 `barges_pool` 的混合池） |
| E-3 | 运力账分官/私（`transport_used` 两本） |
| E-4 | `hire_private`/`impress_private`（和雇/差雇 + 民心代价） |
| E-5 | 门：官物不得用私运力（政策允许时除外）、商货不得用官运力、两本账守恒 |

### 21.8 与既有系统的关系

- `barges_pool`（现混合池）→ 拆为 `carriage.official.boat` / `carriage.private.boat`；
- `漕船海舶` 维（现归「舟车」类目）：**产出后转运力**，不再是可直接交易的普通货（或保留少量可售）；
- 与官仓/民仓类比：官仓（storage/changping）管粮，官运力管搬；民仓（POP grain/goods）同理。

### 21.9 待你拍的一点

**和雇费率**：建议「运费 × 1.5」（官府租民船，价高于民价，理由：急征、需加价）。
**差雇代价**：建议按征用量降民心 0.1–0.3（按量），并可能在后续回合引发民怨事件。
