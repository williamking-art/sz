# 行政区划与归属 · 分级数据设计稿（宋 + 外邦，2026-10-19）

> 用户：「给各主要国家的州府级数据落地，其他的用省级或国家级，先出设计稿」→「地域与政权分离，宋也是」。
> **状态：设计稿，未实施**。实施计划见 §9。

## 0. 一句话

外邦分三级：**T1 州府级**（6 个主要国家，展开到州/府/京）→ **T2 省级**（现有 `provinces`）→ **T3 国家级**（其余 35 国只用国级汇总）。
聚合恒等式：**国 = Σ 省 = Σ 州府**（缺失一律 `None`，不回落 0）。


### 3.2 T2：省（沿用现有字段，补齐 `pops`）

现有 `provinces[i]` 字段**不改名、不改形**，只做两件事：①`pops=null` 的省按 §4 补分解；②新增可选 `seats`（T1 六国）。

### 3.3 T3：国家级

保持现有 21 字段；新增只读聚合入口，使调用方**不必知道某国是几级**。

## 4. 聚合与分解（守恒，口径单点）

```text
国级 = Σ 省 = Σ 州府（pops[6类].size / wealth / grain、land、grain、troops）
省级 = Σ 其州府（仅 T1 国家有州府；T2/T3 国家省即末级）
分解：省 → 州府 按「首都/要冲权重表」× 省 weight 分摊，**总额守恒**（尾差归首府）
```

| 规则 | 说明 |
|---|---|
| 缺失≠0 | 某省 `pops=null` ⇒ 聚合返回 `None` 并给 `reason`，**不当 0** |
| 尾差归首府 | 整数分摊的截断尾差并入该省首府（与既有 POP 分摊惯例一致） |
| 镜像只读 | 国/省汇总值均为**派生**；写点只落州府（T1）或省（T2）或国（T3） |
| 权重来源 | `provinces[i].weight` 已有；州府权重＝首都 1.5 / 要冲 1.2 / 普通 1.0（**设定值**） |

## 5. 数据来源与标注（不冒充史实）

| 项 | 来源 | 标注 |
|---|---|---|
| 州府**名称** | 史实（辽五京道府州、西夏州、高丽京、日本国、大理府、安南府） | 「史实·地名」 |
| 州府**人口/兵力/粮** | 按 §4 从省级/国级总量分解 | 「玩法设定·按权重分解（总量守恒）」 |
| 州府 **lonlat** | 现代城市坐标近似 | 「近似坐标」 |
| 省 `weight` | 现状已有（设定值） | 沿用 |

⚠️ **不得**把分解值写成史料数据；研究稿/面板如需显示，用「设定值」字样（沿用项目既有纪律）。

## 6. 读写单点（新模块）

```text
core/domains/diplomacy/regime_admin.py
  regime_tier(state, name) -> "T1"|"T2"|"T3"
  regime_seats(state, name) -> list|None            州府列表（T1 才有；其余 None）
  regime_provinces(state, name) -> list|None        省列表（T2/T1）
  regime_aggregate(state, name) -> dict             国级汇总（缺失项 None + reasons）
  regime_seat_add(state, name, province, seat) -> dict   写州府（T1）
  regime_set_pops(state, name, province, pops) -> dict   补省 pops（T2 缺口）
  verify_regime_conservation(state) -> list          Σ省==国、Σ州府==省 的违规清单
```

纪律：**调用方不直接读 `provinces`/`seats`**（口径单点）；未迁移国家/缺失字段一律 `None`。

| 阶段 | 内容 | 门 |

## 13. 地域与政权分离（金不是缺口，是**更替**）

> 用户指出：「金是在辽地起来的，做了辽的数据不就是做了金的数据，而且游戏开局还没有金」。
> 这推翻了我原来的「建议补金」——正确做法是**地域资产只做一次，政权可换 owner**。

### 13.1 两类数据

| 层 | 内容 | 变化频率 |
|---|---|---|
| **地域（region）** | 省/州府、地名、人口（6 类 POP）、土地、粮、坐标、建筑；`region_id` 稳定 | 几乎不变（战乱可减损） |
| **政权（regime）** | 国号、君主、attitude、treasury、tech、armies、growth_curve、rename_log | 随外交/战争/更替变 |

### 13.2 结构（Jev：A 0.951 / B 0.037 / C 0.013 ⇒ 采纳 A）

```text
state.regions = {
  "liao_nanjing": {"level": "T1", "parent": "liao_nanjing_dao",
                   "name": "析津府", "kind": "府",
                   "pop": {...6 类...}, "land": 1200, "grain": 800000,
                   "center_lonlat": [116.4, 39.9], "owner": "辽"},
  "liao_nanjing_dao": {"level": "T2", "parent": "liao", "name": "南京道", ...},
}
state.external_regimes[国]["territory"] = [region_id, ...]   # 政权 → 地域（引用，非内嵌）
```

### 13.3 政权更替 API（新模块 `core/domains/diplomacy/regime_transfer.py`）

```text
transfer_regions(state, from_regime, to_regime, region_ids, *, keep_pops=True)
    → 改 regions[*].owner 与 to_regime.territory；人口/土地/建筑**不动**（地域资产）
    → from_regime 的国级汇总按剩余地域重算（armies 等政权字段另行处理）
regime_of_region(state, region_id) -> str
aggregate_by_owner(state) -> {regime: {...}}   # 国级汇总＝Σ其 territory
```

纪律：
- **地域只写一次**（州府/人口/土地），政权更替只改 `owner` 与 `territory`；
- 政权字段（treasury/armies/tech/attitude）**不随地域走**——灭国即失，新建政权另起；
- 聚合仍是 Σ（国 = Σ省 = Σ州府），缺失 `None`；
- 门：①更替后**地域人口/土地逐字不变**；②`aggregate_by_owner` 前后各自守恒；
  ③未更替时行为与现状**逐字相同**（A/B）。

### 13.4 金登场怎么走（史实 1115 起，本作开局尚未建立）

1. 事件触发「女真起兵」⇒ 新建政权 `金`（政权字段从 0/初始值起，**不继承辽的 treasury**）；
2. `transfer_regions(from=辽, to=金, region_ids=[上京道、东京道…])` 逐步交割（按战争进度）；
3. 辽若失地尽 ⇒ 政权标记 `extinct`（保留历史记录，不再出现在外交列表）；
4. 宋地若被占：同样 `transfer_regions(from=宋? ...)` —— 但宋是 `prefectures` 主账，
   需**单独设计**（见 §13.5），不在本稿范围。

### 13.5 宋地也走同一套（用户：「地域与政权分离，宋也是」）

Jev：**A 统一归属层 0.979**（B 全量迁移 0.004 / C 宋不改加字段 0.017）。

```text
state.regions = {
  # 宋：路（T2）与州府（T1）都登记，owner = 宋；详账仍留 prefectures（这里只存指针）
  song_jingji:        {level: T2, name: 京畿路, owner: 宋,
                      prefecture_ref: {route: 京畿路}},
  song_jingji_kaifeng:{level: T1, name: 开封府, owner: 宋,
                      parent: song_jingji,
                      prefecture_ref: {route: 京畿路, seat: 京畿路|开封府}},
  # 外邦：省/州府同样登记，owner = 辽 等；人口/土地等在本条目内
  liao_nanjing:      {level: T1, name: 析津府, owner: 辽, ...},
}
```

**三条铁律**：

1. **归属只有一个来源**：`regions[id].owner`；宋的 `prefectures` **不再承载 owner 语义**（谁拥有由 regions 决定）；
2. **详账不迁移**：宋的 POP / 建筑 / 仓廪 / 府库仍留 `prefectures[路][seats][治所]`；
   `regions` 对宋单元只存 `prefecture_ref` 指针 ⇒ 改动面最小、**未占领时零行为变更**；
3. **占领只改 owner**：`transfer_regions(from=宋, to=金, region_ids=[...])`；
   宋侧结算读 `regions[...].owner`，**非宋的州府跳过宋的税/产/兵源**（占领方收益按简化规则，细化留待裁）。

**为什么不用「prefectures 加 occupied_by」**：那会在宋账里塞一份「谁占了我」的镜像，
与外邦的 `owner` 形成两套语义 —— 正是本项目一直禁的「平行账本」。

**金南下占宋地的路径**：
1. 战争/事件产生占领清单（州府级 `region_id`）；
2. `transfer_regions(from=宋, to=金, ids)` ⇒ owner 变金；
3. 宋侧月度结算按 owner 过滤（未占领州府照旧 ⇒ **A/B 逐字不变**）；
4. 和议归还 ⇒ 反向 `transfer_regions`（owner 回宋，详账未动 ⇒ 无需重建）。

### 13.6 统一模型的完整口径

| 单元 | 级 | `regions` 里存什么 | 详账在哪 |
|---|---|---|---|
| 宋·路 | T2 | owner + `prefecture_ref.route` | `prefectures[路]`（POP 派生镜像） |
| 宋·州府 | T1 | owner + `prefecture_ref.{route,seat}` | `prefectures[路][seats][治所]`（真账） |
| 外邦·省 | T2 | owner + 人口/土地/兵/建筑 | `regions` 自身 |
| 外邦·州府 | T1 | owner + 人口/土地/兵/建筑 | `regions` 自身 |

⇒ **同一套 owner 语义**：`aggregate_by_owner(state)` 可跨「宋地 + 外邦地」统一汇总；
外交/外贸/岁币的国级读数由它派生，**调用方不再关心某块地是宋还是外邦**。

### 13.7 对宋结算的接入点（实施时必须逐点过）

| 结算步骤 | 需加的判定 |
|---|---|
| 田赋/商税/杂税 | 只对 `owner == 宋` 的州府计；被占州府跳过（并记 `occupied` 读数） |
| 产出（农田/作坊） | 同上；被占州府的产出归占领方（简化：暂不产出，防双重记账） |
| 兵源/征兵 | 被占州府不计丁口 |
| 常平仓/仓储损耗 | 被占州府冻结（不结算损耗） |
| 人口流动/流民 | 被占州府人口可外逃（后续） |

> ⚠️ 默认全部 `owner == 宋` ⇒ 上述判定**全是恒真**，故 P1–P4 阶段**零行为变更**；
> 只有真正发生占领时才生效（P5 门用 A/B 锁死这一点）。
