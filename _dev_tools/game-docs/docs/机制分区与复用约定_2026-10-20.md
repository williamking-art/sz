# 机制分区下的复用约定（2026-10-20）

> 回答的问题：**代码按机制分区后，还能不能复用？**（"有些实现几乎一样，是不是该合并？"）
>
> 结论：**能，但复用的单位是「语义不变量」，不是代码长相**。分区边界不动，复用只发生在
> **向下（共享内核）** 与 **反转（注册/插件）** 两个方向；**不允许**为了复用去横向 import 兄弟域。
> 判据：先证明"语义相同"，再谈"代码相同"。

---

## 1. 先明确分区是什么

本项目当前的分层（与 `game/core/AGENTS.md`、`foundation/README.md` 一致）：

```
content/        数据表（无算法）
foundation/     共享内核：numeric / ledger 账本与桥 / registries / 持久化 / 通用工具
core/domains/   机制域：economy / politics / administration / population / military /
                production / construction / transport / diplomacy / culture / events
core/*.py       迁移期入口/编排（settlement、commands、save_load…）
application/    用例编排（agent_router、decree_prefetch、turn_lifecycle）
backend/        FastAPI 薄壳（client/server）
frontend/       Electron + React，只渲染读数
```

**允许的依赖方向**：`frontend → backend → application → core/domains → foundation/content`。
反向边 0 容忍的只有 `core → backend`；其余反向边由 `test_architecture_import_guard.py` 按
「每对语句条数」棘轮冻结（只准减不准增）。

## 2. 复用的三条正确通道

| 通道 | 适用 | 本项目例子 | 不能怎么做 |
|---|---|---|---|
| **① 共享内核（向下抽取）** | 实现**完全机制无关**：数值容错、钳位、守恒、账本、桥、主键定位、注册表基座 | `foundation/common/numeric.py`、`foundation/ledger/*` 桥、`registries.py`、`readout_hub` 契约 | 把某个机制的业务规则塞进 foundation（foundation 不认识"税/赈济/军饷"） |
| **② 模板方法 + 数据表** | **流程相同、数据/规则不同** | 结算步管线 + 各域 step；局势投影 + 种子表；`_settle_extensions` 的多分支结构；`tier provider` | 为一个机制改流程去 `if 域 == "x"`；把差异做成布尔参数汤 |
| **③ 注册 / 插件反转（依赖倒置）** | 宿主不应认识插件 | `SettlementPipeline` 步骤注册、`AGENT_DEFS`/`PENDING_CONTRACTS`、`SITUATION_EFFECT_PATHS`、`readout_hub.READOUTS`、前端 `PanelKind`/`OverlayStack`、`register_*_provider` | 宿主直接 import 每个机制的实现；插件之间互相 import |

> 记忆口诀：**"往下沉，不横着抓；抓不到就注册。"**

## 3. 判定表：哪些"几乎一致"可以合，哪些不能

| 类型 | 判据 | 处置 | 本项目实例 |
|---|---|---|---|
| **A 真同一** | AST 归一后函数体**逐字节相同**，且失败语义/边界一致 | 抽到共享内核（或指定唯一真身，另一份**纯转发**），删副本；把守卫基线对应项删掉 | `settlement_imperial` 8 函数/415 行；`_locate/_routed`、`_seats_map` 在 4 个 bridge 各一份；`_event`、`_get_pref`、`_stat_add`、`_post_title`、`_stats` |
| **B 同形不同义** | 代码形状像，但**缺失/NaN/越界/报错语义不同** | **先写语义表**；语义不同就保留不同名字（`parse_number` vs `finite_or_undefined` vs `require_number`），不要合成一个"万能 `_num`" | `_num` 31 处有 3 族：4L 只判 `isinstance`／10L 带 `default+isfinite`／13L 带字段名报错 |
| **C 同流程不同数据** | 步骤顺序一样，只有费率/表/键不同 | 模板方法 + 数据表/钩子；一份实现 + N 份配置 | 各省域经济相位（A–E）共用一个 `_ext_econ_phases`；`_changping_trade`/`_state_grain_trade` 是同构的"成对划转" |
| **D 展示格式** | 只做显示（数字/单位/百分比/空值） | 前端共享 `utils/format.ts`；后端只给值不给格式 | 前端 `asNum` ×12、`asStr` ×15、`pct` ×7、内联 `clamp` ×10 |
| **E 机制特有** | 看似重复，但改一个另一个**不应该**跟着变 | **允许重复**，在注释写清"为什么不共享"；不要去抽"万能规则引擎" | 不同税种的计税口径、不同建筑的升级前置、不同事件的成败条件 |

> 关键纪律：**A 类才"必须"归一；B 类必须"先裁定口径"；C 类值得做；D 类随手做；E 类禁止硬合。**

## 4. 现状盘点（2026-10-20 AST 实测）

| 指标 | 数字 | 说明 |
|---|---:|---|
| Python 模块 / 内部边 | 329 / 996 | 57.4% import 写在函数内（延迟导入） |
| 越层反向边 | 38 对 / 66 条 | 数据层上引 17 对、业务→AI/应用 16 对（含 2026-10-20 `commands→shock_prefetch`）、业务反调编排 5 对、core→backend 0 |
| 循环依赖 | 7 个 SCC / 71 模块 | 最大 39（结算链+AI 契约+读档入口，含 `shock_prefetch`/`monthly_gazette`），最小环 `load_game → save_load → load_game` |
| **跨文件逐字节相同函数体** | **5 组 / 10 个函数**（原 15 组/38，A 类已归一 10 组/28 函数） | 已冻结在 `test_duplicate_impl_guard.py`；新增即红 |
| 同名函数多份定义 | 86 个名字 / 238 个 def | 其中大量是 B 类（语义不同），**不能按名字合并** |
| 前端同功能 helper | `asNum`/`asStr`/`pct`/`clamp` | ✅ 已收口到 `utils/format.ts`（`asNum/asStr/formatPct/clampPct`；Engineering delta 特例保留） |

结论：**真正的"完全重复"很少（原 15 组，现已归一 10 组）**，大量是"同名不同义"。所以正确动作不是"大合并"，
而是：① 把 A 类收回单点；② 给 B 类写语义表、按语义命名；③ C/D 类抽公共基座；
④ E 类明确不共享。

**剩余 5 组 = E 类（明确保留）**：

| 组 | 函数 | 理由 |
|---|---|---|
| 1 | `_event` / `_event_once`（faction_ban / impeachment） | 两域事件 payload/去重键语义不同，抽公共层会把域语义带进 base |
| 2 | `_get_pref`（imperial_exam / official_appraisal） | 7 行只读访问器；两域对其"缺省空 dict"的用法不同，且抽到 foundation 只省 7 行、增一层间接 |
| 3 | `_stat_add`（civil_building / settlement_agri） | 5 行 statistics 累加器；`statistics` 本身是自由 schema，合并会诱使别人把它当契约 |
| 4 | `_post_title`（faction_distribution / permission_model） | 6 行官称拼接；显示/权限两域对缺省的 fallback 不同 |
| 5 | `_stats`（party_ban_order / personnel_order） | 6 行只读字段抽取；两域字段集合不同（党禁 vs 人事） |

> 判据：E 类允许重复但**必须留理由**（本节即理由）；改动这些函数时优先改调用方语义，不要为消两组而硬合。

| **P3（中）** | `_num` 三族**先写语义表**再决定合并范围；`tier provider` 基座（10 个注册函数去重） | 中（口径风险） | 三族缺失/NaN/None/字符串各 1 条行为用例先行；合并后仍绿 |

**落地状态**：P1 ✅ `b37cb688b1`（seat_locator + 前端 asNum/asStr）；P2 ✅ `3df531fe18`（`settlement_imperial` 去重 415 行）；
P3 部分 ✅（10L `_num` 族收口；4L/13L 按语义差异保留；前端 `pct/clamp` 已收口为 `clampPct/formatPct`）；P4 未做。

### 5.1 `_num` 语义表（2026-10-20 AST 实测：31 个定义 / 15 个不同函数体）

| 族 | 形态 | 语义 | 处置 |
|---|---|---|---|
| **10L（逐字节相同 ×6）** | `construction_cost` / `market_price` / `population_readout` / `minister_agent` / `demand` / `market` | `None`/`bool`/不可转/NaN/±inf ⇒ `default`；否则 `float`；**默认 `None`（缺失≠0）** | ✅ 已收口到 `foundation/common/numeric.py::finite_number`，6 处改 `import ... as _num` |
| **4L（isinstance 族）** | `canal_bridge` / `jobs_readout` 等 11 个模块 | `isinstance(v,(int,float)) and not bool` ⇒ `float(v)`，否则 `None`；**不转数字串** | 保留（语义不同：字符串不采用） |
| **13L（带字段名报错）** | `civil_building.py` | 非法值 ⇒ 抛/记录**字段名**；用于构造期快速失败 | 保留（语义不同：失败要响） |
| 单点使用（其余） | 各 1 份 | 各自业务默认值/边界 | 保留；`numeric.parse_number` 只统一**实现**、不统一默认值 |

> 判据：只有 AST 归一后**函数体完全相等**才合并（A 类）；4L/13L 属 B 类"同形不同义"，
> 合并会改行为（数字串/布尔/报错语义），必须先裁定口径。本次合并后重复守卫基线再减 1 组（6 函数）。

每批都遵守：**先加断言 → 再改结构 → 复跑全量 → 删守卫基线对应项 → 提交**；
新抽象必须落在**下层**，不得引入新的越层边或新 SCC（守卫会红）。

## 6. 四条硬规则（写进 code review 检查单）

1. **复用向下不横向**：需要兄弟域的实现时，先问"它是不是机制无关的？"是→沉到 `foundation/`；
   不是→走注册/插件反转。**禁止** `domains/a` 直接 import `domains/b` 的函数来复用。
2. **同语义才合并**：合并前用"缺失/NaN/越界/异常/单位"五问逐项对表；任何一项不同就是 B 类，
   保留独立命名（`parse_number` / `finite_or_undefined` / `require_number`），不造万能函数。
3. **允许保留重复，但必须留理由**：E 类在注释写"为什么不共享"，否则下一个人会再来合一次。
4. **归一必须伴随删基线**：`test_duplicate_impl_guard.py` 只允许基线变小；归一组后把对应
   `(hash, files)` 删掉，否则守卫会退化成永久豁免。
