# 宋祚局势系统 · 实施规范

> 交给实施方 AI 的**唯一规范**。过程稿与评审记录在 `_ming_probe\songzuo_review\`，不作为实施依据。

> **范围说明**：本规范约束 `SituationReadout`、`state.situations`（event_pool 局势记录）、指标 DSL 与 Step 8.5 结算。它不定义长期政务/密令的政治进度机制，也不替代 `specs/decree-action-chain/` 的圣旨行动闭环；跨系统接线须复用对应单点，不得新造平行进度或效果账本。当前代码状态与后续建议见 §14。

**约束（硬）**：① 人落 6 类 POP 的 `size`（只走既有流动/自然增减接口）；钱粮落 POP `wealth`/`grain` 或国库/内帑；禁止与 POP 平行的账本；`core/money.py` 仅只读；② 口径单点（算法在 core，端点薄壳，前端不复制）；③ AI 只判档位、程序算数，AI 缺失走程序兜底不伪造；④ 每条改动配守恒断言并进回归测试；⑤ **POP 不止经济数据**——六类 POP 各有非经济维度（民心/士绅抵抗/工困/商情/官心/军心），且**政令还要靠军队执行**（见 §3.5、§3.6）；⑥ **利益集团必须是 POP 阶级的子集**（如军功集团 ⊆ 兵 POP 的路域子集），新集团必须先声明 `pop_basis` 才能登记（见 §3.7）。
**门禁**：**v1 与 v2 均已落地**。v2 的前置条件按 `_dev_tools/game-docs/docs/游戏机制说明.md` §6 核对：**① 审查问题 ✅ 已修**、**② 货币口径（M0–M3）✅ 已生效**（B-1/B-2/B-2′/B-3 全部完成），故 v2 按规范落库（`state.situations` / schema 3）。

## 1. 数据模型

### 1.1 SituationReadout（v1 起可用；**内存投影，不落库**）

```python
class SituationReadout(TypedDict):
    id: str                     # f"{origin_kind}:{origin_ref}"
    title: str
    source: Literal["legacy", "focus", "free_effect", "event"]
    status: Literal["active", "resolved", "failed", "cancelled"]
    # 以下各项缺失一律为 None，前端显示"未定义"，禁止用其他字段顶替
    bar_value: int | None       # 0–100；无进度来源为 None
    resolve_condition_text: str | None
    fail_condition_text: str | None
    ongoing_text: str | None    # 仅在来源显式声明持续代价时存在
    progress_text: str | None   # 推进成本（≠ 持续代价），如 "月耗 1 万贯"
    severity: int               # 0–100，core 派生，用于排序
    phase: Literal["起", "中", "终前"] | None
    region_hint: str | None
    faction_hint: str | None
    pop_highlights: list[str] | None      # **经济**维度：该路最窘/最丰阶级（各行 POP 不同）
    channel_highlights: list[str] | None  # **非经济**维度：吏怨/军心/士绅抵抗（§3.5）
    execution_channels: dict | None       # 会签配合 / 吏治折扣 / 军队督行（§3.6）；帝修 = None
    timeline: list[TimelineEntry]

# build_situation_readout(state) 的顶层还下发两张只读通道表：
#   pop_channels:     {"channels": POP_SENTIMENT_CHANNELS, "nation": {...}, "by_route": {...}}
#   faction_channels: {"factions": {...}, "emerging": [...], "basis_table": ..., "declared": bool}
```

### 1.2 SituationRecord（**仅 v2**；**仅 `origin_kind == "event_pool"` 落库**）

对 `legacy` / `focus` / `free_effect` **只生成 Readout，不得生成 Record**（唯一权威源仍是原模块）。

```python
class SituationRecord(TypedDict):
    id: str                     # f"{origin_kind}:{origin_ref}"；首批禁止 occurrence 后缀
    title: str
    origin_kind: Literal["event_pool"]
    origin_ref: str
    status: Literal["active", "resolved", "failed", "cancelled"]
    bar_value: int              # ≥0；仅本 Record 自持
    progress_mode: Literal["bar", "goal"]
    resolve_condition: dict | None      # None = 未定义
    fail_condition: dict | None         # None = 未定义
    ongoing_cost: dict | None           # None = 无持续代价（不得从别处推断）
    progress_cost: dict | None          # 推进成本，与 ongoing_cost 严格分离
    effect_on_resolve: dict | None
    effect_on_fail: dict | None
    assignee: str | None        # 首批恒为 None（依赖官制，不实现）
    region_hint: str | None
    faction_hint: str | None
    cancellable: bool
    inertia: int                # 未干预月漂移（可负）
    streak_ok: int              # 连续满足 resolve 条件月数
    streak_fail: int            # 连续满足 fail 条件月数
    origin_turn: int
    last_settled_turn: int      # 结算幂等专用（见 §4.3）
    deadline: int | None        # None = 无限期
    timeline: list[TimelineEntry]
```

### 1.3 辅助类型

```python
class TimelineEntry(TypedDict):
    turn: int
    kind: Literal["推进", "节点", "谕", "报", "冲突", "终止"]
    text: str
    source: Literal["program", "ai"]

class SituationIntent(TypedDict):
    situation_id: str
    kind: Literal["调兵", "拨帑", "赈济", "查办", "减免", "蠲赋"]
    amount: float
    note: str
    consumed_turn: int | None                    # 已消费则写回合号
    validation_result: Literal["pass", "fail", "pending"]
```

### 1.4 必填 · 默认 · 状态机

- **必填**：`id`、`title`、`origin_kind`、`origin_ref`、`status`、`origin_turn`、`last_settled_turn`。
- **默认**：`bar_value=0`、`progress_mode="bar"`、`streak_ok=0`、`streak_fail=0`、`deadline=None`、`timeline=[]`、`assignee=None`、`region_hint=None`、`faction_hint=None`、`cancellable=True`、`inertia=0`。
- **合法转换**：`active → resolved | failed | cancelled`（单向，无回退）。**终态不再推进、不再扣费、不再判定、不再执行效果**。
- `status` **不得**由任何 API 直接写入（只能由结算步产生）。
- 首批**禁止重复 occurrence**：同 `origin_kind:origin_ref` 已存在即跳过。

## 2. 投影规则

### 2.1 来源 → Readout 映射表

| 来源 | 投影字段 | **禁止的映射** |
|---|---|---|
| `legacy` | `title←name`；`resolve_condition_text←clear_desc`（文案用"**解除**"）；`severity←`由关联派生读数算；`timeline←`该 legacy 月度日志 | ❌ `effect → ongoing_text`（其效果已由结算步施加）❌ 无 fail 条件即 `None`，不得编造 ❌ 帝修不是"执行"对象，`execution_channels` 恒 `None` |
| `focus` | `title←name`；`bar_value←progress`（**已是 0–100**）；`phase←`派生；`progress_text←"月耗 {cost_per_month} 贯"` | ❌ 不写 `ongoing_text` ❌ 不写回 `active_focus` ❌ `cost_per_month` 不得当"持续代价" |
| `free_effect` | `title←name`；`progress_text←"执行成本 {cost}"`；`deadline` 仅只读展示 | ❌ `cost → ongoing_text` ❌ 不递减 `duration` |
| `event` | `title←title`；`severity←`经济落差 + 地区动乱 + **非经济压力**（§3.5）；`region_hint←`标题中最长路名 |
| `event`（非经济） | `channel_highlights←`该路吏怨/军心/士绅抵抗 | ❌ 无关联路时不得编造地区维度（只吃全国吏怨与军心） |

**量纲（易错）**：`legacy.progress` 是 **0–1**、`focus.progress` 是 **0–100**，换算不得混用（`test_legacy_and_focus_progress_dimensions` 断言此点）。

## 3. 条件 DSL

### 3.1 Grammar（固定）

```python
condition = {"all" | "any": [node, ...], "streak": int}   # streak 仅允许出现在根节点
node      = {"metric": str, "arg": str | None,
             "op": ">=" | "<=" | ">" | "<" | "==" | "!=", "value": float | bool | str}
            | condition                                   # 嵌套深度 ≤ 3；子节点内不得出现 streak
```

- 空数组：`all: []` → 恒 `True`；`any: []` → 恒 `False`。
- 非法 `op`、未注册 `metric`、类型不匹配、深度超限、子节点含 `streak` → **建单即拒绝**（不建局势并记 error）。
- `resolve_condition` 与 `fail_condition` **各自独立**维护 streak。

### 3.2 metric 注册表（`core/situation_metrics.py`，唯一权威）

```python
METRICS: dict[str, MetricSpec]   # MetricSpec = (fn, arg_type, return_type, required_arg, missing_policy)
```

| metric | arg | 返回 | 缺失/异常策略 |
|---|---|---|---|
| `region.unrest` | 州路名 | float | 州不存在 → 缺失（记 error） |
| `region.public_support` | 州路名 | float | 同上（**农 POP 的民心通道**） |
| `region.gentry_resistance` | 州路名 | float | 同上（**士绅通道**） |
| `region.fiscal` | 州路名 | float | 同上（**工匠/商人的市面**） |
| `region.mood` | 州路名 | float | 同上 |
| `treasury` | — | float | 不可缺失 |
| `pop.size` / `pop.wealth` / `pop.grain` | 路\|阶层 | float | 路/阶层不存在 → 缺失（记 error） |
| `pop.wealth_per_capita` | 路\|阶层 | float | 同上；`size=0` → 0 |
| `pop.clan` | 路\|士绅 | float | 子池缺失 → 0（未初始化即无宗室） |
| `pop.clerks` | 路\|官僚 | float | 子池缺失 → 0（未初始化即无吏） |
| `pop.arrears_ratio` | 路\|阶层 | float | 欠税/wealth；缺 pop 或 wealth≤0 → 缺失（**不假装"无欠缴"**） |
| `pop.hoard_ratio` | 路\|士绅 | float | 窖银/wealth（窖藏＝不信任）；同上 |
| `clerks.grievance` / `clerks.grip` / `clerks.effective` | — | float | 吏制不可用 → 缺失（**不回落 0**） |
| `clerks.execution_mult` | — | float | 同上（`core/clerks.decree_execution_mult`，结算侧自身回落 1.0） |
| `clerks.route_grievance` / `clerks.route_grip` | 路名 | float | 该路无 `clerks_detail` → 缺失（**逐路不同，不得只取全国均值**） |
| `officials.waiting` | — | float | 官制不可用 → 缺失 |
| `officials.redundant_rate` / `officials.waiting_share` | — | float | 官额 0 或 `posts_quota<=0`（未定编）→ 缺失（**不得显示成冗官 100%**） |
| `faction.satisfaction` | 派系名 | float | 派系不存在 → 缺失（**不默认 50**） |
| `army.morale` / `army.troops` / `army.arrears` | 路名 | float | 该路无驻军 → 缺失 |
| `army.enforcement_mult` | 路名 | float | 该路无驻军 → 缺失（无兵可督行） |

**参数类型语义（易混）**：
- `州路名`：必须能在 `region_brief` 中找到该路，否则记 error（面板进 `partial`）；
- `路名`：路名合法即通过——**"该路无驻军/无吏制明细"是正常事实**，取值为 `None` 而非错误
  （否则内地无禁军会让 `readout_status` 长期 `partial`）；
- `派系名`：由 `state.factions` 自身枚举。

**规则**：① 未注册 metric 一律拒绝；② 任何 metric 抛异常 → **取值缺失并记 error**（不得静默返回 0）；③ 注册表是白名单，新增 metric 必须同时补测试；④ 快照还随带**已派生好**的通道读数（`clerks` / `clerks_routes` / `officials` / `factions` / `army` / `army_routes`），投影层不得重算这些算法。
**首批启用**：上表全部（以 `core/situation_metrics.METRICS` 为准；`region.grain_months` / `event_flag` 属 v2）。

### 3.3 快照与判定接口（`core/situations.py`）

```python
snapshot = build_metric_snapshot(state, metric_keys)   # 一次性取值；纯读取
ok = evaluate(condition, snapshot)                     # 纯函数：不接收 state、不访问全局
```

依赖方向固定：`situations → region_brief`（situations 可读它，**它不得读 situations**，防循环）。

### 3.4 判定顺序（固定）

```
① 建快照
② 评估 fail：命中则 streak_fail += 1，否则归零
③ fail 命中且达 fail.streak（无 streak 视为 1 次即中）→ status = failed
④ 否则评估 resolve：命中则 streak_ok += 1，否则归零；达 resolve.streak → status = resolved
⑤ 两者同回合命中 → 判 failed，并写 kind="冲突" 的 timeline
```

### 3.5 六类 POP 的**非经济维度**注册表（`POP_SENTIMENT_CHANNELS`，代码常量）

POP 给游戏带来的模拟**不止钱粮**：每一类 POP 都有自己的"心气"，且**逐路取值**（宋祚每路
POP 结构不同 → 心气不同）。**禁止**把非经济维度只做在官/吏/兵三类上。

| POP 类 | 通道（label） | primary metric | secondary metric | 权威来源 |
|---|---|---|---|---|
| 农 | 民心 | `region.public_support` | `pop.arrears_ratio`（路\|农） | `core/region_brief.py` + POP 欠税 |
| 士绅 | 士绅抵抗 | `region.gentry_resistance` | `pop.hoard_ratio`（窖银＝不信任） | `core/region_brief.py` + POP 窖银 |
| 工匠 | 工困（市面/欠缴） | `region.fiscal` | `pop.arrears_ratio`（路\|工匠） | `core/region_brief.py` + POP 欠税 |
| 商人 | 商情（市面/欠缴） | `region.fiscal` | `pop.arrears_ratio`（路\|商人） | `core/region_brief.py` + POP 欠税 |
| 官僚 | 官心（冗官/派系满意度） | `officials.redundant_rate` | `faction.satisfaction` | `core/officialdom.py` + `state.factions` |
| 兵 | 军心（士气/欠饷） | `army.morale` | `army.enforcement_mult` | `core/army_models.py` |
| **吏**（官僚 POP 的 `clerks` 子池，**不是第 7 类 POP**） | 吏怨/把持度 → 政令折扣 | `clerks.route_grievance` | `clerks.execution_mult` | `core/clerks.py` |

- 表是**代码事实**：`test_pop_channels.py::test_six_pop_channels_are_declared` 断言
  表键集合 == `GRAIN_CONSUME_PER_CAPITA` 的键集合，且每个 primary/secondary 都已注册；
- `build_situation_readout` 以 `pop_channels = {channels, nation, by_route}` 下发；
- 事件的 `severity` 追加 `noneco_stress`（§2.1）：

```
noneco_stress = 吏怨×8/100 + (1 − 军心/100)×6 + max(0, 士绅抵抗−30)/70×4      # 0–18
severity = clamp(70 + (unrest−50)×0.3 + pop_stress×20 + noneco_stress, 30, 100)
```
吏制读数整体缺失时 `noneco_stress` 上限压到 6（**不得**凭空判"吏怨极重"）。

### 3.6 诏令实际效果：**吏治强关联 ＋ 民心/识字率弱关联 ＋ 军队加成（可选杠杆）**

> **口径修正（用户两轮定稿 2026-09-19）**：
> ① 早期写的"实际效果 = 会签执行率 × 吏治折扣 × 军队督行"**是错的**——它把军队当成所有诏令的恒等乘数；
> ② 随后写的"民政诏令与军队无关"**也不对**——**玩家可以调兵来确保赈济、赋役、清丈、科举
> 等民政政令的强制施行**。正确口径：

```
实际效果 = 吏治（**唯一强关联**） × 民心 / 识字率（**弱关联**，幅度 ≤15%）
           ＋ 军队**强制施行加成**（把效果缺口向上补，最多 30%）
             · 军政/边事类：军队**天然参与**
             · 民政类：**玩家本回合调兵（enforce_troops）时参与**——不调兵则不加不减
```

**会签执行率本身就是吏治的表达**（官场配合度），故它与吏胥折扣同属"吏治"这一强关联项，
不是与吏治并列的第二个通道。

单点实现：`core/decree_effect.py`（`effect_channels` / `decree_effect_mult` / `decree_kind`）。

| 通道 | 强度 | 权威 | 口径 |
|---|---|---|---|
| 吏治（会签执行率） | **强** | `GameState.calc_decree_execution_rate` | 逐诏：立场 × 派系影响力 × 皇威等级；盘面只给**代理**（派系满意度加权，`proxy=true`），**禁止**当执行率 |
| 吏治（吏胥折扣） | **强** | `core/clerks.decree_execution_mult` | `max(0.3, 1 − 把持度×0.35)`；结算侧 `_settle_decrees` 实际乘它 |
| 民心 / 识字率 | 弱 | `population_satisfaction` ＋ **各地各类 POP 自有** `literacy` 加权派生 | `0.85 + 0.10×民心/100 + 0.05×识字率/100`，恒在 `[0.85, 1.0]`（§3.9） |
| 军队（强制施行） | **加成** | `core/army_models.military_channels` | 军队可靠度 = 兵额加权 `clamp(0.35 + 0.65×base − 欠饷惩罚, 0.35, 1.0)`；`effect = base + (1−base)×30%×可靠度` |

- **加成而非折扣**：调兵强制施行**绝不比不调兵差**，只是把"因吏治/民心办不到的那部分"补上来，
  军心越可靠补得越多 → 玩法上支持"赈济/赋役/清丈推不动？调兵压着办"。判定依据是**事务记录**
  （`defense_lines.*.garrison` 实际变化，见 `situation_settle.troops_mustered_this_turn`），
  **不靠诏令自述**。
- `decree_kind`：机构归属命中 `枢密院/兵部/三衙/殿前司…` 或文本命中军事关键词 → `军政`；
  **刻意保守**，拿不准判 `民政`（民政默认不调兵，军队不参与）。
- `unit_monthly_pay` 与 `calc_army_cash` **同源**（`branch_std`），不另设军费口径；
- 军队参与但**无驻军读数** → 军队项为 `None` 并注明"未计入"（**不**回落 1.0 假装无事）；
- 投影层下发 `execution_channels = {strong, clerks_mult, official_support(proxy), civil_mult,
  literacy, kind, military_applies, military_mult, combined_mult, note}`；
  `combined_mult` = 吏治 × 民事，**再按公式加上军队强制施行加成**；
- 帝修（`legacy`）不是执行对象 → `execution_channels = None`；
- **与事件 severity 的区分**：`noneco_stress`（§3.5）里的军心项衡量的是**该路危险程度**
  （兵 POP 心气），与"诏令能否办成"是两件事，勿混用。

### 3.9 识字率（**各地各类 POP 自有**，2026-09-19 新增设定）

> **「既然现在没有识字率，就加入识字率这个设定」**＋**「识字率应该是各地 POP 自有的」**

**挂载**：`prefectures[路]["pops"][阶层]["literacy"]`（0–100 的**比率指标**）。
它不是人口、不是钱粮，故不产生任何平行账本；逐路逐类各不相同——这正是"同一道诏令在
东南办得动、在边地办不动"的弱关联来源。

**口径**（`core/literacy.py`，确定性可测）：

```
阶级基准（content 内 POP_LITERACY_BASE，史实锚点）：
    官僚 92 / 士绅 75 / 商人 32 / 工匠 22 / 兵 8 / 农 5
地区调制 = clamp(0.75 + 0.30×民心/100 − 0.20×动乱/100 + 0.20×art_mastery/100, 0.50, 1.35)
目标识字率 = clamp(阶级基准 × 地区调制, 1, 98)
月度缓动：literacy += (目标 − 当前) × 6%          # 教育是慢变量，不跳变
```

**派生读（不落字段）**：逐路 `route_literacy`（该路各类按 `size` 加权）、
全国 `state.literacy = national_literacy`（全部 POP 按 `size` 加权）。
开局实测：全国 ≈ 8.5，官僚 ≈ 97、士绅 ≈ 81、商人 ≈ 34、工匠 ≈ 24、兵 ≈ 8.5、农 ≈ 5.4。

|---|---|
| 结算步 | Step **3.5.6** `_settle_literacy`（在地区深化之后；镜像 `_STEPS` 已同步） |
| 唯一写入点 | `settle_literacy`（只写 `pops.*.literacy` 与派生值 `state.literacy`） |

| 前端 | 州县详情「民生」栏显示识字率；局势面板弱关联标注"民心/识字率" |

### 3.7 利益集团 ⊆ POP 阶级（`FACTION_POP_BASIS` / `REFORM_POP_BASIS`）

**集团不是与 POP 并列的实体，而是某阶级（某子池、某路域）的子集。**

- `FACTION_POP_BASIS[name] = {pop_classes, subset_of, subset_kind, pool, routes, desc}`
  - `subset_kind ∈ {national, pool, route, pool+route, faction}`；校验 `subset_of ⊆ pop_classes`；
    （`faction` 为 2026-09-19 定稿：集团**按立场切**而非地域切，`routes=None` 全国，
     权威源 `core/faction_basis.py::SUBSET_KINDS`）
  - 例：**军功集团 ⊆ 兵 POP**（按"持军功立场"切，`routes=None` 全国），展示必须写成
    「军功集团 ⊆ 兵 POP（陕西路/河东路/河北路），占全国兵额 X%」，**不得并列展示**；
- `build_faction_channels(state)` 下发 `{factions, emerging, basis_table, declared, basis_errors}`，
  每个集团带 `basis_readout`（`pop_size` / `parent_pop_size` / `share` / `subset_note` / `troops` / `morale` / 地区心气）；
- **改革催生新集团**：`REFORM_POP_BASIS[改革标识] = {label, gain, lose, emergent}`，
  键为**已实现**的改革标识（诏令效果键 `land_survey`/`curtail_waste`/`reduce_office`/`hoard`/`reform`
  或国策 node_key `t1_land_survey`/`g3_curtail`/`g2_reform`/`m1_garrison`/`m3_war_machine`）。
  `emergent` 的新集团**必须带 `pop_basis`**，否则 `validate_faction_basis` 报错、
  `readout_status="partial"`——没有 POP 基本盘的集团不予登记（禁止"无源影响力"）；
- `gain`/`lose` 逐项写到 **POP 类**（可带 `pool`）与原因；v2 据此派生各集团满意度/影响力增量
  （基本盘受益则升、受损则降），**禁止凭空加减**。

### 3.8 AI 的角色：**权衡这些变数**（不产生数值）

- `core/briefing.build_weighing_note(state)` 生成只读的《权衡变数》文本，注入
  `ai/client.py::decree_execute_decide`（诏令拆解）与 `faction_decide`（党争推演）的**系统提示**：
  **吏治（强关联）→ 吏怨/把持折扣 ＋ 官场配合度代理**、民心/文书（弱关联）、
  **军队（仅军政/边事类加成）**、冗官/待阙 → 事权落地。
- AI 输出仍只有档位与叙事（`priority` / `satisfaction` / `influence` / `stance` / `narrative`），
  数值一律由程序按 §3.6 的 core 公式算；AI 缺失 → 程序兜底（现有契约不变）；
- **禁止**把精确盘面读数塞给 AI 之外的自由文本改盘面（§10 第 9 条仍生效）；`build_weighing_note`
  只读、不改状态，测试 `test_pop_channels.py::test_weighing_note_is_readonly_and_mentions_channels` 守此界。

## 4. 结算与推进

### 4.1 插入点

`_settle_situations` 位于 **`_settle_disaster`（Step 8）之后、`_settle_emperor_personal`（Step 9）之前**，使用本回合固定快照。位置以 `core/settlement.py::run_monthly_settlement` 内的**调用顺序**为准（规范不引用行号）。

### 4.2 单条局势处理伪代码（顺序不可变）

```
if record.status != "active":          continue        # 终态跳过
if record.last_settled_turn >= turn:   continue        # 幂等（§4.3）
skip_all = (record.origin_turn == turn)                # 当回合新建：整段跳过

snapshot = build_metric_snapshot(state, used_metrics(record))
intents  = 本回合未消费且 situation_id 匹配的 intent（§5）

if not skip_all:
    if not 扣 ongoing_cost(record):                    # 成对划转；不足 → deferred
        写 timeline("deferred")；不推进；record.last_settled_turn = turn；continue
    Δbar = GRADE_DELTA[grade] + record.inertia + intent_bonus
    record.bar_value = clamp(record.bar_value + Δbar, 0, 100)
    更新 streak 与终态判定（§3.4）
    若进入终态 → 执行 effect_on_resolve / effect_on_fail（§6）

record.last_settled_turn = turn
写 timeline（source="program"；AI 叙述见 §7）
```

**档位来源**：AI 返回档位（§7）或程序客观判据；AI 缺失 → 用 `inertia` 并按"程序推进"记录。

#### 4.2.1 档位 → Δbar 唯一映射表

| 档位 | verybad | bad | normal | good | verygood |
|---|---|---|---|---|---|
| Δbar | −8 | −4 | 0 | +5 | +10 |

- 单点定义：`core/situations.py::GRADE_DELTA`；
- `bar_value` 最终 clamp 到 `[0, 100]`；
- 未干预（无 intent）的自然漂移 = `inertia`（可为负）。

### 4.3 幂等

- `last_settled_turn` 是**结算幂等专用**字段，与"推进"语义分离；
- 结算入口断言 `last_settled_turn < turn`；成功处理后写等值；
- 同回合重复结算 → 全部跳过（不重复扣费/推进/判终态）。

## 5. 玩家意图（圣旨推进局势）

### 5.1 三条通道（仅此三条）

1. **改条件变量（间接）**：圣旨经既有 effects 落民心/动乱/军饷/粮储 → 条件更易满足。**已在生产可用**。
2. **显式意图 `SituationIntent`**：诏令携带 → 作为当月档位判定的输入。
3. **立项新局势**：仅 v2，仅 `event_pool`。

**禁止**：任何接口直接写 `bar_value`（除 §4.2 的档位映射与 inertia）。

### 5.2 生命周期与校验

- **生成**：`issue_decree` 时写入诏令对象的 `situation_intent`（可选字段；无则行为不变）。
- **读取**：Step 8.5 只读 `consumed_turn is None` 且属于本回合的 intent；处理后写 `consumed_turn=turn` 与 `validation_result`。
- **校验器**：唯一实现 `validate_intent(intent, settlement_delta) -> bool`，**只读本回合 `state_applier` 事务记录，不得由最终 state 反推**。

| kind | 校验依据 |
|---|---|
| `拨帑` / `赈济` | 本回合存在该局势 `region_hint` 方向的**成对**钱粮划转，金额 ≥ `amount` |
| `调兵` | 本回合存在 `army_units.station` / `troops` 实际变化，且目标与 `region_hint` 匹配 |
| `查办` | 本回合存在相应人物的 `indictments` / 人事变更记录 |
| `减免` / `蠲赋` | 本回合存在对应税制字段的实际变化 |

- 校验不过 → 不推进（`validation_result="fail"`），仅记 timeline；
- `region_hint` 与 intent 指向不一致 → 直接丢弃。

### 5.3 排序与限额（固定）

```python
KIND_PRIORITY = ["调兵", "拨帑", "赈济", "查办", "减免", "蠲赋"]   # 索引小者优先
```

- 同局势同回合多条 intent → 取 `KIND_PRIORITY` 最前者，其余记 timeline，**不叠加**；
- **不跨单位比较 `amount`**（贯/石/人数不可比）；
- 全局每回合上限 **3 条**有效 intent：按 `(turn, decree_id, situation_id)` 稳定排序取前三。

## 6. 效果契约（`state_applier`）

### 6.1 冻结方案

- 程序效果与 AI 效果**调用同一批量事务 API**；
- **任一效果失败 → 整条局势事务回滚**（不做部分应用）；
- 效果白名单**只有一份注册表**。

### 6.2 注册式路径表（未注册路径一律拒绝）

| 路径模板 | 单位 | 守恒组 | 对手方 | 容差 | reason 枚举 |
|---|---|---|---|---|---|
| `state.treasury` | 贯 | money | POP.wealth / `imperial_treasury` / `local_treasury` | 200 | 局势代价、局势效果 |
| `state.imperial_treasury` | 贯 | money | `treasury` / POP.wealth | 200 | 同上 |
| `prefectures.{路}.pops.{阶层}.wealth` | 贯 | money | `treasury` / `imperial_treasury` | 200 | 同上 |
| `granary` | 石 | grain | POP.grain / `prefectures.{路}.storage` | 200 | 局势代价、赈济、损耗 |
| `prefectures.{路}.pops.{阶层}.grain` | 石 | grain | `granary` / `storage` | 200 | 同上 |
| `prefectures.{路}.storage` | 石 | grain | `granary` | 200 | 同上 |
| `prestige` | — | 无 | — | — | 局势效果 |
| `population_satisfaction` | — | 无 | — | — | 局势效果 |

**首批白名单 = 上表**。`unrest`、`public_support`、`gentry_resistance`、`fiscal`、税率、`clerks.*`、`tax_base.*` 首批**移出白名单**，后续单独评审加入。

### 6.3 人口规则

- **禁止**任何效果直接写 `pops.*.size`；
- 人口变动**只能**调用既有 POP 流动 / 自然增减接口，并在 `reason` 登记；
- 若所需人口接口不存在 → **该局势首批不启用该效果**。

### 6.4 顺序与 deferred

固定顺序：`读快照 → intent 校验 → 扣 ongoing_cost → 更新 bar → 更新 streak → 判 fail → 判 resolve → 执行终态效果`。

- 新建局势（`origin_turn == turn`）跳过整段；
- 终态不扣代价；
- 资财不足 → 记 `deferred`（timeline），**本月不推进**（不得静默扣）。

## 7. AI 契约

### 7.1 输入（固定）

- 注入：`title`、`severity` 档位、`bar` 档位、条件文本、最近 **3** 条 timeline、玩家 intent 文本；
- **禁止注入当前真实读数**（国库/民心/军饷等一律走既有脱敏档位）；
- 条件阈值文字允许包含（阈值是规则，不是盘面读数）；
- 按 `severity` 降序取 **≤8** 条；**未变化局势只注入标题**。

### 7.2 输出（固定 schema）

```json
{"situation_id": "event_pool:shaanxi_bandits", "grade": "good", "narrative": null}
```

- `grade ∈ {verybad, bad, normal, good, verygood}`；`narrative` 可为 `null`；
- 只接受白名单字段；**非法档位 / 缺字段 / 重复 `situation_id` / 未知 id / 越权字段 → 该条进程序兜底，不改变任何状态**；
- 单局势单回合最多 1 次重试，失败即兜底。

### 7.3 AI 文本入库

AI 输出先存**临时变量**；通过 schema / `narrative_guard` / 来源校验后，与状态变更**同一事务**提交，成功后一次性写 `timeline`（`source="ai"`）。**节点事件仅为叙述，不改状态。**

## 14. 2026-10-02 现状复核与改进建议

本节根据当前核心代码、前端面板、`decree-action-chain/tasks.md` 与本地交接镜像补充。它用于标出现状边界和后续优先级；不得将“读数投影完成”理解为“所有政令都能自动执行”。

### 14.1 当前已经形成的闭环

| 能力 | 当前实现 | 边界 |
|---|---|---|
| 多来源局势总览 | `build_situation_readout` 汇聚帝国修正、国策焦点、长期制度、`state.situations` 记录和事件，并附六类 POP 心气、集团基本盘、执行通道 | 这是只读投影；旧来源仍由各自模块持有状态 |
| 自定义局势记录 | `SituationRecord` 校验、指标 DSL、达成/失败条件、持续成本、终态效果、幂等与存档迁移；Step 8.5 月结 | 仅 `event_pool` 记录落入 `state.situations`；不代表每条圣旨自动生成一条可执行事务 |
| AI 月度研判 | AI 契约只接收合法档位/叙事；数值变化由程序公式结算，失败时按规范走程序路径，不接收 AI 自报数值 | AI 失败/缺档与客观 `normal` 档位应在读数和时间线上持续区分，不能让兜底叙事伪装成模型判断 |
| 诏令意图 | `_settle_decrees` 可读取诏令携带的 `situation_intent`；局势结算依据本回合事务日志验证并消费，意图加成受执行度折减 | 上游是否为每种诏令动作稳定地产生结构化意图，仍须逐类核实；无意图不妨碍常规诏令效果，但不能宣称已实现自动映射 |
| 事务“告成”防伪 | `longterm_task.monthly_advance` 对无 handler 的满进度事务返回 `unsupported/待支持`；有 handler 的事项根据注册表记录的落点支持推进 | handler 可能标记效果在下诏时或逐月生效；政治进度到 100% 不应被 UI 解读为该月才首次产生数值效果 |
| 玩家可见性 | `/api/readouts` 下发局势投影；`SituationPanel` 提供局势、六类心气、集团页签，州路面板可双向跳转 | 面板以观察/解释为主，尚非行动编排器；由圣旨/政务界面承接执行操作 |

### 14.2 需要纠正的文档与治理问题

1. **旧测试基线已过时**：§12.1 原 `590 passed` 是历史阶段数据，现已标明；交接镜像报告 2068 passed，但本次未复跑，不能把镜像当成本轮实测。
2. **局势总览不等于共用状态机**：面板聚合不同来源，不等于这些来源共用同一个状态机；`legacy`、`focus`、`free_effect`、事务队列与 `event_pool` 仍须由原模块写入。
3. **圣旨“意图”有契约、无普遍自动映射保证**：意图只在对象携带时进入本回合瞬态列表，并要求对应动作的真实事务证据。不能仅凭诏令文字命中“赈济/拨帑/调兵”就视为动作成功；要逐项审查 `decree-action-chain` 中动作到 handler、效果、审计日志的映射。
4. **行动闭环任务状态需同步**：`decree-action-chain/tasks.md` 仍列长期事务 handler 校验为待做，但当前代码已有 `TASK_HANDLERS`、无 handler 的 `待支持` 分支和结算分流。应在相应规格任务中核实测试与面板状态后更新任务标记，避免任务表继续报已实现代码为缺失；不能据此宣称整个圣旨行动链已完成。

### 14.3 建议实施顺序

| 优先级 | 建议 | 验收断言 |
|---|---|---|
| P0 · 口径同步 | 核对 `decree-action-chain/tasks.md` 的长期事务 handler 项：覆盖范围、无 handler 的 `unsupported`、有 handler 的实际效果时点和相应回归；分别标记已完成/未完成 | 任务表每一项可指向代码和测试；不把“handler 存在”误当成“效果在事务完成时才应用” |
| P0 · 行动来源 | 梳理圣旨、口谕、中旨、密旨到 `situation_intent` / ActionPlan 的生成路径；优先让已落地的结构化命令产生可追踪意图，不从自由文本猜执行结果 | 每个有效意图具有 decree/action ID、目标局势、动作类型、目标地域、量纲金额和本回合执行凭据；失败、未执行与不适用有不同状态 |
| P1 · 因果可读 | 为局势时间线统一展示“旨意/官员响应/授权资源/程序动作/效果落点/受影响 POP”；摘要可展开查看原因和来源 | 玩家能从局势卡片追到本月具体动作与钱粮/人口去向；没有因果证据时显示“未核实/未执行”，不生成完成叙事 |
| P1 · 状态命名 | 统一区分政治议毕、事务进度满、程序效果已执行、长期效果仍生效、待支持、执行受阻；长期效果有明确开始/停止条件与责任主体 | 互斥终态不重叠；持久制度到期/失效有日志，不只把事务从队列移除 |
| P2 · 推演韧性 | 以固定种子覆盖 AI 成功/失败/超时、缺失指标、读档迁移、重复结算、多个 Agent 异议 | 同种子程序结果可复现；AI 只改变允许的研判/叙事，不越权写盘面；退化路径在界面可见 |
| P2 · 面板体验 | 局势面板加入“本月变化/卡点/下一步可做”摘要和来源下钻；只读观察与可执行按钮分开，行动回到对应圣旨/政务界面 | 玩家能看懂为何停滞、谁有权限、缺何资源；无权限或未注册动作不出现可点击的假 CTA |

### 14.4 实施纪律

- 当前结论是**局势读数与基础结算已落地，后续重点是圣旨行动链、因果可解释性和任务状态同步**；不需要重做局势 DSL 或新建第二套事务系统。
- 改动人口、钱粮、执行率、随机推进或终态效果属于核心模拟变化：先定口径与影响，再加定向回归；只改面板或文档不改结算算法。
- 更新“已完成”状态前，对照当前代码、对应回归和真实月度流程；文档任务表、UI 标签和代码不得互相矛盾。
- 读数缺失保持 `None` / 未定义；程序兜底须标注来源，不能用默认 0、1 或通用“办理顺利”掩盖不确定性。
