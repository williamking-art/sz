# 民间经济与营造市场统一设计（讨论稿）

> **目的**：在《宋祚》的宋代经济背景下，统一 POP 生活需求、商品与建材市场、粮食、官民仓储、官营/民营、政府与民间建筑，以及 AI 推演中的新内容提案。
> **状态**：设计讨论稿，尚未替代或修改《民间需求与营造材料市场设计.md》中的既有定论，也不代表已实施。
> **核心定位**：这是一款 AI 推演游戏。经济规则提供因果边界与真实账本，AI 在边界内决定人物、地方与机构如何应对；不把每月推演写成固定行为脚本。市场不是商品清单，而是“生产主体—商品/服务—交易与运输—POP及机构用途—收入与再投资”的地方经济网络。
> **关联文档**：`民间需求与营造材料市场设计.md`、`游戏机制说明.md`、`货币口径规范_M0M1M2.md`、`specs/decree-action-chain/`。

## 1. 设计目标

把当前偏重“政府抽税—政府支出”的循环扩成有民间供需和社会反应的经济推演：

```text
自然与技术条件
  → 农业、手工业、官营和民营生产
  → POP 与商人持有真实库存
  → 本地交易、跨州府贸易、官府采购与仓储调拨
  → 家庭消费、生产投入、营造与军需
  → 价格、收入、短缺、税源、民心、迁徙和政策反应
  → AI 基于新局势提出下一步行动
```

设计应同时满足：

1. 民间消费由生活需求驱动，也受财富余量、价格和可供货量约束。
2. 木、石、砖等营造材料进入真实市场；官府工程与民间营造都能采购和消耗实物。
3. 口粮、商品粮、官仓粮、民间库存具有清楚的归属和转移关系。
4. 官营、专营、许可经营、民营和官府采购是不同经营关系，不是互相替代的经济系统。
5. 新科技、新商品、新蓝图、新装备可以由玩家或 AI 提出，并经验证后进入本局推演。
6. AI 保有充分的策略、偏好、判断和创意空间；确定性代码负责账本、库存、边界校验和已注册效果的执行。
7. 商品目录应能表达从原料、加工品到服务的相互依赖；产业深度来自链条、地域差异、经营主体和冲击传播，不靠给每个物件都造独立数值。
8. 设计目标是州府级地方市场；在州府实体、POP挂载和汇总口径实际建成前，禁止把当前“路级”数据称为已经具备州府级模拟。
9. POP 从全国六类阶层总量进一步深化到州府生计群组，让就业、财富、消费、服务可达、迁徙和身份变化进入因果，同时保留人口与货币守恒。
10. 宋、辽、西夏、大理及之后新并入的领土使用同一地域和 POP/市场数据模型；政权只决定制度与聚合，不另造一套冲突的地方经济真账。
11. 边境贸易和海贸必须有可识别的买卖双方、货物来源/去向、运输路径和付款对手；市舶司是监管/征税/许可机构，不是默认的无限买家。

## 2. 已有定论与本稿关系

以下内容沿用既有初步设计，不在本稿中改成相反口径：

- 民间需求与财富余量共同决定消费，余量不足时不能强迫 POP 消费。
- 营造材料接入贸易；民间建筑也有营造材料需求。
- 建筑造价与材料用量挂钩，加大投入可以缩短工期。
- 加速使用边际递减曲线；基准造价/工期与赶工预算分开表达。
- 木、石、砖是早期建材；水泥、钢筋等新材须经玩家科研或本局技术发展解锁。
- 金、银、铜的实物存量不自动兑换成货币。
- 账目和实物必须有对手方，不凭空生成钱粮、商品或建筑材料。

本稿补充商品供需的真实成交、官民仓储、生产链、服务业、生活需求层级、建筑与市场互动，以及 AI 自由推演的边界。遇到冲突时，应先回到以上权威文档和用户已定口径，不默默覆盖。本稿仍是**待讨论设计**；下文的商品、服务、主体字段、市场网络和分期均非“当前已实现”声明，也不直接授权修改核心结算。

## 3. 历史语境与模拟抽象

游戏以北宋 1101 年为开局背景。宋代商业与货币流通发达，但经济并非现代自由市场；官府也并非所有行业都直接生产。不同商品、地区和时期可以有民营生产、官营供给、专卖/许可、官府采购及民商协作等不同安排。

因此，规则不应全局设为“自由市场”或“国家统购”。应让制度按商品与政策分别配置：

- 日常布帛、木器、陶器等可以由民间生产和商人流通为主。
- 茶、盐、酒等可受专卖、许可、官府批售或税制影响；其生产和运输仍可包含商人参与。
- 官府可直接营造，也可向民间采购、委托运输或征调物资；不同方式有不同成本、速度、民怨与寻租风险。
- 历史抽象要服务于可玩推演，不强求全国各路使用完全相同的产业结构。

具体制度的地区与年份适用性尚需史料和游戏资料进一步确认；材料不足的制度细节应标为待考，不作为硬编码事实。

### 3.1 产业组织原则：不是现代产业分类的硬套

产业链按“地方可获得的原料、生产技能、燃料、劳力、交通和需求”形成。州府不必拥有每个产业，也不要求所有链条闭合：缺失环节可由邻近市场、跨区域商路、进口、官府采购或替代工艺弥补；若都不可用，表现为停工、涨价、降质、转产或迁出。

- 生产主体可以是兼业农户、家庭手工业、作坊、商户、船户、官营机构、承包/受命经营者。并非每种产业都要先建一座大型工厂。
- 建筑类型提供产能、岗位、储存、服务或制度权限；“有建筑”不等于免费产出，还要核对工匠、投入品、维护和销售条件。
- 同一种产出可有不同工艺路线和经营方式。AI可提出本地替代路线；只有登记过的投入/产出与效果可以进入数值结算。
- 商品与服务以需求和生产关系驱动，不设置全国统一的固定产业配比。战乱、灾害、政策、技术或交通变化应能改写地方分工。

具体的行业史实和制度细节按商品、地区、年份逐条核实；候选产业链是玩法模型，不代表每个行业在1101年每个州府都已普遍存在。

## 4. 统一对象：需求、商品、库存、用途、交易

系统中分开表达五个对象：

| 对象 | 说明 | 例子 |
|---|---|---|
| 需求 | 主体希望满足的用途和规模 | 口粮、衣料、住房修缮、军需 |
| 商品 | 可生产或采集的实物类型 | 粮、布、绸、木、砖、铁器 |
| 库存 | 商品当前由哪个主体持有、位于何处 | 农 POP 粮、商人货栈、官仓 |
| 用途/状态 | 库存可否出售、已否预留或拨用 | 自留粮、待售粮、赈济粮、工程预留料 |
| 交易/调拨 | 库存和货币从谁转给谁 | POP 购买、官府采购、平粜、赈济 |

同一单位实物在任一时点只能有一个所有者/库存归属。预留只改变“可用状态”，不能再复制一份库存。消费、损耗、加工、运输损失和外贸都必须作为明确流量记录。

### 4.1 POP 与资产边界

- 人口、财富、粮食及 POP 持有的商品沿用 POP 账本和既有子池；不得另建平行的人口或民间钱账。
- 政府财物和官仓沿用政权/地方的资源与仓储结构，明确财政归属和用途。
- 建筑是持续性资产，目标是挂在州府实体的建筑存量或现有项目/建筑结构中；州府实体迁移完成前沿用当前建筑/项目承载结构并显式标注其路级范围。营造资金来自出资方，材料和工时不能重复计价。
- 商人库存若挂在商人 POP，则不得同时全额记入另一份市场总库存；“市场库存”是对底层库存的只读汇总或临时撮合视图。

### 4.2 空间粒度：州府是目标，路级是当前代码事实

设计目标是每个**州府经济节点**有本地 POP、生产与服务主体、持有库存、需求、价格及建筑/项目，并通过有容量和成本的交通边与其他节点连接。路作为行政和统计汇总层，不替代州府市场。

截至本稿本轮核对，代码中的 `state.prefectures` 键仍是20个“路”级区域；人口、粮食产量、库存和市场价格等目前也以路级聚合为主。现有地图州府几何、府名或城市点不能证明经济结算已下沉到州府。州府级粒度必须作为独立的数据建模与迁移工作：明确州府实体 ID、POP 从路到州府的拆分依据、初始库存/产量分配、府间贸易边、路级读数聚合，以及旧存档迁移；不得按地图面积或等比例随意拆分 POP 和库存。

在该迁移完成前，实施阶段应先做路级兼容验证，并在 UI/文档标清聚合层级。迁移后，各路价格、供需和税收等读数由下辖州府计算结果聚合，不允许出现“州府界面 + 路级单一价格”冒充州府数据。州府内的县、镇、村暂作 AI 描述或产业来源标签，不要求第一阶段单独结算。

### 4.3 生产与服务主体

商品与服务必须归属于有决策与账务责任的主体。首阶段可采用确定性结算的经营实体数据，而非让每个家庭/店铺都单独请求 LLM：

| 主体 | 典型活动 | 资产与责任 |
|---|---|---|
| POP家庭/农户 | 种植、养殖、采集、家庭纺织、自用与余货出售 | 沿用 POP 的财富、粮食与货物字段；兼业收入、支出和存货不能另建平行人口钱账 |
| 民间作坊/商户/运输经营者 | 加工、买卖、仓储、运输、维修、旅店和服务 | 由现有或新增的生产/经营实体结构表达所有者、出资、配方、能力、雇工和库存归属；不能只因叙事创建无账经营体 |
| 官府/官营机构 | 官营生产、采购、仓储、专营、工程和公共服务 | 支出由国库或既有预算账户承担；产物和库存登记官有主体/用途 |
| 工程/项目 | 采购材料、雇工、施工、形成资产 | 临时预留库存与支出来源明确，完工后转为建筑/设施资产并登记维护方 |

具名官员仍以个体 Agent 决策；大型商户、行会、作坊主或地方经营者可成为具名/组织 Agent。其余经济活动可按州府、行业、POP职业群聚合结算。不得为了产业链方便另造与六类 POP 平行的人口或民间现金池。新增经营主体模型需要先确认与既有 POP、M0-M3、库存账户的挂载关系。

### 4.4 商品目录与配方关系

商品定义至少需要：唯一键与显示名、计量单位、存储/易腐/易损特征、基础价值或定价来源、用途、生产/采集方式、投入品与副产物、所需劳力/技能/燃料、地区/季节/科技条件、可替代关系、经营与管制方式。字段缺失不得静默当作零成本、零损耗或无限供给。

商品按需求与链条分层登记，不要求所有条目一开始都有复杂配方：

1. **生计与日用**：粮食（按用途分账）、豆类、蔬菜、鱼肉、盐、油、柴炭、麻布、常用陶器、鞋履、灯烛等。
2. **农林原料**：种子/种苗、牲畜与役畜服务、肥料/粪肥（早期可作农业投入能力）、木材、竹、麻、蚕茧/生丝、茶、药材等。
3. **基础加工料**：麻线/丝线、布帛、染料、铁、铜、木板/构件、砖瓦、石灰、纸、酒、油、酱醋等。
4. **工具与耐用品**：犁具、农具、锄镰、铁锅、木器、车具、船件、家具、衣物和书册。
5. **高阶、制度性与区域货**：绢帛、瓷器、茶、盐、酒、药材、精细纸品、军器、外销货等；专营/许可证单独作为经营制度字段。

候选链条（具体是否拆成独立可交易 SKU，由实现阶段按玩法与存档负担裁定）：

| 链条 | 主要投入 → 产出/服务 | 下游用途与短缺传播 |
|---|---|---|
| 农业与口粮 | 种粮、农具、役畜/耕作劳力、肥力与水利 → 粮食、豆类、油料、蔬菜 | 家庭口粮、种粮、官粮、饲料/加工、市场出售；农具或灌溉不足影响来季供给 |
| 畜牧、渔业与食品加工 | 饲草、养殖/捕捞劳力、盐、燃料 → 肉、鱼、皮毛、腌制品、油、酒、酱醋 | POP消费、军需、商旅餐饮；保鲜和盐不足增加损耗或缩短销售半径 |
| 林业、采矿与燃料 | 山林/矿源、采集劳力、工具 → 木竹、柴炭、煤（地区性）、矿石、石料、陶土 | 家庭燃料、窑炉、冶炼、船造、营造；燃料短缺会同时压低多个加工行业产能 |
| 纺织与染整 | 麻/蚕茧/生丝、纺织劳力、染料与燃料 → 线、麻布、绢帛、染布、成衣 | POP衣着、军衣、贸易与奢侈消费；原料和染料价格影响作坊开工及成品价 |
| 冶炼与工具 | 铁/铜矿、燃料、熟练工匠 → 金属、农具、工具、锅具、钉件、兵器 | 农业、建筑、船业、军需和维修；金属制品可耐用、维修、报废回收，不等于当月全量消费 |
| 陶作、砖瓦与窑业 | 陶土/黏土、燃料、水、窑工 → 陶器、砖、瓦、瓷器（按技术/地区） | 家庭器皿、仓储、营造、商贸；窑炉燃料争用会牵动民用燃料和其他加工 |
| 纸墨、书籍与文具 | 纸料/纤维、竹木、墨料、工匠与印制能力 → 纸、墨、账簿、书册 | 官府文书、教育、商业记账、文化消费；需求可由官府采购和民间市场共同产生 |
| 营造、家具与修缮 | 木石砖瓦、石灰、金属件、工具、工匠、运输 → 房屋、桥梁、道路、仓场、家具及维护服务 | 官民建设共享材料/劳工/运力；工程高峰挤占民间建材和工匠会涨价或延期 |
| 船舶与水陆运输 | 船木、绳索、帆布、铁件、车畜、劳力、港渡/道路条件 → 船、车队、运力、渡运/搬运服务 | 决定本地余货能否成为外地供给；水路/陆路受季节、治安、维护和政策影响 |
| 军需与防务 | 铁器、木料、布帛、皮革、绳索、粮草、匠作及技术 → 装备、修造和军需服务 | 由官府/军队采购或官营供应，可能与民用争用原料、匠人与运力 |

原料—半成品—成品可有多级转换与联产品；配方扣除和产出须同一结算记录，不能原料不减而成品增加。可替代关系由等级、质量、地域习惯、价格和技术共同影响，不把替代写成必然等量转换。库存与账本采用的40–60种首批核心商品只是实施容量建议，不是把上表限定为固定清单；地域性、时代性和 AI 创造内容通过扩展注册表增加。

### 4.5 服务业：不入货仓，按产能与成交结算

服务不是虚构库存，也不能只加一个“服务业繁荣”修正值。每种服务至少描述服务提供者/所有者、可供工时或月容量、所需劳力技能/设施、服务价格或费用来源、实际服务量、受益对象、质量/覆盖、付款去向和未满足量。服务提供者的收入落到相应 POP 或政府账户；劳工工资和经营盈余沿已有货币与 POP 口径结算。服务未使用的产能不能存到下月。

| 服务类别 | 提供者/承载建筑 | 消费者与机制效果 | 关键约束 |
|---|---|---|---|
| 运输、搬运、渡运、船运 | 脚夫、车户、船户、渡口、驿运/商运经营者 | 商户、POP、官府、工程；形成货物位移、到货时间和物流费用 | 道路/河道/港渡、季节、治安、载重、畜力、燃料和维修 |
| 集市、牙人、批发零售 | 市集、摊贩、行商、牙人/经纪 | 买卖双方；撮合交易、承担佣金或市税、扩展本地市场可达性 | 买卖双方库存/购买力、准入制度、市场开放日与治安 |
| 仓储、保管与货栈 | 官仓、民仓、商仓、邸店 | POP、商户、官府、工程；提高存储与跨期调拨能力 | 仓容、持有人、损耗、守护、费用；不能把在库货再算作可售新供给 |
| 磨、榨、酿、染、锻、烧窑等加工 | 家庭副业、作坊、磨坊、染坊、铁作、窑场 | POP、商户、官营机构；作为配方加工/委托加工 | 原料、燃料、水、技艺、设备产能和废品/副产物 |
| 营造与维修 | 木匠、瓦匠、石匠、铁匠、工头、修船匠 | 民居、商户、官府、工程；施工、养护、修理耐用品 | 合格工匠、材料、季节、组织能力、工期和维护预算 |
| 商旅与住宿餐饮 | 旅店/邸店、酒肆、食店、茶坊 | 商旅、官差、居民；服务消费并带来城市就业和客流需求 | 客流、安全、食材、饮水、燃料、床位和地方风俗 |
| 医疗与救助 | 医者、药铺、官/民救济机构 | POP、军队、灾民；影响病患恢复、灾害损失和劳力可用性 | 医者/药材、费用或财政拨付、可达性；疗效不作确定保证 |
| 教育、书写与文书 | 学校、书院、塾师、抄写/账房服务者 | POP、官府、商户；提供教学、契约、账簿和行政文书能力 | 教师、纸墨、设施、学期与经费；识字增长有时滞 |
| 金融与信用中介 | 典当、借贷/兑换、商人合伙等抽象经营活动 | 家庭、商户、工程与官府；缓解短期资金周转、收取费用并承担违约风险 | 借贷双方、偿付来源、期限、担保/关系、利息与制度限制；不得凭空创造净财富 |
| 公共事务服务 | 河渠、道路、桥梁、堤防维护；治安、消防、学校等机构 | 全体或特定受益地区；降低损耗和风险、提高公共设施可用度 | 预算、役工/雇工、材料、协作与执行官员；服务覆盖可能不均 |

市场服务与公共服务要区分：商人运输靠运费和客货需求维持；官道维护可由财政/役务支出提供，降低商户实际运输摩擦，但仍需车船经营者和劳工完成具体运送。官府兴建仓场可提供储备能力，不能自动代替民间储运；公立学校、赈济、治安等以公共预算或制度供给为主，也会与民间经营服务并存。信贷先以有借有还、期限和违约为原则，不把借款算作收入或新增社会财富。

### 4.6 货物流、服务流与市场撮合顺序

以下是**一个月结算边界内**的逻辑顺序，不是每笔交易都即时跳动游戏时间；具体程序拆步以核心结算流水线为准：

1. 读取各州府期初库存、生产能力、POP需求、工程/军需订单及交通状态；库存区分自留、待售、仓储、在途和项目预留。
2. 家庭/作坊/官营主体提出生产与售货意向；以投入品、劳力、燃料、水、技术、能力和资金约束可实现产量。若原料尚未到货，不得同月重复承诺出货。
3. 服务主体报告可用容量与费用；服务按具体需求撮合，如运输服务承载跨府商品、加工服务接单消耗原料、营造劳务服务于项目。
4. 本地优先撮合 POP 基本需求、生产投入和已承诺订单；可售量扣除自留、预留、合同锁定及在途部分。AI 可改变优先级/策略，但引擎复核预算、权限和库存。
5. 剩余需求与余货沿交通网络寻找可达节点。只有付出运输服务、运费、时间及必要损耗/风险后，货物才成为目的地到货；不能用全国总库存直接抹平本地短缺。
6. 货物成交、服务成交、货币转移、原料消耗、工钱、税费、运输费与库存变更逐笔落账；成交价按商品×州府×时间窗发现，并显示管制价、合同价或缺失原因。
7. 结算家庭实际消费、耐用品折耗、生产/工程领料、仓储损耗和公共服务覆盖；未满足需求保留为短缺读数，不造货或直接当作已消费。
8. 更新期末库存、收入/支出、行业存续/退出信号、POP生活水平、税源、价格、项目进度及下一期 AI 可观察的因果摘要。

AI 可探索不同市场顺序、跨期囤货、优先军需、平粜、商路协作或地方调配等行为，但必须给出交易主体、来源、去向和代价。月度处理顺序不能形成“先消费不存在的产出、再用市场补原料”的循环创造。

### 4.7 月回合边界：月内操作、过月推演和结算是三件事

本游戏以月为推进单位。玩家在当前月内的召对、拟旨、批红、调拨和政策操作，不应被误认为游戏在后台已经逐日模拟；有些操作即时登记，有些进入待执行队列，还有些只改变对话记忆。**只有进入月度推进流程，时间才向前走一个月。**具体每项命令是即时、待批、当月生效还是下月生效，必须由命令执行状态说明，不能让叙事文本暗示生效。

每次过月建议明确为：

1. **冻结月初状态**：锁定本月开始时的 POP、库存、预算、建筑、交通、在办项目及玩家已提交命令；该快照是本月所有可用资源的基准。
2. **取入当月情势和玩家命令**：读取已批准/待执行旨意、事件、Agent 记忆与上月结果；区分“玩家做过的交互”与“已形成机械状态的命令”。
3. **运行一次回合级 AI 推演**：调用经济 Agent 和按条件唤醒的领域 Agent，输出结构化意图、判断档位、优先级/风险及可追踪的依据。不是给每个 POP、作坊或交易都单独调用一次 AI。
4. **程序按唯一月结流程执行**：用月初资源和已到货投入完成生产、成交、物流、消费、服务、工程、财政等结算。未注册的 AI 提案不执行；月中在途商品不可提前消费或再投产。
5. **形成月末状态与下月输入**：记入月末库存、在途、收入支出、欠项、项目进度和服务覆盖；已完成的建设/研发按约定时点启用；生成可追踪的因果记录，供玩家查看和下月 Agent 使用。

过月流程可在结算内部安排多个模拟阶段，但这些阶段都属于同一个月，不能隐含多推进几个月。玩家等待的后台 AI 生成、月报富化或 UI 演出也不是额外模拟时间。若某设施在月末才建成，应明确其效果从当月结算的哪个步位起或下月起生效，并全项目统一，不许因 UI 展示先后而改变。

## 4.8 玩家月内交互是否影响过月 AI

不应要求玩家在“过月前持续和 AI 对话”，也不应因玩家本月没有打开某个 AI 面板就降低过月 AI 的推演质量。回合 AI 需要在过月时读取**权威游戏状态与结构化命令**，而不是依赖玩家刚好触发过某个聊天调用。月内交互的影响按以下边界区分：

- **已经落地的命令/状态变更**：应进入过月 AI 的上下文或被结算程序直接读取；例如批准的圣旨、已立项工程、预算与在办事务。
- **Agent 记忆**：此前奏对、协商等形成的公开承诺/关系事实，可按权限和相关性送给对应 Agent；私密记忆不得泄给无权 Agent。
- **尚未批准的提案**：AI 可以在月度推演中评估或续办，但不能当作已下达命令；必须保留 proposed/pending/approved/executing/completed/rejected 等状态差异。
- **纯叙事聊天**：若没有写入结构化状态、相关 Agent 记忆或待办，不应暗中改变经济结算。若游戏希望聊天承诺产生影响，就须明确记录其主体、对象、期限、授权和执行状态。

当前实现差距需特别标明：月结前的 `economy_decide` 虽有可接收 `state` 的签名，但当前结算调用只传 `state.posture`；契约注明本方法目前只消费 posture，具体世界状态由程序结算读取。被唤醒的外交、军事、灾荒等部分 Agent 会接收 `state`，其他调用按其契约而定。因此现状是**过月时确有 AI 推演，但不是全知全域、逐行业 Agent 仿真；经济 AI 与当月微观状态之间的连接尤其有限**。后续应逐契约列清输入，不可笼统写“AI 已阅读全局状态”。

### 4.9 POP 需要深化，但不应把每个人都做成 Agent

当前宋境 POP 以六类（农、士绅、工匠、商人、官僚、兵）聚合，核心字段覆盖人数、财富、粮食及部分商品/身份子池；官僚内部官吏、农户隐户等另有挂载子池，兵额以军队实体为准。这个模型适合全国总账和月度总量结算，但不足以直接表达“谁在什么地方从事什么工作、拿到什么收入、买不到什么服务，以及一次领土变更具体影响了谁”。

改良原则是**保留六类作为政治和财务汇总层，在其下按玩法需要增加州府级 POP 群组/生计画像**，而非删除旧阶层或引入几十种孤立人口账本：

| 群组维度 | 用途 | 建议约束 |
|---|---|---|
| 地点 | 明确某州府/区域的居民归属，连接当地市场、建筑、服务与行政 | 每个群组只有一个稳定 `territory_id`；路/政权人口为聚合读数 |
| 社会阶层 | 沿用现有六类，连接现行阶层政策、税负、政治关系和账务口径 | 六类人数仍可从下层群组求和；官吏/隐户/军人子池继续遵守现有挂载律 |
| 生计/职业 | 农业自耕、佃作、雇农、家庭纺织、作坊、商贸、运输、营造、公共服务等 | 只有当收入、需求、生产或政策效果不同，才细分；允许兼业和季节性转换 |
| 家庭与劳力 | 扶养人口、劳动参与、家户规模及季节劳力 | 先做粗档或占比；只有影响口粮、赋役、就业和兵源的字段进入数值结算 |
| 财富/资产状况 | 影响可支付需求、储蓄、住房、经营投资和债务风险 | 分档可用于行为差异，真实钱粮仍挂 POP/经营主体账，不用“富裕度”替代资产账 |
| 技能、识字与服务接入 | 影响职业转换、生产率、政策理解、医疗/教育/交通可达性 | 地方学校、道路等只改变可达或学习机会，效果按月缓慢形成，不直接瞬时改人口属性 |
| 地方习俗/身份 | 表达新并入地区的语言、风俗、身份或法律地位差异 | 只注册有场景依据的维度；不因易主自动改族属、习俗或忠诚 |

第一阶段的最小可用 POP 不必一次实现所有维度。优先级建议为：①州府地点和六类人口守恒；②生计/职业与就业、工资、商品生产/消费相连；③家户与财富档影响消费和劳力；④技能、识字、健康和公共服务接入形成较慢的状态演化；⑤只在具体玩法需要时加入文化/法律身份细分。年龄可先用劳动/扶养粗分布或年龄结构摘要，不要为了追求仿真而给每个百姓建立独立对象。

月度人口变化必须用**有原因的流量**解释：出生、死亡、迁入迁出、逃荒、归籍、征兵、退伍、职业/阶层转换分别记录来源群组、目标群组、数量、发生地点、月份和驱动因素。人口从一种职业/阶层转换到另一种时，人数从源桶扣除再记入目标桶；迁移改变地点归属；战争死亡、疫病死亡等是明确流出项。所有路径都须能复算州府、阶层、政权和全国总量，不许靠结算末尾“强行补齐”掩盖具体迁移链错误。

POP 子群不等于 AI Agent。官员仍按个体 Agent 行动；少数关键商人/地方领袖可以是具名或组织 Agent；普通居民以群组决策和规则结算为主，AI 按州府/行业汇总选择消费倾向、抗命、迁徙、投资和协商策略。群组拆分/合并时，财富、粮食、商品、欠项、人口和记忆归属均需明确分配与尾差规则，且拆分前后守恒。

### 4.10 领土变化：固定地点账本，变的是管辖与连接

宋的疆域会通过征服、割让、独立、叛乱、收复或边界调整变化。**人口和经济归属于稳定地点；地点再被不同政权控制。**因此领土易主不应复制或删除 POP/库存，也不应把当地人口全数改成新政权的核心人口。

统一空间模型建议采用稳定地域 ID，而不是仅靠显示地名或所属路名：

```text
固定地域 territory_id
  ├─ 行政层级与父级（路 / 府州 / 县等）
  ├─ 几何与相邻交通边
  ├─ 唯一人口、建筑、库存与在途货物锚点
  └─ 按时间变化的政治状态
       ├─ de_facto_controller（实际控制者）
       ├─ sovereign_claim（法理/主张归属，可缺失）
       ├─ administration（实际采用的行政体系）
       ├─ integration_status（占领、羁縻/自治、过渡、整合等）
       └─ market_access / tax_regime / legal_status
```

政治控制、主权主张、行政归属、市场关税区和文化身份不可压成一个 `owner` 字段：军队占领不必然等于完成行政接管；边界主张不等于实际征税；同一政权内部也可有自治或专营制度。前端地图可以用实际控制着色，同时在府县详情展示行政整合和主张状态。

领土变更作为有生效月份的事务处理：

1. 战争/外交/事件先生成有来源的领土变更提案，说明涉及的稳定 ID、范围、控制证据、双方状态和生效月；AI 可叙事争夺经过，但不能仅凭月报改变归属。
2. 由有效命令或事件执行器批准后，原子更新地域的控制/行政/市场制度状态；同步地图、军队驻地、税收规则、官府权限、 Agent 职权和贸易边，留下变更前后快照。
3. 地域内 POP、财富、粮食、商品、建筑、债务和地方知识留在原地域账本；只把当地数值计入新的政权汇总。转移前后“各地域实体总和”不变；政权汇总的变化必须等于易主地域现有账本的迁出/迁入。
4. 新政权依法定/实际能力渐进接管征税、军需、司法、官仓与公共服务；可出现旧官留任、地方势力合作/抵制、商路观望、逃亡或人口迁入等月度反应，由具体政策和地方 Agent 推演，不自动同化。
5. 市场整合分阶段处理：边境限制/军需优先 → 有限互市或指定商路 → 税制/度量衡/货币与商法协调 → 常态府际市场。整合改变关税、交易成本、货币兑换和订单可达性，不复制库存、不瞬间消除地方价格差异。

同一个核心 schema 应供宋境、外邦和新并入地区使用：地点 POP 群组、生产/服务主体、市场库存、建筑项目、控制状态和归属时间轴字段统一；不同政权通过税制、制度、科技、币制、市场准入和 Agent 组织参数化，不维护互不兼容的经济引擎。全国账应由地域账本聚合，政权/路级总数不得再成为第二份可独立结算的 POP 与货物真账。

**当前实现边界**：宋境运行经济以 `state.prefectures` 的路级区域为主；地理人口派生可把路级总量拆到府州点，但这不等于宋境市场/POP 已在府级结算。辽、西夏、大理已有部分省域经济，其余政权仍较粗聚合；地理代码另有分路/政权易主状态。现状是多粒度并存，不能直接宣称已统一。目标架构应先定稳定地域主键和唯一账本归属，再让各 regime 使用同一套 POP 与市场接口，并为旧档拆分保留显式残差/待归属账户；缺少证据的路级 POP 或库存不得按地图面积伪精确分给新易主府州。

### 4.11 辽、夏、大理及其他外国势力：接入共同经济体系，按重要度分层模拟

辽、西夏、大理应进入共同的**地域、POP、产业、仓储、市场、财政和领土变更数据体系**。它们不是纯粹的“战力数值条”，而是可与宋贸易、议和、冲突、封锁、征税和争夺属地的经济主体。共同体系指字段、记账规则和交易接口统一，不是各国政策、币制、官制、人口结构或科技水平都做成一样。

采用分层模拟，避免要么只剩总人口、要么每个远方小国都跑一套昂贵的逐府 AI：

| 模拟层级 | 适用对象 | 每月内容 | 何时升/降级 |
|---|---|---|---|
| **核心逐地域** | 宋、辽、西夏、大理；及与玩家发生征服/谈判/重点贸易的新政权 | 州府/省级 POP 群组、商品供需、生产服务、库存、价格、建筑、边境/海贸订单和政权财政 | 玩家可交互、领土相邻、战事/贸易/外交活跃时保持高细节 |
| **区域摘要** | 暂未与宋接壤、无活跃贸易或外交关系的主要政权 | 政权级产业/人口/财力趋势、有限的商品盈缺、外交军情 | 关系升温、战争或贸易路线接入时向下拆分 |
| **远方市场节点** | 没有必要模拟内部政治的海外贸易伙伴 | 港口/海域需求篮子、可支付额、偏好货物、物价/汇率区间、季节和风险 | 有持续商路或叙事重点时可具名为商团/港市 Agent；否则保持聚合买方 |

当前代码已有部分基础：辽、西夏、大理省域挂六类 POP 和资源/建筑进行地方经济；其他外邦大多仍在政权级简化结算。下一步不是另起“外国经济引擎”，而是让外邦省域与宋州府共享 POP/市场接口，逐步替换分叉口径；AI 成本按高活跃政权调用，不要求每个遥远政权每月逐官逐户推演。

外国朝廷中已登记的具名君主与官员仍是**各自独立的 Agent**，保留各自权限、性格、派系/关系、命令、记忆和责任归属；按战事、外交、边贸、内政等相关事件唤醒，不合并成“辽 AI”“夏 AI”单一人物。地方 POP 和一般经营者继续群组化，重要外商可按商团/首领建组织 Agent，普通船户/货主不逐个调用模型。

跨境市场至少区分：①边境市镇/榷场等陆路节点；②港口与海域商路节点；③贡使、岁币、军需等政府间渠道。政府间外交支付不冒充民间成交，民间商人交易也不因两国敌对就自动全部消失；可按禁令、封锁、许可证、关税、走私风险和关系温度分别影响各渠道。各国货币未必等值，需有成交价/折算率与结算账户；若货币不能兑换，可通过货物交换、银/钱支付或商人信用形成对价，不能无成本地跨账本搬钱。

### 4.12 市舶司与外销：货卖给商人，市舶司监管成交

市舶司在玩法上应承担许可证、船舶/货物查验、货物登记、关税抽解、港口秩序和官府采购/优先购买等职责。正常外贸的**卖方是宋境 POP、作坊、商户或官营供货主体；买方是外国商人/商团或有订单的外国政府/机构**。市舶司默认不是商品所有者，也不应被当成一个无资金上限的货物买家。宋代市舶管理与商旅往来、外商社群和地方商人的联系有史料研究支持；个别年份/港口的具体职权仍须单独核实。[HKU 关于广州、泉州市舶司的研究](https://hub.hku.hk/handle/10722/312794)、[剑桥《宋代海上侨民社群》](https://www.cambridge.org/core/books/abs/cambridge-companion-to-song-china/maritime-diasporic-communities-and-song-china/3B73AB5463838C392BE1E18BBD587076)。

每一笔出口按以下关系结算：

```text
本地卖方库存 − 商品数量
  ↔ 外商/外国机构支付 − 资金或等价结算物
  → 在途货物（港口、海域、航程、风险、保险/护送）
  → 外国目的市场库存 + 商品数量 / 买方获得货物
  → 市舶司按登记贸易额抽税；货物来源、买卖双方和净收款均留痕
```

若用“外部市场池”简化，不要求第一阶段逐个具名外国商人，但每个港口/商路/商品必须有有限需求、支付能力、愿购价格、贸易关系和对手账户；成交后减少其余额或增加其货物/结算负债，不能只从宋商人扣商品、凭空向其加钱。进口反向结算：外国卖方库存减少、宋境买方付钱/银、货物运输到港并入宋境买方库存；市舶司按实际货值/制度规则征税。贡赐、岁币、军费和民间贸易分别记账，不共用一个含糊“外贸收入”科目。

宋代外贸有外商来华，也有宋商出海；对外市场有真实的商旅需求。北宋末年具体商品受港口、航路、许可和禁令影响；诸如丝织品、瓷器、铁器、香药、矿产等只作为候选交易类别，须按商品政策标记可出口、限制、禁运或走私风险，不能全国统一放开。[关于宋代港口与外国商旅需求的研究](https://hub.hku.hk/handle/10722/312794)；[宋代市舶查验、税收与货物管理研究](https://link.springer.com/article/10.1007/s11457-024-09400-y)。

**当前实现差距**：现有 `export_policy` 将真实商品从宋境工匠库存扣除、将收入按 `external` 流记入 POP，但没有具体外商/外国库存/买方预算；这在账目上是明确的体外出售，在交易结构上仍是抽象买方。`calc_maritime_trade()` 又以公式估贸易额并据此计市舶税，未与每笔商品成交额绑定；金融推演的 `silver_in` 也是单独的抽象流量。未来需让实际海贸交易额成为关税税基，让买方与支付来源可查。不能把现有贸易额公式、`silver_in`、商品外销收入和宋境同一笔货叠加成多份收入。

### 4.13 远方市场：中亚商路与欧洲终端需求

远方市场不是一个无边界的“海外买家池”，而是有方向、有中间商、有时间和风险成本的商路网络。地图和经济数据以州府为底时，远方节点也应挂在可追踪的贸易边/港口/关隘上；节点内部可聚合模拟，不需要把每个远方家庭都拆成 POP。

#### 中亚：陆路节点

- 将河西走廊、敦煌等作为宋境西北陆路出口/中转点；再接入西域绿洲、河中等中亚商路节点。节点的通行取决于实际控制、边境局势、道路可达、商队组织和季节风险，不把地图上相邻误当作无成本贸易。
- 贸易对象可以是辽/西夏边地商人、回鹘或中亚商团、绿洲城镇商人等聚合群体。只有当某个商团/港市在事件或玩法中成为焦点时，才升级为有名字、有财富和行为目标的 Agent。
- 节点需求应体现其区域转运角色：既有本地消费，也可能采购丝织品、茶、瓷器、纸、金属器等再转卖；它们不等于“欧洲需求”，且需求篮子、支付手段和路线会随时代、关系与安全状态变化。

#### 欧洲：间接终端需求

- 欧洲需求是经多层商人和港口传回的远端需求信号，不应设成宋商船直达欧洲、宋廷直接面对欧洲买家，也不应让欧洲市场瞬间决定宋境价格。
- 可抽象为“西方终端市场”需求节点：商品由宋境港口卖给实际可接触的海商/中间港市，再由印度洋、波斯湾或红海方向商路逐级转运，最终连接地中海/欧洲终端需求。宋境结算只在本地可达的第一段创建成交；后续段落以在途批次、转售或聚合贸易回报体现。
- 终端需求变化经过航程时滞、转口库存、商人利润和风险折损后，才影响上游商人下一期的采购意向、愿付价与数量。路线中断时，货物可改道、滞销、损耗或被截留；不能把终端订单当作已完成出口收入。
- 不同历史时期的陆路控制与印度洋重心会改变远端链路，不应硬编码为永久畅通的“丝绸之路”或固定欧洲订单。

#### 远方节点与路线数据

每个远方需求节点建议包含：稳定 ID、区域与历史时期、节点类型（消费地/集散港/转口地）、需求篮子（商品、数量区间、品质偏好、替代品）、预算/支付工具、参考价区间、季节性、买方意向可信度、商人库存、连接路线、可达性、运力、时滞、成本、关卡税费、风险和最后更新的需求信号。缺项须标“未定义”，不等于需求或预算为零。

贸易网络边记录运输方式、月运力、航行/行旅时滞、运价、季节窗口、风险与损耗、政治通行条件、税费、可走货类及结算货币。转口节点收到货后，才可按当地库存与商人决策继续发运；价差应扣掉运输、税费、资金占用和风险。设计上区分：本地消费、转口采购、宋境进口、宋境出口、再出口、贡赐/岁币等官方转移。每种交易注明买卖双方和货物最终去向，防止同一货在多个节点重复计作供给或收入。

#### 月度因果与实现优先级

月结中先按现有情报和滞后需求信号生成商人意向，再检查可达路线、买方预算、商人资金、库存、容量和价格撮合；成交货物转入在途，按预计到达月入目的库存。远端发生的转售只通过后续商人订单/报价/供需摘要影响宋境，不倒改已经发生的本地交易。AI Agent 可决定谈判、改道、囤货和冒险，确定性结算器负责验证资金、库存和运输条件。

首期不要铺满完整欧亚人口模拟：先做两个可调的外部宏观需求簇——“中亚陆路商圈”和“印度洋—西亚转口商圈”，并将“地中海/欧洲终端需求”作为后者上游的间接终端节点。随后再按重要性拆分路线和商团。即使远端简化，也要给它有限预算、有限运力、时滞和中间成本，避免变成无限买家。

### 4.14 参照 EU/Victoria 系列后的设计取舍

这些作品提供的是机制工具箱，不是《宋祚》的目标规格。EU 系列主要把贸易做成国家/区域层的战略网络；Victoria 系列把 POP、生计、就业、建筑经营和市场价格连接得更细；EU5进一步把人口需求、地方生产和市场接入拉进 EU 的国家经营循环。宋祚的区别是玩家通过诏令、口谕、密旨和官员 Agent 治理一个月一结的宋代国家，所以应取其因果结构，不能照搬其人口规模、工业化假设或高频市场微操。

#### 值得吸收的机制

1. **EU5：地方供给与市场接入要同时存在。** 地方有资源/产能，不代表全境都能买到；道路、港口、商路和制度边界决定市场范围。适合转化为州府节点之间的可达性、货运时滞和市场圈，而不是一张全国共享仓库。
2. **EU4：贸易网络是玩家可操作的战略层。** 商路节点、商人部署、港口和政策让玩家关心“货从哪里来、经哪里走、收益流向何处”。适合转成市舶/互市许可、商路保护、关卡税、港口与漕运投资、商人支持等旨意选择；不要把 EU4 的抽象贸易值误当成宋代逐件商品交易。
3. **Victoria 2/3：POP 的收入来源要和消费能力相连。** 就业、工资/经营收入、商品消费、生活改善或恶化共同决定下一步人口与政治反应；建筑需要岗位和经营方式，不是无条件加产量的按钮。V2 的家庭/小农生产思路可用于解释尚未进入大型作坊就业的人口；V3 的建筑投入产出和 POP 所有者收入可以帮助形成“民营经营收益回到民间”的闭环。
4. **Victoria 3：贸易应随价差和盈利能力调整，界面要可追踪。** 固定出口数量容易过度微操或把外部市场变成无限吞吐口；可让商人 Agent 根据预期利润调整采购意向，但月结引擎仍受买方预算、供给、运力、税费、风险和本地短缺约束。路线不能在边际利润消失后无限扩张。
5. **各作的迭代经验：玩家需要看懂选择的后果。** 商品详情应能从价格、供需一路查看到生产建筑、主要买方、贸易路线和受影响 POP；建筑详情则能回到投入品、工人、订单与停工原因。说明性 UI 是模拟规则的一部分，不能只给复杂数值不给来源。

#### 需要调整本稿的四个关键点

- **把“市场”从交易清单提升为可达网络。** 设计州府本地市场、相邻可达市场、政权内主干市场、边境/海贸市场四层。每层不是四套重复库存，而是底层库存按连通性产生的可成交集合；控制权、关税区、封锁、季节性和运输容量改变连通性。市场圈应能分裂/合并，并在领土变化时重新计算。
- **把“建筑有产出”改为“生产方法决定经营方式”。** 同一蓝图可以切换家庭兼业、民间雇工、官营或承包等方法，各有投入、岗位、产能、成本、产品质量、收益归属和政策条件。切换生产方法要有迁移/改造期、设备投入或技能适配，不应免费瞬切。AI 可提出调整，玩家可用旨意设目标/限制，但官员和经营 Agent 决定执行路径。
- **补上收入分配和再投资闭环。** 生产销售收入依经营权和合同流向工匠/雇工 POP、商人/业主 POP、官府账户及税收；经营者可以支付工资、分红、留存、购料、修缮或扩建。经营主体如果需要单独周转资金，先确定资本归属并映射到既有 POP/政府钱账，不能新增不计入 M_ALL 的“产业现金池”。
- **限制市场清算的复杂度。** 不照搬每周动态重算；每月冻结一份市场意向快照，按基本生计、已签合同/工程、一般消费、奢侈与转口等有解释的优先级撮合。每阶段一次分配，成交后不在同月回流、重复采购或反复改价；未满足量进入下月意向并允许 AI 改策略。

#### 建议新增的决策与 UI 面

- **玩家控制的是制度和瓶颈**：对某类货设置官买优先、官仓储备目标、专营/许可、进出口限制或税率；命令港口/漕运/道路建设；为商路设保护或拨款。把微观订货留给商人/地方 Agent，防止玩家每月管理几百个摊位。
- **经济 Agent 输出有时效的经营计划**：行业/商号 Agent 可给出本月采购量区间、计划产量、目标市场、预期收益和风险；多名官员 Agent 围绕预算、民生、税收、边防和派系立场提出冲突意见。程序根据月初状态统一验算，并把偏差（价格变化、订单争夺、阻断）记为推演结果。
- **市场地图模式**显示节点、贸易圈、交通边、在途货、未连通地区与卡点；颜色不可只表示政权或单一价格。
- **商品页**展示本地供需/库存/价差、主要供应建筑/来源、用途需求、未满足订单、可达替代市场、在途量、外贸最终层级及为何没成交。
- **建筑页**展示经营方法/所有者/管理 Agent、岗位需求与实到、投入可用月数、工资欠付、产能利用率、产品去向、收入分配、维护/改造和本月推演解释。
- **回合报告**只突出异常或玩家命令相关链条：例如“官命修港 → 工部拨款 → 港口施工延迟（缺木）→ 木价上涨 → 两坊减产 → 布价/民间衣需变化 → 商人改走陆路”；全量数据留在可展开账本，避免每月堆满日志。

#### 适配本游的边界

不采用 EU/Victoria 式海量细粒度 POP/每周动态劳市作为第一阶段目标；不要求每个建筑都成为 Agent，也不让 AI 自由写每笔账。首期只让关键产业链、官营/民营试点、州府市场边和对外商路进入同一套可审计账本。对未细分的普通家庭生产用聚合生产方法，对市场定价用有限商品、分层优先成交和月度滞后。AI 的混沌来自多个 Agent 对旨意和局势的解释、谈判与策略分歧，程序把结果限制在可解释、可复现的月度交易与资源边界内。

#### 建议先做一个可玩的纵向切片

现稿涵盖 POP 深化、全商品链、建筑重构、州府市场、官民仓储、跨政权和欧亚贸易，全部并行会形成过大的重构面。实施前先从有现成数据支持的一条地方链选试点（例如某州府的农副/纺织/窑业链，具体行业由当前数据盘点决定），只打通：

`POP 生计与财富 → 本地需求/价格 → 建筑岗位和经营方法 → 工资/经营收益 → 本地库存和消费 → 交通边上的一笔跨府或外贸 → 市舶/关税或边贸收入 → 官员 Agent 的旨意与次月反应`

切片需同时覆盖一个官府动作和一个民间自主反应：例如圣旨拨款修路或支持港市后，地方官是否筹料、商人是否改道/扩购、工匠是否开工、哪些 POP 收入/价格受到影响。只有账物闭合、界面能追因果、回合不靠玩家逐单微操后，再横向扩充商品、路线和 Agent。

优先级建议：**P0** 统一市场边界、价格/清算口径与 POP 现金流；**P1** 建筑—经营主体并轨和官民生产方法；**P2** 交通/外部需求节点及玩家贸易政策；**P3** 具名商团、多路线策略与完整远方转口链。欧洲终端需求属于 P2 的滞后信号，不能先于宋境出口交易和中转库存实现。

## 5. 民间需求与消费

### 5.1 需求篮子是可变的，不是每类 POP 的死清单

每类 POP 有一套基础偏好、收入能力和生活阶段；实际需求还可受地域、季节、灾情、市场可达性、风俗、政策、迁徙、AI 人物意图和历史事件影响。

需求可按用途分层：

1. **生计需要**：口粮、基本燃料及最基本衣着。
2. **日常用品**：盐、茶、常用器物等。
3. **生产投入**：农具、工具、原料、纸料等。
4. **住房和耐用品**：新建、扩建、修缮、家用器物。
5. **改善与奢侈**：绸、酒、装饰、宴饮、文化服务等。

这只是结构层次，不规定 AI 每月必须按固定权重购买每一项。某阶层可能偏好某些商品，但同用途商品允许替代；地方也可以因特产、交通、风俗和新技术形成独特需求。

### 5.2 消费由三道约束形成

```text
期望需求：由人口、需求层级、现有持有量、习俗和局势决定
可支付量：由收入、财富余量、价格、债务/欠项与保底需求决定
可成交量：由本地及已到货库存、运输、制度和市场接入决定

实际成交量 ≤ min(期望需求，可支付量，可成交供给)
```

贫困不等于没有需求；它代表需求可能无法满足。富裕也不等于所有钱自动消费：储蓄、囤积、投资、借贷或奢侈消费的比例可以由 AI、局势和阶层特征决定。

公式提供合理边界和基线，不锁死行为结果。**AI 可决定需求篮子权重、消费/储蓄倾向、替代品接受度、囤积与投资意图；引擎负责校验购买力、库存和账本。**

### 5.3 消耗品、耐用品和资产投入分开

- 粮、酒等真正被消耗的商品按实际消费量减少。
- 布帛、器具等耐用品采用持有目标、损耗/更新和人口变化形成补购需求；不能将全部购买量等同于当月消耗量。
- 木石砖等投入民居或公共建筑后，转为建筑资产或施工消耗；不会再作为 POP 家庭商品库存存在。
- 住房是建筑服务和耐久资产，不是每月重复购买一份建材。
- 生产投入随配方加工扣除，产品按配方产出；不能将生产所需原料也算作消费。

## 6. 粮食：口粮、商品粮与仓储体系

### 6.1 口粮不是另一种商品

**口粮是粮食被实际食用的用途。**根据职业和家口计算需求，按现有口粮结算流程扣除实际粮食。商品市场成交粮食后，买方持有的粮可以之后成为口粮。

月度流程原则：

1. 汇总各 POP 口粮需求与自有可食存量。
2. 计算可售余粮，保留农户口粮、安全库存及适用的隐户份额。
3. 缺口 POP 可以按购买力向可供粮者购买。
4. 对实际买到的粮完成钱与粮双向转移。
5. 结算实际吃掉的口粮；缺粮才形成短缺和后续压力。

不能先把农户粮全部纳入市场供给，再让农户从市场买回自己的口粮；也不能同一笔钱先支付粮商、又支付粮市卖方。

### 6.2 商品粮是可进入流通的粮

商品粮可来自农户余粮、士绅/地主库存、商人粮栈、跨州府输入或官府平粜。它必须先从原持有人库存转出，才成为买方库存。

- 农户自留粮未上市前不是市场供给。
- 私人囤粮可待售、惜售或自用，AI 和价格预期可影响决定。
- 商人粮栈可以储粮和跨州府销售，但货物必须真实到仓。
- 官府采购入仓后的粮不再计为民间市场供给。

### 6.3 官仓与民仓按所有权和目的区分

官仓应按游戏需要分成调价、赈济、军需/官供等用途。官仓有粮并不代表民间市场有粮：

- **平粜**：官仓粮转入市场，买方付款，官仓库存减少。
- **赈济**：官仓粮转入受济 POP 的粮存或口粮渠道，标明受益对象。
- **军需/禄粮**：官仓粮按军队或官府供应规则拨出。
- **采购/籴入**：官府付款，卖方粮减少，官仓粮增加。

民仓是民间所有的自留或经营库存：

- 农户存粮挂农 POP；商人库存挂商人 POP/既有货栈结构；地主与士绅持粮挂相应主体。
- 市场能否获得民仓粮，取决于所有者是否出售、运输是否通畅、制度是否允许。
- 官府征购不是“无主粮食出现”，必须体现价格、税权或强制手段及对应民怨影响。

具体仓名、职责和地区差异允许后续根据史实扩展；第一阶段先把“调价/赈济/军需/民间持有”四类账务分清。

## 7. 官营、民营、专营和官府采购

经营体制是商品生产与流通的制度属性，不是商品类别。

| 经营方式 | 投资/原料 | 雇工/收入 | 库存与销售 |
|---|---|---|---|
| 民营生产 | POP/民间经营者投入 | 工匠及相关 POP 得工资；经营者承担收益风险 | 民间库存，可本地销售或交商人运销 |
| 官营生产 | 国库/官府资源采购投入 | 官府承担工钱和管理成本 | 进入官仓、军需或官售渠道；也可按政策放入市场 |
| 专营/许可 | 政策限制资格、渠道或价格；可能由官府或持证商人经营 | 税费、专利利得与商人利润按制度分配 | 不能凭“专营”直接造货；仍需生产、仓储和运输 |
| 官府采购民产 | 国库按合同向民间买货 | 民间卖方获得收入 | 货物转成官有并指定工程、军需、赈济等用途 |

AI 可以根据财政、民怨、战事、地方势力与官员立场提出开放、专营、官营或采购方案。方案的收益与副作用要沿账本结算：供应、价格、就业、税收、寻租、走私和民怨均可随情势变化，不预写唯一正确答案。

## 8. 民间建筑、政府建筑与建材市场

### 8.1 建筑类型及其作用

| 类型 | 例子 | 经济作用 |
|---|---|---|
| 公共设施 | 水利、道路、桥渡、港口、官仓、学校 | 改变产量稳定性、交通、仓储、教育或公共服务；有造价与维护 |
| 官营生产/行政 | 官营作坊、仓场、专营机构 | 消耗原料和劳工，生产官有库存或提供行政供给 |
| 民间生产/经营 | 农田、作坊、酒肆、商铺、货栈 | POP/经营者投资生产，雇工，形成民间库存和市场流通 |
| 民居与民间营造 | 住宅、商铺扩建、院落、修缮 | 满足居住与经营空间需求，形成耐久建筑资产和持续材料需求 |

公共设施应改善民间生产经营条件，不自动取代民间供给。道路可以降低运输摩擦，水利可以提高农业稳定性；官营作坊会增加供给，也可能和民间争原料、熟练工匠和运输资源。

### 8.2 建材交易与施工

建材按技术成熟度开放，但都保留实物来源：

- 木、石、砖、铁器/工具等按游戏已有材料和市场体系确定。
- 砖作为实物商品，可储存、交易和损耗。
- 水泥、钢筋等新技术材料在科研后解锁其配方、生产设施或进口渠道；科研解锁能力，不凭空生成材料。
- 金银铜的实物存量不自动兑换成钱；铁等工业材料可以有市场估价，但估价不把实物变成国库货币。

建造工程使用统一的“出资—采购/领料—施工—资产入账”链：

1. 蓝图给出材料数量、劳动量、工期基线、地域要求和效果构件。
2. 立项时形成基准估价与采购计划；材料估价是预算信息，不是独立收费。
3. 若从市场采购，出资方付款给真实卖方，库存由卖方转到项目/仓储。
4. 若从官仓领料，官仓减、项目预留增；不再重复支付一笔市场货款。
5. 施工消耗预留材料并支付工钱/运输/组织成本，完工后登记建筑资产及维护责任。
6. 赶工预算可提高施工能力或优先运输，但不能越过缺料、工匠不足、季节和施工能力等约束；未花余额退回原出资方。

市场价可以随供需变化。文档已有的“立项锁价”建议限定为**蓝图基准估价/已签采购合同**：合同内数量和单价可锁定；合同外缺料的后续采购仍受市场供给、运输和政策影响，并在界面解释追加成本或延期。这样既可解释财政，又保留市场波动的玩法。

### 8.3 民居消费与建筑投资

民间建筑需求应由住房拥挤、人口增长、损坏、经营扩张、财富和材料供给共同驱动。AI 可决定家庭或经营者是否修建、等待、借贷、合伙或迁居；系统只校验支付能力、材料、工期和本地制度。

民居建造花费归出资 POP/经营主体，材料进入建筑，不再同时留在 POP 商品库存。住宅效果通过容量、舒适度/耐久、拥挤缓解或地方吸引力等已注册维度作用；不得每月虚构一笔材料消费。公共住房、民间房产或士绅地产的产权表达要基于现有建筑/资产结构设计，不另造民间货币账本。

### 8.4 建筑资产、经营主体与产出挂钩

商品可以由建筑承载产能，但“有建筑”不能等同于“每月必然产货”。应将**建筑资产**和**经营活动**分开：建筑提供地点、空间、设备、岗位容量和耐久；经营主体决定谁出资、招谁、采用什么配方、向谁买料/卖货、承担盈亏。一个建筑可以容纳多条活动线；一个商号/经营主体也可以租用或管理多处建筑。民间建筑、官营建筑和公共设施共用这套描述，但产权、经营权和管制权分别记录。

#### 建筑蓝图的定义

蓝图既是建造定义，也是可供 AI 选择/提出的产业能力定义。至少包含：

- 建筑类别与用途標籤：住宅、农业、采掘、加工、商贸、服务、仓储、交通、水利、行政、军事等；允许区域/资源/交通前置和可容纳活动。
- 建造条件：木石砖等材料配方、工匠/劳役需求、基准工期、造价口径、施工季节限制、维护材料和后续维护费。
- 能力：每级空间与职位容量、可经营配方/服务、仓储容量、设备/水源/燃料需求、运输接入、产品质量和损耗特征。
- 效果：明确影响对象、计算口径、生效时点、持续条件与上限。公共设施效果应作用于明确的地域/交通网络指标；不以描述文本直接给 POP、财政或产量加数值。
- 兼容/解锁：所需科技、资源与历史设定依据；动态蓝图需记录提案来源、审议状态、注册版本和旧档兼容策略。

#### 建筑实例与经营主体

建筑实例按稳定地域 ID、州府、具体地点（如港口/市镇/乡村；若史料或地图不足则地点粒度标为未细分）登记。建议实例字段包含 `blueprint_id`、等级/面积、建成月份、耐久/损坏、可用设备、所有者、管理者、控制政权、维护责任、当前用途、空置/停业/施工状态和来源项目。不能只用同名建筑的一个全局等级代表各州府的资产与产出。

经营主体（家庭作坊、商号、庄园、官营机构、承包经营者等）另有主体 ID，并关联 Agent/POP、注册地点、资金和信用来源、雇佣岗位、配方/服务、投入库存、产出库存、订单与合同、产权/租赁/经营权、税费义务和经营状态。若一期暂时不引入独立主体，可用“建筑实例内经营记录”作为兼容载体，但字段语义要留出主体 ID，避免之后把一条路上的总作坊池硬拆给各州府。

#### 月度生产因果

每月先由 POP/Agent 形成生产、停产、转产、采购、囤货或扩张意图；程序按建筑能力、可用岗位与技能、输入库存、工资资金、技术、设备、燃料、水源、交通、维护状态、当地法规和订单逐项校验。实际产量不得超过最紧缺投入、有效劳力和设备产能所允许的上限。最小因果链为：

`蓝图/资产可用 → 经营者与资金到位 → 招工/岗位匹配 → 原料和服务采购 → 本月加工/生产 → 成品进经营主体库存 → 本地销售/府际运输/出口 → 收入与工资/税费结算`

缺工、欠薪、缺料、设备损坏、禁营/许可证缺失、道路阻断、销路不足都可以导致低产、停产或转行。建筑的岗位数是容量上限，不代表所有岗位已就业；建筑存在也不能绕过投入、支付和销售因果。生产出来的成品要记在经营主体/建筑仓库，再进入本地市场供给；不能按全国 POP 占比把货随机派给工匠群体。

#### 官营、民营和公共建筑

- **官有官营**：国库/官仓出资、官员 Agent 管理，收入和产品进入明确官有账户/仓储；官员失职、拨款不足和采购延误可影响经营。
- **官有承包**：资产属官府，商人/工匠经营，合同规定租金、采购、税费、价格或优先供应；资产产出与经营收入按合同分账。
- **民有民营**：POP/商号融资、拥有或租用资产，自负盈亏，受税、专营和许可规则约束。
- **官营但民间供料/劳作**：原料采购、劳工工资和最终商品分别记账；不能将“官营”当作免除市场投入成本。
- **公共设施**：道路、桥梁、港口、水利、官仓等主要提供可达性、容量、储备或公共服务，不自动视作普通卖货企业。若设施附有经营活动（如港口装卸、仓储、渡运），需另设经营主体或收费服务。

产权、经营、调度和征用是不同权限。圣旨可立项、拨款、指定负责人、规定时限和目标；对应官员 Agent 仍会申请、协调、采购、征工或拖延，完工后资产才在明确生效月提供能力。诏令可强制调度但须留下成本和阻力，不能把建筑描述直接变成当月效果。

#### 与当前实现的衔接差距

现有代码已有 `prefectures[路]["buildings"]` 建筑等级槽、岗位配置、就业分配和动态蓝图/营造项目，可作为过渡底座；但不同路径并未统一为“府级建筑资产—经营主体—市场交易”：例如宋侧 `state.workshops` 是全局作坊列表，`_settle_workshops` 在全局资源/太仓上扣料，布绸产出再按各路工匠人口占比分派到待售池；这会让具体建筑所在地、经营者与买方链条断开。另有建筑岗位容量与生产配方不完全同一数据源的问题。

因此迁移顺序应是：先给现有每个作坊/蓝图补稳定地点、所有者/经营者、资金/投入/产出库存和来源记录；再让月结从建筑实例与经营记录读取产能，并把成品先写入当地经营库存；最后将旧全局作坊迁成有据可查的地点实例。无法定位的旧存档实体要进入显式“未定位/待分配”桶，不能按人口占比伪装成府级真实生产。

#### 新科技、新商品和新建筑的兼容

AI 提出新工艺/商品/装备/蓝图时，先生成提案版本，说明所需技能、材料、设备、岗位、用途与风险。审核注册后，配方才能用于经营；蓝图可以构造出建筑实例；建成、招工、取得材料后才开放对应生产。若某方案确实不依赖实体建筑（家庭兼业、采集、临时服务等），用显式的家庭生产/服务能力定义，不伪造建筑实例。旧档找不到配方或蓝图版本时，应保留原库存与实例并标明待迁移，不把缺失内容按零产出静默处理。

## 9. AI 推演空间：硬边界固定，行为结果开放

本游戏的混沌性应来自互相影响的决策、局势、地方差异和偶发事件，不来自账目随机错乱。**结算恒等式要稳定，行为选择不必固定。**

### 9.1 引擎负责什么

- 维护 POP、国库、官仓、民间库存、建筑、项目和市场货物的唯一真实账目。
- 校验单位、所有权、支付能力、库存上限、资源来源、技术前置和已注册效果。
- 执行已批准交易、生产、征购、转运、消费、施工和损耗。
- 在规则允许范围内应用价格变化、随机事件和可复现的随机数。
- 记录解释线索，让 UI 能回答“谁提出、为何发生、谁受益/受损”。

### 9.2 AI 可以决定什么

- 各阶层与人物本回合重视什么、如何调整消费与储蓄倾向。
- 地方选择生产、售货、囤货、调货、借贷或迁移的策略。
- 官府选择平粜、赈济、采购、专营、减税、修路、扩产或暂缓工程。
- 不同官员、商人、地方势力对同一旨意提出不同解释、支持、拖延和执行策略。
- 根据情势提出未入库的商品、技术、配方、建筑蓝图、装备、政策或市场关系。
- 在既有合法提案范围内提出多种方案与代价，不必每次沿同一最优路径。

AI 可以给出意图、理由、目标和候选数值；经济引擎负责校验并将**被接纳的具体方案**变成真实状态变更。不要让 LLM 直接写 POP wealth、商品库存或施工进度。

### 9.3 混沌性和安全护栏

- 不给每类 POP 写死“永远买 30% 布、20% 酒”之类脚本；用基础偏好、情境输入与 AI 选择产生变体。
- 不给全国市场强行设单一发展路径；各路按资源禀赋、交通、灾害、制度和玩家政策形成不同结果。
- 不要求 AI 每回合都创新，也不把创新固定绑定到同一个事件；新提案应罕见但可由长期条件、事件或玩家行为触发。
- 随机波动用于天气、运输风险、经营成败等有语义的变量，并受种子控制；金额和库存的加减仍按确定规则结算。
- 保留失败、延误、争议和未满足需求。引擎校验不应把 AI 所有提案优化成成功结果。
- 重要动作需有提案、批准/拒绝、执行状态和因果说明；没有有效处理器的提案标记待支持，不假装产生机械效果。

### 9.4 玩家可审阅月度推演：不给黑箱，也不伪称确定预言

玩家不应只能从月末一段月报倒猜 AI 做了什么。月报负责叙事，不替代推演记录。每月应有一个可展开的“本月推演与结算”视图，至少展示：

1. **本月输入摘要**：参与推演的官员/Agent、读取的命令/事件/上月记忆、关键状态数据的地区与时点；缺失或过期数据标出，不假称完整上下文。
2. **AI 决策记录**：Agent 的职责、判断/档位、建议行动、优先级、风险和简短可核验依据；区分建议、已批准命令和程序实际采用的结果。展示面向玩家的理由摘要与依据，不要求暴露模型隐藏的逐 token 内部思维。
3. **程序执行轨迹**：本月实际执行/跳过/拒绝/延期的步骤及原因；列出关键输入输出与主要数值变化，注明由哪个规则步、哪道命令或哪个建筑产生。
4. **因果链**：从“玩家旨意/局势/地方 Agent 决策”到“资金、商品、工时/服务、库存或人口变化”，再到“受影响 POP、行业、州府、官员”的来源链接；玩家能从月报钻到交易、工程和 Agent 记录。
5. **不确定与未满足**：显示 AI 未调用/失败、契约无定义、资料不足、库存不足、资金不足、执行能力不足和效果未注册等不同原因；不得用一段顺畅叙事掩盖机械失败。

推演结果不必等于可精确预报的最终状态：AI 给的是有限信息下的策略判断/档位，程序执行会受真实库存、市场价格、预算、权限、交通和偶发事件约束。UI 要把“AI 原拟如何做”与“结算实际发生了什么”并列，让玩家理解偏差本身就是游戏过程，而非黑箱误差。

## 9.5 避免 AI 演戏与 AI 失联

- 月内不需要每次点击都调用 LLM。只有需要理解自然语言、谈判、人物表达或开放式策略判断时才调用；结构化确定操作由程序校验。
- 过月时至少应让核心经济决策读取与其相关的真实状态摘要、玩家命令和历史结果；需要时按州府/行业生成受预算限制的分层摘要，避免只给国势总述，也避免把整份世界状态塞给所有 Agent。
- 每个 Agent 只读其职权所需信息和授权记忆；跨领域影响通过可读摘要共享，私密对话按权限隔离。
- 固定契约产生结构化结果；同一回合只调用必要 Agent，避免重复推演导致冲突决策。各 Agent 输出互相矛盾时，记录冲突并由权限、命令顺序或明确的协调 Agent 裁定。
- 若玩家无 AI 交互，月度推演仍用正式游戏状态独立运行；不得为了“补回缺少的聊天”虚构意图或记忆。若过月核心契约失败，按当前拒绝式规则停止/回滚并显示原因，不以旧月 AI 缓存假装本月已推演。

## 10. 新科技、新商品、新蓝图、新装备的生命周期

所有新内容走“提议 → 识别/审议 → 注册 → 生产或部署 → 结算反馈”。提议阶段允许自然语言和新奇想法；进入机械模拟后才需要严格 schema。

| 新内容 | 本局落地前需要明确 | 落地后的可见因果 |
|---|---|---|
| 新科技/技术 | 技术效果维度、研究来源/时间/资源、适用范围、前置与不确定性 | 改变已注册配方、工艺、建筑、装备或制度的可行性/效率 |
| 新商品 | 单位、库存、价格发现、需求用途、生产/贸易来源、存储与折耗 | 实际生产、入库、成交、消费或作为原料使用 |
| 新蓝图/建筑 | 材料清单、岗位/劳动、工期、地域、效果构件、维护和产权/出资方 | 施工扣料与发薪，完工登记资产，维护与外部性持续影响 |
| 新装备 | 实物键、原料/生产、价格、适用兵种、配给规则与损耗 | 武库入库、军队领用、装备率和战力变化 |

新内容需要存档级注册和版本迁移。全新参数或效果先作为“待审提案”；程序只能执行已注册构件。AI 可以描述“新式水泥”“新法织机”等概念，但除非其生产和效果得到注册，不会立即免费改变全图。

玩家可通过科技、圣旨、工程或事件推动注册；不同路径允许不同成本和社会反应。例如官营试制可能更快但耗国帑，民间试制可能慢但商人愿意投资，地方仿制可能效果不稳定。此类路径应留给 AI 和局势演化，而不是固定科技树唯一解。

## 11. 初始库存、开局经济与市场规模

开局 17 维物资库存全空是市场无法启动的重要风险。建议以可解释的初始产业和地区情况播种库存，而不是结算时临时兜底：

- 开局 POP 持有品沿既有 POP 存档字段表达。
- 民间商品库存来自初始作坊产出、商人/作坊库存设定或有记录的开局货栈。
- 官府营造材料来自明确配置的官仓/地方资源；如不设官仓初存，工程就要先采购或等待生产。
- 初始存量应和开局建筑、人口、技术、地区资源、已有贸易路径相匹配。
- 配置的开局存货是世界初始条件，不应伪记为某月生产、购买或货币注入；在账务与日志读数中能区分初始存量和本回合流量。

民间消费扩大后也不要求全体 POP 都富裕或所有货都买到。游戏可以出现地区短缺、富阶层消费旺盛、贫户被价格挤出、官府采购推高市价、运输断绝或作坊转产等不同局面；只需保证原因可追踪、账目真实。

## 12. UI 与推演解释

市场界面按当前实际模拟粒度查看（州府级迁移前明确显示“路级汇总”，完成迁移后可下钻至州府）和商品/服务类别：

- 上月期初库存、本月产量/到货、成交、消耗/损耗、期末库存；
- 民间、官府、在途和项目预留库存分别显示；
- 基准价、实际成交价、需求量、成交量、缺货量与价格变化原因；
- 价格和供给受灾害、技术、政策、运输、征购或垄断影响时，显示对应事件/交易。
- 商品链查看原料来源、加工者、产地、库存所有者、到货路线和最终用途；服务显示提供量、成交量、收费方、受益对象、覆盖不足及限制原因。
- 服务地图/列表区分已有设施、可用能力和当月实际履约，不把建筑存在误显示为服务已覆盖。
- 按“本地生产/消费—府际流入流出—路级汇总”分层展示；跨节点库存明确标为在途或已到货，不能在两地同时可售。

POP 界面显示：

- 需求意向或生活层级（可用叙事档位和数值摘要共同表达）；
- 基本需求满足、买到/未买到的关键品类；
- 主要收入、必要支出、储蓄/囤积变化和财富趋势；
- AI 本回合为何改变消费、储蓄、投资、售粮或迁徙意图。

建筑与项目界面显示：

- 建筑的出资者、经营方式、雇工、产出、供料来源、库存归属和维护者；
- 工程基准材料/工期、已采购和已消耗材料、实付货款/工钱/运输费、赶工预算、延期原因；
- 工程需求对本地民间库存和价格造成的影响。

显示“未定义”与“零”要有区别；无法确认的历史设定或 AI 提案效果，不展示成已生效事实。

## 13. 分批实施建议

### 阶段 A：口径和可观测性

- 列出现有粮、货、建材及仓储字段的真实归属。
- 统一区分库存、需求、成交、消耗、损耗、初始存量。
- 增加按当前路级、POP、商品、所有者统计的供需与守恒读数，并把州府级经济实体列为独立迁移项目。
- 只读跑开局基线，明确消费低、库存空、价格不动各自的原因。

### 阶段 A2：州府实体与市场边界设计

- 先盘点地图行政实体、POP初始化、建筑/项目、价格、库存与存档中所有依赖路键的读写点。
- 定义稳定州府 ID、州府—路归属关系、节点存量、邻接交通边及路级汇总口径；历史数据缺少府级依据时，显式标为估算/待配置，不伪造精度。
- 制定旧档迁移与回退/拒绝策略，验证 ΣPOP、钱粮、货物库存和建筑资产在拆分前后守恒，再逐模块迁移。
- 迁移前不将路级现有商品价格、供给或需求复制到多个州府作为“府级数据”。

### 阶段 A3：POP 群组与人口流量模型

- 先把人口与状态字段盘为来源清单，明确六类 POP、官吏/隐户/军队子池、流民及地方人口读数之间的真账和镜像边界。
- 设计州府 POP 群组 schema；六类仍作汇总维度，先增加能改变就业/收入/商品需求的最小生计画像，不一次性铺开所有职业、年龄和身份组合。
- 把月度出生/死亡、迁移、逃荒、归籍、征兵退伍、职业和阶层转换统一登记为流量，并验证每项的守恒等式。
- 拆分/合并群组时同步处理财富、粮食、商品、债务、服务可达和Agent关联，保留舍入尾差及来源记录。

### 阶段 A4：统一领土注册与易主事务

- 建立稳定地域 ID 和层级映射，区分地理位置、实际控制、主权主张、行政、市场和法律状态。
- 盘点宋境路级经济、辽/西夏/大理省域经济、其他政权汇总经济及地图易主状态，定义一个统一地域账本接口和过渡适配层。
- 实现全地域易主、分割易主、割让、独立/再整合的事务 schema；仅在存在可信细分人口/库存时允许部分区域准确转移，否则保留在路级残差或待分配区。
- 对每类转移明确时间戳、生效月、控制权、税制、军队归属、市场边和存档迁移；检验旧政权、新政权和全图地域总账。

### 阶段 B：民间市场真实成交

- 让 POP 消费受需求、财富、价格与供给共同约束。
- 接通生产者/商人库存到 POP 库存的真实转移。
- 口粮继续走专用粮市与吃粮流程，不重复成交或扣款。
- 建立统一商品目录与需求/生产/建材/官营用途标签；首批建议约 40–60 种可储存核心商品，优先覆盖粮食、燃料、纺织、工具、陶器、营造材料和日用品。
- 按家庭购买、生产投入、耐用品补购和工程领料分开撮合，区分可储存实物与服务能力。
- 校准基本需求满足率和替代行为；品类丰富不能以虚拟供给或统一强制消费达成。

### 阶段 C：官仓、民仓和政府采购

- 明确仓储用途、所有权、采购入仓、平粜、赈济、军需的流程。
- 政府工程成为有预算与库存来源的真实买方。
- 让大额采购、征购和平粜能影响市场供给/价格并产生可解释社会反应。

### 阶段 C2：生产链和行业经营

- 按候选产业链注册配方、劳力/技能、燃料/设备、产能、维护、损耗与副产物；支持家庭兼业、作坊、商户和官营主体等多种组织形态。
- 首批贯通“粮食/农副产品—纺织—燃料/冶炼/工具—陶作/纸墨—营造/船运”等跨行业依赖，不要求每个州府自给自足。
- 生产、停产、转产、扩产和退出读取本地投入价格、销路、工资/劳力、制度与交通；AI提出经营意图，结算引擎校验库存及资金后执行。
- 用缺料、燃料冲击、运输中断、官府订单等局势检查多个行业的传导，而非只验配方能运行。

### 阶段 D：营造材料、民居与官民建筑

- 木石砖等接入真实供给、价格、运输、采购与实物消耗。
- 分离建材实物数量、采购付款、工钱、运费和基准估价，消除双计。
- 民间住房修缮/扩建与公共/官营建筑使用同一市场和材料账，但由不同主体出资。
- 赶工曲线和材料瓶颈共同决定工期。

### 阶段 D2：服务业与商贸网络

- 先落地运输/搬运、市场撮合、仓储、加工、营造维修五类直接支撑商品链的服务，再扩展旅店餐饮、医疗、教育、书写/账房等地方服务。
- 服务能力按月生成、按实际需求履约；记录服务量、费率、付款人、收入接收方、质量/覆盖与未满足量。服务不能存货，也不能离开服务提供者/费用来源凭空生效。
- 交通成为节点间有容量、时间、成本、损耗/风险的网络；水运、陆运、驿运可由官府维护和民间经营共同构成。
- 信贷/典当等晚于基本商品市场实现，并先定义债权债务、到期偿还与违约，避免借款被计作财富创造。

### 阶段 D3：外国市场、边境贸易与市舶结算

- 把宋、辽、西夏、大理接入共同地域/POP/商品数据契约；保持各国制度、币制、税制、产业和 AI 权限差异。
- 先为边境市场与主要海贸港口配置有限需求和预算的外部买方池；随后按玩家互动程度拆出商团/港市 Agent 或活跃外国省域 POP。
- 商品出入境必须创建买卖双方、地点、商品、数量、计价、运输、关税和支付对手的贸易记录；货物进入/离开在途，再入目的地库存。
- 让市舶司税收从当月实际登记贸易额派生；官府优先购买、贡赐、岁币、走私罚没与商人买卖分别结算。
- 校验现实贸易关系影响需求和可达性；无需求、无支付能力、航路中断、禁运或买卖意向不匹配时不得强制外销。

### 阶段 D4：建筑资产与经营实体并轨

- 盘点路级建筑槽、政府工程落成建筑、全局作坊和动态蓝图，制定“建筑实例—经营主体—岗位/配方—库存/交易”的唯一迁移模型。
- 先迁移已有作坊的地点、所有者/经营者、资金来源、投入和产出；没有可信地点的旧数据进入显式未定位桶，不按 POP 占比分摊成府级产量。
- 生产读取建筑有效产能、经营意图、岗位、技能、投入、工资和制度许可；产品进入当地经营库存后才参与市场成交。
- 将产权、经营权、监管权和征用权拆开，支持官营、官有承包、民营、家庭兼业与公共设施；完工资产从下一有效月提供能力。
- 新蓝图/配方经 AI 提案、规则审查、注册、建设/开业后才产生效果；未注册、缺料或未建成时保留待办状态和因果说明。

### 阶段 D5：远方需求和多段转运

- 建立中亚陆路与印度洋—西亚转口两类有限预算宏观市场，并以间接终端需求节点表达地中海/欧洲需求。
- 给路线设置运力、时滞、成本、风险、政治可达与税费；转运分段结算，终端需求通过滞后订单/报价影响宋境采购，不直接生成出口收入。
- 后续按玩家交互与历史重要度拆分具名港市/商团 Agent；基础市场持续使用聚合需求，控制 AI 调用量。
- 通过路线中断、节点库存和转口商利润验证需求信号是否能产生合理价格/采购变化，又不会造成瞬间传导或无限买家。

### 阶段 D6：市场网络、经营方法与玩家决策面

- 在州府市场落地后，再建立由可达性形成的市场圈和政权/边境/海贸连接；网络变化只改变货物可达集合与交易成本，不复制库存。
- 为少数首批行业定义家庭兼业、民间雇工、官营、官有承包等生产方法，并统一表达岗位、投入、产能、工资/收益归属和管制条件。
- 形成 POP 收入—消费—储蓄/经营留存—再投资闭环；任何经营留存资金都必须有明确的 POP/官府所有权和总账映射。
- 市场按月冻结意向并分层清算，禁止同月成交回流导致无限循环；调整的结果最早在下一轮改变生产/路线意向。
- 通过市场地图、商品详情、建筑详情和回合解释把短缺从结果追溯到道路/政策/原料/岗位/预算等来源；玩家的核心操作集中在制度、基础设施、财政支持与轻重缓急。

### 阶段 E：新内容与 AI 扩展

- 为动态商品、配方、科技、蓝图与装备建设存档级登记与迁移。
- 加入待审提案、批准/拒绝、注册、执行和推演解释状态。
- 测试 AI 多种选择在相同局势下产生不同但守恒、可解释的经济路径。
- 允许 AI 为地方资源和局势提议新产品、工艺、服务、蓝图或装备；未注册定义保持提案/试制状态，完成注册后才能参与实际结算。

## 14. 验收断言

### 账物守恒

- 民间购买：买方货币减少额等于卖方收到额；商品从卖方库存转至买方库存。
- 官府采购：国库减少额与卖方收到额一致；官有库存增加或项目预留增加。
- 平粜/赈济/军需：官仓减少量与市场、POP 或兵粮接收量逐笔对应。
- 生产和加工：原料消耗、产品产量按已注册配方；没有来源的商品不得成交。
- 工程：材料、工钱、运输费分别记账；基准估价不产生额外扣款。
- 所有账本缺失值不按 0/1 静默伪造；数据不可用时明示未定义或挂起相关动作。

### 经济行为

- 需求有差异，但权重允许情境变化和 AI 调整。
- 价格/缺货/运输/政策变化能改变实际购买和供给。
- 贫者有需求但可能未满足；富者可以储蓄、投资或消费，不被固定比例强制支出。
- 市场供给不能重复算入多个买方；官仓未释放的粮不算民间可供粮。
- 住宅投资不等同于月度耐用品消费；材料进建筑后退出可交易库存。
- 加工链投入有扣减、产出有来源；多条行业竞争同一种燃料/劳力时，冲击能传到产量、价格和 POP 收入。
- 服务成交不生成货物库存；服务收入有支付来源及接收方，闲置服务能力不跨期累积。
- 跨府商品必须通过可达交通边，发生在途状态、运费、时滞及配置的风险/损耗；目的地未到货前不可售。
- 官府订单与公共设施能促进民间生产/运输，也能挤占资源或造成价格上升；结果由供需与执行情况产生，不预设单向增益。
- 州府节点迁移后：每个 POP、商品库存、建筑和价格只挂一个州府；路级合计等于下辖州府合计；府际转运不能造成源/目的库存双重可售。
- POP 迁移/阶层转换从源群组扣减并给目标群组入账；出生、死亡等外生项逐项注明，人口总账残差不能以兜底调账替代解释。
- POP 群组拆分与合并前后人数、财富、粮食、商品、欠项守恒；地区/政权汇总均由唯一地域账本单向派生。
- 全境切换实际控制者后，不新造/抹去 POP 和库存；变更地账本仅改变政权归集及制度适用，路级/全国人口和货物总数可复算。
- 部分割让若缺少府/县级源数据，应显式保留未分配残差并显示精度限制，不按面积把人口、钱粮或商品虚拟拆散。
- 控制权易主不自动改变地方群组身份或使市场完全整合；整合速度由政策、官吏执行、交通、制度、地方支持与阻力共同决定。
- 辽、夏、大理以及新并入地区与宋共享商品/POP/交易 schema，但政权制度、货币和财政账户有独立配置；低活跃势力聚合运行也必须兼容升格到细粒度，不得复制或丢失其真账。
- 海外买方需求量、愿付价和支付预算有限；成交同时减少卖方实物并给出买方货物/对价，外部账户变化有来源和上限。
- 市舶司不是默认买方；登记的实际外贸成交才计关税税基。抽象市舶贸易额、银流入、商品出口收入不能重复算成多笔财政收入。
- 海贸/边贸运输中断、关系变化或禁运能改变可成交供给、运输成本和税收；未发生交易时，外销为有依据的 0，不用固定税基伪装成交。
- 建筑存在只提供资产能力，不自动生成商品；实际产量可追到经营主体、地点、岗位/技能、投入、工资、技术、维护、许可和当月销路。
- 每月产出先进入本地经营库存；不能按全国或全路 POP 人口比例分派成品，不能将岗位容量当成实际就业或将蓝图描述当成直接效果。
- 官有/民有与官营/民营、承包/公共服务分别表达；官府调度、采购和征用留有实际支付、执行 Agent、延迟与阻力记录。
- 远方节点预算和路线运力有限；中亚、西亚转口和欧洲终端需求分层，欧洲需求经有时滞的中间商采购影响宋境，不构成宋境直接买家。
- 在途商品只在到达后加入目的地可售库存；沿线再销售、损耗、税费和转口价差有记录，货物和收入不得跨节点重复计算。
- 市场圈只由稳定地域、市场规则和交通连通性派生；市场圈分裂、合并或易主不复制库存，也不抹掉不同州府的价格差异。
- 生产方法切换注明改造/设备/学习成本、生效月份和经营收益去向；所有工资、分红、税款、留存和再投资均能回溯至 POP 或政府账户。
- 月度撮合只读取冻结的当期意向，不因交易结果在同月无限重复采购/改价；优先次序和未满足量有解释，未完成订单可在下月重估。
- 玩家发出贸易/产业旨意后能追踪对应 Agent、预算授权、采购/施工阻塞、受益 POP/行业和副作用，不以一个全国加成替代传导链。
- UI 可从市场短缺追溯到可达路线、在途、来源建筑/主体、停产原因和需求群体；从建筑可查其产出用途、收入分配和对下一月决策的影响。

### AI 推演

- 相同初始种子可复现程序随机数和账目结果；AI 策略可基于情境形成不同合法提案/选择。
- 新提案无注册效果时标为待审/待支持，不假装结算成功。
- AI 的自由行为不能创造钱、库存、人口或建筑；但可改变意图、决策、交易策略和制度方向。
- 因果说明能回答：发生了什么、由谁推动、消耗/获得什么、哪些 POP/行业/地区受影响。
- 月内没有触发 AI 对话时，过月决策仍基于已提交的权威游戏状态和有效命令；纯聊天未落状态时不暗中改变数值。
- AI 输入摘要标明时点和空间粒度；当前路级模拟不得以州府级输入标签呈现。
- 每项重要 AI 决策能追到调用 Agent、输入来源摘要、契约输出和程序采用/拒绝结果；叙事月报不能代替执行日志。
- 一个点击过月只推进一个月；玩家操作、后台 AI 等待和报告演出不额外推进时间；本月晚到的运输/完工产能在指定生效月份之前不可使用。

## 15. 需要在实施前锁定的参数

这些属于平衡或历史数据，不应在架构中写死为唯一真理：

1. 各 POP 的生存口粮、基本衣料及温饱保留量的取值与财富口径。
2. 各地区基础需求和商品替代关系，以及季节、风俗和收入的 AI 调整范围。
3. 开局民间库存、官仓库存与商路在途货物的初始配置依据。
4. 各商品单位、基准价、价格波动带和府际贸易成本。
5. 常平、赈济、军需库存的容量、补充、释放和管理风险。
6. 官营/专营/许可/民营之间各商品的初始规则及可被政策改变的范围。
7. 民居住房容量、维修周期、材料需求与人口/财富增长的关系。
8. 砖、水泥、钢筋等材料的生产来源、技术前置和地区可得性。
9. 赶工预算的构成、工期响应曲线、工匠加班/组织上限和退款规则。
10. AI 对需求、投资、库存策略和新内容提案的可调范围与触发条件。
11. 州府人口/库存/产能历史数据的拆分依据、置信度、旧存档迁移与无法拆分数据的保守处理。
12. 首批核心商品颗粒度、各配方单位/产率、副产物、质量层级和可替代范围。
13. 服务能力单位、服务质量/覆盖定义、费率和工资/经营盈余拆分口径。
14. 各交通模式的节点连边、运力、时滞、运费、季节性、风险和损耗口径。
15. 哪些行业优先建模为 POP 家庭兼业，哪些需要独立作坊/商户经营实体，以及其财富和库存挂载规则。
16. 六类 POP 与生计群组的对应/拆分粒度、家户与扶养人口口径、年龄/劳动参与字段及群组拆并尾差规则。
17. POP 跨职业、阶层、州府和政权流动的月度生效时点、驱动因素与存档记录方式。
18. 稳定地域 ID 的历史粒度、宋境路级遗留残差和无法定位到州府的 POP/货物如何展示与参与市场。
19. 领土主权、实际控制、行政、市场关税、货币、法律与身份分别采用何种制度字段及其状态转换条件。
20. 外邦省域 POP、粗粒度政权人口和宋境经济读数合并到统一地域真账时的迁移顺序、双账防护和兼容期限。
21. 辽/夏/大理和其他势力的模拟层级切换条件、月度 Agent 调用预算、何时把政权级摘要拆为地域账。
22. 边境市场与海贸伙伴节点、外商群体、商品需求篮子、支付额度、汇率/折算及贸易信用规则。
23. 市舶司许可证、抽解税、官府博买/优先采购、禁运商品、走私与查缉在 1101 开局及后续局势中的适用范围。
24. 旧 `calc_maritime_trade` 抽象贸易税基、`silver_in` 金融字段与逐笔进出口交易之间的迁移/去重方案。
25. 中亚陆路节点的具体分段、可达年份和边贸规则；印度洋—波斯湾/红海转口路径、地中海/欧洲终端需求的抽象层级与时滞。
26. 建筑实例的细粒度地点、主体产权/租赁关系、行业配方、职位技能、有效产能、维护和关闭状态的首期范围。
27. 全局 `state.workshops` 迁移到州府地点实例时的历史落点依据；不可定位产能、库存及累计产出的保留与展示口径。
28. 市场圈按行政边界、交通连通、关税区或商人网络划分时，彼此冲突的边界优先规则和每月重算成本。
29. 家庭兼业、雇佣经营、官营与承包生产方法的首批行业范围、工资/利润/留存分配和产权账映射。
30. 月度市场分层撮合的优先级、比例分配、定价窗口、合同履约、破产/停业及未满足订单的下月处理方式。
31. 玩家控制贸易政策和基建的参数范围、Agent 可调整意向边界，以及市场/商品/建筑/回合报告的首批可观测指标。

实施时应先确立算法结构与可观测性，再用开局及长局推演校准这些数值；不能因为某一组参数好看就将其误写成宋代史实。
