## 一、判定原则

| 层级 | 名单 | 设定要求 |
|---|---|---|
| **主要国家** | **宋 · 辽 · 西夏 · 大理 · 高丽 · 日本**（6 个）| **底层一致** + 各自完整的**阶层/派系/文化** |
| **外邦（简化）** | 吐蕃 · 琉球 · 安南 · 占城 · 真腊 · 蒙古诸部 · 女真诸部 · … | 可简化（沿用类型模板）|

⚠️ **吐蕃虽是大地域、且在图上有名**，但按裁定**属简化外邦**（非统一政权）。

## 二、两层架构（🔴 核心概念）

```
┌─ 底层（主要国家之间**一致**）─────────────────┐
│  字段集 / 结算模型 / 口径                          │
│  · 建筑-岗位-就业（生产轨）                        │
│  · 产出/消费/价格/税基/家计                        │
│  · 月度结算流水线、守恒与对账恒等式                │
│  ⇒ **同一套模型，只是数值不同**                    │
└──────────────────────────────────────────────┘
                      ×
┌─ 差异层（**各国不同**）──────────────────────┐
│  · **阶层**（POP 类别）                            │
│  · **派系**（政治派系）                            │
│  · **文化**（礼制/习俗/名号）                      │
└──────────────────────────────────────────────┘
```

### 参照：宋侧现状

```
POP_CLASSES = ("\u519c", "\u58eb\u7eb3", "\u5546\u4eba", "\u5b98\u50da", "\u5175", "\u5de5\u5320")
```

⇒ 宋的 **6 类阶层**是**宋的差异层**，**不是底层**。
辽（游牧/部族）、西夏（党项）、大理（西南）、高丽、日本**各自应有自己的阶层表**。

## 四、目标架构

```
REGIME_PROFILES = {
    "\u5b8b": {...},   "\u8fbd": {...},  "\u897f\u590f": {...},
    "\u5927\u7406": {...}, "\u9ad8\u4e3d": {...}, "\u65e5\u672c": {...},
```

每个 profile 含**两层**：

| 层 | 字段 | 是否各国一致 |
|---|---|---|
| 底层 | 建筑/岗位/产出/消费/价格/税/家计 的**字段与模型** | ✅ 一致（数值不同）|
| 差异 | `pop_classes` / `factions` / `culture` | ❌ **各国不同** |

**外邦**继续走类型模板（现表保留作简化层）。

### 纪律

- 🔴 **主要国家不得落 `default`** —— 缺失应**显式报错**（承 §3-3「缺失≠0」），
  不得静默套用简化模板（现状 `宋`/`高丽`/`日本` 正在犯此错）；
- 新增主要国家 ⇒ 必须同时给出 `pop_classes` 与 `factions`，**不得只给数值**。

## 七、底层 = V3 式「建筑框定生产与职业」（2026-10-05 用户追加裁定）

> 用户：「**底层就是如同 v3 那样的建筑来框定生产和职业**」

### 7.1 引擎**已存在** —— `core/building_jobs.py`

```python
__all__ = ["jobs_of", "allocate_employment", "produce_grain_track",
           "produce_job_track", "evolve_building_levels", "job_flow_unemployed",
           "pay_wages_from_revenue", "pay_construction_cost", "apply_bankruptcy",
           "song_job_cfg", "apply_employment_flow", "live_job_buildings"]
```

⇒ 已具备 V3 式要素：**建筑×等级 → 岗位 → 就业 → 产出 → 工资 → 破产**。

**底层机制链条**：

```
建筑(类型 × lv) ──JOBS_PER_LEVEL──→ 岗位数
      ↓ BUILDING_POSITIONS / POSITION_CLASS
  职业 ──→ 归属哪一类 POP（阶层）
      ↓ PER_WORKER_OUTPUT
  产出（原料 → resources；成品 → goods）
```

🔴 **`POSITION_CLASS`（职业→POP 类）即「差异层」接口** ——
底层机制各国一致，**职业映射到哪个阶层由各国自定**。

### 7.2 🔴 但**两套建筑表结构不同** —— 违反「底层一致」

| | 宋侧 | 外邦侧 |
|---|---|---|
| 表 | `building_jobs.SONG_JOBS_PER_LEVEL` | `EXTERNAL_ECON.JOBS_PER_LEVEL` |
| 建筑 | **农田 / 自耕农庄 / 地主农庄 / 工坊 / 商铺 / 庄园** | **桑麻田 / 林果蔗田 / 牧场 / 矿场 / 工坊** |
| 职业 | 自耕农 / 富农 / 贫农 / 佃农 / 地主 / 工匠 / 商人 | （外邦扁平，`BUILDING_WORKER` 单职位）|
| 产出率 | 见宋侧配方 | `PER_WORKER_OUTPUT[类型]` |

⇒ **宋用「自耕农庄/地主农庄」组织农业，外邦用「桑麻田/林果蔗田」** ——
**同一底层、两套互不相通的建筑语汇**。

### 7.3 🔴 宋侧**缺经济作物建筑** —— 与 §3.2/§5 同一问题

宋的建筑表**无「桑麻田 / 林果蔗田」** ⇒ 经济作物**无处安放**，
只能退回 `production_chain` 的路级 `yields`（**无在岗人口约束**）。

⇒ **这解释了「隐含 84.70% 农 POP 种桑麻」的由来**：
不是设定选择，是**宋侧建筑语汇里没有承载经济作物的建筑**。

### 7.4 修正方向（承 §二「两层架构」）

| 层 | 内容 |
|---|---|
| **底层（各国一致）** | **统一建筑语汇**：粮田 / **桑麻田** / **林果蔗田** / 牧场 / 矿场 / 工坊 / 商铺；机制为「建筑×lv → 岗位 → 产出」|
| **差异层（各国不同）** | ① **职业 → POP 阶层** 的映射（宋：自耕农/佃农→农，地主→士绅；辽：牧民→牧民阶层…）② **派系** ③ **文化** |

⚠️ 宋侧现有的 `自耕农庄 / 地主农庄` 是**宋特色**（反映宋代主户/客户、租佃关系，**有史实依据**）——
**不应简单删除**，而应作为**宋的农业建筑形态**纳入统一语汇（如「粮田」的宋式实现）。

### 7.5 落地顺序（依赖关系）

```
① 统一建筑语汇（底层）—— 先定「各国共用的建筑种类表」
② 各国 POSITION_CLASS 映射（差异层）—— 需史料
③ 宋侧纳入桑麻田/林果蔗田 + 启用岗位轨
④ production_chain 的定位（停用？降为外邦/旧档专用？）
```

🔴 **不可跳步**：③ 依赖 ① ② —— 否则又是「换一种错法」。
