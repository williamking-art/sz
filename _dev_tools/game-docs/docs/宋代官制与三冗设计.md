# 宋祚 · 宋代官制与「三冗」设计

> 缘起：现行官制是**静态派生**的常量（`官 = households × 0.00135`），官数永不增长，因此**冗官不可能发生**，"三冗"无从体现。
> 关联：[财力消耗设计.md](财力消耗设计.md)（L2b/L2c sink、L3 郊赉）、[货币口径规范_M0M1M2.md](货币口径规范_M0M1M2.md)。
> 状态：**设计（待实现）**。量级为建议初值，须回放校准。

---

## 一、现状与缺口

| 现有实现 | 位置 | 问题 |
|---|---|---|
| `官 = round(households × 0.00135)` → 全国 **27,001** 人 | `game_state.py:491` | **静态派生**：人口涨则官涨，但**制度性膨胀完全缺失** |
| `吏 = 官 × 8` → **216,008** 人 | `game_state.py:492`、`CLERK_PER_OFFICIAL=8` | 常数倍数，**不随政务量膨胀** |
| `central_orgs[*].posts` / `holders` / `matter_keys` | `game_state.py:688-709` | **差遣的雏形已存在**，但没有"编制 vs 在册"的差额概念 |
| `waste_reform(kind="reduce_office")` | `settlement_steps.py:429-443` | 只"省浮费"（5–15 万贯/月），**不减官数**；且 `savings` 无上限（审计 D-6） |
| `legacy_mechanic.redundant_officials` | `legacy_mechanic.py:124-129` | 只是一张**遗留问题卡**，不是真实存量 |
| `OFFICIAL_PAY_PER_MONTH=30` / `CLERK_PAY_PER_MONTH=2` | `data.py:183-185` | 单一俸额，**没有品阶差、没有待阙/祠禄的半俸** |

**结论**：现在的模型里，官数是人口的一个函数，**既不会冗，也不会费**。三冗缺的不是数值，是**制度**。

## 二、核心结构：官、职、差遣分离（宋代官制的灵魂）

宋代之所以冗官，根子在**"官"与"差遣"分离**——"官"只定品阶与俸禄，"差遣"才是实职。有官无差遣者照样领俸。

```
本官（寄禄官）rank     定品阶 → 定俸禄   【只增不减：磨勘 / 恩荫 / 科举 / 宗室】
  ├─ 有差遣（在岗）    → 全俸   实职数 = 机构编制（有上限！）
  ├─ 待阙（守选）      → 半俸   守选期待授，积压即冗官
  └─ 祠禄（宫观官）    → 30–50% 俸  安置老病/失意官员的闲职
职名（贴职）honor      馆阁职名，荣誉加衔 → 加俸 + 威望
差遣（实职）post       真正干活 → 定员由 central_orgs.posts + 路级编制决定
胥吏 clerk             不受科举/编制约束 → 随政务量自然膨胀（"软性冗员"）
```

**冗官的可量化定义**（这是本设计的核心指标）：

```
冗官数 = 本官总数 − 差遣定员总数
冗官率 = 冗官数 / 本官总数
月俸禄 = 在岗 × 全俸 + 待阙 × 半俸 + 祠禄 × 折俸 + 职名加俸 + 吏俸
```

于是"冗官"第一次变成**可观测、可入账、可被玩家干预**的存量，而不是一句定性描述。

## 三、增长驱动（冗官的来源，逐条史实）

| 来源 | 机制 | 驱动变量 | 史实 |
|---|---|---|---|
| **恩荫（荫补）** | **每遇郊祀 / 诞圣节 / 大臣致仕或死亡 → 荫补子弟亲属入官** | **郊祀周期（3 年）+ 皇威 + 在朝大臣数** | **冗官主源**：一次郊祀荫补数千人 |
| **科举** | 每科取士入本官 | 科举档位（已有 `exam`） | 每科数百人 |
| **磨勘** | 文官三年一迁、武官五年一迁 → **品级上浮 → 人均俸禄涨** | 时间（自动） | 只要不犯错就按期升 |
| **宗室入官** | 宗室人口一定比例入官 | **宗室人口复利**（见 财力消耗 L2c） | 徽宗朝宗室官激增 |
| **举荐 / 自辟** | 大臣可自辟属官（玩家/ AI 行为） | 大臣意愿、派系 | 幕职官 |
| **待阙回流** | 守选期满须授差遣或转祠禄 → 无阙可授则堆在待阙池 | 时间 | 守选积压 |

> **关键设计**：**把恩荫绑在郊祀上** → 让「郊赉」（财力消耗 L3）同时成为**冗官放大器**。一条机制同时产出**冗官**与**冗费**，史实如此，且省一套新系统。

## 四、抑制途径（每一条都要付代价）

| 手段 | 效果 | 代价 |
|---|---|---|
| **元丰改制式改革** | 一次性裁 20–30%，正官名、定员额 | 皇威门槛高；新党/旧党/宦官满意度下滑；**10–20 年后被磨勘+恩荫重新填满** |
| **裁汰冗员**（改造现有 `waste_reform`） | **真正减官数与俸禄**（而非只省浮费） | 官僚梗阻、怨声渐起（现有文案已有）；派系满意度降 |
| **祠禄安置** | 不裁但转宫观官 → 俸禄打 3–5 折 | 治标不治本；宫观官本身仍是冗费 |
| **考课黜落** | 少量淘汰 | 效率低、得罪人 |
| **限制荫补** | 降低恩荫人数 | 宗室/官僚强烈反对 → 皇威下降 |
| **致仕** | 老龄官员退出 | **同时荫补子弟入官 → 净增**（必须做出来，这是最反直觉也最史实的一条） |

> **设计金句**：让玩家亲身体会——**改革有效，但熵增会把它填回来**。三冗不是一次性 bug，而是与治理熵增的长期斗争。

## 五、三冗闭路（做成机制后会自己放大）

```
冗官（有官无差遣）
  → 冗费（俸禄 + 祠禄 + 职名加俸）
  → 财政压力
  → 加征（工商税 / 役钱 / 折色）
  → 民怨 → 流民
  → 冗兵（募兵安置流民；兵额不可逆，"养兵"是维稳手段）
  → 冗费 ↑↑
  → 更依赖恩荫 / 卖官 / 加税补财政   ←─ 闭环回到冗官
```

这条环一旦跑起来，**玩家必须同时从冗官、冗兵、加征三处下手才压得住**——这正是宋代"积贫积弱"的机理，也是本作最有戏的中后期主线之一。

## 十一、政务量 W 的界定

### 11.1 先说清楚难点

"政务量"没有自然单位。任何定义都是**人为选定口径 + 校准锚点**，所以本设计采取两条诚实原则：

1. **单位取「案牍」**：定义为"每月需要处理／核验／回报的政务件数"（宋代文书政治的直观对应物）。
2. **不追求绝对历史精确，只锚定开局自洽**：以开局 `W₀ ↔ 吏数 216,008` 定出"每吏月办件数 k"，之后所有机制只依赖**膨胀率 `W/W₀`**。

### 11.2 现状：backlog 机制已存在，但驱动源是假的

| 现有实现 | 位置 | 问题 |
|---|---|---|
| `prefectures[路].backlog / efficiency` | `game_state.py:457-458` | 积压**增长纯随机**：`backlog += random.randint(0,3) − efficiency/40`（`settlement_steps.py:904-905`）——**与政务量无关** |
| `central_orgs[机构].backlog / efficiency` | `game_state.py:699-700` | 同上，只有人工 `effects` 能改（`settlement.py:230-231`） |
| `decree_bandwidth` | `game_state.py:370` | 玩家属性，**与处理能力脱钩** |
| `matter_keys` / `posts` | `game_state.py:694-695` | 事权与岗位齐备，**但未折算成事务量** |

> **结论**：缺的不是字段，是**定义**。本设计就是把上面这些字段折成一个可加总的 W，并**替换掉那句 `random.randint`**。

### 11.3 定义

```
W(月) = Σ 各分项（单位：案牍件/月）

处理能力 C = Σ(吏数 × 每吏月办件数 k × 机构效率)
吏需求 C_req = W / k
冗吏 = 吏实际 − C_req

净积压 Δbacklog = W − C        ← 替换 settlement_steps.py:904 的随机增长
```

### 11.4 分项表（全部映射到现有字段）

| K | 外交 | `len(external)` + `treaties` 数 | 每政权 0.5 件/月 | 外事 |
| L | 科举 | `exam` 档位（摊到月） | 按周期 | 铨选高峰 |

**权重原则**：C 与 D 最高（**玩家可干预**且是宋代"事务倍增"的根源）；I 随冗官自动增长（**闭路**）；G 随民怨增长（**正反馈**）。

### 11.5 校准锚点

- 开局：`k = W₀ / 216,008`（每吏月办件数），取整后回代自洽。
- 吏需求：`C_req = C_req₀ × (W/W₀)^α`，**α ≈ 0.8**（规模经济：事务越多，人均效率略升）。
- 只测**膨胀率**，不测绝对值 → 避免"历史精确度"这种无法验证的目标。

### 11.6 与机制的挂接（三个真实杠杆）

| 挂接点 | 现状 | 改为 |
|---|---|---|
| **积压增长** | `random.randint(0,3)` | `backlog += max(0, W_route − C_route)` |
| **机构效率** | 随机漂移 `random.randint(-2,1)` | 由积压反向压制：`efficiency` 随 backlog 超阈值下降 |
| **诏令执行率** | 只受派系立场影响 | **叠加政务积压惩罚** → 积压高则政策打折 |
| **冗吏** | 不存在 | `冗吏 = 吏实际 − C_req` |

**玩家可用的三个杠杆**（这是设计的关键——不然 W 只是个读数）：

1. **少下诏 / 精简在办** → 降 C
2. **裁并机构**（`central_orgs` 已有 `裁撤` / `改下辖`）→ 降 D
3. **增吏**（花钱）→ 升 C，但推高冗费

> 于是形成完整抉择：**要效率就得养更多人，要省钱就得忍受拖延**——这正是宋代"冗费"与"有司拖延"的两难。

### 11.7 为什么这样界定能体现"三冗"

```
冗官（本官 > 差遣定员）
  → I 人事铨选政务量 ↑
  → 吏需求 ↑ → 冗吏 ↑ → 冗费 ↑
  → 财政压力 → 加征 → 民怨 ↑
  → G 刑狱词讼 ↑ → 政务量 ↑↑
  → 积压 ↑ → 执行率 ↓ → 政策打折 → 更依赖加征
```

**冗余官僚自己制造出更多政务，从而需要更多冗余胥吏**——这个自我强化环路，就是"三冗"最本质的机理，也是本界定最大的价值所在。

## 十二、机构精练 vs 历史还原：这不是两难

### 12.1 先纠正一个前提

"要不要把机构全还原"这个两难，预设了**冗官靠"机构数量"承载**。但实测与史实都不支持这个预设。

**实测（开局）**：

| 项 | 数量 |
|---|---|
| 中枢机构 `central_orgs` | **18** 个 |
| 中枢岗位（`posts`）合计 | **34** 个 |
| 中枢事权（`matter_keys`）合计 | 39 项 |
| **本官在册** `Σ prefectures[*].officials` | **27,001** 人 |
| 吏 `Σ prefectures[*].clerks` | 216,008 人 |

官数与岗位**相差 800 倍**，且官数由 `户数 × 0.00135` 派生（`game_state.py:491`）——**与岗位毫无关系**。也就是说，模型里连"有官无差遣"这个概念都不存在。

**史实**：三省六部九寺五监在**唐代已经齐备**，宋代并未大幅新增机构。冗官的载体是：

- **寄禄官不理事**（官只定品阶俸禄，差遣才办事）
- **恩荫大量补官**
- **磨勘按期升迁**（官额只增不减）
- **一职多官 / 添差**
- **祠禄安置闲员**

**结论：机构表可以保持现在的精练，冗官与三冗照样做得出来。**

### 12.2 真解：把「机构」与「官额」解耦

| 层 | 承载什么 | 玩家认知负荷 |
|---|---|---|
| **机构表**（18 个，**保持现状**） | **玩法层**：事权归属、岗位、效率、积压 | 低（就是现在这样） |
| **官额 / 编制**（新增） | **制度层**：冗官的载体 | 低（一个面板、几个数字） |

玩家改的**不是 100 个机构名**，而是**几个编制政策**。

> **顺带修正 §二**：差遣定员的 99% 在**地方层**（20 路 × 州县级额定员），中枢 34 个岗位可忽略。所以 `posts_quota` 应由「路级编制」推出，中枢只作加成。

### 12.3 玩家的交互面 = 6 个编制杠杆（全部走现有诏令链路）

| # | 杠杆 | 效果 | 史实依据 |
|---|---|---|---|
| 1 | **定编宽严** | 全国/各机构官额上限 | 元丰官制定员额 |
| 2 | **荫补之门** | 恩荫规模（**冗官主源**） | 郊祀/诞圣节荫补 |
| 3 | **磨勘年限** | 升迁快慢 → 人均俸禄膨胀速度 | 文三年武五年 |
| 4 | **祠禄比例** | 不裁但转宫观闲职（折俸） | 提举宫观 |
| 5 | **吏额编制** | 每机构吏数 | 胥吏之滥 |
| 6 | **考课黜落** | 淘汰力度 | 考课之法 |

六条都是**拟诏 → 会签 → 落地**，**完全复用现有玩法链路，零新增 UI 负担**。

### 12.4 面板只显示"膨胀倍数"，不显示名单

```
中书省   定编 12     在册 34     待阙 22     膨胀 ×2.8
户部     定编 20     在册 51     待阙 31     膨胀 ×2.6
……
全国     定编 19,000 在册 40,000 冗官率 53%
```

玩家看到的是"**每个机构胖了几倍**"，而不是一份长名单。冗官感来自**倍数的持续变大**，而不是条目变多。

### 12.5 史实细节走「奏议 / 事件」，不做成清单

九寺五监、馆阁贴职、宫观官这类细节，**做成奏议卡按需出现**：

- 「臣请复置某监，以处闲员」→ 准 / 驳
- 「乞以提举某宫观安置老臣」→ 准 / 驳
- 「三司事剧，乞增吏额」→ 准 / 驳

**史实感保留，认知负荷只在需要时出现**——这正是本作「AI 推演 + 奏对」的强项，比一张长机构表更贴合玩法。

### 12.6 顺手一个张力：建机构 = 新增"可膨胀载体"

现有 `central_orgs` 已支持新建机构（`settlement.py:251-266` 的 `新建机构`）。建议：

> **每新建一个机构，就多了一处会荫补、会磨勘、会积压的载体** → 机构越多，冗官基数越大。

于是"**想加强治理，就得接受机构自己会长胖**"——把玩家扩张治理结构与冗官代价连成因果，而不是两个孤立的数值。

### 12.7 一个已存在却从未使用的钩子

实测 `prefectures[*].org_branches` **全为 0**（`game_state.py:518` 有字段与"与 central_orgs 双向索引"的注释，但从未填充）。

这是**路级机构分支**的现成挂点。若日后要给地方层一点纵深（如"某路增设提举常平司"），用它即可——**不必新增字段**。

### 12.8 小结

| 担心的 | 实际 |
|---|---|
| 机构太精练，玩家没得改 | 玩家改的是**6 个编制杠杆**，不是机构表 |
| 全还原会毁游戏性 | **不需要还原**——宋代机构本就不比唐多，冗官来自官额膨胀 |
| 冗官没载体 | 载体是「**定编 vs 在册**」的差额，18 个机构足够承载 |
| 史实细节丢失 | 走**奏议卡按需出现**，反而比清单更有味道 |

## 十三、官制与 POP 的有机结合

### 13.1 先揭一个现存的双账（实证）

`官僚 POP.size` 与 `prefectures[].officials` **已经是两本账**，且正在背离。

**代码证据**：

| 处 | 位置 | 用的哪本账 |
|---|---|---|
| POP 初始化 | `game_state.py:71-72, 91` | `sz_guan = _off + _off*8` → **官僚 POP = 官 + 吏** |
| 俸禄**应发/扣款** | `game_state_econ.py:413, 427` | `p["officials"] × 30 + p["clerks"] × 2` |
| 俸禄**实发分配** | `settlement_steps.py:2930-2939` | 按 `p["pops"]["官僚"]["size"]` 权重 |
| 口粮发放 | `settlement_steps.py:1555-1562` | 按 `p["pops"]["官僚"]["size"]` |
| **科举入仕** | `settlement_steps.py:733-738` | **只加 `pops["官僚"]["size"]`，从不更新 `p["officials"]`** |

**实跑证据**（`_scratch/audit-2026/_probe_dual_ledger.py`，科举档位「大」，seed_offset=7）：

| 月 | Σ官僚POP.size | Σ pref[].officials | 账差 | 国库俸禄支出 |
|---|---|---|---|---|
| 0 | 243,009 | 27,001 | 216,008 | 1,242,046 贯/月 |
| 120 | 261,777 | 27,001 | 234,776 | 1,242,046 |
| 240 | 280,497 | 27,001 | 253,496 | 1,242,046 |
| 360 | **299,217** | **27,001** | 272,216 | **1,242,046** |

> **30 年：官僚 POP +23.1%，`officials` +0.0%，国库俸禄支出 +0.0%。**

**这就是"冗官不花钱"的精确根因**：科举年年往官僚池灌人，而国库发俸的依据是另一个**冻结的**变量。附带后果是——1,242,046 贯被摊到越来越大的池子里，**官僚人均俸禄被稀释 19%**（"当官越来越穷"的观感碰巧对了，但机理是 bug 不是设计）。

**结论：官制要与 POP 有机结合，第一步就是消灭这本双账。**

### 13.2 结合原则：POP 是唯一人头账，官制只是它的「身份视图」

```
Σ pops["官僚"].size        ← 唯一人头权威源（在册官员总数）
      │
      ├─ 官制决定这些人的身份子池：在岗 / 待阙 / 祠禄
      └─ 官制决定俸禄规则：全俸 / 半俸 / 折俸
```

- `prefectures[].officials` **必须废弃或改为从 POP 派生**，不能再独立派生（`户数 × 0.00135`）。
- **每步断言**：`Σ(on_post + waiting + sinecure) == Σ pops["官僚"].size == rank_officials`。
- 这正是审计 P1-3「全局 population vs ΣPOP 背离」的**同类教训**——**不能有第二本账**。

### 13.3 官僚 POP 的内部结构：身份子池

```python
pops["官僚"] = {
    "size": N,          # 不变量：size == on_post + waiting + sinecure
    "on_post":  N1,     # 在岗（有差遣）→ 全俸
    "waiting":  N2,     # 待阙（守选）  → 半俸
    "sinecure": N3,     # 祠禄（宫观官）→ 30–50% 俸
    "wealth": ..., "grain": ..., "goods": ..., "欠税": ...,
}
```

**为什么不新增 POP 类别**：官 / 待阙 / 祠禄**社会身份相同**（都是官户，免役、有官户特权、可荫补）。拆成不同 POP 类别会**破坏免役、税基、迁移、消费**等既有逻辑。子池只是"同一身份的不同在岗状态"。

这样一来，**冗官在 POP 层就变成了"待阙子池持续膨胀"**——这是冗官最具体、最可感的形态。

### 13.4 官与吏必须分账（当前 `×9` 混装是错的）

现在 `官僚 POP = 官 + 吏`（`_off × 9`），把两个阶层塞进一个池子。三条理由说明必须分开：

| # | 理由 | 现状后果 |
|---|---|---|
| 1 | **待遇差 15 倍**（官 30 贯 vs 吏 2 贯） | 同一池无法按身份发俸 → 只能按人头均摊，双双失真 |
| 2 | **社会身份不同**：官是士大夫（免役、荫补、可升迁、无出身限制）；吏是役人（本地、无出身、吏不能升为官） | 免役逻辑把吏也算作官户，**税基被错误豁免** |
| 3 | **消费不同**：现按 `GRAIN_CONSUME_PER_CAPITA["官僚"]=1.8 石/人/月` 给整个池 | 吏按官的标准吃粮，**口粮需求被高估**（吏 21.6 万 × 1.8 石 ≈ 38.9 万石/月） |

**两个方案**：

| 方案 | 做法 | 成本 | 评价 |
|---|---|---|---|
| **A** | 新增第 7 个 POP 类 `吏`，与 `官僚`（仅官）并列 | 高：动 `POP_TYPES`、免役、税基、迁移、消费、存档、前端面板、`drain_pop_wealth`、`_money_pools` | 最史实（吏本就是独立阶层），但**刚出过"人口总账背离"的事故，动 POP 类别要极谨慎** |
| **B**（推荐先做） | 保留 6 类，`官僚` 池内加 `clerks` 子字段，俸禄/口粮/消费**按子池分别算** | 低：只改俸禄分配与口粮两项 | 先把账分开、把 15 倍待遇差做对；验证玩法后再考虑升格为独立 POP |

### 13.5 流动轴：官僚 POP 的入口与出口（**这才是"有机"**）

**官制不是外挂在 POP 上的规则，而是 POP 内部职业流动的规则集。**

```
入口                                    出口
  士绅 ──科举──→ 官      （已有 :733-738）   官 ──致仕/罢黜──→ 士绅   （新增）
  农(寒门)──科举──→ 官   （已有 hard 部分）   官 ──死亡──→ 消失 + 荫补子弟 → 官（净增）
  士绅/宗室 ──恩荫──→ 官 （新增，绑郊祀）      官 ──转祠禄──→ 官僚池内 sinecure 子池
  宗室 ──入官──→ 官      （新增）
```

**闭环**：官退休 → 变回地方士绅 → 士绅子弟再考科举 → 又变官。

**这就是"士大夫再生产循环"**。冗官的定义也随之变得有机：

> **冗官 = 这个再生产循环的产出 > 差遣岗位的需求**

比"官数减定员"这种静态定义有味道得多。

### 13.6 效应轴：冗官经 POP 传导到玩法

| 传导 | 机制 | 已有基础 |
|---|---|---|
| **俸禄** | 官俸总额 ＝ Σ(在岗×全俸 + 待阙×半俸 + 祠禄×折俸) → 国库扣款 → 流入官僚 POP wealth | 已有分配链路（:2930-2939），只需改**总额依据** |
| **免役 → 税基萎缩** | 官僚 POP 免役（役钱只从农征）；官数膨胀 → 免役人口↑ → **役钱税基占比↓** | 已有（`poll_tax` 只从农征）；**这是冗官→财政恶化最史实的一条通道** |
| **消费** | 官僚 POP 有钱就消费 → 工匠/商人 POP | 已有（全 POP 消费机制） |
| **待阙贫困 → 怨望** | 待阙子池人数多、俸薄 → 该池 wealth 低 → 派生怨望 / 民心压力 | wealth 已有，**只差把它接到怨望** |
| **政务量** | 官僚 POP size → 人事铨选政务量（§十一 的 I 项）→ 吏需求 | 需新增 |
| **土地兼并** | 官僚/士绅 wealth 高 → 购地 → 隐田 | 士绅购地逻辑可复用 |

> **其中「免役 → 税基萎缩」是最有价值的一条**：它让冗官**不只是花钱，还直接侵蚀税基**，从而把「冗官 → 冗费 → 财政恶化 → 加征 → 民怨」这条链真正接上 POP。

### 13.7 实施顺序（低风险优先）

| 步 | 动作 | 风险 |
|---|---|---|
| 1 | **消灭双账**：`p["officials"]` 改为从 `pops["官僚"].size` 派生（或直接废弃），并加每步断言 | 低——纯一致性修复，不改数值量级 |
| 2 | **拆身份子池**：`on_post`/`waiting`/`sinecure` 三字段 + 不变量断言 | 低——新增字段，旧档按 `on_post = size` 初始化 |
| 3 | **俸禄按子池计价**：在岗全俸、待阙半俸、祠禄折俸 | 中——**改变俸禄总额**，须回放校准 |
| 4 | **接出口**：致仕 → 士绅；死亡 → 荫补 | 中——新增 POP 流动，须保持 ΣPOP 守恒 |
| 5 | **接税基**：免役人口随官僚 POP 膨胀 → 役钱税基相应变化 | 中——改税基，须回放 |
| 6 | **吏分账**（方案 B → 视情况升格 A） | 中高 |

> **第 1 步是纯 bug 修复，应当立即做**——它不改变任何数值量级，只是让"官僚人数"和"俸禄依据"重新变成同一个数。做完之后，冗官的机制才有承载之地。

## 十四、地方官员：三层可见性 + 群体模拟

### 14.1 核心判断：不是"做不做得出"，而是"分几层可见性"

上万地方官不可能逐个具名，但也不能退化成纯数字。解法是**按可见性分层**：

| 层 | 规模 | 可见性 | 载体 |
|---|---|---|---|
| **中央大员** | ~43 人 | **具名个体**：姓名 / 性格 / 忠诚 / 派系 / 家产 | `MINISTERS` + `central_orgs.holders` |
| **中央派出的地方大员** | **~80–90 岗** | **半具名**：可任免、可在事件中露面 | 新增，挂 `prefectures[].orgs` |
| **州县属官 / 幕职 / 监当** | 上万 | **纯统计池**：只进俸禄、税基、政务量、贪腐聚合 | `prefectures[].officials` 聚合 |

**关键**：中间那层的规模正好是**"中管干部"的量级**（20 路 × 4 司 = 80），玩家管得过来，且**史实上他们本就是中央派出的**——用户提出的"地方干部任免理论上是中央"由此自然成立。

### 14.2 地方治理做「功能条线」，不做「层级树」

不要把路-州-县做成层级树（那是 250 州 × 上千县的爆炸）。**只做路级四司（监司）**：

| 司 | 别称 | 职掌 | 挂接现有字段 | 任免该司的后果 |
|---|---|---|---|---|
| **转运使司** | 漕司 | 财赋上供、漕运 | `local_treasury` / `local_finance` / 到账率 | 上供多寡、财赋调运效率 |
| **提点刑狱司** | 宪司 | 刑狱按察 | `unrest` / `backlog` / 刑狱事权 | 积压、民怨、冤狱 |
| **提举常平司** | 仓司 | 常平仓、赈济 | `granary` / `buildings` / 灾荒响应 | 赈济效率、粮价平抑 |
| **安抚使司** | 帅司 | 一路军政 | `defense_lines` / 军需 | 边防、兵变风险 |

> **四司互不统属、各自对中央负责**——这是宋代"地方被切成四块、无法割据"的制衡设计，**而且恰好就是四个可玩旋钮**。历史上的制度设计与玩法需求在这里重合，是这个方案最幸运的地方。

### 14.3 群体模拟技术：Cohort + 抽样外显 + 回写分布

地方属官不做名单，做**分布**：

```
每路官员池（cohort）= { 人数, 品阶分布, 才能分布, 贪腐分布, 年限分布 }
   每月演化：磨勘 → 品阶上移 ｜ 考课 → 淘汰 ｜ 致仕 → 退出
   抽样外显：每月按概率抽 1–2 人，成为事件主角
             （举荐／弹劾／政绩卓异／贪墨被告／灾荒时的该路主官）
   回写分布：玩家对抽样个体的处置 → 回写该路统计分布
             （严惩贪墨 → 该路贪腐分布整体左移）
```

**成本 O(1) 而非 O(万人)**，但每次处置都对应具体的人，戏剧性不丢。这与 §12.5「史实细节走奏议卡按需出现」是同一套思路。

### 14.4 知州–通判制衡 → 做成路级聚合参数

宋代**通判与知州共签，政令方生效**（"一州二守"）。250 州无法逐一具名，所以做成**路级聚合**：

- 每路维护 `dual_sign_tension`（知州–通判协作度 0–1）
- 协作度低 → 该路**政令执行率↓、积压↑**（互相推诿）
- 玩家可 **增派通判**（加强中央控制，但增加冗官）或 **省并通判**（提高效率，但地方坐大风险）
- 这是"**控制 vs 效率**"的经典取舍，非常宋代

> **可选增强**：给 8–10 个史实重镇（开封府、杭州、扬州、大名府、江宁府…）单独具名知州。数量可控，且这些地方本就该有故事。

### 14.5 三条任职规则做成政策杠杆

| 规则 | 史实动因 | 放松后的收益 | 放松后的代价 |
|---|---|---|---|
| **三年一任** | 防久任专权 | 任期长 → 治理熟、效率高 | 地方坐大、尾大不掉 |
| **回避本籍** | 防地方势力 | 熟悉民情、施政贴切 | 门阀滋生、隐田难清 |
| **内外互调** | 防内外隔阂 | 专业化、任期稳定 | 中央对地方失控 |

三条都是**拟诏可调**，每条都有真实取舍——**不设"正确选项"**。

### 14.6 官员质量：让恩荫有"素质代价"

- 每路维护 **人均才能** 与 **人均贪腐**（纯统计，不具名）
- 由**入仕结构**决定：科举比例高 → 才能高；**荫补比例高 → 才能低**
- 才能低 → 积压↑、贪腐↑、民心↓

> **这就把恩荫的代价做实了**：恩荫不只是多花钱（**数量**），还降低地方治理质量（**素质**）。史实上荫补官正是被讥为"冗滥"——数量与素质两条腿都该有代价。

### 14.7 数据落地：钩子早已预留，零新结构

**实测**：`prefectures[路]["orgs"]` **20 路全为空**，而 `central_orgs[*]["branches"]` **18 个机构全有**——`game_state.py:518` 注释写着"本路所辖机构分支列表（与 `central_orgs[机构]["branches"]` 双向索引）"，**脚手架早已存在，只是从未填充**。

central_orgs["两浙路漕司"] = {          # 复用中枢机构的同一结构，零新 schema
    "posts": [{"title": "转运使"}, {"title": "转运副使"}],

## 十五、科举：一期数百进士如何体现

### 15.1 先纠正一个形态错位（实证）

现在的"科举"**不是三年一科，而是每月细水长流**：`POP_FLOW_RATE["科举"] = 0.0001`（0.01%/月），在 `settlement_steps.py:733-738` 按月把士绅/农转入官僚 POP。

实测（士绅 POP = 1,122,014）：

| 档位 | 人/月 | 人/年 | **人/3年（一科）** |
|---|---|---|---|
| 微 | 28 | 336 | 1,008 |
| 小 | 56 | 672 | 2,016 |
| **中** | 112 | 1,344 | **4,032** |
| **大** | 168 | 2,016 | **6,048** |
| 极 | 280 | 3,360 | 10,080 |
| **史实** | — | 70–270 | **200–800**（含特奏名可至 800+） |

**两个错位**：
1. **形态错**：连续月流 ≠ 三年一次的爆发式发榜；
2. **量级错**：现行「中」档 4,032 人/3年，是史实的 **5–20 倍**。

附带：因 §13.1 的双账 bug，这些新增官僚**从不产生俸禄支出**——即当前"取士"既不花钱、也不爆表，纯属幽灵人口。

### 15.2 改为「离散科次」——这是形态的根本修正

- 每 **36 个月**触发一次 `_hold_exam(state)`，**一次性**产生 N 名进士（N 由取士政策决定）。
- `POP_FLOW_RATE["科举"]` 的连续月流应**废弃或大幅下调**（仅保留极小的常态"流外入官"）。
- 对接点已经齐备：`EXAM_INFO`（`open` / `mode` / `talent_pool`）、`EXAM_ACTS`（**已定义**「开科取士／改革科举(经义)／改革科举(词学)／兴州县学／制科荐才／武举」）。
- **事件卡也是现成的**：`events.py:169`「学校贡举法·罢科举行三舍」——崇宁三年罢科举改三舍法，正是徽宗朝真实发生过的重大科举改革。

### 15.3 三层显影（沿用 §14 的分层逻辑）

| 层 | 每科规模 | 显影方式 |
|---|---|---|
| **一甲**（状元／榜眼／探花 ＋ 前 10） | 3–10 人 | **具名个体** → 入翰林/馆阁，进中央候选池 |
| **二甲三甲** | ~50–100 人 | **半具名** → 进 `exam.talent_pool`（**已存在**，0–100），可被举荐、可外放路级四司 |
| **其余** | ~400–600 人 | **纯统计** → 进地方官员 Cohort，**归属其科次** |

> **玩家每科只看到 3–10 个名字**（"崇宁二年取士 538 人，状元某某入翰林"）——一次事件、一个数字、一个名字。**仪式感有，认知负荷零。**

### 15.4 科次（同年）＝ 载体，也是党争的真实来源

宋代士人极重"**同年**"（同榜进士），这是**跨派系的政治关系网**。做成批次对象：

```python
state.exam_cohorts = [
    {"year": 1103, "label": "崇宁二年榜", "count": 538,
     "avg_talent": 72, "hard_poor_share": 0.7,
     "members_named": ["状元某某", "榜眼某某", "探花某某"],
     "members_central": 3, "members_local": 535,
     "faction_lean": {"新党": 0.4, "旧党": 0.3, "东南士人": 0.3}},
    …
]
```

**核心机制：同年援引**——某人升到高位，会援引同年来做下属（宋代荐举制度）。

- **党争不再是"新党/旧党"这种抽象派系，而是具体的科次网络**；
- 且它**自然解释三冗的一个侧面**：同年援引 → 互相安排差遣 → 冗官。

（派系已有「东南士人」＝ 东南科举士绅，可作为科次倾向的落点。）

### 15.5 科举应该是「玩家与士绅的博弈」——游戏性的真正来源

现在科举只是一个被动的经济推演档位。它应该是**一次交易**，每个杠杆都有代价：

| 政策杠杆 | 史实依据 | 收益 | 代价 |
|---|---|---|---|
| **取士规模** | 每科取士数 | 士绅/清流满意、皇威↑ | **冗官↑**（直接灌入待阙池） |
| **考试内容**（经义／诗赋／策论） | 王安石改经义取士引发党争 | 决定新进士的**才能结构与派系倾向** | 另一种倾向的派系怨望 |
| **地域配额**（南北分卷／各路定额） | 宋代科举的地域矛盾 | 各路士绅满意 | 倾斜则另一地怨望 |
| **特奏名（恩科）** | **史实：特奏名是冗官重要来源** | 安抚屡试不第者、稳定士林 | **大量低素质冗官** |
| **学校／三舍法** | 崇宁三年罢科举行三舍 | 绕过科举直接培养、控制取士权 | 士林反弹（事件卡已有） |

> **特奏名是最佳机制**：它是"安抚落第士人"的政治手段，代价是大量低素质冗官——**完美的两难**，而且完全史实。

### 15.6 落第也是机制（两端都有代价）

```
取士少 → 落第多 → 士绅怨望 → 民怨 / 社会不稳
取士多 → 冗官↑ → 冗费↑ → 加征 → 民怨
```

**两端都要付代价**——这才是科举该有的张力，而不是"取士越多越好"。

与 POP 的接口：**落第者留在士绅/农池**，但派生"怨望"（史实：落第士人是社会不稳定因素）。

### 15.7 最关键的连接：科举规模 = 冗官的进水阀

```
一期数百进士
  → 一次性灌入地方官员池数百人
  → 差遣（差遣定员）不会同步增加
  → **待阙池立刻膨胀**
  → 俸禄半额支出↑ + 免役人口↑（税基萎缩）
```

史实上正是如此——宋代"员多阙少"，进士守选多年不得差遣。

> **所以"一期数百进士"完全不必具名**：它的影响通过**待阙池人数**与**俸禄总额**体现。玩家看到的是"本榜取士 538 人，待阙者又添五百"，而不是 538 个名字。

### 15.8 与其他系统的接口

| 系统 | 接口 |
|---|---|
| **POP** | 来源＝士绅 POP（elite）＋农 POP（寒门，`EXAM_HARD_POOR_SHARE` **已有**）；去处＝官僚 POP / 地方 Cohort |
| **官制** | 进士入地方池后，**等不到差遣者进待阙池** ← 与 §13.3 的身份子池直接对接 |
| **素质** | 进士 `avg_talent` 高（考出来的）→ 提升其所在路的 `人均才能`（§14.6） |
| **政务量** | 新增官员 → §十一 的 **I 人事铨选** |
| **M 口径** | 俸禄经 `apply_flow` 出账；考生路费/贡院/学校是**可选的消耗口** |

### 15.9 实施顺序

| 步 | 动作 | 风险 |
|---|---|---|
| 1 | 把月度流改为**36 个月一次的离散科次**；`POP_FLOW_RATE["科举"]` 下调 | 低——形态修正，总量按史实校准 |
| 2 | 取士数按史实锚定（**200–800 人/科**，可由政策放大到 1,000+） | 低 |
| 3 | 一甲具名（3–10 人）+ 二三甲入 `talent_pool` + 其余入地方池 | 中 |
| 4 | 建立 `exam_cohorts` 科次对象 + **同年援引**机制 | 中——接入派系与荐举 |
| 5 | 五个政策杠杆接诏令（取士规模/内容/配额/特奏名/三舍法） | 中 |
| 6 | 落第怨望接民心/不稳 | 中 |

## 十六、吏员制度

### 16.1 定位：吏是「不可见的执行层」

| | 官 | 吏 |
|---|---|---|
| 可见性 | 具名、可任免 | **不具名、纯群体** |
| 任期 | 三年一任、**回避本籍**（流官） | **世代盘踞本地** |
| 出身 | 科举/荫补，士大夫 | 差役/募吏，**不能升为官** |
| 职责 | **决策与责任** | **实际执行** |

> **玩家的政策效果 ＝ 官的意愿 × 吏的执行力。** 官是玩家看得见的手，吏是看得见的**结果**、看不见的**原因**。

### 16.2 体检：现行吏制的四个空白（实证）

| 项 | 现状 |
|---|---|
| **吏额** | `clerks = officials × 8`（`CLERK_PER_OFFICIAL`），**静态常数**，不随政务量变动 |
| **吏禄水平** | 2.0 贯 + 本色 1.5 石（≈1.5 贯）＝ **3.50 贯/月**；官 45 贯/月 → **官吏待遇比 12.9 : 1** |
| **能否养家** | 户均 4 口 → 需 4 × 1.8 石 ＝ 7.2 石 ＝ **7.2 贯/月**；吏所得 3.50 贯 → **缺口 3.7 贯/月，仅覆盖家庭口粮的 49%** |
| **后果** | **吏禄不足没有任何后果**——吏只是变穷（POP wealth 少），**不产生陋规、不产生腐败** |
| **身份** | 与官**混装在同一 POP**（`×9`）；免役逻辑把 21.6 万吏也算作官户 |

> 实证脚本：`_scratch/audit-2026/_probe_clerks.py`。结论：**吏制的三个关键机制（陋规、把持、吏怨）在现行模型中全部缺失**——吏只是一个"每月领 2 贯的人数"。

### 16.3 吏的五个聚合属性（路级，不具名）

| 属性 | 驱动 | 后果 |
|---|---|---|
| **吏额**（编制/实际） | 政务量需求（§11）＋ **编制惯性** | 冗吏 |
| **吏禄充足度** | 地方财力（`pay_ratio` **已有**）＋ 制度性俸薄 | **陋规强度** |
| **把持度** | 世袭、久任、回避政策 | 政令被扭曲 |
| **吏怨** | 吏禄不足 ＋ 裁减 ＋ 被压制 | 消极怠工、阳奉阴违 |
| **来源结构** | 差役 / 募吏 / 世袭 | 影响把持度与民户负担 |

### 16.4 核心机制一：吏强官弱

```
官：三年一任、回避本籍、不熟地方
吏：世代本地、熟稔案牍、掌握簿书
        ↓
官必须通过吏才能落地政令
        ↓
把持度高 → 政令被"翻译"成对吏有利的版本
```

机制化：`实际执行率 ＝ 官效率 × (1 − 把持度 × w)`

> **这里有一个重要的设计转折**：审计 J-2 发现"**叙事说办了、数值没动**"当前是一个**无载体的随机 bug**（模型撒谎，程序不拦）。吏制正好能给这种"执行偏离"一个**有原因、可诊断、可治理**的载体——
> 玩家看到的诏令回执仍是"已施行"，但实际效果打折，**而原因可以在面板上查到**："该路吏胥把持，政令不畅"。
> **同样的现象，从 bug 变成了机制。** 这不是给 bug 找借口，而是让偏离**可归因、可干预**。

### 16.5 核心机制二：吏禄 → 陋规 → 民怨（最史实，也最有戏）

```
吏禄不足（制度性俸薄 12.9:1 ＋ 地方财力不足）
        ↓
吏靠「陋规 / 常例」取偿
        ├─ ① 民户被额外盘剥（农/工商 POP wealth 扣减）
        ├─ ② 商税被截留（入库税额减少）
        └─ ③ 民心下降
```

**玩家取舍**：**给吏发俸以养廉**（加财政支出）**vs 纵容陋规**（损民心与税基）。

史实锚：神宗朝确有"**吏禄**"改革——给吏发俸以养廉，效果有限但方向正确。这正是「**花钱买治理**」的经典决策。

> **这条给玩家的是一种特殊的腐败**：不是"某个贪官"，而是**制度性、系统性、看不见的腐败**——而它恰恰是三冗里最难治的一环。

### 16.6 核心机制三：冗吏与积压并存（史实悖论）

```
C_eff = 吏数 × k × (1 − 吏怨/100) × (1 − 把持度 × w)
冗吏  = 吏实际 − (W / k)
```

**吏数够、但吏怨高 / 把持度高 → 有效处理能力反而不足 → 依旧积压。**

这就是宋代"**吏员冗滥**"与"**有司拖延**"同时存在的机理——**冗而不足**。单纯看人数会觉得该办的都办得完，实际却处处梗阻。

### 16.7 来源与世代化

| 来源 | 机制 | 代价 |
|---|---|---|
| **差役**（乡户轮差） | 从农/士绅 POP 抽调（须保 ΣPOP 守恒） | 不花钱，但**扰民**（民户负担落在农身上） |
| **募吏** | 招募，需俸禄 | 花钱，但可控、专业 |
| **世袭吏户** | 吏职世代相传 | **把持度上升** → 吏强官弱 |

**政策杠杆**：`差役 vs 募吏`（不花钱扰民 / 花钱可控）、`是否限制世袭`（限制 → 降把持度，但得罪地方豪强）。

### 16.8 与 POP 的关系（承 §13.4）

- 吏**不是士大夫**（不能升官，制度性鸿沟），也**不是普通民户**（有职役身份与陋规收入）
- **短期（推荐）**：官僚 POP 内 `clerks` 子池，分开计俸 / 口粮 / 消费
- **长期**：升格为**第 7 个 POP 类 `吏`**，属性接近"城镇职役户"
- 若走**差役**来源 → 从农/士绅 POP 抽调，**必须保 ΣPOP 守恒**

### 16.9 玩家可见性

- 吏**不具名**
- 面板：吏额 / 冗吏率 / 吏禄充足度 / 把持度 / 吏怨
- **定性四档**：`案牍清明 → 吏习其事 → 吏胥弄权 → 吏弊丛生`
- **奏议外显**（按需具名，与 §12.5 一致）：
  - 「某路吏胥舞弊，按察使劾之」→ 查办 / 姑息
  - 「某州吏额不足，案牍壅积，乞增吏」→ 准 / 驳
  - 「豪强把持吏职，乞禁世袭」→ 准 / 驳（得罪地方）

### 16.11 实施顺序

| 步 | 动作 | 风险 |
|---|---|---|
| 1 | **吏额脱离「官×8」**，改由政务量需求驱动（§11），保留编制惯性 | 中——改变吏数，须回放 |
| 2 | **吏禄充足度 → 陋规强度 → 民户盘剥/税收截留/民心下降** | 中——新增资金流，须走 `apply_flow` |

| 5 | 来源结构（差役/募吏/世袭）+ 三条政策杠杆接诏令 | 中 |
| 6 | 吏从官僚 POP 中分账（子池 → 视情况升格为第 7 类） | 中高 |

> **优先级建议**：**第 2 步（吏禄→陋规）单独就能撑起一套玩法**——它把一个"看不见的阶层"变成了玩家必须面对的财政-民心取舍，且完全复用已有的 `pay_ratio` 与 `calc_corruption_deduction`。建议先做它。

## 十七、改制为公务员制度（穿越者的制度优势）

### 17.1 核心论点：公务员制**不是新系统**，而是同一组参数的另一组取值

直觉上会想"新建一套公务员系统"。但 §13（身份子池）、§14（地方四司）、§16（吏的五个属性）已经产出的是一套**参数化制度**：

> **宋代官吏制 ＝ 这组参数的一组值；公务员制 ＝ 同一组参数的另一组值。**
> **改制的本质是"移动参数"，不是"新建系统"。**

这直接回答了"不做大的调整"——**不需要新账本、新机构表、新 POP 类别**。

### 17.2 宋代已具备全部要素——"中国天然适合"的机制表达

| 现代公务员制要素 | 宋代已有 | 设计落点 |
|---|---|---|
| 考试录用 | **科举** | `exam` / `EXAM_ACTS`（已定义 6 个动作） |
| 考核晋升 | **考课 / 磨勘** | §十 O-D3 |
| 独立监察 | **御史台 / 提点刑狱司** | `central_orgs` 御史台 / §14.2 宪司 |
| 常任职业官僚 | 官僚阶层 | 官僚 POP |
| 品级序列 | **本官品阶** | §13.3 身份子池 |
| 编制管理 | **元丰官制定员额** | §12.3 定编杠杆 |
| 退休制度 | **致仕** | §13.5 出口 |

**七项要素宋代全有**。所以转轨不是"移植外来制度"，而是**把已有的推到极致**——这正是"中国天然适合公务员制度"最准确的机制表达（史实上西方文官制度本就参考中国科举）。

### 17.3 转轨三条路线（每条独立推进，各有代价）

| 路线 | 内容 | 收益 | 代价 |
|---|---|---|---|
| **A 并轨** | 官/吏并轨为一元序列，取消 12.9 : 1 的待遇鸿沟 | 消灭**吏强官弱**与**陋规** | **俸禄总支出大涨**（见 17.5）；吏的既得利益反弹 |
| **B 归一入口** | 罢恩荫、罢世袭、禁差役 → 全部考试录用 | **从源头掐断冗官的两个主源** | 得罪宗室 / 士绅 / 地方豪强（皇威↓、派系满意度↓） |
| **C 考绩晋升** | 磨勘"按年必升" → 按考核结果晋升 | 打破熵增，冗官率下降 | **得罪全体官僚** |

三条可独立推进、也可组合——**这就是政策设计空间**。

### 17.4 范围界定（已决策）：**不做转轨系统**，只保证「参数可被政令修改」

> **决策**：不为公务员制做专门的转轨子系统（不做"归一入口"，不做转轨开关）。
> **理由**：
> - 游戏已有完整的政令链路（拟诏 → 会签 → 落地 → 结算），**制度变更本就是它的职责**；
> - 若专门做一套"转轨开关"，等于把玩家的制度设计权收回到开发者手里，反而**削弱玩点**（与 17.8 红线一致）；
> - 玩家（穿越者）应当**自己用政令**一步步把官吏制推成公务员制——**这才是"认知优势"该有的形态**。

**因此 §17 的产出不是代码，而是「参数清单」**：只要下列参数**可被政令修改**，公务员制就是玩家能自行达成的结果。

| 参数 | 出处 | 改后效果 |
|---|---|---|
| 编制（官额／吏额上限） | §12.3 定编杠杆 | 冗官冗吏的总闸 |
| 吏职级薪基 | §16.3 吏禄充足度 | 陋规强度 |
| 恩荫规模 | §三 增长驱动 | 冗官主源 |
| 磨勘年限／考绩 | §四 抑制途径 | 俸禄膨胀速度 |
| 世袭比例 | §16.7 | 把持度 |
| 差役／募吏结构 | §16.7 | 民户负担 ＋ 把持度 |

**唯一的工程要求**：这六个参数必须落在 `free_effect` / `state_applier` 的合法路径白名单内，能被 AI 拟诏与结算消费。**不新增系统、不新增界面。**

### 17.5 财政现实：为什么不能一步到位（实测）

脚本 `_scratch/audit-2026/_civil_service_scenarios.py`，完整月入 **6,842,473 贯**：

| 情景 | 吏额 | 吏薪(贯) | 吏俸折色/月 | 占月入 | 可行性 |
|---|---|---|---|---|---|
| 现状 | 216,008 | 2 | 432,016 | 6.3% | 基准 |
| 只提薪不裁 | 216,008 | 15 | 3,240,120 | **47.4%** | 财政难以承受 |
| 只裁不提 | 72,002 | 2 | 144,004 | 2.1% | 可，但腐败未治 |
| **先裁后提（推荐）** | 72,002 | 15 | 1,080,030 | **15.8%** | **可接受** |
| 提薪到官同薪 | 216,008 | 30 | 6,480,240 | **94.7%** | **不可行** |

> **结论**：公务员化必须"**先定编、再提薪**"，一步并轨必崩。
> 这既是史实（神宗朝「吏禄」改革难行——不是不想给，是给不起），也是**最真实的政策设计空间**。

### 17.6 与 POP 的有机结合（**POP 结构一行不用改**）

| 转轨动作 | POP 层的变化 | 需改 POP 结构？ |
|---|---|---|
| 官/吏并轨 | `clerks` 子池的**待遇系数**归一 | ❌ |
| 入口归一 | `士绅/农 → 官僚` 通道扩大；`恩荫` 通道关闭 | ❌ 只改通道权重 |
| 罢荫补 | 官僚 POP **自我复制率↓** → 士绅 POP 增速↓ | ❌ |
| 退休不补 | 出口（官僚→士绅）不再产生回流入口 | ❌ |
| 俸禄归一 | `clerks` 子池 wealth↑ → 消费结构变化 → 带动工匠/商人 | ❌ |
| 禁世袭轮调 | `把持度`↓；免役/税基逻辑不变 | ❌ |

**六项全部落在"参数与流动规则"上**——与 §13.5 的「士大夫再生产循环」是同一套流动规则，只是改了通道权重。

### 17.7 终点指标（玩家自己争取来的目标）

| 指标 | 宋代设定（30 年无改革） | 公务员制终点 |
|---|---|---|
| 冗官率 | ~67% | **< 10%** |
| 待阙 | 持续膨胀 | **→ 0** |
| 祠禄 | 大量闲员 | **→ 0** |
| 官吏待遇比 | 12.9 : 1 | **→ 1 : 1** |
| 陋规强度 | 高（俸薄必然） | **↓ 由吏禄改革自动产生** |
| 把持度 | 高（世袭本地） | **↓ 由禁世袭 + 轮调自动产生** |

**这是一组明确的"改革完成度"**——可量化、自己挣来、可展示给玩家。

### 17.8 玩法本质：认知差就是玩点（也是红线）

- 玩家（现代人）**知道**"考试录用 ＋ 定编 ＋ 高薪养廉 ＋ 考绩"是出路；
- 而士绅 / 宗室 / 官僚按宋代逻辑认为"祖宗之法不可变"。
- 机制化：**阻力来自派系满意度与皇威**（已有），**收益来自长期财政与治理质量**。

> ⚠️ **红线**：**不能给玩家"点一下就现代化"的按钮**。否则认知优势变成白送增益，玩点就没了。
> 认知优势应体现为"**知道该往哪走 ＋ 愿意承担代价**"，而不是"没有代价"。
> 三条路线各自得罪不同群体、都要花几十年、都会被熵增部分回填——**这才是穿越者的真实处境**。

### 17.9 实施顺序（已按「不做转轨系统」收敛）

| 步 | 动作 |
|---|---|
| 1 | 把 §17.4 的六个参数纳入**可改路径**（`free_effect`／`state_applier` 白名单 ＋ 结算消费） |
| 2 | 参数改动的**代价由派系满意度／皇威自动给出**（复用已有机制，不新写规则） |
| 3 | 终点指标（冗官率／待阙／祠禄／待遇比／陋规／把持度）接面板，作为**改革完成度的读数** |

> **转轨不由开发者实现，而由玩家在局内通过政令逐步达成。**
> 这让"穿越者知道该往哪走"成为真正的玩法，而不是一次性按钮。
