# 宋祚 · 货币口径规范（M0 / M1 / M2）

> 目的：给游戏内所有"钱"建立**单一权威口径**与**逐月对账恒等式**，使"凭空造币 / 凭空销毁"在**构造上可观测、可断言**——这是审计中 A-2、A-4、A-5、D-6 等守恒破口能长期存活的根本原因（游戏没有货币总量概念，各自改各自的字段）。
>
> 状态：**规范（待实现）**。未改动任何源码。相关审计见 [review_2026-09-18.md](../analysis/review_2026-09-18.md)、修复计划见 [fix_plan_2026-09-18.md](../analysis/fix_plan_2026-09-18.md)。

## 一、现行模型的三处结构性错误

现行实现集中在 `core/game_state_econ.py:99-130` 的 `calc_price_level()`：

```python
pop_wealth = Σ prefectures[*].pops[*].wealth
copper_base = pop_wealth + max(0, treasury) + max(0, imperial_treasury)
jiaozi_eff  = jiaozi["issued"] × jiaozi["trust"]/100
silver      = maritime["silver_in"] × (1 if maritime["open"] else 0) × 10000
money       = (copper_base + jiaozi_eff + silver) × (1 − coin["private_melt"])
money_supply = max(0, money)
```

| # | 错误 | 位置 | 说明 |
|---|---|---|---|
| **E1** | **把流量当存量** | `game_state_econ.py:114` | `maritime["silver_in"]` 的定义是"海外白银流入（**万两/年**，基准）"——是**流入速率**，却被当成"手上的白银存量"直接计入货币总量。游戏**根本没有白银存量字段**。 |
| **E2** | **系数误乘整坨** | `game_state_econ.py:116` | `private_melt`（"铜钱私铸/外流比例"）按定义只能作用于**铜钱**，却把 `treasury` / `imperial_treasury` / `jiaozi_eff` / `silver` 一并缩水 10%。这是纯记账错误，且会**掩盖**其他科目的真实变化。 |
| **E3** | **无总量口径、无对账** | 全库 | `money_supply` 只是每次调用时**派生**的读数，不是被维护的存量。以下账户**完全游离在口径之外**：`prefectures[*].local_treasury`、`pops[*].窖银`（士绅窖藏银）、`coin["melted_pool"]`（熔铜池）、`bank["reserve"]`、`bank["capital"]`、`jiaozi["reserve"]`。于是"某账户凭空多出 10 万贯"在总量上**不可观测**。 |

> 代码注释本身也承认了口径缺口：`settlement_steps.py:1206`「local_treasury 不在 money 公式」、`:1142-1143`「熔铜池**不在** money 公式」、`:1790`「local_treasury 不在 money 公式」。

## 二、账户表（谁持有钱）

**每一个持有货币的账户都必须在此表登记，且归属唯一、互斥。** 未登记的账户不得出现在任何资金流动中。

| 账户 ID | 游戏字段 | 性质 | 当前是否在口径内 |
|---|---|---|---|
| `pop.<阶层>.<路>` | `prefectures[路].pops[阶层].wealth`（农/士绅/工匠/商人/官僚/兵 × 20 路） | 民间持钱（铜钱+交子混装，**未拆分**） | ✅ 在（但未拆分） |
| `treasury` | `state.treasury` | 国库 | ✅ 在 |
| `imperial` | `state.imperial_treasury` | 内帑（皇帝私库） | ✅ 在 |
| `local.<路>` | `prefectures[路].local_treasury` | 地方府库 | ❌ **不在** |
| `hoard.<路>` | `prefectures[路].pops["士绅"]["窖银"]` | 士绅窖藏银（退出流通） | ❌ **不在** |
| `melt_pool` | `state.coin["melted_pool"]` | 熔铜池（钱→铜料，退出流通；硬上限 1e8） | ❌ **不在** |
| `bank_reserve` | `state.bank["reserve"]` | 银行准备金 | ❌ **不在** |
| `bank_capital` | `state.bank["capital"]` | 银行资本 | ❌ **不在** |
| `jiaozi_reserve` | `state.jiaozi["reserve"]` | 交子本钱准备（200 万贯） | ❌ **不在** |
| `silver_stock` | **不存在（需新增）** | 海外白银存量（贯） | ❌ **字段缺失** |
| `paper_issued` | `state.jiaozi["issued"]` | 交子发行**面值**（负债侧） | ⚠️ 在（但被当资产混算） |

## 三、口径定义（M0 / M1 / M2 / M3）

**分层原则**：越靠近 M0 越"活跃"（能立刻买东西），越往外越"沉淀"（存在但不在市面转手）。

| 口径 | 名称 | 定义 | 组成 |
|---|---|---|---|
| **M0** | **流通中通货** | 真正在市面上转手的钱 | Σ POP wealth 的**铜钱部分** ＋ **有效交子**＝`issued × trust/100` |
| **M1** | **狭义货币** | M0 ＋ 政府即付资金 | M0 ＋ `treasury` ＋ `imperial` ＋ Σ `local.*` |
| **M2** | **广义货币** | M1 ＋ 沉淀/退出流通 | M1 ＋ Σ `hoard.*` ＋ `melt_pool` ＋ `bank_reserve` |
| **M3** | **全社会货币资产** | M2 ＋ 潜在与对外 | M2 ＋ `silver_stock` ＋ `bank_capital` ＋ `jiaozi_reserve` |

**拆分的处理**：POP `wealth` 目前是铜钱与交子的混合数。规范要求按**现有 `_copper_share` 逻辑显式化**（`settlement_steps.py:1948-1952` 已有该算法）：

```
jiaozi_eff = jiaozi.issued × acceptance
copper_share = clamp(1 − jiaozi_eff / (jiaozi_eff + ΣPOP wealth + treasury + imperial), 0, 1)
M0 = (Σ POP wealth) × copper_share  +  jiaozi_eff
```

**不变量**：M0 ≤ M1 ≤ M2 ≤ M3，且相邻两层之差**非负**（若为负说明账户分类写错）。

## 四、会计恒等式与月度对账（本规范的核心）

### 4.1 全社会货币总量

```
M_ALL = Σ POP wealth + treasury + imperial + Σ local.*
      + Σ hoard.* + melt_pool + bank_reserve + bank_capital + jiaozi_reserve + silver_stock
```

（口径为 M3 的会计全集；`paper_issued` 是**负债**，不计入 M_ALL，见 §4.3。）

### 4.2 变更分解

每月结算后必须满足：

```
ΔM_ALL  ==  外部净注入  −  真实销毁  +  误差
```

| 项 | 通道 | 举例 |
|---|---|---|
| **外部净注入** | 从游戏经济外部进入货币体系 | 市舶海外白银**流入**（`silver_in` 的月度流量，而非存量）、外邦岁币银绢折钱入账 |
| **真实销毁** | 货币永久退出（变成实物或消失） | 交子换界工墨费销毁（`JIAOZI_REDEEM_FEE`）、铜钱熔化出库为铜料**后**铜料离库、铜钱跨境外流 |
| **内部转移** | 账户之间搬钱 | 税收入库、俸禄发放、平粜回收、窖银入窖/出窖、内帑调拨、抄没、**资产维持费（国库 → 工匠/商人 POP）** |
| **误差** | **必须恒为 0** | 任何造币/销毁都会让误差非零 |

> **「或有负债」不进任何 M 口径（口径纪律）**：游戏把"付不出的应付"记为**备忘科目**而非账户：
> `statistics["pay_arrears"]`（军俸欠饷）、`statistics["upkeep_arrears"]`（资产维持欠费）、
> 各 POP 的 `欠税`、`ArmyUnit.arrears`（各军欠饷明细）。
>
> 口径理由：这些钱**从未离开任何账户**（"按实付"的财政在付款时就已经不扣），因此若把它们计成负债账户或
> 虚拟资产，就会凭空造出货币。月结恒等式里它们**必须完全缺席**——这一点由 §13.7 的 `|ΔM_ALL| ≤ 200` 实测守住。
> 面板可以把它们显示成"所欠"（玩家需要的压力感），但**钱账本不认它们**。

**硬要求**：`|误差| ≤ 1 贯`（浮点/整数截断容差）。超出即 `log.error` + 写入 `state.money_audit`，并（在测试中）直接断言失败。

### 4.3 交子：为什么面值不计入 M_ALL

交子是**发行方负债**，对应资产是 `jiaozi_reserve`。若把 `issued` 面值与 `reserve` 同时计入总量，会**双重计算**。规范采用：

- `reserve`（资产）计入 M3；
- 公众持有的**流通中交子**（= `issued`，全社会都持有）计入 M0/M1/M2 的纸币成分；
- 超发导致信用折损的部分（`issued × (1 − acceptance)`）**不是销毁**，而是"贬值沉淀"，单列 `paper_discount` 科目，**不进入任何口径**，但必须可加总回面值：`M0 纸币成分 + paper_discount == issued`。

这样"超发 → 信用跌 → 有效货币减少 → 通缩"的链路才是**账面闭合**的。

## 五、口径与机制的挂接（价值所在）

| 机制 | 现行驱动 | 规范后驱动 | 效果 |
|---|---|---|---|
| **钱荒 `coin.shortage`** | 独立状态量，与货币总量**脱钩** | **由 M0 派生**：`shortage = f(M0 / 实物产出)` | 平粜回收货币、窖银入窖会**真实加重钱荒**；熔化铜钱会加剧钱荒 |
| **物价 `price_level`** | 一坨 mixed money ÷ 实物产出 | **由 M1 派生**：`price_level = BASE × M1 × V / 实物产出` | 窖银出窖是 M2→M1 的内部转移 → **推高物价**；熔化是 M2 真销毁 → **压低物价** |
| **藏富 / 长期通胀压力** | 无 | **M2 − M1**（沉淀层） | 面板显示"民间窖藏 X 万贯（退出流通）"；窖藏高 = 长期通缩压力 |
| **对外/潜在** | 无 | **M3** | 市舶白银存量、银行资本纳入视野 |
| **政策工具** | 各自直接改字段 | 统一为 `apply_flow(kind, src, dst, reason)` | 平粜/换界/熔铜/内帑调拨/抄没全部走同一入口，天然闭合 |

## 七、分三步落地（风险递增）

### 步骤 1 · 只观测，不改数值（**零行为变更、零平衡风险**）

- 新增 `core/money.py`、`silver_stock`（初值由 `silver_in × 10000` 反推一次）、`money_audit`；
- 每月结算末尾跑 `reconcile()`，把 `{m0,m1,m2,m3,各账户余额,残差}` 写入 `state.money_audit`；
- **不改 `calc_price_level` 的任何数值**；
- 面板/`/api/readouts` 展示分层读数（脱敏）。

**验收（关键）**：用审计已确认的 4 个破口做用例——**它们应当立刻让残差非零**：
- A-2 国库穿底后仍全额支出 → 残差应 ≈ +39,318,557（60 月）
- A-4 畜栏产肉 `imperial_treasury +=` 无买方 → 残差应 ≈ +40,000/月
- A-5 酒坊每月累加酒课入内帑 → 残差应 ≈ +2,584,000（77 月）
- D-6 政务 savings 无上限致常费转负 → 残差应随月份转正并加速

> 这一步**不修任何 bug**，但把"不可观测的黑洞"变成"每月一条可断言的残差"。修不修、怎么修，之后单独决策。

### 步骤 2 · 修正公式（**会改变物价数值，需回放校准**）

- `calc_price_level` 改用 M1；
- `private_melt` 作用域收窄到铜钱；
- `silver_in` 流量→`silver_stock` 存量。

**验收**：60 月回放 `price_level` 落回 [0.8, 2.8] 且轨迹平滑；`mean|Δprice_level|` 相比改前不恶化；农存粮/人口总账/起义时间闸三项回归不破。

### 步骤 3 · 机制挂接（**改变玩法手感**）

- `shortage` 改由 M0 派生；
- 窖银出入窖显式记为层级转移（面板可展示"沉淀层"）；
- 平粜/换界/熔铜/内帑调拨/抄没统一走 `apply_flow`。

**验收**：新增"货币总量守恒"回归测试；审计 A-2/A-4/A-5/D-6 四条在修复后残差归零。

## 十、与修复计划的衔接

本规范**应作为 [fix_plan_2026-09-18.md](../analysis/fix_plan_2026-09-18.md) 阶段 3（守恒修复）的前置**：

- 现状是"逐条修守恒 bug"——修一条漏一条（审计已发现 8 条以上）。
- 有了 M 口径后，**守恒变成一条可断言的不变量**，而不是 N 个分散的补丁。
- 建议把"步骤 1（只观测）"插入修复计划的 **批次 2 之后、批次 3 之前**：先用它把阶段 3 要修的那批 bug **变成测试用例**（红），再逐条修到对账残差归零（绿）。这样阶段 3 的工作量与"漏修风险"都会显著下降。

## 十一、各口径过多 / 过少的后果速查

> 记住一句话：**M0 管"买不买得到"，M1 管"物价"，M2 管"藏不藏得住"，M3 管"还能不能放"。**

### M0 · 流通中通货（民间铜钱 + 有效交子）

| 方向 | 游戏内后果 | 触发链路 |
|---|---|---|
| **过少** | **钱荒**：交易萎缩、税收不上来、欠税累积，陷入"没钱→税少→更没钱" | `coin.shortage` ↑ → `tax_coeff = MIN+(MAX−MIN)×(1−shortage)` ↓（`settlement_steps.py:2792`）→ 入库率降、`欠税` 累积；`shortage ≥ 0.6` 直接判时代衰退（`era_mechanic.py:88-90`） |
| **过多** | 市面钱多 → 推高 M1 → **物价上行**；若实物产出没跟上就是**纯通胀** | M0 ↑ → M1 ↑ → `price_level` ↑ → `grain_price` ↑ → 民心 ↓、流民 ↑ |

玩家可见：钱荒四档文案「泉货流转 / 钱荒渐显 / 钱荒严重 / 几乎无钱可用」。

### M1 · 狭义货币（M0 + 国库 + 内帑 + 地方库）

| 方向 | 游戏内后果 | 触发链路 |
|---|---|---|
| **过少** | **通缩**：粮价低、农卖粮收入受损→税基萎缩；实际负担（岁币/军费/俸禄）**变相加重**；士绅惜售囤积 | `price_level` ↓ → `grain_price` ↓ |
| **过多** | **通胀**：米价腾涌 → 民心崩、起义压力累积（1118+ 的流民/米价/民怨分支）；**俸禄指数化**使财政支出暴涨；国库穿底风险 | `price_level` ↑ → `grain_price` ↑；`_pay_index` 在粮价 > `PAY_INDEX_BASE`(1.5) 时放大俸禄支出；逼近 `PRICE_CEIL_HARD`(2.8) 时稳定器被动开启（常平/换界/熔铜） |

### M2 · 广义货币（M1 + 士绅窖银 + 熔铜池 + 银行准备金）

| 方向 | 后果 | 说明 |
|---|---|---|
| **过少**（沉淀薄） | **抗冲击能力差**：一遇灾荒/战争，市面立刻更紧；`HOARD_DRAW_RATE` 无米可炊 | 缺少"蓄水池" |
| **过多**（沉淀厚） | **长期通缩**：大量钱退出流通（士绅入窖 50%、熔铜池、银行准备金）→ M1 被抽水；**财富向士绅集中**→兼并/党争压力 | 这正是宋代"**钱荒**"的真实机理：钱不是没有，是在窖里、在铜料里、流到境外 |

> **关键**：M2 高而 M1 低 = **"看着有钱，市面没钱"**——这是本游戏最值得做出来的经济病。窖银出窖（M2→M1）会**推高物价**，熔铜（M2 真销毁）会**压低物价**。

### M3 · 全社会货币资产（M2 + 白银存量 + 银行资本 + 交子本钱）

| 方向 | 后果 | 说明 |
|---|---|---|
| **过少** | **政策工具箱空转**：交子本钱薄 → `_jiaozi_ceiling()` 低 → 想发钞救急也发不出；银行资本薄 → 无信用扩张空间 | 危机时**无牌可打** |
| **过多** | 信用扩张空间大 → AI 容易"增发交子" → 若 M1 承接不住则 `trust` 崩、有效货币骤缩（**信用悬崖**）；白银堆在 M3 而不入流通 → **"白银流入却不解钱荒"** | 超发 → 接受度跌 → 有效交子缩水 → 反而通缩 |

### 组合态（最有设计价值的部分）

| 组合 | 玩家看到的表象 | 史实对应 |
|---|---|---|
| **M1 高 · M0 低** | 账面钱多、市面转不动——**通胀与钱荒并存** | 交子超发 + 民间窖藏 |
| **M0 高 · 实物产出低** | 纯通胀，米价腾涌、民怨沸腾 | 灾年：钱多货少 |
| **M2 高 · M1 低** | 长期通缩、财政实际负担上升、财富集中 | 北宋**钱荒**（窖藏/铜料/外流） |
| **M3 高 · M1 低** | 信用载体充足但未激活——**政策窗口期** | 交子本钱足而未发 |
| **M0 低 · 物价高** | 最恶劣：既买不到东西又贵（供给崩溃） | 战乱/大灾 |

**一句话设计准则**：让玩家能通过**M0/M1/M2 的相对关系**读出"病因"，而不是只看到一个模糊的"物价 1.8"。这才叫"规范经济数据"。

## 十二、后期囤积（"仓鼠症"）的口径处理

### 12.1 问题

玩家天性囤积，而游戏缺乏足够的"钱漏"，导致后期余额爆炸：

- 主审 240 月无操作回放：**国库 175 万 → 6,735 万贯**（货币总量同期 2.75 亿 → 4.35 亿）。
- J 路 60 回合：**内帑 100 万 → 1.06 亿贯**，而国库恒为 39（另一场景）。

两条后果：

1. **数值失真**：一个数字到几亿贯，玩家失去量感（史实锚：北宋岁入约 6,000 万贯，内藏库封桩是"死钱"）。
2. **口径错误**：按 §三 的 M1 定义（含国库/内帑），囤积会**全额计入活跃购买力** → 一个不花钱的玩家反而制造通胀。这与经济事实（锁在金库不流通）和玩法直觉都相反。

### 12.2 修订：M1 只算"周转金"，超出部分计入"封桩"（沉淀层）

| 账户 | M1（活跃） | M2（沉淀） |
|---|---|---|
| 国库 | `treasury_working = min(treasury, k_国 × 月常费)` | `treasury_idle = treasury − working` |
| 内帑 | `imperial_working = min(imperial, k_内 × 月常费)` | 其余 |

- `月常费` = `MONTHLY_EXP_CIVIL_BASE`（880,000 贯/月）。
- 建议 `k_国 ≈ 3`（约 3 个月周转金）、`k_内 ≈ 1`（内帑本就是"死钱"）。
- **理由**：宋代内藏库／封桩库的本质就是"锁起来不流通"；且这与真实货币经济学一致——**政府存款不计入狭义货币**。

**得到的表象**：仓鼠玩家 → **M2 膨胀、M1 停滞** → 正好落在 §十一 的「**M2 高 · M1 低 = 长期通缩／钱荒**」。面板可以直接告诉玩家："你把钱锁死了，市面在闹钱荒。"

### 12.3 但**必须挂代价**，否则仓鼠是支配策略

通缩本身对玩家偏有利（粮价低 → 民心高、财政实际负担下降），所以"囤积"若无代价就是最优解，而这正是当前版本的现状。代价通道按"自动程度／实现成本"排序：

| # | 代价 | 机制 | 史实锚 | 实现成本 |
|---|---|---|---|---|
| **C1** | **封桩 → 钱荒 → 税基萎缩**（自动、自限） | M0/M1 被抽 → 工商交易萎缩 → 工商税基（工匠+商人产值流量）下降 → 税入下降 | 北宋钱荒确实抑制工商 | 低（沿用现有税基公式） |
| **C2** | **库存越大，损耗与侵渔绝对额越大** | 复用 `calc_corruption_deduction()`，令其随库存规模放大（鼠耗／胥吏侵盗） | 宋代"耗羡""侵渔" | 低 |
| **C3** | **帑藏充溢 → 挥霍通道**（史实、最有戏） | 库存超阈值触发"应奉局式"支出：土木／花石／艮岳／道观，AI 推演档位；玩家可拒绝但要付皇威代价 | 徽宗"丰亨豫大"、应奉局、花石纲、艮岳 | 中 |
| **C4** | **政治要价** | 内帑高 → 大臣／清流持续上疏"请开内帑以充军国"；拒绝 → 派系满意度／皇威下降，同意 → 内帑转国库 | 内藏库封桩与朝臣请开之常态 | 中（复用派系满意度） |
| **C5** | **结构风险** | 国库囤铜钱 → 民间被迫依赖交子 → 发行需求上升 → 信用风险累积 | 北宋钱荒与交子／会子扩张 | 高 |

> **C1 是自限器**：囤得越狠，自己的税入越低——不需要硬 cap 就能收敛。**C3 是戏剧性来源**：把徽宗朝"钱多了就大兴土木"做出来，让仓鼠玩家的钱有去处。

### 12.4 数值规范建议

| 项 | 建议值 |
|---|---|
| **合理区间** | 国库 3–12 个月常费（264 万 ~ 1,056 万贯） |
| **夸张阈值** | > 24 个月常费（≈2,112 万贯）触发"帑藏充溢"事件链（C3/C4） |
| **显示单位** | < 100 万 → 贯；100 万 – 1 亿 → 万贯；> 1 亿 → 亿贯（与现有 `desensitize_*` 定性档位同风格） |
| **上限策略** | **不用硬 cap**（玩家会反感"钱被系统吃掉"），用 **C1 + C2 的边际递减**：库存越高，每多 1 贯的"安全感"越低、损耗越高 |

### 12.5 待决策

| # | 决策 | 建议 |
|---|---|---|
| **仓鼠-D1** | 周转金门槛 `k` 取多少？ | 国库 3 个月常费、内帑 1 个月 |
| **仓鼠-D2** | 是否启用 **C3 挥霍通道**？ | 建议启用——它同时解决"钱没处去"和"徽宗朝味道"两个问题 |
| **仓鼠-D3** | 接受"**通缩是囤积的自然结果**"，还是希望库存高反而通胀？ | 前者（与 §12.2 修订自洽）；若选后者需把国库全额计入 M1，会与囤积直觉冲突 |
