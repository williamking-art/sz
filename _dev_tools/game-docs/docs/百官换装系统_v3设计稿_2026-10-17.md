## 0. 一页摘要（给不看长文的人）

## 1. 目标与非目标

### 1.1 目标（每条都可验收）

| # | 目标 | 验收方式 |
|---|---|---|
| G1 | 全游官员（名臣/监司/知通/知县）走**同一**装配线，旧资源不参与 | 代码内无"名臣分支"；名臣与随机官用同一 Engine 出图 |
| G2 | 每名官员**稳定且不撞脸** | 同姓名永远同图；抽样 300 人 distinct ≥ 99% |
| G3 | 五官**按器官**独立（眉/眼/鼻/口/耳）+ 空白脸型 | 槽位表 + 脸模零五官残留断言 |
| G4 | **膝盖以上**入画、比例统一 | 锚点表 + 膝线在画布内断言 |
| G5 | 品级/年龄/恩赏变化 → 立绘**自动**变，无装备 UI | 状态驱动集成测试 |
| G6 | 素材同源原位、纯 Alpha、风格统一、**不复用旧图** | 质检门（bbox/边缘/直方图）+ 人工目视 |
| G7 | 前端"点哪换哪"只用于调试台；导出与预览一致 | 双端一致性测试 + 目视 |

### 1.2 非目标（明确不做，避免再跑偏）

- **N1** 不做实时 3D/WebGL 网格渲染（用"参数化 2D 渲染 + 程序骨架"满足，不引入引擎级 3D）。
- **N2** 不引入 Live2D Cubism 商业运行时（授权/成本）；微动走 P2 自研参数化方案。
- **N3** 不做装备栏 UI（R10 明令）。
- **N4** 不给每人画专属全身原画（R11「不要专门生图造成美工资源堆积」）。
- **N5** 不做跨时代元素（明补子/龙纹/清帽/京剧靴，R14）。

## 3. 总体架构（五层 + 两条数据流）

~~~text
              ┌──────────────── spec.paperdoll.json ────────────────┐
              │ canvas / anchors / slots[z] / parts / dna / rules  │  ← 唯一真相源
              └───────────────┬─────────────────────┬──────────────┘
                              │ build               │ build
                    ┌─────────▼──────────┐  ┌───────▼──────────────┐
                    │ manifest（部件清单）│  │ manifest.js（前端）   │
                    │ + 资产指纹/校验结果 │  │ 同源同序              │
                    └─────────┬──────────┘  └───────┬──────────────┘
              ┌───────────────▼──────────┐  ┌───────▼──────────────┐
              │ L3a 服务端合成（Python/PIL）│  │ L3b 前端合成（Canvas2D）│
              │ 接口/存档缩略/批量出图      │  │ 召对/名册/调试台/导出  │
              └───────────────┬──────────┘  └───────┬──────────────┘
                              └──── 同序·同坐标·同锚点 ──┘
                                             ▲
                       ┌─────────────────────┴──────────────────────┐
                       │ L4 状态接线：品级 / 年龄 / 特质 / 恩赏 / 情绪 │
                       └────────────────────────────────────────────┘
   L0 锚点与取景   L1 部件资产   L2 DNA与规制   L3 双端合成   L4 游戏状态
~~~

**为什么双端而不是只留一端**：Electron 面板与存档缩略需要服务端出图（不依赖渲染进程），
调试台需要即时点换（前端）；两端共用 manifest，**契约测试**防漂移（见 §11）。

## 4. 画布与锚点（R6 的唯一定义）

- **画布**：810×1080 @1x（3:4）；资产一律 **1620×2160 @2x** 烘焙，运行时按 devicePixelRatio 取用。
- **头身**：头高 **175px**（头顶 y=135 → 颏 y=310）；**膝线 y=1050**，膝上可见高度 915px ≈ **5.2 头身**。
- 该锚点表来自旧 810 世代已校准值（anchors.json），与用户「膝盖往上都在图里」「收腰 200」直接对应。

| 锚点 | y（1x） | 用途/断言 |
|---|---|---|
| 帽檐下沿 | 160 | 必须 ≤ 发际线 − 4（用户：帽檐略高于发际线） |
| 发际线 | 175 | 帽/发/眉三层对齐基准 |
| 眉线 | 220 | 眉层 bbox 中心 ±3 |
| 视平线 | 236 | 眼层 bbox 中心 ±3 |
| 鼻底 | 265 | 鼻层 bbox 下沿 ±3 |
| 口线 | 288 | 口层 bbox 中心 ±3 |
| 颏 | 310 | 脸模 bbox 下沿 ±3 |
| 交领/颈 | 345 | 白中单与脸模衔接处 |
| 肩线 | 380 | 素体/袍服肩点 ±6 |
| 腰线 | 660 | **腰宽 200px（x=298–498）** ±6 |
| 膝线 | 1050 | 必须 ≤ 1080（袍摆可出血） |
| 佩挂：左玉佩 / 右官印鱼袋 | (305,660) / (490,660) | 挂点 ±6 |
| 朝笏端持 | (394,340) 6° | 持笏时人物整体微侧 6°（用户 10-16 12:03） |

> 2x 烘焙时全部 ×2；锚点**只以 1x 为准**，禁止在代码里再写像素值。

## 6. 视觉 DNA 与规制规则（L2）

### 6.1 DNA 字段

| 字段 | 来源 | 说明 |
|---|---|---|
| seed | hash(姓名 + 籍贯 + 生年) | 稳定、可复现；名臣同样走它 |
| face / hair / ear / brow / eye / nose / mouth / beard | PRNG 抽取（受规则权重） | 千人千面的主体 |
| robe / belt / pouch / seal / hu / futou | **由品级推导**，恩赏可覆盖 | 不是随机项 |
| tilt | 姿态（默认 6°，持笏微侧） | P2 动作扩展 |
| flip | 朝堂对坐（左右镜像） | 交互层开关 |
| expression | P2 预留（眉/眼/口变体） | 现在恒为空 |

### 6.2 规制规则（可测）

| 规则 | 内容 | 断言 |
|---|---|---|
| RU-1 品级 | 正三品↑：紫 + 金玉带 + 金鱼袋 + 象牙笏 + 长展角；四五品：绯 + 银带 + 银鱼袋 + 长/短展角；六七品：绿 + 黑/角带 + 无鱼袋 + 木笏 + 短展角 | 三档全组合抽样 0 违规 |
| RU-2 年龄 | <30 无须/短髭；30–55 短髭或三绺；>60 长髯/花白 | 须髯受 age_group 约束 |
| RU-3 特质 | 刚直→剑眉阔目权重↑；文雅→柳叶杏目权重↑ | 权重表可测（同 seed 不同 traits 出不同脸） |
| RU-4 恩赏 | 赐紫/借绯/赐金鱼袋/赐玉带 → **覆盖层**，不改变基础推导 | 恩赏前后立绘 hash 必变 |
| RU-5 禁项 | 明补子/龙纹/清红缨/折角帽/京剧靴 | 资产名与 prompt 双拦截，命中即失败 |

### 6.3 组合空间口径（诚实三档，写进验收）

| 口径 | 算法 | 首期数值 |
|---|---|---|
| 理论笛卡尔积 | 各槽位变体数相乘 | ≈ 6×6×3×6×6×5×5×8 ≈ **9.3×10⁵** |
| 规则可达（去非法组合） | 施加 RU-1/RU-2 后 | 量级 10⁵ |
| 实测 distinct | 随机 300 名官员跑装配 | 目标 ≥ 99% |

> 明确**不用**"4032 万"当验收口径（评审已证其实现塌缩到 ~315）。

## 7. 双端合成契约（L3）

### 7.1 manifest（前后端唯一输入）

~~~json
{
  "schema": "songzuo.paperdoll.manifest/2",
  "canvas": {"w": 810, "h": 1080, "scale": 2},
  "anchors": {"hairline": 175, "brow": 220, "eye": 236, "waist": 660, "knee": 1050},
  "fingerprint": "...",
  "slots": [
    {"key": "face", "z": 3, "locked": false, "parts": [
      {"id": "face_01_guazi", "file": "parts/face/face_01_guazi@2x.png",
       "w": 1620, "h": 2160, "sha1": "..."}
    ]}
  ],
  "rules": {"rank": {"3a": {"robe": "robe_purple", "belt": "belt_jade"}}}
}
~~~

### 7.2 合成不变量（两端都必须成立）

1. 层序 = slot.z 升序，**不含未选中的可关槽位**；
2. 每层贴图坐标恒为 **(0,0)**，不允许运行时平移/缩放/旋转（姿态靠资产，不靠变换）——这是"不回到拼接"的硬边界；
3. 翻转 = 整幅水平镜像（一次变换），不是逐层反转；
4. 缺件 → **报错**（禁止存在性判空跳层）；
5. 同一 DNA → 双端输出像素差均值 < 2/255（容差仅吸收 PNG 编解码差异）。

### 7.3 性能与缓存

- 前端：进入召对先加载 face/robe/futou 三层（约 300ms 内出轮廓），其余按 z 静默补齐；同 DNA 常驻内存。
- 服务端：/api/portrait/{dna_hash}.png；**hash 必须包含**：全部部件 id、tilt、flip、age_group、恩赏覆盖键（评审已指出旧实现漏键导致陈旧图）。
- 预算：单张合成 ≤ 30ms；首屏 ≤ 40 次解码。

## 8. 骨架与火柴人素模（R4/R5）

- **关节表数据化**（与 anchors 同源，程序生成，不出 PNG 素材）：head / neck / shoulder_l·r / elbow_l·r / wrist_l·r / waist / hip / knee_l·r / ankle_l·r（踝在画外）。
- **渲染**：Python 用 PIL/ImageDraw 画关节与连线（调试图）；前端 Canvas 画同构骨架。默认 rig=off。
- **两个用途**：① 部件 bbox 对齐校验（如"眉层必须落在眉线 ±3"）；② P2 姿态参数化（呼吸/微侧/持笏角度）。
- **火柴人素模**：body 槽位（z=2）本质就是"无五官、无服饰的素体"，可直接单独渲染，满足 R5。

## 10. 资产生产管线（P1，需授权）

~~~text
母本（canonical master，2x，含骨架线）
   └─ 逐件原位绘制：agnes-image（工笔设色）或 3D 骨架烘焙
        └─ 抠图（纯 Alpha、无矩形边、无白框）
             └─ 对齐（锚点表定位，2x 画布零偏移）
                  └─ 质检门（自动）→ 入库 → 重建 manifest
~~~

**质检门（自动化，任一不过即失败）**

1. 尺寸 = 1620×2160，模式 RGBA；
2. alpha bbox 落在该槽位的允许区间（见 §11 表）；
3. 边缘残留检测：bbox 四边 2px 内不得出现"整行/整列非零 alpha"（矩形边）；
4. 风格一致：与母本的颜色直方图相似度 > 阈值；
5. 禁项：文件名/描述不得含"补子/龙/红缨/折角"等词；
6. 同源：与母本的锚点线偏移 ≤ 2px。

> **资产入库**：当前 game/assets/paperdoll/** 全是未跟踪文件（166 个），换工作树即丢。
> v3 要求：资产随 manifest 指纹入库（或用 CNB 发布通道），并在 CI 校验指纹一致。

## 11. 校验与回归（写死在测试里）

| # | 断言 | 阈值 |
|---|---|---|
| A1 | 画布与锚点：所有部件 = 1620×2160 RGBA | 精确 |
| A2 | 帽檐下沿 ≤ 发际线 − 4 | 1x 坐标 |
| A3 | 眉/眼/鼻/口/颏 bbox 中心 = 对应锚点 | ±3px |
| A4 | 腰宽 = 200px | ±6px |
| A5 | 膝线 1050 ≤ 画布高 1080 | 精确 |
| A6 | 脸模零五官残留（与五官层 bbox 交集为空） | 精确 |
| A7 | 缺件 → MissingPartError；错画幅 → LayerCanvasError | 用例 |
| A8 | 同 seed 双端：层序与坐标一致；像素差均值 < 2 | 容差 |
