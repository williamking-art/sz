## 一、利益集团与 POP 政治生态

### 1.1 概念：集团是 POP 的"政治出口"，不是第七类人口
- **有政治表达权的 POP 子集** → 构成**利益集团**（皇帝看得见，能影响朝议）。
- **沉默的多数**（农、工匠等无代表者）→ **不进集团**，只经**民心**这一弱通道表达。
- 因此集团的"人数"永远是**某 POP 的切片**，**不新开任何账本**。

### 1.2 集团名单（总集命名）与 POP 基本盘
| 权威键（代码用） | 集团（显示名＝总集） | POP 基本盘 | 类型 |
|---|---|---|---|
| `新党` | 新法系 | 官僚 `officials` 中持新法立场者 | 政策网络 |
| `旧党` | 元祐旧臣与保守士绅 | 士绅 ＋ 官僚中反对绍述者 | 士绅联盟 |
| `皇党集团` | 皇党集团 | 官僚 `officials` 中依附皇权者 | 内廷网络 |
| `军功集团` | 军功集团 | 兵 ＋ 官僚中以军功晋身者 | 军镇网络 |
| `中立派` | 中立派 | 士绅＋商人中不结党者 | 士商联盟 |

**台谏不入集团**：御史台/谏院是**官职**，台谏官各有派系，按个人立场归属。

### 1.3 立场占比（`FACTION_SPLIT_INIT` + `core/faction_split.py`）
- 口径：**立场跟派系，不跟地域**（地域只是出身）→ 占比是**类级**，不按路分。
- 它是**比率（Σ=1）**，不是人口账本：`集团人数 = Σ_路 Σ_类 (基数 POP × 立场占比)`；
  官僚类只取 `officials` 子池（**吏不预党争**——`官僚.size` 含吏，是常见坑）。
- **唯一写入点** `set_split`；工具：`blend_entrants`（入口并流）、`shift_split`（零和转移）、
  `exit_faction_members`（定向退出后重归一）、`defect_toward_satisfaction`（转投）。
- 开局锚点：官僚 45/25/5/10/15；士绅 55/45；商人 100% 中立；兵 100% 军功。

### 1.4 声量（`core/faction_voice.py`）—— 由**官职权限**派生
```
事权(AUTHORITY_MATTERS) → 机构固有事权(central_orgs[*].authority)
  → 官职声量 org_voice() → 官员声量 → 派系声量 voice_seats()
```
- **声量是绝对影响力，不是份额**（不要求各派相加为 100）；进公式时用**边际递减**
  `norm = ln(1+raw)/ln(1+VOICE_FULL)`，故各派可同时高/低。
- 宏观读数 `total_voice`（朝堂总声量）＝权柄分散度：高＝权柄分散（皇权弱）。
- **收益**：玩家改革官职（改权限/越权授权/新建/裁撤）→ 声量**自动跟随**，无需另接通道。

### 1.5 出入口与转投（二期/三期）
- **入口**：科举**座主门生**（本榜"同年"随座主入派，`state.exam["cohorts"]` 记 `examiner_faction`）；
  恩荫随父辈（士绅立场分布）；荐举接口 `recruit_by_recommendation`。
- **出口**：致仕带本派立场回士绅；祠禄/待阙超限按失势定向挤出；非正常离任（贬黜/处死/战殁）
  经 `exit_faction_members` 离散。
- **转投**：`defect_toward_satisfaction`，`flow = rate·s_src·s_dst·Δsat/100`，单月每派 ≤2%，
  同快照成对计算后一次性写回 → **零和**。

### 1.6 派生与写入纪律
- `influence = .25 人口份额 + .20 资源份额 + .25 声量 + .15 制度 + .10 军事 + .05 凝聚力`
  （`core/faction_metrics.py`，只读纯函数）。
- `satisfaction`/`cohesion` 向"由 POP 与实际变化派生的目标"**缓动**；事件/诏令只写 `_event_delta`。
- **唯一写入点**：`core/faction_settle.py`（Step 5.5，位于 POP/制度/财政之后）。
  禁止任何地方直接改 `state.factions[*]` 数值（有 AST 哨兵测试）。

## 二、经济与物价（`econ-price`）
- **固定回合相位顺序**（`core/settlement.py` 步序段）：
  生产 → **工程投入** → 粮食商品市场 → 税收转移 → **货币信用** → **物价** → 集团读数 → 提交；
  同步 `tests/test_pop_identity.py::_STEPS` 镜像（AST 逐位比对）。
- **失败整月回滚**：`core/commands.py` 的快照/还原（已有），新增用例钉住
  turn/population/POP size/statistics 全回滚。
- **路线物价** = 供给 + 需求 + **库存** + **运输（漕运）** + **货币有效供给**；
  全国 `PRICE_LEVEL` 只是人口加权**读数**（`state.grain_price_readout`）；
  **月度涨跌上限**（粮价 15%、物价 20%）。
- **生产/工程声明契约**（`game_state_econ.PROJECT_DECLARATION_FIELDS`）九项：
  原料/钱粮/工匠工时/产出/施工期/维护/折旧/路线/POP受益者；`project_supply_ratio` 取最短板
  驱动**逐步降效**（不静默完成）。
- **税收/工资/价格先改 POP wealth/grain**，再派生满意度与集团态度；**禁止直接给集团发钱**。

## 三、金融（`finance-credit`）
- **有效货币供给** = 流通铜钱 + 有效交子余额 + 实际流通白银折钱；
  **窖藏 / 准备金 / 仓粮显式排除**（`money.supply_breakdown`），并有恒等式断言。
- **交子**：区分发行额/流通额/准备金/兑付率/界期；发行受**三闸门**
  （准备金×皇威、税收接受度、信用上限）；换界**真实减少流通额**；信用下降 → 折价与挤兑。
- **银行**：存款/贷款/准备金率/逾期率/挤兑压力/网点/对象；**贷款 = 债权 + 借款方资产**；
  **利息不入国库**（归银行留存）；**坏账记 `register_flow(burn)`**；函数内 `ΔM_ALL` 断言。
- **汇率**：`STANDARD_INFO` 分离**记账汇率**与**市场汇率**；兑换报价只读
  （`money.exchange_quote`）并给出手续费/铸币损耗/双方资产变化。
- **单位契约**：`FINANCE_SCHEMA_VERSION`、`MONEY_UNIT/GRAIN_UNIT/WON_PER_GUAN`，
  `bank_capital_as_guan` 作"万贯→贯"唯一入口（防贯与万贯混用）。

## 四、工程（`works-tech`）
- **项目五态状态机**：`proposed → funded → building → operating → degraded/abandoned`；
  资金/材料/灾害/治安不足 → **延期或降效**，**不静默完成**。
- **工匠工时**约束推进；工役产生农/工匠**时间损失**并留审计读数；**不新增工程人口**。
- 工程款走 `transfer_public_funds_to_pops`（经 `applier_pipeline`，ΣΔ 守恒、原子回滚）。
- 完工转 `operating` + `capacity`；**维持欠费 → degraded**，补缴可恢复；收益有容量/维护/折旧。

## 五、科技（`works-tech`）
- `TECH_INFO.level` **降为综合读数**（删硬门槛）；真实能力拆为**七域节点**
  （火药/冶金/水利/历法/航海/财政/医学农学），节点声明前置/成本/工匠学者投入/建筑/效果/维护。
- `researching` 消耗**预算与人才时间**（受学校/识字率/材料影响）；**中断保留进度**（有机会成本）。
- **解锁 ≠ 全国生效**：须经建筑/作坊/军队**部署**，以 `adoption` 覆盖率产生效果；
  维持欠费 → adoption 折旧。
- `era` 是时代约束/叙事标签；`west` 改为**来源制**（贸易/使团/书籍/工匠/战争），**不作万能加速器**。

## 六、营建闭环（2026-09-19 补）

### 6.1 明末式蓝图
`BUILDING_BLUEPRINTS`（10 张科技蓝图）与 `BUILDING_STD`（6 座政府建筑）统一为**蓝图表**：
- `category`（财政/军事/民生/科技/交通/内廷）× `branch`（军工/文教/财计/农医/工巧）
- `requires_region`（**地利前置**，用宋祚路型：京畿要地/沿海/缘边；空=何地皆可）
- `cost.silver`（造价，贯）× `cost.months`（**工期 1–6 月**，明末档）
- `outputs`（产出词条，结构化声明）
- `need_node`（科技前置）

### 6.2 三段链路（此前**断开**）
```
蓝图 ──propose_project()──► state.projects[status=proposed]
        （校验：蓝图登记 / 科技前置 / 地利前置 / 国库；失败拒绝式）
                              │
                              ▼   _settle_projects 五态状态机逐月推进
                     funded → building →（progress≥100）→ operating
                              │
                              └──►【落成】prefectures[route]["buildings"][名] += levels
```
- **立项**：`core/construction.propose_project`（唯一入口，含校验；工期 → `speed = 100/months`）
- **推进**：既有工程系统（`state.projects` + `_settle_projects`），供给率降效 / 工匠工时 / 治安折减
- **落成**：完工时写 `buildings` —— 此前**无任何写入点**，故：
  - `_settle_upkeep` 的建筑维持费**实际收不到钱**
  - 科技 `adoption` 覆盖率**恒为默认值**（永无"部署建筑"）
  补齐后两者才真正生效。

### 6.3 入口（玩家可见）
- **后端**：`POST /api/project/propose`
- **前端**：`EngineeringPanel`（工程面板）由只读展示改为**可营建**
  —— 顶部择地（路）+「可建工程」逐项【营建】按钮 +「已开工」读 `state.projects`（五态中文标签）。
  （修复：原「已开工」误筛 `longterm_public/secret` 的 `fixed_construction`，正常对局恒为空。）
