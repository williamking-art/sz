# 开发服务器与回归测试说明

> 定位：记录 sz 项目在腾讯云 CVM 上的开发/测试环境与使用方式（2026-09-23 建立）。
>
> **安全约定（先读）**：本仓库是**公开仓库**，故本文**不写入**服务器公网 IP、
> 登录密码、私钥内容等敏感项。实值请从腾讯云控制台与本地密钥目录获取（见 §2）。

---

## 一、这台机器解决什么问题

本机（Windows 开发机）目前**未安装 Python / Node / Rust 工具链**，因此：

- 跑不了后端 `python -m backend.server`
- 跑不了全量回归 pytest
- 构建不了前端（`game/frontend` 需要 Node 20+）
- 编译不了 `songzuo_server`（Rust）

服务器一次装齐三套工具链，承担以下职责：

| 用途 | 说明 | 现状 |
|---|---|---|
| 全量回归 | `pytest` 约 892 例，耗时约 1 分钟 | 已可用 |
| Rust 构建 | `songzuo_server` 的 Linux release 产物 | 已可用 |
| 跑批/长跑 | 经济模拟压力测试（如 240 月对账） | 已可用 |
| CI（计划） | 每次 push 自动跑回归 | 待建 |

> 注：2 核 2GB 是偏紧的配置，编译 Rust 前已补 2GB swap（见 §3）。
> 这台机器适合**测试与构建**，不要在未评估前承载线上服务。

  （Windows：`C:\Users\<用户名>\.ssh\sz_cvm_ed25519`）
- 对应公钥（可公开，可复制到服务器）：

```

```

服务器侧安装公钥（只需一次）：

```bash

echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIO1AVzSyU0NPBAXQ5GDq7Geg4UkOj+ezMVdXyF+L/r/F sz-cvm' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

日常连接：

```bash
ssh -i ~/.ssh/sz_cvm_ed25519 root@<公网IP>
```

### 2.3 密码登录

**建议关闭**（`PasswordAuthentication no`），只保留密钥。

若必须临时使用密码登录：密码请走密码管理器传递，**绝不写入本仓库、绝不提交**。

> 踩坑记录：Windows 下用 `.cmd` 批处理做 `SSH_ASKPASS` **不可行**
> （`CreateProcess` 无法直接执行 `.cmd`，ssh 会拿到空密码）。
> 若需自动传密码，需编译成真正的 `.exe`。

### 2.4 安全组建议

22 端口的来源请限制为**自己的出口 IP**，不要留 `0.0.0.0/0`。

## 三、机器上已就绪的环境

| 组件 | 版本 | 位置 / 备注 |
|---|---|---|
| Python | 3.11.6 | 系统自带（`python3`） |
| Python 依赖 | fastapi 0.141 / uvicorn 0.53 / shapely 2.1 / rich 15 / requests 2.34 / Pillow 12 / pytest 9.1.1 | 装在 `/opt/sz/game/.venv` |
| Node.js | 20.19.5（npm 10.8.2） | `/usr/local/node-v20.19.5-linux-x64`，已软链至 `/usr/local/bin` |
| Rust | rustc / cargo 1.98.1（rustup，走 rsproxy.cn 镜像） | `~/.cargo/bin` |
| git | 2.43.7 | `dnf install` |
| gcc | 12.3.1（Tencent Compiler） | `dnf install`，Rust 链接所需 |
| Swap | 2GB（`/swapfile`，已写入 `/etc/fstab`） | **必要**：2GB 物理内存编译 Rust 会 OOM |

依赖安装命令（如需重建）：

```bash
# Python 侧
cd /opt/sz/game
python3 -m venv .venv
.venv/bin/python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
    -r requirements.txt pytest

# Node 侧（npmmirror 二进制，避免依赖系统仓库）
curl -fL -o /tmp/node.tar.xz \
  https://registry.npmmirror.com/-/binary/node/v20.19.5/node-v20.19.5-linux-x64.tar.xz
tar -xf /tmp/node.tar.xz -C /usr/local/

# Rust 侧（rsproxy 镜像）
export RUSTUP_DIST_SERVER=https://rsproxy.cn
export RUSTUP_UPDATE_ROOT=https://rsproxy.cn/rustup
curl --proto '=https' --tlsv1.2 -sSf https://rsproxy.cn/rustup-init.sh | sh -s -- -y --profile minimal
```

## 四、日常操作

### 4.1 同步代码

```bash
cd /opt/sz
git pull origin main
```

> 服务器直连 GitHub **时好时坏**：clone 时实测可达 10MB/s，但 `fetch`/`pull`
> 偶发超时（`Failed to connect to github.com port 443`、
> `Failure when receiving data from the peer`）。失败就重试；
> 若连续失败，可从本地直接 `scp` 覆盖单个文件（内容一致时不会与后续 pull 冲突）。

### 4.2 跑全量回归

```bash
cd /opt/sz/game
.venv/bin/python -m pytest           # 当前约 892 例，约 1 分钟
```

长跑建议放后台（避免 SSH 会话被切断）：

```bash
cd /opt/sz/game
nohup .venv/bin/python -m pytest > /tmp/pytest.log 2>&1 &
tail -f /tmp/pytest.log
```

> 注：`pytest.ini` 里 `testpaths = ../_dev_tools/game-dev/tests`，
> 所以**必须从 `game/` 目录**运行。

### 4.3 编译 Rust 后端

```bash
cd /opt/sz/songzuo_server
~/.cargo/bin/cargo build --release
```

2 核机器首次编译较慢，建议后台跑：

```bash
nohup ~/.cargo/bin/cargo build --release > /tmp/cargo.log 2>&1 &
```

### 4.4 常驻运行参考后端（联调用）

```bash
cd /opt/sz/game
.venv/bin/python -m backend.server      # 默认 127.0.0.1:8080
```
