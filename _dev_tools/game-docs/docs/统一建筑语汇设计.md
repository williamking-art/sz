# 统一建筑语汇设计（底层 · V3 式）（2026-10-05）

> **用户裁定**：①底层 = V3 式「建筑框定生产与职业」；②**桑、麻、果、蔗要区分开**。
> 本文为第 ① 步（统一建筑语汇）**设计方案**，未改代码。

---

## 一、现状问题

外邦表把不同作物**混在一栋建筑**里：

```python
"\u6851\u9ebb\u7530": {"\u9ebb": 0.08, "\u4e1d": 0.03}          # \u6851 + \u9ebb \u6df7
"\u6797\u679c\u8517\u7530": {"\u6728": 0.08, "\u77f3": 0.05, "\u679c": 0.05}  # \u6797+\u679c+\u8517 \u6df7\uff0c\u4e14 **\u8517 = 0**
```

⇒ 后果：
1. **无法分作物控制产量**（桑与麻被绑死，不能只增桑不减麻）；
2. **无法表达地理分布**（桑在江南/两浙，蔗在福建/广南，气候适种性完全不同）；
3. **蔗实际为 0** —— 「林果蔗田」名不副实。

## 二、设计原则

| # | 原则 |
|---|---|
| 1 | **一作物一建筑**：桑 / 麻 / 果 / 蔗 **各自独立** |
| 2 | **建筑 = 生产单元**，承载「岗位 → 产出」；**不改机制**（沿用 `building_jobs`）|
| 3 | **占有关系（自耕/佃耕/地主）不与作物混为一维** —— 由**职业**表达（见 §四）|
| 4 | **建筑可得性按路**（依 `yields` 的适种性），非全国一律 |

## 三、统一建筑语汇（底层，各国一致）

| 建筑 | 主产出维 | 说明 |
|---|---|---|
| **农田** | 粮 | 生计轨（宋侧已有，不占岗）|
| **自耕农庄** | 粮 | 宋式：主户自耕（**保留宋特色**）|
| **地主农庄** | 粮 | 宋式：租佃（地主 + 佃农）|
| **桑田** | **丝** | 蚕桑 |
| **麻田** | **麻** | 麻 |
| **果园** | **果** | 园圃 |
| **蔗田** | **蔗** | 糖蔗 |
| **茶园** | **茶** | 茶（现 `yields` 有茶，但无对应建筑）|
| **牧场** | 牲畜 / 马 / 药材 | 辽/西夏为主 |
| **矿场** | 铁 / 铜 / 金 / 银 | |

| **商铺** | —（商业）| 商人在岗 |

⚠️ **林业**（木）暂并入**果园**还是单列，**待定** —— 见 §六。

## 四、占有关系怎么表达（不与作物混为一维）

宋的「自耕/佃耕」是**土地占有关系**，与经济作物**正交**。若组合会产生爆炸：

```
\u274c \u81ea\u8015\u6851\u7530 / \u4f43\u8015\u6851\u7530 / \u5730\u4e3b\u6851\u5e84 / \u81ea\u8015\u9ebb\u7530 / ...   \uff0812+ \u79cd\uff09
```

⇒ **正确做法**：建筑表达**作物**，**占有关系由「职业」表达** ——
而**职业 → POP 阶层** 的映射正是**差异层接口**（`POSITION_CLASS`）。

```
\u6851\u7530 \u5c97\u4f4d\uff1a\u81ea\u8015\u6851\u519c(\u2192\u519c) \u00b7 \u4f43\u6851\u519c(\u2192\u519c) \u00b7 \u56ed\u4e3b(\u2192\u58eb\u7eb3)
\u9ebb\u7530 \u5c97\u4f4d\uff1a\u81ea\u8015\u9ebb\u519c \u00b7 \u4f43\u9ebb\u519c \u00b7 \u56ed\u4e3b
\u2026\u2026
```

⇒ 宋侧既有 `SONG_POSITION_CLASS`（自耕农/富农/贫农/佃农→农，地主→士绅）**可复用**，只需**扩展职业名**。

## 五、🔑 建筑放哪一路 —— **`yields` 已给出依据**

`PREFECTURE_INFO[路]["yields"]` **已经编码了每路的作物适种性**：

```python
京畿路: {'茶': 0, '丝': 1000000, '麻': 500000, '蔗': 0, '果': 500000, ...}
京西路: {'茶': 0, '丝':  500000, '麻': 2500000, '蔗': 0, '果': 500000, ...}
```

⇒ **`yields[维] > 0` 即该路适种** ⇒ **据此放置对应建筑**，
**不臆断、不全国一律**（承 §3-3：缺失≠0）。

例：
| 路 | 应有哪些经济作物建筑 |
|---|---|
| 京畿路 | 桑田 · 麻田 · 果园（**无蔗田**，蔗=0）|
| 福建路/广南 | 蔗田（蔗>0）|

## 七、与既有表的关系

| 表 | 处置 |
|---|---|
| `building_jobs.SONG_JOBS_PER_LEVEL` | **保留并扩展**（加入桑田/麻田/果园/蔗田/茶园）|
| `EXTERNAL_ECON.JOBS_PER_LEVEL`（桑麻田/林果蔗田）| **拆分**为桑田/麻田/果园/蔗田；`牧场/矿场/工坊` 保留 |
| `EXTERNAL_ECON.PER_WORKER_OUTPUT` | 同上拆分；**补宋条目** |
| `SONG_POSITION_CLASS` | **保留**（差异层接口），扩展职业名 |

## 九、参数基数定案（2026-10-05 用户裁定）

> 用户：「**既然是建筑了，那就设定基数就好啦**」

⇒ 建筑是**游戏构件**（承 V3 范式），其参数为**玩法设定基数**，
**不要求史料依据** —— 与「**史料给比例、游戏给基数**」一致：

| 来源 | 决定什么 |
|---|---|
| **史料** | **哪一路种什么**（`PREFECTURE_INFO[路]["yields"]`：京畿路 蔗=0、丝=100 万）|
| **玩法设定（基数）** | 建筑**规模**（`JOBS_PER_LEVEL`）与**单位产出**（`PER_WORKER_OUTPUT`）|

### 9.1 岗位基数 `JOBS_PER_LEVEL`（每级在岗人数）

| 建筑 | 每级在岗 | 备注 |
|---|---:|---|
| 农田 | 0 | 生计轨，不占岗（沿用）|
| 自耕农庄 | 160 | 宋式（沿用 120+20+20）|
| 地主农庄 | 120 | 宋式（沿用 100+20）|
| **桑田** | **80** | |
| **麻田** | **80** | |
| **果园** | **60** | |
| **蔗田** | **60** | |
| **茶园** | **80** | |
| 牧场 | 100 | 沿用外邦 |
| 矿场 | 120 | 沿用外邦 |
| 工坊 | 150 | 沿用外邦 |
| 商铺 | 40 | 沿用宋侧 |

### 9.2 单位产出基数 `PER_WORKER_OUTPUT`（单位/在岗人/月）

| 建筑 | 产出 | 基数 |
|---|---|---:|
| **桑田** | **丝** | **0.030** |
| **麻田** | **麻** | **0.080** |
| **果园** | **果** | **0.050** |
| **蔗田** | **蔗** | **0.060** |
| **茶园** | **茶** | **0.020** |
| 牧场 | 牲畜 / 马 / 药材 | 0.10 / 0.03 / 0.03 |
| 矿场 | 铁 / 铜 | 0.08 / 0.03 |
| 工坊 | 布 / 绸 / 器 / 酒 | 0.06 / 0.015 / 0.01 / 0.03 |

⚠️ 桑/麻沿用外邦 `default` 率（0.03 / 0.08）以**保持底层一致**；
果/蔗/茶为**新设**（原表混在「林果蔗田」里且蔗=0）。

### 9.3 建筑**初置规则**（按 `yields` 放，可调）

```
对每路 r、每个经济作物维 d\uff1a
  if PREFECTURE_INFO[r]["yields"][d] > 0:
      放置对应建筑，初始等级 lv = 1\u20133
      （按该路 yield 占全国该维最大值之比分档）
  else:
      不放置（缺失 ≠ 0，**不臆造建筑**）
```

⇒ 例：京畿路（丝 100 万 / 麻 50 万 / 蔗 0 / 果 50 万）
得 **桑田 · 麻田 · 果园**，**无蔗田**。

### 9.4 启用岗位轨的两项前置

| # | 事项 | 状态 |
|---|---|---|
| 1 | 宋侧 `PER_WORKER_OUTPUT` | ✅ **本节给出（9.2）** |
| 2 | 🔴 **`yields` ↔ 建筑产出的换算** | ⚠️ **仍未定** —— 见下 |

**换算问题的实质**：

```
现状：产出 = yields[维] ÷ 12 × 建筑乘数      （路级年额，无人口约束）
启用后：产出 = Σ(在岗人 × PER_WORKER_OUTPUT)  （建筑驱动）
```

两者**量级未必相等**。三种处置：

| 方案 | 含义 |
|---|---|
| **甲** | **以 `yields` 为准反推建筑等级** —— 保持既有总量，只换机制（**改动最小、平衡不变**）|
| **乙** | 以建筑产出为准，**重标 `yields`** —— 总量会变，需重新平衡 |
| **丙** | 两者并存一段，**对账差异**后再定 |

🔴 **建议甲**：`yields` 是史料给的比例，**应予保留**；建筑只是它的**机制载体**。
（即：先按 9.3 放建筑得初值，再**按 `yields` 反推所需等级**。）
