# 地理环境与生产条件层设计（2026-10-05）

> **用户裁定**：需想清**怎么给各地的生产条件、地理环境做区分**。
> 本文为设计，**未改代码**。

---

## 一、🔴 现状：只有「结果」，没有「条件」

| 现有数据 | 性质 | 说明 |
|---|---|---|
| `PREFECTURE_INFO[路]["yields"]` | **结果** | 京畿路丝 100 万 / 陕西路 43,750 —— **但无「为什么」** |
| `CASH_CROP_LAND[路][作物]` | 结果 | 逐路经济作物用地占比 |
| `TERRAIN_MULT` | ⚠️ **无关** | 是**外邦运费**倍数（`山越1.5 / 草原1.2 / 平川1.0`），**不作用于宋的生产** |
| `demog`（人口/田/户）| 规模 | 来自 `data_prefecture_demog` |

⇒ **现有模型只有「哪路产多少」，没有「为什么产这么多」。**
⇒ 后果：数值不可解释、不可调、无法体现地理差异的**因果**。

## 二、设计目标

引入一层 **`REGION_CONDITIONS[路]`（地理环境与生产条件）**，作为：

```
① 建筑可得性的依据（哪种田能建）
② 生产率系数的来源（进《生产率层设计》）
③ yields \u7684\u7531\u6765\uff08\u89e3\u91ca\uff0c\u800c\u975e\u7ed3\u679c\uff09
```

## 三、维度设计

| 维度 | 取值（分档）| 影响什么 |
|---|---|---|
| **地形** | 平原 / 丘陵 / 山地 / 水乡 / 草原 / 高原 | 可建建筑、**耕作生产率** |
| **气候带** | 暖温带 / 北亚热带 / 中亚热带 / 热带边缘 | **作物适种性**（蔗/茶/果/桑）|
| **水利** | 丰 / 中 / 乏 | **农业生产率**（与「水利」建筑协作）|
| **土壤** | 沃 / 中 / 瘠 | **单产** |
| **区位** | 都城 / 要冲 / 边地 / 海港 / 内陆 | 商业·物流·商税 |
| **灾害频度** | 高 / 中 / 低 | 负向生产率 · 波动 |
| **人口密度** | —— | ❌ **不另设**：已由 POP 表达 → 密度可由 `POP ÷ 面积` 派生 |

⚠️ **人口密度不单列**（承「口径单点」）—— 已有数据能派生，不重复设表。

## 四、关键设计点

### 4.1 与「底层一致」的关系

- **维度集（字段名与分档）各国一致** ⇒ 属**底层**；
- **各路的取值**不同 ⇒ 属**差异**（由史料/地理决定，不是设定）。

⇒ 与「主要国家/外邦分层」自洽：**同一套字段，不同取值**。

### 4.2 与 `yields` 的关系 —— 🔴 本层应能**解释** `yields`

```
yields[路][作物]  ⇐  面积 × 适种性(地形·气候) × 单产(土壤·水利) × 从业占比
```

⇒ **理想状态**：`yields` 是**派生物**，而非独立输入。
⚠️ 但现状 `yields` 是手写的独立数值 ⇒ 二者**可能不自洽**（见 §五）。

### 4.3 与 `CASH_CROP_LAND` 的关系

`CASH_CROP_LAND` 是**从业/用地占比**；本层的**气候适种性**决定
**哪些作物在该路可能被种** ⇒ 两者应**相容**：

```
CASH_CROP_LAND[路][作物] > 0  应蕴含  该路气候适种该作物
```

⚠️ 若出现「气候不适种但占比 > 0」（如寒地种蔗），**即为数据冲突，须裁定**。

## 五、🔴 已发现的数据冲突（必须先在落地前解决）

### 冲突甲：`yields` 与 `CASH_CROP_LAND` 差 **3.75 倍**

| 来源 | 两浙路「丝」从业占比 |
|---|---:|
| 由全国统一基数（§《统一建筑语汇设计》10.2）反算 | **26.26%** |
| `CASH_CROP_LAND["两浙路"]["丝"]` | **7%** |

⇒ **两个数据来源互相矛盾，须裁定谁为准。**

### 冲突乙：本层缺失导致无法裁决

若已有**地理条件层**，即可判断：

- 两浙路产丝 100 万，究竟需要 **26%** 还是 **7%** 的农户？
- 取决于**单位产量**（单产 × 面积）—— 而这正是本层应提供的。

⇒ **本层是解决冲突甲的前提。**

## 八、🔴 解法：让地理条件做「源头」，两表降为「派生物」

> **用户裁定**：「**加入地理条件不就能规定了**」

### 8.1 思路

`yields` 与 `CASH_CROP_LAND` 之所以矛盾，是因为**两者都是手写的独立输入**，
没有共同的来源。⇒ **不可调和，也不该调和。**

**改为**：以**地理条件为唯一源头**，二者皆**派生**：

```
\u5730\u7406\u6761\u4ef6[\u8def]  \uff08\u8bbe\u5b9a\uff09
   \u251c\u2500 \u6c14\u5019\u5e26      \u2192 \u89c4\u5b9a\u300c\u80fd\u79cd\u4ec0\u4e48\u300d\uff08\u9002\u79cd\u6027\uff09
   \u251c\u2500 \u571f\u58e4\u00b7\u6c34\u5229\u00b7\u5730\u5f62 \u2192 \u89c4\u5b9a\u300c\u5355\u4ea7\u591a\u5c11\u300d
   \u2514\u2500 \u9762\u79ef          \u2192 \u89c4\u5b9a\u300c\u80fd\u79cd\u591a\u5c11\u5730\u300d
        \u2193
   \u5efa\u7b51\u89c4\u6a21\uff08\u6851\u7530/\u9ebb\u7530/\u2026\uff09\u00d7 \u57fa\u6570 \u00d7 \u751f\u4ea7\u7387
        \u2193
   \u4ea7\u51fa\uff08\u6d3e\u751f\uff09\u3001\u5360\u6bd4\uff08\u6d3e\u751f\uff09
```

⇒ **`yields` 与 `CASH_CROP_LAND` 都从「输入」降为「校验基准」。**

### 8.2 派生路径（两条，需裁定）

#### 路径甲：**面积分配由设定给出**（简单、可控）

```
① \u5730\u7406\u6761\u4ef6 \u21d2 \u8be5\u8def\u9002\u79cd\u4f5c\u7269\u96c6\u5408
② \u8bbe\u5b9a\u300c\u5404\u4f5c\u7269\u5360\u8be5\u8def\u519c\u7530\u7684\u6bd4\u4f8b\u300d\uff08\u5b9a\u503c\uff0c\u53ef\u8c03\uff09
③ \u4ece\u4e1a\u4eba\u6570 = \u519c POP \u00d7 \u8be5\u6bd4\u4f8b
④ \u5efa\u7b51\u7b49\u7ea7 = \u4ece\u4e1a\u4eba\u6570 \u00f7 \u6bcf\u7ea7\u5728\u5c97
⑤ \u4ea7\u51fa = \u5728\u5c97 \u00d7 \u5168\u56fd\u7edf\u4e00\u57fa\u6570 \u00d7 \u7b49\u7ea7\u7cfb\u6570 \u00d7 \u5730\u7406\u751f\u4ea7\u7387
```

- ✅ 实现简单，量级可控；
- ⚠️ 第 ② 步仍是「手写比例」⇒ **只是把 `CASH_CROP_LAND` 搬了个位置**；
- ✅ 但**至少与 `yields` 一致**（因产出由它派生）。

#### 路径乙：**面积由市场/收益决定**（V3 式，自洽）

```
① \u519c\u6237\u6309\u300c\u51c0\u6536\u76ca\u300d\u9009\u4f5c\u7269\uff1a\u5355\u4ea7\u00d7\u4ef7\u683c \u2212 \u6210\u672c
② \u5730\u7406\u6761\u4ef6\u4f7f\u540c\u4e00\u4f5c\u7269\u5728\u5404\u8def\u5355\u4ea7\u4e0d\u540c\uff08\u2192 \u6bd4\u8f83\u4f18\u52bf\u4e0d\u540c\uff09
③ \u5360\u6bd4\u7531\u9009\u62e9\u81ea\u7136\u6d8c\u73b0\uff08\u4e0d\u518d\u624b\u5199\uff09
```

- ✅ **彻底自洽**：`CASH_CROP_LAND` 不再需要（它是**结果**而非输入）；
- ✅ 与「生产率层」（价格/收益）自然衔接；
- ⚠️ 实现量大（需作物收益模型 + 农户选择），且**可能震荡**（需收敛机制）。

### 8.3 与既有数据的关系

| 现有数据 | 路径甲 | 路径乙 |
|---|---|---|
| `yields` | 降为**校验基准**（对比派生值）| 同左 |
| `CASH_CROP_LAND` | **升为输入**（移到地理条件里）| **废弃**（改为涌现）|
| `REGION_CONDITIONS` | 新增，作为**适种性与单产**来源 | 同左，且驱动选择 |

### 8.4 🔴 校验二（22 处「适种却无占比」）的解释

先前校验用 `.get(d, 0)` 取值 ⇒ **缺省被当成 0**，**违反「缺失≠0」**。

⇒ 这 22 处**很可能是「未录入」而非「真的不种」**。
在 §8.1 架构下，它们**不再是问题**：占比由地理条件 + 设定/选择派生，
`CASH_CROP_LAND` 只作**参考**。

### 8.5 无法回避的一项设定

无论甲还是乙，**都必须先定**：

```
\u5730\u7406\u6761\u4ef6\u2192\u9002\u79cd\u6027\u4e0e\u5355\u4ea7 \u7684\u5177\u4f53\u6362\u7b97
```

- 分档标准（地形/气候/土壤/水利 各几档）；
- 每档 → **适种作物集合** 与 **单产系数**；
⇒ 这些是**玩法设定**（承用户「设定基数就好啦」），**不要求史料**。

⚠️ 但**气候适种性**若要与史实相容（如「寒地不种蔗」），
则**分档应与实际地理位置对应** —— 这部分宜**依地理事实**而非随意设定。
