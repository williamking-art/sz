# 地理环境与生产条件层设计（2026-10-05）

> **用户裁定**：需想清**怎么给各地的生产条件、地理环境做区分**。
> 本文为设计，**未改代码**。

---

## 一、🔴 现状：只有「结果」，没有「条件」

| 现有数据 | 性质 | 说明 |
|---|---|---|
| `PREFECTURE_INFO[路]["yields"]` | **结果** | 京畿路丝 100 万 / 陕西路 43,750 —— **但无「为什么」** |
| `CASH_CROP_LAND[路][作物]` | 结果 | 逐路经济作物用地占比 |
| `TERRAIN_MULT` | ⚠️ **无关** | 是**外邦运费**倍数（`山越1.5 / 草原1.2 / 平川1.0`），**不作用于宋的生产** |
| `demog`（人口/田/户）| 规模 | 来自 `data_prefecture_demog` |

⇒ **现有模型只有「哪路产多少」，没有「为什么产这么多」。**
⇒ 后果：数值不可解释、不可调、无法体现地理差异的**因果**。

## 二、设计目标

引入一层 **`REGION_CONDITIONS[路]`（地理环境与生产条件）**，作为：

```
① 建筑可得性的依据（哪种田能建）
② 生产率系数的来源（进《生产率层设计》）
③ yields \u7684\u7531\u6765\uff08\u89e3\u91ca\uff0c\u800c\u975e\u7ed3\u679c\uff09
```

## 三、维度设计

| 维度 | 取值（分档）| 影响什么 |
|---|---|---|
| **地形** | 平原 / 丘陵 / 山地 / 水乡 / 草原 / 高原 | 可建建筑、**耕作生产率** |
| **气候带** | 暖温带 / 北亚热带 / 中亚热带 / 热带边缘 | **作物适种性**（蔗/茶/果/桑）|
| **水利** | 丰 / 中 / 乏 | **农业生产率**（与「水利」建筑协作）|
| **土壤** | 沃 / 中 / 瘠 | **单产** |
| **区位** | 都城 / 要冲 / 边地 / 海港 / 内陆 | 商业·物流·商税 |
| **灾害频度** | 高 / 中 / 低 | 负向生产率 · 波动 |
| **人口密度** | —— | ❌ **不另设**：已由 POP 表达 → 密度可由 `POP ÷ 面积` 派生 |

⚠️ **人口密度不单列**（承「口径单点」）—— 已有数据能派生，不重复设表。

## 四、关键设计点

### 4.1 与「底层一致」的关系

- **维度集（字段名与分档）各国一致** ⇒ 属**底层**；
- **各路的取值**不同 ⇒ 属**差异**（由史料/地理决定，不是设定）。

⇒ 与「主要国家/外邦分层」自洽：**同一套字段，不同取值**。

### 4.2 与 `yields` 的关系 —— 🔴 本层应能**解释** `yields`

```
yields[路][作物]  ⇐  面积 × 适种性(地形·气候) × 单产(土壤·水利) × 从业占比
```

⇒ **理想状态**：`yields` 是**派生物**，而非独立输入。
⚠️ 但现状 `yields` 是手写的独立数值 ⇒ 二者**可能不自洽**（见 §五）。

### 4.3 与 `CASH_CROP_LAND` 的关系

`CASH_CROP_LAND` 是**从业/用地占比**；本层的**气候适种性**决定
**哪些作物在该路可能被种** ⇒ 两者应**相容**：

```
CASH_CROP_LAND[路][作物] > 0  应蕴含  该路气候适种该作物
```

⚠️ 若出现「气候不适种但占比 > 0」（如寒地种蔗），**即为数据冲突，须裁定**。

## 五、🔴 已发现的数据冲突（必须先在落地前解决）

### 冲突甲：`yields` 与 `CASH_CROP_LAND` 差 **3.75 倍**

| 来源 | 两浙路「丝」从业占比 |
|---|---:|
| 由全国统一基数（§《统一建筑语汇设计》10.2）反算 | **26.26%** |
| `CASH_CROP_LAND["两浙路"]["丝"]` | **7%** |

⇒ **两个数据来源互相矛盾，须裁定谁为准。**

### 冲突乙：本层缺失导致无法裁决

若已有**地理条件层**，即可判断：

- 两浙路产丝 100 万，究竟需要 **26%** 还是 **7%** 的农户？
- 取决于**单位产量**（单产 × 面积）—— 而这正是本层应提供的。

⇒ **本层是解决冲突甲的前提。**
