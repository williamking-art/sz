## 二、生产率层（本次用户要求）

### 2.1 公式

```
产出 = Σ(在岗人 × 单位产出基数) × 建筑等级系数 × 生产率系数
                                   └─ 已有 ─┘      └─ 新增 ─┘

生产率系数 = Π(各因素因子)      # 乘性叠加，各因子默认 1.0
```

### 2.2 因素清单（**可枚举、可分解、可对账**）

| 因素 | 层次 | 作用域 | 现状 |
|---|---|---|---|
| **建筑等级** | 建筑 | 单建筑 | ✅ 已有（`1 + 0.05×(lv−1)`）|
| **科技** | 路/全国 | 生产 | ⚠️ 有 `material_tech.py`/`data_tech.py`，**未接产出** |
| **政令/诏令** | 路/全国 | 生产 | ⚠️ 有 `data_decree.py`，**未接产出** |
| **节气/农时** | 月度 | 农事 | ⚠️ 仅有「与粮同节奏」的**约定**，**无系数** |
| **水利** | 路 | 农业 | ⚠️ 建筑「水利」已有，**未接产出** |
| **灾害/战乱** | 路/月 | 生产 | ⚠️ 有灾害系统，**未接产出** |
| **吏治效率** | 路 | 全产 | ❓ 待定 |

### 2.3 🔴 设计纪律（关键）

**① 口径单点**：只允许一个函数计算，禁各处自行相乘。

```python
def productivity_factors(state, route, building) -> dict[str, float]:
    """返回 {因子名: 系数}；**只列出已生效的因子**。"""
```

**② 缺失 ≠ 1.0**（承 §3-3）：

- **未实现的因素不列入返回 dict**，**不填 1.0**；
- 诊断/界面显示「**未计入**」而非「×1.0」，避免把「没做」伪装成「做了但无影响」。

**③ 可对账**：任一月产量必须能分解为：

```
产出 = 在岗 × 基数 × 等级系数 × Π各因子
```

⇒ 月度诊断须能**逐因子列出**（否则出问题无法定位）。

**④ 因子间不重复计入**：

- 若某政令的效果已被写入**建筑等级**，则**不得再作为因子**乘一次；
- 每个因素**只在一个地方生效**，需在表 2.2 标注归属。
