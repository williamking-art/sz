## 1. 核心循环

- **回合制**：`1 回合 = 1 月`；
- 唯一时钟是 `state.turn`；所有“过多久生效”都用 `due_turn` / `end_turn`，不用 wall clock；
- 月度流程大致为：玩家命令/诏令/军令/召对 → 朝议与执行 → 经济/财政 → 军事/外交 → 派系/事故/科举 → 事件/奏报 → 回合收尾；
- 具体结算顺序以 `core/settlement.py` / `settlement_steps.py` 的管线为准。

### 1.1 结算幂等（2026-10-22）

结算入口 `run_monthly_settlement(state, seed_offset=0, expect_turn=None)` 在末尾推进
`state.turn` 与年月。**改前没有任何幂等守卫**：一次成功结算后若响应丢失、客户端重发，
会**再推一个月**（双重结算）。现在支持**声明式幂等**：

| 调用方声明 | 行为 |
|---|---|
| `expect_turn=None`（默认） | 与改前**完全一致**（老调用方零改动；每次调用都推进） |
| `expect_turn == state.turn` | 正常结算 |
| `expect_turn < state.turn` 且有历史日志 | **幂等重放**：不结算、不改状态，返回该回合日志副本 |
| `expect_turn < state.turn` 但无历史日志 | 不结算 + warning（宁可少给，不重复推月） |
| `expect_turn > state.turn` | 不结算 + warning（客户端超前，跳过一月更危险） |

- 为什么用回合而不是幂等令牌：`state.settlement_log` 本就按回合 append，重放不需要新状态字段；
- **前端接线未做**：要真正防住「重发」需调用方在结算请求里带上它正在展示的回合
  （`settle_local(state, expect_turn=…)` 已支持），当前前端未传 ⇒ 守卫处于**待启用**状态
  （不是"已防住"，别当成保护已生效）；
- 另一并修掉的别名问题：存进 `settlement_log` 的现在是**副本**，调用方就地改返回值不再污染存档历史。

## 2. 权力、权限与皇威

### 2.1 权限挂职位，不挂部门

- `permission_model.has_permission(actor, matter)` = actor **当前所有职位**的权限并集；
- 任命 = 获得该职位权限；免职 = 失去该职位权限；
- 机构只是背景与承办渠道，**不能**把“部门”当作永久权限主体。

### 2.2 皇威权柄

皇威高于阈值时，皇帝对特定程序化命令可直接执行；否则走正常流程。

| 权柄 | 阈值 | 代价 | 入口 |
|---|---:|---:|---|
| 任免 | >80 | 2 | `personnel_order.issue_personnel_order` |
| 军令/调兵 | >85 | 5 | `commands.issue_military_order` |
| 党禁 | >90 | 8 | `party_ban_order.issue_party_ban_order` |

直行仍校验**目标合法性/物理约束**；不是“无代价、无边界”。

### 2.3 军令的皇威差异

- **低皇威（≤85）**：所有军令进入月结算队列，过枢密院/掌 `调兵` 事权，`due_turn` 到期才落地；
- **高皇威（>85）**：除 **调赴/调度军令** 这种天然耗时动作外，其余军令即时执行、扣 5 皇威；
- **高皇威调赴**：可立即下令，但军队移动仍按交通耗时；
- 军令只走 `approve_ai_action → _apply_military_dispatch` 单点，不直写军队。

详见：[`军令机制现状_2026-10-19.md`](../specs/cross-cutting/军令机制现状_2026-10-19.md)。

## 3. 派系、党争与党禁

### 3.1 派系

- 固定五派：新党、旧党、皇党集团、军功集团、中立派；
- `faction_settle.settle_factions_from_pop` 是 `satisfaction/influence/cohesion` 的**唯一写点**；
- `influence` 每月由 POP 派生并覆盖，不能手写；
- `satisfaction/cohesion` 向目标缓动，消化 `_event_delta`；
- 转投只走 `faction_split` 零和入口，Σ=1。

### 3.2 党禁

- 状态在 `state.factions[faction]["ban"]`，不新增顶层 state；
- 轻/中/重：6/12/18 回合；
- 正式职位 `permission_capture` 下降，但**不删除派系/POP 网络**；
- `grievance`、`satisfaction_target`、`cohesion_target` 由 `faction_settle` 消费；
- 被禁官员在事故处理中会被跳过；无可用承办官则升级；
- 科举：考官被禁不结座主门生；中/重取士额 ×0.85/×0.65；重级限三舍；`cohort.ban_context` 留档；
- 党禁令：皇威 >90 直行，否则入队走流程。

**核心口径：禁而不绝。** 党禁不是“删除一个派系”，而是改变正式准入、执行能力与非正式反噬。

详见：[`党禁机制设计_2026-10-19.md`](../specs/cross-cutting/党禁机制设计_2026-10-19.md)。

## 4. 科举与人事

- 科举每 **36 个月**开科，走解试→省试→殿试；
- `state.exam["cohorts"]` 保留最近 12 科；
- 知贡举派系是“座主门生”锚点；新科进士经 `blend_entrants` 随座主入派，只改 `faction_split`，不改 POP size；
- 党禁的 `ban_context` 会进入 cohort：考官限制、取士额、三舍限制；
- 县官不建顶层席位表：`jinshi_to_county` 把知县写入 **MemoryGraph**，县实体带 `posts/quotas/parent_seat_id`，官员用 `governs` 关系挂县，县用 `belongs_to` 挂父州府；
- 任免/罢免是权限变化的正式入口；不要手改 holder 或 `permission_capture`。

## 5. 奏报、事故与情报

### 5.1 三层结构

| 层 | 内容 | 玩家是否直接看到 |
|---|---|---|
| `raw_reports` | 县/州府/路省/军报原件，全文留档 | ❌ 不直接进 UI |
| `handled_reports` | 部门已办/压案/拖延/摘要/建议 | 部分进背景档 |
| `state.memorials` | 需要皇帝决策的“摘要+建议” | ✅ 奏折区 |

- 原件存 `prefectures[路]["seats"][治所]["raw_reports"]`；
- `raw/handled/suppressed/delayed` 状态留痕；正文不因“没到御前”而删除；
- 御前摘要只引用 `raw_report_ids`，不复制、不改写原件。

### 5.2 事故逐级处理

- 县/乡里是**事故地点粒度**，不是独立行政层；
- 有县官（MemoryGraph）则县官处理；否则州府通判/幕职/巡检代行（+1 回合、能力折扣）；
- 逐级：`locality → prefecture → circuit → central`；
- 到 `central` 只产生 `awaiting_decision + recommendation`，再由摘要层进御前；
- 同一 `incident_id` 幂等。

### 5.3 军报与交通

- 军报/军令共用 `transport.route_path`（多跳最短路：`km/days/hops`，含路况表）；
- 军报按 `priority=urgent` 可插御前摘要前排；
- `road_blocked=True` 额外 +1 回合；
- 军报只报事实/请求，不直接调兵。

### 5.4 三个队列不要混

- `state.memorials`：待批奏折/摘要；
- `state.ai_pending_actions`：AI/大臣待批呈请、低皇威军令、部分党禁令；
- `state.edict_drafts`：已准奏/会签中的诏草。

### 5.5 情报边界

- **皇帝通过大臣/机构获取情报**，不是全知 UI；
- 奏报可滞后、偏差、被派系过滤；不显示 `grievance/cohesion/permission_capture` 精确值；
- 想查得更准，走召对/勾校/台谏，不靠新增面板。

详见：[`奏报机制现状整理_2026-10-19.md`](../specs/cross-cutting/奏报机制现状整理_2026-10-19.md)。

### 5.7 结算期的裁决**只读观测副本**（2026-10-22）

月结 Step 0 用 `TianDaoFacade.observe_monthly` 统一观察本月裁决与**概率**，写入
`state._tiandao_observe` 与 `decision_log`（不入存档）。**结算中的消费方一律读这份副本**，
不得自己再造上下文重调门面——否则「日志记的裁决」与「结算实际用的裁决」可能不是同一个
（与阈值双源同型的问题）。

| 消费点 | 读法 |
|---|---|
| 田赋宽严 / 蠲免 / 变法遵从 / 平粜 / 仓场贪墨 | `tiandao_effects.observe_strength` / `observe_mix`（强度连续） |
| 商贾囤抛 / 士绅义庄 / 小农逃散 / 漕运改道 / 募流民 | 同上（概率加权） |
| 采购的劳动政策（差役/雇役） | **2026-10-22 改**：`procurement` 优先 `observe_verdict(state,"labor_service_policy")`，**无记录才回落直调门面**（首月/读旧档），Jev p=0.9915 |

- gate 的判定阈值**单一出处** = `core/ai/tiandao_decision.THRESHOLDS`（`tiandao_effects.objective_threshold` 读取）；
- 观测失败 ⇒ `_tiandao_observe` 置 `None`（**不得残留上月副本**），消费方按中性处理。

### 5.6 奏折事实签的四类判据（2026-10-22 重标）

`TianDaoFacade.scan_memorial_seeds` 用**既有读数**决定本月该出哪种签（不是随机刷）：

| 签 | 判据（相对锚，自校准） | 实测频率 |
|---|---|---|
| 财政（请拨帑银） | 地方府库 **不足 0.1 个月本地月税**（≈三日支应）；见底越深越靠前 | 太平 24 月出现 11 地月（≈2%）|
| 军事（募流民/平粜） | 流民 **超过本地人口的 0.4%** | 饥荒月触发 |
| 政务（督责监司） | 本地民怨 **> 50**（0–100 刻度） | 危机第 8 月起 |
| routine（天下如常） | 上述皆无 | 太平年景常态 |

- 读数缺失（月税/人口/府库）⇒ 该地**不计入**（缺失≠0，不臆造告警）；
- 改前「民怨>40 **且** 府库<5 万贯」是两个条件**从不同时成立**的死签（实测太平 24 月里
  19 月有府库见底，其间民怨最高仅 11.3；危机 12 月则府库一次不见底）——现按上表的
  **相对锚**判，民怨只作严重度修饰。

## 6. 经济、财政、仓储与交通

### 6.1 POP 挂载律（旧 §五 · 现行硬约束）

- 人（官/吏/宗室/兵/编制）只落 **6 类 POP 的 `size`**；
- 钱粮只落 **POP 的 `wealth`/`grain`** 或 **国库/内帑**；
- 允许 POP 子池（如 `hidden`/`faction`/职业子池），**禁止与 POP 平行的第二本账**；
- 阶层/职业/地区变动必须走 `pop_bridge` / `move_pop_people` 等既有通道，保持 ΣPOP 守恒；
- 缺失是缺失，不回落 0/1.0；新增写点必须配守恒断言；
- 这是所有新机制的硬约束，优先于任何局部便利。

- **POP/钱/粮/物料真账在治所（seats）**；路级 `pops` 是只读派生镜像；
- 所有 POP 写入走 `pop_bridge`；地方府库走 `local_treasury_bridge`；仓储走 `storage_bridge` / `spatial_warehouse_bridge`；
- 货币分层 M0/M1/M2，中央与地方账户分离；
- 交通：`transport.route_path` 是最短路入口；`ROAD_QUALITY` 默认空 = 不臆造路况；
- **缺失 ≠ 0**：未知路线/缺坐标返回 `None`，不得回落瞬移；
- 禁止另开“派系人口/党争经费/平行仓库”账本。

### 6.2 民怨（unrest）动力学（2026-10-22 新增）

**口径**：民怨是 0–100 的**缓动状态**，每月向「压力目标」靠拢 `UNREST_DRIFT_RATE`(10%)，
不是增量累加（防跳变、无漂移 runaway）。压力目标由**既有读数**合成，缺失项不计：

| 压力项 | 取值 | 权重（待校准） |
|---|---|---|
| 粮价 | 本地粮价高出平价 1.0 的部分 | ×20（价 3.0 ⇒ +40）|
| 灾情 | `state.disaster_severity`（0–5）| ×8（满灾 ⇒ +40）|
| 流民 | 流民/本地人口，10% 记满 | ×25 |
| 治理 | `govern` 低于 50 的部分 | ×20 |

- 太平年景目标 ≈0 ⇒ 民怨自然回落到低位（实测 12 月中位 15→5）；
- 灾 5 + 粮价 ×3 ⇒ 目标 ≈80，实测 12 月内升到 26→58（内容里 30/45 档位**首次可达**）；
- 60/85 档需**持续两年以上**的极端灾情+失治（目标 90 时约 24 月到 83、36 月到 87）；
- 与既有「治安支出抵减民怨」（`settlement_finance` 的 `runner_pay`）**并存**：该项是额外下行，
  不再依赖它（改前它按军费份额算 ⇒ **无实体军的 8 地民怨永久冻结在初始值**，实测利州路/
  广南西路 24 个月恒 24）；现在无军之地也随压力目标演化。

⚠️ 已知边界：民怨的**下游消费者很少**（局势种子、本地推演档位、流民吸收系数），
所以它在 golden 12 月快照里几乎不显形（实测仅 `army_troops −64`/太仓 `+72`）——
"档位可达"的价值体现在局势/推演分支活了，不是经济数值变化。


### 6.2 2026-10-20 全审修复后的硬口径（违反会破坏守恒）

- **治所级写入必须走桥**：`pop_seat_set/add(pdata, cls, pop_obj, ...)` 写**单个治所真账**并 O(1) 刷新该阶层镜像；`pop_obj_*` 只认**路级**行，对治所级对象恒返回 `None`（不要据此回落直写）。
- **禁止「读路级镜像 → 重铺治所」**：镜像可能滞后于本回合的治所直写；按镜像聚合值回写治所会把已扣的钱整额“复活”（2026-10-20 实测曾造成 12 个月 +13,470,432 贯凭空造币）。需要按比例扣减时，逐治所真账扣减后 `refresh_route_class`。
- **地方府库写点一律走 `local_treasury_bridge`**：建筑升级、区域行政、陆路榷税等直写路级 `local_treasury` 的写点已全部收口；直写会让治所真账滞后，随后走桥写入校正镜像时表现为“凭空销毁”。
- **月度对账残差是造币/销毁的唯一判据**：`state.money_audit["cum_residual"]` 必须≈0；`M_ALL == Σ账户` 只是静态恒等式，不能替代月际对账（`test_m162_long_run_sentinel.py` 已加 12/60/240 月残差断言）。
- **长期旨案卷专款**：`authorize_case` **只登记额度、不即时扣库**；`monthly_case_settle` 按 `monthly_cost` 从国库/内帑实扣并递减 `budget.remaining`（额度上限，不是货币账户）。未授权时 readout 的 `authorization` 为 `None`（面板显示“未授权”，不得回落 0）。
- **陆路榷税有付款方**：由该路商人 POP wealth 经桥扣缴，不足按实扣（`credited < tax`）；不得只入府库。
- **交通队列上限**：`TRANSPORT_QUEUE_MAX_STONE` 缺失/非正时按“不限制”并告警（不得静默全丢）；丢弃量累计进 `statistics["transport_queue_dropped"]` 并留痕。
- **金库工具返回值**：`change_treasury/change_imperial_treasury/change_granary` 返回**实际生效 Δ**（穿底/封顶时小于请求值）；成对记账的调用方按实扣给对方入账。

详见：[`货币口径规范_M0M1M2.md`](货币口径规范_M0M1M2.md)、[`底层经济闭环与全息真账机制规范_2026-10-17.md`](底层经济闭环与全息真账机制规范_2026-10-17.md)。

## 7. 天道

- 项目内嵌 Jev，不是外部子代理；
- `TianDaoEngine`：`gate`（二元）、`choose`（多档）、`score`（分档）、`dice(seed)`（确定性微扰）；
- `TianDaoFacade` 收敛业务裁决（财政、市场、仓储、行政、军事、奏报事实签等）；
- 天道只出 **verdict / omen / 史评 / 理由**；
- **不直接写 state**，不改 `legal/procedure/fact_finding`；
- 同 seed 可复盘；`basis_undefined` 不伪造“平”。

**2026-10-21 加强批（口径，读数值/排查时以此为准）**：

- **facts 契约单一出处** = `core/ai/tiandao_facts.py`（24 个 canonical 键 × 量纲 × 缺失语义）。
  所有裁决上下文一律经它生产；**新增读数必须先在那里登记**。
- **读数口径更正**：`disaster` 取 `state.disaster_severity / 5`（0~5 灾级归一 0~1；
  旧实现读一个无人写入的 `statistics["disaster_level"]` ⇒ 恒缺失）；`integrity` 无贪腐读数时为
  `None`（旧实现回落 1.0＝“吏治完美”）；常平闸门的库存是**常平仓合计**，不是太仓 `granary`。
- **玩法常数外置** = `content/data_tiandao.py`（93 参数，唯一入口 `PARAMS`；标 `# 待校准` 者缺依据）。
- **决策留痕**：每月 11 项裁决写入 `state.decision_log`（有界 200，含 `facts_digest`），
  **随存档持久化**（`schema_version=v5`，旧档缺键按空表）；离线评测用
  `python -m core.ai.tiandao_backtest <save.json>` 算 Brier / ECE / 命中 / 单调。
- **11 项裁决的数值效果（2026-10-22 起全部接线，5 + 5 + 1）**：
  ① 已有 5 项（税负宽严 / 蠲免 / 平粜 / 仓吏贪墨 / 变法遵从）；
  ② 本批新增 5 项：**商贾档**（士绅囤抛力度 ×0.90–1.20，钳位 0.85–1.25）、
  **士绅档**（兼并 0.3%/月 或 义庄赈济 2%/月，均成对转移）、
  **小农档**（典田入同一 0.3% 通道；举家逃亡 ⇒ 饥荒逃散 ×1.5，仍受 5 万人/路上限）、
  **漕运档**（陆路 ⇒ 途耗 ×0.80 + 0.01 贯/石脚钱；和籴 ⇒ 途耗 ×0.90 + 地方府库买粮 3% 入太仓）、
  **募流民档**（True ⇒ 流民 2%/路/月、上限 2,000 人入本路兵额；无实体军的路不扣人）；
  ③ 遵从度（`circuit_decree_compliance`）走 `decree_effect` 合成层。
  🔴 **缺失/非法裁决一律中性**（乘子 1.0 / 不动作），与「无记录」逐字节等价。

## 8. AI 与叙事

- AI 是可选增强层：可用则生成叙事/建议，不可用则本地模板兜底；
- AI 输出走结构化契约与档位，不直接改数值、不创造职权、不伪造证据；
- 结算链不依赖 AI 可用性；AI 失败不得阻断主流程；
- 臣僚立场、奏报摘要、月报叙事可 AI 化，但事实源仍是程序账本。
