## 一、目标

把建材的**持有与领料**从「路」下沉到「**州府（治所）**」，使「建材有没有运到」按**工地所在州府**可观测、可归因。

## 三、目标口径

### 3.1 物理落点：商人 POP `goods` 的**州府子槽**

建材**仍是商品、仍只在商人 POP**（E-1 不变），但 `goods` 内新增一层**按治所**的建材槽：

```
prefectures[路].pops["商人"].goods = {
    "绸": <int>, "布": <int>,           # 既有：民间消费品（路级，不动）
    "建材": {                            # 新增：州府级建材槽
        "<治所>": {"木": n, "石": n, "铁": n, "砖": n, …}   # 物料维已全中文
    }
}
```

**为何放子槽而不是新建 POP**：POP 结构以路为键，改成州府级 POP 是**整层重构**（远超本任务）；
子槽在不破坏 POP 挂载律与既有 71 处 `state.resources` 读取的前提下，给建材**唯一**的州府级归属。
规格 §13.2-3 的「POP `goods` 加建材槽（**调和维度**，非原料维度）」即此意。

### 3.2 单点 API（三处消费侧一律改走它）

```python
material_holding_for_seat(state, seat_id, dim) -> Optional[int]   # 州府级读；无货/未登记 ⇒ None（缺失≠0）
consume_for_seat(state, seat_id, dim, amount) -> int              # 州府级扣；返回**实扣量**（扣不足不静默）
supply_to_seat(state, seat_id, dim, amount) -> int                # 来源池 → 该州府（搬运，守恒）
```

`seat_id` 一律用 `prefecture_entity` 的 **`路\|治所`** 主键；`路→治所` 用既有 `circuit_seats()`。
**旧的路级函数保留但标 `deprecated`**（一次性迁移用），新代码不得再调 —— 避免两套口径并存。

### 3.3 不变量（回归锁定）

1. **唯一归属**：建材只在商人 POP `goods["建材"][治所]`；**无第二处账本**（`state.resources` 仍只是来源池）；
2. **守恒**：`supply_to_seat()` 只搬运，`Σ(各州府建材) + 来源池stock` 不变；扣料是**内部转移**，不凭空生灭；
3. **缺失 ≠ 0**：无该州府槽/无该维 ⇒ `None`，**不回落 0**（否则「没运到」与「有但为 0」不可区分）；
4. **不越州府**：工地只从**本州府**取料，**不跨州府借料**（否则「运没运到」不可观测）；
5. **口径单点**：「能否开工」的判定与「实际领料」必须调**同一个**函数（见 §四·障碍 2）。

## 三补 · 🔴 实施前发现的硬约束（2026-10-03 读代码后修正本方案初稿）

**初稿把批次 1 说成「低风险孤立批次，不与消费侧纠缠」——该判断不成立**，理由如下：

### 硬约束：`market.trade_goods` 绑在**扁平 `goods[dim]`** 上

```
material_holding.trade_material()          # 州府间建材成交
  → core.market.trade_goods(...)           # 🔴 读写 goods[dim]（扁平）
material_holding.py:217-225                # 成交前后按 goods.get(dim) 取差值
```

现布局是**扁平**的：`goods = {"绸": n, "布": n, "木": n, "石": n, "铁": n, …}`（物料维 2026-10-03 已全中文），
`supply_merchant_materials()` 也直接写 `goods[dim]`（`:178`）。
⇒ **一旦把建材搬进 `goods["建材"][治所]`，`market.trade_goods` 立刻取不到料并可能写坏账** ——
   这正是「收窄版 B」失败时记录的「须逐个改上表 8+ 模块的读取口，否则供给侧一改全链断料」**同一个坑**。

### 因此只有三条路，须择一（**不自行假定**）

| 方案 | 做法 | 代价 | 与仓库既有先例的关系 |
|---|---|---|---|
| **① 州府槽为权威 + 扁平为派生缓存** | 建材真身在 `goods["建材"][治所]`；`goods[dim]` 变成由州府槽**同步出来的派生值**（保留给 `market.trade_goods` 等 8+ 模块读），并断言 **Σ(州府) == 扁平值** | 一处派生同步函数 + 断言；**两处表示**，靠断言守住不漂移 | ✅ 与 `prefecture_entity`（路级为父、州府为派生子层、`Σ子==父`）**同构**；也与 `demography.py` 的拆分口径一致 |
| **② 州府槽为权威 + 改造 `market.trade_goods` 为州府感知** | 彻底单账本，无派生 | **要动 `core/market.py` 核心成交通道** + 其所有调用方；风险最高 | ❌ 无先例，等于重做市场撮合 |
| **③ 只做读侧派生（不落州府状态）** | 州府级读数由路级总量**按既有分配规则算出**，不持久化“哪州府有多少” | 最省，但**表达不了「不越州府」**（无法记住某州府已收到多少货）⇒ **C-c 的「先运到才能用」落不了地** | ✅ 同 `prefecture_entity`，但**不满足本任务的目标** |

### 我建议 ①（若目标是「运没运到可观测」）

理由：① 既让建材有**真实持久**的州府归属（满足 C-c「只从本地取、不跨州府借」），
又**不动** `market.trade_goods` 与那 8+ 个读 `state.resources` 的模块，把一个高风险重构压成
「一个同步函数 + 一条守恒断言」。且它**复制了仓库既有先例**（路级为父、州府为派生、Σ子==父）。

⚠️ 若选 ①，**派生同步必须单点**（唯一函数写 `goods[dim]`），否则两处表示会漂移成双账本 ——
这本身要作为不变量回归锁定：**任何写路径后 `Σ(州府)==扁平 且 扁平==stock−未分配`**。

**未择定前，批次 1 不启动**（避免重演「试了再回退」）。

## 三补二 · 🔴 ① 也不成立：真正的缺口在「到货入账」，且建材跨阶层持有

> 采用 ① 之后、动手前又核了两处代码，发现 §3.1 的**账本形态假设**与 §三补 的「低风险」判断**都不成立**。

### 发现 1：运输**时效已是州府级**，但**到货入账是路级**

| 环节 | 现状 | 证据 |
|---|---|---|
| 距离/耗时 | ✅ **州府级**（治所经纬、同州府内 0 耗时） | `transport.py:91-117` `_seat_index()` 取 `pe.all_seats()` 的 `seat_id`；`route_days(frm,to)` 用 haversine |
| 交通边 | ✅ 州府间（`CIRCUIT_INFO.members` 的治所两两成边） | `transport.py:151-158` |
| **发料** | 🔴 **路级**：`circuit = a["circuit"]` → `consume_for_circuit(state, circuit, dim, want)` | `transport.py:204-205` |
| **到货入账** | 🔴 **路级**：`merchant_goods(state, dst["circuit"])` —— **按路记货** | `transport.py:242` |

⇒ **「运到哪个州府」目前不可观测**：批次记了 `frm`/`to`（治所），可货一落地就并进「本路商人货栈」。
这正是 C-c「先运到才能用」目前**只做了一半**的地方，也是 §13.2-3 那道缝的**准确位置**。

### 发现 2：建材**不只由商人 POP 持有**

| 位置 | 写入者 |
|---|---|
| `production_chain.py:125-136` | **工匠 `artisan` 与 商人 `merchant` 都写** |
| `export_policy.py:569-580` | 任意 `seller` POP |
| `market.py:182` | 成交卖方 |
| `material_market.py:725` | 撮合卖方 |
| `material_trade.py:319` | 运输收货方 |
| `market_readout.py:11` | 自述「库存有**四个载体**（`state.resources`／`pop["goods"]`／…）」 |

⇒ §3.1 写的「州府槽放**商人 POP** 的 `goods`」**只覆盖商人那一份**，工匠等会漏在账外；
且 `material_holding_for_circuit()` 本来也只读商人 goods —— **现状路级读数本身就不是全量**。

### 被提前的建模问题

> **一个「路级 POP」持有的建材，如何归属到该路的若干州府？**

POP 是路级的（`prefectures[路].pops[阶层]`），**没有**州府维度。三条路：

| 方案 | 做法 | 代价 / 风险 |
|---|---|---|
| **A** 每个持仓 POP 的 `goods` 内加州府子槽（`goods["建材"][治所]`） | 覆盖全部阶层，保持 POP 挂载律 | 所有持仓 POP 的读写路径都要改；「路级 POP 的料在哪个州府」语义别扭，但**不新建账** |
| **B** 州府料账挂**路级**（如 `state.material_by_seat`） | 简单、覆盖全量 | 🔴 会被判「与 POP 平行的账本」，违反 `AGENTS.md` §3 第 1 条 —— **须用户明确豁免** |
| **C** 只把**到货入账**记到治所（不动持有侧） | `arrive_due` 把到货登记为 `治所→本路商人货栈` 的**带治所来源记录**，并在 `in_transit`/`transit_report` 暴露「各治所到货量」 | 能让「运没运到」**可观测**；但**表达不了「该州府现在有多少料」**，C-c 的「工地只从本地取」仍需 A/B |

**建材州府级下沉不是一个「批次 1 就能立起来」的孤立改动。** 我撤回 §三补 里「① 低风险」的判断，
也撤回 §3.1 的账本形态假设。在 A/B/C 择定前，**批次 1 不启动**——否则就是重演「试了再回退」。

## 六、验收断言

1. **守恒**：`supply_to_seat()` 前后 `Σ(各州府建材) + stock` 恒定；扣料前后 M_ALL 残差不变；
2. **单点**：「能否开工」判定值与 `material_holding_for_seat()` 返回值**同源**（断言两处相等）；
3. **缺失≠0**：未供货的州府返回 `None`（非 0），且调用方能区分并归因「未到货」；
4. **不越州府**：A 州府无料时，即使同路 B 州府有料，A 的工地也**不得**动工；
5. **逐维 Σ子==父**：既有路级总量 = 该路各州府之和（迁移期双向对账）；
6. **旧档幂等**：读旧档不炸、补齐后往返一致；
7. **顺序无关**：受影响测试文件在固定 seed 与随机顺序下**结果一致**。
