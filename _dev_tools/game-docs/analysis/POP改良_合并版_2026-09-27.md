## 0. 关键口径（用户定稿，勿擅改）

| 口径 | 内容 |
|---|---|
| **分类键＝职位** | POP 按**职位**划分；"士农工商"恰好就是职位，兵为军职。推论：**跨类流动＝换职位**（城市化/科举/致仕/入伍）；**类内变化＝同职位内的身份/经营结构＝子池**（身份不是分类键） |
| **一建筑多职位** | "设一个自耕农庄容纳自耕农/富农/贫农，地主的农庄容纳佃农跟地主"——建筑提供**多职位岗位槽**（同 V3 一个农场里 laborers/farmers/aristocrats 并存） |
| **吏＝衙门里的岗位** | 吏是衙门建筑的一个职位槽，**不升格为第 7 类 POP**（职位粒度变化不再牵动六类权威清单/派系/税基/面板全链） |
| **隐户：并入但不显示** | 隐户并入 POP（**加法**子池 `农.hidden`，有生产有消费、计入"总口"），但**朝廷端只给约值**，真值靠**清丈/统计**揭示 → 衍生"中央 vs 地方"博弈玩法 |
| **引入受抚养人口（贴合"户"）** | 设**丁口维度** `ding`（应役）/`kou`（受抚养），与职位划分**正交**；**赋役按丁、消费按口** |
| **户均 5 口、丁率 0.35** | 2000 万明户 × 5 = **在籍 1 亿口**；隐户 500 万户 × 5 = 2500 万口；**总口 1.26 亿** |
| **(ii) 保财政绝对量** | 人口放大而**税收绝对量不变**（人均税负 −20%，即"百姓变宽"）；人均产出/人均存量保持不变 |

## 1. 现状：POP 数据模型与结算

### 1.1 六类 POP 与全部子池

**六类权威清单** = [`content/data.py::GRAIN_CONSUME_PER_CAPITA`](../../../game/content/data.py) 的键序
（`农 / 士绅 / 工匠 / 商人 / 官僚 / 兵`），守卫测试 `test_pop_class_single_source.py`。

| POP | 通用字段 | 子池 | 恒等式 |
|---|---|---|---|
| 农 | `size` `wealth` `grain` `goods` `欠税` | **职位**：`自耕农/富农/贫农/佃农`；**丁口**：`ding/kou`；**隐户**：`hidden`（加法、不在籍） | `Σ职位 == size`、`ding+kou == size`、`hidden` **不参与** |
| 士绅 | 同上 | `窖银`、`estate`/`estate_hoard`（家产，**钱**）、`clan`（宗室） | — |
| 官僚 | 同上 | `officials`/`clerks`、`on_post`/`waiting`/`sinecure` | `size == officials+clerks`、`officials == on_post+waiting+sinecure` |
| 工匠/商人/兵 | 同上 | — | 兵 `size` 由 `army_units` 重聚合（派生量） |

- 六类与子池的**唯一写入点**：`core/officialdom.py`（官/吏）、`core/pop_structure.py`（农职位/丁口）、
  `core/settlement_imperial.py`（隐户）、`core/estate_mechanic.py`（家产）。
- `prefectures[路].officials/clerks` 只是**派生镜像**（唯一写入 `officialdom.sync_legacy_mirror`，供 Rust 与旧档读）。

### 1.2 月度结算中的 POP（步序）

> 步序**权威镜像**在 `_dev_tools/game-dev/tests/test_pop_identity.py::_STEPS`（`test_middle_calibration.py` 逐步同函数比对）；
> `core/settlement_steps.py::_STEPS` 的本地副本**已于 2026-09-27 删除**（零引用且残缺）——新增步骤请同步测试侧镜像与《游戏机制说明》§二。

1. **Step 3 经济基础**（`settlement_econ`）：人口自然增长分摊到各路农 POP → 城市化/回乡（景气驱动）
   → **就业驱动流动**（岗位缺口驱动，串行其后）→ 科举入仕 → 流民吸收。
   其后为 **Step 3.x 田亩户籍**（`_settle_land_local`）：产粮按**田亩归属**分配（自耕田→农；地主田→佃户半+士绅半；
   官田→佃户半+太仓半；皇庄→佃户半+内帑粮；**隐田→隐户 70% / 庇护士绅 30%**）。
2. **Step 10 皇帝个人**（`settlement_imperial`）：隐户**逃籍/归籍**双通道（逐路局部守恒）。
3. **Step 10.5 人口总账校正**：`population = Σ六类 size + 流民`（**不含隐户**——隐户不落籍）。
4. **Step 10.55 子池兜底**（`sync_all_farm_slices`）：任何改动 `农.size` 的通道之后，按现有比例把职位/丁口
   与 `size` 对齐（**只改子池不改 size**），并写诊断读数 `settlement_audit["farm_slice_fixes"]`
   （长期 >0 ⇒ 有通道漏挂钩）；`farm_slice_violations` 应为空。

### 1.3 钱与粮的口径

- **钱**：`core/money.py` 是**只读视图**（M0/M1/M2/M3 与 `ACCOUNTS`）；家产 `estate/estate_hoard` 已从
  `ACCOUNTS` 移除并**并入 `士绅` POP**（M_ALL 不变，属重分类）。
- **粮**：口粮按 `size × GRAIN_CONSUME_PER_CAPITA`；商品消费按 `wealth × GOODS_CONSUME_RATE`（**未按子池分层**，见 §2 D3）。
- **田亩**：`self_farm_land`/`gentry_land`/`official_land`/`imperial_land`/`hidden_land`；
  二税折色按田亩归属拆（自耕份额→农、地主份额→士绅），役钱按**应役丁**征（§4.2）。

### 1.4 守恒与断言的现状

- 生产代码的 `assert` 极少（约 2 处）→ 挂载律条⑤"配守恒断言"**主要由回归测试承担**（`test_pop_identity.py` 等）。
- `ΣPOP == population` 是**月尾硬写**（Step 10.5）而非断言 → 会掩盖"月内破裂"（已加 Step 10.55 诊断缓解）。

## 3. 设计：对照 P 社 Victoria 3

### 3.1 V3 的做法（官方 wiki 实证）

15 种职业按 strata 分层；农业四职位的参数：**Peasants**（自给农，工资系数 0.2、**消费 ×0.05**、
**不能被解雇**、无视就业比例）、**Laborers**（雇工，1.0）、**Farmers**（农场主，2.0，Middle）、
**Aristocrats**（地主，5.0，**只拿分红**）。机制骨架：建筑提供**按职业分的岗位槽** → 招聘看资质+工资
（跳槽需高 10%）→ 建筑利润 → ownership 分红。

### 3.2 本作与 V3 的关系（关键判断）

```
V3  ：职位 → 建筑岗位 → 工资/分红 → SoL(生活水平) → 需求消费 → 政治 → 流动
宋祚：身份 → 土地/岗位 → 分成/自给/俸禄 → 【生计水平】 → 消费分层 → 派系倾向 → 逃籍/流动
                                          ↑ 待补的中介变量
```

V3 是**市场链**（工资/分红驱动），宋祚是**汲取链**（税租役驱动）——**不能照搬**；
但 V3 的 **SoL 可改造为"生计水平"**（= 收入 − 必需支出：口粮+租+税+役，按子池计算），
把"税负分层 → 消费分层 → 流动 → 派系倾向"串成一条因果链。

### 3.3 五层架构

```
L1 人口账   六类职位 ＋ 子池（职位/丁口/身份/户籍）      Σ职位==size、ding+kou==size；隐户加法子池
L2 建筑-岗位 建筑 → {职位: 每级岗位数}                    一个建筑横跨多个 POP 类   ← 已落地(B0)
L3 收入     分成/自给/地租/俸禄/军饷/工钱                按"职位+子池"定价
L4 生计水平 生计 = 收入 − 必需支出（口粮+租+税+役）        ★新增中介变量（SoL 的宋代对应物）
L5 流动     换职位=跨类；换身份=子池；驱动=岗位缺口+生计差+识字门槛
```

### 3.4 建筑-多职位岗位槽（已落地，B0）

| 建筑 | 职位槽（每级岗位） | 由哪个 POP 类填 |
|---|---|---|
| 农田 | `{}` | 生计轨，不占岗（粮维豁免） |
| **自耕农庄** | 自耕农 120 / 富农 20 / 贫农 20 | 全部**农**（同池按序填） |
| **地主农庄** | 佃农 100 / 地主 20 | 佃农→**农**、地主→**士绅**（**跨 POP 类**） |
| 工坊 / 商铺 | 工匠 160 / 商人 40 | 工匠 / 商人 |
| 庄园 | 同地主农庄 | **旧档别名**（零迁移） |

兼容设计：`JOBS_PER_LEVEL` 仍是**扁平总量**（=Σ职位）、`BUILDING_WORKER` 仍是**主类** →
外邦扁平表与既有长局基线**零漂移**；多职位明细走新增 `BUILDING_POSITIONS` + `POSITION_CLASS`。

### 3.5 V3 采纳 / 改造 / 拒绝

| V3 机制 | 本作处置 |
|---|---|
| 职位＝分类键、建筑多岗位槽 | ✅ 采纳 |
| Peasants 消费 ×0.05 / 不能失业 / 无视比例 | ✅ 采纳并改造（用于隐户/贫农的消费标定与生计兜底语义） |
| 工资系数分层 | 🟡 改造为"同建筑内收入级差"（不做农业工资化） |
| **SoL / needs 满足度** | ✅ 改造为 **L4 生计水平**（子池级只读派生，不落存量） |
| qualifications 门槛 | 🟡 用既有 `literacy` + 科举资格 |
| ownership 分红 | 🟡 改造为"地主＝地主农庄的 owner 岗收租"（**不建分红账本**） |
| 文化/宗教 POP、跨国移民、奴隶、全 V3 农业（农领工资） | ❌ 不采纳 |

| 项 | 值 / 做法 |
|---|---|
| 户均口数 | **5**（`PERSONS_PER_HOUSEHOLD`，户→口的唯一权威） |

## 6. 后续

### 6.1 B1d-b 剩余通道（且已查明"为何不照做"）

| 通道 | 结论 |
|---|---|
| 征兵/裁兵（`settlement_common._levy_men/_return_men`） | **不照做**：兵 POP `size` 是**派生量**（由 `army_units` 重聚合），在此 move 会与重聚合打架 → 需专门设计（"随军财富"挂兵 POP 的独立子池，由重聚合同步） |

## 7. 纪律与坑（改 POP 前必读）
