# 《宋祚》POP 改良纲领（2026-09-27 定稿方向）

> **一句话口径（用户 2026-09-27）**：本游的 POP **按职位划分**；"士农工商"恰好就是职位，
> 兵为军职。因此 **分类键 = 职位（occupation）**，身份/土地关系等**不是分类键**，而是职位内的**子池**。
>
> 本纲领把用户给出的四项改良（税负分层／消费分层／就业流动改"岗位容量驱动"／身份跟职位走）
> 收敛成一条主线，并给出批次、落点与验收标准。**未定项以 🟡 标注**，不得当成已定口径实现。

---

## 一、四条规则（由"按职位划分"直接推出）

| # | 规则 | 现存符合度 |
|---|---|---|
| R1 | **跨类流动 = 换职位**（城市化 农→工匠/商人、科举 士绅→官僚、致仕 官僚→士绅、入伍/退役） | ✅ 既有通道本就是换职位 |
| R2 | **类内变化 = 同一职位内的身份/经营结构 = 子池**（官僚 `officials/clerks/on_post/waiting/sinecure`、士绅 `clan/estate`） | ✅ 官僚/士绅已有；**农缺**（本次要补） |
| R3 | **子池只影响收入/税负/消费/政治倾向，不改变职位归属** | 🟡 部分（收入已分层，税负/消费/倾向未分层） |
| R4 | **不新增人口账**：子池 ⊆ 该 POP（人口类子池 Σ == `size`；不在籍者如隐户另立**加法**子池并显式标注） | ✅ `农.hidden` 已是加法子池（见 §五 待决） |

**推论**：六类仍是**职位大类**（= V3 职业谱的粗粒度整合），细粒度一律下沉到子池。
"新增第 7 类"只在**确实是新职位**时才成立（当前唯一候选是**吏**，见 §五）。

## 二、与 V3（P 社 Victoria 3）的对齐关系

V3 是**细粒度职位谱**（15 职 + 失业），本作是它的粗粒度整合：

| V3 职位（wiki 事实） | 本作归入 |
|---|---|
| Peasants（自给农，工资系数 0.2、消费 ×0.05、不能失业）／Laborers（雇工）／Farmers（农场主，Middle） | **农** |
| Aristocrats（地主，纯分红）／Academics／Clergymen | **士绅** |
| Bureaucrats／**Clerks（吏）** | **官僚**（吏为子池，见 §五） |
| Capitalists／Shopkeepers | **商人** |
| Machinists／Engineers | **工匠** |
| Officers／Servicemen | **兵** |

**关键结论**：V3 用**两个职位**（Peasants vs Laborers）表达的东西，本作压进了**一个"农"职位** →
必须用**子池**表达。V3 的 Farmers（经营农）同理只能作 `农` 子池，不能新开类。

**边界（不采纳）**：农业工资化（V3 的 Laborers 领工资）——本作"半 V3"，农不领工资；
奴隶；其余 38 政权的产业链。

## 三、五个改良维度（用户四项 ＋ 1 项延伸）

### D1 身份跟职位走（结构层，前置）
- 目标：`农` 增子池 `自耕农 / 佃农`（＋隐户见 §五），Σ == `size`；补上"农"这一处与官僚/士绅的结构不对称。
- 落点：`game_state._build_pops`（初值）、`data_constants`（比例参数）、存档迁移（旧档按土地结构折算）、面板读数。
- 验收：`自耕农 + 佃农 (+ 隐户?) == 农.size`（逐路）；跨类流动后子池按比例带走（同科举 `_blend_faction_inflow` 的成熟做法）。

### D2 税负分层（用户第 1 项）
- 目标（文档 §3.7 用户修正）：
  - **自耕农**：有**国税＋摊派**（田赋正税＋徭役/科配），无地租；
  - **佃农**：**无国税、无摊派**，负担体现为**地租**（主佃对半分成的田主所得，田主代纳土地税）；
  - **隐户**：两无（不纳不应役）。
- 落点：`settlement_finance._settle_finance` —— 役钱税基由 `Σ农.size` 改为 **`自耕农` 子池**；
  二税折色"自耕份额→自耕农、地主份额→士绅"（已有）＋新增"田主代纳土地税"记账；
  `settlement_econ` 的粜粮完税只作用于自耕农/佃农（按其所得粮）。
- **修掉的真实偏差**：现役钱税基含佃农（`_farm_pop = Σ农.size`，`settlement_finance.py:521`），
  与代码注释/文档"乡村民户（主户）"不符。
- 验收：`役钱 == 自耕农口径`；佃农子池的国税 == 0；地租 Σ 与士绅入账 Σ 恒等（零残差）。

### D3 消费分层（用户第 2 项）
- 目标：收入分层 → **消费结构分层**（自耕农买布、佃农少量、隐户近零）。
  V3 给了现成标定：Peasants 消费 ×0.05。
- 落点：`settlement_granary` 商品/口粮消费段、`GOODS_CONSUME_RATE` 按子池加权；
  口粮不分层（吃粮是生存需求，仍按 size）。
- 验收：Σ消费 == 各子池加权和；商品不断供；隐藏户消费 ≈ 0 但**吃粮照算**（生存）。

### D4 就业流动改"岗位容量驱动"（用户第 3 项）
- 目标：废弃"固定 2%/月无条件回流农轨"（宋侧已默认关闭，见 §六 现状），改为
  **V3 式驱动**：迁移量由**岗位缺口/容量**决定，而非固定比率。
- 落点：`building_jobs.apply_employment_flow`（空岗拉已符合；回流侧待改）、`SONG_JOB_*` 标定。
- 🟡 **待拍板**：见 §五 待决 2（粮维豁免岗位制下"农岗容量"如何定义）。
- 验收：新局零迁移不变；迁移量 ≤ 真实缺口；Σ六类 size 守恒；长局非农不塌陷。

### D5 政治倾向挂子池（延伸，本轮新增建议）
- 理由：D2 的直接后果是**税痛感差异**（自耕农最直接、佃农隐于租中、隐户无税痛），
  这天然是**政治态度**的分野——宋史里形势户/客户对变法立场不同。
- 目标：派系基本盘/心气按**子池**加权（现在按整类）。
- 落点：`faction_basis`（子集读数）、`faction_metrics`。
- 验收：派系基本盘 Σ == 母类子池和；子池立场差可被 AI 读出（只给档位词）。
- 状态：**建议项**，待用户确认是否纳入。

## 五、🟡 待拍板（阻塞相应批次，勿擅自实现）

### 待决 1：隐户"在籍"关系（阻塞 B1 的恒等式形式）
- 现状（2026-09-27 方案 A 已落地）：隐户是 `农.hidden` **加法**子池（**不计入** `农.size`，
  也**不计入** `state.population` 在籍口径）；`Σ农.size + Σhidden = 总口 1 亿`。
- 文档 §3.7 的原话是 `自耕农 + 佃农 + 隐户 == size`（隐户**在** size 内）。
- **二者冲突**，必须二选一：
  - **选项 1（推荐，与已落地实现一致）**：隐户**不在籍** → 恒等式为 `自耕农 + 佃农 == size`，
    隐户单列加法子池 `hidden`；`population`（在籍）不含隐户；役钱/国税只对在籍两层征。
    → 需修订文档 §3.7 的恒等式表述（1 行）。
  - **选项 2（严格按 §3.7 字面）**：隐户计入 `农.size` → 恒等式 `自耕农+佃农+隐户 == size`；
    但 `population` 会含隐户（破坏"不落籍"语义与"总口=在籍8000万+隐2000万"锚），
    且役钱/二税/需求侧都要显式排除隐户子池 → 改动面大、易漏。
- **建议**：选项 1。

### 待决 2："岗位容量"在粮维豁免岗位制下如何定义（阻塞 B3）
- 现状：`SONG_JOBS_PER_LEVEL = {农田: 0, 工坊: 160, 商铺: 40, 庄园: 120}` ——
  **农田 0 岗**（粮维豁免岗位制 = 全部农都算生计在岗）→ 农**没有岗位缺口**，
  于是"容量门"恒开，回流退化为无条件（这正是 60 月非农 −70% 的成因）。
- 三个可选口径：
  - **① 名义农岗容量**：给农田/庄园一个名义容量（如 `农田: 农人口 × 1.0`），
    回流只在"非农超出非农岗容量"时发生 → 最接近 V3 的 hiring 语义；
  - **② 仅"超出空缺"部分回流**：`max(0, idle − open)`（在宋侧量级下仍会大幅回流，**不推荐**）；
  - **③ 明确不做回流**（保持现状关闭）：`SONG_JOB_PUSH_UNEMPLOYED = False`，
    把"生计兜底"留给隐户/流民通道 → 保守但少一层真实压力。
- **建议**：①（需一并给出"非农岗容量"标定，否则 40 万工匠 vs 320 岗仍失衡）。
- ⚠️ 前置事实：宋侧目前**无任何写入** `工坊/商铺/庄园` 的玩家路径（`_settle_projects` 只写政府工程名），
  故 B3 无论选哪个口径，**当前都不会触发**；B3 的价值是为 S3–S5 建筑链路铺好正确语义。

### 待决 3：吏是否升格为第 7 类（阻塞 B5）
- 按"分类键=职位"，**吏是独立职位**（宋代吏为役职/招募办事人员，非官），支持独立成类；
- 现为 `官僚.clerks` 子池（文档 §十八 表 A 曾讨论，结论"最史实但极谨慎"）；
- 代价：动 `GRAIN_CONSUME_PER_CAPITA`（六类权威清单）、`POP_SENTIMENT_CHANNELS`、派系基本盘、
  役钱/免役口径、消费表、存档迁移、前端面板、`drain_pop_wealth`/`_money_pools`，以及
  `test_pop_class_single_source` 守卫。
- **建议**：**暂缓**（先做完 B1–B4；升格单独作为一批，配全链测试）。
