# 立绘机制现状审查与优化设计方案

## 一、现行机制审查

现行立绘采用分层合成：人物头部层 + 姿态服色身体层，输出组合立绘。现有约 42 张头部、24 张身体（4 姿态乘 6 服色），规格 810×1080、3:4、统一绢底。

生成脚本负责身体、姿态偏移、净头和抠图；大臣数据模块负责合成缓存；readouts 返回 URL；群臣和召对面板加载。缺图时回退个人原图或文武默认图。现有基础应保留，升级为运行状态驱动的统一立绘服务。

### 现行优点

1. 头部与官服分离，具备升贬换服基础。
2. 公共身体复用，人物保留专属面孔。
3. 已有尺寸、构图、偏移和抠图规范。
4. 后端缓存，缺图有回退。

### 现行问题

1. 官服主要读取静态人物 rank，升迁、贬谪、罢官、致仕后可能仍穿开局服色。
2. 姿态由派系、年龄、姓名哈希固定，不能表达召对、进谏、军议和请罪。
3. 请求期间写 frontend/public，打包后可能只读，并发生成可能争用。
4. 前端分别拼 URL 和判断回退，缺统一组件。
5. 缓存只含姓名、服色、姿态并依赖时间戳，缺内容版本。
6. 缺少表情、年龄、伤病、服丧、出征和待罪状态。

## 二、目标架构

人物稳定 ID、运行态身份、场景、公开状态先进入 PortraitResolver 纯函数，产出 PortraitSpec；Renderer 或构建期预生成器生成版本化资源；前端统一 MinisterPortrait 组件展示。Resolver 决定穿着和姿态，Renderer 只合成，前端只展示。

## 三、人物 ID 与清单

新增稳定 character_id，如 cai_jing、tong_guan。姓名仅作显示字段，旧存档通过 alias 迁移。新增 portrait_manifest.json，记录 schema/renderer 版本、头部文件、内容哈希、焦点、年龄/表情变体和身体层版本。构建时校验，运行时不扫描全目录。

## 四、分层设计

M0 保留 background、body、head。M2 增加有限 expression（neutral、pleased、stern、worried、ill）、accessory（鱼袋、笏板、冠饰、军职、服丧）和 condition（伤病、风尘、待罪）。人物专属部分留在头部/表情，公共状态复用身体/附件，禁止每人乘服色乘姿态乘表情的组合爆炸。

## 五、服饰、姿态与表情

服饰优先级：特殊剧情状态、宗室爵位、当前运行态官品、是否在任、静态档案回退。zi/fei/lv/qing 按运行态品级；shi 用于在野、罢官、致仕；qinwang 只用于亲王；后续可增加 mourning、military、custody。服饰只表达公开身份，不直接改属性。

场景优先姿态：朝会正立/持笏，召对拱手，奏事持笏，进谏拱手或进谏姿态，请罪低首，军议持笏/军议，致仕拢袖并穿士人服，病中拢袖加 ill。无场景时读取显式 default_pose，取消姓名哈希。

表情不能泄露隐藏忠诚和贪腐。只依据已观察互动：受赏/获准用 pleased，争论/弹劾/军情用 stern，灾情/败报/公开问责用 worried，公开伤病用 ill，其余 neutral。

## 六、解析契约

新增纯函数 resolve_portrait(character_id, public_profile, current_office, scene, visible_condition)，返回 tier、pose、expression、costume、age_stage、asset_key、fallback。相同输入得到相同结果，Resolver 不读写文件。

## 七、渲染、缓存与前端

构建期预生成默认组合、名录缩略图和开局常用图；低频组合写 userData/portrait-cache/{asset_hash}.webp，通过受控路由提供，禁止写源码、frontend/public 或安装目录。母版保留 PNG 810×1080，运行资源输出 WebP 大图、270×360 卡片、144×192 头像。相同 key 并发去重，临时文件校验后原子替换。

建立唯一 MinisterPortrait 组件，统一固定比例、缩略图、焦点、loading、onError、预加载、交叉淡入和 alt。群臣、召对、官署、事件不得自行拼 URL。

## 八、回退与质量门禁

回退链：目标组合→同人物neutral→同人物默认姿态→个人完整原图→年龄/身份/文武默认图→通用剪影。API返回fallback_level供开发诊断。

继续沿用810×1080、统一绢底、头顶肩线、偏移不超过±30px规范。新增manifest完整性、尺寸/模式/alpha/头部质心/留白校验；在黑白洋红三底检查ghost；生成全tier/pose联系表人工检查帽翅、衣领和肤色；核验年龄、胡须、冠服和身份。AI生图只用于开发期，游戏运行时不调用外部服务。

## 九、实施路线

M0：引入人物ID和manifest；Resolver接入运行态官职；停止请求写public；统一前端组件；复用现有42头部和24身体。
M1：预生成默认图和缩略图；缓存迁至userData；内容哈希、原子写、并发去重；API返回PortraitSpec。
M2：召对、进谏、军议、请罪、致仕接入场景姿态；增加有限表情和公开伤病；前端无位移切换。
M3：增加服丧、军议、待罪等少量公共身体层；仅为跨越显著年龄阶段的核心人物制作年龄变体。

## 十、测试与完成定义

必须测试升官、贬官、罢官、复职、致仕换服；亲王与普通宗室区分；相同输入产生相同spec/key；场景结束恢复；隐藏数值不经表情泄露；缺图损坏图正确回退；并发缓存不破损；安装目录只读可运行；旧存档迁移；所有面板统一组件；列表使用缩略图；桌面和移动布局不遮挡。

完成标准：官服真实跟随运行态身份；姿态和表情只反映公开场景；现有分层资产全部复用；运行时不写安装目录；缓存版本化、原子且并发安全；所有面板统一；新增人物只需补manifest和合格素材，无需修改业务代码。
