# 宋解耦与底层地基 · 落地计划（2026-10-21）

> 范围：**只做宋**，先把宋解耦成"内核 + 宋内容包 + 声明式 MOD 接口"；
> **不做其他朝代**、不开放任意 Python MOD、不改结算顺序/经济公式/账本结构。
> 依据：[`底层基础架构v1与宋解耦改造清单`](底层基础架构v1与宋解耦改造清单_2026-10-21.md)；
> 目标结构：P0 地基（零行为）→ P1 宋接口 → P2 宋内容包 → P3 机制段（需数据/授权）。

---

## 0. 总目标与判定

**总目标**：把"宋"从 `core/` 的默认假设里解耦出来，形成：
1. 一个**中性内核**（只认实体/约束/接口，不认朝代名）；
2. 一个**宋内容包**（`content/packs/song_1101/`，含史料/推定/设定/未知标注）；
3. 一个**声明式 MOD 接口**（创意工坊可加内容，不改内核代码）。

**完成判定（M3）**：
- 新局可由 `new_game(pack_id="song_1101")` 只靠 pack 元数据+适配层复现，结果与当前逐字段一致；
- `core/` 新增代码不出现朝代字面量（守卫棘轮只降不升）；
- 存档带 `pack_id/pack_version`，旧档可读，未知 pack 不静默；
- 一个示例 mod 能加载/校验/跑 1 月，非法 mod 被拒；
- 全量 pytest 绿（基线以 `_dev_tools/game-docs/README.md` 为准；本计划开工前实测 **4232 / 0 / 0 / 3**）。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 大爆炸重命名 | **adapter + 守卫 + 逐片迁移**，不做全库改名 |
| 过度抽象 | 只抽象共同点（实体/关系/守恒），名称/层级/参数留 pack |
| 隐藏行为变化 | P0 每步加"同种子快照一致"用例；全量回归 |
| 存档破坏 | pack 字段可选；旧档默认宋；未知 pack 拒绝而非猜测 |
| MOD 越权 | v1 只开放声明式数据；Python 插件后置且需沙箱/审批 |
| 数据假精度 | `provenance/Unknown/Range` 强制标注；缺数据不填 0 |
| AI 写崩经济 | AI 只提案/叙事；schema+约束+审批；不直接写 state |
| 文档漂移 | 每步更新 `game-docs/` 与 handover；新文件进 README 索引 |
