### 2.6 天道/Jev 必须"长在骨头里"的五条

不是再加一个"AI 功能"，而是让它成为**机制做判断时的默认路径**：

1. **决策层是内核服务，不是旁路**
   所有存在"多方案/是非/评分"的机制，都发 `DecisionRequest`（objective、facts、options、constraints、seed、turn），
   由 `DecisionService` 调用天道引擎，返回 `DecisionResult`；机制只做**档位→数值**的映射。
2. **objective 是注册表，不靠中文子串分派**
   `objective` 必须显式登记（gate/choose/score/dice、选项、fact schema、阈值/权重）；宋的权重/选项放
   `packs/song_1101/decisions.json`；**禁止**再用 `condition` 文案/键名隐式猜分支。
3. **每次决策必须留痕，可回放**
   `state.decision_log`（有界）记录：turn、objective、facts hash、verdict、probability、defined、provider、seed、reason；
   玩家/AI 能看到"为什么这么判"，重放同一 seed+输入得到同一结果。
4. **双层：本地天道负责结算，外部 Jev 只做结算前/离线复核**
   结算期**只读**本地确定性引擎；LLM/Jev 外部调用只能在结算前、UI、离线批处理；**禁止同步 HTTP 进结算**。
5. **AI 只提议，Jev 只判断，程序只执行**
   LLM 生成方案/叙事/选项 → Jev/天道判断可行/有据 → 程序按注册表换算数值并过约束 → 写入账本；
   AI 永不直接写 state；Jev 也永不直接写数值。

> 这就是"骨子里"：**机制在不确定处默认问天道；天道只给判断；判断被记录；数值由程序算；内容包决定权重。**

### 2.8 战斗怎么模拟：程序算物理，天道判意志，LLM 只写战报

**明确回答：不能是 LLM 黑箱。** 当前也不是黑箱——是"线性战力比 + 随机触发"的简化模型：

| 现状（已核实） | 问题 |
|---|---|
| `army_models._resolve_battle(defender_power, attacker_power)`：守方胜率=守/(守+攻)，败方伤亡 20%~50%、胜方 5%~12.5% | 单一线性公式；无地形/天气/补给/指挥/训练/情报/士气阶段 |
| `settlement_front._settle_front_battle`：`invasion_will>=90 and year>=1122` 且 `random.random()<0.08` 触发；硬编码河北/河东/陕西 | 触发写死；无战役层选择；随机无 seed 记录 |
| LLM 不参与战斗数值 | 对的，必须保持 |

**目标：战役层 + 战斗层，全部程序化、可回放；天道只做"意志/选择"判断；LLM 只叙事。**

```text
战役层（月/旬）：
  目标（守/攻/牵制/撤退）→ 路线/集结/补给/情报/天气/政治约束
战斗层（阶段化，非即时）：
  接敌 → 部署 → 交锋（多轮）→ 士气/决心判定 → 追击/撤退/攻城/受降
每轮：
  effective_power = 兵力 × 训练 × 装备 × 士气 × 指挥 × 地形 × 补给 × 情报/奇袭
  损耗 =  attrition(effective_power, 对方, 地形, 兵种)
  士气/决心/是否追击 = TianDao.gate/score（只出档位，不出伤亡数）
  指挥选择（战/守/退/伏/攻城）= TianDao.choose（在可行选项内）
  随机扰动 = TianDao.dice(seed=turn+battle_id)（确定性、可回放）
战后：
  伤亡/溃散/俘虏/缴获/城防/声望/问责；战报由 LLM 执笔，数字来自结算
```

**不变量**：兵↔POP 守恒（逃兵/俘虏回流）、军费/军粮从既有账户、兵权/调兵权限、路线/地形可达、无瞬移、无凭空补充。

**天道/Jev 优化路线（让它更"骨头"）**：
1. **事实层加强**：士气/补给/训练/地形/情报/将领/派系/民心进入 `facts`，缺失标 `unknown`（不冒充 0/1）；
2. **objective 细化**：开战/守城/追击/撤退/受降/屠城/犒军等各自 options+criteria，不再一个通用 gate；
3. **权重校准**：用历史战例做离线回测，调权重；不做游戏内在线学习；
4. **结果可解释**：每次决策记录 `objective/facts hash/verdict/probability/defined/seed`，战报可下钻"为什么判定士气崩"；
5. **双层**：本地天道负责逐轮判定；外部 Jev/LLM 只在结算前/离线做语义复核与叙事，禁同步 HTTP；
6. **反黑箱**：战斗数值永远由程序公式算；LLM 不参与胜负/伤亡；Jev 不写数值。

**任务**：P1-11（战斗模型 v1，确定性多轮）、P1-13（Jev 事实/目标/回测）、P2-8（战报/复盘/下钻）、P2-9（军事/地图 pack）。

### 2.9 权威/权限：官制的真正地基（能否内生权限？）

**现状（已核实）**：
- `core/permission_model.py`：**权限挂在职位上**；任职=有该职位事权；免职/空缺=失去；
  同一人兼多职=权限并集；**没有"特旨授予/委任/收回"独立层**，任命/免职是唯一途径；
- `core/authority_gate.py`：只做 executor→actor 解析 + 职位事权判定，只读、fail-closed；
- `core/decree_confirm.py` 等用 `check_matter_authority`；`minister_agent` 有 `authority=0.5` 这类运行态；
- 结论：**现在是"设定式权限"**（职位→事权映射表 + 任命），不是"内生权限"。

#### 权限从哪来：三类来源，缺一不可

| 来源 | 内容 | 例子 |
|---|---|---|
| **法理（de jure）** | 职位、任命、诏令、程序、紧急授权、惯例 | 宰相有度支调度；御史有监察；特旨授权；战时便宜行事 |
| **实际控制（de facto）** | 资源、武力、信息、关系、派系、执行网络 | 掌兵、控库、掌密报、门生故吏、地方听命 |
| **合法性/认同** | 皇权、民心、士绅、军队、官僚的承认 | 得位正、有民心、军队拥戴；否则是僭越 |

**有效权限 = 法理 ∩ 实际控制 ∩ 认同/服从**。
- 有法理无控制 → 令不出门（被拖延/阳奉阴违）；
- 有控制无法理 → 可做事但风险/反噬（僭越、被讨伐）；
- 有法理有控制无认同 → 执行成本高、易反叛。

#### 能产生哪些权限（动作分类）

| 类 | 动作 | 备注 |
|---|---|---|
| 财政 | 征税、调拨、支出、铸币、蠲免 | 与钱粮账户/预算约束绑定 |
| 军事 | 募兵、调兵、开战、守和、赏罚、军需 | 与兵↔POP、军费、兵权绑定 |
| 人事 | 任命、罢免、升迁、考课、荐举 | 与职位/名额/派系绑定 |
| 司法/监察 | 立案、查抄、逮捕、审判、平反 | 与案卷/证据/程序绑定 |
| 信息 | 阅读密奏、发密旨、控制邸报、封锁消息 | 信息不对称是权力来源 |
| 程序 | 会签、封驳、批准、否决、复议 | 程序位本身产生权力 |
| 外交 | 使节、和议、岁币、榷场、宣战 | 与外部政权/合法性绑定 |
| 紧急 | 便宜行事、戒严、征发、先斩后奏 | 必须有日落条款/事后追认 |

#### 怎么"内生"：授权是状态，不是静态表

```text
AuthorityGrant = {
  id, bearer, source(kind, ref), scope(action/matter/domain),
  limits(资源/地域/期限/程序), valid_from/to,
  revocable, legitimacy, procedure, status
}
```

内生机制（都可程序化、可审计）：
1. **职位派生**：office → matter keys（现有）；
2. **任命/差遣**：皇帝/上级授予，产生新 grant（可撤）；
3. **委任/转授权**：上级把子集授给下属（有期限/范围/程序）；
4. **紧急授权**：灾/战触发，带 sunset 与事后追认；
5. **惯例/先例**：重复行使 → 变成"预期权限"，提升合法性/降低阻力；
6. **实际控制**：掌兵/掌库/掌信息 → 获得 de facto 权限（不自动合法）；
7. **派系/联盟**：集体承认/抵制，改变服从概率；
8. **继承/剥夺**：职位更替、查抄、贬谪 → grant 转移/失效。

**生命周期**：创建 → 行使（记录）→ 扩展/收窄 → 暂停/撤销 → 失效/继承 → 成为惯例或反噬。

#### 与天道/Jev 的分工（关键）

- **法理判定 = 程序规则**（grant 是否存在、范围、期限）——Jev 不判"法律上有没有权"；
- **服从/执行 = 天道判断**：官员是否照办、拖延、阳奉阴违、告发、反叛；
  Jev 输入：忠诚/派系/利害/风险/合法性/信息；输出：档位（执行/拖延/拒绝/反噬）；
- **实际后果 = 程序 + 约束**：拒绝则政令不落地；反噬则弹劾/兵变/民变；僭越则合法性下降。

这样"权限内生"不是让 AI 随便发权限，而是：**制度产生法理、实力产生事实、认同决定执行；三者由状态和决策共同演化。**

#### 落地方式

- 保留现有 `permission_model` 职位映射作为 **grant 来源之一**；
- 新增 `kernel/authority.py`：`AuthorityGrant`、`resolve_authority(actor, action, context)` 返回
  `{legal, practical, compliance, effective, reasons}`；
- `check_matter_authority` 改为"查 grant + 返回原因"，不破坏旧调用；
- 任命/诏令/紧急状态写入 grant 事件；惯例由使用记录累积；
- 官员行为（服从/拖延/反噬）走 `DecisionService`；
- 内容包定义 office→matter、grant 类型、程序、合法性规则；MOD 只能声明式加，不得注入代码。

**任务**：P0-12（权限现状审计）、P1-14（AuthorityGrant 模型）、P1-15（内生生命周期+服从判定）、P2-10（权限 pack/UI 下钻）。

### 2.10 改革与新权限：怎么模拟"权限产生了，但没被重视"

玩家改革一定会**创造新机构/新职位/新权限**（市易司、提举常平、提举市舶、军器监……）。
关键不是"法令写没写"，而是**权限从纸面到生效要过三关**：

```text
法理关：改革诏令 → 新机构/新职位/新 AuthorityGrant（有没有权）
组织关：编制/预算/人选/信息渠道（有没有能力）
激励关：官员/派系/地方愿不愿用、用了对谁有利（有没有动机）
```

**有效权限 = 法理 ∩ 组织能力 ∩ 激励/服从**。三关缺一，权限就"存在但空转"。

#### 制度生命周期（内生）

`提出 → 授权(法理) → 设官/给钱(组织) → 启用(首次使用) → 常规化(惯例/能力) → 扩张/被捕获 → 衰退/撤销/名存实亡`

每个机构是一个**有状态对象**，不是布尔值：

```text
Institution = {
  id, name, kind, created_by(诏令/改革), legal_grants[],
  budget, staff, capacity, info_channels,
  utilization(近 N 月使用/机会), legitimacy, capture(被谁控制),
  overhead, corruption_rent, last_used, status
}
```

#### "权限未被重视"会怎样（必须能模拟的后果）

| 现象 | 机制 | 可观察读数 |
|---|---|---|
| **空转耗钱** | 机构设了就有俸禄/办公费/维护费 | `overhead` 持续支出、`utilization` 低 |
| **被用于寻租** | 有权限但无监督/无使用目标 ⇒ 官吏借权勒索/截留 | `corruption_rent` 上升、民怨/商怨 |
| **被派系捕获** | 谁任命/谁给钱 ⇒ 机构服务谁 | `capture` 指向派系；政策效果偏向该派系 |
| **名存实亡** | 有法理、无能力/无激励 ⇒ 政令不落地 | `implementation_gap`；玩家看到"已设官"但无效果 |
| **惯性/难撤销** | 设官容易撤官难；既得利益阻挠 | 撤销成本、合法性/派系反弹 |
| **改革反噬** | 新权限与旧权力冲突 ⇒ 弹劾/消极执行/地方抵制 | 服从档位下降、事件触发 |

**这就是"权限产生但未被重视"的正确模拟**：不是"没效果"三个字，而是**继续花钱、继续被用歪、继续改变激励**。

#### 玩家可以怎么"重视"它

- 给钱/给人/给信息渠道（组织关）；
- 任命合适的人、设考课/监察（激励关）；
- 亲自下诏使用/定目标（启用）；
- 不重视 ⇒ 上述空转/寻租/捕获/名存实亡自然发生；
- 想撤销 ⇒ 付政治成本，可能留下"机构遗产"。

#### 与天道/Jev 的分工

- **法理/组织**：程序规则（grant、预算、编制）——Jev 不判"有没有权"；
- **用不用/怎么用/是否捕获**：天道判断（官员服从、拖延、寻租、告发、反噬），输入忠诚/派系/利害/风险/信息；
- **后果**：程序结算（钱、粮、民心、合法性、事件）。

#### 任务

P0-13（改革/制度现状审计，只读）、P1-16（Institution 模型+生命周期）、P1-17（改革→grant/机构流水线）、P2-11（空转/寻租/捕获后果+读数/UI）。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 大爆炸重命名 | **adapter + 守卫 + 逐片迁移**，不做全库改名 |
| 过度抽象 | 只抽象共同点（实体/关系/守恒），名称/层级/参数留 pack |
| 隐藏行为变化 | P0 每步加"同种子快照一致"用例；全量回归 |
| 存档破坏 | pack 字段可选；旧档默认宋；未知 pack 拒绝而非猜测 |
| MOD 越权 | v1 只开放声明式数据；Python 插件后置且需沙箱/审批 |
| 数据假精度 | `provenance/Unknown/Range` 强制标注；缺数据不填 0 |
| AI 写崩经济 | AI 只提案/叙事；schema+约束+审批；不直接写 state |
| 文档漂移 | 每步更新 `game-docs/` 与 handover；新文件进 README 索引 |
