## 0. 三条硬约束（先立规矩，再谈板块）

| 约束 | 依据 | 对面板的含义 |
|---|---|---|
| **只读派生、算法单点** | `core/region_brief.py` 文件头纪律 ①②③；`/api/readouts::regions` 已消费它 | 面板**只展示**，所有比率/合计/风险**必须出在 `region_brief`**（或其同级派生模块），前端**不得复制算法**（`PrefecturePanel.tsx` 已按此写） |

## 1. 触发与层级（先解决"点谁弹谁"）

本作舆图三层可点（`mapController.pickFeatureAtPoint` 已有优先级：城市 > 路 > 政权）：

| 点击对象 | 现状 | 建议 |
|---|---|---|
| **路**（`circuits`，如两浙路） | `MapView.selectFeature` → `pushOverlay({kind:"detail"})` → `DetailPanel` → 推 `prefecture` | **主入口**：改为直接开「**地方档案（路）**」新面板 —— 即参考图的省级界面 |
| **府/州治所点**（`cities`） | 同上，落到 `PrefecturePanel` | **二级**：路面板内点某府 → 展开府级页（数据用 `content/demography.py` 的州/府派生） |
| **政权**（`regimes`，辽/夏/大理） | 走 `external_view.py` | 复用同一面板骨架，数据源换 `external_view`（外邦省域已有 `provinces[*].pops`） |

> 现状 `PrefecturePanel.tsx`（377 行）已有「列表/单路详情/田亩户籍总览」三视图 + `RegionBriefResult` 类型 +
> 风险徽章 + `Bar` 进度条 + 后端不可用时回落 `state.prefectures`。**本方案是把它扩成"地方档案"多页签，而非推倒重来。**

## 3. 面板骨架（建议）

```
地方档案 · {路名}（{首府}）                        [沿革] [×]
├─ 顶部：舆图缩略（该路多边形高亮）＋ 关键徽章（民心/动乱/风险）
├─ 四格摘要：人口 | 民心 | 动乱 | 月税实收          ← region_brief 已有字段
├─ 左栏「查阅」页签：概览 / 人物 / 民情 / 施政 / 军政 / 营建 / 财赋
└─ 右栏内容区（按页签）：
     概览    = 区域概述 + 地方底册（表）+ 在地阶级（7 卡）      ← #1#2#3
     民情    = 六类 POP 子池明细（农的职位/丁口/隐户、士绅 clan/estate）
     军政    = 城防/驻军表 + 施令按钮组                        ← #4
     营建    = 建筑清单（月耗/效果/岗位）                       ← #5
     财赋    = 田亩分类 + 逐项税收 + 实收效率                    ← #6
     施政    = 近事时间线 + 四按钮                              ← #7#9
```

**渲染约定**（沿用现有）：`PanelKind` 注册进 `OverlayStack`；订阅走 `useGameStore`；进度条用既有 `Bar`
（`PrefecturePanel.tsx:25`）；风险徽章用 `RISK_BADGE`；后端不可用时**回落 `state.prefectures` 但绝不假造派生值**。

## 4. 分期

- **P0（最小可用，纯复用）—— 已核实`region_brief` 现有输出即可支撑**：把现有 `PrefecturePanel` 的单路详情扩为
  「概览 + 在地阶级 7 类 + 军政（城防/民心/动乱/驻军表）」，数据全部来自
  `region_brief` 已输出字段（`population / mood / public_support / **unrest** / **city_defense** / literacy /
  grain_year / grain_stock / grain_months / tax_month / tax_share / army_cash_month / army_grain_month /
  risk_score / risk_label / risk_hints`）与 `p["pops"]`（含 `农` 的职位/丁口/隐户子池）；
  四按钮先只做**跳转**（打开既有面板），不新增写通道。**后端零改动**。
- **P1（派生补齐）**：`region_brief` 扩 `route_briefing / route_buildings / route_tax_items / route_gentry_corruption`；
  地图点击「路」直接开本面板；府级页接 `demography`。
- **P2（文案与体验）**：新增 `content/region_flavor.py`（按路×阶级的诉求/状况文案）、近事按路过滤、
  面板内联动（点阶级→筛选近事）。

## 5. 需你确认的三点

1. **粒度**：面板一级=**路**（复用 `region_brief`，改动小）还是直接做**府/州**级（要先把 `demography` 提升为面板主源）？参考图是"省+首府"合体，本作路≈省。
2. **真值 vs 档位**：**隐田/隐户**在面板上给真数还是档位词？（POP 改良原口径是"朝廷只知约值，清丈才知真数"——若照此，面板应显示**估计区间**，并让"清丈"成为解锁真值的手段。）
3. **军政按钮**：是否允许在面板内直接下令（走 `_apply_military_dispatch` 等既有命令），还是**只跳转**到既有军政面板？

> 现状盘点：`region_brief` 已输出 `name/population/mood/public_support/literacy/grain_year/grain_stock/grain_months/
> tax_month/tax_share/army_cash_month/army_grain_month/risk_score/risk_label/risk_hints`，并有全国汇总与
> `risk_counts`；`PrefecturePanel.tsx` 已有三视图与回落逻辑 —— **P0 几乎不需要后端改动**。
