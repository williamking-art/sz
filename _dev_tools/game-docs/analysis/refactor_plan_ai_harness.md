# 《宋祚》harness 化 + agent 化重构计划

> 状态：草案 v2 · 待评审
> 背景：用户指示「**整个游戏 harness 化、agent 化——AI 就是这个游戏的核心，让 AI 能更有效的发挥就是游戏的宗旨**」；游戏 AI 使用靠提示词规范，引入 harness 后更能体现多样性。
> 关联定稿：言枢密 free_effect 契约 v3（拒绝式·AI 强制）、蔡权衡效果映射数值表、用户「全游戏级强制 AI」决定。
> 核心理念：**AI 是游戏的核心引擎，harness 是骨架，程序是身体（数值/守恒/校验）。**

---

## 〇、游戏宗旨（定位）

**AI 就是这个游戏的核心**——游戏不是「数值模拟 + AI 叙事插件」，而是**「AI 驱动的治国模拟」**：所有机制（经济/军事/政治/事件/外部/叙事）都通过 AI（agent）推演驱动，harness 保证稳定与编排，程序负责数值/守恒/校验。**让 AI 更有效地发挥，就是游戏的宗旨。**

### 产品定义（用户定稿）：穿越者模拟器

> **模拟一个穿越者（玩家），通过跟大臣的对话、发布圣旨（政策），来改变历史进程（北宋徽宗朝）。**

| 本质要素 | 架构支撑 |
|---|---|
| 穿越者（玩家视角）| 玩家是现代视角，与北宋世界对话 |
| 跟大臣对话 | 大臣 = AI agent（persona + 记忆知识库 + 主动性 + 自设工具）→ 召对鲜活连贯 |
| 发布圣旨（政策）| 拟诏 = AI 解析 + free_effect 契约（政策效果推演 → 程序落地）|
| 改变历史进程 | 记忆知识库（因果链）+ 历史大势 → 决策改变走向（蝴蝶效应）|
| 历史模拟 | harness 保证历史一致（推演有依据、前后不矛盾、确定性可复现）|

**设计推论**：对话 + 圣旨是核心交互（全部 AI 驱动）→ 全游戏强制 AI；大臣是「活人」（agent 化）→ 自设工具/记忆/主动；政策是手段（free_effect）→ 任何政策可推演落地；历史进程是目标 → 记忆图谱 + 因果链保证「改变有迹可循、前后一致」。

## 一、目标

1. **长期任务连贯推演**：跨多回合、多大臣、多机构的制度/任务（识字营、养老制度、变法、机构经济、召对线）在 AI 推演下**状态延续、逻辑连贯、不漂移**。
2. **系统稳定性**：确定性（同 seed 可复现）、可观测（统一错误分类）、不伪造（AI 缺失/失败 → 明确报错，不降级假装）。
3. **叙事多样性**：AI 不只靠提示词规范，通过 agent 角色化 + 记忆上下文，输出更多样、更贴历史的推演。

## 一·五、核心哲学（用户校准）：整个游戏 harness 化 + agent 化

**AI 是核心引擎，程序是身体**。不是「给 AI 加层」，而是：

- **整个游戏 harness 化**：harness 是游戏骨架（确定性/编排/记忆/错误处理/动态工具注册），承载 12 步结算流水线及全部机制。
- **整个游戏 agent 化**：12 步流水线的每一步推演层都由 agent 驱动（经济→推演官、吏治→按察使、军事→枢密、漕运→转运使、事件→史官、外部→外邦使节、月报→起居注、拟旨→知制诰、召对→大臣…）；程序负责数值落地、守恒校验、状态夹取。
- **AI 有效发挥 = 游戏宗旨**：AI 提推演/叙事/建议/自设工具，harness 保证稳定与编排，程序保证守恒与真实——三者各司其职，让 AI 充分施展。

**由此自然消解的问题**（无需单独造机制）：
- 叙事-数值一致：harness 注入真实读数 → agent 天然引用真值。
- 事件因果：记忆知识库记录「事件→决策→效果」→ 推演检索历史 → 因果自动形成。
- 大臣主动：agent 化大臣（persona+记忆+主动性）在 harness 编排下自然上疏/进谏/密谋。
- 外部世界：辽/金/西夏各是一个「外邦 agent」（记忆+演化），非一堆数值。
- 长期任务：harness 编排任务生命周期（暂停/恢复是 harness 能力）。
- 存档：状态由 harness/agent 层统一管理（用户指示：不需要管存档）。

## 二、现状诊断（实勘）

| 现状 | 问题 |
|---|---|
| AI 唯一出口 `AIClient._call`（ai/client.py:281），18 个 prompt 模板 | 靠提示词约束输出，缺 harness 结构化（确定性/错误分类/重试）|
| 无 AI 兜底路径：`_fallback_parse`（_error=True）、`_ai_unavailable`（AI_UNAVAILABLE）、economy_decide validator 逐字段默认值 | **类型不统一**（无 AI_NOT_CONFIGURED 常量），降级路径多，行为不一致 |
| 长期任务：`longterm_public` 政务队列、`minister_memory` 大臣记忆、`central_orgs` 机构 | 记忆层零散，无统一「agent 长期状态」；跨回合推演无确定性载体 |
| 测试：`tests/test_ai_contract.py` monkeypatch `_call`；回放无固定 seed | 无统一假后端；`_settle_economy` 含 random（settlement_steps.py:335），回放不可复现 |
| 结算耦合：`settle_turn`(commands.py:131) 注入 `_economy_ai`；消费方 `getattr(...) or {}` 白名单兜底 | 强耦合 + 兜底，强制 AI 后需收敛 |

## 三、目标架构（整个游戏 harness 化 + agent 化）

```
┌─ Harness 层（游戏骨架，本次引入）──────────────────┐
│  · AI 调用管理：统一错误分类（6 码）/ 重试补调 / 确定性注入
│  · 编排引擎：12 步流水线每步 → 对应 agent 推演 → 程序落地
│  · 动态工具注册（agent 自设工具生命周期）
│  · 固定 seed 确定性 + 月度快照可复现
└─────────────────────────────────────────────────┘
            │ 编排（谁何时推演 / 检索什么记忆 / 校验落地）
┌─ Agent 层（游戏引擎：AI 驱动全部机制，本次重构）───┐
│  · 12 步流水线每步一个 agent：
│      经济→推演官 / 吏治→按察使 / 军事→枢密 / 漕运→转运使
│      事件→史官 / 外部→外邦使节 / 月报→起居注 / 拟旨→知制诰 / 召对→大臣
│  · 每 agent：persona（性格/立场/演化）+ 记忆知识库（图谱检索）+ 主动性
│  · ★大臣自设工具：理解玩家对话 → 无现成工具时自建新工具 → harness 注册复用
│  · ★记忆知识库（仿 codebase-memory-mcp）：实体/关系图谱，推演前检索子图注入
└─────────────────────────────────────────────────┘
            │ 推演/叙事/建议（AI 只提建议）
┌─ 程序层（游戏身体：数值/守恒/校验）────────────────┐
│  · 12 步结算流水线（数值落地、钱粮/人口守恒）
│  · free_effect 契约（白名单 13 字段/CAP/拒绝式）
│  · 经济公式/军队模型/POP/税制（不变，只接收 agent 推演结果）
└─────────────────────────────────────────────────┘
```

**关键不变式**：AI（agent）只提推演/叙事/建议，程序算数值并守恒校验后落地；AI 缺失/失败 → 不执行 + 明确报错，绝不伪造。**确定性由 harness 架构本身提供，不设独立假 AI 后端组件。**

## 四、分阶段实施计划

### Phase 0：harness 确定性底座（固定 seed + AI 调用管理）
- 交付：harness 层「AI 调用管理」（统一错误分类 + 重试/补调 + 确定性注入）；回放脚本固定 `random.seed()`；月度快照可复现机制；`_settle_economy` 随机源收敛（settlement_steps.py:335）。
- 验收：同 seed 60 月回放字节级一致；AI 缺失/失败各分类明确报错、不伪造。
- 负责人：谷承构（harness 底座）+ 沈舶司（AI 调用管理接入）。

> 注：**不设独立「假 AI 后端」组件**（用户决定：harness 化后不需要）。测试确定性由 harness 的「AI 调用管理 + 固定 seed」提供——需要确定性推演时，经 harness 注入确定性响应（harness 内置能力），而非模拟 AI 的替身组件。玩家真实无 AI 路径（AI_NOT_CONFIGURED 报错）与测试注入路径由 harness 区分。

### Phase 1：自由动作通用契约
- 交付：`core/free_effect.py`（_apply_free_effect 拒绝式校验+落地）；`state.longterm_effects` 队列 + `_settle_free_effects` 月结；`FREE_EFFECT_FIELD_WHITELIST` 入 data.py；parse_decree 接入 free_effect_decide。
- 验收：once/ongoing 冒烟；白名单/CAP/成本校验拒绝式；长期制度月度结算。
- 负责人：谷承构 + 言枢密（prompt/free_effect_decide）。

### Phase 2：全系统强制 AI + 统一错误分类
- 交付：移除 `_fallback_parse`/`_ai_unavailable`/validator 默认值（景气/城市化/科举/窖银/士绅囤抛等）→ 拒绝式；统一 `_error` 分类常量；ai_config.json 缺失 → 明确提示配置。
- 验收：无 AI 时拟旨/月报/召对/推演全部明确报错不降级；pytest 全绿（假后端覆盖）。
- 负责人：谷承构 + 言枢密（_error 体系）+ 严归正（测试矩阵）。

### Phase 3：现有机制 agent 化（角色化 + 记忆 + 自设工具 + 记忆知识库）
- 交付：**现有机制 agent 化**——经济推演→推演官、拟旨→知制诰、月报→起居注、事件→史官、召对→大臣、军事→枢密、外部→外邦 agent（现有 18 prompt 归角色，机制本体不变，推演层 agent 化）。
- `state.agent_memory`（长期任务状态，跨回合延续）；minister_memory 统一读写；机构经济接长期状态。
- ★**大臣自设工具**：harness 层「动态工具注册机制」（注册/校验/复用/注销）；agent 理解玩家对话 → 无现成工具时自己定义新工具 → harness 校验注册 → 后续复用。
- ★**记忆知识库**：`core/memory_graph.py`（实体/关系图谱，仿 codebase-memory-mcp）；召对/推演前检索相关子图注入上下文（整合记忆分层 + 因果链）。
- 验收：长期任务跨回合连贯；召对线多大臣连续；大臣能自设工具并复用；推演有历史依据（记忆图谱检索）、前后一致。
- 负责人：言枢密（agent 化/意图理解）+ 谷承构（agent_memory/工具注册/记忆图谱）+ 邹运筹（叙事路由）。

### Phase 4：harness 化整合（重试/补调/可复现）
- 交付：统一重试/补调链（在线失败回喂一次）；错误分类全路径覆盖；回放/verify 全部接假后端；启动引导（无 AI 明确提示配置）。
- 验收：稳定性矩阵（超时/鉴权/空响应/非JSON/越界各 → 分类报错不伪造）；60 月回放稳定。
- 负责人：谷承构 + 严归正（验收）。

## 五、验证与验收总纲

1. **pytest 全绿** + 契约测试矩阵（合法/非法字段/越界 delta/超存量 cost/once/ongoing 月结/AI 缺失各分类不执行）。
2. **60 月回放**：固定 seed 复跑字节级一致（harness 确定性驱动），无 NaN、不崩。
3. **长期任务连贯**：识字营/养老制度/变法/机构经济跨回合状态延续（agent_memory 断点续推）。
4. **无 AI 明确报错**：AI_NOT_CONFIGURED 等分类，不伪造效果。
5. **存档兼容**：全阶段新增字段缺省默认，旧档可加载。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 全系统改动大（Phase 2 去兜底波及所有推演点）| 分阶段、每阶段 pytest 全绿再进下一阶段；Phase 0 harness 底座先建 |
| harness 确定性注入与玩家真实 AI 路径混淆 | harness 严格区分「测试注入」与「玩家 AI」两条路径（注入仅测试/回放，生产/玩家走真实 AI 或明确报错）|
| 回放随机源不可复现 | 回放脚本固定 random.seed（Phase 0 收敛 `_settle_economy` 随机源）|
| 提示词→harness 迁移期叙事质量下降 | Phase 3 角色化保留原 prompt 语义，harness 只加结构化外壳 |
| 存档迁移 | 新字段 getattr 缺省 + save_load 迁移（沿用既有模式）|

## 七、执行顺序（依赖）

```
Phase 0（harness 确定性底座）→ Phase 1（free_effect）→ Phase 2（强制AI+错误分类）
→ Phase 3（agent 角色化+记忆）→ Phase 4（harness 整合）
```

Phase 0 是后续一切的地基（harness 底座建好后，强制 AI 后的测试/回放才有确定性载体）；Phase 1/2 可并行推进（不同模块）；Phase 3 依赖 1/2 的错误体系。

## 八、一句话总结

**整个游戏 harness 化 + agent 化**：AI 是游戏的核心引擎，harness 是骨架（确定性/编排/记忆/动态工具/错误处理），程序是身体（数值/守恒/校验）——12 步流水线的每一步都由对应 agent 推演驱动，大臣能自设工具、记忆知识库支撑跨回合连贯，让 AI 更有效地发挥，就是游戏的宗旨。**确定性由 harness 架构本身提供，不设独立假 AI 后端组件。**

## 九、完善改进方案（v1 评审增补）

> 在初稿基础上，针对「跨回合连贯、稳定性、大臣智能」三条主线的增强设计。

### ① 记忆分层 + 遗忘曲线（跨回合连贯的硬保障）
- 三层记忆：**回合内**（短期）/ **任务期**（中期）/ **永久事实**（长期）。
- **衰减**：久远记忆随回合模糊（大臣 12 回合前的承诺可能"记不清"），重大事件/决策**强化记忆**（记牢）。符合史实记忆规律、更生动。
- 落地：agent_memory 扩展为 `{layer, last_touched, decay, content}`。

### ② 因果链追踪（effect ledger，防前后矛盾）
- 每次 AI 推演落效果记录 `{效果, 原因, 回合}` 到因果链（effect ledger）。
- 后续推演/叙事**引用既定事实**（"修水利已增产"是历史）——从机制上杜绝前后矛盾。
- 落地：`state.effect_ledger`（append-only），AI 输入 state_summary 时注入最近因果摘要。

### ③ 大臣 persona 档案 + 立场演化（一致 + 生动）
- 每大臣 **persona 档案**（性格/利益/立场基线，跨召对一致）。
- **立场随事件/派系动态演化**（变法后新党得势、旧党失势），性格稳定、立场可变。
- 落地：`state.minister_persona`（基线档案）+ 既有 faction_stances 演化接入召对。

### ④ 效果仿真沙箱（harness 稳定性 + 决策预览）
- harness 提供**仿真模式**：AI 推演效果先在**克隆状态**预览，玩家可先看影响（变法/大兴土木前预览），测试/回放走仿真（确定性）。
- 落地：`core/sandbox.py::preview_effects(state, contract)`（deepcopy + apply + 读数），UI 决策预览入口。

### ⑤ 长期任务状态机（任务健壮性）
- longterm_effects 从简单队列升级为**状态机**：创建 / 执行 / 受阻 / 暂停 / 完成 / 废弃。
- **受阻**：国库不足→暂停（不静默消失、日志"用度不继"）、事件打断→受阻、条件恢复→重启。
- 落地：longterm_effects 条目加 `state` 字段 + `_settle_free_effects` 状态迁移。

### ⑥ 多 agent 廷议协同（多大臣互动）
- 重大决策走**廷议**：多大臣按立场/利益给意见（新党/旧党/宦官/后族各执一词），皇帝权衡（派系/皇威），推演结果反映立场差异。
- 落地：`ai/prompts/council_settle.md`（廷议推演）+ 现有 council_review 增强为立场输出。

### ⑦ 可解释性决策日志（稳定性 + 玩家理解）
- 每次效果落地带**归因**（narrative + 原因），UI 可查「国库为何 -X」「民心为何降」。
- 落地：`state.decision_log`（append-only：{回合, 动作, 效果, 原因}），UI 决策日志面板 + 测试断言用。

### ⑧ agent 记忆知识库（本地图谱，仿 codebase-memory-mcp）
- 仿 codebase-memory-mcp 的图谱模式，为游戏 agent 建**本地记忆知识库**（持久化知识图谱，毫秒级检索）。
- **实体**：大臣 / 事件 / 决策 / 任务 / 机构 / 制度（如蔡京、崇宁变法、方田均税、识字营、新党）。
- **关系**（带时间戳 + 权重）：支持/反对（蔡京→支持变法）、涉及（崇宁变法→蔡京）、产生（方田均税→国库+民心-）、进展（识字营→第12月）、承诺（蔡京→「变法以富国」）。
- **写入**：每次决策/事件/任务更新 → 记忆层写实体 + 关系。
- **检索**：召对/推演前检索相关子图（如「蔡京」子图：立场/承诺/相关事件）→ 注入 AI 上下文 → 大臣「记得」历史、推演有历史依据（跨回合连贯的硬机制）。
- **衰减/强化**：久远关系弱化、重大事件强化（合并改进点①）。
- 落地：`core/memory_graph.py`（实体/关系模型 + 写入 + 子图检索）；召对/推演 state_summary 注入检索结果；本地存储（memory/ 文件，仿 graph.db）。

### ⑨ 两层记忆（用户定稿：短期行为日志 + 长期知识图谱）
- **短期记忆库**：圣旨/口谕/决策 **append-only 行为日志**（全量保留、可追溯、**不注入 AI 上下文**——避免琐事污染/稀释）；用途：审计、拟旨时关键词检索既往同类。
- **长期记忆库**：记忆知识图谱（实体/关系，选择性注入——召对/推演时 query 相关子图）。
- **协作**：短期喂长期（圣旨落地 → 提炼决策实体 + produces 写入图谱）；注入只从长期（精挑摘要，不污染）。

### ⑩ 融入 MingSalvageSim 菁（用户确认：结合 ming 优点）
- 已吸收：记忆图谱（Phase 3a）、persona 读盘面定姿态（Phase 3b）、工具落档、free_effect 统一入口、数字守恒。
- **④ 叙事-数值一致**：agent 叙事引用的数字必须对得上盘面真值（AI 说"国库充盈"需国库真实充盈；清丈数字不超隐田存量、调粮不超存粮）——harness 注入真实读数 + 程序校验叙事数值。
- **⑤ 来源锚定（取材闭集）**：月报/朝堂剧场/事件只从「本回合真实来源」取材（诏书/在办事务/记忆图谱检索闭集），AI 不得另开无关剧情。
- **⑥ 防错校验表**：人物状态权威校验（生死/去留/现职/归属），叙事写具名人物前先核对（死人不能说话、革职不能办差）——仿 character_statuses。

### ⑪ 省 token 原则（用户定稿：本地算确定性 + AI 保混沌 + 按需查询）
- **核心原则**：能本地算的尽量本地算（省 token、保精度），但**保留 AI 推演的混沌**（不可过度限制 AI 自由度）；省 token 靠「本地化确定性计算 + 按需查询」，**不靠模糊数值、不靠砍 AI 推演空间**。
- **本地算（确定性）**：数值计算（税收/军粮/物价/守恒）、状态查询（国库/民心/欠饷）、立场演化（公式）、任务进度、事件触发阈值、记忆图谱。
- **AI 保混沌（判断+叙事）**：政策效果推演（free_effect）、事件演化后果、大臣反应/召对、景气判断——AI 自由空间完整保留（效果可超预期、事件有意外、大臣有脾气）。
- **按需查询（问到才查）**：召对基础注入只带人物上下文（身份/立场/近期事件），**数值不主动注入**；AI 提到数值时调 `query_state(target)` 工具查询精准值（结构化、防瞎编）；查询缓存（同回合复用）；工具列表 schema（小）替代全量数值注入。
- **硬约束**：数值精准（不模糊化，防推演漂移）；AI 混沌不丢（本地只给准确地基，不替 AI 判断）。
- 落地：`query_state` 按需查询工具 + 召对注入精简 + 本地计算分工表。
