# AI 推演与结算流程（2026-09-21，实测落档）

> 目的：① 给后期"玩家自选模型"提供完整的接触面清单；② 归档推演链路的真实时序与耗时分摊，
> 让后续任何链路优化（并发/合批/分层 provider）都有测量基线而不是凭感觉。
> **本文只描述现状，不含行为改动。** 数据来自 2026-09-21 实测（`sz_advance_probe` 1 回合 + profile）。

## 一、一次回合的完整时序（程序事实）

```
advance_and_settle(state, ai)                        # core/commands.py:437  原子封装（快照回滚）
 ├─ advance_month(state)                             # 事件触发：active_events 追加（可 game_over）
 ├─ settle_turn(state, ai_client)                    #                      commands.py:247
 │  ├─ ai_client.settlement_mode() 上下文            # 结算专用 provider（agnes-2.5-flash 定稿；
 │  │                                                #   未配 settle_model 则不切，行为等同原）
 │  ├─ _ai_prelude(state, ai_client)                 #                      commands.py:325
 │  │  ├─ economy_decide(state.posture)              #  ★必发  → state._economy_ai（景气/囤粮/生产档位，
 │  │  │                                             #           结算内读取）→ 有失败即拒绝式（不兜底不伪造）
 │  │  ├─ route_agents(player_hint, state, 上轮 diff) #  12 步 agent 化：玩家诏令摘要 + 状态触发 + 上轮 diff
 │  │  └─ inject_woken_agents(state, ai, _woken)     #  按需：diplomacy_decide / military_decide /
 │  │                                                #        relief_decide → state._*_ai（未唤醒=0 token）
 │  ├─ settle_local(state)                           #                      commands.py:475（前快照+异常回滚）
 │  │  └─ run_monthly_settlement(state)              #  ~18.6 ms —— 全部确定性结算（Step 1..10.6 存款收敛、
 │  │                                                #   10.9 货币对账；Step 3.5.6 识字率、8.5 局势在内）
 │  ├─ _monthly_report_text(state, ai_client)        #  装饰性叙事月报（失败 → 模板兜底，结算已发生）
 │  ├─ _flush_ai_token(state, ai_client)             #  一回合 token 计量成行入 state.ai_token_log
 │  └─ finish_turn(state)                            #  终局判定 + 记忆库压缩/总结/落盘
 ├─ generate_memorials(state.posture, state, 3)      #  奏章（失败 → narrative_fallback 模板兜底）
 └─ 异常 → _restore_state(snap) 整体回滚（幽灵事件防重复）
```

辅助路（非每回合）：事件选项 `resolve_event(..., ai)`（含 `event_narrative` 叙事）
与玩家操作路（拟旨 `parse_decree`/`polish_decree`、召对 `council_review`、
`draft_decree`、`survey_settle` 等）——各自独立网络往返，调用时才发。

## 二、实测分账（2026-09-21）

| 项 | 值 | 说明 |
|---|---|---|
| 结算本体 | **18.6 ms/回合** | profile 12 回合均值，纯程序（无 AI） |
| LLM 调用 | **4 次 / 回合** | economy(1 必发) + 按需唤醒 agent / memorials / 月报等合计 |
| prompt tokens | **4049**（平均 ~1010/次） | 每路独立，最小的主摘要 ~540 token |
| completion tokens | **2903** | 档位+叙事，思考型预算内 |
| 挂钟耗时 | **27.7 s/回合** | ≈ 7s/次 × 4 次串行网络往返——**瓶颈在往返次数 × 思考型延迟** |
| token 详账 | `state.ai_token_log`（每回合一行的附表，前端「治务 · AI计量」读它） | `calls/prompt/completion/total/label` |

结论（给"换模型"用）：**上下文尺寸不是问题**（~1k/次），耗时大头是网络往返 × 思考型延迟。
换低延迟小模型 → 27.7s 可降到一个数量级；合批/并发是链路级改动，见 §四留档。

## 三、后期玩家自选模型 —— **接触面清单**（全部单点）

### 3.1 配置面（玩家唯一要碰的东西）
| 项 | 位置 | 说明 |
|---|---|---|
| base_url / api_key / model | `ai_config.json`（git-ignored） | AIClient 主配置；`ai/client.py:AIClient.load_saved()` 读取 |
| 结算专用模型（可选） | `settle_base_url / settle_api_key / settle_model` | 过结算时经 `settlement_mode()` 切换；未配 = 不切换（同主模型） |
| key 凭据知识 | `D:\codebuddy\_credentials\llm_providers.md`（**勿提交/勿贴文档**） | Agnes / a6api 的 base_url 与模型清单 |

### 3.2 硬规格（换 provider 时必须满足，否则契约测试会红）
| 规格 | 出处 |
|---|---|
| AI **只出档位与叙事**，数值一律程序算（未知 id/非法档位/重复/越权字段 → 丢弃该条） | `ai/client.py` 白名单过滤 + contract tests |
| 失败 → **拒绝式**（`AIRuntimeError` + `AI_ERROR_CODES`），**不静默兜底不伪造** | `commands.py:settle_turn`；仅叙事类（月报/奏章/事件文案）有模板兜底 |
| provider 回退主失败/空正文/拿不到可解析 JSON → 兜底**一次**，回退内不再回退 | 用户定稿：不用旧世代模型 |
| 思考型端点 `max_tokens` **下限 8192 / 上限 32000**；空响应自愈（加倍预算重发一次）并计费 | `_call_impl/_call_with_tools` |
| 结算模式与回退**可叠加**、退出时 provider 严格还原 | `settlement_mode()` 上下文契约 |

### 3.3 兜底与否一览（哪些失败能忍、哪些不能）

| 调用路 | 失败处置 | 理由 |
|---|---|---|
| `economy_decide`（*★必发*） | **拒绝式**，结算不发生 | 数值本身全部程序算，AI 只出档位；但缺档位结算不可推进（契约拒绝） |
| agent 唤醒族（diplomacy/military/relief…） | 路由失败回退：**P1 三契约保底注入**（不阻断结算） | 12 步按需注入 |
| 月报 `_monthly_report_text` | 模板兜底（装饰性） | 叙事呈现，结算已就地发生 |
| `generate_memorials` | 模板兜底（`narrative_fallback.fallback_memorials`） | 同上 |
| 事件叙事 `event_narrative` | 模板兜底 | 同上 |

### 3.4 多回合一局的整体节奏（当前实测）
- 240 月压力测试（纯程序）：tests ~60–70s（pytest 全量的主体就是它）；
- 游戏过程 1 回合 ≈ **27.7s（含 AI）**；若玩家后期选低延迟模型，可显著下降（上下文仅 ~1k/次）。
