### 2.1 新增 `game/core/foundation/kernel/`（建议路径，避免再开平铺大文件）

| 模块 | 职责 | 第一阶段 |
|---|---|---|
| `ids.py` | 中性 ID 与枚举：`AdminLevel`、`TaxKind`、`OfficeKind`、`CurrencyKind`、`PopClass`、`AccountKind` | 只定义 + 映射，不改调用 |

### 2.2 宋内容包（不是新朝代）


### 2.3 状态与存档

### 2.4 约束与不确定性（宋也要用）

- `Unknown`/`Range` 先挂到：**开局年份/年号、家计阈值、作坊工价、外邦省人口**；
- 约束先落 4 条：**钱粮人守恒、POP 挂载、预算/池、权限**；
- 所有"缺失"必须带 `reason`，禁止 `or 0`/`or 1.0`（已有守卫可扩展）。

### 2.5 跨朝代共同点：人口 / 区划 / 官制（只用于定接口，本阶段不实现其他朝代）

用户补充的关键点：各朝代**人口口径、区域划分、官制**都不一样。但"不一样"的是**名称、层级、分类、参数**；
**实体、关系、守恒**是共同的。基础架构只抽象后者，前者全部下沉到 pack。

#### 2.5.1 人口：共同点是"人—户—登记—负担—流动"

| 跨朝代共同点（内核） | 各朝差异（pack 参数/规则） |
|---|---|
| 人/户/口是存量；有出生、死亡、婚配、迁移 | 户口登记制度（编户/黄册/里甲/保甲…） |
| **实际人口 ≥ 登记人口**（隐户/逃户/客户） | 隐户/逃户的判定与统计口径 |
| 家庭是生产/消费/纳税/服役的基本单位 | 家庭结构、户等划分标准 |
| 有劳动能力/抚养比/消费需求 | 丁/中/老/小的年龄口径 |
| 有田产/职业/身份/依附关系 | 主户/客户/佃农/部曲/军户/匠户… |
| 有赋税/徭役/兵役义务 | 税基（丁/户/田/资产）与役法 |
| 有贫富分化与流动 | 土地兼并、迁徙限制、赈济资格 |
| 城乡/职业分布 | 城市人口、坊郭户、市籍等 |

**内核接口（建议）**：
```text
PopulationModel:
  households(state, place) -> 户数/口数/户等分布
  cohorts(state) -> 年龄/性别/身份/劳动能力
  registration(state) -> 登记/隐漏/客户/流民
  obligations(state, household) -> 税/役/兵役（由 pack 规则算）
  distribution(state) -> 财富/田产/收入分布（区间/分位）
```
**不变量**：`登记 + 隐漏 == 实际`；户成员 Σ == 人口；劳动投入 ≤ 可劳动人口；
出生−死亡±迁移 == 人口变化；田产/身份份额之和守恒。

#### 2.5.2 区划：共同点是"地点—层级—管辖—控制"四张图

不要把"行政区划"当成一张表。跨朝代共同结构是**四张可分离的图**：

| 图 | 含义 | 跨朝代共同点 | 差异 |
|---|---|---|---|
| **地点图** | 地理点/面/距离 | 位置、相邻、距离、资源 | 州/府/县/省/道/路名称与数量 |
| **行政层级图** | 谁管谁（parent/child） | 层级包含、治所、辖区 | 层级数、层级名、特殊单位（军/监/羁縻/藩） |
| **政治控制图** | 谁实际控制 | 归属/占领/羁縻/双属 | 宋/辽/金/夏…控制关系 |
| **职能管辖图** | 谁收税/谁司法/谁调兵 | 管辖范围、财政流、司法/军事区 | 路—州—县、省—府—县、军区/监察区 |

**内核接口**：
```text
TerritoryModel:
  places() -> 地点/几何/资源
  admin_units(level) -> 单位；parent(child)；seat_of(unit)
  jurisdiction(place) -> 行政/税务/司法/军事归属（可多套）
  control(place) -> 实际控制政权
  fiscal_flows(unit) -> 上供/留州/起运
```
**不变量**：每个地点在每个层级**恰有一个**行政父节点；辖区是划分（不重叠、不遗漏）；
控制关系可重叠但必须显式；治所必须属于本单位；财政流上下游之和守恒。
**落地方式**：宋的 `路/州府/治所` 只是 pack 里的一套 `levels` 与 `unit_types`；
内核不写"路"、不写 21/136 这些数。

#### 2.5.3 官制：共同点是"职位—人—任命—权限—程序—考课"

| 跨朝代共同点（内核） | 各朝差异（pack） |
|---|---|
| 职位（office）有品级/职责/俸禄 | 三省六部/中书门下/内阁/军机… |
| 人（actor）与职位分离 | 官/吏/差遣/使职的区分 |
| 任命（appointment）有任期/兼摄/代理 | 科举/察举/九品/恩荫/荐举 |
| 权限（authority）按职位/差遣/授权 | 事权划分、台谏、密旨、节度 |
| 组织（organization）有层级/编制 | 衙署/机构/编制 |
| 程序（procedure）有会签/封驳/执行 | 诏令流程、三省审核、内阁票拟 |
| 考课（evaluation）有指标/周期 | 考课/磨勘/京察/大计 |
| 信息（information）有奏报/邸报/密报 | 信息来源、延迟、偏差 |
| 派系/关系网络 | 新旧党/地域/门生故吏 |

**内核接口**：
```text
OfficialdomModel:
  offices() -> 职位目录（id/rank/duty/salary）
  organizations() -> 机构树
  appointments() -> actor→office/tenure/acting
  authority(actor, action, scope) -> 是否可做（约束，不是数值）
  procedure(decree) -> 会签/封驳/执行状态机
  evaluation(actor) -> 考课（由 pack 规则算）
```
**不变量**：一职一任（会签/并列需显式）；任命不重叠；权限 ⊆ 职位/授权；
程序状态机合法；俸禄必须从既有账户出；信息可见性按角色/密级判定。

#### 2.5.4 共同点如何进入基础架构

| 领域 | 内核只负责 | pack 提供 |
|---|---|---|
| 人口 | 存量/流量/登记/劳动/负担的**接口与守恒** | 户等、税基、役法、登记制度、身份类别 |
| 区划 | 四张图 + 划分/守恒/控制 | 层级定义、单位类型、名称、特殊区、治所规则 |
| 官制 | 职位/任命/权限/程序/考课**接口** | 官名、机构、品级、选拔、考课、俸禄参数 |

**实施顺序（仍只做宋）**：
1. **人口接口**（家计/赋役直接依赖）→ 2. **区划四图接口**（税基/管辖依赖）→
3. **官制接口**（诏令/执行/考课依赖）。三者都先用宋的数据适配，不写其他朝代。

> 这样"各朝不一样"不会逼内核分叉：**内核只认实体与不变量，pack 决定名称、层级、分类、参数和规则。**

## 3. MOD / 创意工坊接口 v1（先声明式，不开放任意 Python）

### 3.1 包类型与加载顺序

```json
{
  "id": "workshop.example.more_tea",
  "name": "创意工坊：更多茶类",
  "version": "1.0.0",
  "game_version": ">=0.1",
  "type": "content",
  "dependencies": ["song_1101"],
  "load_order": 100,
  "data": ["data/goods.json", "data/events.json"],
  "ai": ["ai/prompts.md"],
  "patches": [{"target": "goods.tea", "mode": "append", "value": {...}}]
}
```

### 3.2 第一阶段只允许的扩展点

- **数据表追加/覆盖**：商品、建筑蓝图、科技节点、事件、官职、税种、势力、人物、剧本；
- **补丁语义**：`append`（新 ID）/`replace`（同 ID，需显式声明）/`patch`（字段级）；冲突必须报错，不允许静默覆盖；
- **AI 提示/文风**：`ai/` 目录，按 pack 切换；
- **不允许**：任意 Python 入口、网络、文件系统任意读写、直接改 state/账本。

### 3.3 第二阶段（如果确实需要）

- 受控 Python 插件：显式 `entrypoint` + 沙箱/白名单 + 版本检查 + 玩家确认；
- 所有插件产出仍必须过 schema + 约束 + 审批，AI 不直接写 state。

### 3.4 验收

- 一个示例 mod（只加 1 个商品/1 个事件）能**加载、校验、开新局、跑 1 个月**，不改变基础包存档；
- 非法 mod（撞 ID/坏 schema/依赖缺失）**拒绝加载并给出原因**，不进入半加载状态。
