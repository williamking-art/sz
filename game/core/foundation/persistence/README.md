# foundation/persistence — 存档与旧档迁移

> 存档槽位机械与旧档迁移。**`save_game` / `load_game` 本体仍在 `core/save_load.py`**，
> 原因见 [../README.md](../README.md) §一（迁移期保留宿主，勿在本目录另开存档格式）。

## 模块（2 个，均 `git mv` 自 `core/save_load.py`，**零行为变更**）

| 模块 | 行 | 职责 |
|---|---:|---|
| `slots.py` | 77 | 存档槽位机械（3 个接口） |
| `migrations.py` | 78 | 旧档迁移（2 个接口），只取**实测无业务依赖**的部分 |

## 🔴 纪律

- **迁移必须是幂等的**，且**绝不覆盖已下沉的数据**。
  范例：`_migrate_pops_to_seats` 在载入时为 `seats` 缺失的路补拆分，已下沉的档**不覆盖**。
- 旧档迁移里**不得引入业务判断**——本目录只做「结构补齐」，玩法口径不在这里定。
- 新增迁移步骤时同步核对读数口径；`save_load` 是 §五 登记的 12 条反向边之一，
  它调本目录之外的东西时**函数内 import**，且失败必须留痕（见 `../README.md`）。
